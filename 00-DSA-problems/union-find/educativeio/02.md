# Redundant Connection — Java 24

This is a classic Union-Find (Disjoint Set Union / DSU) problem.

The key observation is that a tree with \\(n\\) nodes must have exactly \\(n-1\\) edges and contain no cycles. Here, the graph is connected and has \\(n\\) edges, so it contains exactly one cycle. We need to find the edge whose removal breaks that cycle, choosing the last such edge in the original `edges` array.

## 1. Intuition: How do we detect the redundant edge?

Imagine processing the edges one by one.

- If an edge connects two nodes that are in different connected components, accept it and merge their components.
- If an edge connects two nodes that are already in the same component, it creates a cycle. That edge is redundant.

Union-Find efficiently answers the question: Are these two nodes already connected?

Input:

`edges = [[1,2], [1,3], [2,3]]`

- `[1,2]` connects two separate components.
- `[1,3]` connects node 3 to the existing component.
- `[2,3]` connects nodes already connected through `2 → 1 → 3`.

Therefore, `[2,3]` is the redundant edge.

## 2. Solution 1 — Union-Find (optimal)

### Java 24 code

```

import java.util.*;

class Solution {

    // parent[x] is the representative-parent of node x.
    private int[] parent;

    // rank[x] approximates the height of the tree rooted at x.
    // It helps us attach the smaller tree under the larger one.
    private int[] rank;

    // Find the representative of the component containing x.
    private int find(int x) {

        // A root is its own parent.
        if (parent[x] == x) {
            return x;
        }

        // Path compression:
        // Make x point directly to the root, flattening the tree.
        return parent[x] = find(parent[x]);
    }

    // Merge the components containing a and b.
    // Returns false if they are already in the same component.
    private boolean union(int a, int b) {

        // Find the roots of both components.
        int rootA = find(a);
        int rootB = find(b);

        // Same root means a and b are already connected.
        // Adding this edge would create a cycle.
        if (rootA == rootB) {
            return false;
        }

        // Union by rank: attach the shallower tree under the deeper tree.
        if (rank[rootA] < rank[rootB]) {
            parent[rootA] = rootB;
        } else if (rank[rootA] > rank[rootB]) {
            parent[rootB] = rootA;
        } else {
            // Both trees have the same rank.
            // Choose rootA as the new root and increase its rank.
            parent[rootB] = rootA;
            rank[rootA]++;
        }

        // Two different components were successfully merged.
        return true;
    }

    public int[] findRedundantConnection(int[][] edges) {

        int n = edges.length;

        // Nodes are labeled from 1 through n.
        // Allocate n + 1 slots so that node labels can be used directly.
        parent = new int[n + 1];
        rank = new int[n + 1];

        // Initially, every node belongs to its own component.
        for (int node = 1; node <= n; node++) {
            parent[node] = node;
            rank[node] = 0;
        }

        // Process edges in their original order.
        for (int[] edge : edges) {
            int a = edge[0];
            int b = edge[1];

            // If union fails, a and b are already connected.
            // This edge closes a cycle.
            if (!union(a, b)) {
                return edge;
            }
        }

        // Unreachable under the given problem constraints:
        // the graph is guaranteed to contain exactly one cycle.
        return new int[0];
    }
}

```

### 3. Understand the two DSU operations

`find(x)` — Which component contains `x`?

Suppose the parent links look like this:

```
1
|
2
|
3
```

If `find(3)` returns `1`, path compression updates the links so that future lookups are faster.

`union(a, b)` — Can we merge these components?

| Condition            | Meaning              | Action                         |
| -------------------- | -------------------- | ------------------------------ |
| `find(a) != find(b)` | Different components | Merge them; return `true`      |
| `find(a) == find(b)` | Already connected    | Cycle detected; return `false` |

The crucial point is that we detect a cycle before merging. When both endpoints already share a representative, merging them cannot add any new connectivity.

## 4. Dry run

Consider:

```
edges = [[1,2], [1,3], [2,3]]
```

Initially, every node is separate.

For readability, the component groups below represent the sets of nodes connected so far, regardless of the internal DSU parent pointers.

| Edge    | Components before processing | Result                          |
| ------- | ---------------------------- | ------------------------------- |
| `[1,2]` | `{1}`, `{2}`, `{3}`          | Merge 1 and 2                   |
| `[1,3]` | `{1,2}`, `{3}`               | Merge 3 into the component      |
| `[2,3]` | `{1,2,3}`                    | Same component — cycle detected |

The algorithm returns `[2,3]` immediately.

### Why does returning the first cycle edge give the correct answer?

The problem guarantees that the graph contains exactly one cycle. The first edge that fails to merge two components is the edge that closes that cycle in the given processing order. Removing it leaves a connected, acyclic graph — a tree.

Because the cycle is unique, there is exactly one edge that is redundant when processing the edges in their original order. Thus, the first detected redundant edge is also the required answer.

## 5. Complexity analysis

Let \\(n\\) be the number of nodes and edges. The problem guarantees `edges.length == n`.

- Time: \\(O(n\alpha(n))\\), where \\(\alpha(n)\\) is the inverse Ackermann function. With path compression and union by rank, this is effectively linear for practical input sizes.
- Space: \\(O(n)\\) for the `parent` and `rank` arrays.
- Auxiliary space per operation: \\(O(\alpha(n))\\) amortized; the recursive `find` also uses a small call stack.

This is the preferred solution because it processes each edge once and avoids building an adjacency list.

## 6. Solution 2 — DFS (alternative)

Another way to think about the problem is to maintain the graph built from the edges processed so far.

Before adding an edge `(a, b)`, use DFS to check whether `b` is already reachable from `a`.

- If reachable, adding the edge creates a cycle.
- Otherwise, add the edge to the graph.

```

import java.util.*;

class SolutionDFS {

    public int[] findRedundantConnection(int[][] edges) {

        int n = edges.length;

        // Adjacency list for the graph built so far.
        List<Integer>[] graph = new ArrayList[n + 1];

        for (int i = 1; i <= n; i++) {
            graph[i] = new ArrayList<>();
        }

        for (int[] edge : edges) {
            int a = edge[0];
            int b = edge[1];

            // Check whether a path from a to b already exists.
            boolean[] visited = new boolean[n + 1];

            if (hasPath(a, b, graph, visited)) {
                // Adding this edge would create a cycle.
                return edge;
            }

            // No existing path: safely add the undirected edge.
            graph[a].add(b);
            graph[b].add(a);
        }

        // Unreachable under the problem constraints.
        return new int[0];
    }

    private boolean hasPath(
            int current,
            int target,
            List<Integer>[] graph,
            boolean[] visited) {

        // We reached the destination, so a path exists.
        if (current == target) {
            return true;
        }

        visited[current] = true;

        // Explore every unvisited neighbor.
        for (int neighbor : graph[current]) {
            if (!visited[neighbor]
                    && hasPath(neighbor, target, graph, visited)) {
                return true;
            }
        }

        // No path to the target was found from this node.
        return false;
    }
}

```

Complexity

- Time: \\(O(n^2)\\) in the worst case, because DFS can traverse \\(O(n)\\) nodes for each of \\(n\\) edges.
- Space: \\(O(n)\\) for the adjacency list, visited array, and recursion stack.

When to use it: DFS is useful when you want to practice graph traversal or need to determine reachability. For this specific problem, Union-Find is simpler and more efficient.

## 7. How to derive the Union-Find solution in an interview

Think through these questions in order:

1. What makes a tree? It is connected and has no cycles.
2. What does the extra edge do? It creates a cycle in the connected graph.
3. How can I detect a cycle while adding edges? If both endpoints are already connected, the edge closes a cycle.
4. Which data structure efficiently tracks connected components? Union-Find.
5. How do I handle the last-edge requirement? Process edges in input order. The edge that closes the unique cycle is the last processed edge on that cycle.

That leads directly to `find`, `union`, path compression, and union by rank.

## 8. Edge cases

| Case                                      | Expected behavior                         |
| ----------------------------------------- | ----------------------------------------- |
| Cycle closes on the last edge             | Return the last edge                      |
| Cycle closes before other non-cycle edges | Return the edge that closes the cycle     |
| Node labels start at `1`                  | Allocate arrays of size `n + 1`           |
| Edge endpoints already connected          | Do not merge; return that edge            |
| Graph has no cycle                        | Not possible under the stated constraints |

## 9. Interview follow-up questions

Q1. Why do we need both path compression and union by rank?

They improve the efficiency of DSU. Path compression flattens trees during `find`, while union by rank avoids building unnecessarily tall trees during `union`.

Q2. Could we use only a `parent` array without `rank`?

Yes. Basic Union-Find still works, but its worst-case performance can deteriorate without balancing. For an interview-ready implementation, use both optimizations.

Q3. What if the graph contains multiple cycles?

The same algorithm returns the first edge, in input order, that closes a cycle. However, with multiple cycles, that may not be the last edge among all possible removable edges. The exact requirement would need to be considered separately.

Q4. How would you solve the problem if edges were directed?

This is a different problem. Union-Find alone is not generally sufficient to handle directed-cycle or directed-tree constraints. You would need to account for direction and possibly nodes with multiple parents.

Q5. What is the connection between this problem and Minimum Spanning Tree (MST)?

Kruskal's algorithm also uses Union-Find. It processes edges in increasing weight order and skips edges whose endpoints are already connected, because those edges would create cycles. Here, we process edges in their given order and return the redundant edge instead of skipping it.

Recommendation: Master the Union-Find solution first. It is the standard interview approach for Redundant Connection and reinforces a reusable pattern for cycle detection, connected components, and Kruskal's MST algorithm.
