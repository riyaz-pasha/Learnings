# Last Day Where You Can Still Cross — Java 24

This problem is a classic graph-connectivity problem. The two most useful approaches are Binary Search + BFS/DFS and Reverse Flooding + Disjoint Set Union (DSU).

I'll build the intuition from the ground up, then show the solutions from brute force to optimal, with the reasoning, edge cases, and complexity explained directly inside the Java code comments.

## 0. Simplify the problem

Imagine a grid where:

- `0` means land — you can walk on it.
- `1` means water — you cannot walk on it.
- Every day, exactly one new cell becomes water.
- You may start at any land cell in the top row.
- You must reach at least one land cell in the bottom row.
- You can move up, down, left, or right, but not diagonally.

Our task is to find the last day on which a top-to-bottom path still exists.

### Example

Consider a `2 × 2` grid with these flooding events:

```
waterCells = [[1,1], [2,1], [1,2], [2,2]]
```

Initially, on day 0, all cells are land:

```
Day 0

L L
L L
```

On day 1, cell `(1,1)` floods:

```
Day 1

W L
L L
```

We can still cross using the right column.

On day 2, cell `(2,1)` floods:

```
Day 2

W L
W L
```

We can still cross using the right column.

On day 3, cell `(1,2)` floods:

```
Day 3

W W
W L
```

There is no land cell left in the top row, so crossing is impossible.

Therefore, the answer is day 2.

Notice that the question asks for the last successful day, not the day on which crossing first becomes impossible.

## 1. Clarifying questions to ask the interviewer

1. Can I start from any cell in the top row? Yes. This means we must consider all available top-row land cells, rather than a fixed starting position.
2. Can I finish at any cell in the bottom row? Yes. We only need to reach one bottom-row land cell.
3. Are movements restricted to four directions? Yes. Diagonal movement is not allowed, so connectivity is based on up, down, left, and right neighbors.
4. Is every cell flooded exactly once, and is the order guaranteed? Yes. `waterCells` contains every cell exactly once. This allows us to simulate days reliably and also process the flooding events in reverse.
5. What is the expected input size and complexity? The grid has at most 2,500 cells. BFS/DFS with binary search is already efficient enough, but reverse-time DSU offers a near-linear solution.

## 2. Core intuition

The key observation is that once crossing becomes impossible, it can never become possible again as the days progress.

Why?

Each day changes a land cell into water. We never turn water back into land in the forward direction. Removing land cannot create a new path that did not previously exist.

Therefore, the answer has a monotonic property:

```
Day:       0   1   2   3   4   5   6
Can cross: Y   Y   Y   Y   N   N   N
                       ^
                Last valid day = 3
```

This gives us two approaches.

- Approach A: Binary search over the day. Check whether crossing is possible on a chosen day using BFS or DFS.
- Approach B: Reverse the flooding process. Start with a fully flooded grid and restore land cells in reverse order. The first time the top and bottom become connected, the current day is the answer.

The second approach is the most efficient because it combines naturally with DSU.

## 3. Approach 1 — Brute force: Simulate every day and run BFS

### Intuition

Try every possible day in chronological order.

For each day:

1. Flood the cells that should be underwater by that day.
2. Start BFS from every land cell in the top row.
3. If BFS reaches any land cell in the bottom row, crossing is possible.
4. Remember that day as the answer.
5. Stop when crossing becomes impossible, because it will never become possible again.

### Java 24 code

```
import java.util.*;

class BruteForceSolution {

    private static final int[][] DIRECTIONS = {
        {-1, 0}, {1, 0}, {0, -1}, {0, 1}
    };

    public int latestDayToCross(int rows, int cols, int[][] waterCells) {
        boolean[][] land = new boolean[rows][cols];

        // Initially, every cell is land.
        for (boolean[] row : land) {
            Arrays.fill(row, true);
        }

        int lastValidDay = 0;

        // Day 0 is always crossable because the grid is entirely land.
        for (int day = 1; day <= waterCells.length; day++) {

            // Convert the 1-based coordinates from the problem to
            // Java's 0-based array indices.
            int r = waterCells[day - 1][0] - 1;
            int c = waterCells[day - 1][1] - 1;
            land[r][c] = false;

            // Test whether a path exists after this day's flooding.
            if (!canCross(land, rows, cols)) {
                // Since flooding only removes land, all later days
                // are also impossible. The previous day was the answer.
                return lastValidDay;
            }

            lastValidDay = day;
        }

        // With every cell flooded exactly once, this is unreachable
        // for valid inputs, but returning the last valid day is safe.
        return lastValidDay;
    }

    private boolean canCross(boolean[][] land, int rows, int cols) {
        boolean[][] visited = new boolean[rows][cols];
        Queue<int[]> queue = new ArrayDeque<>();

        // Any land cell in row 0 is a valid BFS starting point.
        for (int c = 0; c < cols; c++) {
            if (land[0][c]) {
                visited[0][c] = true;
                queue.offer(new int[]{0, c});
            }
        }

        while (!queue.isEmpty()) {
            int[] cell = queue.poll();
            int r = cell[0];
            int c = cell[1];

            // Reaching any cell in the last row completes the crossing.
            if (r == rows - 1) {
                return true;
            }

            for (int[] direction : DIRECTIONS) {
                int nr = r + direction[0];
                int nc = c + direction[1];

                if (nr < 0 || nr >= rows ||
                    nc < 0 || nc >= cols) {
                    continue;
                }

                // Only land cells can be traversed, and each cell
                // should enter the queue at most once.
                if (land[nr][nc] && !visited[nr][nc]) {
                    visited[nr][nc] = true;
                    queue.offer(new int[]{nr, nc});
                }
            }
        }

        return false;
    }
}
```

### Complexity

Let \\(N = rows \times cols\\).

- Time: \\(O(N^2)\\). There are at most \\(N\\) days to test, and each BFS visits at most \\(N\\) cells.
- Auxiliary space: \\(O(N)\\) for the land grid, visited grid, and BFS queue.

This works for the given constraints, but it repeats much of the same work on consecutive days.

## 4. Approach 2 — Binary search + BFS

### Intuition: Search for the boundary

We know the days have this structure:

```
Crossable:      Y Y Y Y Y
Not crossable:            N N N N

                            ^
                  Boundary between Y and N
```

Instead of testing every day, binary search finds the boundary.

For a candidate day `mid`:

1. Reconstruct the grid after flooding the first `mid` cells.
2. Run BFS to check whether crossing is possible.
3. If possible, search later days because we want the latest valid day.
4. If impossible, search earlier days.

The search range is from day `0` to day `N`.

### Why does binary search work?

Define `canCross(day)` as true if a crossing exists after flooding the first `day` cells.

This function is monotonic:

- If `canCross(day)` is true, every earlier day is also crossable.
- If `canCross(day)` is false, every later day is also not crossable.

So we can find the last true value using binary search.

### Java 24 code

```
import java.util.*;

class BinarySearchSolution {

    private static final int[][] DIRECTIONS = {
        {-1, 0}, {1, 0}, {0, -1}, {0, 1}
    };

    public int latestDayToCross(int rows, int cols, int[][] waterCells) {
        int low = 0;
        int high = waterCells.length;

        // Invariant:
        // - low is a day that is known to be crossable (day 0 is valid).
        // - high is an upper bound on the answer; day N is fully flooded.
        //
        // Find the greatest day for which canCross(day) is true.
        while (low < high) {
            // Upper midpoint is important: when low + 1 == high,
            // choosing the lower midpoint would fail to make progress.
            int mid = low + (high - low + 1) / 2;

            if (canCross(rows, cols, waterCells, mid)) {
                // This day works, so the answer may be this day
                // or a later one.
                low = mid;
            } else {
                // This day fails, and every later day also fails.
                high = mid - 1;
            }
        }

        return low;
    }

    private boolean canCross(
            int rows, int cols, int[][] waterCells, int day) {

        boolean[][] land = new boolean[rows][cols];

        // Begin with all cells as land.
        for (boolean[] row : land) {
            Arrays.fill(row, true);
        }

        // Apply exactly the first 'day' flooding events.
        for (int i = 0; i < day; i++) {
            int r = waterCells[i][0] - 1;
            int c = waterCells[i][1] - 1;
            land[r][c] = false;
        }

        boolean[][] visited = new boolean[rows][cols];
        Queue<int[]> queue = new ArrayDeque<>();

        // Multi-source BFS: every top-row land cell is a possible start.
        for (int c = 0; c < cols; c++) {
            if (land[0][c]) {
                visited[0][c] = true;
                queue.offer(new int[]{0, c});
            }
        }

        while (!queue.isEmpty()) {
            int[] current = queue.poll();
            int r = current[0];
            int c = current[1];

            if (r == rows - 1) {
                return true;
            }

            for (int[] direction : DIRECTIONS) {
                int nr = r + direction[0];
                int nc = c + direction[1];

                if (nr < 0 || nr >= rows ||
                    nc < 0 || nc >= cols) {
                    continue;
                }

                if (land[nr][nc] && !visited[nr][nc]) {
                    visited[nr][nc] = true;
                    queue.offer(new int[]{nr, nc});
                }
            }
        }

        return false;
    }
}
```

### Complexity

Let \\(N = rows \times cols\\).

- Time: \\(O(N\log N)\\). Binary search performs \\(O(\log N)\\) checks. Each check rebuilds the grid in \\(O(N)\\) and runs BFS in \\(O(N)\\).
- Auxiliary space: \\(O(N)\\) for the grid, visited matrix, and queue.

This is a good interview solution: the monotonic property leads directly to binary search.

## 5. Approach 3 — Optimal: Reverse flooding + DSU

This is the approach I would recommend presenting after explaining binary search.

### Step 1: Think backward

Forward in time, land becomes water:

```
All land  →  Some water  →  More water  →  All water
```

Reversing time gives us:

```
All water  →  Restore land  →  Restore more land  →  All land
```

Instead of removing connectivity every day, we now add connectivity as land is restored.

This is exactly what a Disjoint Set Union (DSU) data structure handles efficiently.

### Step 2: What does DSU do?

DSU maintains connected components. Each cell belongs to a component of connected land cells.

It supports two key operations:

- `find(x)`: identify the representative of the component containing `x`.
- `union(a, b)`: merge the components containing `a` and `b`.

Two cells are connected if their representatives are equal.

We also use two virtual nodes:

- `TOP`: connected to every land cell in the top row.
- `BOTTOM`: connected to every land cell in the bottom row.

The crossing condition becomes:

```
dsu.find(TOP) == dsu.find(BOTTOM)
```

Why? Because a connected component containing both virtual nodes has a land path from the top row to the bottom row.

### Step 3: Restore cells in reverse order

Suppose the original flooding events are:

```
Day 1: A becomes water
Day 2: B becomes water
Day 3: C becomes water
```

We begin with all cells underwater, corresponding to day `N`.

Then restore:

```
Restore C → equivalent to undoing day 3 → day 2
Restore B → equivalent to undoing day 2 → day 1
Restore A → equivalent to undoing day 1 → day 0
```

The first time `TOP` and `BOTTOM` become connected, we have found the latest day that was still crossable.

More precisely, if restoring `waterCells[i]` creates the connection, the answer is `i`, using the problem's 1-based day numbering.

### Example: `2 × 2` grid

Flooding order:

```
waterCells = [[1,1], [2,1], [1,2], [2,2]]
```

Start at day 4, with all water.

| Reverse operation | Equivalent day | Crossing?         |
| ----------------- | -------------- | ----------------- |
| Restore `(2,2)`   | 3              | No                |
| Restore `(1,2)`   | 2              | Yes               |
| Restore `(2,1)`   | 1              | Already connected |
| Restore `(1,1)`   | 0              | Already connected |

When `(1,2)` is restored, the right column becomes a complete path from top to bottom. This reverses the flooding event from day 3, so the latest successful forward day is 2.

### Java 24 code

```
class ReverseDSUSolution {

    private static final int[][] DIRECTIONS = {
        {-1, 0}, {1, 0}, {0, -1}, {0, 1}
    };

    public int latestDayToCross(int rows, int cols, int[][] waterCells) {
        int total = rows * cols;

        // Every grid cell receives an ID in [0, total - 1].
        // Virtual nodes are placed after all real cells.
        int TOP = total;
        int BOTTOM = total + 1;

        DSU dsu = new DSU(total + 2);

        // Initially, day N: every cell is water.
        // 'land' records which cells have been restored while going backward.
        boolean[][] land = new boolean[rows][cols];

        // Undo the flooding events from last to first.
        for (int i = total - 1; i >= 0; i--) {
            // The i-th event in Java corresponds to forward day i + 1.
            int r = waterCells[i][0] - 1;
            int c = waterCells[i][1] - 1;

            // Restore this cell to land.
            land[r][c] = true;

            // Map a (row, col) coordinate to a unique DSU ID.
            int current = r * cols + c;

            // Connect this land cell to the virtual top/bottom nodes
            // when it lies on the corresponding boundary.
            if (r == 0) {
                dsu.union(current, TOP);
            }

            if (r == rows - 1) {
                dsu.union(current, BOTTOM);
            }

            // Connect the restored land cell to all adjacent land cells.
            // We only need to check four neighbors because diagonal
            // movement is not permitted by the problem.
            for (int[] direction : DIRECTIONS) {
                int nr = r + direction[0];
                int nc = c + direction[1];

                if (nr < 0 || nr >= rows ||
                    nc < 0 || nc >= cols) {
                    continue;
                }

                if (land[nr][nc]) {
                    int neighbor = nr * cols + nc;
                    dsu.union(current, neighbor);
                }
            }

            // The first connection encountered while restoring cells
            // is the reverse of the day on which crossing was lost.
            //
            // waterCells[i] flooded on forward day i + 1.
            // Restoring it takes us back to day i.
            //
            // Therefore, return i, NOT i + 1.
            if (dsu.find(TOP) == dsu.find(BOTTOM)) {
                return i;
            }
        }

        // Day 0 is entirely land, so a crossing always exists
        // for the valid positive grid dimensions in this problem.
        return 0;
    }

    // DSU with path compression and union by size.
    private static class DSU {
        private final int[] parent;
        private final int[] size;

        DSU(int n) {
            parent = new int[n];
            size = new int[n];

            for (int i = 0; i < n; i++) {
                parent[i] = i;
                size[i] = 1;
            }
        }

        // Find the representative of x's connected component.
        // Path compression flattens the tree, making future finds faster.
        int find(int x) {
            if (parent[x] != x) {
                parent[x] = find(parent[x]);
            }
            return parent[x];
        }

        // Merge two components, attaching the smaller tree to the larger.
        // This keeps the trees shallow and makes operations nearly O(1)
        // amortized when combined with path compression.
        void union(int a, int b) {
            int rootA = find(a);
            int rootB = find(b);

            if (rootA == rootB) {
                return;
            }

            if (size[rootA] < size[rootB]) {
                int temp = rootA;
                rootA = rootB;
                rootB = temp;
            }

            parent[rootB] = rootA;
            size[rootA] += size[rootB];
        }
    }
}
```

### Complexity

Let \\(N = rows \times cols\\).

- Time: \\(O(N\alpha(N))\\), where \\(\alpha(N)\\) is the inverse Ackermann function. We restore each cell once and perform a constant number of DSU operations per cell. With path compression and union by size, these operations are effectively constant time for practical input sizes.
- Auxiliary space: \\(O(N)\\) for the land matrix and DSU arrays. The four-direction array occupies constant space.

This is asymptotically better than binary search + BFS, which takes \\(O(N\log N)\\).

## 6. Compare all approaches

| Approach               | Time                | Auxiliary space | Main idea                            |
| ---------------------- | ------------------- | --------------- | ------------------------------------ |
| Brute force + BFS      | \\(O(N^2)\\)        | \\(O(N)\\)      | Check every day                      |
| Binary search + BFS    | \\(O(N\log N)\\)    | \\(O(N)\\)      | Search for the last valid day        |
| Reverse flooding + DSU | \\(O(N\alpha(N))\\) | \\(O(N)\\)      | Restore land and detect connectivity |

Interview recommendation: Start with brute force to establish correctness, use monotonicity to derive binary search, and then present reverse-time DSU as the optimal solution.

## 7. Important edge cases

1. Day 0: The entire grid is land, so crossing is always possible.
2. No land in the top row: Crossing is immediately impossible for that day.
3. No land in the bottom row: Crossing is impossible because there is nowhere to finish.
4. A single narrow path: Flooding one critical cell may disconnect the top from the bottom.
5. Multiple possible starting cells: BFS must begin from all top-row land cells. In DSU, every top-row land cell must connect to `TOP`.
6. Off-by-one errors: Flooding event `waterCells[i]` occurs on day `i + 1`, but undoing that event returns us to day `i`. The reverse DSU solution must return `i`.
7. Coordinate conversion: Input coordinates are 1-based, but Java array indices are 0-based.
8. Diagonal connectivity: Two diagonally adjacent land cells are not connected unless an orthogonal path exists.

## 8. Interviewer follow-up questions and answers

Q1. Why not use DSU directly while flooding cells forward?

Standard DSU efficiently merges connected components but does not efficiently split them. Flooding removes land and can disconnect a component. Reversing the process turns removals into additions, which DSU handles efficiently.

Q2. Why do we need virtual `TOP` and `BOTTOM` nodes?

Without them, we would have to check every top-row cell against every bottom-row cell. Virtual nodes turn the crossing condition into a single connectivity check:

```
dsu.find(TOP) == dsu.find(BOTTOM)
```

Q3. Why connect a restored cell to all four neighbors?

A restored land cell may connect previously separate land components. Checking all four orthogonal neighbors ensures that every valid new connection is discovered.

Q4. Why is binary search valid even though the grid changes every day?

The grid changes, but the answer to the feasibility question is monotonic. Once crossing becomes impossible, further flooding cannot restore a path. Binary search needs this monotonicity, not an unchanged grid.

Q5. Can we use DFS instead of BFS?

Yes. Both explore the connected land cells and take \\(O(N)\\) time for a single grid. BFS is often easier to explain iteratively, while recursive DFS can risk stack overflow on larger grids in languages with limited call stacks.

Q6. What if we wanted to find the earliest day on which crossing becomes impossible?

It is exactly one day after the latest successful day. If the answer is `d`, the earliest impossible day is `d + 1`, because one cell floods per day.

Q7. Can we optimize beyond reverse DSU?

For this problem, reverse DSU is an excellent asymptotic solution. With \\(N \le 2500\\), binary search + BFS is also entirely practical and may be simpler to implement correctly under interview pressure.

Final takeaway: The hardest part is not implementing DSU. It is recognizing that reversing the flood turns a difficult connectivity-removal problem into an easy connectivity-addition problem. Once that insight clicks, the algorithm becomes straightforward.

Let's forget the code for a moment and understand the problem as if we're solving it on a whiteboard in an interview.

The most important thing to understand is why we reverse the flooding process. Once that makes sense, the DSU solution becomes much easier.

# 1. First, understand what we're trying to find

Imagine a grid with 3 rows and 3 columns.

- `L` = land, so we can walk on it.
- `W` = water, so we cannot walk on it.

Initially, the entire grid is land:

```
        Column
         1 2 3
       ┌───────┐
Row 1  │ L L L │  ← Start anywhere here
Row 2  │ L L L │
Row 3  │ L L L │  ← Reach anywhere here
       └───────┘
```

We want to travel from the top row to the bottom row.

For example, we can walk down the first column:

```
L L L
↓
L L L
↓
L L L
```

Now suppose the cell `(2,1)` becomes water:

```
L L L
W L L
L L L
```

The first column is blocked, but we can still cross using the second column.

```
L → L → L
    ↓
W   L   L
    ↓
L   L   L
```

The important point: we do not need a particular path. We only need some path from any top-row land cell to any bottom-row land cell.

As more cells become water, our possible paths gradually disappear.

Our task is to identify the last day before every possible crossing has been blocked.

# 2. Approach 1: Solve it the obvious way first

Suppose there are 9 cells.

We could do this:

1. Flood one cell.
2. Check whether a crossing still exists.
3. Flood another cell.
4. Check again.
5. Repeat until crossing becomes impossible.

How do we check whether crossing exists? Use BFS.

BFS starts from every land cell in the top row, explores neighboring land cells, and succeeds if it reaches the bottom row.

For example:

```
L W W
L W W
L L W
```

BFS can travel down the first column and then move right on the bottom row. Crossing is possible.

But in this grid:

```
L W W
W L W
L L W
```

The top-left cell has no land neighbor connecting it to the bottom. The middle land cells cannot be reached from the top. Crossing is impossible.

This brute-force method works, but it repeats a lot of BFS work.

Can we do better?

# 3. The key observation: Flooding only makes things worse

Think about the following sequence:

```
Day 0: Crossing possible
Day 1: Crossing possible
Day 2: Crossing possible
Day 3: Crossing impossible
Day 4: Crossing impossible
Day 5: Crossing impossible
```

Once crossing becomes impossible, adding more water cannot create a new land path.

This gives us a useful property:

- Earlier days are easier to cross.
- Later days are harder to cross.
- There is one boundary between the last successful day and the first unsuccessful day.

We could use binary search to find this boundary. But there is an even more interesting observation.

## What if we reverse time?

Forward in time, we do this:

```
All land → Less land → Even less land → All water
```

Instead, imagine starting with all water and restoring the land cells in reverse order:

```
All water → A little land → More land → All land
```

Now the situation improves with every step.

This is powerful because DSU is excellent at maintaining connectivity when we add land cells, but not when we remove land cells.

Let's understand exactly why.

## Reverse direction: Undo each flood

The final day is day 4, when every cell is water.

```
Day 4

W W
W W
```

We restore cells in the opposite order from `waterCells`.

That means:

1. Restore D.
2. Restore B.
3. Restore C.
4. Restore A.

Notice something important: restoring D takes us from day 4 back to day 3. Restoring B takes us from day 3 back to day 2.

Let's walk through this carefully.

### Reverse step 1: Restore D

We restore `(2,2)`:

```
W W
W L
```

Can we cross? No, because there is no land in the top row.

The virtual top and bottom are not connected.

### Reverse step 2: Restore B

We restore `(1,2)`:

```
W L
W L
```

Now the right column is entirely land.

```
TOP
 |
 B
 |
 D
 |
BOTTOM
```

We have connected the top to the bottom!

But remember, we are going backward.

We just restored the cell that flooded on day 3. Therefore, we have undone day 3 and returned to day 2.

That is our answer.

The key relationship is:

| Reverse operation           | Forward day we return to |
| --------------------------- | ------------------------ |
| Restore `waterCells[3]` (D) | Day 3                    |
| Restore `waterCells[2]` (B) | Day 2                    |
| Restore `waterCells[1]` (C) | Day 1                    |
| Restore `waterCells[0]` (A) | Day 0                    |

Array indices are zero-based, but flooding days are one-based. If restoring `waterCells[i]` reconnects the grid, return `i`.

This is the central insight of the entire algorithm.

# 5. But how does DSU know that B and D are connected?

This is the next important piece.

DSU stands for Disjoint Set Union. Think of it as a system that keeps track of groups of connected land cells.

It gives us two operations:

- `find(x)`: Which group does cell `x` belong to?
- `union(a, b)`: Put the groups containing `a` and `b` together.

We don't need to explicitly store every path. We only need to know which cells belong to the same connected component.

## Step 1: Give every cell a number

For a `2 × 2` grid, we can assign IDs like this:

```
  0   1
  2   3
```

So:

```
A = 0
B = 1
C = 2
D = 3
```

For a grid with `cols` columns, the formula is:

```
int id = row * cols + col;
```

Remember that `row` and `col` are zero-based.

For example, D has coordinates `(1,1)` in Java indexing:

```
int id = 1 * 2 + 1; // 3
```

Every cell has a unique ID.

## Step 2: Add two imaginary cells

We create two extra DSU nodes:

```
TOP
BOTTOM
```

These are not real cells in the grid.

Their purpose is to simplify the question:

> Is there a connected land path from any cell in the top row to any cell in the bottom row?

Whenever we restore a land cell in the top row, connect it to `TOP`.

Whenever we restore a land cell in the bottom row, connect it to `BOTTOM`.

For our example:

```
TOP       BOTTOM
 |           |
 B           D
```

If B and D become connected, then TOP and BOTTOM become connected too.

We can check this with one condition:

```
dsu.find(TOP) == dsu.find(BOTTOM)
```

If both have the same representative, they belong to the same connected component, meaning a crossing exists.

## Step 3: Connect adjacent land cells

Suppose B is restored while D is already land:

```
W B
W D
```

B is at `(0,1)` and D is at `(1,1)`.

They are vertical neighbors, so we merge their DSU groups:

```
dsu.union(B, D);
```

We also connect B to `TOP` and D to `BOTTOM`.

Conceptually, the group becomes:

```
TOP
 |
 B
 |
 D
 |
BOTTOM
```

The two virtual nodes now belong to the same group.

That's all DSU needs to know. It does not need to remember the actual route `B → D`.

## Step 4: Why check all four directions?

A restored cell can connect to previously restored land in any of these directions:

```
        UP
         |
LEFT — CURRENT — RIGHT
         |
       DOWN
```

For every neighbor, we check:

1. Is it inside the grid?
2. Is it already land?
3. If yes, merge its group with the current cell's group.

We do not connect diagonally because diagonal movement is forbidden.

# 6. The complete optimal Java 24 solution

Here is the code again, with the reasoning explained at each important step. You can use this as your interview-ready implementation.

```
import java.util.Arrays;

class Solution {

    // These are the only legal moves in the problem.
    // We cannot move diagonally.
    private static final int[][] DIRECTIONS = {
        {-1, 0}, // Up
        { 1, 0}, // Down
        { 0,-1}, // Left
        { 0, 1}  // Right
    };

    public int latestDayToCross(int rows, int cols, int[][] waterCells) {

        int totalCells = rows * cols;

        // Real grid cells use IDs 0 through totalCells - 1.
        // The two additional IDs represent imaginary boundary nodes.
        int TOP = totalCells;
        int BOTTOM = totalCells + 1;

        DSU dsu = new DSU(totalCells + 2);

        // Initially, we are at the final day: every cell is water.
        // land[r][c] becomes true only when we restore that cell.
        boolean[][] land = new boolean[rows][cols];

        // Process flooding events backward.
        //
        // waterCells[i] was flooded on forward day i + 1.
        // Restoring that cell reverses the flood and returns us to day i.
        //
        // We move from the last event toward the first event.
        for (int i = totalCells - 1; i >= 0; i--) {

            // Convert the problem's 1-based coordinates into
            // Java's 0-based row and column indices.
            int r = waterCells[i][0] - 1;
            int c = waterCells[i][1] - 1;

            // Step 1: Restore this cell from water to land.
            land[r][c] = true;

            // Step 2: Convert its grid coordinates to a unique DSU ID.
            int current = r * cols + c;

            // Step 3: Connect the restored cell to the virtual boundaries.
            //
            // Any top-row land cell can be a starting point.
            if (r == 0) {
                dsu.union(current, TOP);
            }

            // Any bottom-row land cell can be a destination.
            if (r == rows - 1) {
                dsu.union(current, BOTTOM);
            }

            // Step 4: Connect this cell to all neighboring land cells.
            for (int[] direction : DIRECTIONS) {

                int nr = r + direction[0];
                int nc = c + direction[1];

                // Ignore neighbors outside the grid.
                if (nr < 0 || nr >= rows ||
                    nc < 0 || nc >= cols) {
                    continue;
                }

                // A water neighbor cannot be part of a land path.
                // Only merge cells if the neighbor has already
                // been restored and is currently land.
                if (land[nr][nc]) {
                    int neighbor = nr * cols + nc;

                    // Merge the two connected components.
                    dsu.union(current, neighbor);
                }
            }

            // Step 5: Check whether a complete crossing now exists.
            //
            // If TOP and BOTTOM have the same representative, there is
            // a connected chain of land cells from the top to the bottom.
            if (dsu.find(TOP) == dsu.find(BOTTOM)) {

                // CRITICAL OFF-BY-ONE DETAIL:
                //
                // waterCells[i] flooded on forward day i + 1.
                // We have just undone that event, so we are back on day i.
                //
                // This is the latest successful forward day.
                return i;
            }
        }

        // Day 0 has every cell as land, so a crossing always exists.
        // For valid input, the loop must eventually find the connection.
        return 0;
    }

    private static class DSU {

        // parent[x] tells us the parent of node x in the DSU tree.
        private final int[] parent;

        // size[x] is the size of the component whose root is x.
        // It is used to merge smaller components into larger ones.
        private final int[] size;

        DSU(int n) {
            parent = new int[n];
            size = new int[n];

            // Initially, every cell and virtual node is its own component.
            for (int i = 0; i < n; i++) {
                parent[i] = i;
                size[i] = 1;
            }
        }

        int find(int x) {

            // If x is its own parent, it is the representative of its group.
            if (parent[x] == x) {
                return x;
            }

            // Path compression:
            // Make x point directly to the root, so future find operations
            // can reach the representative faster.
            return parent[x] = find(parent[x]);
        }

        void union(int a, int b) {

            // Find the representatives of the two groups.
            int rootA = find(a);
            int rootB = find(b);

            // Already connected: merging them again is unnecessary.
            if (rootA == rootB) {
                return;
            }

            // Union by size:
            // Attach the smaller component to the larger one.
            // This prevents DSU trees from becoming unnecessarily deep.
            if (size[rootA] < size[rootB]) {
                int temp = rootA;
                rootA = rootB;
                rootB = temp;
            }

            // Merge rootB's component into rootA's component.
            parent[rootB] = rootA;
            size[rootA] += size[rootB];
        }
    }
}
```

Input:

```
rows = 2;

waterCells = new int[][] {
    {1, 1},

    {2, 2}
```

The IDs are:

```
0 1
2 3
```

And the virtual nodes are `TOP = 4`, `BOTTOM = 5`.

Initially, all real cells are water, so no cell is connected to either virtual node.

| Loop index `i` | Cell restored  | What happens?                          | TOP connected to BOTTOM? |
| -------------- | -------------- | -------------------------------------- | ------------------------ |
| 3              | `(2,2)` = ID 3 | Connect ID 3 to BOTTOM                 | No                       |

Why does the second iteration connect the two boundaries?

After restoring `(1,2)`, the grid is:

```
W L
W L
```

Cell 1 is connected to `TOP`. Cell 3 is connected to `BOTTOM`. Because these cells are neighbors, `union(1, 3)` puts them in the same component.

Consequently:

```
dsu.find(TOP) == dsu.find(BOTTOM)
```

is true, and the algorithm returns `2`.

# 8. Complexity: Why is reverse DSU optimal?

Let \\(N = rows \times cols\\).

- Time complexity: \\(O(N\alpha(N))\\). Every cell is restored once. For each restored cell, we check four neighbors and perform a constant number of DSU operations. Path compression and union by size make those operations nearly constant time.
- Auxiliary space: \\(O(N)\\). The land matrix uses \\(O(N)\\) space. The DSU parent and size arrays also use \\(O(N)\\) space. The direction array has constant size.

For the given maximum of 2,500 cells, all three approaches are practical. Reverse DSU is asymptotically the fastest.

# 9. Common mistakes to avoid

Mistake 1: Returning `i + 1` instead of `i`.

The flooding event at index `i` happens on day `i + 1`. But in reverse, restoring that cell takes us back to day `i`. Return `i`.

Mistake 2: Forgetting that any top cell can be a starting point.

That is why we connect every restored top-row cell to `TOP`, not just the first column.

Mistake 3: Connecting water cells.

Only restored cells have `land[r][c] == true`. A water cell must never be merged as a neighbor.

Mistake 4: Thinking DSU stores the actual path.

DSU stores connected components, not the sequence of cells in a route. If TOP and BOTTOM have the same representative, connectivity guarantees that a path exists.

Mistake 5: Trying to undo DSU operations.

We don't undo DSU operations. We start with no land and add cells in reverse chronological order, so every DSU operation is a union.

# 10. What you should remember in an interview

The entire algorithm comes down to four steps:

1. Start with all cells as water.
2. Restore cells in reverse order of `waterCells`.
3. Use DSU to merge each restored cell with neighboring land and the virtual boundaries.
4. The first time `TOP` and `BOTTOM` become connected, return the current array index.

The most important mental model is this:

Forward flooding removes land and can break connectivity. Reverse flooding adds land and can create connectivity. DSU efficiently tracks that connectivity as it grows.

If you remember why reversing time changes the problem into something DSU can solve efficiently, you understand the core idea—not just the code.
