# Path Exists in Graph — Java 24 Solutions

This is a fundamental graph problem commonly known as Find if Path Exists in Graph (LeetCode 1971).

The goal is to determine whether we can travel from `source` to `destination` using zero or more edges in an undirected graph.

There are three useful approaches:

1. BFS (Breadth-First Search) — explore neighbors level by level.
2. DFS (Depth-First Search) — explore one path as deeply as possible.
3. Union-Find / DSU — determine whether both vertices belong to the same connected component.

For this problem, I recommend learning BFS/DFS first, then Union-Find. All three are useful, but the best choice depends on whether you need to traverse the graph or only check connectivity.

## 1. Understand the problem

Suppose we have:

Example graph

Edges: [[0,1], [1,3], [0,2], [2,3], [3,4]]

For `source = 0` and `destination = 4`, the answer is `true`.

One valid path is:

`0 → 1 → 3 → 4`

We do not need to find the shortest path. We only need to establish whether at least one path exists.

### Important observations

- Edges are bidirectional: if `0` connects to `1`, then `1` also connects to `0`.
- A vertex can have multiple neighbors.
- The graph can be disconnected.
- If `source == destination`, the answer is always `true`: a path of zero edges is sufficient.
- The graph can contain cycles, so BFS and DFS need a `visited` array.

## 2. Solution 1 — BFS (recommended starting solution)

### Intuition

Think of dropping a stone into water. The ripple spreads outward from the starting point.

BFS works similarly:

1. Start from `source`.
2. Put it into a queue.
3. Remove one vertex from the queue.
4. Examine all its neighbors.
5. Add every unvisited neighbor to the queue.
6. If we encounter `destination`, return `true`.
7. If the queue becomes empty, return `false`.

The `visited` array ensures we don't repeatedly process the same vertex, especially when the graph contains cycles.

### Java 24 code — fully commented

```

import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;
import java.util.Queue;

class Solution {

    public boolean validPath(
            int n,
            int[][] edges,
            int source,
            int destination) {

        // If we start and end at the same vertex, the path exists
        // without traversing any edge.
        if (source == destination) {
            return true;
        }

        // Step 1: Build an adjacency list.
        // graph.get(u) contains every vertex directly connected to u.
        List<List<Integer>> graph = new ArrayList<>();

        for (int i = 0; i < n; i++) {
            graph.add(new ArrayList<>());
        }

        // The graph is undirected, so add both directions.
        for (int[] edge : edges) {
            int u = edge[0];
            int v = edge[1];

            graph.get(u).add(v);
            graph.get(v).add(u);
        }

        // Step 2: Track which vertices have already been discovered.
        boolean[] visited = new boolean[n];

        // Step 3: BFS explores discovered vertices in FIFO order.
        Queue<Integer> queue = new ArrayDeque<>();

        // Begin the search at the source.
        queue.offer(source);
        visited[source] = true;

        // Step 4: Continue while there are vertices to explore.
        while (!queue.isEmpty()) {

            // Process the oldest discovered vertex first.
            int current = queue.poll();

            // We reached the required destination.
            if (current == destination) {
                return true;
            }

            // Step 5: Explore every neighbor of the current vertex.
            for (int neighbor : graph.get(current)) {

                // Ignore vertices already discovered.
                if (visited[neighbor]) {
                    continue;
                }

                // Mark BEFORE adding to the queue.
                // This prevents the same vertex from being added
                // multiple times through different edges.
                visited[neighbor] = true;
                queue.offer(neighbor);
            }
        }

        // The entire reachable component has been explored.
        // The destination was never reached.
        return false;
    }
}

```

### Why use an adjacency list?

An adjacency list stores only the edges that actually exist.

For example, given:

```
int[][] edges = {
    {0, 1},
    {0, 2},
    {1, 3}
};
```

The adjacency list becomes:

```
0 -> [1, 2]
1 -> [0, 3]
2 -> [0]
3 -> [1]
```

Notice that we insert both `u → v` and `v → u` because the graph is bidirectional.

### Dry run

Input:

```
n = 5
edges = [[0,1], [1,3], [0,2], [2,3], [3,4]]
source = 0
destination = 4
```

| Step | Action                             | Queue after processing | Visited vertices |
| ---- | ---------------------------------- | ---------------------- | ---------------- |
| 1    | Start at `0`                       | `[0]`                  | `{0}`            |
| 2    | Remove `0`; discover `1, 2`        | `[1, 2]`               | `{0,1,2}`        |
| 3    | Remove `1`; discover `3`           | `[2, 3]`               | `{0,1,2,3}`      |
| 4    | Remove `2`; `3` is already visited | `[3]`                  | `{0,1,2,3}`      |
| 5    | Remove `3`; discover `4`           | `[4]`                  | `{0,1,2,3,4}`    |
| 6    | Remove `4`; destination reached    | `[]`                   | All five         |

Result: `true`.

Vertex `3` is not added twice, even though both `1` and `2` connect to it.

### Complexity

Let \\(V=n\\) and \\(E=\text{edges.length}\\).

- Time: \\(O(V+E)\\). Building the adjacency list and traversing the graph each take linear time.
- Space: \\(O(V+E)\\) total, including the adjacency list. The visited array and queue use \\(O(V)\\) additional space.

## 3. Solution 2 — DFS (Depth-First Search)

### Intuition

Instead of spreading outward level by level, DFS follows one route as far as possible before backtracking.

For example:

```
0 → 1 → 3 → 4
```

If that route doesn't reach the destination, DFS explores other unexplored neighbors.

DFS is equally valid for a simple reachability check.

### Java 24 code — iterative DFS

An iterative implementation uses a stack. It avoids recursion-depth issues on large graphs.

```

import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.List;
import java.util.Deque;

class Solution {

    public boolean validPath(
            int n,
            int[][] edges,
            int source,
            int destination) {

        // A vertex is always reachable from itself.
        if (source == destination) {
            return true;
        }

        // Build the adjacency list for the undirected graph.
        List<List<Integer>> graph = new ArrayList<>();

        for (int i = 0; i < n; i++) {
            graph.add(new ArrayList<>());
        }

        for (int[] edge : edges) {
            int u = edge[0];
            int v = edge[1];

            graph.get(u).add(v);
            graph.get(v).add(u);
        }

        // Track discovered vertices to avoid cycles.
        boolean[] visited = new boolean[n];

        // A stack gives DFS its last-in, first-out behavior.
        Deque<Integer> stack = new ArrayDeque<>();

        stack.push(source);
        visited[source] = true;

        while (!stack.isEmpty()) {

            // Explore the most recently discovered vertex.
            int current = stack.pop();

            // We found a path to the destination.
            if (current == destination) {
                return true;
            }

            for (int neighbor : graph.get(current)) {

                if (visited[neighbor]) {
                    continue;
                }

                // Mark when discovered, before pushing.
                visited[neighbor] = true;
                stack.push(neighbor);
            }
        }

        // Every vertex reachable from source was explored.
        return false;
    }
}

```

### Why use a stack instead of a queue?

- Queue: first in, first out — BFS.
- Stack: last in, first out — DFS.

The underlying graph representation and `visited` logic are identical. Only the traversal order changes.

### Recursive DFS alternative

Recursive DFS is concise and is often useful for understanding the pattern:

```
private boolean dfs(
        int current,
        int destination,
        List<List<Integer>> graph,
        boolean[] visited) {

    // The destination has been reached.
    if (current == destination) {
        return true;
    }

    // Prevent revisiting this vertex through a cycle.
    visited[current] = true;

    for (int neighbor : graph.get(current)) {

        if (!visited[neighbor]) {

            // If any recursive path reaches the destination,
            // the entire chain returns true.
            if (dfs(neighbor, destination, graph, visited)) {
                return true;
            }
        }
    }

    // No unexplored path from this vertex reached the target.
    return false;
}
```

Call it after constructing the adjacency list:

```
return dfs(source, destination, graph, new boolean[n]);
```

The helper belongs inside the same `Solution` class as `validPath`.

Complexity for both DFS implementations:

- Time: \\(O(V+E)\\).
- Space: \\(O(V+E)\\) including the graph; \\(O(V)\\) auxiliary space for the visited array and stack or recursion.

The iterative version is generally safer when graph depth can be large.

## 4. Solution 3 — Union-Find (Disjoint Set Union / DSU)

This is the solution I would learn next for your Union-Find pattern practice.

### Intuition: think in connected groups

Instead of physically travelling from `source` to `destination`, we can identify which vertices belong to the same connected component.

Initially, every vertex is in its own group:

```
{0}  {1}  {2}  {3}  {4}
```

For every edge `[u, v]`, merge the groups containing `u` and `v`.

For example, using edges `[[0,1], [1,3], [0,2], [2,3], [3,4]]`:

```
Initially:       {0} {1} {2} {3} {4}
Union(0,1):      {0,1} {2} {3} {4}
Union(1,3):      {0,1,3} {2} {4}
Union(0,2):      {0,1,2,3} {4}
Union(2,3):      No new merge; already connected
Union(3,4):      {0,1,2,3,4}
```

Now `0` and `4` belong to the same group, so the answer is `true`.

The key observation is:

> Every edge connects its two vertices into the same connected component. After processing all edges, two vertices are connected if and only if they have the same representative (root).

### Java 24 code — complete DSU solution

```

class Solution {

    public boolean validPath(
            int n,
            int[][] edges,
            int source,
            int destination) {

        // Zero edges are sufficient when both endpoints are identical.
        if (source == destination) {
            return true;
        }

        // Initially, every vertex is its own connected component.
        DSU dsu = new DSU(n);

        // Every edge says its two endpoints are connected.
        for (int[] edge : edges) {
            int u = edge[0];
            int v = edge[1];

            // Merge the components containing u and v.
            dsu.union(u, v);
        }

        // Same root means the vertices belong to the same component.
        return dsu.find(source) == dsu.find(destination);
    }

    private static class DSU {

        // parent[x] stores the parent of vertex x in the DSU tree.
        private final int[] parent;

        // size[x] stores the size of the component rooted at x.
        // Only root sizes are used when merging components.
        private final int[] size;

        DSU(int n) {
            parent = new int[n];
            size = new int[n];

            for (int i = 0; i < n; i++) {
                // Initially, each vertex is its own root.
                parent[i] = i;
                size[i] = 1;
            }
        }

        int find(int x) {

            // A root is the representative of its component.
            if (parent[x] == x) {
                return x;
            }

            // Path compression:
            // Connect x directly to the root found recursively.
            // Future find operations on x become faster.
            parent[x] = find(parent[x]);

            return parent[x];
        }

        void union(int a, int b) {

            // Find the representatives of both components.
            int rootA = find(a);
            int rootB = find(b);

            // Already in the same component: nothing to merge.
            if (rootA == rootB) {
                return;
            }

            // Union by size:
            // Attach the smaller component under the larger one.
            if (size[rootA] < size[rootB]) {
                int temp = rootA;
                rootA = rootB;
                rootB = temp;
            }

            // rootA remains the root; rootB becomes its child.
            parent[rootB] = rootA;

            // Update the size of the surviving component.
            size[rootA] += size[rootB];
        }
    }
}

```

### Why do we need both `find()` and `union()`?

- `find(x)` answers: which component does `x` belong to?
- `union(a, b)` merges the components containing `a` and `b`.

Two important optimizations make DSU efficient:

1. Path compression: during `find`, make nodes point directly to their root.
2. Union by size: attach the smaller component beneath the larger one, keeping trees shallow.

### Complexity

With path compression and union by size:

- Time: \\(O(V + E\alpha(V))\\), including initialization and all unions. The inverse Ackermann function \\(\alpha(V)\\) grows so slowly that DSU operations are effectively constant time for practical input sizes.
- Space: \\(O(V)\\) auxiliary space for `parent` and `size`.

Unlike BFS and DFS, DSU does not require an adjacency list.

## 5. Which solution should you use?

| Approach      | Time                  | Extra space\* | Best use case                                      |
| ------------- | --------------------- | ------------- | -------------------------------------------------- |
| BFS           | \\(O(V+E)\\)          | \\(O(V)\\)    | Reachability; shortest path in an unweighted graph |
| Iterative DFS | \\(O(V+E)\\)          | \\(O(V)\\)    | Reachability; exploring graph structure            |
| Recursive DFS | \\(O(V+E)\\)          | \\(O(V)\\)    | Concise recursive traversal                        |
| Union-Find    | \\(O(V+E\alpha(V))\\) | \\(O(V)\\)    | Connectivity queries without traversal             |

\*Extra space excludes the input. BFS/DFS also require an adjacency list of \\(O(V+E)\\) space, whereas DSU does not.

My recommendation for this particular problem:

- If you are learning graph traversal, implement BFS first.
- If you are practicing the Union-Find pattern, implement DSU and understand why processing every edge determines connectivity.
- If you need to answer many path queries on the same graph, preprocess the connected components with DSU or DFS/BFS, then answer each query efficiently.

## 6. Edge cases to remember

| Input situation                                   | Expected result         | Reason                                                                       |
| ------------------------------------------------- | ----------------------- | ---------------------------------------------------------------------------- |
| `source == destination`                           | `true`                  | Zero-edge path exists                                                        |
| `edges = []`, `source != destination`             | `false`                 | No vertices are connected                                                    |
| `n = 1`, `source = destination = 0`               | `true`                  | Only one vertex exists                                                       |
| Direct edge `[source, destination]`               | `true`                  | One-edge path exists                                                         |
| Path exists through several intermediate vertices | `true`                  | Direct connection is unnecessary                                             |
| Source and destination are in separate components | `false`                 | No sequence of edges connects them                                           |
| Graph contains cycles                             | Depends on connectivity | `visited` prevents infinite traversal; DSU detects already-merged components |

## 7. How to derive this in an interview

When you see this problem, ask yourself these questions in order.

Question 1: What does “a valid path exists” mean?

It means the destination is reachable from the source through zero or more edges.

Question 2: Do I need the shortest path?

No. The problem asks only whether a path exists, so we do not need shortest-path algorithms such as Dijkstra's algorithm.

Question 3: How can I explore all reachable vertices?

Use BFS or DFS. Start at the source and mark vertices as visited to avoid cycles.

Question 4: Can I solve it without traversing the graph?

Yes. Since every edge connects two vertices into the same connected component, DSU can merge all connected components and compare the roots of the source and destination.

Question 5: Which is the simplest optimal solution?

BFS or DFS gives \\(O(V+E)\\) time. DSU is also effectively linear for this task and uses less auxiliary space because it does not need an adjacency list.

## 8. Follow-up interview questions and answers

Q1. Why is the graph undirected?

Each edge `[u, v]` represents a bidirectional connection, so the adjacency list must include both `u → v` and `v → u`.

Q2. Why mark a vertex visited when adding it to the queue rather than when removing it?

Marking it on discovery prevents multiple neighboring vertices from adding the same vertex to the queue. It avoids redundant queue entries and simplifies traversal.

Q3. Can BFS find the shortest path too?

Yes. In an unweighted graph, BFS discovers vertices in nondecreasing order of their distance from the source. Store a `parent` or `distance` array if you need to reconstruct or measure the shortest path.

Q4. Can Union-Find tell me the actual path between two vertices?

Not directly. DSU maintains connectivity information, not the sequence of edges forming a path. Use BFS or DFS with a parent array when you need to reconstruct the path.

Q5. What if there are thousands of connectivity queries on the same graph?

Build the DSU once by processing all edges. Each subsequent connectivity query is answered by checking whether the two vertices have the same root, taking amortized \\(O(\alpha(V))\\) time per query.

Q6. How would you count the connected components?

With DSU, initialize the component count to `n` and decrement it whenever `union()` successfully merges two previously distinct roots. The final count is the number of connected components.

Q7. Is a cycle a problem for DSU?

No. If both endpoints of an edge already have the same root, `union()` does nothing. That is how DSU handles redundant connections and cycles.

## Final takeaway

This problem is a basic graph connectivity problem.

- BFS/DFS: Can I reach the destination by exploring from the source?
- Union-Find: Do the source and destination belong to the same connected component?

Learn all three, but don't force Union-Find onto every graph problem. BFS and DFS are more versatile when you need distances, paths, or traversal order; DSU is particularly useful when the problem revolves around merging components or repeatedly checking connectivity.
