# Similar String Groups — LeetCode 839 (Union-Find / DFS)

This is a classic connected components problem. Since you're studying Union-Find, this problem is a good example of how to convert a string-comparison problem into a graph problem and then solve it using Disjoint Set Union (DSU).

## 1. Understand the problem

Two strings are similar if:

1. They are already identical, or
2. We can make them identical by swapping exactly two positions in one string.

Because all strings are anagrams of one another, we only need to check whether at most two positions differ.

For example:

```
"tars" and "rats"

t a r s
r a t s
^   ^

Swap positions 0 and 2 in "tars":
"rats"

Therefore, they are similar.
```

Another example:

```
"tars" and "arts"

t a r s
a r t s
^ ^ ^

Three positions differ, so one swap cannot make them equal.
They are not similar.
```

A similarity group is a connected component: strings can belong to the same group through a chain of similar strings, even if the first and last strings aren't directly similar.

## 2. Key intuition: model strings as a graph

Imagine every string is a node. Connect two nodes with an edge whenever their strings are similar.

The answer is the number of connected components in this graph.

Consider:

```
strs = ["tars", "rats", "arts", "star"]
```

Suppose the similarities are:

```
tars ─── rats ─── arts

star
```

Here, `"tars"`, `"rats"`, and `"arts"` form one group through similarity connections, while `"star"` is a separate group.

Therefore, the answer is `2`.

There are two natural ways to count these components:

- DFS/BFS: Build or explore the similarity graph and count its connected components.
- Union-Find: Compare pairs of strings and merge their components whenever they are similar.

Union-Find is especially useful here because we only need to merge connected components; we don't need to store the graph explicitly.

## 3. Approach 1 — Union-Find (recommended)

### Step 1: Compare every pair

For `n` strings, compare all pairs `(i, j)` where `i < j`.

If `strs[i]` and `strs[j]` are similar, they belong to the same group, so perform:

```
union(i, j);
```

### Step 2: How do we check whether two strings are similar?

Compare corresponding characters and count mismatches.

For example:

```
x = "tars"
y = "rats"

Index:    0  1  2  3
x:        t  a  r  s
y:        r  a  t  s
          ^
                ^

Mismatches = 2
```

There are only two differing positions, and swapping those two characters makes the strings equal.

We have three cases:

| Number of mismatches | Similar?          | Reason                                      |
| -------------------- | ----------------- | ------------------------------------------- |
| `0`                  | Yes               | Strings are identical                       |
| `2`                  | Yes, for anagrams | Swap the two mismatched characters          |
| More than `2`        | No                | One swap cannot fix more than two positions |

Because the problem guarantees that all strings are anagrams, exactly two mismatches must be interchangeable. For a reusable helper that doesn't rely on this guarantee, explicitly verify that the two characters cross-match.

### Step 3: Count the groups

Initially, every string belongs to its own group.

```
strs = ["tars", "rats", "arts"]

Initially:

0     1     2
tars  rats  arts

groups = 3
```

After comparing `"tars"` and `"rats"`:

```
0 ─── 1      2

groups = 2
```

After comparing `"rats"` and `"arts"`:

```
0 ─── 1 ─── 2

groups = 1
```

Each successful union between two different components decreases the group count by one.

Important: If two strings are already in the same component, a union must not decrease the count again.

## 4. Complete Java 24 solution

```
class Solution {

    public int numSimilarGroups(String[] strs) {
        int n = strs.length;

        // Initially, each string is its own connected component.
        UnionFind uf = new UnionFind(n);

        // Compare every unordered pair of strings.
        // We use j = i + 1 to avoid comparing a pair twice
        // and to avoid comparing a string with itself.
        for (int i = 0; i < n; i++) {
            for (int j = i + 1; j < n; j++) {

                // Similar strings must belong to the same group.
                if (areSimilar(strs[i], strs[j])) {
                    uf.union(i, j);
                }
            }
        }

        // Every connected component represents one similarity group.
        return uf.getGroupCount();
    }

    private boolean areSimilar(String x, String y) {
        int firstMismatch = -1;
        int secondMismatch = -1;
        int mismatchCount = 0;

        for (int i = 0; i < x.length(); i++) {

            // Matching characters do not need any operation.
            if (x.charAt(i) == y.charAt(i)) {
                continue;
            }

            mismatchCount++;

            // One swap can correct at most two positions.
            // We can stop immediately if we find a third mismatch.
            if (mismatchCount > 2) {
                return false;
            }

            // Remember the two positions that differ.
            if (firstMismatch == -1) {
                firstMismatch = i;
            } else {
                secondMismatch = i;
            }
        }

        // Identical strings are similar without any swap.
        if (mismatchCount == 0) {
            return true;
        }

        // Exactly two mismatches must cross-match so that
        // swapping these two positions transforms x into y.
        return mismatchCount == 2
                && x.charAt(firstMismatch) == y.charAt(secondMismatch)
                && x.charAt(secondMismatch) == y.charAt(firstMismatch);
    }

    private static class UnionFind {
        private final int[] parent;
        private final int[] size;
        private int groups;

        UnionFind(int n) {
            parent = new int[n];
            size = new int[n];
            groups = n;

            for (int i = 0; i < n; i++) {
                // Initially, every node is its own root.
                parent[i] = i;
                size[i] = 1;
            }
        }

        int find(int node) {
            // Path compression: make every visited node point
            // directly to the root, speeding up future operations.
            if (parent[node] != node) {
                parent[node] = find(parent[node]);
            }

            return parent[node];
        }

        void union(int a, int b) {
            int rootA = find(a);
            int rootB = find(b);

            // Already connected: no new component is merged.
            if (rootA == rootB) {
                return;
            }

            // Union by size: attach the smaller tree to the larger one.
            if (size[rootA] < size[rootB]) {
                int temp = rootA;
                rootA = rootB;
                rootB = temp;
            }

            parent[rootB] = rootA;
            size[rootA] += size[rootB];

            // Two previously separate groups have become one.
            groups--;
        }

        int getGroupCount() {
            return groups;
        }
    }
}
```

### Why keep a `groups` variable?

We could call `find(i)` for every node and count distinct roots at the end. However, maintaining the group count directly is simpler:

- Initialize `groups = n`.
- Decrement only when `union()` merges two distinct roots.
- Return `groups`.

This also avoids allocating a separate set of roots.

### Why use both path compression and union by size?

- Path compression: Shortens paths to the root during `find()`.
- Union by size: Keeps trees shallow by attaching the smaller component to the larger one.

Together, they make each Union-Find operation nearly constant time in practice.

## 6. Time and space complexity

Let:

- \\(n\\) = number of strings.
- \\(L\\) = length of each string.

### Time complexity

There are at most

\\[ \frac{n(n-1)}{2}=O(n^2) \\]

unique pairs to compare.

Each similarity check takes \\(O(L)\\) time in the worst case because it scans the characters of the strings.

Union-Find operations take amortized \\(O(\alpha(n))\\) time per operation, where \\(\alpha\\) is the inverse Ackermann function.

Therefore:

\\[ T(n,L)=O(n^2L+n^2\alpha(n)) \\]

Since \\(\alpha(n)\\) is extremely small and \\(L \geq 1\\), the overall time complexity simplifies to:

Time: \\(O(n^2L)\\)

### Space complexity

- `parent`: \\(O(n)\\)
- `size`: \\(O(n)\\)
- Other variables: \\(O(1)\\)

Auxiliary space: \\(O(n)\\), excluding the input strings.

With \\(n \leq 300\\) and \\(L \leq 300\\), the solution comfortably fits the constraints.

## 7. Alternative approach — DFS/BFS

Union-Find is not the only solution. This problem is fundamentally about connected components, so DFS or BFS works as well.

### Idea

1. Treat every string as a graph node.
2. Create an edge between every similar pair.
3. Start DFS from each unvisited node.
4. Every new DFS traversal identifies one connected component.

### Java solution using DFS

```
class Solution {

    public int numSimilarGroups(String[] strs) {
        int n = strs.length;

        // Build an adjacency list: graph[i] contains all strings
        // that are directly similar to strs[i].
        List<Integer>[] graph = new List[n];

        for (int i = 0; i < n; i++) {
            graph[i] = new ArrayList<>();
        }

        // Build the undirected similarity graph.
        for (int i = 0; i < n; i++) {
            for (int j = i + 1; j < n; j++) {
                if (areSimilar(strs[i], strs[j])) {
                    graph[i].add(j);
                    graph[j].add(i);
                }
            }
        }

        boolean[] visited = new boolean[n];
        int groups = 0;

        // Each unvisited node starts a new connected component.
        for (int i = 0; i < n; i++) {
            if (!visited[i]) {
                groups++;
                dfs(i, graph, visited);
            }
        }

        return groups;
    }

    private void dfs(
            int node,
            List<Integer>[] graph,
            boolean[] visited) {

        // Mark before exploring neighbors to prevent revisiting
        // nodes and entering infinite cycles.
        visited[node] = true;

        for (int neighbor : graph[node]) {
            if (!visited[neighbor]) {
                dfs(neighbor, graph, visited);
            }
        }
    }

    private boolean areSimilar(String x, String y) {
        int first = -1;
        int second = -1;
        int mismatches = 0;

        for (int i = 0; i < x.length(); i++) {
            if (x.charAt(i) == y.charAt(i)) {
                continue;
            }

            mismatches++;

            if (mismatches > 2) {
                return false;
            }

            if (first == -1) {
                first = i;
            } else {
                second = i;
            }
        }

        if (mismatches == 0) {
            return true;
        }

        return mismatches == 2
                && x.charAt(first) == y.charAt(second)
                && x.charAt(second) == y.charAt(first);
    }
}
```

### Complexity

| Metric | Complexity    | Explanation                                   |
| ------ | ------------- | --------------------------------------------- |
| Time   | \\(O(n^2L)\\) | Compare all pairs, then traverse the graph    |
| Space  | \\(O(n^2)\\)  | Adjacency list can contain \\(O(n^2)\\) edges |

Which should you choose in an interview?

| Situation                                     | Preferred approach          |
| --------------------------------------------- | --------------------------- |
| Only need the number of groups                | Union-Find                  |
| Need to traverse or inspect group members     | DFS/BFS                     |
| Need repeated component merges                | Union-Find                  |
| Need to store and analyze graph relationships | DFS/BFS with adjacency list |

For this problem, I'd recommend Union-Find first, because it avoids storing all graph edges and directly maintains the answer.

## 8. Edge cases to remember

| Input              | Expected output           | Why                                                                                                                                      |
| ------------------ | ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `["abc"]`          | `1`                       | One string forms one component                                                                                                           |
| `["abc", "abc"]`   | `1`                       | Identical strings are similar                                                                                                            |
| `["abc", "acb"]`   | `1`                       | One swap is sufficient                                                                                                                   |
| `["abc", "bca"]`   | `1`                       | They differ at three positions, so this pair is not directly similar; however, this example has no third string to bridge the connection |
| `["abcd", "badc"]` | `1`                       | Two swaps are needed, but both strings differ at four positions; this is a useful reminder to count actual mismatches                    |
| `["abc", "def"]`   | Not a valid problem input | The strings aren't anagrams                                                                                                              |

One correction to the third-row reasoning is worth emphasizing: under the problem's anagram guarantee, `"abc"` and `"bca"` are not directly similar, because three positions differ. With only those two strings, the correct answer is `2`, not `1`. Similarly, `"abcd"` and `"badc"` differ at four positions and also form two groups.

The corrected edge-case table is:

| Input              | Expected output |
| ------------------ | --------------- |
| `["abc"]`          | `1`             |
| `["abc", "abc"]`   | `1`             |
| `["abc", "acb"]`   | `1`             |
| `["abc", "bca"]`   | `2`             |
| `["abcd", "badc"]` | `2`             |

This is an important distinction: anagrams are not necessarily similar. Being anagrams is what allows us to recognize a valid two-position swap when exactly two mismatches exist.

## 9. How to derive this solution in an interview

A good thought process is:

1. Recognize the relationship: Similarity defines an edge between two strings.
2. Recognize the requested output: The problem asks for groups connected through chains, which means connected components.
3. Choose a component-counting technique: DFS/BFS or Union-Find.
4. Derive the similarity test: One swap changes at most two positions, so count mismatches and stop as soon as there are more than two.
5. Optimize the implementation: Use Union-Find with path compression and union by size, maintaining a component count.

A concise explanation to give the interviewer:

> I model each string as a node, with an edge between two strings if they are identical or differ in exactly two cross-matching positions. The answer is the number of connected components. Rather than materializing the graph, I compare each unordered pair and union similar strings. I initialize the component count to the number of strings and decrement it only when two previously separate components merge. This gives \\(O(n^2L)\\) time and \\(O(n)\\) auxiliary space.

## 10. Follow-up interview questions

Q1. Why does the problem guarantee that all strings are anagrams?

Because if two strings differ at exactly two positions, the mismatched characters must be swapped versions of each other. Without the anagram guarantee, two mismatches alone would not prove that one swap can make the strings identical.

Q2. Why do we check each pair only once?

The graph is undirected: if `strs[i]` is similar to `strs[j]`, the reverse is also true. Therefore, `j = i + 1` avoids duplicate comparisons.

Q3. Why not just count the number of similar pairs?

Because similarity is not necessarily transitive. A group is based on reachability through a chain, not on every pair being directly similar.

Q4. What happens when `union(a, b)` receives nodes already in the same component?

`find(a)` and `find(b)` return the same root. We do nothing, and the component count remains unchanged.

Q5. Can we optimize beyond comparing all pairs?

Potentially, by exploiting additional properties of the input or indexing permutations. However, with only 300 strings, pairwise comparison is simple and efficient. In an interview, the \\(O(n^2L)\\) solution is a strong choice.

Q6. Is this the same pattern as Number of Islands?

They share the connected-components idea, but the graph is different:

- Number of Islands: Neighbors are defined by grid adjacency.
- Similar String Groups: Neighbors are defined by comparing entire strings.

Both can be solved using DFS/BFS or Union-Find.

Final takeaway: Learn this as the pairwise relationship → connected components → Union-Find pattern. The reusable part is the DSU; the problem-specific part is the `areSimilar()` function.












# Similar String Groups — Let's Understand It From Zero

Let's forget the code for a moment. The confusing part of this problem is that it combines two different ideas:

1. Comparing two strings to decide whether they are similar.
2. Grouping strings that are connected, using Union-Find.

We'll understand each idea separately, then combine them into the solution.

## 1. First, understand what makes two strings similar

The problem says that two strings are similar if:

- They are already identical, or
- We can make them identical by swapping two characters in one string.

A swap means choosing two positions and exchanging the characters at those positions.

### Example 1: Two strings are similar

Suppose:

```
x = "tars"
y = "rats"
```

Write the characters at their positions:

```
Position:  0  1  2  3
x:         t  a  r  s
y:         r  a  t  s
```

Compare them position by position:

| Position | `x` | `y` | Same? |
| -------- | --- | --- | ----- |
| 0        | `t` | `r` | No    |
| 1        | `a` | `a` | Yes   |
| 2        | `r` | `t` | No    |
| 3        | `s` | `s` | Yes   |

Only positions `0` and `2` are different.

Now swap the characters at positions `0` and `2` in `x`:

```
Before:  t a r s
         ^   ^

Swap t and r

After:   r a t s
```

We get `"rats"`, which is exactly `y`.

Therefore, `"tars"` and `"rats"` are similar.

### Example 2: Two strings are not similar

Consider:

```
x = "abc"
y = "bca"
```

Compare them:

```
Position:  0  1  2
x:         a  b  c
y:         b  c  a
```

Every position is different.

We have three mismatches:

- Position `0`: `a` versus `b`
- Position `1`: `b` versus `c`
- Position `2`: `c` versus `a`

One swap can change at most two positions. Since three positions differ, one swap cannot make these strings equal.

Therefore, they are not directly similar.

This is an important point: two strings can contain exactly the same characters but still not be similar.

## 2. The rule for checking similarity

For this problem, all strings are guaranteed to be anagrams. That guarantee makes the comparison easier.

Count how many positions differ.

| Mismatches | Meaning                                          | Similar? |
| ---------- | ------------------------------------------------ | -------- |
| 0          | Strings are already identical                    | Yes      |
| 1          | Impossible for distinct anagrams of equal length | No       |
| 2          | The two mismatched characters can be swapped     | Yes      |
| 3 or more  | One swap cannot fix all differences              | No       |

Why is exactly one mismatch impossible? Because the strings contain the same characters with the same frequencies. If one position has a different character, at least one other position must also differ to balance the character counts.

For two mismatches, the anagram guarantee ensures that the characters must cross-match.

For example:

```
x = "tars"
y = "rats"

x[0] = 't'       y[0] = 'r'
x[2] = 'r'       y[2] = 't'

x[0] == y[2]     // true
x[2] == y[0]     // true
```

That is enough to prove that swapping these two positions works.

So our first helper function will answer just one question:

> Can one swap, or no swap, make these two strings identical?

We will call it `areSimilar(x, y)`.

## 3. Now understand what a similarity group means

This is the more important part of the problem.

A group does not require every string to be directly similar to every other string.

Instead, strings can be connected through a chain of similar strings.

Consider these three strings:

```
A = "tars"
B = "rats"
C = "arts"
```

We already know that `A` and `B` are similar.

Let's compare `B` and `C`:

```
B = "rats"
C = "arts"

Position:  0  1  2  3
B:         r  a  t  s
C:         a  r  t  s
```

Only positions `0` and `1` differ. Swapping them transforms `"rats"` into `"arts"`.

So `B` and `C` are similar too.

We can represent the relationships like this:

```
"tars" ───── "rats" ───── "arts"
   A             B             C
```

All three strings belong to the same group because we can travel from any one to another through these connections.

Notice that `"tars"` and `"arts"` differ at three positions. They are not directly similar, but they still belong to the same group through `"rats"`.

This is the key idea:

Direct similarity and belonging to the same group are not the same thing.

- Direct similarity asks whether one swap can transform one string into another.
- Group membership asks whether there is a chain of direct similarities connecting them.

## 4. What if there are multiple groups?

Consider this input:

```
String[] strs = {"tars", "rats", "arts", "star"};
```

We have four strings. Initially, imagine each string is alone:

```
Group 1: "tars"

Group 2: "rats"

Group 3: "arts"

Group 4: "star"
```

Initially, the group count is `4`.

Now compare pairs.

Comparison 1: `"tars"` and `"rats"`

They are similar, so combine their groups:

```
"tars" ─── "rats"

Groups remaining = 3
```

Comparison 2: `"tars"` and `"arts"`

Three positions differ, so these two strings are not directly similar. No merge happens.

However, they may still belong to the same group through another string.

Comparison 3: `"rats"` and `"arts"`

They are similar, so merge their groups:

```
"tars" ─── "rats" ─── "arts"

Groups remaining = 2
```

Why does the count decrease only once here? Because `"rats"` and `"arts"` were already connected to `"tars"` through the first merge. We are extending an existing group, not creating another merge between separate groups.

The remaining string, `"star"`, does not connect to any of the first three.

Our final result is:

```
Group 1: "tars", "rats", "arts"

Group 2: "star"

Answer = 2
```

This is what the problem asks us to calculate.

## 5. How does Union-Find help us?

Let's temporarily forget the actual words and give every string an index.

```
Index     String
  0       "tars"
  1       "rats"
  2       "arts"
  3       "star"
```

Union-Find manages groups of these indices.

It provides two main operations.

### Operation A: `find(i)`

`find(i)` tells us which group contains index `i`, represented by the group's root.

Initially, each index is its own root:

```
0     1     2     3

groups = 4
```

Each index is alone, so:

```
find(0) = 0
find(1) = 1
find(2) = 2
find(3) = 3
```

### Operation B: `union(a, b)`

`union(a, b)` combines the groups containing `a` and `b`, but only if they are currently separate.

Initially:

```
0     1     2     3
```

Since indices `0` and `1` represent similar strings, call:

```
union(0, 1);
```

Now the structure may look like this:

```
0
|
1

2     3
```

Here, `0` is the root of the first group. The exact tree shape can vary depending on the Union-Find implementation.

The group count decreases from `4` to `3`.

Next:

```
union(1, 2);
```

Even though we use index `1`, which is not the root, Union-Find finds its root first and merges that entire component with the component containing `2`.

The result is one connected component containing `0`, `1`, and `2`, plus the separate component containing `3`.

```
0
|
1
|
2

3

groups = 2
```

The actual implementation uses path compression and union by size, so its tree might look different. The important fact is that all connected indices have the same root.

### The most important Union-Find rule

Suppose we execute:

```
union(0, 1);
union(1, 2);
union(0, 2);
```

The third operation must not reduce the group count again.

Why? Because `0` and `2` already belong to the same group.

In code:

```
int rootA = find(a);
int rootB = find(b);

if (rootA == rootB) {
    return; // Already in the same group. Nothing to merge.
}

// Different roots mean two separate groups.
// Merge them and decrease the group count.
```

Remember this: A successful union means merging two previously separate groups, not merely discovering another pair of similar strings.

## 6. Put the two ideas together

Now the full algorithm becomes straightforward.

1. Create one group per string.
2. Compare every pair of strings.
3. If the pair is similar, union their indices.
4. Return the number of groups remaining.

Here is the flow:

```
Input strings
      |
      v
Initially, each string is its own group
      |
      v
Compare every pair of strings
      |
      v
Are the two strings similar?
      |
   Yes|       No
      v        |
  Union them   |
      |        |
      +----+---+
           |
           v
     Check next pair
           |
           v
   Return final group count
```

The algorithm has two independent responsibilities:

- `areSimilar()` decides whether two strings should be connected.
- `UnionFind` tracks the connected groups.

Keeping these responsibilities separate makes the code much easier to understand.

## 7. Complete Java solution with detailed comments

Read this code in three parts: the main algorithm, the similarity check, and Union-Find.

```
class Solution {

    public int numSimilarGroups(String[] strs) {
        int n = strs.length;

        // STEP 1:
        // Initially, every string is a separate group.
        //
        // Example:
        // strs = ["tars", "rats", "arts", "star"]
        //
        // Index:  0      1      2      3
        // Groups: {0}    {1}    {2}    {3}
        //
        // Therefore, the initial group count is 4.
        UnionFind uf = new UnionFind(n);

        // STEP 2:
        // Compare every pair of strings.
        //
        // i represents the first string.
        // j represents the second string.
        //
        // Start j at i + 1 because:
        // - We don't need to compare a string with itself.
        // - Similarity is symmetric, so comparing (0, 1)
        //   is sufficient; we don't need to compare (1, 0).
        for (int i = 0; i < n; i++) {
            for (int j = i + 1; j < n; j++) {

                // STEP 3:
                // If these two strings are directly similar,
                // their indices must belong to the same group.
                if (areSimilar(strs[i], strs[j])) {

                    // This merges their groups ONLY if they
                    // are currently separate groups.
                    uf.union(i, j);
                }
            }
        }

        // STEP 4:
        // After checking every pair, all required connections
        // have been processed. The remaining component count
        // is the number of similarity groups.
        return uf.getGroupCount();
    }

    private boolean areSimilar(String x, String y) {

        // Remember the positions where x and y differ.
        // We only need to remember at most two positions.
        int firstMismatch = -1;
        int secondMismatch = -1;

        int mismatchCount = 0;

        // Compare corresponding characters in both strings.
        for (int i = 0; i < x.length(); i++) {

            // If the characters match, this position is fine.
            if (x.charAt(i) == y.charAt(i)) {
                continue;
            }

            // Otherwise, this position is a mismatch.
            mismatchCount++;

            // A single swap can change at most two positions.
            // A third mismatch proves that one swap is insufficient.
            if (mismatchCount > 2) {
                return false;
            }

            // Store the first mismatching position.
            if (firstMismatch == -1) {
                firstMismatch = i;
            } else {
                // Store the second mismatching position.
                secondMismatch = i;
            }
        }

        // CASE 1:
        // No mismatches means the strings are identical.
        if (mismatchCount == 0) {
            return true;
        }

        // CASE 2:
        // Exactly two mismatches are allowed.
        //
        // Because all input strings are anagrams, the two
        // mismatched characters must be swapped versions
        // of each other.
        //
        // Verify explicitly that swapping these positions works.
        return mismatchCount == 2
                && x.charAt(firstMismatch) == y.charAt(secondMismatch)
                && x.charAt(secondMismatch) == y.charAt(firstMismatch);
    }

    private static class UnionFind {

        // parent[i] tells us the parent of node i.
        // A root is identified by parent[root] == root.
        private final int[] parent;

        // size[root] stores the number of nodes in that root's
        // component. We use it to keep the trees shallow.
        private final int[] size;

        // Number of connected components currently remaining.
        private int groups;

        UnionFind(int n) {
            parent = new int[n];
            size = new int[n];

            // Initially, every node is a separate component.
            groups = n;

            for (int i = 0; i < n; i++) {
                parent[i] = i; // Every node starts as its own root.
                size[i] = 1;   // Every component initially has one node.
            }
        }

        int find(int node) {

            // If node is its own parent, it is the root.
            if (parent[node] == node) {
                return node;
            }

            // PATH COMPRESSION:
            // Recursively find the root and make this node point
            // directly to it.
            //
            // This shortens the path for future find() calls.
            parent[node] = find(parent[node]);

            return parent[node];
        }

        void union(int a, int b) {

            // Find the roots of the components containing a and b.
            int rootA = find(a);
            int rootB = find(b);

            // If both roots are identical, these nodes are already
            // connected. Merging them again would change nothing.
            if (rootA == rootB) {
                return;
            }

            // UNION BY SIZE:
            // Keep the larger component as the parent.
            // This prevents unnecessarily tall trees.
            if (size[rootA] < size[rootB]) {
                int temp = rootA;
                rootA = rootB;
                rootB = temp;
            }

            // Attach the smaller component's root to the larger one.
            parent[rootB] = rootA;

            // The resulting component contains nodes from both trees.
            size[rootA] += size[rootB];

            // Two previously separate components have become one.
            groups--;
        }

        int getGroupCount() {
            return groups;
        }
    }
}
```

### The code's most important lines

If the code feels long, focus on these five lines first:

```
if (areSimilar(strs[i], strs[j])) {
    uf.union(i, j);
}

return uf.getGroupCount();
```

Everything else supports those operations:

- `areSimilar()` decides which pairs should connect.
- `union()` merges their groups.
- `find()` identifies the group containing each index.
- `groups--` records that two distinct groups have become one.

## 8. Detailed dry run: follow the group count

Use this smaller input first:

```
String[] strs = {"tars", "rats", "arts"};
```

We have three strings:

```
Index 0: "tars"
Index 1: "rats"
Index 2: "arts"
```

### Initial state

```
Groups: {0} {1} {2}
groups = 3
```

Every string starts separately, regardless of whether it might be similar to another string.

### First comparison: indices `0` and `1`

```
"tars"
"rats"
```

The mismatches occur at positions `0` and `2`.

`areSimilar()` returns `true`, so we call:

```
uf.union(0, 1);
```

Union-Find finds two different roots and merges them.

```
Group 1: {0, 1}
Group 2: {2}

groups = 2
```

### Second comparison: indices `0` and `2`

```
"tars"
"arts"
```

Three positions differ, so `areSimilar()` returns `false`.

No union occurs.

```
Group 1: {0, 1}
Group 2: {2}

groups = 2
```

### Third comparison: indices `1` and `2`

```
"rats"
"arts"
```

Only positions `0` and `1` differ. Swapping them makes the strings equal.

Therefore:

```
uf.union(1, 2);
```

`find(1)` returns the root of the first group. `find(2)` returns the root of the second group. Since these roots differ, Union-Find merges them.

```
Group 1: {0, 1, 2}

groups = 1
```

The final answer is:

```
1
```

The important detail is that index `1` was already connected to index `0`. Union-Find understands this through the root, so connecting index `1` to index `2` brings the entire first group together with the second group.

## 9. One more example: why we cannot simply count similar pairs

Consider:

```
String[] strs = {"tars", "rats", "arts"};
```

We found two similar pairs:

- `"tars"` and `"rats"`
- `"rats"` and `"arts"`

There are two similar pairs but only one group.

This distinction is critical.

If you count similar pairs, your answer would be `2`, which is wrong.

Instead, count how many separate groups remain after all the connections have been processed.

Think of people at a party:

- Alice knows Bob.
- Bob knows Charlie.
- Alice doesn't need to know Charlie directly for all three to belong to the same connected social circle.

Union-Find works the same way.

## 10. Complexity — why this solution is efficient

Let \\(n\\) be the number of strings and \\(L\\) their common length.

| Operation                     | Time complexity       |
| ----------------------------- | --------------------- |
| Compare one pair of strings   | \\(O(L)\\)            |
| Compare all pairs             | \\(O(n^2L)\\)         |
| Union-Find operations overall | \\(O(n^2\alpha(n))\\) |
| Total time                    | \\(O(n^2L)\\)         |
| Auxiliary space               | \\(O(n)\\)            |

Here, \\(\alpha(n)\\) is the inverse Ackermann function, which is effectively constant for practical input sizes.

We use \\(O(n)\\) extra space for the `parent` and `size` arrays. We do not build an adjacency list, which would potentially require \\(O(n^2)\\) space.

## 11. Common mistakes

1. Assuming anagrams are always similar. They are not. `"abc"` and `"bca"` are anagrams but are not directly similar.
2. Assuming every pair in a group must be directly similar. A chain of connections is enough.
3. Decreasing the group count for every similar pair. Decrease it only when the two roots differ.
4. Forgetting the initial group count. It starts at `strs.length`, because every string is initially its own group.
5. Checking only whether there are two mismatches without considering the anagram guarantee. For this problem, the guarantee makes two mismatches sufficient; the code also explicitly checks the cross-match.

## 12. How to think about this problem in an interview

Use these questions in order:

1. What are the objects? The individual strings.
2. What connects two objects? Their similarity.
3. What does the problem ask for? The number of groups connected through these relationships.
4. Which data structure handles merging groups? Union-Find.
5. When should two groups merge? When their strings are directly similar.
6. How do we decide similarity? Count mismatches and check whether a single swap can fix them.

The entire pattern can be summarized as:

```
Objects
   ↓
Define when two objects are connected
   ↓
Compare pairs
   ↓
Union connected objects
   ↓
Count remaining components
```

The most useful takeaway is to separate the rule that defines a connection from the data structure that manages groups. This distinction will help you solve other Union-Find problems, including Number of Islands, Redundant Connection, and Accounts Merge.&#x20;
