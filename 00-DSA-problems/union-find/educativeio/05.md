# Regions Cut By Slashes — Java Solution

This is LeetCode 959. Regions Cut By Slashes. It is a classic Union-Find (Disjoint Set Union / DSU) problem, and it's an excellent problem to solve after learning Number of Islands, Redundant Connection, and Most Stones Removed with Same Row or Column.

The key challenge is that the grid contains diagonal lines, not ordinary walls between cells. We must count the connected regions formed by those lines.

## 1. Understand the problem

Each cell contains one of three characters:

- `/` — a diagonal from bottom-left to top-right.
- `\` — a diagonal from top-left to bottom-right.
- A blank space — no diagonal, so the cell remains fully connected.

The important observation is that a diagonal splits a square into two triangles, but it doesn't necessarily create a completely separate region across the entire grid. Triangles can still connect to neighboring triangles.

Our goal is to count connected components of the resulting open space.

## 2. Best approach: Union-Find with 4 triangles per cell

Instead of treating each cell as one unit, divide every cell into four triangular parts:

- `0` = Top
- `1` = Right
- `2` = Bottom
- `3` = Left

Each cell now contains four parts that can be connected using Union-Find.

### How the characters connect the triangles

Blank space (` `)

All four triangles connect to one another.

```
Top ─ Right ─ Bottom ─ Left ─ Top
```

Forward slash (`/`)

The diagonal separates the top-left pair from the bottom-right pair:

- Union Top with Left.
- Union Right with Bottom.

Backslash (`\`)

The diagonal separates the top-right pair from the bottom-left pair:

- Union Top with Right.
- Union Bottom with Left.

Notice that for slash cells, we do not union all four triangles together.

## 3. Java 24 solution — Union-Find

The simplest way to implement the idea is to represent each triangle with a unique integer ID.

For cell `(r, c)`, the four triangle IDs are:

```
int base = (r * n + c) * 4;

int top    = base;
int right  = base + 1;
int bottom = base + 2;
int left   = base + 3;
```

Why does this work? Every cell gets four consecutive IDs, so all \\(n \times n\\) cells require exactly \\(4n^2\\) DSU elements.

### Complete code

```
import java.util.Arrays;

class Solution {

    public int regionsBySlashes(String[] grid) {
        int n = grid.length;

        // Each cell is represented by four triangular parts.
        // Initially, every triangle is a separate component.
        int totalTriangles = 4 * n * n;

        DSU dsu = new DSU(totalTriangles);

        // Process every cell.
        for (int r = 0; r < n; r++) {
            for (int c = 0; c < n; c++) {

                int base = (r * n + c) * 4;

                int top = base;
                int right = base + 1;
                int bottom = base + 2;
                int left = base + 3;

                char ch = grid[r].charAt(c);

                // ------------------------------------------------
                // STEP 1: Connect triangles INSIDE the current cell.
                // ------------------------------------------------

                if (ch == ' ') {
                    // Blank cell: no diagonal blocks any connection.
                    // All four triangles belong to the same region.
                    dsu.union(top, right);
                    dsu.union(right, bottom);
                    dsu.union(bottom, left);

                } else if (ch == '/') {
                    // Forward slash:
                    //
                    //       TOP
                    //      /   |
                    // LEFT     RIGHT
                    //      \   |
                    //      BOTTOM
                    //
                    // The actual diagonal separates two pairs:
                    // TOP <-> LEFT and RIGHT <-> BOTTOM.
                    dsu.union(top, left);
                    dsu.union(right, bottom);

                } else { // ch == '\\'
                    // Backslash separates the other two pairs:
                    // TOP <-> RIGHT and BOTTOM <-> LEFT.
                    dsu.union(top, right);
                    dsu.union(bottom, left);
                }

                // ------------------------------------------------
                // STEP 2: Connect this cell to its TOP neighbor.
                // ------------------------------------------------

                if (r > 0) {
                    // Current TOP touches the cell above's BOTTOM.
                    int aboveBase = ((r - 1) * n + c) * 4;
                    int aboveBottom = aboveBase + 2;

                    dsu.union(top, aboveBottom);
                }

                // ------------------------------------------------
                // STEP 3: Connect this cell to its LEFT neighbor.
                // ------------------------------------------------

                if (c > 0) {
                    // Current LEFT touches the cell to the left's RIGHT.
                    int leftBase = (r * n + (c - 1)) * 4;
                    int leftRight = leftBase + 1;

                    dsu.union(left, leftRight);
                }
            }
        }

        // Every remaining DSU component represents one region.
        return dsu.countComponents();
    }

    // Disjoint Set Union with path compression and union by size.
    static class DSU {
        private final int[] parent;
        private final int[] size;
        private int components;

        DSU(int n) {
            parent = new int[n];
            size = new int[n];
            components = n;

            // Initially, each triangle is its own component.
            for (int i = 0; i < n; i++) {
                parent[i] = i;
                size[i] = 1;
            }
        }

        // Find the representative of a component.
        // Path compression flattens the tree for future operations.
        int find(int x) {
            if (parent[x] != x) {
                parent[x] = find(parent[x]);
            }
            return parent[x];
        }

        // Merge two components only if they are different.
        boolean union(int a, int b) {
            int rootA = find(a);
            int rootB = find(b);

            // Already connected: merging changes nothing.
            if (rootA == rootB) {
                return false;
            }

            // Attach the smaller tree under the larger tree.
            if (size[rootA] < size[rootB]) {
                int temp = rootA;
                rootA = rootB;
                rootB = temp;
            }

            parent[rootB] = rootA;
            size[rootA] += size[rootB];

            // Two components have become one.
            components--;

            return true;
        }

        int countComponents() {
            return components;
        }
    }
}
```

## 4. How to derive this solution in an interview

Don't start by memorizing the triangle mapping. Derive it from the connectivity problem.

### Step 1: Why can't we use ordinary grid DFS directly?

In Number of Islands, an entire cell is either land or water. You can visit neighboring cells using four directions.

Here, a single cell may contain two disconnected areas because of a diagonal. Treating the entire cell as one node would incorrectly merge those areas.

### Step 2: How do we represent the smaller connected pieces?

Split every square into four triangles. The diagonal determines which triangles can connect inside the cell.

Now each triangle can be treated as a node in a graph.

### Step 3: Which triangles should be connected?

For each cell:

| Character | Internal unions                            | Components inside an isolated cell |
| --------- | ------------------------------------------ | ---------------------------------- |
| Blank     | `top-right`, `right-bottom`, `bottom-left` | 1                                  |
| `/`       | `top-left`, `right-bottom`                 | 2                                  |
| `\`       | `top-right`, `bottom-left`                 | 2                                  |

These unions are only the internal connections. Neighboring cells must also be connected wherever their edges touch.

### Step 4: How do we connect neighboring cells?

Only process the top and left neighbors.

- Top of current cell ↔ bottom of cell above.
- Left of current cell ↔ right of cell to the left.

Why only two directions? Every adjacent pair of cells will be handled exactly once. Processing all four directions would repeat many unions unnecessarily.

### Step 5: How do we count the regions?

Start with \\(4n^2\\) independent triangle components. Every successful union merges two components, reducing the count by one.

Therefore:

\\[ \text{Regions}=4n^2-\text{number of successful unions} \\]

Our implementation tracks this count directly in `DSU.components`.

## 5. Dry run with an example

Consider:

```
String[] grid = {
    " /",

```

```
+---+---+
|   | / |
|   |   |
+---+---+
| / |   |
|   |   |
+---+---+
```

We have a 2 × 2 grid, so initially there are:

\\[ 4 \times 2 \times 2 = 16 \\]

independent triangles.

The characters are:

| Cell     | Character | Internal connections |
| -------- | --------- | -------------------- |
| `(0, 0)` | Blank     | 3 unions             |
| `(0, 1)` | `/`       | 2 unions             |
| `(1, 0)` | `/`       | 2 unions             |
| `(1, 1)` | Blank     | 3 unions             |

These are the maximum internal unions before accounting for neighboring cells.

Now process the cells row by row:

1. Cell `(0,0)` is blank. Its four triangles merge into one component, reducing the count from 16 to 13.
2. Cell `(0,1)` contains `/`. Its top-left pair and right-bottom pair merge separately, reducing the count to 11. Its top triangle also connects to the bottom triangle of `(0,0)`, reducing the count to 10.
3. Cell `(1,0)` contains `/`. Its two pairs merge, reducing the count to 8. Its top triangle connects to the bottom triangle above it, and its left triangle connects to the right triangle of `(0,0)`, reducing the count to 6.
4. Cell `(1,1)` is blank. Its internal unions reduce the count by 3, and its top and left neighbor connections reduce the count further.

After processing every cell, the final component count is 2.

The two regions are the two separate open areas created by the diagonal arrangement.

## 6. Complexity analysis

Let \\(n\\) be the number of rows and columns.

Time complexity:

\\[ O(n^2 \alpha(n^2)) \approx O(n^2) \\]

We process \\(n^2\\) cells and perform a constant number of DSU operations per cell. With path compression and union by size, each operation takes amortized \\(O(\alpha(n^2))\\) time, where \\(\alpha\\) is the inverse Ackermann function, which is effectively constant for practical inputs.

Space complexity:

\\[ O(n^2) \\]

We store parent and size arrays for \\(4n^2\\) triangles. The DSU storage dominates the auxiliary space.

Given the constraint \\(n \le 30\\), we need at most \\(4 \times 30^2 = 3600\\) DSU elements.

## 7. Alternative solutions

There are two other useful ways to solve this problem.

### Approach 2: Expand each cell into a 3 × 3 grid

Replace each original cell with nine smaller cells. Draw each diagonal as three blocked pixels through the expanded cell, then use DFS or BFS to count connected components among the unblocked pixels.

For example:

```
Original: /       Expanded:

                  ..#
                  .#.
                  #..
```

Here, `#` represents a blocked pixel and `.` represents open space.

For each original cell:

- `/`: block the top-right to bottom-left diagonal.
- `\`: block the top-left to bottom-right diagonal.
- Blank: block nothing.

Then run DFS/BFS over the resulting \\(3n \times 3n\\) grid.

Complexity

- Time: \\(O(n^2)\\)
- Auxiliary space: \\(O(n^2)\\)

This approach is often easier to visualize because it turns diagonal connectivity into ordinary grid connectivity. The trade-off is that you must allocate and traverse the expanded grid.

### Approach 3: Use a graph and connected components

You can explicitly create a graph in which every triangle is a vertex and every valid connection is an edge. Then count connected components using DFS, BFS, or DSU.

This is conceptually the same as the four-triangle approach, but DSU is particularly natural here because we only need to merge connected pieces and count the resulting components.

### Which approach should you choose?

| Approach                  | Best use                                                          |
| ------------------------- | ----------------------------------------------------------------- |
| Four triangles + DSU      | Best for learning Union-Find and solving this problem efficiently |
| 3 × 3 expansion + DFS/BFS | Best when visualizing connected open areas is easier              |
| Explicit graph + DFS/BFS  | Best for understanding the general connected-components model     |

For your Union-Find interview preparation, I recommend mastering the four-triangle DSU approach first.

## 9. Interview follow-up questions

Q1. Why do we need four triangles instead of two?

Four triangles make connectivity across cell boundaries explicit. With two halves, you would need to handle orientations and boundary connections more carefully. Four triangles provide a uniform representation for every character.

Q2. Why does a blank cell need only three unions?

Because connecting four initially separate triangles into one component requires exactly three successful unions. Connecting all four pairs is unnecessary.

Q3. Why use union by size and path compression?

Without these optimizations, DSU trees can become tall, making `find()` slower. Both optimizations keep operations extremely efficient.

Q4. Could we count the regions by subtracting successful unions?

Yes. Start at \\(4n^2\\) and decrement the count only when `union()` actually merges two different components. This is exactly what the implementation does.

Q5. Is this fundamentally a Union-Find problem?

It is a connected-components problem that can be solved with several algorithms. DSU is a natural fit because connectivity is built incrementally as we process cells.

Q6. Can this be solved with ordinary DFS/BFS?

Yes. The 3 × 3 expansion converts the diagonals into blocked cells, allowing standard DFS/BFS to count the remaining connected components.

## Final takeaway

The important lesson is not to memorize the triangle IDs. It is to recognize the transformation:

1. A cell is too coarse a unit because a diagonal can split it.
2. Split the cell into smaller pieces that represent its connectivity.
3. Merge pieces that touch inside the cell and across cell boundaries.
4. Count the remaining connected components.

That is the core Union-Find pattern behind Regions Cut By Slashes.

## 2. Why counting each square separately fails

Consider this input:

```
String[] grid = {
    " /",
    "/ "
};
```

It is a 2 × 2 grid:

```
+-------+-------+
|       |   /   |
|       |  /    |
+-------+-------+
|   /   |       |
|  /    |       |
+-------+-------+
```

Each of the four cells contains either a blank or a slash.

If we count each cell independently:

- Top-left blank: 1 region.
- Top-right slash: 2 regions.
- Bottom-left slash: 2 regions.
- Bottom-right blank: 1 region.

Total: \\(1+2+2+1=6\\).

But the answer is 2, not 6.

Why? Because some open areas from different cells connect to one another. Counting each cell independently counts the same overall region multiple times.

We need a way to determine which small pieces are connected, even when they belong to different cells.

## 3. The big idea: Split every square into four triangles

Imagine putting a dot in the middle of each square and dividing the square into four parts.

We name the parts clockwise:

```
             TOP
              0
        +-----------+
        | \    |    |
        |  \   |    |
 LEFT 3 |-------+---| 1 RIGHT
        |      /    |
        |     /     |
        +-----------+
              2
            BOTTOM
```

Don't worry about the exact drawing above. The important thing is the four names:

```
         TOP (0)
             |
LEFT (3) — CENTER — RIGHT (1)
             |
       BOTTOM (2)
```

We will use these names consistently:

| Triangle | Number |
| -------- | ------ |
| Top      | 0      |
| Right    | 1      |
| Bottom   | 2      |
| Left     | 3      |

Why do we split the cell into four triangles?

Because now we can represent each individual open part separately. We can connect two parts if there is no line blocking movement between them.

Let's see how that works.

## 4. Understand the three possible cells

### Case A: Blank cell (` `)

There is no diagonal. All four triangles belong to the same region.

```
          TOP
           |
      +----+----+
      |    |    |
 LEFT +----+----+ RIGHT
      |    |    |
      +----+----+
           |
         BOTTOM
```

All four triangles can connect.

We can join them one by one:

```
union(top, right);
union(right, bottom);
union(bottom, left);
```

Think of `union(a, b)` as saying:

> These two pieces are connected, so they belong to the same region.

Why three unions instead of six? Because to connect four separate components into one, we need only three successful merges.

After these operations:

```
Before:  T   R   B   L       4 components

After:   T — R — B — L       1 component
```

### Case B: Forward slash (`/`)

A forward slash runs from bottom-left to top-right.

```
+-----------+
| TOP     / |
|        /  |
|       /   |
|      /    |
|     /     |
+-----------+
```

Look at the two sides of the diagonal:

- The top and left parts are connected to each other.
- The right and bottom parts are connected to each other.
- The two pairs cannot connect through the diagonal.

Therefore:

```
union(top, left);
union(right, bottom);
```

Visually:

```
Before:   T    R    B    L

After:   T—L       R—B

         2 separate components
```

Notice that we do not connect `top` to `right`. The diagonal separates those two sides.

### Case C: Backslash (`\`)

A backslash runs from top-left to bottom-right.

```
+-----------+
| \         |
|  \        |
|   \       |
|    \      |
|     \     |
+-----------+
```

This time:

- The top and right parts are connected.
- The bottom and left parts are connected.

Therefore:

```
union(top, right);
union(bottom, left);
```

Visually:

```
Before:   T    R    B    L

After:    T—R       B—L

          2 separate components
```

### Memorize the geometry, not just the code

| Cell  | First pair  | Second pair      |
| ----- | ----------- | ---------------- |
| Blank | Top ↔ Right | Connect all four |
| `/`   | Top ↔ Left  | Right ↔ Bottom   |
| `\`   | Top ↔ Right | Bottom ↔ Left    |

For a blank, the pairs are only an illustration of how to start joining all four parts; all four must eventually be connected.

At this point, we can correctly represent the regions inside each individual square. But we still have to connect neighboring squares.

## 5. The second big idea: Neighboring triangles can connect

Consider two blank cells next to each other.

```
+-----------+-----------+
|           |           |
|   CELL A  |   CELL B  |
|           |           |
+-----------+-----------+
```

The right side of cell A touches the left side of cell B.

So:

```
union(rightOfA, leftOfB);
```

Similarly, for cells stacked vertically:

```
+-----------+
|  CELL A   |
+-----------+
|  CELL B   |
+-----------+
```

The bottom of cell A touches the top of cell B.

So:

```
union(bottomOfA, topOfB);
```

This gives us two kinds of connections:

1. Internal connections: between triangles inside the same cell, based on `/`, `\`, or blank.
2. External connections: between triangles in neighboring cells, wherever their edges touch.

Both are essential.

### Why only check the top and left neighbors?

Suppose we process cells from left to right, top to bottom.

For any current cell:

- Its top neighbor has already been processed.
- Its left neighbor has already been processed.
- Its right and bottom neighbors will be handled later.

Therefore, we only need these two checks:

```
if (r > 0) {
    union(currentTop, aboveBottom);
}

if (c > 0) {
    union(currentLeft, leftNeighborRight);
}
```

This ensures every shared boundary is considered once, without unnecessary duplicate work.

## 6. Now the easiest way to understand Union-Find

You might be wondering: how does the computer know which triangles belong to the same region?

That's what Union-Find (DSU) does.

Think of every triangle as a person standing alone in a room. Initially, every person is in a separate group.

- `find(x)` tells us which group triangle `x` belongs to.
- `union(a, b)` merges the groups containing `a` and `b`, if they are different.
- `components` tells us how many separate groups remain.

Initially, for a 1 × 1 grid, we have four groups:

```
T    R    B    L

4 separate components
```

For a blank cell, we perform three merges:

```
union(T, R)  → 3 components
union(R, B)  → 2 components
union(B, L)  → 1 component
```

The component count decreases only when two previously separate groups merge.

For a slash cell:

```
union(T, L)  → 3 components
union(R, B)  → 2 components
```

The result is two separate components.

Important: A DSU component represents a connected piece of open space. It might contain triangles from several different cells.

That is the key to solving the problem.

Component count:

\\[ 11-1=10 \\]

We have not connected all triangles in B together. Its two diagonal-separated groups remain distinct unless they connect through other cells.

### Step 3: Process cell C — `/`

Inside C:

```
T connects to L
R connects to B
```

Two successful unions.

Component count:

\\[ 10-2=8 \\]

Next, C's top touches A's bottom:

```
union(C.top, A.bottom);
```

This connects C's top-left group to the group containing A. One successful union.

Component count:

\\[ 8-1=7 \\]

Now C's left side touches A's right side:

```
union(C.left, A.right);
```

But A is blank, so its four triangles were already connected. C's left triangle was also connected to C's top triangle by its `/` diagonal.

These two triangles are already in the same component! This union does not merge any new components.

Component count remains:

\\[ 7 \\]

This is why `union()` must check whether two pieces are already connected before decrementing the count.

### Step 4: Process cell D — blank

Inside D, all four triangles connect using three successful unions.

Component count:

\\[ 7-3=4 \\]

D's top touches B's bottom:

```
union(D.top, B.bottom);
```

This merges two components.

Component count:

\\[ 4-1=3 \\]

D's left touches C's right:

```
union(D.left, C.right);
```

This merges another two components.

Component count:

\\[ 3-1=2 \\]

We are done. No cells remain.

Final answer: 2 regions.

### What should you learn from this dry run?

The component count doesn't simply decrease by the number of union calls. Some union calls connect triangles that are already in the same component, so they do not change the count.

This is exactly what makes DSU useful.

## 8. Complete Java code with detailed comments

Now that the idea is clear, let's map it into code.

There are three things the code must do:

1. Assign four unique IDs to every cell's triangles.
2. Union the correct triangles inside the cell and across cell boundaries.
3. Return the number of components remaining.

```
class Solution {

    public int regionsBySlashes(String[] grid) {
        int n = grid.length;

        // Every cell is divided into 4 triangles:
        // 0 = Top, 1 = Right, 2 = Bottom, 3 = Left.
        //
        // There are n * n cells, so the total number of triangles
        // (and initial DSU components) is 4 * n * n.
        DSU dsu = new DSU(4 * n * n);

        // Process cells row by row, from top-left to bottom-right.
        for (int r = 0; r < n; r++) {
            for (int c = 0; c < n; c++) {

                // Give each cell four consecutive IDs.
                //
                // Example for n = 2:
                // Cell (0, 0): IDs 0, 1, 2, 3
                // Cell (0, 1): IDs 4, 5, 6, 7
                // Cell (1, 0): IDs 8, 9, 10, 11
                // Cell (1, 1): IDs 12, 13, 14, 15
                //
                // Formula: (r * n + c) * 4
                int base = (r * n + c) * 4;

                int top = base;
                int right = base + 1;
                int bottom = base + 2;
                int left = base + 3;

                char ch = grid[r].charAt(c);

                // ------------------------------------------------
                // PART 1: Connect triangles INSIDE the current cell.
                // ------------------------------------------------

                if (ch == ' ') {

                    // Blank cell: no diagonal separates the space.
                    // All four triangles must belong to one component.
                    //
                    // Three unions are enough to connect four parts.
                    dsu.union(top, right);
                    dsu.union(right, bottom);
                    dsu.union(bottom, left);

                } else if (ch == '/') {

                    // Forward slash runs from bottom-left to top-right.
                    //
                    // Top and Left form one connected side.
                    // Right and Bottom form the other connected side.
                    //
                    // Do NOT connect these two pairs through the slash.
                    dsu.union(top, left);
                    dsu.union(right, bottom);

                } else { // ch == '\\'

                    // Backslash runs from top-left to bottom-right.
                    //
                    // Top and Right form one connected side.
                    // Bottom and Left form the other connected side.
                    dsu.union(top, right);
                    dsu.union(bottom, left);
                }

                // ------------------------------------------------
                // PART 2: Connect to the cell ABOVE.
                // ------------------------------------------------

                if (r > 0) {

                    // The current cell's TOP edge touches the cell
                    // above's BOTTOM edge.
                    //
                    // Cell above has coordinates (r - 1, c).
                    int aboveBase = ((r - 1) * n + c) * 4;
                    int aboveBottom = aboveBase + 2;

                    // Merge these pieces if they aren't connected yet.
                    dsu.union(top, aboveBottom);
                }

                // ------------------------------------------------
                // PART 3: Connect to the cell on the LEFT.
                // ------------------------------------------------

                if (c > 0) {

                    // The current cell's LEFT edge touches the
                    // left neighbor's RIGHT edge.
                    //
                    // Left neighbor has coordinates (r, c - 1).
                    int leftBase = (r * n + (c - 1)) * 4;
                    int leftRight = leftBase + 1;

                    dsu.union(left, leftRight);
                }
            }
        }

        // After processing every cell, each DSU component represents
        // one connected region of open space.
        return dsu.components;
    }

    static class DSU {

        // parent[x] tells us the parent of triangle x in the DSU tree.
        private final int[] parent;

        // size[root] stores the size of a component, used to keep
        // the DSU trees shallow when merging components.
        private final int[] size;

        // Number of connected components currently remaining.
        int components;

        DSU(int n) {
            parent = new int[n];
            size = new int[n];

            // Initially, every triangle is independent.
            components = n;

            for (int i = 0; i < n; i++) {
                parent[i] = i; // Every triangle is its own root.
                size[i] = 1;   // Each component contains one triangle.
            }
        }

        int find(int x) {

            // A root is the representative of its component.
            if (parent[x] == x) {
                return x;
            }

            // Path compression:
            // Point x directly to the root to speed up future finds.
            return parent[x] = find(parent[x]);
        }

        void union(int a, int b) {

            // Find the components containing a and b.
            int rootA = find(a);
            int rootB = find(b);

            // Already in the same component.
            // No new connection is created, so the component count
            // must NOT decrease.
            if (rootA == rootB) {
                return;
            }

            // Union by size:
            // Attach the smaller tree under the larger tree.
            // This keeps the trees shallow and find() efficient.
            if (size[rootA] < size[rootB]) {
                int temp = rootA;
                rootA = rootB;
                rootB = temp;
            }

            // Merge component B into component A.
            parent[rootB] = rootA;
            size[rootA] += size[rootB];

            // Two separate components have become one.
            components--;
        }
    }
}
```

### How to read the implementation

When you see:

```
int base = (r * n + c) * 4;
```

think: "Give this cell its own four triangle IDs."

When you see:

```
dsu.union(top, left);
```

think: "The top and left open areas inside this slash cell are connected."

When you see:

```
dsu.union(top, aboveBottom);
```

think: "The top edge of this cell touches the bottom edge of the cell above it."

When you see:

```
components--;
```

think: "Two previously separate connected areas have merged into one."

That is the entire algorithm.

## 10. Complexity

For an \\(n \times n\\) grid:

- Time: \\(O(n^2 \alpha(n^2))\\), effectively \\(O(n^2)\\) for practical inputs.
- Auxiliary space: \\(O(n^2)\\), because the DSU stores four triangles per cell.

Here, \\(\alpha\\) is the inverse Ackermann function, which grows so slowly that it is effectively constant for these constraints.

## 11. How to approach this in an interview

When the interviewer gives you this problem, ask yourself these questions in order:

1. What am I counting? Connected areas of open space, not cells.
2. Why can't I treat each cell as one node? A diagonal can split a cell into two disconnected parts.
3. How can I represent those parts? Split every cell into four triangles.
4. What connects the triangles? The character inside the cell and the shared edges with neighboring cells.
5. Which algorithm maintains connected components efficiently? Union-Find.
6. When do I decrement the answer? Only when two previously distinct components merge.

The most important mental model is this:

We are not merging the slashes. We are merging the open spaces around the slashes.

The triangles are simply a convenient way to represent those open spaces. Once you understand that, the code becomes a direct translation of the geometry into DSU operations.
