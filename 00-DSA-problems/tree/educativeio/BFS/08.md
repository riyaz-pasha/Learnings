# 🧠 Step 1: What is the problem really asking?

You need to:

👉 Pick a **single empty land (0)**
👉 Such that **sum of distances to ALL buildings (1)** is minimum

---

### 🔍 Think of it like:

> “Where should I build my house so that total walking distance to all buildings is minimum?”

---

# ❌ First (Wrong) Idea — Why it fails

### Try:

For every empty cell → run BFS → calculate distance to all buildings

```
for each cell (i, j) == 0:
    run BFS → find distance to all buildings
    take minimum
```

---

### 🚨 Problem:

* Grid = 50 x 50 = 2500 cells
* BFS per cell = 2500

👉 Total = **2500 × 2500 = ~6 million operations**

👉 In worst case even worse → **TLE**

---

# 🔄 Step 2: Reverse Thinking (This is the KEY)

Instead of:

> empty land → buildings

Think:

> buildings → empty land

---

### ❓ Why this works better?

Let’s say:

* Buildings = 5
* Empty cells = 2000

---

### Compare:

| Approach        | BFS Runs   |
| --------------- | ---------- |
| From empty land | 2000 BFS ❌ |
| From buildings  | 5 BFS ✅    |

👉 Huge improvement!

---

# 🧠 Step 3: What happens when we BFS from ONE building?

Let’s say we start BFS from a building.

We will reach all empty cells with shortest distance.

Example:

```
Grid:
1 0 0
0 0 0
0 0 1
```

From building (0,0), distances:

```
X 1 2
1 2 3
2 3 X
```

👉 Now we know:

* Distance from this building → every empty cell

---

# 🧩 Step 4: But we have MULTIPLE buildings

So we repeat BFS for each building.

Now imagine we maintain:

```
distance[r][c] = sum of distances from ALL buildings
```

---

### After building 1:

```
distance:
X 1 2
1 2 3
2 3 X
```

---

### After building 2:

Add distances again:

```
distance:
X 1+? 2+?
1+? 2+?
2+? 3+? X
```

👉 Finally:

Each cell contains:

> Total distance from ALL buildings

---

# ❗ But here is a BIG problem

What if some empty cell:

👉 Can reach building 1
👉 But CANNOT reach building 2

---

### Then that cell is INVALID ❌

---

# 🧠 Step 5: Why we need `reach[][]`

We need to track:

```
reach[r][c] = how many buildings can reach this cell
```

---

### Example:

| Cell  | Distance | Reach |
| ----- | -------- | ----- |
| (1,1) | 6        | 2 ✅   |
| (2,0) | 5        | 1 ❌   |

👉 Only consider cells where:

```
reach == totalBuildings
```

---

# 🧠 Step 6: Final Goal

Now we just do:

```
find min(distance[r][c])
where:
    grid[r][c] == 0
    AND reach[r][c] == totalBuildings
```

---

# 🔥 Why SUM of distances?

Because question says:

> “Total travel distance = sum of distances to all buildings”

---

### Example:

If we pick cell (1,1):

* Distance to building A = 2
* Distance to building B = 3

👉 Total = **2 + 3 = 5**

---

We want:

```
minimum of these totals
```

---

# 🧠 Full Mental Model (Very Important)

Think like this:

> Each building spreads out (BFS wave)

```
Building A spreads distances
Building B spreads distances
Building C spreads distances
```

At each empty cell:

* We collect all waves
* Sum them up
* Check if all buildings reached

---

# 🧠 Why BFS (not DFS)?

Because:

* We need **shortest path**
* BFS guarantees shortest path in unweighted grid

---

# 📌 Summary (Interview Ready)

### ✔ Why start from buildings?

* Fewer BFS runs → efficient

---

### ✔ Why distance[][]?

* To store **total distance from all buildings**

---

### ✔ Why reach[][]?

* To ensure **cell can reach ALL buildings**

---

### ✔ Why sum distances?

* Problem explicitly asks for total travel distance

---

# 🎯 One-line intuition (MEMORIZE THIS)

> “Instead of going from every empty land to buildings, we push distances from each building to all lands and accumulate results.”
