# Spellchecker — Java Solution (HashMap + String Normalization)

The key idea is to use three different lookup structures, one for each matching rule. The order in which we check them guarantees that the highest-priority match wins.

## 1. Understand the intuition

Suppose:

```
wordlist = ["KiTe", "kite", "hare", "Hare"];

queries = ["kite", "KITE", "KiTe", "HARE", "Hear"];
```

The matching rules have different priorities:

| Priority | Rule                  | Example             |
| -------- | --------------------- | ------------------- |
| 1        | Exact match           | `"KiTe"` → `"KiTe"` |
| 2        | Ignore capitalization | `"KITE"` → `"KiTe"` |
| 3        | Ignore vowels         | `"HARE"` → `"hare"` |
| 4        | No match              | `"Hear"` → `""`     |

Notice that `wordlist` contains both `"KiTe"` and `"kite"`. For a case-insensitive match, we must return the first matching word from `wordlist`.

The easiest way to guarantee this is to use `putIfAbsent()` when building our lookup maps.

## 2. The key observation: Normalize words

Instead of checking every word against every query, we can transform words into standard representations.

Consider the word `"KiTe"`.

Original word

## KiTe

Normalization 1 — lowercase

## kite

Handles capitalization mistakes

Normalization 2 — lowercase and replace vowels with '\*'

## k\*t\*

Handles vowel mistakes

Why replace vowels with `'*'`?

- `"KiTe"` → `"k*t*"`
- `"keto"` → `"k*t*"`
- `"kote"` → `"k*t*"`

All three words have the same consonants in the same positions, and the same length. Therefore, they share the same vowel-normalized representation.

## 3. Java 24 solution

```
import java.util.*;

class Solution {

    public String[] spellchecker(String[] wordlist, String[] queries) {

        // Rule 1: Exact, case-sensitive matches.
        Set<String> exactWords = new HashSet<>();

        // Rule 2: Lowercase word -> first original word with that lowercase form.
        Map<String, String> caseInsensitiveMap = new HashMap<>();

        // Rule 3: Vowel-normalized word -> first original matching word.
        Map<String, String> vowelMap = new HashMap<>();

        // Build all lookup structures from the correct dictionary.
        for (String word : wordlist) {

            exactWords.add(word);

            // Example: "KiTe" -> "kite"
            String lower = word.toLowerCase(Locale.ROOT);

            // Preserve the FIRST word in wordlist for this normalized key.
            caseInsensitiveMap.putIfAbsent(lower, word);

            // Example: "KiTe" -> "k*t*"
            String vowelNormalized = normalizeVowels(lower);

            // Again, preserve the FIRST word for vowel-based matches.
            vowelMap.putIfAbsent(vowelNormalized, word);
        }

        String[] answer = new String[queries.length];

        for (int i = 0; i < queries.length; i++) {

            String query = queries[i];

            // Priority 1: Exact match.
            if (exactWords.contains(query)) {
                answer[i] = query;
                continue;
            }

            String lower = query.toLowerCase(Locale.ROOT);

            // Priority 2: Case-insensitive match.
            if (caseInsensitiveMap.containsKey(lower)) {
                answer[i] = caseInsensitiveMap.get(lower);
                continue;
            }

            // Priority 3: Vowel-error match.
            String vowelNormalized = normalizeVowels(lower);

            answer[i] = vowelMap.getOrDefault(vowelNormalized, "");
        }

        return answer;
    }

    private String normalizeVowels(String word) {

        StringBuilder result = new StringBuilder(word.length());

        for (char ch : word.toCharArray()) {

            // Replace every vowel with the same marker.
            // Consonants remain unchanged.
            if (ch == 'a' || ch == 'e' || ch == 'i'
                    || ch == 'o' || ch == 'u') {
                result.append('*');
            } else {
                result.append(ch);
            }
        }

        return result.toString();
    }
}
```

## 4. Dry run

Consider:

```
wordlist = ["KiTe", "kite", "hare", "Hare"];
queries = ["kite", "KITE", "KiTe", "HARE", "Hear", "keti"];
```

After processing the dictionary:

| Original word | Lowercase key | Vowel key |
| ------------- | ------------- | --------- |
| `KiTe`        | `kite`        | `k*t*`    |
| `kite`        | `kite`        | `k*t*`    |
| `hare`        | `hare`        | `h*r*`    |
| `Hare`        | `hare`        | `h*r*`    |

Because we use `putIfAbsent()`, the lowercase key `kite` maps to `"KiTe"`, and `hare` maps to `"hare"`.

Now process each query:

| Query  | Exact match? | Case-insensitive match? | Vowel match? | Answer |
| ------ | ------------ | ----------------------- | ------------ | ------ |
| `kite` | Yes          | —                       | —            | `kite` |
| `KITE` | No           | `KiTe`                  | —            | `KiTe` |
| `KiTe` | Yes          | —                       | —            | `KiTe` |
| `HARE` | No           | `hare`                  | —            | `hare` |
| `Hear` | No           | No                      | No           | `""`   |
| `keti` | No           | No                      | `KiTe`       | `KiTe` |

Important: `HARE` returns `"hare"` because that is the first case-insensitive match in `wordlist`. The exact-match rule would take precedence if the query were exactly `"Hare"`.

## 5. Why do we need three data structures?

- `HashSet<String>`: distinguishes exact matches from all other matches.
- `HashMap<String, String>` for lowercase keys: finds capitalization matches in expected \\(O(1)\\) time.
- `HashMap<String, String>` for vowel-normalized keys: finds vowel-error matches in expected \\(O(1)\\) time.

We cannot use only one map because the three matching rules have different priorities. In particular, an exact match must win even when another dictionary entry has the same lowercase representation.

## 6. Complexity analysis

Let:

- \\(N\\) = number of words in `wordlist`
- \\(Q\\) = number of queries
- \\(L\\) = maximum word length

| Operation                   | Time            |
| --------------------------- | --------------- |
| Build lookup structures     | \\(O(NL)\\)     |
| Normalize and check queries | \\(O(QL)\\)     |
| Total                       | \\(O((N+Q)L)\\) |

- Space complexity: \\(O(NL + QL)\\) including the answer array and stored strings.
- Auxiliary space excluding the answer: \\(O(NL)\\).

HashMap and HashSet operations are expected \\(O(1)\\), while normalization takes \\(O(L)\\).

## 7. Interview approach to remember

Think of this as a priority-based lookup problem:

1. Store exact words in a set.
2. Convert each dictionary word to lowercase and store the first original word for each key.
3. Normalize vowels and store the first original word for each normalized key.
4. For each query, check the exact set first, then the lowercase map, then the vowel map.
5. Return an empty string if all three checks fail.

The most important details interviewers look for are the precedence order, preserving the first dictionary match with `putIfAbsent()`, and using a consistent vowel-normalization rule.
