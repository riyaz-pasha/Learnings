# 🧠 Intuition (How to think in interview)

👉 Core idea:
- For each **message**, remember the **last timestamp** when it was printed.
- When a new request comes:
  - If message **never seen before → print (TRUE)**
  - If seen before:
    - Check **time difference**
    - If `currentTimestamp - lastTimestamp >= S` → print
    - Else → skip (FALSE)

👉 So we need:
- Fast lookup by message → **HashMap**

# ✅ Approach 1: HashMap (Optimal & Standard)

## 💡 Key Idea
Store:
```
message → lastPrintedTimestamp
```

---

## 🧾 Java (Clean + Interview Ready)

```java
import java.util.*;

/**
 * Logger Rate Limiter
 *
 * Core Idea:
 * - Maintain a map: message -> last printed timestamp
 * - For each request:
 *      If message not present OR enough time has passed → allow
 *      Else → reject
 */
public class LoggerRateLimiter {

    // Map to store last printed timestamp for each message
    private final Map<String, Integer> lastPrintedTime;

    // Time window S
    private final int window;

    public LoggerRateLimiter(int window) {
        this.window = window;
        this.lastPrintedTime = new HashMap<>();
    }

    /**
     * Returns TRUE if message should be printed, else FALSE
     */
    public boolean shouldPrintMessage(int timestamp, String message) {

        // Case 1: message never seen before
        if (!lastPrintedTime.containsKey(message)) {
            lastPrintedTime.put(message, timestamp);
            return true;
        }

        int lastTime = lastPrintedTime.get(message);

        // Case 2: check if enough time has passed
        if (timestamp - lastTime >= window) {
            lastPrintedTime.put(message, timestamp); // update timestamp
            return true;
        }

        // Case 3: duplicate within window
        return false;
    }
}
```

## ⏱ Complexity

| Operation | Time | Space |
|----------|------|-------|
| shouldPrintMessage | O(1) | O(N) |

- N = unique messages

# 🚀 Approach 2: HashMap + Cleanup (Sliding Window Optimization)

## 💡 Problem with Approach 1
- Old messages **stay forever** in map → memory leak

## 💡 Improvement
- Remove entries older than `S` seconds

---

## 🧾 Java (Optimized Version)

```java
import java.util.*;

/**
 * Optimized Logger with cleanup using Queue + Map
 */
public class LoggerRateLimiterOptimized {

    private final Map<String, Integer> map;
    private final Queue<Map.Entry<String, Integer>> queue;
    private final int window;

    public LoggerRateLimiterOptimized(int window) {
        this.window = window;
        this.map = new HashMap<>();
        this.queue = new ArrayDeque<>();
    }

    public boolean shouldPrintMessage(int timestamp, String message) {

        // 🧹 Step 1: Cleanup old messages (out of window)
        while (!queue.isEmpty() && timestamp - queue.peek().getValue() >= window) {
            var entry = queue.poll();
            map.remove(entry.getKey());
        }

        // Step 2: Check if message exists
        if (map.containsKey(message)) {
            return false;
        }

        // Step 3: Add new message
        map.put(message, timestamp);
        queue.offer(Map.entry(message, timestamp));

        return true;
    }
}
```

---

## ⏱ Complexity

| Operation | Time | Space |
|----------|------|-------|
| shouldPrintMessage | Amortized O(1) | O(K) |

- K = messages in last S seconds only

---

## 🧠 Why Queue?

👉 Because timestamps are **sorted (given in problem)**  
→ Perfect for **sliding window**

# ✅ Approach 3A: Per-Message TreeSet (Robust & Clean)

## 💡 Idea

For each message:
```text
message → sorted timestamps
```

Use:
- `TreeSet<Integer>` → keeps timestamps sorted automatically

---

## 🔥 Intuition (Interview Thinking)

For a new `(timestamp, message)`:
1. Find the **closest previous timestamp**
2. If it's within `S` → reject
3. Else → accept

👉 We don’t need ALL timestamps, just relevant ones within window

---

## 🧾 Java Implementation

```java
import java.util.*;

/**
 * Handles UNSORTED timestamps using TreeSet
 *
 * For each message:
 *   Maintain sorted timestamps
 *
 * Why TreeSet?
 *   - floor() → largest <= timestamp
 *   - ceiling() → smallest >= timestamp
 */
class RequestLoggerUnsorted {

    // message → sorted timestamps
    private final Map<String, TreeSet<Integer>> map;

    private final int timeLimit;

    public RequestLoggerUnsorted(int timeLimit) {
        this.map = new HashMap<>();
        this.timeLimit = timeLimit;
    }

    public boolean messageRequestDecision(int timestamp, String message) {

        // Get or create TreeSet
        map.putIfAbsent(message, new TreeSet<>());
        TreeSet<Integer> timestamps = map.get(message);

        /**
         * Step 1: Find closest previous timestamp
         */
        Integer prev = timestamps.floor(timestamp);

        // If exists and within window → reject
        if (prev != null && timestamp - prev < timeLimit) {
            return false;
        }

        /**
         * Step 2: (Optional) Cleanup old timestamps
         * Remove anything older than (timestamp - timeLimit)
         *
         * NOTE:
         * Not strictly required for correctness,
         * but avoids memory growth
         */
        while (!timestamps.isEmpty() &&
               timestamps.first() <= timestamp - timeLimit) {
            timestamps.pollFirst();
        }

        /**
         * Step 3: Add current timestamp
         */
        timestamps.add(timestamp);

        return true;
    }
}
```

---

## ⏱ Complexity

| Operation | Time |
|----------|------|
| Insert / Query | O(log K) |

- K = timestamps per message

---

## ✅ Pros

- Handles **unsorted timestamps perfectly**
- Clean logic
- Easy to reason in interview

---

## ❌ Cons

- Extra log factor
- Memory can grow if no cleanup

# 🚀 Approach 3B: TreeMap (Global Time Index)

## 💡 Idea

Instead of per message:
```text
timestamp → list of messages
```

Use:
- `TreeMap<Integer, List<String>>`

---

## ⚠️ Why this is tricky?

👉 For each request:
- You must scan **time range [timestamp - S, timestamp]**
- Check if message exists

---

## 🧾 Java Implementation

```java
import java.util.*;

/**
 * Global TreeMap approach
 *
 * timestamp → list of messages
 */
class RequestLoggerTreeMap {

    private final TreeMap<Integer, List<String>> timeMap;
    private final int timeLimit;

    public RequestLoggerTreeMap(int timeLimit) {
        this.timeMap = new TreeMap<>();
        this.timeLimit = timeLimit;
    }

    public boolean messageRequestDecision(int timestamp, String message) {

        /**
         * Step 1: Get submap in range [timestamp - timeLimit, timestamp]
         */
        NavigableMap<Integer, List<String>> subMap =
                timeMap.subMap(timestamp - timeLimit + 1, true,
                               timestamp, true);

        /**
         * Step 2: Check if message exists in this range
         */
        for (List<String> messages : subMap.values()) {
            if (messages.contains(message)) {
                return false;
            }
        }

        /**
         * Step 3: Insert current message
         */
        timeMap.computeIfAbsent(timestamp, k -> new ArrayList<>())
               .add(message);

        return true;
    }
}
```

---

## ⏱ Complexity

| Operation | Time |
|----------|------|
| Query | O(K * M) |

- K = timestamps in window  
- M = messages per timestamp  

👉 ❌ Not scalable
