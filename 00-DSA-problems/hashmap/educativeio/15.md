## Good Subarray — Prefix Sum + Remainder

### Key idea

We need a subarray whose:

- length is **at least 2**
- sum is divisible by `k`

The important mathematical observation is:

> If two prefix sums have the **same remainder when divided by `k`**, the elements between them have a sum divisible by `k`.

For prefix sums:

```text
prefix[j] % k == prefix[i] % k
```

then:

```text
(prefix[j] - prefix[i]) % k == 0
```

So the problem becomes:

> Have we seen the same remainder before, with an index at least 2 positions behind?

---

### Example

```text
nums = [23, 2, 4, 6, 7]
k = 6
```

Prefix sums and remainders:

```text
index   prefix sum   remainder
--------------------------------
 0          0           0
 1         23           5
 2         25           1
 3         29           5   ← remainder 5 seen at index 1
```

The subarray between prefix indices `1` and `3` is:

```text
[2, 4]
```

Sum:

```text
2 + 4 = 6
```

which is divisible by `6`.

Length:

```text
3 - 1 = 2
```

So answer is `true`.

---

## Java 24 — Optimal Solution

```java
import java.util.*;

/**
 * Good Subarray
 *
 * Idea:
 * -----
 * Use prefix sums and store the FIRST index at which each
 * remainder (prefixSum % k) was seen.
 *
 * Why does this work?
 *
 * Suppose:
 *
 * prefixSum[j] % k == prefixSum[i] % k
 *
 * Then:
 *
 * (prefixSum[j] - prefixSum[i]) % k == 0
 *
 * And prefixSum[j] - prefixSum[i] is exactly the sum of
 * the subarray (i + 1 ... j).
 *
 * Therefore, that subarray has a sum divisible by k.
 *
 * The tricky part is the length >= 2 requirement.
 *
 * We need:
 *
 * j - i >= 2
 *
 * So we store the earliest index for every remainder.
 *
 * Why earliest?
 * --------------
 * If a remainder was first seen at index i, using that index
 * gives us the LONGEST possible subarray ending at j.
 * Therefore, if even that subarray has length < 2,
 * no later occurrence can help us.
 *
 * Time Complexity:  O(n)
 * Space Complexity: O(min(n, k))
 */
class Solution {

    public boolean checkSubarraySum(int[] nums, int k) {

        // remainder -> first index where this remainder occurred
        Map<Integer, Integer> firstIndex = new HashMap<>();

        /*
         * Important trick:
         *
         * Remainder 0 is considered to have appeared at index -1.
         *
         * This allows us to detect a subarray starting from index 0.
         *
         * Example:
         * nums = [6, ...], k = 6
         *
         * prefixSum at index 0 = 6
         * 6 % 6 = 0
         *
         * Current index - previous index
         * = 0 - (-1)
         * = 1
         *
         * That's only length 1, so we correctly reject it.
         *
         * For [6, 6]:
         *
         * index 1 - (-1) = 2
         *
         * Therefore we accept it.
         */
        firstIndex.put(0, -1);

        long prefixSum = 0;

        for (int i = 0; i < nums.length; i++) {

            prefixSum += nums[i];

            // We only care about the remainder.
            int remainder = (int) (prefixSum % k);

            /*
             * Have we seen this remainder before?
             *
             * If yes, the elements between the previous index
             * and current index have a sum divisible by k.
             */
            if (firstIndex.containsKey(remainder)) {

                int previousIndex = firstIndex.get(remainder);

                /*
                 * The subarray must contain at least 2 elements.
                 *
                 * Length = i - previousIndex
                 */
                if (i - previousIndex >= 2) {
                    return true;
                }

            } else {

                /*
                 * IMPORTANT:
                 *
                 * Store ONLY the first occurrence.
                 *
                 * Keeping the earliest index maximizes the length
                 * of any future subarray using this remainder.
                 */
                firstIndex.put(remainder, i);
            }
        }

        return false;
    }
}
```

### Easy interview way to think about it

Think of **prefix sums as checkpoints**.

Suppose:

```text
prefix sum at i = 17
prefix sum at j = 29
k = 6
```

Their remainders are:

```text
17 % 6 = 5
29 % 6 = 5
```

Same remainder means:

```text
29 - 17 = 12
12 % 6 = 0
```

Therefore, everything between those two checkpoints has a sum divisible by `k`.

The only extra condition is:

```text
j - i >= 2
```

because the subarray needs at least two elements.

### The one line to remember

> **Same prefix remainder + distance ≥ 2 ⇒ good subarray.**

## 1. First, forget `k` for a moment

Suppose:

```text
nums = [2, 4, 6]
```

We want to find a subarray whose sum is divisible by `6`.

Try:

```text
[2]       → 2
[2,4]     → 6  ✅
[4,6]     → 10
[2,4,6]   → 12 ✅
```

The obvious way is to calculate every subarray → **O(n²)**.

We need a shortcut.

---

# 2. Think about prefix sums

Instead of calculating every subarray sum, calculate cumulative sums:

```text
nums:         2     4     6
              ↓     ↓     ↓
prefix:       2     6    12
```

Why is this useful?

Suppose:

```text
prefix[i] = sum of elements from 0 to i
```

Then the sum between two positions can be obtained by subtraction.

For example:

```text
prefix at index 2 = 12
prefix before index 1 = 2

12 - 2 = 10
```

That's the sum of:

```text
[4, 6]
```

So:

> **Subarray sum = difference between two prefix sums.**

This is the first important idea.

---

# 3. Now bring `k` back

We don't actually care about the exact sum.

We only care:

```text
Is the sum divisible by k?
```

For example, if:

```text
k = 6
```

then these are all equivalent for our purpose:

```text
6
12
18
24
30
```

They all have:

```text
sum % 6 = 0
```

Now look at these two prefix sums:

```text
prefix A = 8
prefix B = 20
```

Their remainders are:

```text
8  % 6 = 2
20 % 6 = 2
```

**Same remainder!**

Now subtract them:

```text
20 - 8 = 12
```

And:

```text
12 % 6 = 0
```

Aha!

### This is the key observation:

> **If two prefix sums have the same remainder when divided by `k`, their difference is divisible by `k`.**

---

# 4. Why does that work?

Let's make it mathematical but simple.

Suppose:

```text
A % k = r
B % k = r
```

That means:

```text
A = something * k + r
B = somethingElse * k + r
```

Subtract:

```text
B - A

= (somethingElse * k + r)
  - (something * k + r)

= (somethingElse - something) * k
```

The `r` disappears!

Therefore:

```text
(B - A) % k = 0
```

And `B - A` is exactly the sum of some subarray.

---

# 5. Let's use a real example

```text
nums = [23, 2, 4, 6, 7]
k = 6
```

Calculate prefix sums:

```text
index       0    1    2    3    4
nums       23    2    4    6    7

prefix     23   25   29   35   42
```

Now calculate remainder `% 6`:

```text
prefix       remainder
----------------------
23              5
25              1
29              5    ← same remainder!
35              5    ← same again
42              0
```

Look at:

```text
23 % 6 = 5
29 % 6 = 5
```

Therefore:

```text
29 - 23 = 6
```

So the elements between those prefix sums are:

```text
[2, 4]
```

Their sum:

```text
2 + 4 = 6
```

Divisible by 6.

And length is:

```text
2
```

So we found our answer.

---

# 6. So what are we actually storing?

Now the algorithm becomes much easier to understand.

As we walk through the array, we say:

> "I've seen remainder `5` before. Where did I see it?"

For the example:

```text
remainder 5 → index 0
remainder 1 → index 1
```

Then at index `2`:

```text
remainder = 5
```

We have seen `5` before at index `0`.

Therefore:

```text
current index - previous index
= 2 - 0
= 2
```

Length is at least 2 → **answer true**.

---

# 7. Why do we store the FIRST index?

This is another important part.

Suppose:

```text
remainder 5 appeared at:

index 2
index 5
index 8
```

If we're currently at index `8`, which one should we use?

Obviously:

```text
index 2
```

because:

```text
8 - 2 = 6
```

gives the longest possible subarray.

If we used index `5`:

```text
8 - 5 = 3
```

Still potentially valid, but the earliest index gives us the maximum chance of getting length ≥ 2.

So:

> **For each remainder, remember its first/earliest index.**

---

# 8. What about a subarray starting from index 0?

This is the clever trick that often confuses people.

Consider:

```text
nums = [6, 2]
k = 6
```

Prefix sums:

```text
index       0    1
prefix      6    8
remainder   0    2
```

At index `0`, remainder is `0`.

But we need to know:

> "Have I seen remainder 0 before the array started?"

We pretend that we did:

```text
remainder 0 → index -1
```

So initially:

```java
firstIndex.put(0, -1);
```

Now when we reach index `1` in:

```text
[6, 6]
```

the prefix sum is `12`.

```text
12 % 6 = 0
```

We previously saw remainder `0` at `-1`.

Therefore:

```text
1 - (-1) = 2
```

Length = 2 → valid.

---

# 9. The whole algorithm in your head

When you see this problem, think:

### Step 1

Build a running prefix sum.

```text
prefixSum += nums[i]
```

### Step 2

Don't store the entire prefix sum.

Only store:

```text
prefixSum % k
```

because we're interested in divisibility.

### Step 3

Ask:

> "Have I seen this remainder before?"

If **NO**:

```text
remember remainder → current index
```

If **YES**:

```text
previousIndex = where I first saw it

if currentIndex - previousIndex >= 2
    return true
```

That's it.

---

# 10. Visual mental model

Think of remainders as **buckets**.

For `k = 5`, there are only:

```text
0  1  2  3  4
```

Every prefix sum falls into one of these buckets.

For example:

```text
prefix sum    remainder
-----------------------
7                 2
12                2
17                2
```

All three are in the same bucket.

Therefore:

```text
12 - 7 = 5       → divisible by 5
17 - 7 = 10      → divisible by 5
17 - 12 = 5      → divisible by 5
```

So the problem is essentially:

> **Find two prefix sums that fall into the same remainder bucket and are at least 2 indices apart.**

That's the entire intuition.

If the interviewer asks **"Why does this work?"**, say:

> "I use prefix sums. If two prefix sums have the same remainder when divided by `k`, their difference must be divisible by `k`, and that difference represents the sum of the subarray between them. I store the earliest index for each remainder so I can check whether the subarray length is at least 2."

### And the mental formula to remember:

```text
Same remainder
      ↓
Difference is divisible by k
      ↓
Difference of prefix sums = subarray sum
      ↓
If index difference >= 2
      ↓
Good subarray
```
