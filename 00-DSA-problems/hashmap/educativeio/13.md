This is the classic **Top Five Average** problem. The key idea is: **for each student, keep only their 5 highest scores**.

### Approach 1 — Min-Heap per student ⭐ Recommended

The easiest interview way to think about it:

> **For every student, maintain a min-heap of size 5.**  
> When a new score arrives:
> - If fewer than 5 scores → add it.
> - Otherwise, compare with the smallest of the current top 5.
> - If the new score is larger → remove the smallest and add the new score.

Why a **min-heap**? Because we want the **smallest among our current top 5** to be removed when a better score arrives.

```java
import java.util.*;

/**
 * Top Five Average
 *
 * For each student:
 *     Find their highest 5 scores
 *     Average = sum of highest 5 / 5
 *
 * Example:
 *     ID 1 -> scores: 91, 92, 60, 88, 90, 95
 *
 *     Top 5 = 92, 91, 90, 88, 95
 *     Average = 456 / 5 = 91
 *
 * Time Complexity:
 *     O(N log 5) ~= O(N)
 *
 *     N = number of score entries.
 *
 * Space Complexity:
 *     O(S * 5) ~= O(S)
 *
 *     S = number of unique students.
 */
class Solution {

    public int[][] highFive(int[][] items) {

        /*
         * Map:
         *
         * studentId -> min heap containing their TOP 5 scores
         *
         * Why PriorityQueue?
         *
         * Java's PriorityQueue is a MIN-HEAP by default.
         *
         * That means:
         * peek() -> smallest score in the heap.
         *
         * Since we only keep 5 scores, the smallest one is
         * exactly the score we want to throw away when a
         * better score arrives.
         */
        Map<Integer, PriorityQueue<Integer>> topScores = new HashMap<>();

        for (int[] item : items) {

            int id = item[0];
            int score = item[1];

            // Create a min-heap for this student if necessary.
            PriorityQueue<Integer> heap =
                    topScores.computeIfAbsent(id, k -> new PriorityQueue<>());

            /*
             * Case 1:
             * We have fewer than 5 scores.
             *
             * Simply add the score.
             */
            if (heap.size() < 5) {
                heap.offer(score);
            }

            /*
             * Case 2:
             * Already have 5 scores.
             *
             * heap.peek() = smallest of our current top 5.
             *
             * If the new score is larger, it deserves to be
             * part of the top 5.
             */
            else if (score > heap.peek()) {

                // Remove the smallest score.
                heap.poll();

                // Add the new, better score.
                heap.offer(score);
            }

            /*
             * Otherwise:
             *
             * score <= heap.peek()
             *
             * So this score cannot enter the top 5.
             */
        }

        /*
         * Student IDs must be returned in ascending order.
         *
         * TreeMap automatically keeps keys sorted.
         *
         * We could alternatively sort the HashMap keys.
         */
        Map<Integer, PriorityQueue<Integer>> sorted =
                new TreeMap<>(topScores);

        int[][] result = new int[sorted.size()][2];

        int index = 0;

        for (Map.Entry<Integer, PriorityQueue<Integer>> entry
                : sorted.entrySet()) {

            int id = entry.getKey();
            PriorityQueue<Integer> heap = entry.getValue();

            /*
             * The heap contains exactly the highest 5 scores.
             *
             * Calculate their sum.
             *
             * We don't need to destroy the heap, but polling is
             * perfectly fine here because we're done with it.
             */
            int sum = 0;

            for (int score : heap) {
                sum += score;
            }

            // Integer division is explicitly required by the problem.
            int average = sum / 5;

            result[index++] = new int[]{id, average};
        }

        return result;
    }
}
```

### How to think about it in an interview

Suppose:

```text
Student 1:
Scores = 100, 90, 80, 70, 60, 50
```

We only care about:

```text
100, 90, 80, 70, 60
```

When `50` arrives, it doesn't matter because:

```text
50 < smallest of current top 5 (60)
```

Now suppose `95` arrives:

```text
Current top 5:
60, 70, 80, 90, 100

95 > 60
```

So:

```text
remove 60
add 95

70, 80, 90, 95, 100
```

That's exactly what the **min-heap** gives us.

### Approach 2 — Store all scores, then sort

This is simpler and is also perfectly acceptable given the constraint `items.length <= 1000`.

```java
import java.util.*;

class Solution {

    public int[][] highFive(int[][] items) {

        Map<Integer, List<Integer>> scores = new HashMap<>();

        // Group scores by student.
        for (int[] item : items) {
            scores
                .computeIfAbsent(item[0], k -> new ArrayList<>())
                .add(item[1]);
        }

        // TreeMap gives ascending student IDs.
        Map<Integer, List<Integer>> sorted = new TreeMap<>(scores);

        int[][] result = new int[sorted.size()][2];

        int index = 0;

        for (Map.Entry<Integer, List<Integer>> entry : sorted.entrySet()) {

            List<Integer> studentScores = entry.getValue();

            // Highest scores first.
            studentScores.sort(Comparator.reverseOrder());

            int sum = 0;

            // Only first five are needed.
            for (int i = 0; i < 5; i++) {
                sum += studentScores.get(i);
            }

            result[index++] = new int[]{
                entry.getKey(),
                sum / 5
            };
        }

        return result;
    }
}
```

**Complexity:**

If a student has `k` scores:

- Sorting: `O(k log k)`
- Finding top 5: `O(5)` → effectively `O(1)`
- Overall: **O(N log N)** worst case
- Space: **O(N)**

### Which one should you use in an interview?

| Approach | Time | Space | Interview |
|---|---:|---:|---|
| **Min-Heap of 5** | `O(N log 5)` ≈ `O(N)` | `O(S)` | ⭐ Best |
| Sort all scores | `O(N log N)` | `O(N)` | ⭐ Simplest |

I'd recommend the **min-heap solution** because it demonstrates an important interview pattern:

> **When you need the top K elements, think about a heap of size K.**

Here `K = 5`, so instead of sorting potentially many scores, we maintain only the **best 5** at all times.
