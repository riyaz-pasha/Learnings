# Subarray Sums Divisible by K — Java Solution

This problem is a classic Prefix Sum + Remainder Frequency problem, very similar to Subarray Sum Equals K and Continuous Subarray Sum.

The key idea is:

Instead of calculating every subarray, count how many previous prefix sums have the same remainder when divided by `k`.

## 1. Understand the intuition

Suppose:

```
nums = [4, 5, 0, -2, -3, 1]
k = 5
```

We need to count non-empty contiguous subarrays whose sum is divisible by `5`.

A sum is divisible by `5` if its remainder is `0`.

For example:

- `[5]` → sum = 5 → divisible by 5.
- `[5, 0]` → sum = 5 → divisible by 5.
- `[5, 0, -2, -3]` → sum = 0 → divisible by 5.
- `[4, 5, 0, -2, -3, 1]` → sum = 5 → divisible by 5.

There are 7 valid subarrays in total.

### The mathematical trick

Let `prefixSum[i]` be the sum of all elements from index `0` to `i`.

The sum of a subarray from index `j + 1` to `i` is:

\\[ \text{subarraySum}=prefixSum[i]-prefixSum[j] \\]

For this sum to be divisible by \\(k\\):

\\[ (prefixSum[i]-prefixSum[j])\bmod k=0 \\]

Rearranging the condition:

\\[ prefixSum[i]\bmod k=prefixSum[j]\bmod k \\]

This is the breakthrough: a subarray sum is divisible by `k` whenever its ending prefix sum and an earlier prefix sum have the same remainder.

We don't need the actual prefix sums to be equal. Their remainders just need to match.

## 2. Java solution — optimal approach

```

import java.util.Arrays;

class Solution {

    public int subarraysDivByK(int[] nums, int k) {

        // remainderCount[r] = number of previous prefix sums
        // whose remainder is r when divided by k.
        //
        // Since every remainder is in [0, k - 1], an array
        // is simpler and faster than a HashMap.
        int[] remainderCount = new int[k];

        // An empty prefix sum is 0, and 0 % k = 0.
        //
        // This lets us count subarrays starting at index 0
        // whenever their sum is divisible by k.
        remainderCount[0] = 1;

        int prefixSum = 0;
        int answer = 0;

        for (int num : nums) {

            // Calculate the running prefix sum.
            prefixSum += num;

            // Java can return a negative remainder for negative
            // numbers. Normalize it into the range [0, k - 1].
            int remainder = ((prefixSum % k) + k) % k;

            // Every previous prefix sum with this same remainder
            // creates one valid subarray ending at the current index.
            answer += remainderCount[remainder];

            // Record the current prefix sum for future subarrays.
            remainderCount[remainder]++;
        }

        return answer;
    }
}

```

### Complexity analysis

- Time: \\(O(n+k)\\) — initialize the frequency array of size `k`, then process every element once. More precisely, \\(O(n+k)\\).
- Auxiliary space: \\(O(k)\\) — the remainder frequency array.
- For the given constraints, this is efficient because \\(n \leq 30{,}000\\) and \\(k \leq 10{,}000\\).

## 3. Dry run — understand how the count increases

Consider a smaller example:

```
nums = [4, 5, 0, -2]
k = 5
```

Initially, `remainderCount[0] = 1`, representing the empty prefix.

| Index | Number | Prefix sum | Remainder | Previous matching remainders | Answer |
| ----- | ------ | ---------- | --------- | ---------------------------- | ------ |
| 0     | 4      | 4          | 4         | 0                            | 0      |
| 1     | 5      | 9          | 4         | 1                            | 1      |
| 2     | 0      | 9          | 4         | 2                            | 3      |
| 3     | -2     | 7          | 2         | 0                            | 3      |

At index `1`, the prefix sum is `9`, with remainder `4`. The earlier prefix sum `4` also has remainder `4`.

Therefore:

\\[ 9-4=5 \\]

That gives the valid subarray `[5]`.

At index `2`, the prefix sum is again `9`, with remainder `4`. There are now two earlier prefix sums with remainder `4` (the prefix sums `4` and `9`).

This gives two more valid subarrays:

- `[5, 0]` → sum = 5
- `[0]` → sum = 0

The answer increases by `2`, from `1` to `3`.

The final answer for this smaller example is `3`.

## 4. Why do we initialize `remainderCount[0] = 1`?

This is one of the most important details.

Consider:

```
nums = [5]
k = 5
```

The prefix sum is `5`, and its remainder is `0`.

We need to count `[5]` as a valid subarray. But there are no earlier array elements whose prefix sum could match.

By initializing the frequency of remainder `0` to `1`, we represent an empty prefix before the array begins.

Then, when the current remainder is `0`, we find one match and count `[5]`.

Without this initialization, subarrays starting at index `0` whose sums are divisible by `k` would be missed.

## 5. Why do we normalize negative remainders?

In Java:

```
System.out.println(-2 % 5); // -2
```

But our frequency array only supports indices from `0` to `k - 1`.

We normalize the remainder using:

```
int remainder = ((prefixSum % k) + k) % k;
```

For example, if `prefixSum = -2` and `k = 5`:

\\[ ((-2 \bmod 5)+5)\bmod 5=3 \\]

The normalized remainder is `3`, which is a valid array index.

## 6. Other possible solutions

| Approach                           | Time               | Extra space        | When to use                        |
| ---------------------------------- | ------------------ | ------------------ | ---------------------------------- |
| Brute force — check every subarray | \\(O(n^2)\\)       | \\(O(1)\\)         | Small inputs; easiest baseline     |
| Prefix sum + `HashMap`             | \\(O(n)\\) average | \\(O(k)\\) at most | General-purpose frequency counting |
| Prefix sum + frequency array       | \\(O(n+k)\\)       | \\(O(k)\\)         | Best fit for these constraints     |

A brute-force solution is straightforward: start at each index, keep adding elements to a running sum, and increment the answer whenever the sum is divisible by `k`. It takes \\(O(n^2)\\) time.

The `HashMap<Integer, Integer>` version uses the same prefix-remainder idea as the optimal solution, but stores remainder frequencies in a map instead of an array. It is useful when the remainder domain is large or not conveniently bounded.

## 7. Interview takeaway

Remember this pattern:

1. Prefix sums turn a subarray sum into the difference between two prefix sums.
2. Divisibility means those prefix sums must have the same remainder.
3. Frequency counting tells us how many valid starting positions exist for each ending position.
4. Count before inserting the current remainder, so we only count non-empty subarrays.
5. Seed remainder zero with frequency one to include subarrays starting at index `0`.

The general pattern is:

> When a problem asks for the number of subarrays satisfying a condition on their sum, consider prefix sums first. If the condition involves divisibility, consider tracking prefix-sum remainders.

Let's forget the code for a moment. We'll understand why this approach works using a simple example, and then build the solution step by step.

# 1. First, understand the problem

Suppose:

```
nums = [2, 3, 1, 6]
k = 3
```

We need to count all contiguous subarrays whose sum is divisible by `3`.

Some valid subarrays are:

- `[3]` → sum = 3
- `[3, 1, 6]` → sum = 10 (not valid)
- `[3, 1, 6]` is not divisible by 3, so ignore it.
- `[3, 1, 6]` aside, `[3, 1, 6]` has no relevance; let's focus on valid ones.
- `[3]` → sum = 3
- `[3, 1, 6]` → sum = 10, not valid
- `[3, 1]` → sum = 4, not valid
- `[6]` → sum = 6
- `[3, 1, 6]` → sum = 10, not valid
- `[2, 3, 1]` → sum = 6

The correct answer is 4: `[3]`, `[6]`, `[2, 3, 1]`, and `[3, 1, 6]` is not valid, so instead the fourth valid subarray is `[3, 1, 6]`? Its sum is 10, so that is not valid either. Let's enumerate correctly:

- `[3]` → 3
- `[6]` → 6
- `[2, 3, 1]` → 6
- `[2, 3, 1, 6]` → 12

So the answer is 4.

A brute-force solution would examine every possible subarray. But we can solve it more efficiently.

# 2. The big insight: we don't need the actual sum!

Let's use a smaller example:

```
nums = [2, 3, 1]
k = 3
```

Calculate the running sum, called the prefix sum.

| Index | Number | Prefix sum | Remainder (`prefixSum % 3`) |
| ----- | ------ | ---------- | --------------------------- |
| 0     | 2      | 2          | 2                           |
| 1     | 3      | 5          | 2                           |
| 2     | 1      | 6          | 0                           |

Notice something interesting:

- First prefix sum = `2`, remainder = `2`.
- Second prefix sum = `5`, remainder = `2`.

Both prefix sums have the same remainder.

What happens when we subtract them?

\\[ 5-2=3 \\]

The result is divisible by `3`!

That difference represents the subarray `[3]`.

Here's the important rule:

If two prefix sums have the same remainder when divided by `k`, the subarray between them has a sum divisible by `k`.

Why? Because the difference between two numbers with the same remainder is always divisible by that divisor.

For example:

| First prefix sum | Second prefix sum | Difference | Divisible by 3?           |
| ---------------- | ----------------- | ---------- | ------------------------- |
| 2                | 5                 | 3          | Yes                       |
| 5                | 6                 | 1          | No — different remainders |
| 0                | 6                 | 6          | Yes                       |

This is the entire mathematical trick.

# 3. Now, how do we count these subarrays?

We don't want to remember every prefix sum. We only need to remember how many times each remainder has appeared.

Imagine we maintain a frequency array:

```
int[] remainderCount = new int[k];
```

For `k = 3`, it has three positions:

## 0

Remainder 0

# 1

## 1

Remainder 1

# 0

## 2

Remainder 2

# 0

The values represent how many previous prefix sums had each remainder. Initially, remainder 0 has frequency 1 because of the empty prefix.

Let's process the array one number at a time.

## Step 1: Process `2`

Running sum = `2`.

Remainder = `2 % 3 = 2`.

No previous prefix sum has remainder `2`, so we cannot form a valid subarray ending here.

We record remainder `2`.

- Answer = `0`
- Frequency of remainder `2` = `1`

## Step 2: Process `3`

Running sum = `5`.

Remainder = `5 % 3 = 2`.

We've seen remainder `2` once before!

That earlier prefix sum was `2`. The difference is:

\\[ 5-2=3 \\]

So we have found one valid subarray: `[3]`.

- Answer = `1`
- Frequency of remainder `2` becomes `2`

## Step 3: Process `1`

Running sum = `6`.

Remainder = `6 % 3 = 0`.

We've already initialized the frequency of remainder `0` to `1`, representing the empty prefix.

That means the entire subarray `[2, 3, 1]` has sum `6`, which is divisible by `3`.

- Answer = `2`
- Frequency of remainder `0` becomes `2`

Final answer: 2 valid subarrays.

They are `[3]` and `[2, 3, 1]`.

# 4. The code follows directly from the intuition

```

class Solution {
    public int subarraysDivByK(int[] nums, int k) {

        // Store how many prefix sums have each remainder.
        int[] remainderCount = new int[k];

        // An empty prefix allows us to count subarrays
        // starting from index 0.
        remainderCount[0] = 1;

        int prefixSum = 0;
        int answer = 0;

        for (int num : nums) {

            // Extend the prefix sum by the current number.
            prefixSum += num;

            // Normalize the remainder because Java can
            // produce negative remainders for negative sums.
            int remainder = ((prefixSum % k) + k) % k;

            // Every earlier prefix with this remainder
            // creates one valid subarray ending here.
            answer += remainderCount[remainder];

            // Save this prefix for future elements.
            remainderCount[remainder]++;
        }

        return answer;
    }
}

```

## 5. The one thing to remember for interviews

Think of it this way:

Question: How can I know whether a subarray sum is divisible by `k` without calculating every subarray?

Answer: Calculate prefix sums and compare their remainders. Equal remainders mean their difference is divisible by `k`.

Then use a frequency array to count how many earlier prefix sums have the same remainder.

One final detail: we add the frequency before incrementing it. Otherwise, the current prefix could match itself, which would count an empty subarray.

If you understand why `5 - 2 = 3` produces a valid subarray in our example, you've understood the core idea.
