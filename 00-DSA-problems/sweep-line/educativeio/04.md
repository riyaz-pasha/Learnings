# 2406. Divide Intervals Into Minimum Number of Groups — Java 24

The key idea is to find the maximum number of intervals that overlap at the same point. That number is exactly the minimum number of groups required.

There are two optimal approaches worth knowing for interviews:

1. Min-heap / PriorityQueue — sort intervals by start time and track the earliest-ending interval.
2. Sweep line — process start and end events to track how many intervals overlap.

Both run in \\(O(n\log n)\\) time. The most important detail is that intervals are inclusive, so `[1, 5]` and `[5, 8]` overlap. An interval ending at `5` cannot share a group with an interval starting at `5`.

## 0. Understand the problem in simple terms

Imagine each interval is a meeting that occupies a time range. Meetings that overlap cannot use the same room.

Your task is to assign every meeting to a room while using as few rooms as possible.

For example:

```
intervals = [[5,10], [6,8], [1,5], [2,3], [1,10]]
```

The intervals `[1,5]`, `[1,10]`, and `[5,10]` create conflicts at different points. In particular, at position `5`, these three intervals are all active.

Visualizing the overlap

Each horizontal line represents an inclusive interval.

We can assign the intervals to three groups:

- Group 1: `[1,5]`, `[6,8]`
- Group 2: `[2,3]`, `[5,10]`

Why can't we use only two groups? Because at position `5`, three intervals contain that point. Each must belong to a different group.

Therefore, the answer is `3`.

## 1. Clarifying questions to ask the interviewer

In a real interview, ask these questions when the problem statement doesn't already settle them.

1. Are the intervals inclusive or half-open? This determines whether `[1,5]` and `[5,8]` overlap. Here, they are inclusive, so they do.
2. Can an interval have the same start and end? Yes, `[5,5]` is valid and intersects any other interval containing `5`.
3. Are the input intervals sorted? No sorting is guaranteed, so our algorithm must handle arbitrary order.
4. What are the input constraints? With up to \\(10^5\\) intervals, an \\(O(n^2)\\) solution may be too slow; we should target \\(O(n\log n)\\).
5. Can we modify the input? We can sort a copy if preserving the caller's array is important. Otherwise, sorting the input directly is simpler.

The most important clarification is the inclusive boundary rule. It affects both the heap comparison and the sweep-line event ordering.

## 2. Core intuition: maximum overlap determines the answer

Suppose five intervals all contain position `7`.

```
Interval A: [1, 9]
Interval B: [3, 8]
Interval C: [5, 10]
Interval D: [6, 7]
Interval E: [7, 12]
```

At position `7`, all five intervals overlap. No two of them can share a group, so at least five groups are necessary.

Conversely, if the maximum overlap anywhere is five, we can assign intervals to five groups by reusing a group as soon as its previous interval finishes strictly before the next interval starts.

This gives the fundamental result:

\\[ \boxed{\text{Minimum groups}=\text{Maximum simultaneous overlap}} \\]

We do not need to construct the groups because the problem asks only for their minimum count.

## 3. Solution 1 — Brute force (baseline)

The simplest way to think about the problem is to consider every possible coordinate and count how many intervals contain it.

Since every interval lies within the coordinate range `1` to `10^6`, we could check each coordinate and count active intervals. This is easy to understand, but it can be expensive.

A more general brute-force baseline is to count overlaps for every interval's left endpoint. The maximum overlap must occur at some interval's left endpoint, because overlap increases only when an interval starts.

```java
class SolutionBruteForce {

    public int minGroups(int[][] intervals) {
        // For each interval's left endpoint, count every interval that
        // contains that point. The largest count is the answer.
        //
        // Inclusive intervals require:
        //     other.left <= point && point <= other.right
        //
        // Why checking left endpoints is sufficient:
        // The active-interval count can increase only at a start point.
        // Between consecutive start points, it cannot increase.
        //
        // Time: O(n^2)
        // - There are n candidate left endpoints.
        // - For each candidate, scan all n intervals.
        //
        // Auxiliary space: O(1)
        // - Only a few counters are used; the input is not modified.

        int answer = 0;

        for (int[] candidate : intervals) {
            int point = candidate[0];
            int overlapping = 0;

            for (int[] interval : intervals) {
                if (interval[0] <= point && point <= interval[1]) {
                    overlapping++;
                }
            }

            answer = Math.max(answer, overlapping);
        }

        return answer;
    }
}
```

Why this is not optimal: with \\(n=100{,}000\\), the algorithm may perform approximately \\(10^{10}\\) interval checks. We need to avoid repeatedly scanning all intervals.

## 4. Solution 2 — Min-heap (PriorityQueue)

This is a particularly intuitive interview solution because it directly models assigning intervals to groups.

### Mental model

Imagine every group has a current last interval. To place a new interval, we want to find the group that becomes available first.

So we maintain a min-heap containing the right endpoint of the last interval in each group.

1. Sort intervals by their left endpoint.
2. Look at the interval with the earliest start.
3. Check the group whose interval ends earliest.
4. If that end is strictly less than the new start, reuse that group.
5. Otherwise, create a new group.
6. Update the heap with the new interval's end.

The strict comparison matters: `end < start`, not `end <= start`, because both endpoints are inclusive.

### Example walkthrough

Consider:

```
intervals = [[1,5], [2,3], [5,10], [6,8]]
```

After sorting, they are already in start-time order.

| New interval | Previous group ends | Action                                 | Group count |
| ------------ | ------------------- | -------------------------------------- | ----------- |
| `[1,5]`      | `[]`                | Create a group                         | 1           |
| `[2,3]`      | `[5]`               | `5 >= 2`, create a group               | 2           |
| `[5,10]`     | `[3,5]`             | `3 < 5`, reuse the group ending at `3` | 2           |
| `[6,8]`      | `[5,10]`            | `5 < 6`, reuse the group ending at `5` | 2           |

The answer is `2`.

Notice that `[1,5]` and `[5,10]` cannot share a group, but `[2,3]` and `[5,10]` can.

```java
import java.util.Arrays;
import java.util.PriorityQueue;

class SolutionMinHeap {

    public int minGroups(int[][] intervals) {
        // Sort by start time so we process intervals chronologically.
        // The secondary right-endpoint ordering is not required for
        // correctness, but makes ties deterministic.
        Arrays.sort(intervals, (a, b) -> {
            int byStart = Integer.compare(a[0], b[0]);
            return byStart != 0
                    ? byStart
                    : Integer.compare(a[1], b[1]);
        });

        // The heap stores the right endpoint of the last interval
        // assigned to each currently allocated group.
        //
        // The minimum element is the earliest group that could possibly
        // become available. We only need each group's last end time,
        // not the full list of intervals assigned to that group.
        PriorityQueue<Integer> groupEndTimes = new PriorityQueue<>();

        for (int[] interval : intervals) {
            int start = interval[0];
            int end = interval[1];

            // An inclusive interval ending at x still occupies x.
            // Therefore, a group ending at x is reusable only if x < start.
            if (!groupEndTimes.isEmpty()
                    && groupEndTimes.peek() < start) {

                // The earliest-ending group is reusable.
                // Remove its old endpoint before replacing it with end.
                groupEndTimes.poll();
            }

            // Either we reused one group or no group was available and
            // we need a new one. In both cases, record this interval's end.
            groupEndTimes.offer(end);
        }

        // Each heap entry represents one group.
        // Its size is the number of groups allocated by the algorithm.
        //
        // Time: O(n log n)
        // - Sorting: O(n log n).
        // - Each interval causes at most one heap removal and one insertion,
        //   each O(log n), giving O(n log n) overall.
        //
        // Auxiliary space: O(n)
        // - The heap can hold up to n endpoints.
        // - Java's in-place array sort uses implementation-dependent
        //   auxiliary stack/work space as well.
        return groupEndTimes.size();
    }
}
```

### Why does the heap algorithm work?

The heap always exposes the group with the earliest ending interval.

- If that group ends before the new interval starts, we can safely reuse it.
- If it does not end before the new interval starts, every other group ends at the same time or later. Therefore, no group is reusable, and we must create a new one.

This is a greedy choice: always try to reuse the group that becomes available first. It avoids creating a new group whenever reuse is possible.

One subtle point: the heap size is the number of groups allocated so far, and it never decreases. Reusing a group replaces its endpoint rather than reducing the number of groups.

## 5. Solution 3 — Sweep line (optimal and elegant)

The sweep-line approach is often the cleanest way to express the mathematical insight: count how many intervals are active at every position and remember the maximum.

### Mental model: events on a number line

Every interval creates two events:

- Start event: an interval becomes active, so the count increases by `1`.
- End event: an interval stops being active, so the count decreases by `1`.

Because intervals are inclusive, if one interval ends at `5` and another starts at `5`, the start must be processed before the end at that coordinate. Otherwise, we would incorrectly conclude that the intervals do not overlap.

For example:

```
Intervals: [1, 5], [5, 8]

Coordinate 5:
    Start [5, 8]  -> active count increases
    End   [1, 5]  -> active count decreases

Maximum active count at 5 = 2
```

We sort all events by coordinate and, for equal coordinates, process start events first.

```java
import java.util.ArrayList;
import java.util.Comparator;
import java.util.List;

class SolutionSweepLine {

    // Immutable data carrier for one event.
    // delta = +1 means an interval starts.
    // delta = -1 means an interval ends.
    private record Event(int position, int delta) {}

    public int minGroups(int[][] intervals) {
        List<Event> events = new ArrayList<>(2 * intervals.length);

        for (int[] interval : intervals) {
            int left = interval[0];
            int right = interval[1];

            events.add(new Event(left, +1));
            events.add(new Event(right, -1));
        }

        // Sort by coordinate.
        // For equal coordinates, +1 must come before -1 because the
        // intervals are inclusive and both contain the shared endpoint.
        events.sort(
            Comparator.comparingInt(Event::position)
                .thenComparingInt(Event::delta).reversed()
        );

        // IMPORTANT:
        // Reversing the entire comparator above reverses BOTH fields.
        // Although this puts +1 before -1, it also sorts coordinates
        // in descending order, which is incorrect for a sweep line.
        //
        // Use a comparator that sorts coordinates ascending and only
        // reverses the tie-breaker for delta instead.
        events.sort(
            Comparator.comparingInt(Event::position)
                .thenComparing(
                    Comparator.comparingInt(Event::delta).reversed()
                )
        );

        int active = 0;
        int maxOverlap = 0;

        for (Event event : events) {
            // Apply each event in the specified order.
            active += event.delta();

            // The maximum number of simultaneous intervals is the
            // minimum number of groups required.
            maxOverlap = Math.max(maxOverlap, active);
        }

        // Time: O(n log n)
        // - There are 2n events.
        // - Sorting 2n events costs O(n log n).
        // - Scanning the events costs O(n).
        //
        // Auxiliary space: O(n)
        // - Two events are stored for every interval.
        return maxOverlap;
    }
}
```

For production interview code, we can simplify this implementation by using a single comparator and avoiding the redundant sort:

```java
import java.util.ArrayList;
import java.util.Comparator;
import java.util.List;

class Solution {

    private record Event(int position, int delta) {}

    public int minGroups(int[][] intervals) {
        List<Event> events = new ArrayList<>(2 * intervals.length);

        for (int[] interval : intervals) {
            events.add(new Event(interval[0], +1));
            events.add(new Event(interval[1], -1));
        }

        // Primary key: position ascending.
        // Tie-breaker: delta descending, so +1 comes before -1.
        // This is essential for inclusive intervals.
        events.sort(
            Comparator.comparingInt(Event::position)
                .thenComparing(
                    Comparator.comparingInt(Event::delta).reversed()
                )
        );

        int active = 0;
        int answer = 0;

        for (Event event : events) {
            active += event.delta();
            answer = Math.max(answer, active);
        }

        // Time: O(n log n), dominated by sorting 2n events.
        // Auxiliary space: O(n) for the event list.
        return answer;
    }
}
```

Why does sweep line work?

At any point in the scan, `active` represents the number of intervals currently active under the event ordering. Every increase corresponds to an interval starting, and every decrease corresponds to an interval ending.

The largest value of `active` is the largest set of mutually intersecting intervals at a common coordinate. Those intervals require separate groups, and assigning groups greedily achieves that bound.

## 6. Solution 4 — Difference array (uses the coordinate constraints)

There is another useful approach because the problem constrains coordinates to `1` through `10^6`.

Since coordinates are integers, an inclusive interval `[left, right]` can be represented as:

- Add `1` at `left`.
- Subtract `1` at `right + 1`.

This transforms inclusive intervals into a prefix-sum problem.

For `[2,5]`, the updates are `+1` at coordinate `2` and `-1` at coordinate `6`. The active count remains increased at every integer position from `2` through `5`.

```java
class SolutionDifferenceArray {

    public int minGroups(int[][] intervals) {
        // The maximum coordinate is 10^6, so right + 1 is at most
        // 1,000,001. Allocate one additional slot for that decrement.
        final int MAX_COORDINATE = 1_000_000;
        int[] difference = new int[MAX_COORDINATE + 2];

        for (int[] interval : intervals) {
            int left = interval[0];
            int right = interval[1];

            // Start contributing at left.
            difference[left]++;

            // Stop contributing AFTER right.
            // This right + 1 update is what preserves inclusive endpoints.
            difference[right + 1]--;
        }

        int active = 0;
        int answer = 0;

        for (int position = 1;
             position <= MAX_COORDINATE;
             position++) {

            // Prefix sum reconstructs the number of intervals containing
            // the current integer coordinate.
            active += difference[position];

            answer = Math.max(answer, active);
        }

        // Time: O(n + M), where M = 10^6 is the maximum coordinate.
        // - n updates, followed by a scan of the coordinate range.
        //
        // Auxiliary space: O(M), for the difference array.
        //
        // This is attractive when the coordinate range is small and known.
        // It is less general than the heap and sweep-line solutions:
        // if coordinates are huge, an array of size M is impractical.
        return answer;
    }
}
```

## 7. Compare all approaches

| Approach         | Time             | Auxiliary space | When to use                                            |
| ---------------- | ---------------- | --------------- | ------------------------------------------------------ |
| Brute force      | \\(O(n^2)\\)     | \\(O(1)\\)      | Learning the core overlap idea                         |
| Min-heap         | \\(O(n\log n)\\) | \\(O(n)\\)      | Best for explaining group assignment                   |
| Sweep line       | \\(O(n\log n)\\) | \\(O(n)\\)      | Best for directly finding maximum overlap              |
| Difference array | \\(O(n+M)\\)     | \\(O(M)\\)      | When the coordinate range \\(M\\) is small and bounded |

For a general interview, I would recommend the min-heap solution if the interviewer emphasizes constructing or assigning groups, and sweep line if the goal is simply to return the minimum number.

## 8. Edge cases to watch out for

| Input                        | Expected | Reason                                                                                        |
| ---------------------------- | -------- | --------------------------------------------------------------------------------------------- |
| `[[1,3]]`                    | `1`      | Only one interval                                                                             |
| `[[1,2],[3,4]]`              | `1`      | The intervals do not overlap                                                                  |
| `[[1,2],[2,3]]`              | `2`      | Shared endpoint `2` is inclusive                                                              |
| `[[5,5],[5,5]]`              | `2`      | Both intervals occupy the same point                                                          |
| `[[1,10],[2,9],[3,8]]`       | `3`      | All three overlap                                                                             |
| `[[1,10],[2,3],[4,5],[6,7]]` | `2`      | One long interval overlaps each shorter interval, but the shorter intervals can share a group |

Two especially common bugs:

1. Using `end <= start` in the heap approach. This incorrectly allows intervals sharing an endpoint to reuse a group. Use `end < start`.
2. Processing end events before start events at equal coordinates in sweep line. This undercounts overlap for inclusive intervals. Process starts first.

## 9. Interviewer follow-up questions and answers

Q1. Why is the maximum overlap a lower bound on the number of groups?

If \\(k\\) intervals all contain the same coordinate, every pair intersects. Therefore, no two of those intervals can belong to the same group. At least \\(k\\) groups are necessary.

Q2. Why does the min-heap algorithm choose the earliest-ending group?

If the earliest-ending group cannot be reused, no other group can be reused either, because every other ending time is greater than or equal to the earliest ending time. If it can be reused, taking it frees the group that becomes available first.

Q3. Could we use a `TreeMap` instead of a heap?

Yes. A `TreeMap` can store the frequency of each group's ending time and let us find the smallest ending time. However, it introduces more bookkeeping and does not improve the asymptotic complexity. A `PriorityQueue` is simpler.

Q4. What changes if intervals are half-open, such as `[left, right)`?

Intervals that end at `x` do not include `x`. Therefore, `[1,5)` and `[5,8)` do not overlap. In the heap approach, `end <= start` becomes the reuse condition. In sweep line, process end events before start events at equal coordinates.

Q5. How would you return the actual groups instead of only their count?

Maintain a min-heap of `(endTime, groupId)` and a collection of interval lists, one per group. When the earliest-ending group is reusable, append the new interval to that group's list; otherwise, create a new group. This preserves the \\(O(n\log n)\\) time complexity, excluding the output storage.

Q6. Can the sweep-line algorithm be used when coordinates are extremely large?

Yes. Unlike the difference array, sweep line stores only the \\(2n\\) interval events. Its complexity depends on the number of intervals, not the magnitude of the coordinates.

Q7. Does sorting the input in the heap solution modify the caller's array?

Yes. `Arrays.sort(intervals, ...)` reorders the outer array. If the input must remain unchanged, clone the interval rows first and sort the copy.

## 10. Final interview takeaway

Remember these three ideas:

- Mathematical insight: minimum groups equal maximum simultaneous overlap.
- Heap insight: reuse the group with the earliest ending interval, but only when `end < start`.
- Sweep-line insight: count starts and ends, processing starts before ends at equal coordinates because intervals are inclusive.

For LeetCode 2406, both the heap and sweep-line approaches achieve the optimal \\(O(n\log n)\\) time complexity.
