# 218. The Skyline Problem — Hard

The Skyline Problem is a classic Sweep Line + Priority Queue (Max Heap) problem.

There are multiple ways to solve it:

1. Brute force — check every building at every relevant coordinate.
2. Sweep Line + TreeMap — maintain active building heights in sorted order.
3. Sweep Line + Max Heap — maintain active buildings using a priority queue.
4. Divide and Conquer — recursively construct and merge skylines.

The most commonly used optimal interview solution is Sweep Line + Max Heap, with \\(O(n \log n)\\) time complexity.

## 0. Simplify the problem statement

Imagine buildings represented as rectangles.

Each building has:

```
[left, right, height]
```

For example:

```
[2, 9, 10]
```

Means:

- Building starts at x = 2.
- Building ends at x = 9.
- Building height = 10.

We need to look at all buildings together and draw their outer boundary.

At every x-coordinate, the skyline height is simply:

The maximum height among all buildings covering that x-coordinate.

We return only the coordinates where the skyline height changes.

Example:

```
Buildings:

       +-------+
       |       |
       |   B   |
   +---+-------+
   |       A   |
   |           |
---+-----------+---------
   2   3   7   9  12
```

Input:

```
buildings = new int[][] {
    {2, 9, 10},
    {3, 7, 15},
    {5, 12, 12}
};
```

Output:

```
[
    [2, 10],
    [3, 15],
    [7, 12],
    [12, 0]
]
```

Why?

| X-coordinate | Active buildings | Maximum height |
| ------------ | ---------------- | -------------- |
| 2            | A                | 10             |
| 3            | A, B             | 15             |
| 5            | A, B, C          | 15             |
| 7            | A, C             | 12             |
| 9            | C                | 12             |
| 12           | None             | 0              |

Notice that we don't output x = 5 or x = 9 because the skyline height doesn't change there.

## 1. Clarifying questions to ask the interviewer

1. Are buildings sorted by their left coordinate?

   Why: This determines whether we can process buildings directly without sorting their starting coordinates. Here, they are already sorted.
2. Are intervals half-open: [left, right)?

   Why: A building is no longer active at its right coordinate. This matters when one building ends exactly where another begins.
3. Can multiple buildings have the same start or end coordinate?

   Why: We must correctly process multiple events at the same x-coordinate.
4. Can coordinates and heights reach `Integer.MAX_VALUE`?

   Why: We should avoid arithmetic such as `right + 1`, which could overflow.
5. Should we return only actual changes in skyline height?

   Why: We must eliminate consecutive points with equal heights.

The given problem already establishes these assumptions.

## 2. Core intuition — Sweep Line + Max Heap

Think of a vertical line moving from left to right across the city.

At every position, we ask:

What is the tallest building currently active?

That tallest building determines the skyline.

We need two things:

1. An event system to know when buildings start and end.
2. A data structure to efficiently find the tallest active building.

A Max Heap solves the second problem.

### Mental model

Suppose we have:

```
Building A = [2, 9, 10]
Building B = [3, 7, 15]
Building C = [5, 12, 12]
```

As we sweep from left to right:

```
x = 2:
    A starts
    Active heights = {10}
    Skyline = 10

x = 3:
    B starts
    Active heights = {10, 15}
    Skyline = 15

x = 5:
    C starts
    Active heights = {10, 15, 12}
    Skyline = 15

x = 7:
    B ends
    Active heights = {10, 12}
    Skyline = 12

x = 9:
    A ends
    Active heights = {12}
    Skyline = 12

x = 12:
    C ends
    Active heights = {}
    Skyline = 0
```

The resulting skyline:

```
[[2,10], [3,15], [7,12], [12,0]]
```

### Why Max Heap?

A Max Heap gives us:

- Insert a building: \\(O(\log n)\\)
- Find maximum height: \\(O(1)\\)
- Remove maximum height: \\(O(\log n)\\)

However, there is one important challenge.

Java's `PriorityQueue` does not efficiently remove an arbitrary element.

We solve this using Lazy Deletion.

### Lazy Deletion

Instead of immediately removing a building when it ends:

- Mark it as expired using its right coordinate.
- Whenever it reaches the top of the heap, remove it if it has expired.
- Continue until the top represents an active building.

For a building:

```
[left, right, height]
```

It is expired when:

```
right <= currentX
```

This works because buildings are active over half-open intervals `[left, right)`.

We store:

```
private record Building(int right, int height) {}
```

And use:

```java
PriorityQueue<Building> maxHeap =
    new PriorityQueue<>(
        (a, b) -> Integer.compare(b.height(), a.height())
    );
```

# 3. Solution 1 — Brute Force

### Intuition

For every unique building boundary:

1. Look at all buildings.
2. Find buildings covering the current x-coordinate.
3. Find the maximum height.
4. If the maximum height changes, add a key point.

This directly implements the definition of the skyline.

```java
import java.util.*;

class Solution {

    public List<List<Integer>> getSkyline(int[][] buildings) {

        /*
         * BRUTE FORCE APPROACH
         *
         * STEP 1: Collect all unique x-coordinates.
         *
         * Every possible skyline change must happen at a building's
         * left or right boundary.
         *
         * Therefore, we only need to examine these coordinates.
         */

        TreeSet<Integer> coordinates = new TreeSet<>();

        for (int[] building : buildings) {
            coordinates.add(building[0]);
            coordinates.add(building[1]);
        }

        List<List<Integer>> result = new ArrayList<>();

        int previousHeight = 0;

        /*
         * STEP 2: Examine every unique x-coordinate.
         *
         * For each coordinate, scan every building and determine
         * whether it covers this position.
         *
         * A building [left, right) covers x when:
         *
         * left <= x < right
         */

        for (int x : coordinates) {

            int currentMaxHeight = 0;

            for (int[] building : buildings) {

                int left = building[0];
                int right = building[1];
                int height = building[2];

                if (left <= x && x < right) {
                    currentMaxHeight =
                        Math.max(currentMaxHeight, height);
                }
            }

            /*
             * STEP 3: Add a key point only when the height changes.
             *
             * This automatically eliminates consecutive horizontal
             * segments having the same height.
             */

            if (currentMaxHeight != previousHeight) {

                result.add(
                    List.of(x, currentMaxHeight)
                );

                previousHeight = currentMaxHeight;
            }
        }

        return result;
    }
}
```

### Complexity

Let:

- \\(n\\) = number of buildings.
- \\(m\\) = number of unique x-coordinates.
- \\(m \leq 2n\\).

| Operation               | Complexity        |
| ----------------------- | ----------------- |
| Collect coordinates     | \\(O(n \log n)\\) |
| Examine all coordinates | \\(O(mn)\\)       |
| Generate output         | \\(O(m)\\)        |

- Time: \\(O(n^2)\\)
- Space: \\(O(n)\\)

Why not optimal?

For every coordinate, we scan every building, even though most buildings may not be active.

# 4. Solution 2 — Sweep Line + TreeMap

This is another excellent solution and is particularly useful when explaining active intervals.

### Intuition

Instead of using a Max Heap, maintain the frequencies of active building heights in a `TreeMap`.

The TreeMap stores:

```
Height -> Number of active buildings having this height
```

Example:

```
{
    10 -> 1,
    12 -> 2,
    15 -> 1
}
```

The tallest active building is:

```
activeHeights.lastKey();
```

When a building starts:

```
activeHeights.merge(height, 1, Integer::sum);
```

When a building ends:

```
activeHeights.compute(height, ...);
```

We use a `TreeMap` because:

- It maintains heights in sorted order.
- It supports duplicates through frequencies.
- It can find the maximum height in \\(O(\log n)\\).

### Java 24 implementation

```java
import java.util.*;

class Solution {

    private record Event(int x, int height, boolean isStart) {}

    public List<List<Integer>> getSkyline(int[][] buildings) {

        /*
         * SWEEP LINE + TREEMAP
         *
         * STEP 1: Convert buildings into events.
         *
         * Every building creates two events:
         *
         * Start event: +height
         * End event:   -height
         *
         * Example:
         * Building [2, 9, 10]
         *
         * Events:
         * (2, 10, true)
         * (9, 10, false)
         */

        List<Event> events = new ArrayList<>();

        for (int[] building : buildings) {

            int left = building[0];
            int right = building[1];
            int height = building[2];

            events.add(new Event(left, height, true));
            events.add(new Event(right, height, false));
        }

        /*
         * STEP 2: Sort events by x-coordinate.
         *
         * We process all events at the same x-coordinate together.
         *
         * This is important because multiple buildings can start
         * or end at exactly the same coordinate.
         */

        events.sort(
            Comparator.comparingInt(Event::x)
        );

        /*
         * STEP 3: Maintain active building heights.
         *
         * Height -> Frequency
         *
         * Initially, no building is active.
         *
         * We can think of height 0 as the ground.
         */

        TreeMap<Integer, Integer> activeHeights = new TreeMap<>();

        activeHeights.put(0, 1);

        List<List<Integer>> result = new ArrayList<>();

        int previousHeight = 0;

        /*
         * STEP 4: Process all events at the same x-coordinate.
         *
         * Processing them together ensures we output at most
         * one key point for each x-coordinate.
         */

        int i = 0;

        while (i < events.size()) {

            int currentX = events.get(i).x();

            while (i < events.size()
                    && events.get(i).x() == currentX) {

                Event event = events.get(i);

                int height = event.height();

                if (event.isStart()) {

                    /*
                     * A building starts.
                     * Increase the frequency of its height.
                     */

                    activeHeights.merge(
                        height, 1, Integer::sum
                    );

                } else {

                    /*
                     * A building ends.
                     * Decrease its height frequency.
                     *
                     * Remove the height entirely when its
                     * frequency becomes zero.
                     */

                    int frequency = activeHeights.get(height);

                    if (frequency == 1) {
                        activeHeights.remove(height);
                    } else {
                        activeHeights.put(
                            height, frequency - 1
                        );
                    }
                }

                i++;
            }

            /*
             * STEP 5: Find the tallest active building.
             *
             * lastKey() returns the largest height.
             */

            int currentHeight = activeHeights.lastKey();

            /*
             * STEP 6: Emit a key point only when the skyline changes.
             */

            if (currentHeight != previousHeight) {

                result.add(
                    List.of(currentX, currentHeight)
                );

                previousHeight = currentHeight;
            }
        }

        return result;
    }
}
```

### Complexity

- Creating events: \\(O(n)\\)
- Sorting events: \\(O(n \log n)\\)
- Each event updates the TreeMap: \\(O(\log n)\\)
- Finding maximum: \\(O(\log n)\\) for `lastKey()`.

Therefore:

- Time: \\(O(n \log n)\\)
- Space: \\(O(n)\\)

This is an optimal asymptotic solution.

# 5. Solution 3 — Sweep Line + Max Heap (Recommended)

This is the solution I would recommend presenting in a senior-level interview.

### Important optimization: Process buildings directly

The problem guarantees that buildings are already sorted by their left coordinate.

Therefore, we do not need to create and sort all events.

Instead, we can:

1. Maintain an index pointing to the next building.
2. Maintain a Max Heap of active buildings.
3. Find the next relevant x-coordinate.
4. Add buildings starting at or before that coordinate.
5. Remove expired buildings from the heap.
6. Determine the current maximum height.
7. Emit a key point if the height changes.

### How do we find the next x-coordinate?

There are two possibilities:

- The next building starts.
- The currently tallest building ends.

Therefore:

```
int currentX = Math.min(
    nextBuildingLeft,
    maxHeap.peek().right()
);
```

There is one subtlety: if the heap is empty, the next coordinate must be the next building's left edge.

Also, if multiple buildings start or end at the same coordinate, we must process them together.

### Complete Java 24 implementation

```java
import java.util.*;

class Solution {

    /*
     * We store only the information needed by the sweep line:
     *
     * right  -> When this building stops being active.
     * height -> Its height.
     *
     * We don't need the left coordinate because we insert a building
     * into the heap only when its left coordinate has been reached.
     */
    private record Building(int right, int height) {}

    public List<List<Integer>> getSkyline(int[][] buildings) {

        int n = buildings.length;

        /*
         * STEP 1: Create a Max Heap.
         *
         * Java PriorityQueue is a Min Heap by default.
         *
         * We reverse the comparator so that the tallest building
         * appears at the top.
         *
         * For equal heights, we can prioritize the building
         * that ends later. This is a useful tie-breaker.
         *
         * IMPORTANT:
         * Use Integer.compare instead of subtraction to avoid
         * integer overflow in comparators.
         */
        PriorityQueue<Building> maxHeap =
            new PriorityQueue<>(
                (a, b) -> {
                    int heightComparison =
                        Integer.compare(b.height(), a.height());

                    if (heightComparison != 0) {
                        return heightComparison;
                    }

                    return Integer.compare(b.right(), a.right());
                }
            );

        List<List<Integer>> result = new ArrayList<>();

        /*
         * i points to the next building that has not yet been
         * inserted into the heap.
         */
        int i = 0;

        /*
         * The previous skyline height is initially zero because
         * before the first building, the city is at ground level.
         */
        int previousHeight = 0;

        /*
         * STEP 2: Continue until every building has been processed
         * and the heap contains no active buildings.
         */
        while (i < n || !maxHeap.isEmpty()) {

            /*
             * STEP 3: Determine the next interesting x-coordinate.
             *
             * There are two possibilities:
             *
             * 1. A new building starts at buildings[i][0].
             * 2. The tallest active building ends at maxHeap.peek().right().
             *
             * The earlier of these two events is the next coordinate
             * where the skyline could potentially change.
             */

            int currentX;

            if (maxHeap.isEmpty()) {

                /*
                 * No active buildings.
                 *
                 * The next event must be a building starting.
                 */
                currentX = buildings[i][0];

            } else if (i == n) {

                /*
                 * All buildings have already been inserted.
                 *
                 * The next event must be the expiration of the
                 * tallest building.
                 */
                currentX = maxHeap.peek().right();

            } else {

                /*
                 * Both a future start and an active building end
                 * are possible.
                 *
                 * Process whichever happens first.
                 */
                currentX = Math.min(
                    buildings[i][0],
                    maxHeap.peek().right()
                );
            }

            /*
             * STEP 4: Insert every building that starts at currentX.
             *
             * Since buildings are sorted by left coordinate,
             * we can process them sequentially.
             *
             * Notice the <= condition:
             *
             * Every building starting at this coordinate must be
             * inserted before determining the new skyline height.
             *
             * This correctly handles multiple buildings sharing
             * the same left coordinate.
             */
            while (i < n && buildings[i][0] <= currentX) {

                int right = buildings[i][1];
                int height = buildings[i][2];

                maxHeap.offer(
                    new Building(right, height)
                );

                i++;
            }

            /*
             * STEP 5: Remove expired buildings from the heap.
             *
             * A building [left, right) is active only while:
             *
             * currentX < right
             *
             * Therefore, it is expired when:
             *
             * right <= currentX
             *
             * LAZY DELETION:
             *
             * We do not search the heap to remove every expired
             * building.
             *
             * We remove expired buildings only when they reach
             * the top of the heap.
             *
             * Why is this safe?
             *
             * The heap is used only to determine the maximum height.
             * An expired building below the top cannot affect the
             * current maximum.
             *
             * Once it reaches the top, we remove it before reading
             * the maximum.
             */
            while (!maxHeap.isEmpty()
                    && maxHeap.peek().right() <= currentX) {

                maxHeap.poll();
            }

            /*
             * STEP 6: Determine the current skyline height.
             *
             * If the heap is empty, no building is active.
             * Therefore, the skyline height is zero.
             *
             * Otherwise, the tallest active building determines
             * the skyline.
             */
            int currentHeight = maxHeap.isEmpty()
                    ? 0
                    : maxHeap.peek().height();

            /*
             * STEP 7: Generate a key point only when the skyline
             * height changes.
             *
             * This guarantees that we never generate consecutive
             * horizontal segments having the same height.
             *
             * Example:
             *
             * Previous height = 10
             * Current height  = 10
             *
             * No key point is necessary.
             *
             * Previous height = 10
             * Current height  = 15
             *
             * Add [currentX, 15].
             */
            if (currentHeight != previousHeight) {

                result.add(
                    List.of(currentX, currentHeight)
                );

                previousHeight = currentHeight;
            }
        }

        return result;
    }
}
```

### Complexity analysis

Let \\(n\\) be the number of buildings.

Time complexity: \\(O(n \log n)\\)

Why?

1. Each building is inserted into the heap exactly once: \\(O(n \log n)\\).
2. Each building is removed from the heap at most once: \\(O(n \log n)\\).
3. Every iteration processes at least one meaningful event.
4. Each heap insertion and removal costs \\(O(\log n)\\).
5. Each peek costs \\(O(1)\\).

Therefore:

\\[ T(n) = O(n\log n) \\]

Space complexity: \\(O(n)\\)

- Max Heap can contain at most \\(n\\) buildings.
- Result can contain at most \\(2n\\) key points.
- No additional event array or sorting structure is required.

\\[ S(n) = O(n) \\]

## 7. Solution 4 — Divide and Conquer

Another optimal approach is Divide and Conquer.

### Intuition

Instead of processing all buildings simultaneously:

1. Divide the buildings into two halves.
2. Find the skyline of the left half.
3. Find the skyline of the right half.
4. Merge the two skylines.

The merge operation is similar to merging two sorted lists.

For each skyline, maintain:

- Its current x-coordinate.
- Its current height.

At every step:

- Pick the smaller next x-coordinate.
- Update the corresponding skyline height.
- Calculate the maximum of both heights.
- Emit a point if the maximum changes.

### Java 24 implementation

```java
import java.util.*;

class Solution {

    /*
     * Immutable key point.
     */
    private record Point(int x, int height) {}

    public List<List<Integer>> getSkyline(int[][] buildings) {

        List<Point> skyline = divideAndConquer(
            buildings, 0, buildings.length - 1
        );

        List<List<Integer>> result = new ArrayList<>();

        for (Point point : skyline) {
            result.add(
                List.of(point.x(), point.height())
            );
        }

        return result;
    }

    private List<Point> divideAndConquer(
            int[][] buildings,
            int left,
            int right) {

        /*
         * BASE CASE:
         *
         * A single building has exactly two skyline points:
         *
         * [left, height]
         * [right, 0]
         */
        if (left == right) {

            return List.of(
                new Point(buildings[left][0], buildings[left][2]),
                new Point(buildings[left][1], 0)
            );
        }

        /*
         * DIVIDE:
         *
         * Split the buildings into two halves.
         */
        int mid = left + (right - left) / 2;

        /*
         * CONQUER:
         *
         * Recursively calculate each half's skyline.
         */
        List<Point> leftSkyline =
            divideAndConquer(buildings, left, mid);

        List<Point> rightSkyline =
            divideAndConquer(buildings, mid + 1, right);

        /*
         * COMBINE:
         *
         * Merge the two already sorted skylines.
         */
        return merge(leftSkyline, rightSkyline);
    }

    private List<Point> merge(
            List<Point> first,
            List<Point> second) {

        List<Point> result = new ArrayList<>();

        int i = 0;
        int j = 0;

        /*
         * Current height contributed by each skyline.
         *
         * Initially, both are at ground level.
         */
        int height1 = 0;
        int height2 = 0;

        /*
         * Previously emitted skyline height.
         */
        int previousHeight = 0;

        /*
         * Merge the two sorted point lists.
         */
        while (i < first.size() || j < second.size()) {

            int x;

            /*
             * Select the smaller x-coordinate.
             *
             * If both skylines have a point at the same x,
             * process both updates together.
             */
            if (j >= second.size()
                    || (i < first.size()
                    && first.get(i).x() < second.get(j).x())) {

                x = first.get(i).x();
                height1 = first.get(i).height();

                i++;

            } else if (i >= first.size()
                    || second.get(j).x() < first.get(i).x()) {

                x = second.get(j).x();
                height2 = second.get(j).height();

                j++;

            } else {

                /*
                 * Both skylines change at the same x-coordinate.
                 *
                 * Update both heights before calculating the
                 * combined skyline.
                 */
                x = first.get(i).x();

                height1 = first.get(i).height();
                height2 = second.get(j).height();

                i++;
                j++;
            }

            /*
             * The combined skyline is the maximum of both heights.
             */
            int currentHeight = Math.max(height1, height2);

            /*
             * Only emit a point when the combined skyline changes.
             */
            if (currentHeight != previousHeight) {

                result.add(
                    new Point(x, currentHeight)
                );

                previousHeight = currentHeight;
            }
        }

        return result;
    }
}
```

### Complexity

The merge operation takes linear time in the sizes of the two skylines.

The recurrence is:

\\[ T(n) = 2T(n/2) + O(n) \\]

By the Master Theorem:

\\[ T(n) = O(n\log n) \\]

Space:

- Recursive call stack: \\(O(\log n)\\).
- Intermediate skyline lists: \\(O(n\log n)\\) total allocation across recursion levels.
- Final output: \\(O(n)\\).

Auxiliary peak space: \\(O(n)\\) for the merge buffers at the deepest active merge, plus \\(O(\log n)\\) recursion stack, assuming completed child lists are released when no longer needed.

## 8. Comparison of all approaches

| Approach              | Time             | Space                     | Main idea                               |
| --------------------- | ---------------- | ------------------------- | --------------------------------------- |
| Brute Force           | \\(O(n^2)\\)     | \\(O(n)\\)                | Scan every building at every coordinate |
| Sweep Line + TreeMap  | \\(O(n\log n)\\) | \\(O(n)\\)                | Maintain active height frequencies      |
| Sweep Line + Max Heap | \\(O(n\log n)\\) | \\(O(n)\\)                | Maintain tallest active building        |
| Divide and Conquer    | \\(O(n\log n)\\) | \\(O(n)\\) auxiliary peak | Recursively merge skylines              |

My recommendation: Use Sweep Line + Max Heap in the interview. It demonstrates sorting/event reasoning, heap usage, lazy deletion, and careful handling of interval boundaries.

## 9. Important edge cases

### Case 1: Two buildings touch each other

```
buildings = new int[][] {
    {0, 2, 3},
    {2, 5, 3}
};
```

Output:

```
[[0, 3], [5, 0]]
```

Why?

At x = 2, the first building ends and the second begins. The height remains 3.

Therefore, no key point is generated at x = 2.

### Case 2: One building completely hides another

```
buildings = new int[][] {
    {1, 10, 10},
    {2, 5, 5}
};
```

Output:

```
[[1, 10], [10, 0]]

The shorter building never changes the skyline.

### Case 3: Buildings with identical heights

### Case 4: Same starting coordinate

### Case 6: Maximum integer coordinates

The constraints allow:

```

Avoid:

## 10. Interviewer follow-up questions

Q1. Why can't we simply remove a building from Java PriorityQueue when it ends?

Because `PriorityQueue.remove(Object)` takes \\(O(n)\\) time in the worst case.

Lazy deletion avoids searching for arbitrary elements. We remove expired buildings only when they reach the heap's top.

Q2. Why do we need the right coordinate in the heap?

Because height alone cannot tell us whether a building is still active.

We need the right coordinate to determine expiration:

```
building.right() <= currentX
```

Q3. Why do we use a Max Heap instead of a Min Heap?

The skyline is determined by the tallest active building. A Max Heap exposes that building in \\(O(1)\\).

Q4. Why do we process all buildings starting at the same coordinate together?

Otherwise, we could emit intermediate heights that exist only because we processed simultaneous events one at a time.

The skyline should reflect the combined state after all changes at that coordinate.

Q5. Why is `right <= currentX` used instead of `right < currentX`?

Because building intervals are half-open:

\\[ [left,right) \\]

The building is not active at its right endpoint.

Q6. Can we solve this using a segment tree?

Yes. Coordinate compression combined with a segment tree can maintain maximum heights over coordinate ranges.

However, it introduces more implementation complexity and is unnecessary for this problem.

Q7. Is the Max Heap solution always better than TreeMap?

Not necessarily.

- Max Heap: simpler maximum lookup, but requires lazy deletion.
- TreeMap: supports exact height frequency management and direct removal.

Both achieve \\(O(n\log n)\\).

Q8. Why is the answer size at most \\(2n\\)?

There are only \\(2n\\) building boundaries, and skyline changes can happen only at these coordinates. Therefore, there can be at most \\(2n\\) key points.

## 5. Important: Do we actually need these rules in YOUR implementation?

Here is the most important interview insight.

Your implementation does this:

```
while (i < events.size()
        && events.get(i).x() == currentX) {

    Event event = events.get(i);

    if (event.isStart()) {
        activeHeights.merge(
            event.height(), 1, Integer::sum
        );
    } else {
        activeHeights.computeIfPresent(
            event.height(),
            (key, frequency) ->
                frequency == 1 ? null : frequency - 1
        );
    }

    i++;
}

// Calculate skyline only after ALL events at currentX.
int currentHeight = activeHeights.lastKey();
```

Notice the order:

1. Process all START events.
2. Process all END events.
3. Only then calculate the maximum height.

Actually, because you process the entire group before calculating the maximum, the order of events within that group does not affect the final TreeMap.

Therefore, you can simplify your comparator to:

```
events.sort(
    Comparator.comparingInt(Event::x)
);
```

This is completely correct for your implementation.

The more elaborate comparator is useful when:

- You want deterministic conventional event ordering.
- You process events individually and potentially generate output after each event.
- You want to follow the standard Skyline sweep-line event convention.

My interview recommendation: Keep the grouped-processing approach and use the simpler comparator. Explain that all events at the same x-coordinate are applied before calculating the skyline, so tie-breaking by height is unnecessary.

That is a better understanding of the algorithm than memorizing the comparator rules.
