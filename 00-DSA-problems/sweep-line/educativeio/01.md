# 1854. Maximum Population Year — Java 24 Solutions

Difficulty: Easy

The key idea is to count how many people are alive in each year and return the earliest year with the highest population.

There are multiple ways to solve this problem. The best interview solution is a difference array, which lets us calculate the population changes efficiently.

## 0. Simplify the problem statement

Each person is represented by two years:

- `birth`: the year the person starts being counted.
- `death`: the year the person stops being counted.

A person is alive during the years `[birth, death - 1]`. The death year itself is excluded.

For example:

```
logs = [[1993, 1999], [2000, 2010]]
```

- Person 1 is alive from 1993 through 1998.
- Person 2 is alive from 2000 through 2009.

The population is `1` in both periods, and `0` in the years between them.

Since the maximum population is `1`, the answer is 1993, the earliest year when that maximum occurs.

One important detail: if multiple years have the same maximum population, return the smallest year.

## 1. Clarifying questions to ask the interviewer

| Question                                                            | Why it matters                                                               |
| ------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| Is the death year exclusive?                                        | Yes. A person with death year 1999 is not counted in 1999.                   |
| What should we return if several years have the maximum population? | The earliest year, so we must preserve the first maximum encountered.        |
| What is the possible range of years?                                | Years are between 1950 and 2050, allowing a small fixed-size array.          |
| Can the input contain only one person?                              | Yes. Our algorithm must handle a single interval correctly.                  |
| Are the birth and death years guaranteed to be valid?               | The constraints guarantee `birth < death`, so no extra validation is needed. |

## 2. Core intuition: population changes, not individual people

Imagine a timeline. Instead of repeatedly asking whether every person is alive in every year, record only when the population changes.

For each person born in year `b` and dying in year `d`:

- Population increases by `1` in year `b`.
- Population decreases by `1` in year `d`.

Why decrease in `d`? Because the person is no longer counted starting that year.

For example, consider:

```
logs = [[1950, 1960], [1955, 1965]]
```

The changes are:

```
Year:         1950 1951 1952 1953 1954 1955 1956 ... 1960 ... 1965
Person 1:       +1                                  -1
Person 2:                         +1                 -1
```

The population evolves as follows:

```
1950–1954: population = 1
1955–1959: population = 2
1960–1964: population = 1
1965 onward: population = 0
```

The answer is `1955`.

This leads to the difference-array technique: store changes in an array and compute the running sum to obtain the actual population.

## 3. Solution 1 — Brute force

The simplest approach checks every possible year and counts how many people are alive in that year.

```java
class Solution {

    public int maximumPopulation(int[][] logs) {
        // The constraints restrict all relevant years to 1950–2050.
        int earliestYear = 1950;
        int latestYear = 2050;

        int maxPopulation = 0;
        int answer = earliestYear;

        // Try every possible year.
        for (int year = earliestYear; year <= latestYear; year++) {
            int population = 0;

            // Count people who are alive during this year.
            for (int[] log : logs) {
                int birth = log[0];
                int death = log[1];

                // Birth is inclusive; death is exclusive.
                if (birth <= year && year < death) {
                    population++;
                }
            }

            // Use strict >, not >=.
            // If a later year ties the maximum, we keep the earlier year.
            if (population > maxPopulation) {
                maxPopulation = population;
                answer = year;
            }
        }

        return answer;
    }
}
```

### Complexity

Let:

- \\(Y\\) be the number of years in the search range.
- \\(n\\) be the number of people.
- Time: \\(O(Yn)\\), because each of the \\(Y\\) years examines all \\(n\\) people.
- Space: \\(O(1)\\), because we use only a few variables.

With the given constraints, this is perfectly acceptable. However, it does repeated work: the population in adjacent years usually differs by only a few people.

## 4. Solution 2 — Difference array (optimal interview solution)

This solution uses the fact that each person creates exactly two population changes.

```java
class Solution {

    public int maximumPopulation(int[][] logs) {
        // Years range from 1950 through 2050, inclusive.
        // We need 101 slots so index 100 represents year 2050.
        int[] changes = new int[101];

        // Step 1: Record population changes.
        for (int[] log : logs) {
            int birth = log[0];
            int death = log[1];

            // A person starts contributing to the population in birth.
            changes[birth - 1950]++;

            // A person stops contributing in death.
            // This correctly excludes the death year itself.
            changes[death - 1950]--;
        }

        // Step 2: Reconstruct the population using a running sum.
        int population = 0;
        int maxPopulation = 0;
        int answer = 1950;

        // Traverse years in increasing order.
        for (int i = 0; i < changes.length; i++) {
            // Apply this year's changes to get the population for this year.
            population += changes[i];

            // Update only when we find a strictly larger population.
            // Because years are scanned chronologically, ties retain
            // the earliest year automatically.
            if (population > maxPopulation) {
                maxPopulation = population;
                answer = 1950 + i;
            }
        }

        return answer;
    }
}
```

### Walk through an example

Input:

```
logs = [[1950, 1960], [1955, 1965], [1955, 1970]]
```

Step 1: Record changes.

| Year | Change | Explanation          |
| ---- | ------ | -------------------- |
| 1950 | +1     | First person is born |
| 1955 | +2     | Two people are born  |
| 1960 | -1     | First person dies    |
| 1965 | -1     | Second person dies   |
| 1970 | -1     | Third person dies    |

All other years have a change of zero.

Step 2: Compute the running sum.

| Year | Change | Population | Maximum so far |
| ---- | ------ | ---------- | -------------- |
| 1950 | +1     | 1          | 1              |
| 1951 | 0      | 1          | 1              |
| 1952 | 0      | 1          | 1              |
| 1955 | +2     | 3          | 3              |
| 1956 | 0      | 3          | 3              |
| 1959 | 0      | 3          | 3              |
| 1960 | -1     | 2          | 3              |
| 1965 | -1     | 1          | 3              |
| 1970 | -1     | 0          | 3              |

The answer is `1955`, when the population first reaches `3`.

### Why does this work?

The difference array stores events rather than the population itself.

The running sum converts these events into the actual population:

\\[ P(y)=\sum\_{k=1950}^{y}\text{changes}[k-1950] \\]

Each birth contributes `+1` starting in the birth year, and each death contributes `-1` starting in the death year. Therefore, the running sum always equals the number of people alive in the current year.

Because we scan from earliest to latest and update the answer only when `population > maxPopulation`, the first year achieving the maximum is preserved.

### Complexity

- Time: \\(O(n+Y)\\), where \\(n\\) is the number of people and \\(Y=101\\) is the number of years. We process each person's two events, then scan the array once.
- Space: \\(O(Y)\\) for the difference array. Here that is a fixed 101 integers, so it is effectively \\(O(1)\\) under the given constraints.

This is the preferred interview solution because it is efficient, simple, and directly models how the population changes over time.

## 5. Solution 3 — Difference array with a smaller, dynamic range

If the year range were not fixed, we could restrict the scan to the earliest birth and latest death rather than always scanning 1950 through 2050.

For this problem, the fixed-size array above is simpler. Still, the dynamic approach illustrates how to adapt the technique to different constraints.

```java
class Solution {

    public int maximumPopulation(int[][] logs) {
        int minYear = Integer.MAX_VALUE;
        int maxYear = Integer.MIN_VALUE;

        // Find the relevant time range.
        for (int[] log : logs) {
            minYear = Math.min(minYear, log[0]);
            maxYear = Math.max(maxYear, log[1]);
        }

        // Include maxYear because a death event is recorded in that year.
        int[] changes = new int[maxYear - minYear + 1];

        // Encode births and deaths as population changes.
        for (int[] log : logs) {
            changes[log[0] - minYear]++;
            changes[log[1] - minYear]--;
        }

        int population = 0;
        int maxPopulation = 0;
        int answer = minYear;

        for (int i = 0; i < changes.length; i++) {
            population += changes[i];

            // Strict comparison guarantees the earliest year wins ties.
            if (population > maxPopulation) {
                maxPopulation = population;
                answer = minYear + i;
            }
        }

        return answer;
    }
}
```

### Complexity

- Time: \\(O(n+R)\\), where \\(R = \text{maxYear} - \text{minYear} + 1\\).
- Space: \\(O(R)\\) for the difference array.

This version is useful when the year range varies significantly between inputs. The fixed-range version is more straightforward for LeetCode 1854.

## 6. Edge cases to watch out for

| Edge case                        | Example                        | Expected behavior                   |
| -------------------------------- | ------------------------------ | ----------------------------------- |
| One person                       | `[[2000, 2001]]`               | Return `2000`                       |
| All intervals are disjoint       | `[[1993, 1999], [2000, 2010]]` | Return `1993`                       |
| Overlapping intervals            | `[[1950, 1960], [1955, 1965]]` | Return `1955`                       |
| Multiple maximum years           | `[[1950, 1960], [1955, 1965]]` | Return `1955`, the earliest maximum |
| Death year boundary              | `[[2000, 2001]]`               | Population is zero in 2001          |
| Maximum at the first year        | `[[1950, 1960]]`               | Return `1950`                       |
| Maximum at the latest birth year | `[[2049, 2050]]`               | Return `2049`                       |

The most common mistakes are:

1. Decreasing population in `death - 1` instead of `death`.
2. Updating the answer on `population >= maxPopulation`, which can return a later tied year.
3. Allocating only 100 slots instead of 101 when using offsets from 1950 through 2050.
4. Forgetting to apply the current year's change before comparing the population for that year.

## 7. Interviewer follow-up questions and answers

Q1. Why use a difference array instead of checking every year against every person?

The brute-force solution repeats the same checks for each year. The difference array processes each person's birth and death once, then uses a running sum to calculate every year's population. This reduces the time complexity from \\(O(Yn)\\) to \\(O(Y+n)\\).

Q2. Why decrement at the death year?

The problem defines the alive interval as `[birth, death - 1]`. Therefore, the person must stop contributing to the population at the beginning of `death`.

Q3. Why use `>` rather than `>=` when updating the answer?

We process years in ascending order. The first year with a particular maximum is the earliest one. Using `>=` would overwrite that year when the same maximum appears later.

Q4. Can we solve it using a `HashMap`?

Yes. Store the birth and death changes in a map, sort the event years, and maintain a running population. This is useful if the year range is extremely large but the number of distinct event years is small.

The time complexity is \\(O(n\log n)\\) for sorting the event years, and the space complexity is \\(O(n)\\). For the bounded year range in this problem, an array is simpler and more efficient.

Q5. What if years can be as large as \\(10^9\\)?

A year-indexed array would be impractical. We could use a `TreeMap<Integer, Integer>` to record changes, then traverse its entries in ascending order while accumulating the population. This is an event-based sweep-line approach.

Q6. Is this a prefix-sum problem or a sweep-line problem?

It is both:

- The difference array encodes population changes.
- The prefix sum reconstructs the population.
- Conceptually, sweeping through the timeline processes birth and death events in chronological order.

Q7. What is the best solution to present in an interview?

Present the difference-array solution. Explain the exclusive death year first, show why each person generates `+1` and `-1`, then demonstrate the running sum and the strict `>` tie-breaking condition.

The final complexity is \\(O(n+Y)\\) time and \\(O(Y)\\) space, where \\(Y=101\\) under the problem's constraints.

# 1854. Maximum Population Year — Sweep Line Algorithm in Java 24

The most important thing to understand about the sweep-line approach is this:

We do not need to calculate the population independently for every year. We only need to process the years when the population changes.

This problem is a great example of a sweep-line algorithm because each person creates two events: one when they are born and another when they die.

We'll build the solution from the basic idea, work through an example step by step, and then implement it in Java 24.

## 1. Understand the problem first

Suppose we have these people:

```
int[][] logs = {
    {1950, 1960},
    {1955, 1965},
    {1955, 1970}
};
```

Each pair represents `[birthYear, deathYear]`.

A person is counted from their birth year, but not in their death year.

That means:

- Person 1 is alive from 1950 through 1959.
- Person 2 is alive from 1955 through 1964.
- Person 3 is alive from 1955 through 1969.

The population changes over time:

| Year | People alive    | Population |
| ---- | --------------- | ---------- |
| 1950 | Person 1        | 1          |
| 1951 | Person 1        | 1          |
| 1954 | Person 1        | 1          |
| 1955 | Persons 1, 2, 3 | 3          |
| 1959 | Persons 1, 2, 3 | 3          |
| 1960 | Persons 2, 3    | 2          |
| 1965 | Person 3        | 1          |
| 1970 | Nobody          | 0          |

The maximum population is `3`, and the earliest year with that population is `1955`.

Our goal is to find that year without checking every person in every year.

## 2. Thought process: how to discover the sweep-line solution

Imagine you are standing on a timeline, moving from the earliest year to the latest year.

You maintain one variable:

```
int population = 0;
```

As you move forward, you update this variable whenever someone is born or dies.

Ask yourself: When should the population increase, and when should it decrease?

For each person `[birth, death]`:

- At `birth`, population increases by `1`.
- At `death`, population decreases by `1`.

Why decrease at `death` rather than `death - 1`? Because the person is still alive during `death - 1`, but they are no longer counted in `death`.

For example, consider one person:

```
Person: [2000, 2003]

Year:       2000  2001  2002  2003  2004
Alive?       Yes   Yes   Yes    No    No
Population:   +1    +1    +1    -1     0
```

We do not need to store `+1` for every year from 2000 to 2002. We only need two events:

```
2000 -> +1
2003 -> -1
```

The running population naturally stays at `1` between those events.

This is the core insight: record changes, then sweep through the changes in chronological order.

## 3. Build the sweep-line algorithm step by step

### Step 1: Convert people into events

For every person, create two events:

| Person         | Birth event  | Death event  |
| -------------- | ------------ | ------------ |
| `[1950, 1960]` | `(1950, +1)` | `(1960, -1)` |
| `[1955, 1965]` | `(1955, +1)` | `(1965, -1)` |
| `[1955, 1970]` | `(1955, +1)` | `(1970, -1)` |

Notice that two people are born in 1955. Therefore, their changes can be combined:

```
1950 -> +1
1955 -> +2
1960 -> -1
1965 -> -1
1970 -> -1
```

We now have five distinct event years instead of checking all 21 years from 1950 through 1970.

### Step 2: Sort events by year

The sweep line must process events chronologically.

```
1950       1955       1960       1965       1970
  |          |          |          |          |
 +1         +2         -1         -1         -1
```

We can use a `TreeMap<Integer, Integer>` to keep event years sorted automatically. The key is the year, and the value is the net population change in that year.

### Step 3: Sweep through the events

Start with:

```
int population = 0;
int maxPopulation = 0;
int answer = 1950;
```

Process each event in ascending year order.

| Event year | Change | Running population | Maximum so far | Answer |
| ---------- | ------ | ------------------ | -------------- | ------ |
| 1950       | +1     | 1                  | 1              | 1950   |
| 1955       | +2     | 3                  | 3              | 1955   |
| 1960       | -1     | 2                  | 3              | 1955   |
| 1965       | -1     | 1                  | 3              | 1955   |
| 1970       | -1     | 0                  | 3              | 1955   |

The population remains constant between consecutive event years. For example, after processing the 1955 event, the population remains `3` until the 1960 event.

This is why we only need to examine event years: the population cannot increase or decrease between events.

### Step 4: Handle ties correctly

Suppose the maximum population occurs in both 1960 and 1970.

Because events are processed in ascending order, we encounter 1960 first.

Use:

```
if (population > maxPopulation)
```

Do not use `>=`, because that would replace the earlier year when the same maximum appears again.

One subtle detail: we must process all changes for a given year together before checking its population. A birth and a death can happen in the same year. Their net effect determines the population for that year.

## 4. Java 24 solution using `TreeMap`

This is the cleanest implementation of the event-based sweep-line approach.

```java
import java.util.Map;
import java.util.TreeMap;

class Solution {

    public int maximumPopulation(int[][] logs) {

        /*
         * THOUGHT PROCESS:
         *
         * Instead of checking every person for every year, represent
         * each birth and death as a population-change event.
         *
         * Birth year -> +1, because the person becomes alive in that year.
         * Death year -> -1, because the person is excluded starting that year.
         *
         * A TreeMap stores years in sorted order and combines changes
         * automatically when several events occur in the same year.
         *
         * Example:
         * [1950, 1960] produces 1950 -> +1 and 1960 -> -1.
         * [1955, 1965] produces 1955 -> +1 and 1965 -> -1.
         *
         * At 1955, the map's value becomes +1 for each birth in that year.
         */

        // Key = event year; value = net change in population during that year.
        // TreeMap guarantees ascending iteration order of the years.
        Map<Integer, Integer> events = new TreeMap<>();

        for (int[] log : logs) {
            int birth = log[0];
            int death = log[1];

            // A birth adds one person to the population starting in birth year.
            events.merge(birth, 1, Integer::sum);

            // A death removes one person starting in death year.
            // This respects the problem's inclusive-birth, exclusive-death rule.
            events.merge(death, -1, Integer::sum);
        }

        /*
         * SWEEP-LINE:
         *
         * Imagine moving from left to right along the timeline.
         * Between event years, nobody enters or leaves the population,
         * so the population remains constant.
         *
         * We only need to update the population at event years.
         */

        int population = 0;
        int maxPopulation = 0;

        // The constraints guarantee that the earliest possible year is 1950.
        int answer = 1950;

        for (Map.Entry<Integer, Integer> event : events.entrySet()) {
            int year = event.getKey();
            int change = event.getValue();

            // Apply ALL net changes for this year.
            // This gives the population alive during this particular year.
            population += change;

            /*
             * Update only when the population is strictly greater.
             *
             * Why not >=?
             * Events are visited in chronological order. If a later year
             * ties the maximum, keeping the existing answer guarantees
             * that we return the earliest year with maximum population.
             */
            if (population > maxPopulation) {
                maxPopulation = population;
                answer = year;
            }
        }

        return answer;
    }
}

/*
 * TIME COMPLEXITY:
 *
 * Let n = number of people and E = number of distinct event years.
 *
 * 1. Creating events:
 *    Each person creates two events, so there are at most 2n insertions.
 *    Each TreeMap insertion takes O(log E).
 *    Total: O(n log E).
 *
 * 2. Sweeping events:
 *    We visit each distinct event year once.
 *    Total: O(E).
 *
 * Overall: O(n log E + E).
 *
 * Since E <= 2n, this simplifies to O(n log n) in the general case.
 *
 * SPACE COMPLEXITY:
 *
 * The TreeMap stores at most 2n distinct event years.
 * Therefore, auxiliary space is O(E) = O(n).
 *
 * For this problem, years are bounded between 1950 and 2050, so the
 * number of distinct event years is at most 101.
 */
```

## 5. Visualize the sweep line

Here is the mental model to remember during an interview:

```
Timeline:
          1950       1955       1960       1965       1970
            |          |          |          |          |
Event:     +1         +2         -1         -1         -1
            |          |          |          |          |
Population  1 --------> 3 --------> 2 --------> 1 --------> 0
                       ^
                       |
                  Maximum = 3
                  Answer = 1955
```

The sweep line maintains the current population. When it encounters an event, it applies that event's change and checks whether the new population exceeds the previous maximum.

## 6. Why `TreeMap` is a good fit

Consider two people:

```
Person A: [2000, 2005]
Person B: [2005, 2010]
```

At 2005, one person dies and another is born.

The events are:

```
2000 -> +1
2005 -> -1 + 1 = 0
2010 -> -1
```

The net change at 2005 is zero. The population is `1` in both 2004 and 2005.

Using `TreeMap.merge()` combines the events for 2005 automatically. We do not need special logic to handle multiple births and deaths in the same year.

There is another useful property: if we use a `HashMap`, we would need to sort its keys before sweeping. A `TreeMap` maintains the keys in sorted order as events are added.

## 7. An alternative sweep-line implementation using event records

In Java 24, we can explicitly model each event using a `record`. This makes the event-based mental model especially clear and is useful if an interviewer asks you to represent events as objects.

```java
import java.util.ArrayList;
import java.util.Comparator;
import java.util.List;

class Solution {

    // Each event records the year and how the population changes in that year.
    // A record is useful because an event is a simple immutable data value.
    private record Event(int year, int delta) {}

    public int maximumPopulation(int[][] logs) {

        List<Event> events = new ArrayList<>(2 * logs.length);

        // Create exactly two events for every person.
        for (int[] log : logs) {
            events.add(new Event(log[0], +1)); // Birth: population increases.
            events.add(new Event(log[1], -1)); // Death: population decreases.
        }

        // Sort all events chronologically.
        events.sort(Comparator.comparingInt(Event::year));

        int population = 0;
        int maxPopulation = 0;
        int answer = 1950;

        int i = 0;

        while (i < events.size()) {
            int year = events.get(i).year();
            int netChange = 0;

            /*
             * Group every event belonging to the same year.
             *
             * This is important because multiple people may be born or die
             * in the same year. Apply their combined change before measuring
             * the population for that year.
             */
            while (i < events.size() && events.get(i).year() == year) {
                netChange += events.get(i).delta();
                i++;
            }

            // Population for 'year' is obtained after applying its net change.
            population += netChange;

            // Strict comparison preserves the earliest year in a tie.
            if (population > maxPopulation) {
                maxPopulation = population;
                answer = year;
            }
        }

        return answer;
    }
}

/*
 * TIME COMPLEXITY:
 *
 * Creating the events takes O(n).
 * Sorting 2n events takes O(n log n).
 * Sweeping and grouping events takes O(n).
 *
 * Total: O(n log n).
 *
 * SPACE COMPLEXITY:
 *
 * We store two event records per person.
 * Total auxiliary space: O(n).
 */
```

Both implementations use the same algorithm. The difference is how the events are represented:

- `TreeMap`: aggregates same-year events automatically and keeps years sorted.
- Event records: explicitly stores every birth and death event, then sorts and groups them.

For an interview, I would generally start with the `TreeMap` solution because the code is concise. I would use the event-record approach if the interviewer wanted to discuss a more general sweep-line framework.

## 8. Interview follow-up questions

Q1. Why can we ignore years without events?

The population only changes when a birth or death occurs. Between two consecutive event years, the population remains constant. Therefore, no intermediate year can introduce a new, higher population.

Q2. What if several people are born and die in the same year?

Combine all their changes for that year before evaluating the population. The net change is the number of births minus the number of deaths in that year.

Q3. Is the complexity always \\(O(n\log n)\\)?

For the event-record implementation, yes, in the general case because sorting \\(2n\\) events dominates. For the `TreeMap` implementation, the more precise bound is \\(O(n\log E+E)\\), where \\(E\\) is the number of distinct event years. With the fixed 1950–2050 range, \\(E\\) is bounded by 101.

Q4. When is sweep line better than a difference array?

A difference array is particularly convenient when the coordinate range is small and bounded, as it is here. Sweep line is more flexible when event coordinates are sparse or the coordinate range is huge, because it processes only event locations rather than allocating an array for every possible year.

Q5. What is the single most important correctness detail?

Apply the birth and death changes for a year before evaluating that year's population. Then update the answer only when the population is strictly greater than the maximum seen so far.

Final takeaway: Think of the problem as a timeline of events. A birth adds one, a death removes one, a running sum gives the population, and chronological processing with a strict maximum comparison guarantees the earliest answer.
