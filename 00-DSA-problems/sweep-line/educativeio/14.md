# 699. Falling Squares — Hard

The optimal solution is Coordinate Compression + Segment Tree with Lazy Propagation.

There are also simpler approaches worth understanding first:

1. Brute force: Check every previously dropped square.
2. Coordinate compression + array: Simulate heights directly.
3. Coordinate compression + Segment Tree: Efficient range maximum query and range assignment.
4. Dynamic Segment Tree: Useful when the coordinate range is extremely large and compression is not preferred.

Let's understand each approach step by step.

# 0. Simplify the problem

You are dropping squares onto a horizontal X-axis.

Each square is represented by:

```
[left, sideLength]
```

For every square:

1. Find the maximum height of the existing squares underneath its horizontal interval.
2. The new square lands on top of that maximum height.
3. Its new height becomes:

   `maximumExistingHeight + sideLength`
4. Update the horizontal interval covered by this square with its new height.
5. Record the maximum height across all squares so far.

Important: Squares are permanent. Once dropped, they never move.

### Example

```
positions = [[1,2], [2,3], [6,1]]
```

First square: `[1, 2]`

```
       ┌────┐
       │    │  Height = 2
───────┴────┴──────── X-axis
       1    3
```

Maximum height = 2.

Second square: `[2, 3]`

Its horizontal interval overlaps the first square.

It lands on top of the first square.

```
          ┌──────┐
          │      │
       ┌──┴──────┤
       │         │
───────┴─────────┴──── X-axis
       1         5
```

The second square's bottom is at height 2.

Its top is at height:

`2 + 3 = 5`

Maximum height = 5.

Third square: `[6, 1]`

It does not overlap either previous square.

Its height is 1.

The maximum height remains 5.

```
Output = [2, 5, 5]
```

# 1. Clarifying questions to ask the interviewer

Before coding, clarify these details:

Q1. Are the intervals inclusive or half-open?

Why?

The problem says brushing the left/right side does not count as landing.

Therefore, we should interpret the horizontal interval as:

`[left, left + sideLength)`

For example:

- Square A: `[1, 3)`
- Square B: `[3, 5)`

These squares only touch at coordinate 3. They do not overlap.

Q2. Can squares overlap partially?

Why?

Yes. A new square can overlap multiple previous squares. It must land on the highest existing surface anywhere in its horizontal interval.

Q3. Do we need to return the maximum height after every drop or the individual square's height?

Why?

The required answer is the global maximum height after each drop, not necessarily the height of the newly dropped square.

Q4. Can coordinates and heights exceed the Java int range?

Why?

Given constraints:

- `left <= 10^8`
- `sideLength <= 10^6`
- `n <= 1000`

The maximum possible total height is at most \\(10^9\\), which fits in `int`. However, using `long` for intermediate coordinate arithmetic is a good defensive practice.

# 2. Core intuition and mental model

Think of the X-axis as a collection of horizontal segments.

Each segment stores the current topmost height at that position.

For every new square, we perform two operations:

1. Range Maximum Query: Find the maximum height over the square's horizontal interval.
2. Range Assignment: Set the height of the entire interval to the new square's top height.

The important observation:

A square does not care about the individual squares underneath it. It only cares about the maximum height across its horizontal interval.

For example:

```
Existing heights:

X:       1   2   3   4   5   6
Height:  2   2   4   4   1   1

New square covers [2, 5)

Maximum existing height = 4

New square side length = 3

New square top = 4 + 3 = 7

Update all positions in [2, 5) to height 7.
```

This is exactly the kind of problem where a Segment Tree with Lazy Propagation is useful.

# 3. Approach 1: Brute Force

The simplest solution is to maintain all previously dropped squares.

For each new square:

1. Calculate its horizontal interval.
2. Iterate over all previous squares.
3. Check whether the intervals overlap.
4. Find the maximum top height among overlapping squares.
5. Place the new square at that height.
6. Store its new top height.

```
import java.util.*;

class Solution {

    // Stores the horizontal interval and the top height of a dropped square.
    private record Square(long left, long right, long top) {}

    public List<Integer> fallingSquares(int[][] positions) {

        List<Square> squares = new ArrayList<>();
        List<Integer> answer = new ArrayList<>();

        int globalMax = 0;

        for (int[] position : positions) {

            long left = position[0];

            // Half-open interval [left, right).
            long right = left + position[1];

            long baseHeight = 0;

            /*
             * STEP 1: Find the maximum height of all previously
             * dropped squares that horizontally overlap this square.
             *
             * Two half-open intervals overlap when:
             *
             * newLeft < oldRight AND oldLeft < newRight
             *
             * Strict inequalities are important:
             * touching boundaries do not count as overlap.
             */
            for (Square previous : squares) {

                boolean overlaps =
                        left < previous.right() &&
                        previous.left() < right;

                if (overlaps) {

                    /*
                     * The new square falls until it touches the
                     * highest overlapping square.
                     *
                     * Therefore, its base height is the maximum
                     * top height among overlapping squares.
                     */
                    baseHeight = Math.max(
                            baseHeight,
                            previous.top()
                    );
                }
            }

            /*
             * STEP 2: Calculate the top height of the new square.
             *
             * New top = Highest supporting surface + Side length.
             */
            long newTop = baseHeight + position[1];

            /*
             * STEP 3: Store the newly dropped square.
             *
             * Previously dropped squares remain unchanged.
             */
            squares.add(new Square(left, right, newTop));

            /*
             * STEP 4: Maintain the tallest stack seen so far.
             */
            globalMax = (int) Math.max(globalMax, newTop);

            answer.add(globalMax);
        }

        return answer;
    }
}
```

### Complexity

Let `n` be the number of squares.

- Time: O(n²). For each square, we inspect every previously dropped square.
- Space: O(n). We store every dropped square and the answer.

This is simple but can be improved.

# 4. Approach 2: Coordinate Compression + Array

Before jumping to Segment Trees, let's understand coordinate compression.

## Why coordinate compression?

Our coordinates can be as large as `100,000,000`.

Creating an array indexed directly by X-coordinate would be wasteful.

But notice:

We only care about coordinates where squares begin or end.

For every square, collect:

```
left
right = left + sideLength
```

Then sort all unique coordinates and replace them with smaller indices.

### Example

```
positions = [[1,2], [2,3], [6,1]]
```

Original coordinates:

```
1, 3, 2, 5, 6, 7
```

After sorting and removing duplicates:

```
Original:  1   2   3   5   6   7
Index:     0   1   2   3   4   5
```

Now the square intervals become:

```
[1, 3) -> compressed indices [0, 2)
[2, 5) -> compressed indices [1, 3)
[6, 7) -> compressed indices [4, 5)
```

The compressed intervals represent elementary segments between consecutive coordinates.

```
Coordinates:  1    2    3       5    6    7
              |----|----|-------|----|----|
Index:          0    1    2       3    4
```

Each index represents an elementary interval, not a coordinate point.

This distinction is important.

## Java implementation

```
import java.util.*;

class Solution {

    public List<Integer> fallingSquares(int[][] positions) {

        /*
         * STEP 1: Collect all left and right boundaries.
         *
         * WHY?
         * We only need to represent intervals where square boundaries
         * occur. We do not need every integer coordinate.
         */
        TreeSet<Long> coordinates = new TreeSet<>();

        for (int[] position : positions) {

            long left = position[0];
            long right = left + position[1];

            coordinates.add(left);
            coordinates.add(right);
        }

        /*
         * STEP 2: Assign compressed indices to sorted coordinates.
         *
         * Example:
         * Original coordinates: [1, 2, 3, 5, 6, 7]
         *
         * Compressed indices:
         * 1 -> 0
         * 2 -> 1
         * 3 -> 2
         * 5 -> 3
         * 6 -> 4
         * 7 -> 5
         */
        Map<Long, Integer> index = new HashMap<>();

        int id = 0;

        for (long coordinate : coordinates) {
            index.put(coordinate, id++);
        }

        /*
         * STEP 3: Create an array representing the height
         * of every elementary interval.
         *
         * If there are m unique coordinates, there are m - 1
         * elementary intervals.
         */
        int[] heights = new int[id - 1];

        List<Integer> answer = new ArrayList<>();

        int globalMax = 0;

        /*
         * STEP 4: Process squares in their original dropping order.
         */
        for (int[] position : positions) {

            long left = position[0];
            long right = left + position[1];

            int start = index.get(left);
            int end = index.get(right);

            /*
             * Find the maximum height over elementary intervals
             * covered by [start, end).
             */
            int baseHeight = 0;

            for (int i = start; i < end; i++) {

                baseHeight = Math.max(
                        baseHeight,
                        heights[i]
                );
            }

            /*
             * The new square lands on the highest existing surface.
             */
            int newHeight = baseHeight + position[1];

            /*
             * Update every elementary interval covered by the square.
             *
             * WHY ASSIGN instead of ADD?
             *
             * The new square becomes the topmost surface over its
             * entire horizontal interval.
             *
             * Therefore, all covered intervals now have the new
             * square's top height.
             */
            for (int i = start; i < end; i++) {
                heights[i] = newHeight;
            }

            globalMax = Math.max(globalMax, newHeight);

            answer.add(globalMax);
        }

        return answer;
    }
}
```

### Complexity

Let `n` be the number of squares and `m` the number of unique coordinates.

Since every square contributes two coordinates:

`m <= 2n`

- Coordinate compression: O(n log n)
- Each range maximum query: O(m)
- Each range update: O(m)
- Total: O(n²).
- Space: O(n).

This is better in terms of representing the coordinate range, but the query and update operations are still linear.

We need a data structure that supports both operations efficiently.

# 5. Approach 3: Optimal — Coordinate Compression + Segment Tree + Lazy Propagation

Recommended solution

## 5.1 Why Segment Tree?

We need two operations over an interval:

| Operation           | Meaning                                            |
| ------------------- | -------------------------------------------------- |
| Range Maximum Query | Find the maximum height in `[L, R)`                |
| Range Assignment    | Set every height in `[L, R)` to a particular value |

A Segment Tree supports both efficiently.

However, updating every individual element in a range would still be expensive.

That's where Lazy Propagation comes in.

Instead of immediately updating every child node, we record a pending assignment at the parent.

The assignment is propagated to children only when necessary.

## 5.2 Segment Tree mental model

Suppose our compressed elementary intervals are:

```
[1,2) [2,3) [3,5) [5,6) [6,7)
```

Our Segment Tree stores the maximum height of each segment.

Conceptually:

```
                    [0, 5)
                   max = 4
                  /       \
             [0, 2)       [2, 5)
             max = 2      max = 4
             /   \        /    \
           [0,1) [1,2)  [2,3) [3,5)
             2     2      4      4
```

Each node represents a range.

Its value is the maximum height within that range.

## 5.3 Lazy propagation

Suppose we want to assign height 7 to the entire range `[1, 5)`.

Without lazy propagation, we might visit every leaf.

With lazy propagation:

- Fully covered nodes receive the new value immediately.
- Their lazy assignment is recorded.
- Their children are updated only when a later query or update needs them.

For range assignment, the lazy value must represent a pending assignment, not an addition.

We use:

```
-1 = no pending assignment
```

Since all actual heights are nonnegative, `-1` is a safe sentinel.

## 5.4 Complete optimal Java 24 solution

```
import java.util.*;

/*
 * 699. Falling Squares
 *
 * OPTIMAL APPROACH:
 * Coordinate Compression + Segment Tree + Lazy Propagation.
 *
 * Operations required:
 *
 * 1. Range Maximum Query:
 *    Find the maximum height in [left, right).
 *
 * 2. Range Assignment:
 *    Assign the same height to every elementary interval
 *    inside [left, right).
 *
 * Segment Tree supports both operations in O(log n).
 */
class Solution {

    /*
     * Immutable representation of a square's horizontal boundaries.
     *
     * We use long for coordinates to make left + sideLength safe
     * even if constraints are expanded in the future.
     */
    private record Interval(long left, long right) {}

    private static final class SegmentTree {

        /*
         * Maximum height in each segment.
         *
         * tree[node] stores the maximum height among all
         * elementary intervals represented by this node.
         */
        private final int[] tree;

        /*
         * Lazy assignment value.
         *
         * lazy[node] = -1:
         *     No pending assignment.
         *
         * lazy[node] = x:
         *     Entire segment represented by this node
         *     should have height x.
         *
         * Assignment is different from addition.
         * We overwrite previous heights with the new height.
         */
        private final int[] lazy;

        /*
         * Number of elementary intervals.
         */
        private final int n;

        SegmentTree(int n) {

            this.n = n;

            /*
             * A segment tree generally needs approximately 4*n nodes.
             */
            this.tree = new int[4 * n];

            this.lazy = new int[4 * n];

            /*
             * Initially, every position has height zero.
             *
             * No node has a pending assignment.
             */
            Arrays.fill(lazy, -1);
        }

        /*
         * Apply an assignment directly to a node.
         *
         * WHY?
         * Every elementary interval represented by this node
         * will have exactly the same height.
         *
         * Therefore:
         *
         * Maximum of the segment = assigned height.
         *
         * We also record the assignment for its children.
         */
        private void apply(int node, int value) {

            tree[node] = value;

            lazy[node] = value;
        }

        /*
         * Push a pending assignment from the current node
         * to its children.
         *
         * WHY?
         * A parent may have received a range assignment without
         * visiting its children.
         *
         * Before partially querying or updating its children,
         * we must make sure they reflect the parent's assignment.
         */
        private void pushDown(int node) {

            if (lazy[node] == -1) {
                return;
            }

            int value = lazy[node];

            /*
             * Both children inherit the parent's assignment.
             */
            apply(node * 2, value);

            apply(node * 2 + 1, value);

            /*
             * The parent's lazy assignment has now been propagated.
             */
            lazy[node] = -1;
        }

        /*
         * Merge information from the two children.
         *
         * WHY MAX?
         * Each node represents the maximum height over its
         * complete interval.
         *
         * Therefore, the parent's maximum is:
         *
         * max(leftChildMaximum, rightChildMaximum).
         */
        private void pullUp(int node) {

            tree[node] = Math.max(
                    tree[node * 2],
                    tree[node * 2 + 1]
            );
        }

        /*
         * PUBLIC RANGE MAXIMUM QUERY.
         *
         * Query the maximum height over [queryLeft, queryRight).
         *
         * We use half-open intervals consistently.
         */
        int query(int queryLeft, int queryRight) {

            return query(
                    1,
                    0,
                    n,
                    queryLeft,
                    queryRight
            );
        }

        /*
         * Recursive range maximum query.
         *
         * Parameters:
         *
         * node:
         *     Current segment tree node.
         *
         * start, end:
         *     Current node's represented interval [start, end).
         *
         * queryLeft, queryRight:
         *     Requested interval [queryLeft, queryRight).
         */
        private int query(
                int node,
                int start,
                int end,
                int queryLeft,
                int queryRight
        ) {

            /*
             * CASE 1: Complete overlap.
             *
             * The current node's interval is completely contained
             * inside the requested query interval.
             *
             * Its stored maximum is exactly what we need.
             */
            if (queryLeft <= start && end <= queryRight) {

                return tree[node];
            }

            /*
             * Before exploring children, propagate pending
             * assignments so child values are up to date.
             */
            pushDown(node);

            int mid = start + (end - start) / 2;

            int result = 0;

            /*
             * CASE 2: Query intersects the left child.
             */
            if (queryLeft < mid) {

                result = Math.max(
                        result,
                        query(
                                node * 2,
                                start,
                                mid,
                                queryLeft,
                                queryRight
                        )
                );
            }

            /*
             * CASE 3: Query intersects the right child.
             */
            if (queryRight > mid) {

                result = Math.max(
                        result,
                        query(
                                node * 2 + 1,
                                mid,
                                end,
                                queryLeft,
                                queryRight
                        )
                );
            }

            /*
             * Merge the results from all intersecting children.
             */
            return result;
        }

        /*
         * PUBLIC RANGE ASSIGNMENT.
         *
         * Assign 'value' to every elementary interval
         * in [updateLeft, updateRight).
         */
        void update(
                int updateLeft,
                int updateRight,
                int value
        ) {

            update(
                    1,
                    0,
                    n,
                    updateLeft,
                    updateRight,
                    value
            );
        }

        /*
         * Recursive range assignment with lazy propagation.
         */
        private void update(
                int node,
                int start,
                int end,
                int updateLeft,
                int updateRight,
                int value
        ) {

            /*
             * CASE 1: Complete overlap.
             *
             * The current segment is completely covered
             * by the update interval.
             *
             * No need to visit its children.
             *
             * Directly assign the new value and record it lazily.
             */
            if (updateLeft <= start && end <= updateRight) {

                apply(node, value);

                return;
            }

            /*
             * CASE 2: Partial overlap.
             *
             * We must propagate any previous assignment
             * before modifying individual children.
             */
            pushDown(node);

            int mid = start + (end - start) / 2;

            /*
             * Update the left child if it intersects the update range.
             */
            if (updateLeft < mid) {

                update(
                        node * 2,
                        start,
                        mid,
                        updateLeft,
                        updateRight,
                        value
                );
            }

            /*
             * Update the right child if it intersects the update range.
             */
            if (updateRight > mid) {

                update(
                        node * 2 + 1,
                        mid,
                        end,
                        updateLeft,
                        updateRight,
                        value
                );
            }

            /*
             * After modifying children, recompute this node's maximum.
             */
            pullUp(node);
        }
    }

    public List<Integer> fallingSquares(int[][] positions) {

        int n = positions.length;

        /*
         * STEP 1: Coordinate Compression.
         *
         * Each square contributes:
         *
         * left  = positions[i][0]
         * right = left + positions[i][1]
         *
         * We collect both boundaries.
         *
         * WHY?
         * We need to represent all horizontal elementary intervals
         * where the height can change.
         *
         * There is no need to allocate an array for all original
         * X-coordinates, which may be as large as 10^8.
         */
        TreeSet<Long> coordinateSet = new TreeSet<>();

        for (int[] position : positions) {

            long left = position[0];

            long right = left + position[1];

            coordinateSet.add(left);

            coordinateSet.add(right);
        }

        /*
         * STEP 2: Map original coordinates to compressed indices.
         *
         * Sorted unique coordinates receive indices:
         *
         * c0 -> 0
         * c1 -> 1
         * c2 -> 2
         * ...
         *
         * An original interval [ci, cj) becomes
         * compressed interval [i, j).
         */
        Map<Long, Integer> indexMap = new HashMap<>();

        int index = 0;

        for (long coordinate : coordinateSet) {

            indexMap.put(coordinate, index);

            index++;
        }

        /*
         * STEP 3: Build the Segment Tree.
         *
         * If there are m unique coordinates, there are m - 1
         * elementary intervals.
         *
         * Example:
         *
         * Coordinates: [1, 2, 3, 5, 6, 7]
         *
         * Elementary intervals:
         *
         * [1,2), [2,3), [3,5), [5,6), [6,7)
         *
         * Therefore, segment tree size = m - 1.
         */
        int segmentCount = coordinateSet.size() - 1;

        SegmentTree segmentTree = new SegmentTree(segmentCount);

        /*
         * STEP 4: Process squares in their original order.
         *
         * The dropping order matters.
         * We cannot sort the squares themselves.
         */
        List<Integer> answer = new ArrayList<>();

        int globalMax = 0;

        for (int[] position : positions) {

            long left = position[0];

            long right = left + position[1];

            int sideLength = position[1];

            /*
             * Convert original boundaries to compressed indices.
             *
             * Original interval:
             *     [left, right)
             *
             * Compressed interval:
             *     [start, end)
             *
             * Each index represents an elementary interval.
             */
            int start = indexMap.get(left);

            int end = indexMap.get(right);

            /*
             * STEP 5: Range Maximum Query.
             *
             * Find the maximum existing height underneath
             * the new square.
             *
             * WHY?
             * A falling square stops when it first touches
             * the highest surface within its horizontal footprint.
             *
             * This is exactly a range maximum query.
             */
            int baseHeight = segmentTree.query(start, end);

            /*
             * STEP 6: Calculate the new square's top height.
             *
             * New bottom = baseHeight
             *
             * New top = baseHeight + sideLength
             *
             * This new top height becomes the surface over
             * the entire horizontal footprint of the square.
             */
            int newHeight = baseHeight + sideLength;

            /*
             * STEP 7: Range Assignment.
             *
             * Assign newHeight to every elementary interval
             * covered by the newly dropped square.
             *
             * WHY ASSIGN?
             *
             * The new square becomes the topmost surface across
             * its complete horizontal footprint.
             *
             * Even if the previous heights were different,
             * the new square covers them all.
             *
             * This is why we use range assignment rather than
             * range addition.
             */
            segmentTree.update(
                    start,
                    end,
                    newHeight
            );

            /*
             * STEP 8: Maintain the global maximum.
             *
             * We only need to compare the new square's top
             * against the previous global maximum.
             *
             * Previously existing squares never move or shrink,
             * so the global maximum can never decrease.
             */
            globalMax = Math.max(globalMax, newHeight);

            answer.add(globalMax);
        }

        return answer;
    }
}
```

# 7. Approach 4: Dynamic Segment Tree

Coordinate compression is particularly convenient here because all square boundaries are known upfront.

However, suppose the coordinates are extremely large or arrive dynamically, and we cannot preprocess all boundaries.

We can use a Dynamic Segment Tree.

The idea:

- Build nodes only when needed.
- Each node represents a coordinate interval.
- Each node stores its maximum height.
- Each node stores a lazy assignment.
- Missing nodes represent untouched regions with height zero.

The following implementation uses the original coordinate domain `[1, 1_000_000_001)` based on the problem's constraints.

```
class Solution {

    private static final class Node {

        int maxHeight;

        // -1 means no pending assignment.
        int lazy = -1;

        Node left;
        Node right;
    }

    private final Node root = new Node();

    public List<Integer> fallingSquares(int[][] positions) {

        List<Integer> answer = new ArrayList<>();

        int globalMax = 0;

        /*
         * The coordinate domain is large, but we create nodes
         * only for regions that are actually accessed.
         */
        for (int[] position : positions) {

            int left = position[0];

            int right = left + position[1];

            int side = position[1];

            int base = query(
                    root,
                    1,
                    1_000_000_001,
                    left,
                    right
            );

            int newHeight = base + side;

            update(
                    root,
                    1,
                    1_000_000_001,
                    left,
                    right,
                    newHeight
            );

            globalMax = Math.max(globalMax, newHeight);

            answer.add(globalMax);
        }

        return answer;
    }

    private void apply(Node node, int value) {

        node.maxHeight = value;

        node.lazy = value;
    }

    private void pushDown(Node node) {

        if (node.lazy == -1) {
            return;
        }

        if (node.left == null) {
            node.left = new Node();
        }

        if (node.right == null) {
            node.right = new Node();
        }

        apply(node.left, node.lazy);

        apply(node.right, node.lazy);

        node.lazy = -1;
    }

    private int query(
            Node node,
            int start,
            int end,
            int queryLeft,
            int queryRight
    ) {

        /*
         * An absent node represents an untouched region.
         * Its height is zero.
         */
        if (node == null) {
            return 0;
        }

        if (queryLeft <= start && end <= queryRight) {
            return node.maxHeight;
        }

        pushDown(node);

        int mid = start + (end - start) / 2;

        int result = 0;

        if (queryLeft < mid) {

            result = Math.max(
                    result,
                    query(
                            node.left,
                            start,
                            mid,
                            queryLeft,
                            queryRight
                    )
            );
        }

        if (queryRight > mid) {

            result = Math.max(
                    result,
                    query(
                            node.right,
                            mid,
                            end,
                            queryLeft,
                            queryRight
                    )
            );
        }

        return result;
    }

    private void update(
            Node node,
            int start,
            int end,
            int updateLeft,
            int updateRight,
            int value
    ) {

        if (updateLeft <= start && end <= updateRight) {

            apply(node, value);

            return;
        }

        pushDown(node);

        int mid = start + (end - start) / 2;

        if (updateLeft < mid) {

            if (node.left == null) {
                node.left = new Node();
            }

            update(
                    node.left,
                    start,
                    mid,
                    updateLeft,
                    updateRight,
                    value
            );
        }

        if (updateRight > mid) {

            if (node.right == null) {
                node.right = new Node();
            }

            update(
                    node.right,
                    mid,
                    end,
                    updateLeft,
                    updateRight,
                    value
            );
        }

        int leftMax = node.left == null
                ? 0
                : node.left.maxHeight;

        int rightMax = node.right == null
                ? 0
                : node.right.maxHeight;

        node.maxHeight = Math.max(leftMax, rightMax);
    }
}
```

### Complexity

Let `U` be the size of the coordinate domain.

- Time per query: O(log U), under the standard segment-tree range-operation bound.
- Time per update: O(log U), under the same bound.
- Total time: O(n log U).
- Space: O(n log U) in the worst case for dynamically allocated nodes.

For this problem, coordinate compression is usually preferable because all boundaries are known in advance.

# 8. Comparison of all approaches

| Approach                   | Time complexity | Space complexity |
| -------------------------- | --------------- | ---------------- |
| Brute force                | O(n²)           | O(n)             |
| Compression + Array        | O(n²)           | O(n)             |
| Compression + Segment Tree | O(n log n)      | O(n)             |
| Dynamic Segment Tree       | O(n log U)      | O(n log U)       |

My interview recommendation: Start by explaining brute force, identify that the repeated operation is range maximum + range assignment, then introduce coordinate compression and lazy propagation.

# 9. Important edge cases

1\. Squares that only touch boundaries

```
positions = new int[][] {
    {1, 2},
    {3, 2}
};
```

Intervals:

```
[1, 3)
[3, 5)
```

They do not overlap.

Output:

```
[2, 2]
```

2\. Complete overlap

```
positions = new int[][] {
    {1, 5},
    {1, 3}
};
```

The second square lands on top of the first.

Output:

```
[5, 8]
```

3\. Nested intervals

```
positions = new int[][] {
    {1, 10},
    {3, 2},
    {4, 1}
};
```

Output:

```
[10, 12, 13]
```

4\. No overlap

```
positions = new int[][] {
    {1, 2},
    {10, 3},
    {20, 1}
};
```

Output:

```
[2, 3, 3]
```

5\. Multiple overlapping squares with different heights

The new square must land on the highest surface, not the first or last overlapping square.

6\. Same left coordinate, different side lengths

The new square must account for the previous square's height across its entire footprint.

# 10. Interviewer follow-up questions

### Q1. Why do we need coordinate compression?

Because original coordinates can be very large, but the number of relevant boundaries is at most `2 * n`.

Coordinate compression preserves interval relationships while reducing the problem to O(n) elementary segments.

### Q2. Why do we use elementary intervals instead of coordinate points?

Because square heights are constant between consecutive boundaries.

For example:

```
Coordinates: 1, 2, 5

Elementary intervals:
[1,2), [2,5)
```

The height of each interval can be represented using one value.

### Q3. Why is range assignment required instead of range addition?

Suppose the existing heights are:

```
[2, 4, 3]
```

A new square lands on top of the maximum height 4 and has side length 2.

Its top height becomes 6.

The resulting heights are:

```
[6, 6, 6]
```

Not:

```
[4, 6, 5]
```

The new square covers the entire interval, so every covered position must be assigned 6.

### Q4. Why is lazy propagation necessary?

Without lazy propagation, assigning a value to a large range could require visiting every elementary interval.

Lazy propagation lets us assign an entire segment in O(1) at its corresponding tree node.

### Q5. Why can we maintain global maximum separately?

Because every newly dropped square adds a new top surface, and previous squares never move or shrink.

Therefore:

```
globalMax = Math.max(globalMax, newHeight);
```

is sufficient.

### Q6. Can we solve this using a Fenwick Tree (BIT)?

A conventional Fenwick Tree efficiently supports prefix sums and related operations.

This problem requires both arbitrary range maximum queries and range assignments.

A standard Fenwick Tree does not naturally support these operations together, so a Segment Tree is a better fit.

### Q7. What changes if squares can be removed?

We would need to recompute heights affected by the removed square.

The current segment tree stores only the topmost height, not the full collection of underlying squares.

Therefore, simply assigning a lower height would be incorrect. We would need additional information about the overlapping squares, such as an interval structure or a more sophisticated segment representation.

### Q8. Why not use a TreeMap?

A TreeMap can store intervals and their heights, but range splitting, merging, querying maximum height, and assigning new heights require careful interval maintenance.

A segment tree gives predictable logarithmic range operations and is more straightforward for this problem.

# 11. What to remember for interviews

The most important pattern is:

```
Range Maximum Query
        +
Range Assignment
        +
Large Coordinate Domain
        |
        v
Coordinate Compression
        |
        v
Segment Tree + Lazy Propagation
```

When you encounter a problem involving:

- Large coordinate values.
- Repeated interval updates.
- Queries over interval maximum/minimum.
- Overlapping intervals.
- Range assignment.

Think about Coordinate Compression + Lazy Segment Tree.

The key insight in Falling Squares is not the geometry. It is recognizing that every square performs a range maximum query followed by a range assignment.
