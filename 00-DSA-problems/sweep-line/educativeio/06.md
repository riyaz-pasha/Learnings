# LeetCode 759 — Employee Free Time (Java 24)

Core pattern: Merge Intervals + Sweep Line

Problem link: [Employee Free Time](https://leetcode.com/problems/employee-free-time/description/?utm_source=chatgpt.com)

## 0. Simplify the problem statement

You are given the working schedules of multiple employees. Each employee has a list of non-overlapping intervals, sorted by start time.

Each interval represents when that employee is busy.

Your task is to find the intervals when every employee is free at the same time.

For example, suppose we have three employees:

```
Employee 1: [1, 3], [6, 7]
Employee 2: [2, 4]
Employee 3: [2, 5], [9, 12]
```

We want to find gaps when nobody is working.

The key observation is that we do not need to find each employee's free time separately. Instead, we can combine everyone's busy intervals and merge all overlapping intervals. The gaps between the merged intervals are the common free times.

## 1. Clarifying questions to ask the interviewer

1. Are intervals sorted within each employee's schedule? The problem guarantees this, which allows us to merge schedules efficiently. If it did not, we would need to sort them.
2. Are intervals half-open, such as `[1, 3)`? The problem uses the `Interval` representation with start and end values. We should clarify whether an employee ending at time `3` and another starting at time `3` creates a free interval. Under the usual interval interpretation, a zero-duration gap is not returned.
3. Should we return only finite free intervals between busy periods? Yes. We don't return unbounded free time before the first busy interval or after the last one.
4. Can the input be empty? The original problem provides at least one employee and non-empty schedules. In production code, we can still decide how to handle empty input defensively.
5. Can we modify the input? This determines whether sorting the flattened intervals in place is acceptable. We can avoid changing the original schedules by building a separate collection.

## 2. Core intuition — why merging busy intervals works

Imagine a timeline. If even one employee is working, that time is not free for everyone.

So instead of asking, "When is each employee free?", ask:

When is at least one employee busy?

That gives us the union of all busy intervals. Once we know those periods, every gap between consecutive busy periods is common free time.

### Visual example

Input:

```
Employee A:  [1, 3]       [6, 7]
Employee B:      [2, 4]
Employee C:      [2, 5]               [9, 12]
```

After sorting all intervals by start time:

```
[1,3] [2,4] [2,5] [6,7] [9,12]
```

Merge overlapping intervals:

```
[1,3] + [2,4] + [2,5]  ->  [1,5]

[6,7]                  ->  [6,7]

[9,12]                 ->  [9,12]
```

The combined busy timeline is:

```
Time:   1---------5  6---7  9---------12
        |  BUSY   |  BUSY |  BUSY     |

Gaps:               5-6   7-9
                    FREE  FREE
```

Therefore, the answer is:

```
[[5, 6], [7, 9]]
```

This matches the problem's requirement to return sorted, finite, positive-length free intervals.&#x20;

### The mental model: track the farthest busy endpoint

You do not actually need to store every merged interval.

After sorting, maintain one variable:

`lastBusyEnd` = the farthest endpoint reached by any busy interval processed so far.

For every next interval `[start, end]`, there are two possibilities.

Case 1: The next interval overlaps or touches existing busy time.

```
Existing busy:  [1---------5]
Next interval:       [3-----7]
Combined:        [1-----------7]
```

There is no free time between them. Update:

```
lastBusyEnd = Math.max(lastBusyEnd, end);
```

Why `Math.max`? Because a nested interval must not shrink the busy range.

Case 2: The next interval starts after the current busy range ends.

```
Existing busy:  [1---5]
Next interval:              [8---10]
```

The gap `[5, 8]` is free for every employee because we have processed every busy interval starting before `8`, and none extends beyond `5`.

Record the gap, then start tracking the next busy range.

```
freeTimes.add(new Interval(lastBusyEnd, start));
lastBusyEnd = end;
```

The important rule is:

```
if (start <= lastBusyEnd)
    extend the current busy range if necessary
else
    record [lastBusyEnd, start] and start a new busy range
```

The intervals are sorted by start time, so once we find a gap, no later interval can fill it.

## 3. All solutions — from brute force to optimal

Let:

- \\(N\\) = total number of intervals across all employees.
- \\(K\\) = number of employees.
- \\(F\\) = number of common free intervals returned.

### Solution 1: Sort all intervals, then merge and find gaps

This is the clearest interview solution.

1. Flatten all employee schedules into one list.
2. Sort by interval start.
3. Scan once, tracking `lastBusyEnd`.
4. Whenever `start > lastBusyEnd`, record a free interval.

Time complexity: \\(O(N\log N)\\), dominated by sorting.

Space complexity: \\(O(N)\\) for the flattened intervals and, in the implementation below, the result. We can also store a separate merged list, but that is unnecessary.

### Solution 2: Min-heap merge of already-sorted employee schedules

Every employee's intervals are already sorted. Instead of sorting all \\(N\\) intervals again, we can use a min-heap containing the next unprocessed interval from each employee.

1. Insert the first interval of each employee into a min-heap.
2. Extract the interval with the smallest start time.
3. Compare it with the currently tracked busy range.
4. Insert the next interval from the employee whose interval was extracted.
5. Continue until the heap is empty.

Each interval enters and leaves the heap once, and the heap contains at most \\(K\\) intervals.

Time complexity: \\(O(N\log K)\\).

Auxiliary space: \\(O(K)\\) for the heap, excluding the output. This is preferable when there are many intervals spread across relatively few employees.

## 4. Java 24 implementations with detailed inline comments

### Approach A — Flatten, sort, and sweep (recommended)

This is the best starting point in an interview because the reasoning is simple, the code is concise, and the correctness is easy to prove.

```java
import java.util.ArrayList;
import java.util.Comparator;
import java.util.List;

class Solution {

    public List<Interval> employeeFreeTime(
            List<List<Interval>> schedule) {

        /*
         * STEP 1: Flatten every employee's busy intervals into one list.
         *
         * WHY?
         * Common free time depends on all employees together.
         * We don't need to know which employee owns an interval;
         * we only need to know when someone is busy.
         *
         * We store references to the input intervals and never mutate them.
         *
         * Let N = total number of intervals across all employees.
         * Flattening takes O(N) time and O(N) additional space.
         */
        List<Interval> all = new ArrayList<>();

        for (List<Interval> employee : schedule) {
            all.addAll(employee);
        }

        /*
         * STEP 2: Sort all intervals by their start time.
         *
         * WHY?
         * When intervals are processed chronologically, every interval
         * that could overlap the current busy range has an earlier
         * or equal start time and has already been considered.
         *
         * This lets us detect a free gap using only one running endpoint.
         *
         * Time: O(N log N)
         */
        all.sort(Comparator.comparingInt(interval -> interval.start));

        /*
         * STEP 3: Sweep the sorted intervals.
         *
         * lastBusyEnd represents the farthest endpoint reached by
         * the union of all busy intervals processed so far.
         *
         * We don't need to store merged intervals separately.
         * We can produce free intervals as soon as we discover a gap.
         */
        List<Interval> freeTimes = new ArrayList<>();

        // LeetCode guarantees a non-empty schedule, but this guard
        // makes the method safe for an empty outer list as well.
        if (all.isEmpty()) {
            return freeTimes;
        }

        // The first interval establishes the initial busy range.
        int lastBusyEnd = all.getFirst().end;

        for (int i = 1; i < all.size(); i++) {
            Interval current = all.get(i);

            /*
             * CASE 1: Overlapping or touching busy intervals.
             *
             * Example:
             * Existing coverage: [1, 5]
             * Current interval:  [3, 7]
             *
             * The combined busy range becomes [1, 7].
             *
             * Use MAX because a nested interval must not shorten
             * the endpoint:
             * [1, 10] followed by [3, 4] still ends at 10.
             *
             * Touching intervals also have no positive-length gap:
             * [1, 5] and [5, 8] leave no free time between them.
             */
            if (current.start <= lastBusyEnd) {
                lastBusyEnd = Math.max(lastBusyEnd, current.end);
            } else {
                /*
                 * CASE 2: A positive-length gap exists.
                 *
                 * Example:
                 * Existing busy coverage ends at 5.
                 * The next interval starts at 8.
                 *
                 * No employee is busy during [5, 8], so this is
                 * common free time.
                 *
                 * Why is this gap safe to report?
                 * All intervals were sorted by start time. Every
                 * interval starting before 8 has already been
                 * processed, and none extends beyond time 5.
                 *
                 * Record the gap, then begin tracking the next
                 * busy range. The current interval is disjoint from
                 * the previous range, so its end becomes the new end.
                 */
                freeTimes.add(
                    new Interval(lastBusyEnd, current.start)
                );

                lastBusyEnd = current.end;
            }
        }

        /*
         * STEP 4: Return the result.
         *
         * We intentionally do not add free time before the first
         * busy interval or after the final busy interval.
         *
         * The problem asks only for finite common free intervals.
         *
         * Time for the sweep: O(N)
         * Auxiliary space beyond the flattened input and output: O(1)
         *
         * Total time: O(N log N)
         * Total space: O(N), including the flattened list and output.
         */
        return freeTimes;
    }
}
```

Important LeetCode detail: The platform provides the `Interval` class. You do not need to define it in your submission. The implementation uses Java 21+ collection methods such as `getFirst()`, which are supported in Java 24.

### Approach B — Min-heap (optimal when employee schedules are individually sorted)

This version avoids globally sorting all intervals. It merges the already-sorted schedules, much like the merge step of merge sort or the solution to Merge K Sorted Lists.

```java
import java.util.ArrayList;
import java.util.Comparator;
import java.util.List;
import java.util.PriorityQueue;

class Solution {

    /*
     * A heap entry identifies the next interval to process:
     *
     * employeeIndex = which employee owns the interval
     * intervalIndex = which interval within that employee's schedule
     *
     * A record is immutable and makes a good compact data carrier.
     */
    private record Cursor(int employeeIndex, int intervalIndex) {}

    public List<Interval> employeeFreeTime(
            List<List<Interval>> schedule) {

        List<Interval> freeTimes = new ArrayList<>();

        /*
         * The heap contains at most one next-unprocessed interval
         * per employee.
         *
         * The comparator looks up each cursor's interval and orders
         * cursors by interval start time.
         *
         * Thus, peek()/poll() gives the globally earliest remaining
         * interval without sorting all N intervals.
         */
        PriorityQueue<Cursor> minHeap = new PriorityQueue<>(
            Comparator.comparingInt(cursor ->
                schedule.get(cursor.employeeIndex())
                        .get(cursor.intervalIndex()).start)
        );

        /*
         * Initially, insert the first interval from every employee.
         *
         * The original problem guarantees each employee has a
         * non-empty schedule. The check also supports empty lists.
         */
        for (int employee = 0; employee < schedule.size(); employee++) {
            if (!schedule.get(employee).isEmpty()) {
                minHeap.offer(new Cursor(employee, 0));
            }
        }

        // If there are no intervals, there are no finite gaps to report.
        if (minHeap.isEmpty()) {
            return freeTimes;
        }

        /*
         * The earliest interval establishes the initial busy coverage.
         * Polling it also frees its employee's cursor slot so we can
         * insert that employee's next interval.
         */
        Cursor first = minHeap.poll();
        Interval firstInterval = schedule.get(first.employeeIndex())
                                         .get(first.intervalIndex());

        int lastBusyEnd = firstInterval.end;

        // Add that employee's next interval, if one exists.
        int nextIndex = first.intervalIndex() + 1;
        if (nextIndex < schedule.get(first.employeeIndex()).size()) {
            minHeap.offer(
                new Cursor(first.employeeIndex(), nextIndex)
            );
        }

        /*
         * Repeatedly consume the globally earliest remaining interval.
         * Each employee contributes its intervals in their existing
         * sorted order.
         */
        while (!minHeap.isEmpty()) {
            Cursor cursor = minHeap.poll();

            Interval current = schedule.get(cursor.employeeIndex())
                                       .get(cursor.intervalIndex());

            /*
             * As in the sorting solution:
             *
             * start <= lastBusyEnd means overlapping/touching busy time.
             * Otherwise, [lastBusyEnd, start] is a common free interval.
             */
            if (current.start <= lastBusyEnd) {
                lastBusyEnd = Math.max(lastBusyEnd, current.end);
            } else {
                freeTimes.add(new Interval(lastBusyEnd, current.start));
                lastBusyEnd = current.end;
            }

            /*
             * Advance only the employee whose interval was consumed.
             *
             * Because each employee's schedule is already sorted,
             * its next interval cannot start before its current interval.
             * Inserting this successor maintains the heap's global
             * chronological ordering.
             */
            int next = cursor.intervalIndex() + 1;
            List<Interval> employeeSchedule =
                schedule.get(cursor.employeeIndex());

            if (next < employeeSchedule.size()) {
                minHeap.offer(new Cursor(cursor.employeeIndex(), next));
            }
        }

        /*
         * Each of the N intervals is inserted into and removed from
         * the heap exactly once.
         *
         * Time: O(N log K), where K is the number of employees.
         * Auxiliary space: O(K) for the heap.
         * Output space: O(F), where F is the number of free intervals.
         */
        return freeTimes;
    }
}
```

## 5. Edge cases to watch out for

| Scenario                                       | What should happen?                                  |
| ---------------------------------------------- | ---------------------------------------------------- |
| All employees' intervals overlap               | Return an empty list                                 |
| Intervals touch, such as `[1, 3]` and `[3, 5]` | Do not report `[3, 3]`                               |
| An interval is contained inside another        | Keep the farther endpoint                            |
| Several consecutive intervals overlap          | Merge them into one busy range                       |
| There is a gap between two busy ranges         | Report that gap exactly once                         |
| Free time exists before the first interval     | Ignore it; it is unbounded                           |
| Free time exists after the last interval       | Ignore it; it is unbounded                           |
| An employee has no intervals                   | The heap solution can safely skip that employee      |
| Input intervals are already globally sorted    | The merge scan can run in \\(O(N)\\) without sorting |

## 6. Interviewer follow-up questions and answers

Q1. Why can't we just find each employee's free intervals and intersect them?

You can, but it introduces an extra operation: finding the intersection of many free-time lists. Merging the busy intervals is simpler because the union of all busy periods directly identifies every common free-time gap.

Q2. Why is the maximum endpoint important?

Consider `[1, 10]`, `[2, 4]`, `[5, 7]`. If we replace the endpoint with each current interval's end, we could incorrectly shrink the tracked busy range from `10` to `4`. `Math.max` preserves the farthest coverage.

Q3. Why is the heap solution \\(O(N\log K)\\), not \\(O(N\log N)\\)?

The heap never contains more than one interval per employee. Its maximum size is \\(K\\), and each of the \\(N\\) intervals is inserted and removed once. Each heap operation costs \\(O(\log K)\\).

Q4. Which solution should I use in a coding interview?

Start with flatten + sort + sweep. It is easier to explain and prove correct. Then mention the min-heap optimization because each employee's schedule is already sorted. If the interviewer emphasizes scalability and minimizing the cost of sorting, implement the heap version.

Q5. Can we solve this with a sweep-line event map?

Yes. You can create start and end events, track the number of active busy intervals, and identify periods where that count is zero. However, you must handle simultaneous events carefully and bound the answer to the earliest and latest busy times. For this problem, merging intervals is more direct.

Q6. Can we do better than \\(O(N\log N)\\)?

Yes, under the sorted-per-employee guarantee. The min-heap solution runs in \\(O(N\log K)\\). If there is only one employee, it reduces to \\(O(N)\\); more generally, when \\(K\\) is much smaller than \\(N\\), it can be substantially more efficient than global sorting.

Final takeaway: The key insight is that common free time is the complement of the union of everyone's busy intervals. Sort or merge the busy intervals, maintain the farthest busy endpoint, and emit a free interval whenever the next start is strictly greater than that endpoint.
