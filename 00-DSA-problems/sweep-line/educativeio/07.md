# 2251. Number of Flowers in Full Bloom — Java 24

The key to this problem is understanding that each flower contributes to the answer only during its blooming interval, including both the start and end times. We need to count how many intervals contain each person's arrival time.

There are three useful approaches:

1. Brute force: Check every flower for every person.
2. Binary search: Sort flower start times and end times separately, then count how many intervals contain each arrival.
3. Sweep line: Process flower start and end events in chronological order while answering people's queries. This is a useful alternative, but binary search is especially clean for this problem.

## 0. Simplify the problem statement

Suppose we have these flowers:

```
Flower A: [1, 6]
Flower B: [3, 7]
Flower C: [9, 12]
Flower D: [4, 13]
```

A flower is blooming at time `t` if:

\\[ start \le t \le end \\]

For example, at time `3`:

- Flower A is blooming: `1 <= 3 <= 6`.
- Flower B is blooming: `3 <= 3 <= 7`.
- Flower C is not blooming.
- Flower D is not blooming yet.

Therefore, the answer for time `3` is `2`.

For the given example:

```
flowers = [[1,6], [3,7], [9,12], [4,13]]
people  = [2, 3, 7, 11]

answer  = [1, 2, 2, 2]
```

Notice that people may arrive at the same time. We must still return an answer for every person in their original order.

## 1. Clarifying questions to ask the interviewer

- Are the intervals inclusive? Yes, the statement says a flower blooms from `start` through `end`, inclusive. This determines how we handle arrivals exactly at either boundary.
- Can people arrive at the same time? Yes. Example 2 has repeated arrival times. The answer for each such person must be identical.
- Can we reorder people? We can process them in sorted order internally, but must restore their original order in the returned array.
- Are input sizes large? Yes, both arrays can contain up to \\(5 \times 10^4\\) elements. An \\(O(FP)\\) solution, where \\(F\\) is the number of flowers and \\(P\\) is the number of people, performs up to \\(2.5 \times 10^9\\) checks and is too slow in the worst case.

## 2. Core intuition: count starts and ends

Instead of asking, "Which flowers contain this person's arrival time?", ask two easier questions:

1. How many flowers have started blooming by time `t`?
2. How many flowers have already finished blooming before time `t`?

Then:

\\[ \boxed{ \text{blooming}(t) = \text{startsAtOrBefore}(t) - \text{endsBefore}(t) } \\]

Why does this work?

Every flower that has started is a candidate. Some of those flowers have already ended, so we subtract them.

The inclusive interval boundary is important:

- A flower starting at `t` must be counted.
- A flower ending at `t` must still be counted.

Therefore, we count starts using `start <= t`, but subtract only ends satisfying `end < t`.

This leads to an elegant binary-search solution.

## 3. Optimal solution: Binary search

### Mental model

Imagine two separate sorted lists:

```
Flower start times: [1, 3, 4, 9]
Flower end times:   [6, 7, 12, 13]
```

For a person arriving at time `7`:

```
Starts <= 7: [1, 3, 4]       -> 3 flowers have started
Ends < 7:    [6]             -> 1 flower has finished

Blooming flowers = 3 - 1 = 2
```

We don't need to examine every flower. Binary search tells us how many elements satisfy each condition.

- `upperBound(starts, t)` returns the number of start times `<= t`.
- `lowerBound(ends, t)` returns the number of end times `< t`.

Both searches run in \\(O(\log F)\\) time after sorting.

### Java 24 implementation

```java
import java.util.Arrays;

class Solution {

    public int[] fullBloomFlowers(int[][] flowers, int[] people) {
        /*
         * PROBLEM:
         * For each arrival time t, count flowers satisfying:
         *
         *     start <= t <= end
         *
         * Both boundaries are inclusive.
         *
         * OPTIMAL IDEA:
         *
         * Every flower that has started blooming is initially a candidate.
         * Remove candidates whose blooming period ended BEFORE time t.
         *
         *     blooming(t) = startsAtOrBefore(t) - endsBefore(t)
         *
         * We can calculate these two counts independently using binary
         * search after sorting all start times and end times.
         *
         * WHY THIS IS BETTER THAN CHECKING EVERY FLOWER:
         *
         * Brute force examines every flower for every person: O(F * P).
         * Sorting takes O(F log F), and each person then needs only
         * two O(log F) binary searches.
         */

        int flowerCount = flowers.length;
        int personCount = people.length;

        // Store starts and ends separately because the two conditions
        // are independent and each list can be sorted independently.
        int[] starts = new int[flowerCount];
        int[] ends = new int[flowerCount];

        for (int i = 0; i < flowerCount; i++) {
            starts[i] = flowers[i][0];
            ends[i] = flowers[i][1];
        }

        // Sorting enables binary search.
        // Time: O(F log F) for each array, hence O(F log F) overall.
        Arrays.sort(starts);
        Arrays.sort(ends);

        int[] answer = new int[personCount];

        for (int i = 0; i < personCount; i++) {
            int time = people[i];

            /*
             * Count flowers that have started by this time.
             *
             * upperBound(starts, time) returns the first index whose
             * value is GREATER than time.
             *
             * Because starts is sorted, every element before that index
             * satisfies start <= time.
             *
             * The returned index is also the number of qualifying starts.
             */
            int started = upperBound(starts, time);

            /*
             * Count flowers that have already finished before this time.
             *
             * lowerBound(ends, time) returns the first index whose
             * value is GREATER THAN OR EQUAL TO time.
             *
             * Every element before that index satisfies end < time.
             *
             * IMPORTANT:
             * We subtract only ends < time, NOT ends <= time.
             * A flower ending exactly at time is still in full bloom.
             */
            int finished = lowerBound(ends, time);

            // All started flowers minus flowers that finished earlier.
            answer[i] = started - finished;
        }

        /*
         * TIME COMPLEXITY:
         *
         * Sorting starts and ends:
         *     O(F log F)
         *
         * For each of P people:
         *     Two binary searches, each O(log F)
         *     Total query time: O(P log F)
         *
         * Overall: O(F log F + P log F)
         *
         * SPACE COMPLEXITY:
         *
         * starts and ends: O(F)
         * answer: O(P)
         *
         * Total auxiliary/output space: O(F + P).
         */
        return answer;
    }

    /*
     * Returns the first index i such that arr[i] > target.
     *
     * Equivalently, returns the number of elements <= target.
     *
     * Example:
     * arr = [1, 3, 3, 4, 9], target = 3
     *
     * Result = 3, because [1, 3, 3] contains three elements <= 3.
     *
     * Time: O(log n)
     * Extra space: O(1)
     */
    private int upperBound(int[] arr, int target) {
        int left = 0;
        int right = arr.length;

        // Search the half-open interval [left, right).
        while (left < right) {
            int mid = left + (right - left) / 2;

            if (arr[mid] <= target) {
                // This element qualifies. Search for more qualifying
                // elements to its right.
                left = mid + 1;
            } else {
                // This element is too large, so search to its left.
                right = mid;
            }
        }

        return left;
    }

    /*
     * Returns the first index i such that arr[i] >= target.
     *
     * Equivalently, returns the number of elements < target.
     *
     * Example:
     * arr = [3, 6, 7, 7, 13], target = 7
     *
     * Result = 2, because only [3, 6] is strictly less than 7.
     *
     * Time: O(log n)
     * Extra space: O(1)
     */
    private int lowerBound(int[] arr, int target) {
        int left = 0;
        int right = arr.length;

        while (left < right) {
            int mid = left + (right - left) / 2;

            if (arr[mid] < target) {
                // This element is strictly smaller than target.
                left = mid + 1;
            } else {
                // This element qualifies as a boundary candidate.
                // Search left to find the first such index.
                right = mid;
            }
        }

        return left;
    }
}
```

## 4. Dry run with an example

Input:

```
flowers = [[1,6], [3,7], [9,12], [4,13]]
people  = [2, 3, 7, 11]
```

After sorting:

```
starts = [1, 3, 4, 9]
ends   = [6, 7, 12, 13]
```

At each arrival time, binary search finds the two counts.

| Arrival `t` | Starts `<= t` | Ends `< t` | Blooming |
| ----------- | ------------- | ---------- | -------- |
| 2           | 1             | 0          | 1        |
| 3           | 2             | 0          | 2        |
| 7           | 3             | 1          | 2        |
| 11          | 4             | 2          | 2        |

Therefore:

```
answer = [1, 2, 2, 2]
```

### Why the boundary logic matters

Consider this input:

```
flowers = [[3, 3]]
people  = [2, 3, 4]
```

The flower blooms at exactly time `3`, for that instant only.

| Arrival | Starts `<= t` | Ends `< t` | Answer |
| ------- | ------------- | ---------- | ------ |
| 2       | 0             | 0          | 0      |
| 3       | 1             | 0          | 1      |
| 4       | 1             | 1          | 0      |

Output:

```
[0, 1, 0]
```

If we incorrectly subtract end times `<= t`, the answer at time `3` would become zero. That is the most important off-by-one error to avoid.

## 5. Other possible solutions

### Approach A: Brute force

The simplest approach directly checks whether each flower is blooming when each person arrives.

```java
class BruteForceSolution {

    public int[] fullBloomFlowers(int[][] flowers, int[] people) {
        int[] answer = new int[people.length];

        for (int i = 0; i < people.length; i++) {
            int time = people[i];

            // Count every flower whose inclusive interval contains time.
            for (int[] flower : flowers) {
                if (flower[0] <= time && time <= flower[1]) {
                    answer[i]++;
                }
            }
        }

        /*
         * TIME: O(F * P), because each person checks all flowers.
         * SPACE: O(P) for the answer; O(1) auxiliary space.
         *
         * This is easy to understand but too slow in the worst case:
         * 50,000 * 50,000 = 2.5 billion flower-person comparisons.
         */
        return answer;
    }
}
```

Use this as the starting point in an interview to establish correctness before optimizing.

### Approach B: Sweep line

The sweep-line approach processes arrival times in sorted order and maintains the number of currently blooming flowers.

Mental model:

```
Time increases from left to right.

Flower starts -> active count increases
Person arrives -> record active count
Flower ends   -> active count decreases
```

Because both boundaries are inclusive, a flower ending at time `t` must still be active when a person arrives at `t`. Thus, for events at the same time, process starts first, queries second, and ends last.

```java
import java.util.Arrays;

class SweepLineSolution {

    // Immutable event: time, event type, and original person index.
    // Type 0 = flower starts, 1 = person arrives, 2 = flower ends.
    private record Event(int time, int type, int personIndex) {}

    public int[] fullBloomFlowers(int[][] flowers, int[] people) {
        int f = flowers.length;
        int p = people.length;

        Event[] events = new Event[2 * f + p];
        int k = 0;

        for (int[] flower : flowers) {
            // Start before query at the same time: inclusive start.
            events[k++] = new Event(flower[0], 0, -1);

            // End after query at the same time: inclusive end.
            events[k++] = new Event(flower[1], 2, -1);
        }

        for (int i = 0; i < p; i++) {
            events[k++] = new Event(people[i], 1, i);
        }

        /*
         * Sort by time, then event type.
         *
         * Type order 0, 1, 2 ensures that at a shared time:
         * 1. All flowers starting now become active.
         * 2. People observe the active count.
         * 3. Flowers ending now become inactive.
         *
         * This ordering correctly handles flowers with start == end.
         */
        Arrays.sort(events,
                java.util.Comparator.comparingInt(Event::time)
                        .thenComparingInt(Event::type));

        int[] answer = new int[p];
        int active = 0;

        for (Event event : events) {
            switch (event.type()) {
                case 0 -> active++;
                case 1 -> answer[event.personIndex()] = active;
                case 2 -> active--;
                default -> throw new IllegalStateException(
                        "Unexpected event type");
            }
        }

        /*
         * TIME: O((F + P) log(F + P)) for sorting, plus O(F + P)
         * for event creation and processing.
         *
         * SPACE: O(F + P) for events and O(P) for the answer.
         *
         * Sweep line is a good general-purpose technique for interval
         * problems. Here, two sorted arrays plus binary search usually
         * produce simpler code and the same asymptotic performance
         * when F and P are of comparable size.
         */
        return answer;
    }
}
```

## 6. Edge cases to remember

| Case                                    | Expected behavior               |
| --------------------------------------- | ------------------------------- |
| Arrival before every flower starts      | Return `0`                      |
| Arrival after every flower ends         | Return `0`                      |
| Arrival equals a flower's start         | Count that flower               |
| Arrival equals a flower's end           | Count that flower               |
| Flower has `start == end`               | Count it at that exact time     |
| Multiple flowers share start/end times  | Count each flower independently |
| Multiple people arrive at the same time | Return the same count for each  |
| One flower and one person               | Apply the same interval rule    |

## 7. Interviewer follow-up questions

Q1. Why do we use two different binary searches?

Because the conditions are different. We need the number of starts `<= t`, which uses `upperBound`, and the number of ends `< t`, which uses `lowerBound`.

Q2. Could we use `start <= t` and `end >= t` directly with binary search?

Not on the original intervals as a single sorted list. Sorting starts and ends independently allows us to count the two conditions efficiently without checking individual intervals.

Q3. What changes if intervals are half-open, `[start, end)`?

A flower ending at `t` would no longer be blooming. We would subtract ends satisfying `end <= t`, so both counts would use `upperBound`:

```
int started = upperBound(starts, time); // start <= time
int finished = upperBound(ends, time);  // end <= time
answer[i] = started - finished;
```

Q4. What if the arrival times are already sorted?

The binary-search approach remains correct. A sweep-line implementation can process the people and flower events in chronological order, and if the events are also already sorted, the processing phase becomes linear.

Q5. Which solution should you present in an interview?

Present the brute-force solution first to demonstrate the direct interpretation, then optimize to sorting plus two binary searches. It is concise, easy to prove correct, and runs in \\(O(F\log F + P\log F)\\) time with \\(O(F+P)\\) space. Use sweep line when discussing event ordering and interval-processing patterns more generally.

## 1. What's wrong with your code?

Consider:

```
flowers = [[1, 6], [3, 7], [9, 12], [4, 13]]
people  = [2, 3, 7, 11]
```

Your `TreeMap` contains these events:

| Time | Event delta | Meaning                        |
| ---- | ----------- | ------------------------------ |
| 1    | +1          | One flower starts              |
| 3    | +1          | Another flower starts          |
| 4    | +1          | Another flower starts          |
| 7    | -1          | Flower ending at 6 is removed  |
| 8    | -1          | Flower ending at 7 is removed  |
| 9    | +1          | Another flower starts          |
| 14   | -1          | Flower ending at 13 is removed |

Notice that at time `4`, the map stores `+1`, but three flowers are blooming, not one.

Your code does this:

```
var left = map.floorEntry(people[i]);
int ans = Math.max(left.getValue(), 0);
```

`floorEntry(t)` returns the event at the greatest key less than or equal to `t`. Its value is just the delta at that time, not the total number of active flowers.

For example, at time `4`, `floorEntry(4)` returns `(4, +1)`. But the correct count is:

```
+1 +1 +1 = 3
```

You need the sum of all event deltas up to the person's arrival time.

Also, `Math.max(left.getValue(), 0)` doesn't fix this issue. It only clamps a single event's delta to zero.

## 2. Corrected solution using TreeMap

```java
import java.util.*;

class Solution {
    public int[] fullBloomFlowers(int[][] flowers, int[] people) {
        TreeMap<Integer, Integer> map = new TreeMap<>();

        for (int[] f : flowers) {
            int start = f[0];
            int end = f[1];

            // The flower starts contributing at start.
            map.merge(start, 1, Integer::sum);

            // The flower stops contributing at end + 1.
            // This preserves the inclusive [start, end] interval.
            map.merge(end + 1, -1, Integer::sum);
        }

        // Convert event deltas into the actual number of blooming flowers
        // at each event time by calculating a running prefix sum.
        int active = 0;
        TreeMap<Integer, Integer> blooming = new TreeMap<>();

        for (var entry : map.entrySet()) {
            active += entry.getValue();
            blooming.put(entry.getKey(), active);
        }

        int[] answer = new int[people.length];

        for (int i = 0; i < people.length; i++) {
            // Find the latest event at or before the person's arrival.
            // Its stored value is now the actual active flower count.
            var entry = blooming.floorEntry(people[i]);

            answer[i] = (entry == null) ? 0 : entry.getValue();
        }

        return answer;
    }
}
```

### Complexity

Let \\(F\\) be the number of flowers and \\(P\\) the number of people.

- Time: \\(O(F\log F + P\log F)\\). Building and processing the event map costs \\(O(F\log F)\\), and each person's `floorEntry` query costs \\(O(\log F)\\).
- Space: \\(O(F + P)\\) for the event maps and answer array.

## 3. Can we keep just one TreeMap?

Yes! You can replace the original event deltas with their prefix sums directly, avoiding a second map.

```java
import java.util.*;

class Solution {
    public int[] fullBloomFlowers(int[][] flowers, int[] people) {
        TreeMap<Integer, Integer> map = new TreeMap<>();

        for (int[] f : flowers) {
            map.merge(f[0], 1, Integer::sum);
            map.merge(f[1] + 1, -1, Integer::sum);
        }

        // Replace each delta with the running active flower count.
        int active = 0;

        for (var entry : map.entrySet()) {
            active += entry.getValue();
            entry.setValue(active);
        }

        int[] answer = new int[people.length];

        for (int i = 0; i < people.length; i++) {
            var entry = map.floorEntry(people[i]);
            answer[i] = (entry == null) ? 0 : entry.getValue();
        }

        return answer;
    }
}
```

One important Java detail: Updating `entry.setValue(active)` is safe here because it changes the value of an existing map entry without changing the map's structure.

This is the closest correction to your original code: the difference is that you turn each event's delta into a cumulative count before querying it.

## 1. Which solution is better?

Let \\(F\\) be the number of flowers and \\(P\\) be the number of people.

| Approach                | Time complexity            | Extra space  | Recommendation                        |
| ----------------------- | -------------------------- | ------------ | ------------------------------------- |
| Brute force             | \\(O(FP)\\)                | \\(O(P)\\)   | Too slow                              |
| `TreeMap` + prefix sum  | \\(O(F\log F + P\log F)\\) | \\(O(F+P)\\) | Correct, good for sweep-line learning |
| Sorting + binary search | \\(O(F\log F + P\log F)\\) | \\(O(F+P)\\) | Recommended                           |
| Sorted sweep line       | \\(O((F+P)\log(F+P))\\)    | \\(O(F+P)\\) | Good alternative                      |

The sorting + binary search solution is usually preferable because it is simple, efficient, and easy to reason about. Both approaches have the same asymptotic time complexity.

## 2. Recommended solution: Sorting + binary search

### Core intuition

For a person arriving at time `t`, a flower is blooming when:

```
start <= t <= end
```

Instead of checking every flower, count two things:

1. Flowers whose start time is less than or equal to `t`.
2. Flowers whose end time is strictly less than `t`.

Subtract the second count from the first:

\\[ \boxed{\text{blooming}(t)=\\#(start\le t)-\\#(end\<t)} \\]

Why does this work?

- Every flower that has started is initially counted.
- Flowers that have already finished must be removed.
- A flower ending exactly at `t` is still blooming, so we subtract only ends strictly less than `t`.

For example:

```
flowers = [[1,6], [3,7], [9,12], [4,13]]
t = 7

Sorted starts = [1,3,4,9]
Sorted ends   = [6,7,12,13]

Starts <= 7 = 3
Ends   <  7 = 1

Blooming = 3 - 1 = 2
```

### Java 24 code with detailed inline comments

```java
import java.util.Arrays;

class Solution {

    public int[] fullBloomFlowers(int[][] flowers, int[] people) {

        /*
         * STEP 1: Extract flower start times and end times.
         *
         * Each flower is an inclusive interval [start, end].
         * A flower is blooming at time t if:
         *
         *     start <= t && t <= end
         *
         * We want to count the intervals satisfying this condition
         * for every person's arrival time.
         *
         * Instead of checking every interval for every person,
         * we will count qualifying start times and end times separately.
         */

        int flowerCount = flowers.length;
        int[] starts = new int[flowerCount];
        int[] ends = new int[flowerCount];

        for (int i = 0; i < flowerCount; i++) {
            starts[i] = flowers[i][0];
            ends[i] = flowers[i][1];
        }

        /*
         * STEP 2: Sort both arrays.
         *
         * WHY?
         *
         * Once an array is sorted, binary search can find how many
         * elements satisfy a boundary condition in O(log F) time.
         *
         * For example:
         *
         *     starts = [1, 3, 4, 9]
         *
         * At time t = 7, the first three starts are <= 7.
         *
         * Sorting time:
         *     O(F log F) for starts
         *     O(F log F) for ends
         *
         * Combined: O(F log F).
         */

        Arrays.sort(starts);
        Arrays.sort(ends);

        /*
         * STEP 3: Answer each person's query independently.
         *
         * We use two binary searches:
         *
         * A. upperBound(starts, t):
         *    Number of start times <= t.
         *
         * B. lowerBound(ends, t):
         *    Number of end times < t.
         *
         * Therefore:
         *
         *     blooming = started - finished
         *
         * The strict inequality for finished is crucial because
         * the problem states that intervals are inclusive.
         */

        int[] answer = new int[people.length];

        for (int i = 0; i < people.length; i++) {
            int time = people[i];

            int started = upperBound(starts, time);
            int finished = lowerBound(ends, time);

            answer[i] = started - finished;
        }

        /*
         * COMPLEXITY ANALYSIS
         *
         * Let F = number of flowers and P = number of people.
         *
         * Time:
         *     Extract arrays: O(F)
         *     Sort arrays: O(F log F)
         *     Two binary searches per person: O(P log F)
         *
         * Total: O(F log F + P log F).
         *
         * Space:
         *     starts: O(F)
         *     ends: O(F)
         *     answer: O(P)
         *
         * Total: O(F + P), including the output array.
         *
         * Since F and P can each be up to 50,000, this is efficient.
         */

        return answer;
    }

    /*
     * UPPER BOUND:
     *
     * Returns the first index whose value is STRICTLY GREATER
     * than target.
     *
     * Therefore, the returned index equals the number of elements
     * that are <= target.
     *
     * Example:
     *
     *     arr    = [1, 3, 3, 4, 9]
     *     target = 3
     *
     *     qualifying elements = [1, 3, 3]
     *     result = 3
     *
     * We use this for start times because a flower starting exactly
     * at the person's arrival time must be counted.
     *
     * Time: O(log F)
     * Space: O(1)
     */
    private int upperBound(int[] arr, int target) {
        int left = 0;
        int right = arr.length;

        // Search within the half-open interval [left, right).
        while (left < right) {
            int mid = left + (right - left) / 2;

            if (arr[mid] <= target) {
                // This start time qualifies.
                // Search to the right for more qualifying elements.
                left = mid + 1;
            } else {
                // This start time is too large.
                right = mid;
            }
        }

        return left;
    }

    /*
     * LOWER BOUND:
     *
     * Returns the first index whose value is GREATER THAN OR EQUAL
     * to target.
     *
     * Therefore, the returned index equals the number of elements
     * strictly smaller than target.
     *
     * Example:
     *
     *     arr    = [3, 6, 7, 7, 13]
     *     target = 7
     *
     *     qualifying elements = [3, 6]
     *     result = 2
     *
     * We use this for end times because a flower ending exactly
     * at the person's arrival time is STILL blooming.
     *
     * Time: O(log F)
     * Space: O(1)
     */
    private int lowerBound(int[] arr, int target) {
        int left = 0;
        int right = arr.length;

        while (left < right) {
            int mid = left + (right - left) / 2;

            if (arr[mid] < target) {
                // This end time is strictly earlier than arrival.
                left = mid + 1;
            } else {
                // This end time is >= arrival.
                // Search left for the first such position.
                right = mid;
            }
        }

        return left;
    }
}
```

## 3. If you prefer your `TreeMap` solution

Your approach is also valid after the prefix-sum correction. Here is a simpler version that modifies the existing map instead of building a second map.

```java
import java.util.*;

class Solution {

    public int[] fullBloomFlowers(int[][] flowers, int[] people) {

        /*
         * STEP 1: Build an event map.
         *
         * At a flower's start time, the active count increases by 1.
         * At end + 1, it decreases by 1.
         *
         * Using end + 1 handles inclusive intervals:
         * a flower ending at t remains active at t itself.
         *
         * For example, [3, 5]:
         *
         *     time 3: +1
         *     time 6: -1
         *
         * So it is counted at times 3, 4 and 5, but not at 6.
         */
        TreeMap<Integer, Integer> map = new TreeMap<>();

        for (int[] flower : flowers) {
            map.merge(flower[0], 1, Integer::sum);
            map.merge(flower[1] + 1, -1, Integer::sum);
        }

        /*
         * STEP 2: Convert deltas into cumulative active counts.
         *
         * A map value initially means "how much does the count change
         * at this time?" It does NOT mean "how many flowers are blooming."
         *
         * We must accumulate the deltas in chronological order.
         *
         * Example:
         *
         *     time:  1   3   4   7
         *     delta: +1  +1  +1  -1
         *     count:  1   2   3   2
         *
         * TreeMap iterates keys in ascending order.
         */
        int active = 0;

        for (Map.Entry<Integer, Integer> entry : map.entrySet()) {
            active += entry.getValue();

            // Updating an existing entry's value does not structurally
            // modify the map, so this is safe during iteration.
            entry.setValue(active);
        }

        /*
         * STEP 3: Query each person's arrival time.
         *
         * floorEntry(t) returns the greatest event time <= t.
         *
         * Since we replaced deltas with cumulative counts, the value
         * at that event time is the number of flowers blooming at t.
         *
         * If no event exists at or before t, the count is zero.
         */
        int[] answer = new int[people.length];

        for (int i = 0; i < people.length; i++) {
            Map.Entry<Integer, Integer> entry =
                    map.floorEntry(people[i]);

            answer[i] = (entry == null) ? 0 : entry.getValue();
        }

        /*
         * TIME:
         *     Build map: O(F log F)
         *     Prefix sum: O(F)
         *     Queries: O(P log F)
         *
         *     Total: O(F log F + P log F).
         *
         * SPACE:
         *     Event map: O(F)
         *     Answer: O(P)
         *
         *     Total: O(F + P).
         */
        return answer;
    }
}
```

## 4. Final interview recommendation

I would present sorting + binary search first because the counting formula is compact and the boundary conditions are explicit.

Use `TreeMap` when you specifically want to demonstrate an ordered event map, prefix sums, or dynamic ordered queries. Remember that `floorEntry()` only finds the previous event; it does not accumulate the deltas for you. You must convert the deltas into active counts first.

The most important insight to remember is:

\\[ \boxed{\text{Blooming flowers} = \text{starts}\le t - \text{ends}\<t} \\]

That single formula makes the binary-search solution straightforward and avoids the inclusive-boundary bug.
