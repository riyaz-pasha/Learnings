# 1094. Car Pooling — Java 24 Solutions

The key idea is Sweep Line + Difference Array. Both approaches track how the number of passengers changes as the car travels east.

## 0. Understand the problem simply

Imagine a car traveling along a straight road. Each trip is represented as:

`[passengers, pickupLocation, dropOffLocation]`

For example, `[2, 1, 5]` means:

- Pick up 2 passengers at kilometer 1.
- Carry them until kilometer 5.
- Drop them off at kilometer 5.

The car has a fixed capacity. We need to determine whether it can complete every trip without ever carrying more passengers than its capacity.

Example:

```
trips = [[2, 1, 5], [3, 3, 7]]
capacity = 4
```

```
Kilometer:       1       3       5       7
                 |-------|-------|-------|
Trip 1:          +2              -2
Trip 2:                  +3              -3

Passengers:      2       5       3       0
                         ^
                    Capacity exceeded!
```

At kilometer 3, the car already has 2 passengers and picks up 3 more. The total becomes 5, exceeding the capacity of 4. Therefore, the answer is `false`.

Important detail: Passengers being dropped off at a location leave before new passengers are picked up at that same location. Thus, we must evaluate occupancy after processing all changes at a location.

## 1. Clarifying questions to ask the interviewer

1. Can trips have the same pickup or drop-off location? Why: We need to correctly combine multiple passenger changes at the same kilometer.
2. Are passengers dropped off before others are picked up at the same location? Why: This determines how events at a shared location should be processed. The problem explicitly says yes.
3. Are locations bounded? Why: Locations range from 0 to 1000, making a difference array an excellent option. If locations were extremely large, sorting events would be more appropriate.
4. Can trips be given in arbitrary order? Why: We cannot assume the input is sorted by pickup location. We need to process locations in travel order.
5. Do we need to return the maximum number of passengers, or just whether the trips are feasible? Why: The required answer is a boolean, but calculating maximum occupancy is a useful intermediate step.

## 2. Core intuition: Think in terms of changes, not trips

The most important mental model is this:

We do not need to simulate every kilometer or track every passenger. We only need to track where the passenger count changes.

For every trip `[p, from, to]`:

- At `from`, the passenger count increases by `p`.
- At `to`, the passenger count decreases by `p`.

We can express this as:

```
change[from] += passengers
change[to]   -= passengers
```

As we travel from west to east, we accumulate these changes to know the current occupancy.

For the example `[[2,1,5], [3,3,7]]`:

| Kilometer | Change | Passengers after change |
| --------- | ------ | ----------------------- |
| 1         | +2     | 2                       |
| 3         | +3     | 5                       |
| 5         | -2     | 3                       |
| 7         | -3     | 0                       |

We check the capacity after each location's changes. If the passenger count exceeds capacity at any point, return `false`.

## 3. Solution 1 — Brute force: Check every kilometer

```java
class Solution {

    public boolean carPooling(int[][] trips, int capacity) {

        // WHY THIS WORKS:
        // The car's occupancy changes only at pickup and drop-off locations.
        // We can check every kilometer and count the passengers whose trips
        // include that kilometer.
        //
        // A trip [p, from, to] occupies the road segment [from, to).
        // At kilometer x, the passengers are inside the car when:
        // from <= x < to.
        //
        // This condition ensures that passengers dropped off at x are
        // no longer counted, while passengers picked up at x are counted.
        //
        // TIME COMPLEXITY: O(n * M)
        // n = number of trips, M = maximum drop-off location.
        // At each kilometer, we scan every trip.
        //
        // SPACE COMPLEXITY: O(1)
        // We use only a few integer variables.

        int maxLocation = 0;

        for (int[] trip : trips) {
            maxLocation = Math.max(maxLocation, trip[2]);
        }

        // Visit each kilometer where passengers could be on board.
        for (int kilometer = 0;
             kilometer < maxLocation;
             kilometer++) {

            int passengers = 0;

            // Count passengers whose trips cover this kilometer.
            for (int[] trip : trips) {

                int count = trip[0];
                int from = trip[1];
                int to = trip[2];

                if (from <= kilometer && kilometer < to) {
                    passengers += count;
                }
            }

            // If the occupancy exceeds capacity at any point,
            // the car cannot complete all trips.
            if (passengers > capacity) {
                return false;
            }
        }

        return true;
    }
}
```

Why is this not optimal?

We repeatedly examine all trips at every kilometer, even though the passenger count usually remains unchanged between pickup and drop-off locations.

With \\(n = 1000\\) and \\(M = 1000\\), this is roughly one million trip checks. The constraints make it feasible, but we can do better.

## 4. Solution 2 — Sweep line using sorted events

Instead of checking every kilometer, record only the locations where the passenger count changes.

Each trip generates two events:

- Pickup: `(from, +passengers)`
- Drop-off: `(to, -passengers)`

Sort events by location and process them from west to east.

```java
import java.util.ArrayList;
import java.util.Comparator;
import java.util.List;

class Solution {

    // A record represents an immutable event on the road.
    // delta > 0 means passengers enter the car.
    // delta < 0 means passengers leave the car.
    private record Event(int location, int delta) {}

    public boolean carPooling(int[][] trips, int capacity) {

        // WHY A SWEEP LINE?
        // Passenger occupancy changes only at trip endpoints.
        // Sorting those endpoints lets us skip all unchanged road segments.
        //
        // TIME COMPLEXITY: O(n log n)
        // We create 2n events and sort them in O(n log n).
        // Processing the sorted events takes O(n).
        //
        // SPACE COMPLEXITY: O(n)
        // We store two events per trip.

        List<Event> events = new ArrayList<>(2 * trips.length);

        for (int[] trip : trips) {
            int passengers = trip[0];
            int from = trip[1];
            int to = trip[2];

            // Pick up passengers at the starting location.
            events.add(new Event(from, passengers));

            // Drop off those passengers at the ending location.
            events.add(new Event(to, -passengers));
        }

        // Sort by location first.
        // If events share a location, negative deltas come first.
        //
        // WHY PROCESS DROPOFFS FIRST?
        // The problem states that passengers leave before new passengers
        // enter at the same location.
        //
        // Processing negative deltas first also avoids temporarily
        // exceeding capacity when a drop-off and pickup share a location.
        events.sort(
            Comparator.comparingInt(Event::location)
                      .thenComparingInt(Event::delta)
        );

        int passengers = 0;

        for (Event event : events) {

            // Apply the change at the current event.
            passengers += event.delta();

            // Occupancy must never exceed the vehicle's capacity.
            if (passengers > capacity) {
                return false;
            }
        }

        // All events were processed without exceeding capacity.
        // The final occupancy returns to zero because every trip
        // contributes an equal pickup and drop-off amount.
        return true;
    }
}
```

### Example walkthrough

Input:

```
trips = [[2, 1, 5], [3, 3, 7]]
capacity = 5
```

The events after sorting are:

```
(location, delta)

(1, +2)
(3, +3)
(5, -2)
(7, -3)
```

Processing them:

| Event     | Calculation | Occupancy | Valid? |
| --------- | ----------- | --------- | ------ |
| `(1, +2)` | `0 + 2`     | 2         | Yes    |
| `(3, +3)` | `2 + 3`     | 5         | Yes    |
| `(5, -2)` | `5 - 2`     | 3         | Yes    |
| `(7, -3)` | `3 - 3`     | 0         | Yes    |

The answer is `true`.

If capacity were 4, we would return `false` at kilometer 3, when occupancy becomes 5.

A subtle implementation detail: We process events at the same location individually, with drop-offs first. We could alternatively group all events at a location, apply their combined change, and check occupancy once. Both approaches work.

## 5. Solution 3 — Optimal for the given constraints: Difference array

The problem guarantees that every location is between 0 and 1000. We can exploit this bounded range to avoid sorting altogether.

Instead of storing events in a list, use an array:

```
change[location] = net passenger change at that location
```

For each trip `[p, from, to]`:

```
change[from] += p
change[to]   -= p
```

Then scan the array in increasing location order, maintaining a running passenger count.

```java
class Solution {

    public boolean carPooling(int[][] trips, int capacity) {

        // WHY THIS IS THE BEST FIT FOR THESE CONSTRAINTS:
        // Locations are bounded: 0 <= location <= 1000.
        // We can allocate an array indexed directly by location.
        //
        // Instead of sorting 2n events, we accumulate every change
        // at its exact location in constant time.
        //
        // TIME COMPLEXITY: O(n + M)
        // n = number of trips.
        // M = maximum location, at most 1000.
        // Building the array takes O(n), and scanning it takes O(M).
        //
        // SPACE COMPLEXITY: O(M)
        // We use one integer array of size M + 1.
        //
        // With the given constraints, this is effectively O(n + 1000)
        // time and O(1000) auxiliary space.

        int maxLocation = 0;

        for (int[] trip : trips) {
            maxLocation = Math.max(maxLocation, trip[2]);
        }

        // change[x] stores the net number of passengers entering
        // or leaving the car at location x.
        int[] change = new int[maxLocation + 1];

        for (int[] trip : trips) {
            int passengers = trip[0];
            int from = trip[1];
            int to = trip[2];

            // Passengers enter the car at the pickup location.
            change[from] += passengers;

            // Passengers leave the car at the drop-off location.
            change[to] -= passengers;
        }

        int passengers = 0;

        // Sweep from west to east.
        // Applying the net change at each location is sufficient:
        // all drop-offs and pickups at that location are combined.
        for (int location = 0;
             location <= maxLocation;
             location++) {

            passengers += change[location];

            // Because all changes at this location are combined,
            // passengers represents occupancy after all drop-offs
            // and pickups at the location have been handled.
            if (passengers > capacity) {
                return false;
            }
        }

        return true;
    }
}
```

### Why does the difference array work?

Consider these trips:

```
trips = [[2, 1, 5], [3, 3, 7], [2, 5, 8]]
capacity = 5
```

Initially, every `change` entry is zero.

After recording the trips:

| Location | Change | Reason                     |
| -------- | ------ | -------------------------- |
| 1        | +2     | First trip picks up 2      |
| 3        | +3     | Second trip picks up 3     |
| 5        | 0      | Drop off 2, then pick up 2 |
| 7        | -3     | Second trip drops off 3    |
| 8        | -2     | Third trip drops off 2     |

At location 5, the changes cancel out: `-2 + 2 = 0`.

The passenger count evolves as follows:

```
Location:       1       3       5       7       8
Change:        +2      +3       0      -3      -2
Occupancy:      2       5       5       2       0
```

The answer is `true`, because occupancy never exceeds 5.

Notice that we don't need to know the order of individual events at location 5 in this solution. Since all drop-offs happen before pickups, the net change produces the correct occupancy after that location's operations.

## 6. Comparison of all approaches

| Approach          | Time complexity  | Extra space | Best use case                      |
| ----------------- | ---------------- | ----------- | ---------------------------------- |
| Brute force       | \\(O(nM)\\)      | \\(O(1)\\)  | Small inputs; easiest baseline     |
| Sorted sweep line | \\(O(n\log n)\\) | \\(O(n)\\)  | Large or sparse coordinate ranges  |
| Difference array  | \\(O(n+M)\\)     | \\(O(M)\\)  | Small, bounded integer coordinates |

Here, \\(n\\) is the number of trips and \\(M\\) is the maximum location.

Interview recommendation: Start with the brute-force idea, explain why passenger counts change only at endpoints, and then present the difference array as the optimal solution for these constraints. If the interviewer removes the location bound or makes the coordinates very large, switch to the sorted sweep-line approach.

## 7. Edge cases to watch out for

1. Capacity exactly reached
   ```
   trips = [[2, 1, 5], [3, 3, 7]]
   capacity = 5
   ```
   Return `true`. The condition must be `passengers > capacity`, not `passengers >= capacity`.
2. Drop-off and pickup at the same location
   ```
   trips = [[3, 1, 5], [3, 5, 8]]
   capacity = 3
   ```
   Return `true`. Three passengers leave before the next three enter.
3. Several trips overlap
   ```
   trips = [[2, 1, 6], [2, 2, 5], [1, 3, 7]]
   capacity = 4
   ```
   Return `true`. The maximum occupancy is 5? No—the correct occupancy at kilometer 3 is \\(2+2+1=5\\), so the answer is `false`. This is a useful test for manually validating the occupancy calculation.
4. Trip starts at location zero
   ```
   trips = [[3, 0, 2]]
   capacity = 3
   ```
   Return `true`. The difference array must include index 0.
5. Drop-off at the maximum location
   ```
   trips = [[2, 998, 1000]]
   capacity = 2
   ```
   Return `true`. Allocate enough space to access index 1000 when using a fixed-size difference array.
6. Multiple pickups and drop-offs at one location

   Aggregate all changes at that location or sort drop-offs before pickups. Never reject a valid set of trips merely because of an intermediate occupancy during incorrectly ordered events.

## 8. Interviewer follow-up questions and answers

Q1. Why do we subtract passengers at the drop-off location rather than `to - 1`?

Because the passenger count describes the state after processing the events at a location. The trip occupies the interval from `from` inclusive to `to` exclusive. Subtracting at `to` means those passengers are no longer counted there.

Q2. Why is a difference array more efficient than sorting events?

The coordinates are small, bounded integers, so an array index directly identifies each location. We can accumulate changes in \\(O(n)\\) and scan the locations in \\(O(M)\\), rather than spending \\(O(n\log n)\\) sorting events.

Q3. What if locations can be as large as \\(10^9\\)?

A difference array of that size would waste memory. Use the sorted sweep-line solution, which stores only the \\(2n\\) trip endpoints.

Q4. Can we use a priority queue?

Yes, although it is unnecessary here. A min-heap ordered by drop-off time can track active trips as pickup events are processed in sorted order. Before adding passengers for a new pickup location, remove trips ending at or before that location. This can achieve \\(O(n\log n)\\) time.

Q5. Can we calculate the maximum occupancy instead of returning a boolean?

Yes. During the sweep, maintain `maxPassengers = Math.max(maxPassengers, passengers)`. The maximum occupancy tells us the minimum capacity required to serve all trips.

Q6. Why is this called a sweep-line algorithm?

Conceptually, we move a line from left to right across the road. At each event location, we update the active passenger count. This is the same general technique used in interval overlap, meeting-room allocation, and geometric intersection problems.

Q7. What if the trips are not sorted?

That does not affect the difference-array solution because locations are scanned in ascending order. For the event-based solution, sort the events before processing them.

Final takeaway: Car Pooling is an interval-overlap problem disguised as a transportation problem. Translate each trip into a positive change at pickup and a negative change at drop-off, then sweep through those changes while ensuring the running occupancy never exceeds capacity.




















```java
import java.util.ArrayList;
import java.util.Comparator;
import java.util.List;

class Solution {

    // Represents a change in the number of passengers at a specific location.
    //
    // location: The kilometer where the passenger count changes.
    // passengerChange:
    //   Positive value -> passengers are picked up.
    //   Negative value -> passengers are dropped off.
    //
    // Example:
    // Event(3, 2)  -> Pick up 2 passengers at kilometer 3.
    // Event(5, -2) -> Drop off 2 passengers at kilometer 5.
    //
    // A record is useful here because each event is an immutable data carrier.
    private record Event(int location, int passengerChange) {
    }

    public boolean carPooling(int[][] trips, int capacity) {

        // STEP 1: Convert every trip into two events.
        //
        // Each trip is represented as:
        // [numberOfPassengers, pickupLocation, dropOffLocation]
        //
        // Instead of simulating every kilometer, we track only the locations
        // where the number of passengers changes.
        //
        // For a trip [2, 1, 5]:
        //   At kilometer 1, the car picks up 2 passengers: +2.
        //   At kilometer 5, the car drops off 2 passengers: -2.
        //
        // Why is this enough?
        // Between pickup and drop-off locations, the passenger count remains
        // unchanged. Therefore, we only need to process these event locations.
        //
        // Every trip produces exactly two events, so there are 2 * n events.
        List<Event> events = new ArrayList<>(2 * trips.length);

        for (int[] trip : trips) {

            int numberOfPassengers = trip[0];
            int pickupLocation = trip[1];
            int dropOffLocation = trip[2];

            // Positive change: passengers enter the car at the pickup location.
            events.add(new Event(pickupLocation, numberOfPassengers));

            // Negative change: passengers leave the car at the drop-off location.
            events.add(new Event(dropOffLocation, -numberOfPassengers));
        }

        // STEP 2: Sort all events by location in ascending order.
        //
        // We must process locations from west to east because the car only
        // travels east. The order of the input trips is irrelevant.
        //
        // If two events have the same location, sort by passengerChange:
        // negative values (drop-offs) come before positive values (pickups).
        //
        // Why?
        // The problem states that passengers are dropped off before new
        // passengers are picked up at the same location.
        //
        // Example:
        // Event(5, -3) comes before Event(5, +2).
        //
        // We will also group all events at the same location below, so the
        // final occupancy check happens after all changes at that location.
        events.sort(
            Comparator.comparingInt(Event::location)
                      .thenComparingInt(Event::passengerChange)
        );

        // STEP 3: Sweep through the sorted events and track occupancy.
        //
        // currentPassengers represents the number of passengers currently
        // inside the car after processing all previously visited locations.
        int currentPassengers = 0;

        // Index of the next event that has not yet been processed.
        int eventIndex = 0;

        while (eventIndex < events.size()) {

            // Identify the next location on the road.
            int currentLocation = events.get(eventIndex).location();

            // STEP 4: Process every event at this same location.
            //
            // Multiple trips can start or end at the same kilometer.
            // We combine all their passenger changes before checking capacity.
            //
            // Because the events are sorted, all events for currentLocation
            // appear consecutively.
            while (eventIndex < events.size()
                    && events.get(eventIndex).location() == currentLocation) {

                Event event = events.get(eventIndex);

                // Apply the event:
                //   Positive change -> occupancy increases.
                //   Negative change -> occupancy decreases.
                currentPassengers += event.passengerChange();

                eventIndex++;
            }

            // STEP 5: Check capacity after all events at this location.
            //
            // All drop-offs and pickups at this location have now been applied.
            // Therefore, currentPassengers is the occupancy after processing
            // the location, consistent with the problem's drop-off-first rule.
            //
            // If occupancy exceeds capacity at any location, the trips cannot
            // all be completed using this vehicle.
            if (currentPassengers > capacity) {
                return false;
            }
        }

        // Every event was processed without exceeding capacity.
        // Each trip contributed an equal positive pickup and negative drop-off,
        // so the passenger count also returns to zero after the final event.
        return true;
    }
}

/*
 * TIME COMPLEXITY: O(n log n)
 *
 * Let n = trips.length.
 *
 * 1. Creating events:
 *    Each trip creates two events, so this takes O(n) time.
 *
 * 2. Sorting events:
 *    There are 2n events. Sorting them takes O(2n log(2n)),
 *    which simplifies to O(n log n).
 *
 * 3. Processing events:
 *    Each event is visited exactly once across the nested loops.
 *    The total processing time is O(n), not O(n^2).
 *
 * Overall:
 *    O(n) + O(n log n) + O(n) = O(n log n).
 *
 * SPACE COMPLEXITY: O(n)
 *
 * We store two Event records per trip, resulting in 2n events.
 * Since constant factors are ignored in asymptotic analysis, auxiliary
 * space is O(n).
 */
```

## Why group events at the same location?

Consider:

```
int[][] trips = {
    {3, 1, 5},
    {3, 5, 8}
};
int capacity = 3;
```

At kilometer 5, the first trip drops off 3 passengers and the second trip picks up 3.

The changes at kilometer 5 are:

```
-3 + 3 = 0
```

The car has 3 passengers before kilometer 5 and 3 passengers after processing kilometer 5. It never exceeds capacity, so the answer is `true`.
