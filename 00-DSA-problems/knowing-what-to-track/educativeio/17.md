# Find All Anagrams in a String — Java 24

The key idea is to use a sliding window + character frequency array. Instead of generating every substring and sorting it to check whether it is an anagram, we maintain character frequencies as the window moves across the string.

## 1. Understand the problem

Given two strings, `a` and `b`, find every starting index in `a` where a substring is an anagram of `b`.

Example:

```
a = "cbaebabacd"
b = "abc"

Output = [0, 6]
```

Why?

Index 0 — substring `"cba"`

## c

## b

## a

Anagram of `"abc"` — include index 0.

Index 6 — substring `"bac"`

## b

## a

## c

Anagram of `"abc"` — include index 6.

Notice that anagrams do not need to have the same character order. They only need the same characters with the same frequencies.

## 2. Intuition: how do we solve it efficiently?

Suppose `b = "abc"`. Every valid substring must have exactly three characters.

Therefore, instead of checking substrings of different lengths, we maintain a fixed-size window of length `b.length()`.

For example, as we move through `a`:

```
a = "cbaebabacd"
b = "abc"
      Window size = 3

[c b a] e b a b a c d
 c [b a e] b a b a c d
 c b [a e b] a b a c d
 ...
```

Each time the window moves one position to the right:

1. Remove the character that leaves the window.
2. Add the character that enters the window.
3. Check whether the window's character frequencies match those of `b`.
4. If they match, record the window's starting index.

The important optimization is that only two character frequencies change per window movement, rather than recounting every character from scratch.

## 3. Approach 1 — Brute force

The simplest solution is to examine every substring of length `b.length()` and check whether it is an anagram of `b`.

### Idea

For each possible starting index:

1. Extract a substring of length `m`, where `m = b.length()`.
2. Convert the substring and `b` into character arrays.
3. Sort both arrays.
4. If the sorted arrays are equal, record the starting index.

Sorting makes the character order identical when two strings are anagrams.

### Java code

```
import java.util.*;

class Solution {
    public List<Integer> findAnagrams(String a, String b) {
        List<Integer> result = new ArrayList<>();

        int n = a.length();
        int m = b.length();

        // An anagram must have exactly the same length.
        if (m > n) {
            return result;
        }

        // Sorting b once avoids repeating this work for every window.
        char[] target = b.toCharArray();
        Arrays.sort(target);

        // Consider every possible window of length m.
        for (int start = 0; start <= n - m; start++) {
            // Extract the current substring and sort its characters.
            char[] window = a.substring(start, start + m).toCharArray();
            Arrays.sort(window);

            // Equal sorted arrays imply equal character frequencies.
            if (Arrays.equals(window, target)) {
                result.add(start);
            }
        }

        return result;
    }
}
```

Complexity

Let \\(n = |a|\\) and \\(m = |b|\\).

- Time: \\(O(nm\log m)\\), because there are \\(O(n)\\) windows and each window takes \\(O(m\log m)\\) to sort.
- Auxiliary space: \\(O(m)\\) for the character arrays of the current window and target, excluding the output list.

Why is this not ideal? Adjacent windows overlap heavily, but we repeatedly extract and sort almost the same characters.

## 4. Approach 2 — Sliding window + frequency array

This is the standard interview solution and is usually the best balance of simplicity and performance.

### Key observation

Since both strings contain only lowercase English letters, we need to track just 26 character frequencies.

For example:

```
b = "abc"

Character:   a  b  c  d  e ... z
Frequency:   1  1  1  0  0 ... 0
```

We maintain two frequency arrays:

- `targetFreq`: frequencies of characters in `b`.
- `windowFreq`: frequencies of characters in the current window of `a`.

If the two arrays are equal, the window is an anagram.

### Java code

```

import java.util.*;

class Solution {
    public List<Integer> findAnagrams(String a, String b) {
        List<Integer> result = new ArrayList<>();

        int n = a.length();
        int m = b.length();

        // Every candidate window must have length m.
        if (m > n) {
            return result;
        }

        // Only 26 slots are needed for lowercase English letters.
        int[] targetFreq = new int[26];
        int[] windowFreq = new int[26];

        // Build the required character frequencies for b.
        for (int i = 0; i < m; i++) {
            targetFreq[b.charAt(i) - 'a']++;
        }

        // Build the first window: a[0 ... m - 1].
        for (int i = 0; i < m; i++) {
            windowFreq[a.charAt(i) - 'a']++;
        }

        // The first window is a candidate starting at index 0.
        if (Arrays.equals(targetFreq, windowFreq)) {
            result.add(0);
        }

        // Slide the fixed-size window one position at a time.
        for (int right = m; right < n; right++) {
            // The character immediately before the new window leaves.
            int left = right - m;
            windowFreq[a.charAt(left) - 'a']--;

            // The new rightmost character enters the window.
            windowFreq[a.charAt(right) - 'a']++;

            // The new window starts at left + 1.
            int start = left + 1;

            // Matching frequencies mean the window is an anagram.
            if (Arrays.equals(targetFreq, windowFreq)) {
                result.add(start);
            }
        }

        return result;
    }
}

```

### Complexity

- Time: \\(O(n \times 26) = O(n)\\), because each window comparison examines at most 26 entries, a constant-sized alphabet.
- Auxiliary space: \\(O(26) = O(1)\\), excluding the output list.

This solution is already asymptotically optimal: in the worst case, we must examine the characters of `a`, which takes \\(O(n)\\) time.

## 5. Dry run — step by step

Consider:

```
a = "cbaebabacd"
b = "abc"
m = 3
```

The target frequencies are:

```
a: 1, b: 1, c: 1
All other characters: 0
```

Let's slide the window through the string.

| Start index | Window | Anagram of `"abc"`? | Reason                |
| ----------- | ------ | ------------------- | --------------------- |
| 0           | `cba`  | Yes                 | One each of a, b, c   |
| 1           | `bae`  | No                  | Contains e, missing c |
| 2           | `aeb`  | No                  | Contains e, missing c |
| 3           | `eba`  | No                  | Contains e, missing c |
| 4           | `bab`  | No                  | Two b's, missing c    |
| 5           | `aba`  | No                  | Two a's, missing c    |
| 6           | `bac`  | Yes                 | One each of a, b, c   |
| 7           | `acd`  | No                  | Contains d, missing b |

Therefore, the result is:

```
[0, 6]
```

Notice that we never need to sort a substring. We update the frequencies by removing one character and adding another.

## 6. Approach 3 — Optimized sliding window with a difference array

If an interviewer asks, "Can you avoid comparing all 26 frequencies for every window?", this is the next optimization.

### Intuition

Instead of maintaining two frequency arrays and comparing them, maintain one array called `diff`.

Define:

\\[ \text{diff}[c] = \text{targetFreq}[c] - \text{windowFreq}[c] \\]

If all entries are zero, the current window is an anagram.

Rather than checking all 26 entries repeatedly, maintain `nonZero`, the number of entries in `diff` that are not zero.

- `nonZero == 0`: all frequencies match.
- `nonZero > 0`: at least one frequency differs.

Whenever a character enters or leaves the window, update just one entry of `diff` and adjust `nonZero` if that entry changes between zero and nonzero.

### Java code

```

import java.util.*;

class Solution {
    public List<Integer> findAnagrams(String a, String b) {
        List<Integer> result = new ArrayList<>();

        int n = a.length();
        int m = b.length();

        if (m > n) {
            return result;
        }

        // Positive values mean the window needs more of a character;
        // negative values mean the window has too many of that character.
        int[] diff = new int[26];

        // Initially, account for every character required by b.
        for (int i = 0; i < m; i++) {
            diff[b.charAt(i) - 'a']++;
        }

        // Subtract the frequencies of the first window from the target.
        for (int i = 0; i < m; i++) {
            diff[a.charAt(i) - 'a']--;
        }

        // Count how many character frequencies currently differ.
        int nonZero = 0;
        for (int value : diff) {
            if (value != 0) {
                nonZero++;
            }
        }

        // The first window matches if no frequency differs.
        if (nonZero == 0) {
            result.add(0);
        }

        // Move the window forward one character at a time.
        for (int right = m; right < n; right++) {
            int outgoing = a.charAt(right - m) - 'a';
            int incoming = a.charAt(right) - 'a';

            // The outgoing character is removed from the window.
            // Therefore, targetFreq - windowFreq increases by one.
            if (diff[outgoing] == 0) nonZero++;
            diff[outgoing]++;
            if (diff[outgoing] == 0) nonZero--;

            // The incoming character is added to the window.
            // Therefore, targetFreq - windowFreq decreases by one.
            if (diff[incoming] == 0) nonZero++;
            diff[incoming]--;
            if (diff[incoming] == 0) nonZero--;

            // All character frequencies match when nonZero is zero.
            if (nonZero == 0) {
                result.add(right - m + 1);
            }
        }

        return result;
    }
}

```

### Complexity

- Time: \\(O(n + 26) = O(n)\\).
- Auxiliary space: \\(O(26) = O(1)\\), excluding the output list.

Which approach should you use in an interview?

I recommend Approach 2 first. It is easy to explain, hard to get wrong, and already \\(O(n)\\) for a fixed alphabet. Approach 3 is a useful follow-up optimization that demonstrates how to eliminate repeated frequency comparisons.

## 7. Edge cases to remember

| Input                   | Expected output | Why                                               |
| ----------------------- | --------------- | ------------------------------------------------- |
| `a = "a", b = "a"`      | `[0]`           | The whole string matches                          |
| `a = "a", b = "b"`      | `[]`            | Character frequencies differ                      |
| `a = "abc", b = "abcd"` | `[]`            | Pattern is longer than the text                   |
| `a = "aaaaa", b = "aa"` | `[0, 1, 2, 3]`  | Overlapping anagrams are allowed                  |
| `a = "abab", b = "ab"`  | `[0, 1, 2]`     | Every window is an anagram                        |
| `a = "baa", b = "aa"`   | `[1]`           | Repeated characters must have correct frequencies |

A common mistake is to compare only which characters are present. For example, `"aab"` and `"abb"` contain the same distinct characters, but they are not anagrams because their frequencies differ.

Another common mistake is to increment the left pointer incorrectly. For a window ending at `right`, its starting index is always:

\\[ \text{start} = \text{right} - m + 1 \\]

## 8. How to derive this solution in an interview

A good way to reason from scratch is to ask yourself these questions:

1. What makes two strings anagrams? They have identical character frequencies.
2. What lengths should I examine? Only substrings of length `b.length()`.
3. Can I reuse work between adjacent substrings? Yes. The window shifts by one character, so only one character leaves and one enters.
4. How can I compare frequencies efficiently? Use a 26-element frequency array because the alphabet is fixed.
5. Can I avoid comparing all 26 entries each time? Yes, maintain a `nonZero` counter.

This progression takes you from brute force to an optimal sliding-window solution naturally.

## 9. Interview follow-up questions

Q1. Why use a fixed-size window?

Every anagram of `b` must contain exactly `b.length()` characters. Any shorter or longer substring cannot qualify.

Q2. Why is sliding window better than checking each substring independently?

Adjacent substrings overlap. We reuse the previous window's frequencies instead of recounting or sorting all its characters.

Q3. What if the strings contain uppercase letters, Unicode, or arbitrary characters?

The 26-element array is no longer sufficient. Use a `HashMap<Character, Integer>` for a wider character set, or an appropriate Unicode code-point frequency structure if full Unicode support is required.

Q4. What if the problem asks for the total number of anagrams instead of their indices?

Increment a counter whenever a window matches. You can avoid storing the result indices, reducing auxiliary space to \\(O(1)\\) for the fixed alphabet.

Q5. Can we solve it using a single frequency array?

Yes. Approach 3 uses a difference array and tracks how many entries are nonzero. This lets us detect matches in constant time per window.

Q6. What is the lower bound on time complexity?

We must inspect the input characters in the general case, so \\(O(n)\\) is optimal. The standard sliding-window algorithm achieves this.

## 10. Final comparison

| Approach                     | Time complexity   | Auxiliary space | Interview value               |
| ---------------------------- | ----------------- | --------------- | ----------------------------- |
| Sort every window            | \\(O(nm\log m)\\) | \\(O(m)\\)      | Good baseline                 |
| Two frequency arrays         | \\(O(26n)=O(n)\\) | \\(O(1)\\)      | Best starting solution        |
| Difference array + `nonZero` | \\(O(n)\\)        | \\(O(1)\\)      | Strong optimization follow-up |

Remember this pattern: fixed-length substring + character frequencies + sliding window. The same pattern is useful for many string problems, including permutation-in-string checks and finding substrings that satisfy character-frequency constraints.
