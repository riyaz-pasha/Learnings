# Zigzag Conversion — Java Solution

The key idea is to simulate moving through the rows of the zigzag pattern, then concatenate the characters row by row.

## 1. Approach: Row-by-row simulation (Best solution)

For example, given:

```
s = "COMPUTER"
numRows = 3
```

The zigzag pattern is:

## C

## ·

## ·

## P

## ·

## ·

## ·

## O

## M

## ·

## U

## ·

## E

## ·

## ·

## ·

## ·

## T

## ·

## ·

## R

Illustrative row positions: the actual zigzag moves diagonally upward between vertical sections.

Reading the actual zigzag row by row gives:

```
Row 0: C   U
Row 1: O P T R
Row 2: M   E

Result: CUOPTRME
```

We do not need to create a two-dimensional matrix. We only need to store the characters belonging to each row.

### Java code

```
class Solution {
    public String convert(String s, int numRows) {

        // Edge case 1: With one row, the string does not change.
        // Edge case 2: If rows >= string length, no zigzag is possible.
        if (numRows == 1 || numRows >= s.length()) {
            return s;
        }

        // Each StringBuilder stores the characters belonging to one row.
        StringBuilder[] rows = new StringBuilder[numRows];

        for (int i = 0; i < numRows; i++) {
            rows[i] = new StringBuilder();
        }

        int currentRow = 0;

        // Initially, move down through the rows.
        int direction = 1;

        for (char ch : s.toCharArray()) {

            // Add the current character to its corresponding row.
            rows[currentRow].append(ch);

            // At the top, start moving down.
            if (currentRow == 0) {
                direction = 1;
            }
            // At the bottom, start moving diagonally upward.
            else if (currentRow == numRows - 1) {
                direction = -1;
            }

            // Move one row in the current direction.
            currentRow += direction;
        }

        // Read the rows from top to bottom to build the answer.
        StringBuilder result = new StringBuilder(s.length());

        for (StringBuilder row : rows) {
            result.append(row);
        }

        return result.toString();
    }
}
```

## 2. How to derive the solution in an interview

Think about the movement of a character, not its final index.

There are only two directions:

- Down: `0 → 1 → 2 → ... → numRows - 1`
- Up: `numRows - 1 → ... → 2 → 1 → 0`

Whenever we reach the bottom row, reverse the direction. Whenever we reach the top row, reverse it again.

The algorithm needs just three things:

1. `rows[]` — stores the characters for each row.
2. `currentRow` — identifies where the next character belongs.
3. `direction` — indicates whether we move down (`+1`) or up (`-1`).

This is simpler than calculating the exact position of every character.

## 3. Dry run

Input:

```
s = "COMPUTER"
numRows = 3
```

| Character | Current row | Action             | Row contents after insertion |
| --------- | ----------- | ------------------ | ---------------------------- |
| C         | 0           | Move down          | `C`, `, `                    |
| O         | 1           | Move down          | `C`, `O`, \`\`               |
| M         | 2           | Reverse; move up   | `C`, `O`, `M`                |
| P         | 1           | Move up            | `C`, `OP`, `M`               |
| U         | 0           | Reverse; move down | `CU`, `OP`, `M`              |
| T         | 1           | Move down          | `CU`, `OPT`, `M`             |
| E         | 2           | Reverse; move up   | `CU`, `OPT`, `ME`            |
| R         | 1           | Move up            | `CU`, `OPTR`, `ME`           |

Concatenate all rows:

```
CU + OPTR + ME = CUOPTRME
```

## 4. Complexity analysis

Let \\(n\\) be the length of the input string and \\(r\\) be `numRows`.

| Complexity      | Analysis                                          |
| --------------- | ------------------------------------------------- |
| Time            | \\(O(n+r)\\), which is \\(O(n)\\) when \\(r\<n\\) |
| Auxiliary space | \\(O(n+r)\\), which is \\(O(n)\\) when \\(r\<n\\) |
| Output space    | \\(O(n)\\) for the resulting string               |

Each character is processed once, and each row is appended once to the result. Java's `StringBuilder` avoids repeatedly creating intermediate strings.

## 5. Important edge cases

| Input         | Expected output | Reason                                 |
| ------------- | --------------- | -------------------------------------- |
| `"A"`, `1`    | `"A"`           | Only one row                           |
| `"ABC"`, `1`  | `"ABC"`         | No zigzag with one row                 |
| `"ABC"`, `3`  | `"ABC"`         | Each character occupies a separate row |
| `"ABC"`, `5`  | `"ABC"`         | Number of rows exceeds string length   |
| `"ABCD"`, `2` | `"ACBD"`        | Alternates between two rows            |

## 6. Alternative: Mathematical index calculation

Another solution calculates the positions of characters directly, without simulating row movement.

The zigzag cycle length is:

\\[ \text{cycleLength}=2(r-1) \\]

For each row, calculate the characters belonging to that row using the cycle length and, for middle rows, an additional diagonal position.

This approach is useful if an interviewer specifically asks for a mathematical solution, but it is more error-prone than simulation. The row-by-row solution above is the recommended default.

## 7. Interview follow-up questions

Q1. Why do we need the special case `numRows == 1`?

With one row, the direction logic would repeatedly reverse at the same row, so handling it separately is clearer and avoids incorrect movement.

Q2. Why use `StringBuilder` instead of string concatenation?

Repeated string concatenation can create many intermediate strings. `StringBuilder` appends characters efficiently.

Q3. Can we solve this without storing separate row builders?

Yes. We can calculate the exact indices for each row using the cycle length, but the simulation approach is easier to implement and maintain.

Q4. What happens when `numRows >= s.length()`?

Every character fits in its own row, or there are more rows than characters. The original string is already the answer.

Q5. Is this a graph or dynamic programming problem?

Neither. It is a simulation problem: maintain a current position and direction, then aggregate the result.

Interview takeaway: Whenever a problem describes moving in a repeating pattern, first consider whether you can simulate the movement with a position variable and a direction variable. Here, that produces a clean \\(O(n)\\) solution.
