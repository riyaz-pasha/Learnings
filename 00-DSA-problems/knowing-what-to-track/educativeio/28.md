# Maximum Product of Three Numbers — Java Solution

The goal is to choose exactly three elements from an integer array such that their product is as large as possible.

The important catch is that the array can contain negative numbers. Therefore, the three largest elements are not always the correct answer.

## 1. Understand the key observation

There are only two possible candidates for the maximum product:

1. The product of the three largest numbers.
2. The product of the two smallest numbers and the largest number.

Why?

- Three large positive numbers can produce the maximum product.
- Two large-magnitude negative numbers produce a positive product when multiplied together. Multiplying that result by the largest number can give an even larger answer.

For example:

Example 1 — Positive numbers dominate

## nums = [1, 2, 3, 4]

\\[ 4 \times 3 \times 2 = 24 \\]

Example 2 — Negative numbers matter

## nums = [-10, -10, 1, 3, 2]

\\[ (-10)\times(-10)\times3 = 300 \\]

The three largest numbers give only \\(3 \times 2 \times 1 = 6\\), which is not optimal.

## 2. Solution 1: Sort the array

This is the easiest solution to derive in an interview.

After sorting the array in ascending order:

- `nums[n - 1]`, `nums[n - 2]`, and `nums[n - 3]` are the three largest numbers.
- `nums[0]` and `nums[1]` are the two smallest numbers.

Calculate both candidate products and return the larger one.

### Java code — Sorting approach

```

import java.util.Arrays;

class Solution {
    public int maximumProduct(int[] nums) {
        // Sort in ascending order.
        // After sorting, the smallest values are at the beginning
        // and the largest values are at the end.
        Arrays.sort(nums);

        int n = nums.length;

        // Candidate 1: Product of the three largest numbers.
        int largestThree = nums[n - 1] * nums[n - 2] * nums[n - 3];

        // Candidate 2: Product of the two smallest numbers
        // (possibly negative) and the largest number.
        int twoSmallestAndLargest = nums[0] * nums[1] * nums[n - 1];

        // The maximum product must be one of these two candidates.
        return Math.max(largestThree, twoSmallestAndLargest);
    }
}

```

Complexity

- Time: \\(O(n\log n)\\) due to sorting.
- Auxiliary space: Depends on the sorting implementation; Java's primitive-array sort uses implementation-dependent workspace.

Trade-off: This solution is simple and easy to explain, but we can do better without sorting.

## 3. Solution 2: One pass — optimal approach

We only need five values from the array:

- `max1`: largest number
- `max2`: second-largest number
- `max3`: third-largest number
- `min1`: smallest number
- `min2`: second-smallest number

We can find all five in a single traversal, then calculate the same two candidate products.

### Java code — Optimal \\(O(n)\\) solution

```

class Solution {
    public int maximumProduct(int[] nums) {
        // Track the three largest numbers.
        int max1 = Integer.MIN_VALUE;
        int max2 = Integer.MIN_VALUE;
        int max3 = Integer.MIN_VALUE;

        // Track the two smallest numbers.
        int min1 = Integer.MAX_VALUE;
        int min2 = Integer.MAX_VALUE;

        for (int num : nums) {

            // Update the three largest values.
            if (num >= max1) {
                // The previous largest shifts to second place,
                // and the previous second-largest shifts to third.
                max3 = max2;
                max2 = max1;
                max1 = num;
            } else if (num >= max2) {
                // This number belongs in second place.
                max3 = max2;
                max2 = num;
            } else if (num > max3) {
                // This number belongs in third place.
                max3 = num;
            }

            // Update the two smallest values.
            if (num <= min1) {
                // The previous smallest shifts to second place.
                min2 = min1;
                min1 = num;
            } else if (num < min2) {
                min2 = num;
            }
        }

        // Candidate 1: Three largest numbers.
        int largestThree = max1 * max2 * max3;

        // Candidate 2: Two smallest numbers and the largest.
        int twoSmallestAndLargest = min1 * min2 * max1;

        return Math.max(largestThree, twoSmallestAndLargest);
    }
}

```

### How to derive the one-pass solution in an interview

Think of the problem in two stages:

1. Reduce the search space: Instead of considering every possible triplet, prove that only two triplets can be optimal.
2. Find the required extremes: Maintain the three largest and two smallest values as you scan the array.

This avoids sorting and does not require storing a separate array.

### Dry run

Consider:

`nums = [-10, -10, 1, 3, 2]`

| Number processed | Three largest (`max1, max2, max3`) | Two smallest (`min1, min2`) |
| ---------------- | ---------------------------------- | --------------------------- |
| -10              | -10, -∞, -∞                        | -10, +∞                     |
| -10              | -10, -10, -∞                       | -10, -10                    |
| 1                | 1, -10, -10                        | -10, -10                    |
| 3                | 3, 1, -10                          | -10, -10                    |
| 2                | 3, 2, 1                            | -10, -10                    |

Here, the final values are:

- Three largest product: \\(3 \times 2 \times 1 = 6\\)
- Two smallest and largest product: \\((-10)\times(-10)\times3 = 300\\)

Answer: `300`

Note: The `-∞` and `+∞` symbols in the table represent the initial integer sentinel values; they are not actual array elements.

### Complexity

- Time: \\(O(n)\\), because every element is processed once.
- Auxiliary space: \\(O(1)\\), because we maintain only five variables.

This is the optimal asymptotic time complexity: any correct algorithm must inspect the array elements in the general case, requiring \\(\Omega(n)\\) time.

## 4. Why does comparing just two products work?

Let the sorted values be:

\\[ a_1 \le a_2 \le \cdots \le a_n \\]

There are two relevant cases.

Case A: The three largest values give the best product.

If the optimal triplet contains no two negative values whose product improves the result, choosing the three largest values is optimal.

Case B: Two negative values give a better product.

The most negative values have the largest absolute magnitudes among the negative values. Their product is nonnegative, and pairing them with the largest available number gives the second candidate:

\\[ a_1 \times a_2 \times a_n \\]

Comparing these two candidates covers the possible optimal triplets.

## 5. Edge cases to remember

| Input                        | Expected output | Reason                                                |
| ---------------------------- | --------------- | ----------------------------------------------------- |
| `[1, 2, 3]`                  | `6`             | Exactly three elements                                |
| `[-1, -2, -3]`               | `-6`            | All products are negative; the least negative is best |
| `[-10, -10, 1, 3, 2]`        | `300`           | Two negatives produce a large positive product        |
| `[-5, -4, -3, -2, -1]`       | `-6`            | The three largest values are `-1, -2, -3`             |
| `[0, 0, 0, 0]`               | `0`             | Every triplet product is zero                         |
| `[-1000, -1000, 1000, 1000]` | `1000000000`    | Two negative values and one positive value            |

With the given constraints, the absolute maximum product is \\(1000^3 = 10^9\\), which fits within Java's `int` range.

## 6. Other approaches

| Approach                         | Time             | Auxiliary space          | Notes                                                 |
| -------------------------------- | ---------------- | ------------------------ | ----------------------------------------------------- |
| Brute force: check every triplet | \\(O(n^3)\\)     | \\(O(1)\\)               | Simple baseline; too slow for \\(n=10^4\\)            |
| Sort and compare two candidates  | \\(O(n\log n)\\) | Implementation-dependent | Easiest to derive                                     |
| One pass tracking five extremes  | \\(O(n)\\)       | \\(O(1)\\)               | Best practical solution                               |
| Max/min heap                     | \\(O(n\log n)\\) | \\(O(n)\\)               | Unnecessary when a fixed number of extremes is needed |

## 7. Interview follow-up questions

Q1. Why not simply multiply the three largest numbers?

Because two negative numbers can multiply into a large positive value. For example, `[-10, -10, 1, 2, 3]` has a maximum product of `300`, not `6`.

Q2. Why track the two smallest numbers rather than all negative numbers?

Only the two smallest values are needed to construct the strongest candidate involving two negative values. Tracking every negative number would require unnecessary storage.

Q3. Does the one-pass algorithm work with duplicate values?

Yes. The comparisons use `>=` and `<=` when updating the largest and smallest values, so duplicate values are handled correctly.

Q4. Can the product overflow?

Not under the stated constraints. If the input bounds were much larger, use `long` for the products and return type if the method signature permits it.

Q5. What if the problem asks for the actual three elements instead of their product?

Track the indices alongside the five extreme values. Compare the candidate products and return the indices associated with the winning triplet. Be careful to preserve the correct indices when shifting the largest and smallest values.

## Final recommendation

For coding interviews, start with the sorting solution to establish the key insight, then optimize to the one-pass solution with \\(O(n)\\) time and \\(O(1)\\) auxiliary space. The most important lesson is to consider both the three largest values and the two smallest values paired with the largest value.
