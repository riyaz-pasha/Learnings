# Maximum Frequency Stack — Java 24

This is a classic data structure design problem (LeetCode 895). The key challenge is that `pop()` must remove the most frequent element, and when multiple elements have the same frequency, it must remove the most recently pushed among them.

The best solution uses two HashMaps and a frequency-indexed stack structure to achieve \\(O(1)\\) average time for both `push()` and `pop()`.

## 1. Understand the problem with an example

Consider these operations:

```
push(5)
push(7)
push(5)
push(7)
push(4)
push(5)
```

The stack contains these values in insertion order:

Frequencies: 5 → 3, 7 → 2, 4 → 1

Now call `pop()`.

- `5` has frequency 3.
- `7` has frequency 2.
- `4` has frequency 1.

So `pop()` returns 5.

Suppose the next `pop()` is called. Now `5` has frequency 2, and `7` also has frequency 2. Both are tied for the maximum frequency.

However, `7` was pushed more recently than the remaining `5` at frequency 2. Therefore, `pop()` returns 7.

Expected output for three consecutive pops:

```
pop() → 5
pop() → 7
pop() → 5
```

The important insight is that this is not an ordinary stack and not simply a frequency counter. We must track both frequency and recency.

## 2. Intuition: how do we solve it efficiently?

A straightforward solution might scan every element to find the most frequent one whenever `pop()` is called. But that would take \\(O(n)\\) time per pop.

Instead, ask two questions:

1. How can we immediately know the current frequency of each value?
2. How can we immediately find the most recently pushed value at the highest frequency?

We can answer both using two maps and a maximum-frequency variable.

### The two maps

### 1. `frequency` — value → current frequency

Answers: How often has this value appeared in the current stack?

## 5

freq = 3

## 7

freq = 2

## 4

freq = 1

### 2. `group` — frequency → stack of values

Answers: Which value most recently reached this frequency?

Frequency 3

Bottom [5] Top

Frequency 2

Bottom [5, 7] Top

Frequency 1

Bottom [5, 7, 4] Top

Each group's rightmost value is its stack top. A value is recorded whenever a push makes it reach a new frequency.

We also maintain `maxFrequency`, which stores the highest frequency currently present. This lets `pop()` find the correct group without searching.

## 3. Java 24 solution

```

import java.util.ArrayDeque;
import java.util.Deque;
import java.util.HashMap;
import java.util.Map;

class FreqStack {

    // Maps each value to its current frequency in the stack.
    private final Map<Integer, Integer> frequency = new HashMap<>();

    // group[f] stores values in the order they reached frequency f.
    // The most recently recorded value is at the top of this stack.
    private final Map<Integer, Deque<Integer>> group = new HashMap<>();

    // Highest frequency among all values currently in the stack.
    private int maxFrequency = 0;

    public FreqStack() {
        // HashMaps and maxFrequency are initialized automatically.
    }

    public void push(int value) {

        // Step 1: Increase this value's frequency by one.
        int newFrequency = frequency.getOrDefault(value, 0) + 1;
        frequency.put(value, newFrequency);

        // Step 2: Record the value in the stack for its new frequency.
        // Creating the deque only when this frequency is first encountered.
        group.computeIfAbsent(newFrequency, f -> new ArrayDeque<>())
             .push(value);

        // Step 3: Update the maximum frequency if necessary.
        maxFrequency = Math.max(maxFrequency, newFrequency);
    }

    public int pop() {

        // Step 1: The answer must come from the highest-frequency group.
        Deque<Integer> candidates = group.get(maxFrequency);

        // Step 2: Pop the most recently recorded value from that group.
        int value = candidates.pop();

        // Step 3: This value has lost one occurrence.
        int updatedFrequency = frequency.get(value) - 1;
        frequency.put(value, updatedFrequency);

        // Step 4: If this frequency group is empty, the maximum
        // frequency no longer exists, so reduce it by one.
        if (candidates.isEmpty()) {
            maxFrequency--;
        }

        // Step 5: Return the most frequent, most-recently-pushed value.
        return value;
    }
}

```

### Why `group` is not just a frequency counter

Suppose we push `5`, `7`, `5`, `7`.

The frequency map becomes:

```
frequency = {
    5: 2,
    7: 2
}
```

The frequencies are tied. The frequency map alone cannot tell us which value should be popped first.

But the group stacks preserve the required order:

```
group[1] = [5, 7]  // top = 7
group[2] = [5, 7]  // top = 7
```

Thus, `group[2].pop()` returns `7`, satisfying the recency rule.

Notice that `group[1]` is not the same as the set of values currently having frequency 1. It is a historical ordering of values that reached frequency 1. Some of those values may subsequently have moved to a higher frequency. This is intentional.

### What happens during each pop?

First pop: `5`

- `maxFrequency = 3`, so we pop from `group[3]`.
- The value `5` is removed.
- Its frequency decreases from 3 to 2.
- `group[3]` is empty, so `maxFrequency` becomes 2.

Second pop: `7`

- `maxFrequency = 2`, so we pop from `group[2]`.
- The top element is `7`, because it reached frequency 2 more recently than `5`.
- Its frequency decreases from 2 to 1.
- `group[2]` still contains `5`, so `maxFrequency` remains 2.

Third pop: `5`

- `group[2]` now has `5` at its top.
- We remove `5`, reducing its frequency to 1.
- `group[2]` becomes empty, so `maxFrequency` decreases to 1.

The resulting pop sequence is `5, 7, 5`.

## 5. How to derive this solution in an interview

A useful way to approach the problem is to start with the simplest possible solution and identify its bottleneck.

Step 1: Count frequencies

Use a `HashMap<Integer, Integer>` to track how often each value appears. This makes frequency updates efficient, but does not resolve ties by recency.

Step 2: Preserve recency within each frequency

Use a separate stack for each frequency. Whenever a value reaches frequency `f`, push it onto `group[f]`. Its position in that stack preserves the order in which values reached that frequency.

Step 3: Eliminate searching

Track `maxFrequency`. A pop always comes from that group, and when the group becomes empty, decrease the maximum frequency by one.

The central insight is that a value can move between frequency levels as it is pushed and popped. We don't need to reorganize every value when this happens; we only record the event in the stack corresponding to the new frequency.

## 6. Time and space complexity

Let \\(n\\) be the number of elements currently in the structure, and \\(M\\) be the maximum number of elements ever stored.

| Operation     | Time complexity    | Reason                                       |
| ------------- | ------------------ | -------------------------------------------- |
| `push(value)` | \\(O(1)\\) average | HashMap update and deque push                |
| `pop()`       | \\(O(1)\\) average | Deque pop and HashMap update                 |
| Space         | \\(O(M)\\)         | Frequency entries and frequency-group stacks |

Both operations have \\(O(1)\\) average time complexity, which is the optimal target for this problem.

A subtle detail: `group` retains historical entries in lower-frequency stacks, even after values have moved to higher frequencies. That is safe because only `group[maxFrequency]` is used for a pop. These historical entries do not need to be deleted.

## 7. Edge cases to understand

| Scenario                                | Expected behavior                                                                       |
| --------------------------------------- | --------------------------------------------------------------------------------------- |
| Only one element exists                 | Pop and return that element; maximum frequency becomes 0.                               |
| Same value pushed repeatedly            | It becomes the most frequent value and is popped until its frequency decreases.         |
| Several values tie                      | Pop the value most recently recorded at the maximum frequency.                          |
| A maximum-frequency group becomes empty | Decrease `maxFrequency` by one.                                                         |
| A value's frequency decreases           | Update its frequency map entry; do not remove its historical entries from other groups. |
| Value `0`                               | Works normally; zero is a valid element, not an absence marker.                         |

The problem guarantees that `pop()` is never called on an empty structure, so explicit empty-stack validation is unnecessary.

## 8. Other possible approaches

### Approach A: Frequency map + scan on every pop

Maintain a frequency map and an insertion history. During each `pop()`, scan the history to find the value with the highest frequency and most recent occurrence.

- `push()`: \\(O(1)\\) average.
- `pop()`: \\(O(n)\\), depending on the scanning and removal strategy.
- Space: \\(O(n)\\).

This is useful as a brute-force baseline but unnecessarily slow.

### Approach B: Priority queue

Store entries with frequency and recency information, ordered by highest frequency and then latest push. Each update requires maintaining the heap's state and ensuring that entries reflect current frequencies. A correct implementation typically uses versioning or lazy invalidation.

- `push()`: typically \\(O(\log n)\\).
- `pop()`: typically \\(O(\log n)\\).
- Space: \\(O(n)\\) or more, depending on lazy invalidation.

This can work, but it is more complicated than the frequency-group solution.

### Approach C: Frequency-group stacks — recommended

Use the two maps and `maxFrequency` shown above.

- `push()`: \\(O(1)\\) average.
- `pop()`: \\(O(1)\\) average.
- Space: \\(O(n)\\) for the stored elements and metadata.

This is the standard optimal interview solution.

## 9. Interview follow-up questions and answers

Q1. Why can't we use only a `HashMap` for frequencies?

Because frequencies alone don't preserve insertion recency. Two values can have the same maximum frequency, and we must know which one reached that frequency most recently.

Q2. Why don't we decrement `maxFrequency` on every pop?

Because the maximum frequency might still exist. For example, if `group[2]` contains both `5` and `7`, popping one element leaves another candidate at frequency 2. We decrement `maxFrequency` only when that group becomes empty.

Q3. Why does `maxFrequency` decrease by exactly one?

Every push increases an element's frequency by exactly one, and therefore can increase the maximum by at most one. When the current maximum-frequency group becomes empty, no element has that frequency anymore. The next possible maximum is at most one less, so decrementing by one is sufficient.

Q4. Why use `ArrayDeque` instead of `Stack`?

`ArrayDeque` is the preferred modern Java choice for stack operations in ordinary single-threaded code. Its `push()` and `pop()` methods operate at the deque's head without the legacy `Stack` class's unnecessary synchronization overhead.

Q5. Is the structure thread-safe?

No. The two maps, the deques, and `maxFrequency` are updated together. Concurrent access requires synchronization or another design that provides atomic updates.

Q6. What if we need to return the most frequent element without removing it?

We can peek at `group[maxFrequency]` instead of popping. The current most frequent, most recently recorded candidate is at that group's top. No frequency updates are needed.

## 10. Clarifying questions to ask the interviewer

Before implementing, confirm:

- Can values be duplicated? Yes, because frequency is central to the problem.
- Does recency refer to the most recent push among values tied for maximum frequency? Yes.
- Can `pop()` be called on an empty structure? Here, the constraints guarantee it cannot.
- Are both operations expected to run in constant time? This is a useful target to confirm, and the two-map approach achieves average \\(O(1)\\).

Final takeaway: Think of the data structure as a frequency counter plus a stack for each frequency. The frequency counter tells you which group to use, the group stack resolves recency, and `maxFrequency` avoids searching. That's the entire optimization.
