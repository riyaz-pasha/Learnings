# Count Distinct Anagrams of a String — Java 24

The key observation is that each word can be rearranged independently, but the spaces must remain in their original positions.

For each word, count its distinct permutations and multiply the answers for all words. Since the result can be very large, perform the calculation modulo \\(10^9+7\\).

## 1. Intuition and reasoning

Suppose the input is:

```
s = "too hot"
```

The string contains two words: `"too"` and `"hot"`.

- `"too"` has 3 letters, where `o` occurs twice. Its distinct anagrams are \\(\frac{3!}{2!}=3\\).
- `"hot"` has 3 distinct letters. Its distinct anagrams are \\(3!=6\\).

Because the words can be rearranged independently, the multiplication principle gives:

\\[ \text{Answer}=3\times6=\boxed{18} \\]

We multiply rather than add because every valid arrangement of the first word can be combined with every valid arrangement of the second word.

## 2. Formula for a single word

If a word has \\(n\\) letters and each distinct character occurs \\(f_1,f_2,\ldots,f_k\\) times, the number of distinct anagrams is:

\\[ \boxed{\frac{n!}{f_1!f_2!\cdots f_k!}} \\]

Why do we divide by repeated-character factorials? If we treated identical letters as different, we would count the same arrangement multiple times.

For example, `"aab"` has \\(3!=6\\) arrangements if the two `a` characters are treated as different. But swapping those identical `a` characters does not create a new string, so we divide by \\(2!\\):

\\[ \frac{3!}{2!}=3 \\]

The three distinct arrangements are `aab`, `aba`, and `baa`.

For the complete input, the answer is:

\\[ \boxed{ \prod\_{\text{each word }w} \frac{|w|!}{\prod\_{c} \operatorname{freq}\_w(c)!} \pmod {10^9+7} } \\]

## 3. Optimized Java 24 solution

The main challenge is division under modulo. We cannot directly divide by factorials after taking modulo.

Since \\(M=10^9+7\\) is prime, Fermat's little theorem gives:

\\[ a^{-1}\equiv a^{M-2}\pmod M \\]

Therefore, we can precompute factorials and inverse factorials, allowing each word's answer to be calculated efficiently.

```

class Solution {
    private static final long MOD = 1_000_000_007L;

    public int countAnagrams(String s) {
        int n = s.length();

        // fact[i] = i! % MOD.
        long[] fact = new long[n + 1];

        // invFact[i] = modular inverse of i! % MOD.
        long[] invFact = new long[n + 1];

        // Precompute factorials from 0! to n!.
        fact[0] = 1;
        for (int i = 1; i <= n; i++) {
            fact[i] = fact[i - 1] * i % MOD;
        }

        // By Fermat's little theorem:
        // invFact[n] = (n!)^(MOD - 2) % MOD.
        invFact[n] = modPow(fact[n], MOD - 2);

        // Derive all smaller inverse factorials:
        // 1/(i-1)! = i * 1/i! (mod MOD).
        for (int i = n; i >= 1; i--) {
            invFact[i - 1] = invFact[i] * i % MOD;
        }

        long answer = 1;
        int[] frequency = new int[26];
        int wordLength = 0;

        // Process each word independently.
        for (int i = 0; i <= n; i++) {

            // A space or the end of the string marks
            // the end of the current word.
            if (i == n || s.charAt(i) == ' ') {

                // Start with wordLength! and divide out
                // the factorial of every character count.
                long ways = fact[wordLength];

                for (int count : frequency) {
                    if (count > 0) {
                        ways = ways * invFact[count] % MOD;
                    }
                }

                // Independent word arrangements multiply.
                answer = answer * ways % MOD;

                // Reset state before processing the next word.
                frequency = new int[26];
                wordLength = 0;

            } else {
                char ch = s.charAt(i);

                // Count occurrences of each lowercase letter.
                frequency[ch - 'a']++;
                wordLength++;
            }
        }

        return (int) answer;
    }

    // Computes base^exponent % MOD using binary exponentiation.
    private long modPow(long base, long exponent) {
        long result = 1;

        while (exponent > 0) {
            // If the current exponent bit is set, multiply.
            if ((exponent & 1) == 1) {
                result = result * base % MOD;
            }

            // Square the base and halve the exponent.
            base = base * base % MOD;
            exponent >>= 1;
        }

        return result;
    }
}

```

## 5. Why inverse factorials work

Consider a word of length \\(n\\), with character frequencies \\(f_1,f_2,\ldots,f_k\\).

We need to calculate:

\\[ \frac{n!}{f_1!f_2!\cdots f_k!} \\]

In modular arithmetic, division is replaced with multiplication by modular inverses:

\\[ n!\times(f_1!)^{-1}\times(f_2!)^{-1}\cdots \pmod M \\]

Our precomputed `invFact[count]` stores exactly the modular inverse of `count!`.

This is why the following line works:

```
ways = ways * invFact[count] % MOD;
```

The `modPow` method computes these inverses efficiently using binary exponentiation in \\(O(\log M)\\) time.

## 6. Complexity analysis

Let \\(n\\) be the length of the entire string, including spaces.

| Operation                        | Complexity        |
| -------------------------------- | ----------------- |
| Factorial precomputation         | \\(O(n)\\)        |
| Inverse factorial precomputation | \\(O(n+\log M)\\) |
| Processing all words             | \\(O(n+26W)\\)    |
| Total time                       | \\(O(n+\log M)\\) |
| Auxiliary space                  | \\(O(n)\\)        |

Here, \\(W\\) is the number of words. Since \\(W\le n\\) and the alphabet has only 26 letters, processing the frequencies takes \\(O(n)\\) time.

The factorial arrays require \\(O(n)\\) space, while the frequency array requires only \\(O(26)=O(1)\\) space at any moment.

## 7. Edge cases to consider

| Input       | Expected result | Reason                          |
| ----------- | --------------- | ------------------------------- |
| `"a"`       | 1               | Only one arrangement            |
| `"aa"`      | 1               | Identical letters               |
| `"ab"`      | 2               | Two distinct letters            |
| `"a a"`     | 1               | Each word has one letter        |
| `"ab ab"`   | 4               | \\(2!\times2!\\)                |
| `"aaa bbb"` | 1               | Each word has identical letters |
| `"aab abc"` | 18              | \\(3\times6\\)                  |

The constraints guarantee that the string is nonempty and that consecutive words have exactly one space, so there are no empty words to process.

## 8. Alternative approaches

- Brute force: Generate every permutation of each word and count distinct strings using a set. This becomes factorial-time and is impractical even for relatively short words.
- Direct factorial calculation: Calculate \\(n!\\) and divide by the repeated-character factorials using ordinary integer arithmetic. This fails because factorials grow extremely quickly and modular division is not ordinary division.
- Optimized modular arithmetic (recommended): Precompute factorials and inverse factorials, then calculate each word's multinomial coefficient. This is efficient and handles the constraints comfortably.

## 9. Interview follow-up questions

Q1. Why can't we simply calculate `fact[n] / fact[count]` modulo `MOD`?

Because modular arithmetic does not preserve ordinary division. We must multiply by the modular inverse instead.

Q2. Why is the modulus required to be prime?

The Fermat-based inverse formula \\(a^{M-2}\bmod M\\) requires a prime modulus and a nonzero value modulo that prime.

Q3. Why must character frequencies reset after each word?

Because each word is rearranged independently, and characters cannot move across spaces. Counting frequencies over the entire string would incorrectly allow letters to move between words.

Q4. Can we avoid precomputing inverse factorials?

Yes. We could calculate each required modular inverse using binary exponentiation, but that repeats expensive calculations. Precomputation is preferable when multiple factorial inverses are needed.

Q5. What is the key mathematical concept behind this problem?

The multinomial coefficient, combined with the multiplication principle and modular multiplicative inverses.

Interview tip: First recognize that the answer is the product of each word's distinct permutation count. Then recognize the multinomial coefficient and handle division using modular inverses. That leads directly to the optimized solution.
