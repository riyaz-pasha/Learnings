# Pivot Index — Java Solution

The cleanest and most efficient solution is to use a running left sum and the total sum of the array.

## 1. Optimal solution — One pass after calculating the total sum

```
class Solution {
    public int pivotIndex(int[] nums) {
        // Step 1: Calculate the sum of all elements.
        int totalSum = 0;

        for (int num : nums) {
            totalSum += num;
        }

        // Step 2: Start with an empty left side.
        int leftSum = 0;

        // Check indices from left to right to find the LEFTMOST pivot.
        for (int i = 0; i < nums.length; i++) {

            // Right sum = total sum - left sum - current element.
            int rightSum = totalSum - leftSum - nums[i];

            // A pivot exists when both side sums are equal.
            if (leftSum == rightSum) {
                return i;
            }

            // Include the current element in the left sum
            // before checking the next index.
            leftSum += nums[i];
        }

        // No pivot index exists.
        return -1;
    }
}
```

### Complexity analysis

- Time: \\(O(n)\\) — one pass to calculate the total sum and another pass to find the pivot.
- Auxiliary space: \\(O(1)\\) — only two variables are maintained.

## 2. Intuition: How do we calculate the right sum efficiently?

At every index `i`, we need to compare:

- `leftSum`: sum of elements before `i`.
- `rightSum`: sum of elements after `i`.

A straightforward approach would recalculate both sums for every index, taking \\(O(n^2)\\) time.

Instead, observe that:

\\[ \text{TotalSum}=\text{LeftSum}+\text{nums[i]}+\text{RightSum} \\]

Rearranging this equation gives:

\\[ \boxed{\text{RightSum}=\text{TotalSum}-\text{LeftSum}-\text{nums[i]}} \\]

This is the key insight. We can calculate the right sum in constant time without another loop.

## 3. Dry run with an example

Input:

```
nums = [1, 7, 3, 6, 5, 6]
```

The total sum is \\(28\\).

| Index `i` | `nums[i]` | Left sum | Right sum | Pivot? |
| --------- | --------- | -------- | --------- | ------ |
| 0         | 1         | 0        | 27        | No     |
| 1         | 7         | 1        | 20        | No     |
| 2         | 3         | 8        | 17        | No     |
| 3         | 6         | 11       | 11        | Yes    |

At index `3`:

- Left elements: `[1, 7, 3]` → sum = 11
- Right elements: `[5, 6]` → sum = 11

Since both sums are equal, the answer is `3`.

We return immediately because we iterate from left to right, guaranteeing that this is the leftmost pivot.

## 4. Important edge cases

Case 1: Pivot at the left edge

`nums = [2, 1, -1]`

Left sum at index `0` is `0`, and right sum is `1 + (-1) = 0`.

Output: 0

Case 2: Pivot at the right edge

`nums = [1, -1, 2]`

At index `2`, the left sum is `1 + (-1) = 0` and the right sum is `0`.

Output: 2

Case 3: No pivot exists

`nums = [1, 2, 3]`

No index has equal left and right sums.

Output: -1

Case 4: Multiple valid pivots

`nums = [0, 0, 0]`

Every index is a pivot, so we return the first one.

Output: 0

## 5. Alternative solution — Prefix sums

We can also precompute prefix sums and check each index. This is useful when you want to understand prefix-sum techniques.

```
class Solution {
    public int pivotIndex(int[] nums) {
        int n = nums.length;
        int[] prefixSum = new int[n];

        // prefixSum[i] stores the sum from index 0 through i.
        prefixSum[0] = nums[0];

        for (int i = 1; i < n; i++) {
            prefixSum[i] = prefixSum[i - 1] + nums[i];
        }

        int totalSum = prefixSum[n - 1];

        for (int i = 0; i < n; i++) {
            // Everything before i; zero when i is the first index.
            int leftSum = (i == 0) ? 0 : prefixSum[i - 1];

            // Everything after i.
            int rightSum = totalSum - prefixSum[i];

            if (leftSum == rightSum) {
                return i;
            }
        }

        return -1;
    }
}
```

- Time: \\(O(n)\\)
- Auxiliary space: \\(O(n)\\)

The prefix-sum approach works, but the first solution is better for this problem because it achieves the same time complexity with \\(O(1)\\) auxiliary space.

## 6. Interview tips

Why update `leftSum` after checking the pivot?

Because the current element belongs to neither side. Only after checking index `i` should `nums[i]` be added to the left sum for the next index.

Why does the algorithm handle negative numbers?

The formula uses addition and subtraction, so it works regardless of whether array elements are positive, negative, or zero.

Can we solve it in one pass?

We need the total sum before determining the right sum using this approach. Therefore, we use two linear traversals, which still gives optimal \\(O(n)\\) time and \\(O(1)\\) auxiliary space.

What should you say in an interview?

“I'll calculate the total sum first. Then I'll traverse the array while maintaining the sum of elements to the left. At each index, I'll derive the right sum by subtracting the left sum and current element from the total. If the two side sums match, I'll return that index immediately, ensuring the leftmost pivot. Otherwise, I'll return `-1`.”
