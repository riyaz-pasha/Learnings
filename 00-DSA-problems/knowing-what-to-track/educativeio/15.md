# Partition a Sorted Array Into Increasing Subsequences — Java

The key to this problem is understanding the difference between increasing subsequences and contiguous subarrays, and then using the fact that the array is already sorted.

## 1. Understand the problem

You are given a sorted array `nums` and an integer `k`.

You must partition every element into one or more disjoint increasing subsequences, where each subsequence has at least `k` elements.

- Disjoint: Every array element must belong to exactly one subsequence.
- Increasing: Elements in each subsequence must be strictly increasing.
- Subsequence: Elements do not need to be adjacent in the original array.
- Length at least `k`: Every subsequence must contain at least `k` elements.

### Example 1

```
nums = [1, 2, 3, 4, 5]
k = 3
```

We can create one subsequence:

```
[1, 2, 3, 4, 5]
```

Its length is 5, which is at least 3.

Output: `true`

### Example 2

```
nums = [1, 2, 3, 4]
k = 3
```

There are 4 elements, and each subsequence must have at least 3 elements.

We can put all elements into one increasing subsequence:

```
[1, 2, 3, 4]
```

Output: `true`

### Example 3

```
nums = [1, 1, 2, 2]
k = 2
```

We cannot put equal values into the same strictly increasing subsequence. But we can partition the array as follows:

```
Subsequence 1: [1, 2]
Subsequence 2: [1, 2]
```

Each subsequence has length 2 and is strictly increasing.

Output: `true`

## 2. The key observation

Because the array is sorted, the only obstacle to making a subsequence strictly increasing is duplicate values.

For example:

```
nums = [1, 1, 1, 2, 2, 3]
```

The three occurrences of `1` cannot belong to the same strictly increasing subsequence. Therefore, we need at least 3 different subsequences.

More generally:

\\[ \text{minimum subsequences required} = \text{maximum frequency of any value} \\]

Let:

- \\(n\\) = number of elements in `nums`
- \\(k\\) = minimum allowed subsequence length
- \\(f\_{\max}\\) = maximum frequency of any value

Since we need at least \\(f\_{\max}\\) subsequences and every subsequence must have at least \\(k\\) elements, we need:

\\[ n \geq k \times f\_{\max} \\]

Therefore, the answer is:

\\[ \boxed{f\_{\max} \leq \left\lfloor\frac{n}{k}\right\rfloor} \\]

This condition is both necessary and sufficient for a sorted array.

## 3. Optimal Java solution

```

class Solution {

    public boolean canPartition(int[] nums, int k) {
        int n = nums.length;

        // Since every subsequence needs at least k elements,
        // we can have at most n / k subsequences.
        int maxAllowedFrequency = n / k;

        int currentFrequency = 1;

        // Count consecutive occurrences because nums is sorted.
        for (int i = 1; i < n; i++) {

            if (nums[i] == nums[i - 1]) {
                currentFrequency++;
            } else {
                // A value occurs too frequently, so we would
                // need more subsequences than we can support.
                if (currentFrequency > maxAllowedFrequency) {
                    return false;
                }

                // Start counting the next distinct value.
                currentFrequency = 1;
            }
        }

        // Important: Check the final group as well because
        // the loop does not check it when the array ends.
        return currentFrequency <= maxAllowedFrequency;
    }
}

```

### Example that returns false

```

```

Here:


## 5. Complexity analysis

- Time complexity: \\(O(n)\\) — we scan the array once.
- Auxiliary space complexity: \\(O(1)\\) — we use only a few integer variables.

## 6. Interview intuition

The easiest way to derive this solution is to ask three questions:

1. What forces us to create separate subsequences? Duplicate values, because a strictly increasing subsequence cannot contain the same value twice.
2. How many subsequences must we create at minimum? At least as many as the maximum frequency of any value.
3. Can we make every subsequence at least length `k`? Only if the array has enough elements to give each required subsequence at least `k` elements.

That gives us the decisive condition:

```
maxFrequency <= nums.length / k
```

Since the array is sorted, we can calculate `maxFrequency` in one pass without using a `HashMap` or sorting the array again.

# Partition Sorted Array Into Increasing Subsequences — Detailed Java Explanation

Let's derive the solution from scratch, understand why the condition works, walk through examples, and examine the edge cases you might be asked about in an interview.

## 1. Understand exactly what the problem asks

You are given:

- `nums`: a sorted integer array in non-decreasing order.
- `k`: the minimum length required for every subsequence.

Your task is to determine whether you can divide all elements into one or more disjoint, strictly increasing subsequences, each having a length of at least `k`.

Three definitions are especially important.

1\. Disjoint subsequences

Every occurrence in the original array must be used exactly once. You cannot reuse an element or discard inconvenient elements.

2\. Increasing subsequences

Values must be strictly increasing. For example, `[1, 2, 4]` is strictly increasing, but `[1, 2, 2]` is not.

3\. Subsequences are not necessarily contiguous

You can skip positions in the original array when constructing a subsequence.

For example, from `[1, 1, 2, 2, 3]`, you can create `[1, 2, 3]` by selecting elements at different positions.

The important distinction is that duplicate values cannot appear twice in the same strictly increasing subsequence, but they can be distributed across different subsequences.

## 2. Start with a simple example

Suppose:

```
nums = [1, 2, 3, 4, 5]
k = 3
```

Can we partition the array?

Yes. We can use one subsequence containing every element:

```
Subsequence 1: [1, 2, 3, 4, 5]
```

It is strictly increasing and has length 5, which is at least 3.

Therefore, the answer is `true`.

Now consider:

```
nums = [1, 1, 2, 2]
k = 2
```

We cannot put both occurrences of `1` in the same subsequence, and we cannot put both occurrences of `2` in the same subsequence.

But we can distribute them:

```
Subsequence 1: [1, 2]
Subsequence 2: [1, 2]
```

Both subsequences have length 2 and are strictly increasing.

The answer is still `true`.

This gives us our first key insight: duplicates force us to create separate subsequences.

## 3. The core intuition: duplicates determine how many subsequences we need

Consider a slightly different example:

```
nums = [1, 1, 1, 2, 2, 3]
k = 2
```

There are three occurrences of `1`.

Because a strictly increasing subsequence cannot contain the same value more than once, those three occurrences must go into three different subsequences.

Visualize the distribution

1

2

1

1

Needs one more element

The three 1s require at least three subsequences. Each subsequence must contain at least two elements.

We need at least three subsequences, but the third one still needs another element to reach length 2.

We can use the remaining elements to fill it:

```
Subsequence 1: [1, 2]
Subsequence 2: [1, 2]
Subsequence 3: [1, 3]
```

All three subsequences are strictly increasing and have length at least 2.

Therefore, the answer is `true`.

Notice what happened: the number of occurrences of `1` determined the minimum number of subsequences we needed.

Let's express this mathematically.

Let:

- \\(n\\) = total number of elements.
- \\(k\\) = minimum length of each subsequence.
- \\(f\_{\max}\\) = maximum frequency of any value.

Then:

\\[ \boxed{\text{Minimum number of subsequences}=f\_{\max}} \\]

Why? Because every occurrence of the most frequent value must be placed into a different subsequence. And, because the array is sorted, we can construct increasing subsequences by distributing equal values across them and filling them with other values.

## 4. Derive the mathematical condition

Suppose the array has:

```
nums = [1, 1, 1, 2, 2, 3]
k = 2
```

The maximum frequency is 3, so we need at least 3 subsequences.

Each subsequence must contain at least 2 elements.

Therefore, the minimum number of elements required is:

\\[ 3 \times 2 = 6 \\]

We have exactly 6 elements, so the partition is possible.

Now suppose:

```
nums = [1, 1, 1, 1, 2, 3]
k = 2
```

Here:

- Total elements: \\(n=6\\)
- Maximum frequency: \\(f\_{\max}=4\\)
- Minimum required length: \\(k=2\\)

We need at least four subsequences, each containing at least two elements.

\\[ 4 \times 2 = 8 \\]

But we only have six elements. It is impossible to fill all four subsequences.

Therefore, the answer is `false`.

### Deriving the formula

If we need at least \\(f\_{\max}\\) subsequences, and every subsequence requires at least \\(k\\) elements, then:

\\[ n \geq f\_{\max} \times k \\]

Rearranging:

\\[ f\_{\max} \leq \frac{n}{k} \\]

Since the number of subsequences must be an integer, we use integer division:

\\[ \boxed{f\_{\max} \leq \left\lfloor\frac{n}{k}\right\rfloor} \\]

This is the key condition that solves the problem.

## 5. Why is this condition sufficient, not just necessary?

This is an important interview question.

We've shown that if the maximum frequency is too high, the partition is impossible. But if the maximum frequency is low enough, can we always construct a valid partition?

Yes, because the array is sorted.

Imagine creating \\(f\_{\max}\\) subsequences, one for each required row. For every distinct value, distribute its occurrences among different subsequences. This ensures that no subsequence contains duplicate values.

Because the input is sorted, the values within each subsequence can be arranged in strictly increasing order.

Also, every subsequence can contain at most one occurrence of each distinct value. If there are \\(d\\) distinct values, then each subsequence can have at most \\(d\\) elements. Since the total number of elements is \\(n\\) and \\(n \geq kf\_{\max}\\), we have enough elements to make every subsequence at least length \\(k\\).

We can distribute the occurrences across the subsequences so that their lengths differ by at most one. Since the total is at least \\(kf\_{\max}\\), every subsequence can receive at least \\(k\\) elements.

Thus, the condition is both necessary and sufficient.

## 6. Translate the reasoning into an algorithm

We now need an efficient way to find the maximum frequency.

Because `nums` is already sorted, equal values appear consecutively.

For example:

```
nums = [1, 1, 1, 2, 2, 3, 3, 3, 3]
```

The frequency groups are:

```
1 -> 3 occurrences
2 -> 2 occurrences
3 -> 4 occurrences
```

Therefore:

```
maxFrequency = 4
```

We don't need a `HashMap`, because we can count each group directly while traversing the array.

### Algorithm

1. Calculate `maxAllowedFrequency = nums.length / k`.
2. Initialize `currentFrequency = 1`.
3. Traverse the array from index 1.
4. If the current element equals the previous element, increment the frequency.
5. If the value changes, compare the completed frequency with `maxAllowedFrequency`.
6. If the frequency exceeds the limit, return `false`.
7. Reset the frequency to 1 and continue.
8. After the loop, check the final frequency group and return the result.

Why do we check the last group separately? Because the loop checks a frequency group only when it encounters a different value. The final group has no next value to trigger that check.

## 7. Complete Java solution with detailed comments

```

class Solution {

    public boolean canPartition(int[] nums, int k) {
        int n = nums.length;

        // Every subsequence must contain at least k elements.
        // Therefore, we cannot have more than n / k subsequences.
        //
        // Example: n = 6, k = 2
        // At most 6 / 2 = 3 subsequences are possible.
        int maxAllowedFrequency = n / k;

        // Count occurrences of the current value.
        // The first element starts a group of frequency 1.
        int currentFrequency = 1;

        // The array is sorted, so duplicate values are adjacent.
        for (int i = 1; i < n; i++) {

            if (nums[i] == nums[i - 1]) {

                // Same value: extend the current frequency group.
                currentFrequency++;

            } else {

                // The previous frequency group has ended.
                // If its frequency exceeds the limit, we need
                // too many subsequences to satisfy the length k.
                if (currentFrequency > maxAllowedFrequency) {
                    return false;
                }

                // A new distinct value starts here.
                currentFrequency = 1;
            }
        }

        // The final group is not checked inside the loop,
        // because there is no next distinct value to trigger it.
        return currentFrequency <= maxAllowedFrequency;
    }
}

```

## 9. Edge cases you should know

Case 1: All elements are distinct

true

```
nums = [1, 2, 3, 4]
k = 2
```

Maximum frequency is 1, and the allowed frequency is \\(4/2=2\\).

We can create `[1, 2, 3, 4]` as one subsequence.

Case 2: All elements are equal

false

```
nums = [5, 5, 5, 5]
k = 2
```

Maximum frequency is 4, but the allowed frequency is \\(4/2=2\\).

Each subsequence can contain at most one `5`, so every subsequence would have length 1. The required length is 2.

Case 3: k equals array length

true

```
nums = [1, 2, 3, 4]
k = 4
```

The allowed frequency is 1. All elements are distinct, so one subsequence containing all elements works.

Case 4: Duplicate group at the end

false

```
nums = [1, 2, 3, 3, 3, 3]
k = 2
```

The allowed frequency is 3, but the final group has frequency 4.

This case catches the common bug of forgetting to check the last frequency group after the loop.

Case 5: Minimum input size

true

```
nums = [7]
k = 1
```

The allowed frequency is 1, and the actual frequency is 1. The single-element subsequence satisfies the requirement.

## 10. Alternative solutions

The one-pass frequency scan is optimal for this sorted input. However, understanding alternatives helps you explain your design choices in interviews.

### Approach A: One-pass frequency counting — recommended

This is the solution we derived above.

- Time: \\(O(n)\\)
- Auxiliary space: \\(O(1)\\)
- Advantage: Uses the sorted property directly without extra data structures.

### Approach B: Frequency map

Count every value using a `HashMap`, find the maximum frequency, and apply the same mathematical condition.

```
import java.util.HashMap;
import java.util.Map;

class Solution {

    public boolean canPartition(int[] nums, int k) {
        Map<Integer, Integer> frequency = new HashMap<>();

        int maxFrequency = 0;

        for (int num : nums) {
            int count = frequency.merge(num, 1, Integer::sum);
            maxFrequency = Math.max(maxFrequency, count);
        }

        return maxFrequency <= nums.length / k;
    }
}
```

Complexities:

- Time: \\(O(n)\\) expected.
- Auxiliary space: \\(O(u)\\), where \\(u\\) is the number of distinct values.

This works even if the input is unsorted, provided the mathematical condition remains applicable to the problem's subsequence definition. However, for this particular sorted-array problem, the map is unnecessary.

## 11. Common mistakes

1. Checking only whether `nums.length >= k`. This is insufficient because duplicate values may force too many subsequences.
2. Counting only distinct values. Distinct values determine how many elements a subsequence can contain, but the maximum frequency determines how many subsequences are required.
3. Treating subsequences as contiguous subarrays. Elements can be selected from different positions, as long as the selected values are strictly increasing.
4. Forgetting the final frequency group. The last group needs an explicit check after the loop.
5. Using `>` incorrectly. A frequency equal to `n / k` is allowed. Return `false` only when the frequency is greater than that limit.

## 12. Final interview summary

Remember this chain of reasoning:

Duplicate values

Cannot appear twice in one strictly increasing subsequence

Maximum frequency = minimum subsequences required

Each subsequence needs at least k elements

Total elements must be sufficient

Final condition

\\[ \boxed{\text{maxFrequency} \leq \lfloor n/k \rfloor} \\]

Complexities of the optimal solution

| Complexity      | Result     | Reason                       |
| --------------- | ---------- | ---------------------------- |
| Time            | \\(O(n)\\) | One pass through the array   |
| Auxiliary space | \\(O(1)\\) | Only a few integer variables |

The main interview skill here is recognizing that you don't need to construct the subsequences. You only need to prove whether enough elements exist to support the minimum number of subsequences forced by duplicate values.
