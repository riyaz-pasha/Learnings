# Count and Say — Java 24 Solution

The key idea is simple: start with `"1"` and repeatedly describe consecutive groups of identical characters.

For example, if the current string is `"1211"`:

- One `1` → `"11"`
- One `2` → `"12"`
- Two `1`s → `"21"`

Combining these descriptions gives `"111221"`.

## 1. Intuition: Build the sequence iteratively

The sequence starts as follows:

| \\(n\\) | Count-and-say string |
| ------- | -------------------- |
| 1       | `"1"`                |
| 2       | `"11"`               |
| 3       | `"21"`               |
| 4       | `"1211"`             |
| 5       | `"111221"`           |
| 6       | `"312211"`           |

Notice that to calculate the \\(n\\)-th string, we only need the \\((n-1)\\)-th string. We don't need to store the entire sequence.

The algorithm is:

1. Initialize the current string to `"1"`.
2. Repeat \\(n-1\\) times.
3. Scan the current string from left to right.
4. Count consecutive identical characters.
5. Append the count followed by the character.
6. Use the generated string as the input for the next iteration.

## 2. Optimal practical solution — Iteration

Java 24 · LeetCode-compatible

```

class Solution {

    public String countAndSay(int n) {

        // Base case: the sequence starts with "1".
        String current = "1";

        // To reach the nth term, transform the string n - 1 times.
        for (int term = 2; term <= n; term++) {

            // Build the next term without repeatedly creating
            // intermediate strings using String concatenation.
            StringBuilder next = new StringBuilder();

            int i = 0;

            // Read the current string from left to right.
            while (i < current.length()) {

                char digit = current.charAt(i);

                // Count how many consecutive occurrences of this
                // character form the current group.
                int count = 0;

                while (i < current.length()
                        && current.charAt(i) == digit) {

                    count++;
                    i++;
                }

                // Run-length encoding format: count followed by digit.
                next.append(count);
                next.append(digit);
            }

            // The generated string becomes the input for the next term.
            current = next.toString();
        }

        return current;
    }
}

```

### Why does this work?

The most important part is the nested `while` loop:

```
while (i < current.length()
        && current.charAt(i) == digit) {
    count++;
    i++;
}
```

It consumes an entire group of identical consecutive characters. Once the group ends, we append its count and character, then process the next group.

Important: `i` is advanced inside the inner loop, so every character is processed exactly once per term. We don't accidentally count the same character again.

## 3. Dry run: `n = 5`

Let's trace the generation of each term.

Term 1

### `"1"`

Initial value; no encoding needed.

Term 2

### `"11"`

One `1` → append `11`.

Term 3

### `"21"`

Two `1`s → append `21`.

Term 4

### `"1211"`

One `2` → `12`; one `1` → `11`; combine → `1211`.

Term 5

### `"111221"`

Encode `"1211"` group by group:

| Group | Description | Output |
| ----- | ----------- | ------ |
| `1`   | One `1`     | `11`   |
| `2`   | One `2`     | `12`   |
| `11`  | Two `1`s    | `21`   |

Concatenate `11 + 12 + 21` → `"111221"`.

## 4. Time and space complexity

Let \\(L_i\\) be the length of the \\(i\\)-th term.

Time complexity:

\\[ O\left(\sum\_{i=1}^{n-1} L_i\right) \\]

Each transformation scans the previous term once and generates the next term. A convenient upper bound is \\(O(nL_n)\\), where \\(L_n\\) is the length of the final term.

Auxiliary space complexity: \\(O(L_n)\\).

We hold the current string and construct the next string. Both are bounded by the size of the generated terms. The output itself is also \\(O(L_n)\\).

Since \\(n \leq 30\\), this iterative solution is efficient for the given constraints.

## 5. Alternative solution — Recursion

We can also define the solution recursively:

- If `n == 1`, return `"1"`.
- Otherwise, calculate `countAndSay(n - 1)`.
- Encode the returned string and return the result.

```

class Solution {

    public String countAndSay(int n) {

        // Base case: first term of the sequence.
        if (n == 1) {
            return "1";
        }

        // Recursively obtain the previous term.
        String previous = countAndSay(n - 1);

        // Encode the previous term using run-length encoding.
        StringBuilder next = new StringBuilder();

        int i = 0;

        while (i < previous.length()) {

            char digit = previous.charAt(i);
            int count = 0;

            // Consume all consecutive occurrences of this character.
            while (i < previous.length()
                    && previous.charAt(i) == digit) {
                count++;
                i++;
            }

            next.append(count).append(digit);
        }

        return next.toString();
    }
}

```

Complexities:

- Time: \\(O(\sum\_{i=1}^{n-1} L_i)\\), where \\(L_i\\) is the length of term \\(i\\).
- Auxiliary space: \\(O(\sum\_{i=1}^{n} L_i)\\) in the worst case, including the recursion stack and strings retained by recursive calls.

Which should you choose? Prefer iteration in interviews. It is easier to trace, avoids recursion overhead, and doesn't retain a stack of previous terms.

## 6. Edge cases to discuss

| Input    | Expected output        | Why?                                     |
| -------- | ---------------------- | ---------------------------------------- |
| `n = 1`  | `"1"`                  | Base case                                |
| `n = 2`  | `"11"`                 | One occurrence of `1`                    |
| `n = 3`  | `"21"`                 | Two occurrences of `1`                   |
| `n = 4`  | `"1211"`               | One `2`, followed by one `1`             |
| `n = 30` | The 30th sequence term | Maximum constraint; iteration handles it |

A subtle point: the output is a string, not an integer. For example, `"111221"` must not be converted to a number because we need to preserve its individual digits and their order.

## 7. Interview follow-up questions

Q1. Why use `StringBuilder` instead of string concatenation?

Repeated concatenation creates intermediate strings because Java strings are immutable. `StringBuilder` efficiently appends each count and character while constructing a term.

Q2. Why do we append the count before the character?

That is the definition of this run-length encoding. Two consecutive `1`s become `"21"`, not `"12"`.

Q3. Why is the inner loop's boundary check necessary?

The condition `i < current.length()` prevents accessing a character beyond the end of the string. It is especially important when a group reaches the final character.

Q4. Can the count contain multiple digits?

Yes. In general, run-length encoding allows counts such as `12` followed by a character. Here, `StringBuilder.append(count)` correctly handles multi-digit counts too.

Q5. Can we solve this using dynamic programming?

The iterative approach already uses the key DP idea: each term depends on the previous term. We optimize memory by retaining only the current term and constructing the next one instead of storing every term.

Q6. What clarifying questions would you ask the interviewer?

- Is `n` guaranteed to be positive? Here, the constraint says yes.
- Should the result be returned as a string? Yes.
- Is there an upper bound on `n`? Yes, `n ≤ 30`, so the iterative solution is sufficient.

## 8. The interview mental model

Remember this pattern:

1. Start: `"1"`.
2. Scan: Find a maximal group of equal consecutive characters.
3. Describe: Append `group length + character`.
4. Repeat: Use the newly generated string for the next term.

This is a useful general pattern for problems involving consecutive groups, string compression, and run-length encoding.
