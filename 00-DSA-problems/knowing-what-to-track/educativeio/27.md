# Find the Celebrity — Java Solution

This is a classic DSA problem that can be solved in \\(O(n)\\) time using at most \\(3n\\) calls to the `knows(a, b)` API.

The key technique is candidate elimination followed by verification. You do not need to examine every cell of the matrix.

## 1. Understand the problem

A celebrity must satisfy two conditions:

1. Everyone knows the celebrity: For every person \\(i \ne c\\), `knows(i, c) == true`.
2. The celebrity knows nobody else: For every person \\(i \ne c\\), `knows(c, i) == false`.

The diagonal is irrelevant because `graph[i][i] == 1`, but a person does not need to know themselves for this problem.

### Example 1: Celebrity exists

Rows represent the person asking; columns represent the person being asked about.

| Person | 0 | 1 | 2 |
| ------ | - | - | - |
| 0      | 1 | 1 | 0 |
| 1      | 0 | 1 | 0 |
| 2      | 1 | 1 | 1 |

Person `2` is the celebrity because persons `0` and `1` know `2`, while `2` knows neither `0` nor `1`.

Output: `2`

## 2. Intuition: Eliminate people who cannot be celebrities

Imagine asking just one question about two people, `a` and `b`:

`knows(a, b)`

There are only two possibilities.

Case 1: `knows(a, b) == true`

Person `a` knows someone else (`b`), so `a` cannot be a celebrity.

Eliminate `a`; keep `b` as the candidate.

Case 2: `knows(a, b) == false`

Person `a` does not know `b`, but a celebrity must be known by everyone. Therefore, `b` cannot be the celebrity.

Eliminate `b`; keep `a` as the candidate.

The important observation is that every API call can eliminate at least one person.

After eliminating candidates until only one remains, that person is a potential celebrity. We must still verify both conditions because elimination alone does not prove that a celebrity exists.

## 3. Optimal approach: Two phases

### Phase 1 — Find a candidate

Start by assuming person `0` is the candidate.

For every other person `i` from `1` to `n - 1`:

- If `knows(candidate, i)` is `true`, eliminate the current candidate and set `candidate = i`.
- Otherwise, keep the current candidate because they do not know `i`.

After this phase, at most one person can still be a celebrity.

### Phase 2 — Verify the candidate

For every person `i` except the candidate, check both conditions:

- `knows(candidate, i)` must be `false`.
- `knows(i, candidate)` must be `true`.

If either condition fails, return `-1`. Otherwise, return the candidate's label.

## 4. Java 24 solution

```
class Solution {

    // The knows(a, b) API is provided by the problem platform.
    // It returns true if person a knows person b.

    public int findCelebrity(int n) {

        // PHASE 1: Find a potential celebrity.
        // Initially, assume person 0 is the celebrity.
        int candidate = 0;

        // Compare the current candidate with every other person.
        for (int person = 1; person < n; person++) {

            // If candidate knows person, candidate cannot be a celebrity.
            // A celebrity must know nobody else.
            if (knows(candidate, person)) {

                // Eliminate the old candidate and select this person.
                candidate = person;
            }

            // Otherwise, the current candidate does not know person.
            // So person cannot be a celebrity: a celebrity must be known
            // by everyone, including the current candidate.
        }

        // PHASE 2: Verify that the remaining candidate is a celebrity.
        for (int person = 0; person < n; person++) {

            // A person does not need to be compared with themselves.
            if (person == candidate) {
                continue;
            }

            // Condition 1: The candidate must know nobody else.
            if (knows(candidate, person)) {
                return -1;
            }

            // Condition 2: Everyone else must know the candidate.
            if (!knows(person, candidate)) {
                return -1;
            }
        }

        // Both conditions hold for every other person.
        return candidate;
    }
}
```

Note: The `knows(a, b)` API is supplied by the platform, so you should not implement it yourself when submitting this solution.

## 5. Dry run

Consider this matrix:

\\[ \begin{bmatrix} 1 & 1 & 0\\\ 0 & 1 & 0\\\ 1 & 1 & 1 \end{bmatrix} \\]

The correct answer is person `2`.

### Phase 1: Candidate elimination

| Step | API call      | Result  | Decision                                        |
| ---- | ------------- | ------- | ----------------------------------------------- |
| 1    | `knows(0, 1)` | `true`  | Person `0` is eliminated; candidate = `1`       |
| 2    | `knows(1, 2)` | `false` | Person `2` is eliminated; candidate remains `1` |

At this point, the candidate is `1`. Notice that this matrix actually has no celebrity: person `1` does not know person `2`, but person `0` knows person `1`, and person `1` is not known by person `2`? Let's verify the matrix: `graph[2][1] = 1`, `graph[0][1] = 1`, and `graph[1][0] = 0`. Person `1` is known by everyone else, and knows neither `0` nor `2`.

Therefore, person `1` is the celebrity, and the output is `1`.

### Phase 2: Verification

| Person checked | Check         | Result           |
| -------------- | ------------- | ---------------- |
| `0`            | `knows(1, 0)` | `false` — valid  |
| `0`            | `knows(0, 1)` | `true` — invalid |

The verification finds a contradiction, so the answer is `-1`.

This illustrates why the candidate phase alone is insufficient.

The verification table above has the check direction reversed in its final row. The correct verification is:

| Person checked | API call      | Result          |
| -------------- | ------------- | --------------- |
| `0`            | `knows(1, 0)` | `false` — valid |
| `0`            | `knows(0, 1)` | `true` — valid  |
| `2`            | `knows(1, 2)` | `false` — valid |
| `2`            | `knows(2, 1)` | `true` — valid  |

All checks pass, so the correct output is `1`.

## 6. Complexity analysis

### Time complexity

- Candidate elimination: \\(n-1\\) API calls.
- Candidate verification: at most \\(2(n-1)\\) API calls.

Therefore, the maximum number of calls is:

\\[ (n-1)+2(n-1)=3n-3 \\]

Hence:

- Time: \\(O(n)\\)
- Auxiliary space: \\(O(1)\\)

This meets the requirement of at most \\(3n\\) `knows` calls.

## 7. Alternative solutions

| Approach                               | Time         | Extra space | API calls          |
| -------------------------------------- | ------------ | ----------- | ------------------ |
| Brute force: test every person         | \\(O(n^2)\\) | \\(O(1)\\)  | \\(O(n^2)\\)       |
| Two-pointer elimination + verification | \\(O(n)\\)   | \\(O(1)\\)  | At most \\(3n-3\\) |
| Stack-based elimination + verification | \\(O(n)\\)   | \\(O(n)\\)  | \\(O(n)\\)         |

The two-pointer elimination method is equivalent in principle to the candidate method shown above, and is also optimal for this problem. The stack approach is unnecessary because the candidate can be maintained using a single integer.

### Brute force: when is it useful?

For every person `c`, check whether everyone else knows `c` and `c` knows nobody else. Return the first person satisfying both conditions.

This is easy to understand but can require \\(O(n^2)\\) API calls, violating the desired call limit.

## 8. Edge cases to discuss in interviews

- No celebrity: The verification phase returns `-1`.
- Celebrity is person `0`: The initial candidate may remain unchanged and pass verification.
- Celebrity is person `n - 1`: The elimination phase can select the final person.
- Only two people: The same algorithm works without special handling.
- Everyone knows everyone: No celebrity exists because each person knows someone else.
- Nobody knows anyone else: No celebrity exists because nobody is known by everyone.

## 9. Interview follow-up questions

Q1. Why do we need a verification phase?

Candidate elimination only guarantees that all eliminated people cannot be celebrities. It does not guarantee that the remaining candidate satisfies both celebrity conditions.

Q2. Why does each comparison eliminate someone?

If `knows(a, b)` is true, `a` cannot be a celebrity. If it is false, `b` cannot be a celebrity because `b` is not known by `a`.

Q3. Can we solve this in \\(O(1)\\) space?

Yes. Only the candidate index and loop variables are needed.

Q4. Why not use the matrix directly?

The matrix representation describes the relationships, but the interview specifically asks you to use the `knows` API. Accessing matrix cells directly may violate that requirement.

Q5. What should you clarify before coding?

- Is `knows(a, b)` guaranteed to be available and consistent?
- Should the function return `-1` when there is no celebrity?
- Does the API-call limit include both elimination and verification?

Interview takeaway: Remember the rule: if `a` knows `b`, eliminate `a`; otherwise, eliminate `b`. Find one candidate in a single pass, verify it in a second pass, and achieve \\(O(n)\\) time with constant extra space.

# 1. Analyze your solution first

Your code calculates:

```
score[c] += knows(c, i) ? 1 : 0;
score[c] -= knows(i, c) ? 1 : 0;
```

For every candidate `c`, you are doing two things:

- Adding `1` when `c` knows someone else.
- Subtracting `1` when someone else knows `c`.

Let's examine what the score really means.

Let:

- \\(out(c)\\) = number of other people known by `c`.
- \\(in(c)\\) = number of other people who know `c`.

Your score is:

\\[ score[c] = out(c) - in(c) \\]

But a celebrity needs:

\\[ out(c)=0,\qquad in(c)=n-1 \\]

Therefore, the celebrity's score is:

\\[ score[c]=0-(n-1)=-(n-1) \\]

There is a bug in your code: you check `score[c] == n - 1`, but your formula gives a celebrity a score of `-(n - 1)`. Even if you change the sign, the score alone is not enough to prove that someone is a celebrity.

For example, with four people, a person might know one person and be known by two others. Their score is \\(1-2=-1\\), but they are not a celebrity. Other combinations can produce the same score.

The underlying issue is that your score combines two independent conditions into one number, losing information.

## What you did well

- You identified that every person can be evaluated using their incoming and outgoing relationships.
- You tried to summarize the relationships rather than storing the entire relationship matrix again.
- You were looking for a condition that could identify the answer.

Those are good instincts. Now let's develop the next step: instead of calculating more information, ask whether you can avoid examining some people entirely.

# 2. The real interview skill: Question your first solution

When you get a problem, don't jump directly from the statement to an algorithm. Go through these questions in order.

## 1

What does the answer really require?

A celebrity must satisfy two conditions: zero outgoing relationships and \\(n-1\\) incoming relationships.

## 2

What is the simplest correct solution?

Test every person. This is your starting point, not a mistake.

## 3

What work am I repeating?

For each possible celebrity, you inspect relationships involving that person. Many of those relationships are being examined repeatedly.

## 4

Can one observation eliminate an entire possibility?

This is the breakthrough. One `knows(a, b)` result tells you that either `a` or `b` cannot possibly be the celebrity.

## 5

Can I separate finding a candidate from proving the answer?

Eliminate impossible candidates in one pass, then verify the sole survivor.

Notice the progression: you don't need to invent the optimal solution out of nowhere. You start with a correct solution and repeatedly ask how to reduce the work.

# 3. How to derive the celebrity algorithm yourself

Let's pretend you're in an interview and you haven't seen this problem before.

## Step 1: Start with the brute-force idea

Your initial thought could be:

"For every person, I'll check whether everyone knows them and whether they know nobody."

That's correct.

```
// Conceptual brute-force structure
for (int candidate = 0; candidate < n; candidate++) {
    // Check all other people against this candidate.
    // If every celebrity condition holds, return candidate.
}
```

The problem is that this might take \\(O(n^2)\\) API calls.

Now ask yourself:

Do I really need to check every person as a possible celebrity?

## Step 2: Look at one relationship instead of the entire matrix

Suppose there are two people, `A` and `B`.

Ask:

```
knows(A, B)
```

Now reason through both outcomes.

### Outcome A: A knows B

A

Knows B

B

Known by A

A cannot be a celebrity because A knows someone else.

Therefore, eliminate A.

### Outcome B: A does not know B

A

Doesn't know B

B

Not known by A

B cannot be a celebrity because a celebrity must be known by everyone, including A.

Therefore, eliminate B.

Here's the question I want you to train yourself to ask:

> Can I prove that one of these two people is definitely not the answer, without knowing anything about the other relationships?

In this problem, the answer is yes.

That is the key insight.

## Step 3: Turn elimination into an algorithm

Imagine the following sequence:

- Start with person `0` as your candidate.
- Compare the candidate with person `1`.
- Eliminate whichever person cannot be the celebrity.
- Compare the surviving candidate with person `2`.
- Continue until every person has been considered.

At every step, you maintain one invariant:

The actual celebrity, if one exists, has not been eliminated.

After \\(n-1\\) comparisons, only one candidate remains.

## Step 4: Ask what could still go wrong

You have one candidate, but are they definitely a celebrity?

No.

The candidate might still know someone else, or someone might not know the candidate. The elimination process doesn't check every required relationship for the survivor.

So you verify the candidate in a second pass.

This is a common algorithm-design pattern:

Eliminate impossible answers → verify the remaining candidate.

It appears in several problems involving majorities, judges, sinks in graphs, and candidate selection.

# 4. Why your score-based approach feels natural, but elimination is better

Your instinct was to aggregate information. That is often useful, but here the question is whether you need to calculate that information at all.

Compare the two approaches:

| Your approach               | Candidate elimination                      |
| --------------------------- | ------------------------------------------ |
| Evaluate every person       | Keep only one candidate                    |
| Collect relationship scores | Use each relationship to eliminate someone |
| Revisit many relationships  | Each elimination uses one API call         |
| \\(O(n^2)\\) API calls      | At most \\(3n-3\\) API calls               |
| \\(O(n)\\) auxiliary space  | \\(O(1)\\) auxiliary space                 |

There is also a valid degree-based solution when the entire matrix is directly accessible: count incoming and outgoing relationships, then check both counts. That is useful for learning, but the API-call limit makes elimination preferable here.

A useful distinction: aggregation answers "how many relationships does this person have?" Elimination answers "can this person possibly be the answer?" The second question is more powerful when one observation can rule out a candidate completely.

# 5. Your interview thought process, word for word

In an interview, you could explain your reasoning like this:

I'll start with a brute-force solution that checks each person against everyone else, which takes O(n²) time.

However, the celebrity conditions give me an opportunity to eliminate candidates.

If person A knows person B, A cannot be a celebrity. If A doesn't know B, B cannot be a celebrity because the celebrity must be known by everyone.

Therefore, each API call eliminates at least one candidate. I can find a potential celebrity in one pass and then verify that the candidate knows nobody else and is known by everybody else.

This reduces the algorithm to O(n) time, O(1) auxiliary space, and at most 3n − 3 API calls.

You don't need to explain everything you considered. Explain the brute-force baseline, the observation that eliminates candidates, and why verification is necessary.
