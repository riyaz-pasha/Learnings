# Tic-Tac-Toe — Board-Based Solution

## 1. Idea and intuition

We have an `n × n` board. Two players place marks, represented by `1` and `2`. After each move, we must determine whether the current player has completed an entire row, column, or diagonal.

**The simplest idea:** Store the complete board and check whether the current player has won after every move.

We need three methods:

1. `isValid(row, col)` — checks whether the cell is inside the board and empty.
2. `move(row, col, player)` — validates the move, places the mark, and checks for a winner.
3. `didWin(player)` — checks every row, column, and both diagonals.

## 2. Complete Java implementation

Save this as `TicTacToe.java`.

```java
import java.util.*;

class TicTacToe {

    /*
     * IDEA:
     * Store the complete board so that we can inspect any cell
     * when checking whether a player has won.
     *
     * board[row][col] == 0  -> empty cell
     * board[row][col] == 1  -> player 1's mark
     * board[row][col] == 2  -> player 2's mark
     *
     * TRADE-OFF:
     * This makes the solution easy to understand, but checking
     * the complete board after every move takes O(n^2) time.
     */
    private final int[][] board;

    // Board dimension: n rows and n columns.
    private final int n;

    /*
     * Constructor:
     * Java initializes every int in the board to 0 automatically,
     * so initially every cell is empty.
     *
     * Time:  O(n^2) — initializes n * n cells.
     * Space: O(n^2) — stores the board.
     */
    public TicTacToe(int n) {
        this.board = new int[n][n];
        this.n = n;
    }

    /*
     * Plays one move for the specified player.
     *
     * Steps:
     * 1. Verify that the cell is inside the board and is empty.
     * 2. Place the player's mark in that cell.
     * 3. Check whether this player has completed a winning line.
     * 4. Return the player's ID if they won; otherwise return 0.
     *
     * Returns -1 for an invalid move. The original problem
     * guarantees valid moves, so this check is optional.
     *
     * Time:  O(n^2) because didWin() scans the board.
     * Space: O(1) additional space for this method.
     */
    public int move(int row, int col, int player) {

        // Do not place a mark outside the board or in an occupied cell.
        if (!this.isValid(row, col)) {
            return -1;
        }

        // Record the move so didWin() can inspect the updated board.
        this.board[row][col] = player;

        // Check whether the current player has completed any winning line.
        if (this.didWin(player)) {
            return player;
        }

        // The current move did not produce a winner.
        return 0;
    }

    /*
     * Checks whether the specified player has filled:
     * - Any complete row
     * - Any complete column
     * - The main diagonal
     * - The anti-diagonal
     *
     * IMPORTANT:
     * We check every possible winning line, not just the row
     * and column of the latest move. This is correct, but performs
     * unnecessary work because only lines containing the latest
     * move could have changed.
     *
     * Time:  O(n^2) — rows and columns take O(n^2) total;
     *        both diagonals together take O(n).
     * Space: O(1) — uses only a boolean variable and loop counters.
     */
    private boolean didWin(int player) {

        /*
         * STEP 1: Check every row.
         *
         * For each row r, assume the player has won that row.
         * If even one cell does not contain the player's mark,
         * that row is not a winning row.
         */
        for (int r = 0; r < this.n; r++) {

            boolean didMatch = true;

            for (int c = 0; c < this.n; c++) {

                // One cell differs, so this entire row is not a win.
                if (this.board[r][c] != player) {
                    didMatch = false;
                    break; // No need to inspect the remaining cells.
                }
            }

            // Every cell in row r contains the current player's mark.
            if (didMatch) {
                return true;
            }
        }

        /*
         * STEP 2: Check every column.
         *
         * Fix a column c and inspect all its rows.
         * If all n cells contain the current player's mark,
         * that column is a winning column.
         */
        for (int c = 0; c < this.n; c++) {

            boolean didMatch = true;

            for (int r = 0; r < this.n; r++) {

                if (this.board[r][c] != player) {
                    didMatch = false;
                    break;
                }
            }

            if (didMatch) {
                return true;
            }
        }

        /*
         * STEP 3: Check the main diagonal.
         *
         * Its cells have coordinates:
         * (0,0), (1,1), (2,2), ..., (n-1,n-1).
         *
         * In every cell, row == column.
         */
        boolean didMatch = true;

        for (int d1 = 0; d1 < this.n; d1++) {

            if (this.board[d1][d1] != player) {
                didMatch = false;
                break;
            }
        }

        if (didMatch) {
            return true;
        }

        /*
         * STEP 4: Check the anti-diagonal.
         *
         * Its cells have coordinates:
         * (0,n-1), (1,n-2), ..., (n-1,0).
         *
         * The column is n - 1 - row.
         */
        didMatch = true;

        for (int d1 = 0; d1 < this.n; d1++) {

            if (this.board[d1][this.n - 1 - d1] != player) {
                didMatch = false;
                break;
            }
        }

        if (didMatch) {
            return true;
        }

        // None of the possible winning lines was completed.
        return false;
    }

    /*
     * Checks whether a move can be placed at (row, col).
     *
     * A valid cell must:
     * 1. Have a non-negative row and column.
     * 2. Have row and column strictly less than n.
     * 3. Currently contain 0, meaning the cell is empty.
     *
     * Time:  O(1)
     * Space: O(1)
     */
    private boolean isValid(int row, int col) {

        if (row < 0
                || col < 0
                || row >= this.n
                || col >= this.n
                || this.board[row][col] != 0) {

            return false;
        }

        return true;
    }
}
```

## 3. Example walkthrough

Consider a board of size `3 × 3`.

The players make these moves:

| Move | Player | Position | Return value |
|---|---|---|---|
| 1 | 1 | `(0, 0)` | `0` |
| 2 | 2 | `(1, 0)` | `0` |
| 3 | 1 | `(0, 1)` | `0` |
| 4 | 2 | `(1, 1)` | `0` |
| 5 | 1 | `(0, 2)` | `1` |

After move 5, the board looks like this:

```text
  0 1 2
0 X X X
1 O O .
2 . . .
```

Player 1 has filled row 0.

When `didWin(1)` checks row 0:

- `board[0][0] == 1` — match.
- `board[0][1] == 1` — match.
- `board[0][2] == 1` — match.

The inner loop finishes without setting `didMatch` to `false`. Therefore, `didWin(1)` returns `true`, and `move(0, 2, 1)` returns `1`.

## 4. Why is this solution inefficient?

The problem is not correctness. The problem is repeated work.

Suppose `n = 9`. After each move, your implementation potentially examines:

- 81 cells across all rows.
- 81 cells across all columns.
- 18 cells across the two diagonals.

That is up to 180 cell checks in a single call to `didWin()`, although early exits may reduce the actual number.

Now consider placing a mark at `(0, 0)`. This move cannot change row 8 or column 8, yet your implementation checks those lines anyway.

**The central optimization insight:** A move affects at most four winning lines. We should update or inspect only those lines instead of scanning all possible lines.

### Complexity summary

Let `n` be the board dimension.

| Operation | Time | Extra space |
|---|---:|---:|
| Constructor | O(n²) | O(n²) for the board |
| `isValid()` | O(1) | O(1) |
| `didWin()` | O(n²) | O(1) |
| `move()` | O(n²) | O(1) additional space |
| All n² moves | O(n⁴) | O(n²) for the board |

## 5. What is the optimal alternative?

Instead of storing every cell, maintain:

- `int[] rows` — progress in each row.
- `int[] cols` — progress in each column.
- `int diagonal` — progress in the main diagonal.
- `int antiDiagonal` — progress in the anti-diagonal.

Encode player 1 as `+1` and player 2 as `-1`. When a counter reaches `+n` or `-n`, that line is complete.

The optimized solution takes **O(1) time per move and O(n) space**. It is more efficient because each move updates a fixed number of counters without scanning the board.

## 6. Interview strategy

A good way to present this problem is:

1. Start with the complete-board simulation and explain why it is correct.
2. Analyze the cost: O(n²) per move.
3. Notice that only the row, column, and applicable diagonals containing the new mark can change.
4. Maintain counters incrementally and reach O(1) per move.

This progression demonstrates that you can produce a correct baseline solution and then improve it by eliminating unnecessary repeated work.

# Tic-Tac-Toe — Optimized Java Solution

## 1. Problem recap

We need to implement a `TicTacToe` class for an `n × n` board with two players.

- Player `1` places marks represented by `1`.
- Player `2` places marks represented by `2`.
- A player wins by completing any row, column, or diagonal.
- `move(row, col, player)` returns the winner's ID if the move wins; otherwise, it returns `0`.

The original board-based approach stores every cell and scans all rows, columns, and diagonals after every move.

That approach works, but we can do better.

## 2. Intuition: Avoid checking the entire board

Imagine a `3 × 3` board and player 1 places a mark at `(0, 1)`.

Which winning lines could this move possibly complete?

1. Row `0`.
2. Column `1`.
3. The main diagonal, if `row == col`.
4. The anti-diagonal, if `row + col == n - 1`.

All other rows, columns, and diagonals remain unchanged.

**Key insight:** We don't need to remember the complete board to determine whether a player wins. We only need to remember how close each row, column, and diagonal is to being completed.

We can maintain counters for these lines and update only the counters affected by each move.

## 3. The clever trick: Use signed counters

We could maintain separate counters for each player, but that would require more state.

Instead, encode the players using opposite signs:

- Player 1 contributes `+1`.
- Player 2 contributes `-1`.

For each row, column, and diagonal, maintain the sum of the marks contributed by its cells.

For a board of size `3`:

| Line contents | Counter | Meaning |
|---|---:|---|
| `X X X` | `+3` | Player 1 wins |
| `O O O` | `-3` | Player 2 wins |
| `X X O` | `+1` | No win |
| `X O O` | `-1` | No win |
| `X O X` | `+1` | No win |

Here, `X` represents player 1 and `O` represents player 2.

A line contains exactly `n` cells. Therefore, its counter reaches `+n` only when every cell belongs to player 1, or `-n` only when every cell belongs to player 2.

So our winning condition becomes:

```java
Math.abs(counter) == n
```

This eliminates the need to inspect individual cells.

## 4. Complete Java implementation

Save this as `TicTacToe.java`.

```java
class TicTacToe {

    /*
     * PROBLEM:
     * We must determine whether each move completes a row,
     * column, or diagonal without repeatedly scanning the board.
     *
     * OPTIMIZATION:
     * Instead of storing every board cell, store one counter
     * for each row and column, plus two diagonal counters.
     *
     * Player 1 contributes +1.
     * Player 2 contributes -1.
     *
     * If any relevant counter reaches +n or -n,
     * the current player has completed that line.
     */

    private final int n;

    /*
     * rows[r] = sum of the contributions of all marks
     * placed in row r.
     *
     * Example for n = 3:
     * rows[0] == 2 means player 1 has a net contribution of +2.
     * rows[0] == -2 means player 2 has a net contribution of -2.
     *
     * A value of +3 or -3 means the row is complete.
     */
    private final int[] rows;

    /*
     * cols[c] = sum of the contributions of all marks
     * placed in column c.
     *
     * A value of +n or -n means the column is complete.
     */
    private final int[] cols;

    /*
     * Main diagonal:
     * (0,0), (1,1), (2,2), ..., (n-1,n-1).
     *
     * A cell belongs to this diagonal when row == col.
     */
    private int diagonal;

    /*
     * Anti-diagonal:
     * (0,n-1), (1,n-2), ..., (n-1,0).
     *
     * A cell belongs to this diagonal when row + col == n - 1.
     */
    private int antiDiagonal;

    /*
     * Constructor
     *
     * We don't need an n x n board.
     * We only need n row counters and n column counters.
     *
     * Java initializes all int array elements and int fields to 0.
     *
     * Time:  O(n)
     * Space: O(n)
     */
    public TicTacToe(int n) {
        this.n = n;
        this.rows = new int[n];
        this.cols = new int[n];
    }

    /*
     * Plays one move and returns:
     * - player, if the current player wins.
     * - 0, otherwise.
     *
     * ASSUMPTION:
     * The problem guarantees that every move is valid and
     * that no moves occur after a winning condition is reached.
     *
     * Time:  O(1)
     * Space: O(1) additional space per call.
     */
    public int move(int row, int col, int player) {

        /*
         * STEP 1: Convert the player ID to a signed contribution.
         *
         * Player 1 -> +1
         * Player 2 -> -1
         *
         * This lets us detect either player's completed line
         * using the absolute value of a single counter.
         */
        int value = (player == 1) ? 1 : -1;

        /*
         * STEP 2: Update the affected row and column.
         *
         * The move at (row, col) changes exactly:
         * - row 'row'
         * - column 'col'
         *
         * No other row or column needs to be updated.
         */
        rows[row] += value;
        cols[col] += value;

        /*
         * STEP 3: Update the main diagonal only when applicable.
         *
         * Example:
         * (1,1) belongs to the main diagonal.
         * (1,2) does not.
         */
        if (row == col) {
            diagonal += value;
        }

        /*
         * STEP 4: Update the anti-diagonal only when applicable.
         *
         * For n = 3:
         * (0,2), (1,1), (2,0) belong to this diagonal.
         */
        if (row + col == n - 1) {
            antiDiagonal += value;
        }

        /*
         * STEP 5: Check whether any affected line is complete.
         *
         * We check:
         * - The current row.
         * - The current column.
         * - The main diagonal counter.
         * - The anti-diagonal counter.
         *
         * Why use Math.abs()?
         * +n means player 1 filled the line.
         * -n means player 2 filled the line.
         *
         * Since only the current player's contribution was added,
         * reaching either boundary identifies the current winner.
         */
        if (Math.abs(rows[row]) == n
                || Math.abs(cols[col]) == n
                || Math.abs(diagonal) == n
                || Math.abs(antiDiagonal) == n) {

            return player;
        }

        /*
         * None of the affected lines reached +n or -n.
         * Therefore, this move did not produce a winner.
         */
        return 0;
    }
}
```

## 5. Detailed dry run

Consider a board of size `3 × 3`.

We will make the following moves:

| Move | Player | Position |
|---|---|---|
| 1 | 1 | `(0, 0)` |
| 2 | 2 | `(1, 0)` |
| 3 | 1 | `(0, 1)` |
| 4 | 2 | `(1, 1)` |
| 5 | 1 | `(0, 2)` |

Our initial state is:

```text
rows        = [0, 0, 0]
cols        = [0, 0, 0]
diagonal    = 0
antiDiagonal = 0
```

### Move 1: Player 1 at `(0, 0)`

Player 1 contributes `+1`.

- `rows[0] += 1`
- `cols[0] += 1`
- `row == col`, so update the main diagonal.
- `row + col != n - 1`, so the anti-diagonal is unchanged.

State:

```text
rows         = [1, 0, 0]
cols         = [1, 0, 0]
diagonal     = 1
antiDiagonal = 0
```

No counter has an absolute value of `3`. Return `0`.

### Move 2: Player 2 at `(1, 0)`

Player 2 contributes `-1`.

- `rows[1] -= 1`
- `cols[0] -= 1`
- Neither diagonal contains `(1, 0)`.

State:

```text
rows         = [1, -1, 0]
cols         = [0, 0, 0]
diagonal     = 1
antiDiagonal = 0
```

No winning counter exists. Return `0`.

Notice that column 0 now has counter `0`. Player 1's `+1` and player 2's `-1` cancel each other out.

### Move 3: Player 1 at `(0, 1)`

Player 1 contributes `+1`.

- `rows[0] += 1`
- `cols[1] += 1`
- Neither diagonal contains `(0, 1)`.

State:

```text
rows         = [2, -1, 0]
cols         = [0, 1, 0]
diagonal     = 1
antiDiagonal = 0
```

Row 0 has counter `2`. Since `2 != 3`, player 1 has not won. Return `0`.

### Move 4: Player 2 at `(1, 1)`

Player 2 contributes `-1`.

- `rows[1] -= 1`
- `cols[1] -= 1`
- `row == col`, so decrement the main diagonal.
- `row + col == 2`, so decrement the anti-diagonal.

State:

```text
rows         = [2, -2, 0]
cols         = [0, 0, 0]
diagonal     = 0
antiDiagonal = -1
```

No counter has an absolute value of `3`. Return `0`.

### Move 5: Player 1 at `(0, 2)`

Player 1 contributes `+1`.

- `rows[0] += 1`
- `cols[2] += 1`
- The cell belongs to the anti-diagonal because `0 + 2 == 3 - 1`.
- It does not belong to the main diagonal.

Updated state:

```text
rows         = [3, -2, 0]
cols         = [0, 0, 1]
diagonal     = 0
antiDiagonal = 0
```

Now:

```java
Math.abs(rows[0]) == 3
```

This condition is true. The entire first row belongs to player 1, so `move(0, 2, 1)` returns `1`.

## 6. Why does the signed-counter technique work?

The mathematical invariant is:

**For any line, its counter equals the number of player 1 marks minus the number of player 2 marks in that line.**

For a line containing `n` cells, let:

- `x` = number of player 1 marks.
- `y` = number of player 2 marks.
- `e` = number of empty cells.

Then:

`x + y + e = n`

The line's counter is:

`counter = x - y`

If the counter equals `+n`, then:

`x - y = n`

Because `x` cannot exceed `n`, this is possible only when `x = n` and `y = 0`.

Similarly, if the counter equals `-n`, then every cell belongs to player 2.

Therefore:

```java
Math.abs(counter) == n
```

is sufficient to detect a winning line.

## 7. Why is the optimized solution better?

The original solution stores the board and checks every row and column after every move.

The optimized solution maintains the information needed to determine whether a line is complete.

| Metric | Board-based solution | Counter-based solution |
|---|---:|---:|
| Constructor time | O(n²) | O(n) |
| Time per move | O(n²) | **O(1)** |
| Space | O(n²) | **O(n)** |
| Total time for n² moves | O(n⁴) | **O(n²)** |

### Why the improvement matters

For `n = 9`, your original solution checks up to 81 cells across all rows and another 81 across all columns, plus up to 18 diagonal cells, in a full `didWin()` scan.

The optimized solution performs a constant number of counter updates and comparisons per move, regardless of board size.

The counter approach also eliminates the need to store the entire board, reducing space from O(n²) to O(n).

## 8. Important implementation details

### Why do we check `row == col`?

The main diagonal contains cells where the row index and column index are equal:

```text
(0,0)  .  .
  .   (1,1) .
  .    .   (2,2)
```

A move updates the main diagonal counter only when it lies on this diagonal.

### Why do we check `row + col == n - 1`?

The anti-diagonal runs from the top-right corner to the bottom-left corner.

For a `3 × 3` board:

```text
.  .  (0,2)
. (1,1) .
(2,0) .  .
```

The row and column indices of every cell on this diagonal add up to `n - 1`.

### Why don't we store the board?

The problem guarantees that every move is valid and uses a unique cell, and the only required output is whether the current move wins.

We do not need to reconstruct the board or inspect individual cells. The counters retain exactly the information required to answer the question.

If we needed to display the board, validate occupied cells ourselves, undo moves, or support arbitrary board queries, retaining the board could still be useful.

## 9. Final interview summary

The most important part of this problem is not the code; it is the observation that avoids repeated work.

1. **Brute force:** Store the board and scan all winning lines after each move — O(n²) per move.
2. **Observe:** Only the row, column, and applicable diagonals containing the latest move can change.
3. **Maintain state:** Keep row, column, and diagonal counters.
4. **Use signed values:** Player 1 contributes `+1`; player 2 contributes `-1`.
5. **Detect a win:** If any relevant counter reaches an absolute value of `n`, return the current player's ID.

The final result is **O(1) time per move and O(n) space**, compared with O(n²) time per move and O(n²) space for the board-based approach.

This is a useful general problem-solving pattern: instead of recomputing an answer from all the data after every operation, maintain a compact summary that can be updated incrementally.
