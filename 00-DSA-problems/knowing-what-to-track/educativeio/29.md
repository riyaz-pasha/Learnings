# Shortest Unsorted Continuous Subarray — Java 24

This is a classic array problem that can be solved in \\(O(n)\\) time and \\(O(1)\\) extra space without sorting the array.

The key observation is that we don't need to sort the array ourselves. We only need to identify the smallest contiguous section that is preventing the entire array from being sorted.

## 1. Example

Consider:

```
nums = [2, 6, 4, 8, 10, 9, 15]
```

The array is not sorted because `6 > 4` and `10 > 9`.

## 2. Approach 1: Sort a copy — easiest to understand

The simplest idea is to compare the original array with a sorted copy.

1. Clone the array.
2. Sort the clone.
3. Find the first index where the arrays differ.
4. Find the last index where the arrays differ.
5. Return the distance between those indices, inclusive.

If both arrays are identical, the original array was already sorted, so return `0`.

### Java 24 code

```

import java.util.Arrays;

class Solution {
    public int findUnsortedSubarray(int[] nums) {
        int n = nums.length;

        // Preserve the original array so we can compare it with
        // the completely sorted version.
        int[] sorted = nums.clone();

        // This takes O(n log n) time.
        Arrays.sort(sorted);

        // Find the first position where sorting changes the value.
        int left = 0;
        while (left < n && nums[left] == sorted[left]) {
            left++;
        }

        // No differences means the original array is already sorted.
        if (left == n) {
            return 0;
        }

        // Find the last position where sorting changes the value.
        int right = n - 1;
        while (right >= 0 && nums[right] == sorted[right]) {
            right--;
        }

        // Both endpoints are inclusive.
        return right - left + 1;
    }
}

```

Complexity

- Time: \\(O(n\log n)\\), dominated by sorting.
- Space: \\(O(n)\\), for the cloned array.

This is a good starting point because it gives us a reference for what the correctly sorted array should look like. But the follow-up asks us to do better.

## 3. Approach 2: One-pass boundary detection — optimal

We can solve this in linear time by tracking two things:

- The left boundary: how far from the left the unsorted section begins.
- The right boundary: how far from the right the unsorted section ends.

The trick is to scan the array twice, using two different running values.

### Pass 1: Find the right boundary

Scan from left to right while maintaining the maximum value seen so far.

If the current value is smaller than that maximum, it is out of order and must be included in the subarray.

For example:

```
nums = [2, 6, 4, 8, 10, 9, 15]

Value:       2   6   4   8   10   9   15
Max so far:  2   6   6   8   10  10   15
                  ^   ^
                  |   +-- 4 < 6: update right boundary
                  +------ maximum becomes 6
```

More precisely, when we reach `4`, the maximum seen so far is `6`. Since `4 < 6`, the element at index `2` is out of order. Later, when we reach `9`, the maximum is `10`; since `9 < 10`, the right boundary extends to index `5`.

So the right boundary is `5`.

### Pass 2: Find the left boundary

Now scan from right to left while maintaining the minimum value seen so far.

If the current value is greater than that minimum, it is out of order and must be included.

For the same example:

```
nums = [2, 6, 4, 8, 10, 9, 15]

Scan from right to left:

15 -> minimum = 15
 9 -> minimum = 9
10 -> 10 > 9, so left boundary = index 4
 8 -> minimum = 8
 4 -> minimum = 4
 6 -> 6 > 4, so left boundary = index 1
 2 -> minimum = 2
```

The left boundary is `1`, and the right boundary is `5`.

Therefore:

\\[ \text{length}=5-1+1=\boxed{5} \\]

### Optimal Java 24 code

```

class Solution {
    public int findUnsortedSubarray(int[] nums) {
        int n = nums.length;

        // PASS 1: Scan from left to right.
        // maxSoFar represents the largest value encountered so far.
        int maxSoFar = nums[0];

        // right records the last index that is out of order.
        // -1 means we have not found any disorder yet.
        int right = -1;

        for (int i = 1; i < n; i++) {

            if (nums[i] < maxSoFar) {
                // The current value is smaller than an earlier value.
                // Therefore, this position must be inside the subarray
                // that needs sorting.
                right = i;
            } else {
                // Maintain the maximum value seen so far.
                maxSoFar = nums[i];
            }
        }

        // If no element was smaller than a previous maximum,
        // the entire array is already sorted.
        if (right == -1) {
            return 0;
        }

        // PASS 2: Scan from right to left.
        // minSoFar represents the smallest value encountered so far.
        int minSoFar = nums[n - 1];

        // left records the first index that is out of order.
        int left = 0;

        for (int i = n - 2; i >= 0; i--) {

            if (nums[i] > minSoFar) {
                // The current value is greater than a later value.
                // It must be included in the subarray to be sorted.
                left = i;
            } else {
                // Maintain the minimum value seen so far.
                minSoFar = nums[i];
            }
        }

        // Both boundaries are inclusive.
        return right - left + 1;
    }
}

```

Complexity analysis

| Metric             | Complexity                        |
| ------------------ | --------------------------------- |
| Time               | \\(O(n)\\) — two linear scans     |
| Auxiliary space    | \\(O(1)\\) — only a few variables |
| Array modification | None                              |

This is the optimal solution for the follow-up: linear time and constant extra space.

## 4. Dry run of the optimal solution

Input:

```
nums = [2, 6, 4, 8, 10, 9, 15]
```

### First pass: Left to right

| Index | Value | `maxSoFar` before comparison | Condition  | `right` |
| ----- | ----- | ---------------------------- | ---------- | ------- |
| 0     | 2     | Initialize to 2              | —          | -1      |
| 1     | 6     | 2                            | `6 >= 2`   | -1      |
| 2     | 4     | 6                            | `4 < 6`    | 2       |
| 3     | 8     | 6                            | `8 >= 6`   | 2       |
| 4     | 10    | 8                            | `10 >= 8`  | 2       |
| 5     | 9     | 10                           | `9 < 10`   | 5       |
| 6     | 15    | 10                           | `15 >= 10` | 5       |

At the end, `right = 5`.

Notice that we do not update `maxSoFar` when the current value is smaller. We need to remember the earlier maximum that the current value violates.

### Second pass: Right to left

| Index | Value | `minSoFar` before comparison | Condition | `left` |
| ----- | ----- | ---------------------------- | --------- | ------ |
| 6     | 15    | Initialize to 15             | —         | 0      |
| 5     | 9     | 15                           | `9 <= 15` | 0      |
| 4     | 10    | 9                            | `10 > 9`  | 4      |
| 3     | 8     | 9                            | `8 <= 9`  | 4      |

| 1     | 6     | 4                            | `6 > 4`   | 1      |
| 0     | 2     | 4                            | `2 <= 4`  | 1      |

At the end, `left = 1`.

The final calculation is:

\\[ 5-1+1=\boxed{5} \\]

The required subarray is `[6, 4, 8, 10, 9]`.

## 5. How to derive this solution in an interview

The most important insight is to ask: What makes an element belong to the unsorted subarray?

There are two complementary situations.

Moving left to right

If an element is smaller than the maximum seen earlier, it violates the sorted order. Record its index as the new right boundary.

Moving right to left

If an element is greater than the minimum seen later, it violates the sorted order. Record its index as the new left boundary.

Why do these two scans find the minimum required range?

- Any element violating the order must be included.
- Extending the range to the last left-to-right violation and the first right-to-left violation captures all displaced elements.
- Everything outside the resulting interval already fits the required sorted order and can remain untouched.

### A second example: Why boundaries must extend

Consider:

```
nums = [1, 3, 5, 4, 2, 6, 7]
```

The obvious inversion is `5 > 4`, but sorting just `[5, 4]` is not enough:

```
[1, 3, 4, 5, 2, 6, 7]  // Still unsorted!
```

The value `2` belongs before `3`, so the subarray must extend from index `1` through index `4`:

```
Original: [1, 3, 5, 4, 2, 6, 7]
                    ^^^^^^^^^^^
Required range:     [3, 5, 4, 2]
After sorting: [1, 2, 3, 4, 5, 6, 7]
Answer: 4
```

This is exactly why identifying just the first and last adjacent inversion is insufficient. We must track the running maximum and minimum.

## 6. Edge cases to remember

| Input                   | Expected output | Reason                               |
| ----------------------- | --------------- | ------------------------------------ |
| `[1]`                   | `0`             | Single element is sorted             |
| `[1, 2, 3, 4]`          | `0`             | Already sorted                       |
| `[4, 3, 2, 1]`          | `4`             | Entire array must be sorted          |
| `[1, 3, 2, 4, 5]`       | `2`             | Only `[3, 2]` needs sorting          |
| `[1, 2, 2, 2, 3]`       | `0`             | Equal elements are allowed           |
| `[2, 1]`                | `2`             | Both elements are out of order       |
| `[1, 3, 5, 4, 2, 6, 7]` | `4`             | The range must extend to include `2` |

The algorithm correctly handles duplicates because it uses strict comparisons (`<` and `>`). Equal values do not violate nondecreasing order.

## 7. Other solutions and their trade-offs

| Approach                                            | Time                                           | Extra space                                           | When to use                           |
| --------------------------------------------------- | ---------------------------------------------- | ----------------------------------------------------- | ------------------------------------- |
| Brute force: try every subarray and test the result | \\(O(n^3)\\) or better with incremental checks | \\(O(n)\\) or \\(O(1)\\), depending on implementation | Learning the problem                  |
| Sort a copy and compare                             | \\(O(n\log n)\\)                               | \\(O(n)\\)                                            | Simplest reliable solution            |
| Monotonic stack                                     | \\(O(n)\\)                                     | \\(O(n)\\)                                            | When stack-based reasoning is desired |
| Running maximum and minimum                         | \\(O(n)\\)                                     | \\(O(1)\\)                                            | Best interview solution               |

The monotonic-stack approach also works in linear time. One stack pass finds the left boundary, and another finds the right boundary. However, it requires extra space, so the running maximum/minimum method is preferable here.

## 8. Interview follow-up questions

Q1. Why can't we just find the first and last adjacent inversions?

Because an element farther away can also be displaced. In `[1, 3, 5, 4, 2, 6, 7]`, the inversion `5 > 4` is not enough; the subarray must extend left to index `1` to include `3`.

Q2. Why does the left-to-right scan find the right boundary?

If `nums[i] < maxSoFar`, some earlier element is larger than `nums[i]`. That element cannot remain before `nums[i]` in the final sorted array. Therefore, `i` must be included in the sorting range.

Q3. Why does the right-to-left scan find the left boundary?

If `nums[i] > minSoFar`, some later element is smaller than `nums[i]`. Therefore, `nums[i]` cannot remain at its current position and must be included.

Q4. Can the algorithm modify the original array?

No. It only reads the array and tracks a few integer variables.

Q5. What if the array contains negative numbers or duplicates?

The algorithm works without modification. It relies on relative ordering, not on the actual numeric range, and equal values are handled correctly.

Q6. Can this be done in one pass?

The standard maximum/minimum solution uses two directional scans. A single traversal can sometimes maintain more elaborate state, but the two-pass method is simpler to reason about, remains \\(O(n)\\), and is the preferred interview solution.

## Final interview takeaway

Remember this pattern:

- Left to right: a value smaller than the running maximum means the right boundary must extend.
- Right to left: a value greater than the running minimum means the left boundary must extend.
- If the first pass finds no violation, return `0`.
- Otherwise, return `right - left + 1`.

The essential insight is that we are not sorting the array. We are identifying the smallest range containing every element that violates the final sorted order.

## 1. Why do we need two passes in the first place?

Consider:

```
nums = [2, 6, 4, 8, 10, 9, 15]
```

We need to find two independent things:

- The right boundary: the last index that must be included.
- The left boundary: the first index that must be included.

These boundaries are discovered using different information.

### Finding the right boundary

We need to know whether the current element is smaller than something before it.

Example: `4` at index `2` is smaller than the earlier `6`.

This naturally suggests scanning left to right while tracking the maximum so far.

### Finding the left boundary

We need to know whether the current element is greater than something after it.

Example: `10` at index `4` is greater than the later `9`.

This naturally suggests scanning right to left while tracking the minimum so far.

The two passes work because each scan needs information from the opposite side of the current element.

## 2. What if we reverse the directions?

Let's test your idea.

### A. Find the right boundary by scanning right to left

Suppose we track the minimum value seen so far.

```
nums = [2, 6, 4, 8, 10, 9, 15]
```

Scanning from the right:

- See `15`: minimum is `15`.
- See `9`: minimum becomes `9`.
- See `10`: `10 > 9`, so index `4` is out of order.
- Continue scanning.

This detects that `10` is out of order, but it does not directly tell us the rightmost element that must be included.

In fact, when scanning right to left, the condition `nums[i] > minSoFar` identifies elements that contribute to the left boundary, not the right boundary.

### B. Find the left boundary by scanning left to right

Similarly, scanning left to right while tracking the maximum detects elements that are too small relative to earlier elements.

That condition identifies the right boundary, not the left boundary.

So simply swapping the directions while keeping the same logic swaps the roles of the boundaries.

## 3. Can we find both boundaries using your preferred directions?

Yes. We can reverse the order of the two passes, but the useful information remains the same:

- To find the left boundary, scan from right to left and track the minimum.
- To find the right boundary, scan from left to right and track the maximum.

The order in which we perform the passes does not matter. What matters is the direction of the information we need.

Here's the correct mapping:

| Scan direction | Track          | Violation condition  | Boundary found |
| -------------- | -------------- | -------------------- | -------------- |
| Left to right  | Maximum so far | `nums[i] < maxSoFar` | Right boundary |
| Right to left  | Minimum so far | `nums[i] > minSoFar` | Left boundary  |

## 4. The deeper reason: what information is available?

Imagine you're standing at index `i`.

When scanning left to right, you know everything about the prefix `nums[0..i]`, but you don't yet know what comes after `i`. You can determine whether the current value is too small relative to earlier values.

When scanning right to left, you know everything about the suffix `nums[i..n-1]`, but you don't yet know what came before `i`. You can determine whether the current value is too large relative to later values.

That's why the two scans complement each other.

Interview takeaway: Don't memorize just the scan directions. Ask yourself which side of the current element can prove that it is out of order. Earlier larger values reveal the right boundary; later smaller values reveal the left boundary.
