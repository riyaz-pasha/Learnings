# String Swap — Java Solution

The key observation is that we need at most one swap in exactly one string. Therefore, we can compare the strings character by character and determine whether a single swap can fix all the differences.

## 1. Intuition: Find the mismatched positions

There are three possible cases:

1. Zero mismatches: The strings are already equal, so return `true` without swapping.
2. Exactly two mismatches: A single swap can work if the mismatched characters are cross-matched.
3. Any other number of mismatches: Return `false`.

For example:

Case 1: Already equal

s1

## bank

s2

## bank

Result: true — zero swaps needed.

Case 2: Two mismatches that can be fixed

s1

## bank

s2

## kanb

Swap the `b` and `k` in `s2` to obtain `bank`.

Result: true.

Case 3: Three mismatches

s1

## abcd

s2

## badc

Actually, this example has four mismatches, so one swap cannot fix it.

Result: false.

## 2. Optimal solution — Single pass

We only need to remember the first two mismatched indices. If a third mismatch appears, we can immediately return `false`.

```

class Solution {
    public boolean areAlmostEqual(String s1, String s2) {
        // Store the positions where the strings differ.
        int first = -1;
        int second = -1;

        for (int i = 0; i < s1.length(); i++) {
            // Matching characters need no action.
            if (s1.charAt(i) == s2.charAt(i)) {
                continue;
            }

            // Record the first mismatch.
            if (first == -1) {
                first = i;
            }
            // Record the second mismatch.
            else if (second == -1) {
                second = i;
            }
            // Three or more mismatches cannot be fixed by one swap.
            else {
                return false;
            }
        }

        // No mismatches: the strings are already equal.
        if (first == -1) {
            return true;
        }

        // Exactly one mismatch cannot be fixed by swapping.
        if (second == -1) {
            return false;
        }

        // One swap must exchange the two mismatched characters.
        return s1.charAt(first) == s2.charAt(second)
                && s1.charAt(second) == s2.charAt(first);
    }
}

```

### Why does the final condition work?

Suppose the strings are:

```
s1 = bank
s2 = kanb

Index:  0 1 2 3
s1:     b a n k
s2:     k a n b
        ^     ^
```

The mismatches occur at indices `0` and `3`.

To make the strings equal, swapping those two positions in `s2` must produce:

```
Before: k a n b
Swap:   ^     ^
After:  b a n k
```

This works only if both cross-matches hold:

- `s1[first] == s2[second]` → `b == b`
- `s1[second] == s2[first]` → `k == k`

If either condition fails, the swap cannot make the strings equal.

## 3. Dry run

Consider `s1 = "attack"` and `s2 = "defend"`.

| Index | `s1[i]` | `s2[i]` | Action                          |
| ----- | ------- | ------- | ------------------------------- |
| 0     | a       | d       | `first = 0`                     |
| 1     | t       | e       | `second = 1`                    |
| 2     | t       | f       | Third mismatch → return `false` |

We stop immediately because one swap can change the characters at only two positions.

## 4. Alternative solution — Brute force

Another way to approach this problem is to try every possible swap in either string and check whether the result matches the other string. This is useful for understanding the problem, although it is inefficient.

```
class Solution {
    public boolean areAlmostEqual(String s1, String s2) {
        int n = s1.length();

        // Zero swaps are allowed.
        if (s1.equals(s2)) {
            return true;
        }

        char[] chars = s2.toCharArray();

        // Try every possible pair of positions in s2.
        for (int i = 0; i < n; i++) {
            for (int j = i + 1; j < n; j++) {
                // Perform a temporary swap.
                char temp = chars[i];
                chars[i] = chars[j];
                chars[j] = temp;

                // Check whether this swap solves the problem.
                if (new String(chars).equals(s1)) {
                    return true;
                }

                // Restore the original string before trying
                // the next pair of positions.
                temp = chars[i];
                chars[i] = chars[j];
                chars[j] = temp;
            }
        }

        return false;
    }
}
```

Since the strings must be equal after the swap, swapping either string is equivalent: the same two positions can be swapped in the other string instead.

## 5. Complexity comparison

| Approach                      | Time complexity | Auxiliary space |
| ----------------------------- | --------------- | --------------- |
| Single-pass mismatch tracking | \\(O(n)\\)      | \\(O(1)\\)      |
| Try every swap                | \\(O(n^3)\\)    | \\(O(n)\\)      |

Here, \\(n\\) is the length of the strings. The brute-force solution tries \\(O(n^2)\\) swaps, and each comparison or string construction can take \\(O(n)\\) time.

Interview recommendation: Use the single-pass solution. It is optimal because every character needs to be inspected at most once, and only two mismatch positions need to be stored.

## 6. Edge cases to remember

| Input (`s1`, `s2`) | Output  | Reason                         |
| ------------------ | ------- | ------------------------------ |
| `"abc"`, `"abc"`   | `true`  | Already equal                  |
| `"ab"`, `"ba"`     | `true`  | One swap fixes both mismatches |
| `"ab"`, `"ac"`     | `false` | Only one mismatch              |
| `"abcd"`, `"badc"` | `false` | Four mismatches                |
| `"aa"`, `"aa"`     | `true`  | Zero swaps allowed             |
| `"aa"`, `"ab"`     | `false` | One mismatch                   |

## 7. Follow-up interview questions

Q1. Why can't exactly one mismatch be fixed?

A swap changes two positions. If two strings differ at exactly one position, swapping two characters cannot correct that position without potentially introducing another mismatch.

Q2. What if the problem required exactly one swap, rather than at most one swap?

If swapping the same index with itself is allowed, an already-equal string can still return `true` by swapping an index with itself. If only two distinct indices are allowed, an already-equal string is possible only if some two positions contain the same character; otherwise, it cannot remain unchanged after a swap.

Q3. Can we solve it using a frequency map?

Not by itself. Equal character frequencies establish that one string is an anagram of the other, but they do not establish that a single swap is sufficient. For example, `"abcd"` and `"badc"` have the same frequencies but require two swaps.

Q4. What is the central observation to state in an interview?

> A single swap can correct at most two mismatched positions. Therefore, the strings must have either zero mismatches or exactly two mismatches whose characters cross-match.

That observation leads directly to the optimal \\(O(n)\\)-time, \\(O(1)\\)-space solution.
