# Count Hills and Valleys — Java Solution

The key idea is to ignore consecutive duplicate values and compare each element with its nearest different neighbors.

## 1. Optimal approach: Single pass

### Intuition

An index is a hill if its value is strictly greater than both its nearest different neighbors. Similarly, it is a valley if its value is strictly smaller than both.

For example:

### Example: `nums = [2, 4, 1, 1, 6, 5]`

The duplicate 1s represent one valley, not two.

- `4` is a hill because `4 > 2` and `4 > 1`.
- The consecutive `1`s form one valley because `1 < 4` and `1 < 6`.
- `6` is a hill because `6 > 1` and `6 > 5`.

Answer: 3

### Java 24 code

```

class Solution {
    public int countHillValley(int[] nums) {
        int count = 0;

        // Start at index 1 because the first element cannot be a hill or valley.
        // The last element also cannot qualify because it lacks a right neighbor.
        for (int i = 1; i < nums.length - 1; i++) {

            // Ignore duplicate values immediately to the left.
            // We need the nearest value that differs from nums[i].
            if (nums[i] == nums[i - 1]) {
                continue;
            }

            // Find the nearest different value to the right.
            int right = i + 1;

            while (right < nums.length && nums[right] == nums[i]) {
                right++;
            }

            // If no different right neighbor exists, this index cannot qualify.
            if (right == nums.length) {
                continue;
            }

            // Compare with the nearest different neighbors.
            boolean isHill =
                    nums[i] > nums[i - 1] && nums[i] > nums[right];

            boolean isValley =
                    nums[i] < nums[i - 1] && nums[i] < nums[right];

            // Count the index if it is either a hill or a valley.
            if (isHill || isValley) {
                count++;
            }
        }

        return count;
    }
}

```

## 2. A simpler and more efficient approach

We can simplify the logic further by comparing consecutive distinct values.

Whenever the direction of the sequence changes, we have found a hill or valley.

For example:

`[2, 4, 1, 1, 6, 5]`

Remove consecutive duplicates:

`[2, 4, 1, 6, 5]`

Now examine the direction:

- `2 → 4`: increasing
- `4 → 1`: decreasing — direction changed, so `4` is a hill.
- `1 → 6`: increasing — direction changed, so `1` is a valley.
- `6 → 5`: decreasing — direction changed, so `6` is a hill.

Total = `3`.

### Java code (recommended for interviews)

```

class Solution {
    public int countHillValley(int[] nums) {
        int count = 0;
        int previousDirection = 0;

        for (int i = 1; i < nums.length; i++) {
            // Calculate the direction between adjacent values:
            //  1 = increasing, -1 = decreasing, 0 = equal.
            int direction = Integer.compare(nums[i], nums[i - 1]);

            // Equal values do not change the current direction.
            // This automatically ignores consecutive duplicates.
            if (direction == 0) {
                continue;
            }

            // A change from increasing to decreasing means a hill.
            // A change from decreasing to increasing means a valley.
            if (previousDirection != 0 && direction != previousDirection) {
                count++;
            }

            // Remember the latest non-zero direction.
            previousDirection = direction;
        }

        return count;
    }
}

```

## 3. Dry run

Input: `nums = [2, 4, 1, 1, 6, 5]`

| Pair    | Direction    | Previous direction | Count |
| ------- | ------------ | ------------------ | ----- |
| `2 → 4` | Increasing   | None               | 0     |
| `4 → 1` | Decreasing   | Increasing         | 1     |
| `1 → 1` | Equal — skip | Decreasing         | 1     |
| `1 → 6` | Increasing   | Decreasing         | 2     |
| `6 → 5` | Decreasing   | Increasing         | 3     |

Output: `3`

## 4. Complexity analysis

| Approach          | Time complexity         | Space complexity |
| ----------------- | ----------------------- | ---------------- |
| Neighbor scanning | \\(O(n^2)\\) worst case | \\(O(1)\\)       |
| Direction changes | \\(O(n)\\)              | \\(O(1)\\)       |

The first approach can repeatedly scan duplicates to the right. The second approach processes each element once, making it the optimal solution.

## 5. Edge cases to remember

| Input          | Output | Reason                      |
| -------------- | ------ | --------------------------- |
| `[1, 2, 1]`    | 1      | One hill                    |
| `[2, 1, 2]`    | 1      | One valley                  |
| `[1, 1, 1]`    | 0      | No direction change         |
| `[1, 2, 2, 1]` | 1      | Duplicate peak counted once |
| `[1, 2, 3, 4]` | 0      | Always increasing           |
| `[4, 3, 2, 1]` | 0      | Always decreasing           |

## 6. Interview explanation

A concise way to explain the solution:

> Consecutive equal values should not affect whether a hill or valley exists. Instead of explicitly searching for the nearest different neighbors, I track the direction between consecutive elements. Whenever the direction changes from increasing to decreasing or vice versa, I count one hill or valley. Equal adjacent values are skipped, so duplicate plateaus are naturally counted only once. This gives \\(O(n)\\) time and \\(O(1)\\) extra space.

Recommendation: Use the second solution in an interview. It is shorter, more efficient, and demonstrates the key observation that hills and valleys are simply changes in direction.
