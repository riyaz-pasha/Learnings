# Maximum Consecutive Ones — Java Solution

The goal is to find the maximum number of consecutive `1`s in a binary array and return that count.

## 1. Intuition: How should we think about this?

Imagine walking through the array from left to right and counting consecutive `1`s.

- When we encounter `1`, increase the current count.
- When we encounter `0`, the current sequence of consecutive `1`s ends, so reset the count to `0`.
- After every increment, update the maximum count found so far.

We need two variables:

- `currentCount`: Length of the current consecutive sequence of `1`s.
- `maxCount`: Length of the longest consecutive sequence found so far.

The key insight is that a zero breaks a consecutive sequence, but it does not erase the maximum we have already found.

## 2. Java solution — Optimal approach

```

class Solution {
    public int findMaxConsecutiveOnes(int[] nums) {
        int currentCount = 0; // Counts consecutive 1s in the current sequence.
        int maxCount = 0;     // Stores the longest sequence found so far.

        for (int num : nums) {
            if (num == 1) {
                // Extend the current sequence of consecutive 1s.
                currentCount++;

                // Record the longest sequence seen up to this position.
                maxCount = Math.max(maxCount, currentCount);
            } else {
                // A zero breaks the current sequence.
                currentCount = 0;
            }
        }

        // Return the longest sequence found anywhere in the array.
        return maxCount;
    }
}

```

## 3. Dry run with an example

Input:

```
nums = [1, 1, 0, 1, 1, 1, 0, 1]
```

Initially, `currentCount = 0` and `maxCount = 0`.

| Index | `nums[i]` | `currentCount` | `maxCount` | Explanation                |
| ----- | --------- | -------------- | ---------- | -------------------------- |
| 0     | 1         | 1              | 1          | First `1`                  |
| 1     | 1         | 2              | 2          | Consecutive sequence grows |
| 2     | 0         | 0              | 2          | Zero resets current count  |
| 3     | 1         | 1              | 2          | New sequence begins        |
| 4     | 1         | 2              | 2          | Sequence grows             |
| 5     | 1         | 3              | 3          | New maximum found          |
| 6     | 0         | 0              | 3          | Zero resets current count  |
| 7     | 1         | 1              | 3          | New sequence begins        |

Output:

```
3
```

The longest sequence is `[1, 1, 1]`, with length `3`.

## 4. How to derive this solution in an interview

Think through these questions:

1. What are we counting? The length of a consecutive run of `1`s.
2. When does a run end? When we encounter a `0` or reach the end of the array.
3. Do we need to store every run? No. We only need the current run and the maximum run.
4. Can we process the array in one pass? Yes. Each element gives us all the information we need.

This leads directly to the two-counter solution, without sorting, extra arrays, or nested loops.

## 5. Complexity analysis

- Time complexity: \\(O(n)\\) — We visit every array element exactly once.
- Auxiliary space complexity: \\(O(1)\\) — We use only two integer variables, regardless of the array size.

This is optimal: in the general case, we must inspect every element to guarantee the correct answer.

## 6. Edge cases

| Input           | Output | Reason                      |
| --------------- | ------ | --------------------------- |
| `[1]`           | 1      | One consecutive `1`         |
| `[0]`           | 0      | No `1`s                     |
| `[1,1,1,1]`     | 4      | Entire array contains `1`s  |
| `[0,0,0]`       | 0      | No consecutive `1`s         |
| `[1,0,1,1,0,1]` | 2      | Longest run has length 2    |
| `[1,1,0,1,1,1]` | 3      | The last run is the longest |

## 7. Alternative solution: Track the start of each run

We can also track where the current run starts and calculate its length whenever we encounter a zero.

```

class Solution {
    public int findMaxConsecutiveOnes(int[] nums) {
        int start = 0;    // Starting index of the current run.
        int maxCount = 0;

        for (int i = 0; i < nums.length; i++) {
            if (nums[i] == 0) {
                // The run ends immediately before this zero.
                maxCount = Math.max(maxCount, i - start);

                // The next possible run starts after this zero.
                start = i + 1;
            }
        }

        // Handle a run that continues all the way to the last element.
        maxCount = Math.max(maxCount, nums.length - start);

        return maxCount;
    }
}

```

- Time: \\(O(n)\\)
- Auxiliary space: \\(O(1)\\)

This approach is equally efficient, but the first solution is generally easier to understand and explain because it updates the maximum as it scans.

## 8. Interview follow-up questions

Q1. Can we solve it using a sliding window?

Yes, but a sliding window is unnecessary here. A simple counter is sufficient because encountering `0` immediately ends the current run.

Q2. What if we are allowed to flip at most one zero into a one?

That becomes a different problem: Max Consecutive Ones II. We can solve it using a sliding window containing at most one zero.

Q3. What if we can flip at most `k` zeros?

Use a sliding window with at most `k` zeros. Expand the right boundary, and move the left boundary whenever the window contains more than `k` zeros. The maximum valid window length is the answer.

Q4. Why don't we reset `maxCount` when we see zero?

Because `maxCount` represents the best result across the entire array. Resetting it would discard previously discovered answers.

Q5. Can we use Java Streams?

It is possible to build a solution using streams, but it requires more complicated stateful processing. A regular loop is clearer, easier to debug, and preferable in a DSA interview.

Remember this pattern: For consecutive-element problems, maintain a counter for the current run, reset it when the condition breaks, and update a separate maximum. This pattern also applies to consecutive characters, increasing runs, and other contiguous sequences.
