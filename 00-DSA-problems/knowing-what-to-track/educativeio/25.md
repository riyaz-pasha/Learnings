Let's forget the difference array for a moment and understand the problem from the beginning. Once the problem makes sense, the code will become much easier.

# 1. First understand what the problem is asking

You are given an array:

```
nums = [2, 0, 2]
```

And these queries:

```
queries = [[0, 2], [0, 1], [1, 2]]
```

Each query `[l, r]` says:

> You may decrease any elements you choose within indices `l` through `r` by exactly `1` each.

Important: You do not have to decrease every element in the range. You can choose any subset, including the empty subset.

For example, if we have:

```
nums = [2, 3, 1]
```

And the query is `[0, 1]`, we can choose to decrement:

- Only index `0`: `[1, 3, 1]`
- Only index `1`: `[2, 2, 1]`
- Both indices: `[1, 2, 1]`
- Neither index: `[2, 3, 1]`

We process all queries sequentially, and our goal is to make every element zero.

## 2. The most important observation

Consider this array:

Each query can decrement a particular index at most once. Different queries can decrement the same index again.

Think about each index separately.

- Index `0` has value `2`. It needs 2 decrements.
- Index `1` has value `0`. It needs 0 decrements.
- Index `2` has value `2`. It needs 2 decrements.

Now ask: how many queries cover each index?

| Query    | Indices covered |
| -------- | --------------- |
| `[0, 2]` | 0, 1, 2         |
| `[0, 1]` | 0, 1            |
| `[1, 2]` | 1, 2            |

Therefore:

| Index | Required decrements | Available decrements |
| ----- | ------------------- | -------------------- |
| 0     | 2                   | 2                    |
| 1     | 0                   | 3                    |
| 2     | 2                   | 2                    |

Every index has enough available decrements, so the answer is `true`.

Why can we reason this way without simulating the queries?

Because each query gives every index in its range one independent opportunity to be decremented. We can choose which indices to decrement in each query.

So the entire problem reduces to this simple condition:

\\[ \boxed{\text{coverage}[i] \geq \text{nums}[i]} \\]

If this condition is true for every index, return `true`. If even one index fails it, return `false`.

Now we need to solve the remaining problem efficiently: how do we count the queries covering every index?

# 3. First solve it using a simple approach

Before learning the optimized solution, let's write the solution that is easiest to understand.

For every index, count how many queries cover it.

```
class Solution {
    public boolean isZeroArray(int[] nums, int[][] queries) {
        int n = nums.length;

        // Check each index independently.
        for (int i = 0; i < n; i++) {
            int coverage = 0;

            // Count how many queries include index i.
            for (int[] query : queries) {
                int left = query[0];
                int right = query[1];

                // Index i is covered if it lies inside [left, right].
                if (left <= i && i <= right) {
                    coverage++;
                }
            }

            // We need at least nums[i] opportunities to decrement it.
            if (coverage < nums[i]) {
                return false;
            }
        }

        return true;
    }
}
```

The problem with this approach: for every index, we examine every query. Its time complexity is \\(O(nq)\\), which can mean up to \\(10^{10}\\) checks for the given constraints.

We need a faster way to count coverage.

# 4. The intuition behind the difference array

Forget the full algorithm for a moment. Imagine there is only one query:

```
Query: [1, 3]
```

Our array has five indices:

```
Index:      0   1   2   3   4
```

This query covers indices `1`, `2`, and `3`.

The coverage we want is:

```
Index:      0   1   2   3   4
Coverage:   0   1   1   1   0
```

The straightforward way is to increment positions `1`, `2`, and `3`.

But what if the query is `[1, 99999]`? We would have to update almost 100,000 positions for just one query.

Instead, notice that coverage changes only at two places:

- At index `1`, coverage increases from `0` to `1`.
- At index `4`, coverage decreases from `1` to `0`.

We can record only those two changes:

```
Index:      0   1   2   3   4   5
diff:       0  +1   0   0  -1   0
```

Why put `-1` at index `4`? Because index `4` is immediately after the query's right boundary, index `3`.

We have not yet calculated the coverage. We have only recorded where it changes.

Now, let's reconstruct coverage by adding the values from left to right.

The running sum is the actual number of queries covering the current index.

The running sum behaves like this:

```
Index 0: 0 + 0  = 0  -> no query covers it
Index 1: 0 + 1  = 1  -> one query covers it
Index 2: 1 + 0  = 1  -> one query covers it
Index 3: 1 + 0  = 1  -> one query covers it
Index 4: 1 - 1  = 0  -> the query has ended
```

We have reconstructed the entire coverage array without updating every position individually!

This is the key idea of a difference array:

> Record where a range starts and stops affecting the array, then use a running sum to determine the effect at each position.

# 5. Apply this idea to our actual problem

For each query `[l, r]`, we do just two updates:

```
diff[l]++;
diff[r + 1]--;
```

Let's see why this works with three queries.

Input:

```
nums    = [2, 0, 2]
queries = [[0, 2], [0, 1], [1, 2]]
```

We create a difference array of length `n + 1`, which is `4`.

Initially:

```
Index:  0  1  2  3
diff:   0  0  0  0
```

### Process query 1: `[0, 2]`

```
diff[0]++;
diff[3]--;
```

The query starts at index `0` and ends at index `2`. Index `3` is where its effect stops.

```
diff = [1, 0, 0, -1]
```

### Process query 2: `[0, 1]`

```
diff[0]++;
diff[2]--;
```

```
diff = [2, 0, -1, -1]
```

Notice that `diff[0]` becomes `2` because two queries start at index `0`.

### Process query 3: `[1, 2]`

```
diff[1]++;
diff[3]--;
```

```
diff = [2, 1, -1, -2]
```

Our final difference array is:

```
Index:  0   1   2   3
diff:   2   1  -1  -2
```

Important: this is not the coverage array yet. It only stores changes in coverage.

## 6. The final step: prefix sum

We walk through `nums` from left to right, maintaining a variable called `availableDecrements`.

Initially:

```
int availableDecrements = 0;
```

At each index, we add the corresponding difference-array value:

```
availableDecrements += diff[i];
```

This gives the number of queries covering the current index.

# 7. Final code with detailed comments

This is the version I recommend remembering for interviews.

```

class Solution {
    public boolean isZeroArray(int[] nums, int[][] queries) {
        int n = nums.length;

        // IDEA:
        // We don't need to simulate the decrements.
        // For each index i, we only need to know how many queries cover it.
        //
        // If coverage[i] >= nums[i] for every index, the answer is true.
        //
        // A difference array lets us count range coverage efficiently:
        // each query contributes only two boundary updates.

        // n + 1 gives us a safe position at r + 1,
        // even when a query ends at the last array index (n - 1).
        int[] diff = new int[n + 1];

        // STEP 1: Record the boundaries of every query.
        for (int[] query : queries) {
            int l = query[0];
            int r = query[1];

            // Coverage starts increasing at index l.
            diff[l]++;

            // Coverage stops increasing after index r.
            // The decrement at r + 1 cancels this query's contribution
            // when we later calculate prefix sums.
            diff[r + 1]--;
        }

        // STEP 2: Reconstruct coverage using a prefix sum.
        // This variable represents the number of queries covering i.
        int availableDecrements = 0;

        for (int i = 0; i < n; i++) {
            // Apply the coverage change at the current index.
            availableDecrements += diff[i];

            // Each query covering i can decrement nums[i] once.
            // If too few queries cover this index, it cannot reach zero.
            if (availableDecrements < nums[i]) {
                return false;
            }
        }

        // Every element has enough available decrements to become zero.
        return true;
    }
}

```

## 8. What if the answer is `false`?

Consider this example:

```
nums    = [1, 2, 1]
queries = [[0, 1], [1, 2]]
```

The coverage is:

```
Index:                0  1  2
nums[i]:              1  2  1
availableDecrements:  1  2  1
```

All elements have sufficient coverage, so the result is `true`.

Now remove the first query:

```
nums    = [1, 2, 1]
queries = [[1, 2]]
```

The coverage becomes:

```
Index:                0  1  2
nums[i]:              1  2  1
availableDecrements:  0  1  1
```

At index `0`, we need one decrement but have zero available decrements.

```
0 < 1  // true
```

We immediately return `false`. There is no need to inspect the remaining indices.

## 9. Complexity

Let `n` be the array length and `q` be the number of queries.

- Time: \\(O(n+q)\\). We process every query once and every array index once.
- Extra space: \\(O(n)\\). We allocate the difference array of length `n + 1`.

## 10. Interview follow-up questions

Q1. Why don't we actually decrement `nums[i]`?

Because the problem allows independent choices for each index in every query. Only the number of opportunities matters, not the order in which we use them.

Q2. Why do we use `diff[r + 1]--` instead of `diff[r]--`?

The query includes index `r`. Its contribution must remain active at `r` and stop only at `r + 1`.

Q3. Why is the difference array of size `n + 1`?

A query can end at index `n - 1`, requiring an update at index `n`. That extra position prevents an out-of-bounds access.

Q4. Can we solve it without a difference array?

Yes. The nested-loop approach works, but it takes \\(O(nq)\\) time. The difference array reduces the time complexity to \\(O(n+q)\\).

The one-line intuition to remember:

> Count how many queries cover each index using range-boundary updates and prefix sums; if every index has coverage at least equal to its value, the array can become zero.
