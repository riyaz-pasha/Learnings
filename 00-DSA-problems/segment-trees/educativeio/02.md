# Range Minimum Queries and Updates — Segment Tree

This is the Range Minimum Query (RMQ) with Point Updates problem.

The optimal solution is a Segment Tree.

Given:

- An array of `n` integers.
- `q` queries.
- Two operations:
  1. Update `arr[k] = u`.
  2. Find the minimum element in the inclusive range `[a, b]`.

Since `n, q ≤ 2 × 10^5`, we need an efficient data structure.

## 0. Understand the problem with an example

Consider:

```
arr = [3, 2, 4, 5, 1, 1, 5, 3]
```

Queries:

```
2 1 4
2 5 6
1 2 3
2 1 4
```

Remember that the input uses 1-based indexing.

| Query   | Operation              | Result    |
| ------- | ---------------------- | --------- |
| `2 1 4` | Minimum in `[1, 4]`    | `2`       |
| `2 5 6` | Minimum in `[5, 6]`    | `1`       |
| `1 2 3` | Update position 2 to 3 | No output |
| `2 1 4` | Minimum in `[1, 4]`    | `3`       |

Output:

```
2
1
3
```

Notice that after updating position 2:

```
Before: [3, 2, 4, 5, 1, 1, 5, 3]
After:  [3, 3, 4, 5, 1, 1, 5, 3]
```

The minimum of the first four elements changes from `2` to `3`.

## 1. Clarifying questions to ask the interviewer

Before implementing, clarify:

1. Are the ranges inclusive?
   - The statement says `[a, b]`, so we assume both endpoints are included.
2. Are updates point updates or range updates?
   - Only one position is updated. Therefore, we don't need lazy propagation.
3. Can values be negative?
   - Given constraints specify positive values, but a reusable implementation should support negative values too.
4. What are the constraints?
   - With `n, q ≤ 2 × 10^5`, an `O(log n)` solution per operation is appropriate.
5. Is the input indexing 0-based or 1-based?
   - Input is 1-based. We will convert to 0-based internally.

## 2. All possible approaches

| Approach          | Update                   | Range minimum                                             | Total complexity      |
| ----------------- | ------------------------ | --------------------------------------------------------- | --------------------- |
| Brute force array | O(1)                     | O(n)                                                      | O(qn)                 |
| Segment Tree      | O(log n)                 | O(log n)                                                  | O(n + q log n)        |
| Fenwick Tree      | O(log n)                 | Not directly supported for arbitrary minimum with updates | —                     |
| Sparse Table      | O(n log n) preprocessing | O(1)                                                      | Updates are expensive |

Why not use a Fenwick Tree?

Fenwick Trees work naturally with operations such as sum, XOR, and certain prefix aggregates.

However, minimum does not have an inverse operation. If the current minimum is updated to a larger value, a Fenwick Tree cannot generally determine the next minimum from its stored minimum alone.

Why not use a Sparse Table?

Sparse Tables are excellent for static arrays, but point updates can invalidate many precomputed entries.

Therefore, we use a Segment Tree.

# 3. Core intuition — Segment Tree

The main idea is:

Instead of repeatedly scanning an entire range, divide the array into smaller segments and store the minimum of each segment.

For our example:

```
arr = [3, 2, 4, 5, 1, 1, 5, 3]
```

We construct a binary tree.

Every node represents an interval.

- Leaf nodes represent individual elements.
- Internal nodes represent the minimum of their children.
- The root represents the minimum of the entire array.

## Segment Tree visualization

Each internal node stores min(left child, right child).

```
                         [1, 8] = 1
                       /            \
               [1, 4] = 2          [5, 8] = 1
               /      \             /       \
         [1, 2]=2   [3, 4]=4   [5, 6]=1   [7, 8]=3
          /   \      /   \      /   \      /   \
         3     2    4     5    1     1    5     3
```

For example:

```
Minimum of [1, 4]

         [1, 4] = 2
          /     \
       [1,2]   [3,4]
         2        4

Answer = min(2, 4) = 2
```

The important observation is that we don't need to visit every element.

We can use already-computed segment minimums.

## How range queries work

There are three possibilities when comparing a tree node's interval with the requested query interval.

Case 1: Complete overlap

The node's entire interval is inside the requested interval.

Return the minimum stored at that node.

Case 2: No overlap

The node's interval is completely outside the requested interval.

Return positive infinity (`Integer.MAX_VALUE`).

Why?

Because:

```java
Math.min(5, Integer.MAX_VALUE) == 5
```

Therefore, this value doesn't affect the answer.

Case 3: Partial overlap

The node overlaps the query interval partially.

Recursively search both children and return their minimum.

```java
return Math.min(leftResult, rightResult);
```

## How updates work

Suppose:

```
arr = [3, 2, 4, 5, 1, 1, 5, 3]

Update position 2 to 3.
```

Only the leaf representing position 2 changes.

We then recalculate the minimum of its ancestors.

```
Before:

       [1, 2] = 2
        /   \
       3     2

After:

       [1, 2] = 3
        /   \
       3     3
```

We don't rebuild the entire tree.

We update only one root-to-leaf path.

Tree height is `O(log n)`.

Therefore, an update takes `O(log n)`.

# 4. Java 24 solutions

## Solution 1: Brute Force

This is the simplest implementation.

We directly scan the requested range for every minimum query.

```java
import java.util.*;

class Solution {

    public static void main(String[] args) {

        Scanner sc = new Scanner(System.in);

        int n = sc.nextInt();
        int q = sc.nextInt();

        int[] arr = new int[n];

        for (int i = 0; i < n; i++) {
            arr[i] = sc.nextInt();
        }

        while (q-- > 0) {

            int type = sc.nextInt();

            if (type == 1) {

                // Convert 1-based input index to 0-based index.
                int k = sc.nextInt() - 1;

                int u = sc.nextInt();

                // Point update takes O(1).
                arr[k] = u;

            } else {

                // Convert inclusive 1-based range to 0-based.
                int a = sc.nextInt() - 1;
                int b = sc.nextInt() - 1;

                int min = Integer.MAX_VALUE;

                // Directly examine every element in [a, b].
                for (int i = a; i <= b; i++) {
                    min = Math.min(min, arr[i]);
                }

                System.out.println(min);
            }
        }

        sc.close();
    }
}
```

Complexity:

- Build: `O(n)`
- Update: `O(1)`
- Query: `O(n)`
- Space: `O(n)` for the input array.

Worst-case time:

\\[ O(n + qn) \\]

With `n, q = 200000`, this approach is too slow.

## Solution 2: Segment Tree — Recursive Implementation

This is the standard interview implementation.

We use an array to represent the binary tree.

### Why allocate `4 * n`?

For a segment tree containing `n` elements, an array of size `4 * n` is sufficient for the conventional recursive representation.

We don't need to explicitly create tree nodes.

### Complete Java 24 implementation

```java
import java.io.*;
import java.util.*;

class Solution {

    private static int[] tree;
    private static int n;

    public static void main(String[] args) throws IOException {

        BufferedReader br = new BufferedReader(
            new InputStreamReader(System.in)
        );

        StringTokenizer st = new StringTokenizer(br.readLine());

        n = Integer.parseInt(st.nextToken());
        int q = Integer.parseInt(st.nextToken());

        int[] arr = new int[n];

        st = new StringTokenizer(br.readLine());

        for (int i = 0; i < n; i++) {
            arr[i] = Integer.parseInt(st.nextToken());
        }

        // Allocate enough space for the recursive segment tree.
        tree = new int[4 * n];

        // Build the tree once.
        build(1, 0, n - 1, arr);

        StringBuilder output = new StringBuilder();

        while (q-- > 0) {

            st = new StringTokenizer(br.readLine());

            int type = Integer.parseInt(st.nextToken());

            if (type == 1) {

                // Convert 1-based position to 0-based.
                int k = Integer.parseInt(st.nextToken()) - 1;

                int u = Integer.parseInt(st.nextToken());

                // Update the leaf and recalculate ancestors.
                update(1, 0, n - 1, k, u);

            } else {

                // Convert 1-based inclusive range to 0-based.
                int a = Integer.parseInt(st.nextToken()) - 1;
                int b = Integer.parseInt(st.nextToken()) - 1;

                int answer = query(
                    1, 0, n - 1, a, b
                );

                output.append(answer).append('\n');
            }
        }

        System.out.print(output);
    }

    /*
     * BUILD SEGMENT TREE
     *
     * node = current tree node index.
     * start = left endpoint represented by this node.
     * end = right endpoint represented by this node.
     *
     * Tree representation:
     *
     * left child  = 2 * node
     * right child = 2 * node + 1
     *
     * A leaf represents exactly one array element.
     *
     * Time: O(n)
     * Space: O(log n) recursion stack.
     */

    private static void build(
        int node,
        int start,
        int end,
        int[] arr
    ) {

        // Base case: this node represents one element.
        if (start == end) {
            tree[node] = arr[start];
            return;
        }

        int mid = start + (end - start) / 2;

        // Construct left half.
        build(
            2 * node,
            start,
            mid,
            arr
        );

        // Construct right half.
        build(
            2 * node + 1,
            mid + 1,
            end,
            arr
        );

        // Parent stores the minimum of both children.
        tree[node] = Math.min(
            tree[2 * node],
            tree[2 * node + 1]
        );
    }

    /*
     * POINT UPDATE
     *
     * Change arr[index] to value.
     *
     * We recursively find the leaf corresponding to index.
     * Once the leaf is updated, we recalculate the minimum
     * of every ancestor on the path back to the root.
     *
     * Only one root-to-leaf path is visited.
     *
     * Time: O(log n)
     * Space: O(log n) recursion stack.
     */

    private static void update(
        int node,
        int start,
        int end,
        int index,
        int value
    ) {

        // We have reached the leaf for the target index.
        if (start == end) {
            tree[node] = value;
            return;
        }

        int mid = start + (end - start) / 2;

        if (index <= mid) {

            // Target belongs to the left subtree.
            update(
                2 * node,
                start,
                mid,
                index,
                value
            );

        } else {

            // Target belongs to the right subtree.
            update(
                2 * node + 1,
                mid + 1,
                end,
                index,
                value
            );
        }

        // Recalculate the current node after updating
        // its affected child.
        tree[node] = Math.min(
            tree[2 * node],
            tree[2 * node + 1]
        );
    }

    /*
     * RANGE MINIMUM QUERY
     *
     * Find the minimum in query range [left, right].
     *
     * Three possible cases:
     *
     * 1. NO OVERLAP:
     *    Current segment is completely outside query range.
     *    Return Integer.MAX_VALUE.
     *
     * 2. COMPLETE OVERLAP:
     *    Current segment is completely inside query range.
     *    Return the minimum already stored in this node.
     *
     * 3. PARTIAL OVERLAP:
     *    Search both children and combine their answers.
     *
     * Time: O(log n) for a segment tree range query.
     * Space: O(log n) recursion stack.
     */

    private static int query(
        int node,
        int start,
        int end,
        int left,
        int right
    ) {

        // CASE 1: NO OVERLAP.
        //
        // Current segment: [start, end]
        // Query segment:   [left, right]
        //
        // No intersection exists.
        //
        // MAX_VALUE is the identity element for minimum.
        // It ensures that this segment does not affect
        // the final answer.

        if (end < left || start > right) {
            return Integer.MAX_VALUE;
        }

        // CASE 2: COMPLETE OVERLAP.
        //
        // Current segment lies entirely inside the query.
        //
        // No need to explore its children because its
        // minimum has already been calculated during build
        // or maintained during updates.

        if (left <= start && end <= right) {
            return tree[node];
        }

        // CASE 3: PARTIAL OVERLAP.
        //
        // The current segment partially intersects the query.
        // Explore both children.

        int mid = start + (end - start) / 2;

        int leftMin = query(
            2 * node,
            start,
            mid,
            left,
            right
        );

        int rightMin = query(
            2 * node + 1,
            mid + 1,
            end,
            left,
            right
        );

        // Combine the results from both subtrees.
        return Math.min(leftMin, rightMin);
    }
}
```

### Complexity analysis

| Operation            | Time complexity |
| -------------------- | --------------- |
| Build                | O(n)            |
| Point update         | O(log n)        |
| Range minimum query  | O(log n)        |
| All queries          | O(q log n)      |
| Total                | O(n + q log n)  |
| Segment tree storage | O(n)            |
| Recursion stack      | O(log n)        |

For the given constraints:

```
n = 200,000
q = 200,000
```

This is efficient enough.

## 5. Solution 3: Iterative Segment Tree

This is another important implementation to know.

Instead of recursively constructing the tree, we use a flat array.

The key idea is to store all original elements in the second half of the tree array.

For `n` elements:

```java
tree[n]     = arr[0]
tree[n + 1] = arr[1]
tree[n + 2] = arr[2]
...
tree[2*n-1] = arr[n-1]
```

The first `n` positions store internal segment information.

For every node:

```java
tree[i] = Math.min(tree[2 * i], tree[2 * i + 1]);
```

### Visualization

For `n = 4`:

```
Array:
[3, 2, 4, 5]

Tree array:

Index:  1   2   3   4   5   6   7
Value:  2   2   4   3   2   4   5

                 2
              /     \
             2       4
           /  \     /  \
          3    2   4    5
```

### Complete Java 24 implementation

```java
import java.io.*;
import java.util.*;

class Solution {

    private static int n;
    private static int[] tree;

    /*
     * CONSTRUCTOR / BUILD
     *
     * Leaves are stored from index n to 2*n - 1.
     *
     * Internal nodes are calculated bottom-up.
     *
     * Time: O(n)
     * Space: O(n)
     */

    private static void build(int[] arr) {

        n = arr.length;

        tree = new int[2 * n];

        // Place original elements at the leaf positions.
        for (int i = 0; i < n; i++) {
            tree[n + i] = arr[i];
        }

        // Construct internal nodes from bottom to top.
        for (int i = n - 1; i >= 1; i--) {

            tree[i] = Math.min(
                tree[2 * i],
                tree[2 * i + 1]
            );
        }
    }

    /*
     * POINT UPDATE
     *
     * First update the corresponding leaf.
     * Then travel towards the root, recalculating
     * the minimum at every ancestor.
     *
     * Time: O(log n)
     * Space: O(1)
     */

    private static void update(int index, int value) {

        // Convert original array index into leaf index.
        index += n;

        // Update the leaf.
        tree[index] = value;

        // Recalculate all ancestors.
        while (index > 1) {

            index /= 2;

            tree[index] = Math.min(
                tree[2 * index],
                tree[2 * index + 1]
            );
        }
    }

    /*
     * RANGE MINIMUM QUERY
     *
     * Query range is inclusive [left, right].
     *
     * Convert it into the leaf-index representation.
     *
     * If left is a right child, its parent also contains
     * elements outside the remaining query range.
     * Therefore, consume this node and move right.
     *
     * If right is a left child, its parent also contains
     * elements outside the remaining query range.
     * Therefore, consume this node and move left.
     *
     * Continue until both pointers meet.
     *
     * Time: O(log n)
     * Space: O(1)
     */

    private static int query(int left, int right) {

        left += n;
        right += n;

        int answer = Integer.MAX_VALUE;

        // Continue while there are unprocessed segments.
        while (left <= right) {

            // Left is a right child.
            //
            // Its sibling lies outside the remaining range.
            // Therefore, consume the current node.

            if ((left & 1) == 1) {

                answer = Math.min(
                    answer,
                    tree[left]
                );

                left++;
            }

            // Right is a left child.
            //
            // Its sibling lies outside the remaining range.
            // Therefore, consume the current node.

            if ((right & 1) == 0) {

                answer = Math.min(
                    answer,
                    tree[right]
                );

                right--;
            }

            // Move both pointers to their parents.
            left /= 2;
            right /= 2;
        }

        return answer;
    }

    public static void main(String[] args) throws IOException {

        BufferedReader br = new BufferedReader(
            new InputStreamReader(System.in)
        );

        StringTokenizer st = new StringTokenizer(br.readLine());

        int size = Integer.parseInt(st.nextToken());
        int q = Integer.parseInt(st.nextToken());

        int[] arr = new int[size];

        st = new StringTokenizer(br.readLine());

        for (int i = 0; i < size; i++) {
            arr[i] = Integer.parseInt(st.nextToken());
        }

        build(arr);

        StringBuilder output = new StringBuilder();

        while (q-- > 0) {

            st = new StringTokenizer(br.readLine());

            int type = Integer.parseInt(st.nextToken());

            if (type == 1) {

                int k = Integer.parseInt(st.nextToken()) - 1;
                int u = Integer.parseInt(st.nextToken());

                update(k, u);

            } else {

                int a = Integer.parseInt(st.nextToken()) - 1;
                int b = Integer.parseInt(st.nextToken()) - 1;

                output.append(query(a, b)).append('\n');
            }
        }

        System.out.print(output);
    }
}
```

Important: This iterative implementation works for arbitrary `n`, including when `n` is not a power of two. Its flat-tree representation has a slightly less intuitive structure in that case, but the iterative query algorithm remains valid.

# 6. Edge cases to consider

| Edge case            | Input / situation                      | Expected behavior           |
| -------------------- | -------------------------------------- | --------------------------- |
| Single element       | `n = 1`                                | Return that element         |
| Entire range         | `[1, n]`                               | Return global minimum       |
| Single-element query | `[k, k]`                               | Return `arr[k]`             |
| Update minimum       | Change current minimum to larger value | Recalculate ancestors       |
| Update non-minimum   | Change an element to smaller value     | Recalculate ancestors       |
| Repeated updates     | Update same position multiple times    | Latest value wins           |
| Equal values         | Multiple elements have same minimum    | Return that minimum         |
| Boundary query       | `[1, 1]` or `[n, n]`                   | Correctly handle boundaries |

One particularly important case:

```
arr = [1, 2, 3, 4]

Update position 1 to 10.

arr = [10, 2, 3, 4]
```

The global minimum changes from `1` to `2`.

This illustrates why we must recalculate ancestors after an update.

# 7. Interviewer follow-up questions

Q1. Why is a Segment Tree better than brute force?

Because brute force requires scanning every element in a query range, taking `O(n)` in the worst case.

A Segment Tree stores precomputed minimums for segments, allowing updates and queries in `O(log n)`.

Q2. Why do we return `Integer.MAX_VALUE` for no overlap?

Because `Integer.MAX_VALUE` is the identity element for the minimum operation.

\\[ \min(x, Integer.MAX\\\_VALUE) = x \\]

It doesn't change the actual answer.

Q3. Why do we need to update all ancestors?

An ancestor stores the minimum of its entire interval.

When one leaf changes, the minimum of every interval containing that leaf might also change.

Therefore, we recalculate the path from the leaf to the root.

Q4. Can we use a Segment Tree for range maximum queries?

Yes.

Replace:

```java
Math.min(left, right)
```

with:

```java
Math.max(left, right)
```

And replace:

```java
Integer.MAX_VALUE
```

with:

```java
Integer.MIN_VALUE
```

Q5. Can we use a Segment Tree for range sum queries?

Yes.

Replace the minimum operation with addition.

The no-overlap identity becomes `0`.

Q6. Can we use lazy propagation here?

No need.

Lazy propagation is useful when we perform range updates, such as:

```
Add 5 to every element in [a, b].
```

Here, we only update one position, so ordinary point-update Segment Trees are sufficient.

Q7. What if we need the minimum value AND its index?

Store a pair:

```java
record MinResult(int value, int index) {}
```

When merging two results:

```java
private static MinResult merge(
    MinResult a,
    MinResult b
) {

    if (a.value() <= b.value()) {
        return a;
    }

    return b;
}
```

This example breaks ties by choosing the leftmost index.

Q8. Why is iterative Segment Tree useful?

It avoids recursive function calls, has `O(1)` auxiliary space per operation, and is often convenient in competitive programming.

# 8. Final comparison and recommendation

| Feature                   | Recursive Segment Tree | Iterative Segment Tree |
| ------------------------- | ---------------------- | ---------------------- |
| Build                     | O(n)                   | O(n)                   |
| Update                    | O(log n)               | O(log n)               |
| Query                     | O(log n)               | O(log n)               |
| Tree storage              | 4n                     | 2n                     |
| Recursion                 | Yes                    | No                     |
| Implementation            | Easier to understand   | More compact           |
| Auxiliary operation space | O(log n)               | O(1)                   |

My recommendation for interviews:

1. Start by explaining the brute-force solution.
2. Identify why it is too slow for `n, q ≤ 2 × 10^5`.
3. Introduce the Segment Tree and explain its three query cases.
4. Implement the recursive version first because its logic is easier to communicate.
5. If the interviewer asks about iterative implementation or memory optimization, present the iterative version.

The most important mental model to remember:

A Segment Tree is a hierarchy of precomputed answers. Updates modify one path, while queries combine a small number of precomputed segments.

That is the central idea behind this entire problem.
