# **2213. Longest Substring of One Repeating Character**

**Difficulty:** Hard\
**Pattern:** Segment Tree + Range Query + Point Update\
**Optimal Time Complexity:** \\(O((n+k)\log n)\\)\
**Optimal Space Complexity:** \\(O(n)\\)

## **0. Simplify the problem statement**

You are given:

- A string `s`.
- An array `queryIndices`, containing positions to update.
- A string `queryCharacters`, containing the new characters for those positions.

For every query:

1. Update `s[queryIndices[i]]` to `queryCharacters[i]`.
2. Find the length of the longest contiguous substring containing only the same character.
3. Store that length in the answer.

**Important:** We need the longest *contiguous* substring, not the longest subsequence.

### **Example**

```
s = "babacc"

queryCharacters = "bcb"
queryIndices    = [1, 3, 3]
```

| Query | Updated string | Longest repeating substring | Answer |
| ----- | -------------- | --------------------------- | ------ |
| 1     | bbbacc         | bbb                         | 3      |
| 2     | bbbccc         | bbb or ccc                  | 3      |
| 3     | bbbbcc         | bbbb                        | 4      |

Result:

```
[3, 3, 4]
```

## **1. Clarifying questions to ask the interviewer**

Before designing the solution, clarify:

1. **Are updates permanent?**

   Yes, each update modifies the string for subsequent queries. This matters because we cannot independently process each query against the original string.
2. **Can multiple queries update the same index?**

   Yes. We must always use the latest character at that index.
3. **Can an update assign the same character already present?**

   Yes. We should handle it efficiently without unnecessary tree modifications.
4. **Do we need the longest substring after every update?**

   Yes. Therefore, we need a data structure supporting efficient point updates and global maximum queries.
5. **What are the constraints?**

   \\(n,k \leq 10^5\\).

   This rules out repeatedly scanning the entire string after every update, which would take \\(O(nk)\\).

## **2. Core intuition: Segment Tree**

### **First, understand why brute force is expensive**

Consider:

```
s = "aaabbccccdde"
```

The longest repeating substring is:

```
cccc
```

Length = 4.

After changing one character, we need to determine whether the longest group has changed.

A straightforward solution scans the entire string after every update.

With \\(n=10^5\\) and \\(k=10^5\\):

\\[ O(n \times k) = O(10^{10}) \\]

Too slow.

We need to avoid rescanning the entire string.

### **Key observation**

The problem asks us to maintain the longest contiguous sequence of identical characters under point updates.

This is exactly what a **Segment Tree** can handle.

However, a normal segment tree storing only the maximum repeating substring length is insufficient.

Why?

Consider two adjacent segments:

```
Left segment:  aaabb
Right segment: bbccc
```

The longest repeating substring in the left segment is:

```
aaa -> 3
```

The longest repeating substring in the right segment is:

```
ccc -> 3
```

But after combining them:

```
aaabbbccc
```

The middle `bbb` has length 3, formed by combining:

```
Left suffix:  bb
Right prefix: b
```

Therefore, when merging two segments, we need additional information.

### **What should every segment tree node store?**

For each interval, maintain four properties:

| Property | Meaning                                                        |
| -------- | -------------------------------------------------------------- |
| `length` | Total length of the interval                                   |
| `prefix` | Longest repeating-character prefix                             |
| `suffix` | Longest repeating-character suffix                             |
| `best`   | Longest repeating-character substring anywhere in the interval |

We also need:

- `leftChar`: First character in the interval.
- `rightChar`: Last character in the interval.

These boundary characters tell us whether two adjacent segments can be merged into a longer repeating substring.

### **Visual representation**

Consider:

```
String = "aaabbcc"
```

Split it into two segments:

```
          "aaabb" | "cc"
```

Their information:

```
Left segment:
    length = 5
    prefix = 3
    suffix = 2
    best   = 3
    first  = 'a'
    last   = 'b'

Right segment:
    length = 2
    prefix = 2
    suffix = 2
    best   = 2
    first  = 'c'
    last   = 'c'
```

Since:

```
'b' != 'c'
```

There is no cross-boundary repeating substring.

The combined information becomes:

```
length = 7
prefix = 3
suffix = 2
best   = 3
```

Now consider:

```
String = "aaabb|bbccc"
```

Here, the left segment ends with `b`, and the right segment starts with `b`.

They can be combined.

```
Left suffix  = "bb"  -> 2
Right prefix = "bb"  -> 2

Combined substring = "bbbb" -> 4
```

Therefore:

\\[ best = \max(left.best,\ right.best,\ left.suffix + right.prefix) \\]

The third term is included only when the boundary characters match.

## **3. Segment Tree merge logic**

This is the most important part of the problem.

Suppose we have two adjacent segment tree nodes:

```
             Parent
            /      \
         Left      Right
```

Let their properties be:

```java
left.length
left.prefix
left.suffix
left.best
left.leftChar
left.rightChar

right.length
right.prefix
right.suffix
right.best
right.leftChar
right.rightChar
```

### **Step 1: Calculate total length**

```
parent.length = left.length + right.length;
```

### **Step 2: Calculate prefix**

The prefix of the combined interval normally comes from the left segment.

But if the entire left segment consists of the same character as the beginning of the right segment, we can extend the prefix.

```java
parent.prefix = left.prefix;

if (left.prefix == left.length
        && left.rightChar == right.leftChar) {

    parent.prefix += right.prefix;
}
```

Why check `left.prefix == left.length`?

Because the entire left segment must consist of the same character for the combined prefix to extend into the right segment.

### **Step 3: Calculate suffix**

Symmetrically:

```java
parent.suffix = right.suffix;

if (right.suffix == right.length
        && left.rightChar == right.leftChar) {

    parent.suffix += left.suffix;
}
```

### **Step 4: Calculate best**

The longest repeating substring can exist in three places:

1. Entirely inside the left segment.
2. Entirely inside the right segment.
3. Across the boundary between the two segments.

Therefore:

```java
parent.best = Math.max(left.best, right.best);

if (left.rightChar == right.leftChar) {
    parent.best = Math.max(
        parent.best,
        left.suffix + right.prefix
    );
}
```

This is the heart of the solution.

# **4. All possible solutions**

## **Approach 1: Brute Force**

**Idea:** Apply each update, then scan the entire string to find the longest repeating substring.

```java
class Solution {

    public int[] longestRepeating(
            String s,
            String queryCharacters,
            int[] queryIndices) {

        // Convert String to char[] because Java Strings are immutable.
        char[] chars = s.toCharArray();

        int k = queryIndices.length;
        int[] answer = new int[k];

        // Process every update.
        for (int q = 0; q < k; q++) {

            // Apply the current update.
            chars[queryIndices[q]] = queryCharacters.charAt(q);

            // Find the longest repeating substring.
            int maxLength = 0;
            int currentLength = 0;
            char previous = '\0';

            for (char current : chars) {

                // Continue the current group if characters match.
                if (current == previous) {
                    currentLength++;
                } else {
                    // Start a new group.
                    currentLength = 1;
                }

                // Update the global maximum.
                maxLength = Math.max(maxLength, currentLength);

                previous = current;
            }

            answer[q] = maxLength;
        }

        return answer;
    }
}
```

**Complexity analysis:**

- Updating one character: \\(O(1)\\).
- Scanning the string: \\(O(n)\\).
- Processing all queries: \\(O(nk)\\).
- Auxiliary space: \\(O(n)\\) for the mutable character array.
- Answer space: \\(O(k)\\).

Overall:

\\[ \boxed{O(nk)\text{ time},\quad O(n+k)\text{ space}} \\]

**Problem:** At maximum constraints, this requires approximately \\(10^{10}\\) character inspections.

Not acceptable.

## **Approach 2: Segment Tree (Optimal)**

We maintain the six properties discussed earlier.

The segment tree supports:

- Point update: \\(O(\log n)\\).
- Global maximum query: \\(O(1)\\), because the answer is always stored at the root.

This gives:

\\[ \boxed{O((n+k)\log n)\text{ time}} \\]

### **Java 24 implementation**

For readability, we will use a Java `record` to represent each segment.

```java

class Solution {

    // Each node summarizes a contiguous interval.
    //
    // length    = total number of characters in this interval.
    // prefix    = longest repeating-character prefix.
    // suffix    = longest repeating-character suffix.
    // best      = longest repeating-character substring anywhere.
    // leftChar  = first character in this interval.
    // rightChar = last character in this interval.
    //
    // A record is useful here because segment summaries are immutable.
    private record Node(
        int length,
        int prefix,
        int suffix,
        int best,
        char leftChar,
        char rightChar
    ) {}

    private char[] chars;
    private Node[] tree;
    private int n;

    public int[] longestRepeating(
            String s,
            String queryCharacters,
            int[] queryIndices) {

        // Convert the immutable String into a mutable character array.
        chars = s.toCharArray();

        n = chars.length;

        // A segment tree generally requires at most 4*n nodes.
        tree = new Node[4 * n];

        // Build summaries for all intervals.
        build(1, 0, n - 1);

        int k = queryIndices.length;
        int[] answer = new int[k];

        // Process queries sequentially because each update
        // affects all subsequent queries.
        for (int i = 0; i < k; i++) {

            int index = queryIndices[i];
            char newChar = queryCharacters.charAt(i);

            // Apply the point update.
            update(1, 0, n - 1, index, newChar);

            // The root represents the complete string [0, n-1].
            // Therefore, root.best is the answer.
            answer[i] = tree[1].best();
        }

        return answer;
    }

    // ---------------------------------------------------------
    // BUILD
    // ---------------------------------------------------------

    private void build(int node, int start, int end) {

        // Base case:
        // A leaf represents exactly one character.
        if (start == end) {

            char c = chars[start];

            tree[node] = new Node(
                1,  // length
                1,  // prefix
                1,  // suffix
                1,  // best
                c,  // leftChar
                c   // rightChar
            );

            return;
        }

        int mid = start + (end - start) / 2;

        // Build the left half.
        build(node * 2, start, mid);

        // Build the right half.
        build(node * 2 + 1, mid + 1, end);

        // Combine the two child summaries.
        tree[node] = merge(
            tree[node * 2],
            tree[node * 2 + 1]
        );
    }

    // ---------------------------------------------------------
    // MERGE
    // ---------------------------------------------------------

    private Node merge(Node left, Node right) {

        // Total interval length is the sum of child lengths.
        int length = left.length() + right.length();

        // The first character of the combined interval
        // always comes from the left child.
        char leftChar = left.leftChar();

        // The last character always comes from the right child.
        char rightChar = right.rightChar();

        // Initially, the combined prefix is the left prefix.
        int prefix = left.prefix();

        // We can extend the prefix into the right child only if:
        //
        // 1. The ENTIRE left child is one repeating character.
        // 2. The last character of left equals the first of right.
        //
        // left.prefix() == left.length() means the entire
        // left interval consists of the same character.
        if (left.prefix() == left.length()
                && left.rightChar() == right.leftChar()) {

            prefix += right.prefix();
        }

        // Initially, the combined suffix is the right suffix.
        int suffix = right.suffix();

        // We can extend the suffix into the left child only if:
        //
        // 1. The ENTIRE right child is one repeating character.
        // 2. The boundary characters match.
        if (right.suffix() == right.length()
                && left.rightChar() == right.leftChar()) {

            suffix += left.suffix();
        }

        // The longest repeating substring can be:
        //
        // 1. Completely inside the left child.
        // 2. Completely inside the right child.
        // 3. Crossing the boundary between the children.
        //
        // Initially consider the first two possibilities.
        int best = Math.max(left.best(), right.best());

        // If boundary characters match, the left suffix
        // and right prefix form one larger repeating substring.
        if (left.rightChar() == right.leftChar()) {

            int crossingLength =
                left.suffix() + right.prefix();

            best = Math.max(best, crossingLength);
        }

        // Return the summary of the combined interval.
        return new Node(
            length,
            prefix,
            suffix,
            best,
            leftChar,
            rightChar
        );
    }

    // ---------------------------------------------------------
    // POINT UPDATE
    // ---------------------------------------------------------

    private void update(
            int node,
            int start,
            int end,
            int index,
            char newChar) {

        // We have reached the leaf representing the target index.
        if (start == end) {

            // Update the actual string representation.
            chars[index] = newChar;

            // Rebuild the leaf summary.
            tree[node] = new Node(
                1,
                1,
                1,
                1,
                newChar,
                newChar
            );

            return;
        }

        int mid = start + (end - start) / 2;

        // Determine which child contains the target index.
        if (index <= mid) {

            update(
                node * 2,
                start,
                mid,
                index,
                newChar
            );

        } else {

            update(
                node * 2 + 1,
                mid + 1,
                end,
                index,
                newChar
            );
        }

        // Only ancestors of the updated leaf need recomputation.
        //
        // The unaffected child already contains a valid summary.
        // Re-merging the children updates all affected intervals.
        tree[node] = merge(
            tree[node * 2],
            tree[node * 2 + 1]
        );
    }
}

```

### **Complexity analysis**

Let:

- \\(n\\) = length of the original string.
- \\(k\\) = number of queries.

| Operation           | Time complexity  |
| ------------------- | ---------------- |
| Build segment tree  | \\(O(n)\\)       |
| One point update    | \\(O(\log n)\\)  |
| Read global maximum | \\(O(1)\\)       |
| Process all queries | \\(O(k\log n)\\) |

Total:

\\[ O(n+k\log n) \\]

Since \\(k\geq 1\\), this is commonly expressed as:

\\[ \boxed{O(n+k\log n)} \\]

Space:

- Character array: \\(O(n)\\).
- Segment tree: \\(O(n)\\).
- Answer array: \\(O(k)\\).
- Recursive call stack: \\(O(\log n)\\).

Therefore:

\\[ \boxed{O(n+k)\text{ auxiliary and output space}} \\]

The segment tree itself uses \\(O(n)\\) space.

## **6. Edge cases to watch out for**

| Edge case                       | Input / Situation                | Expected behavior                   |
| ------------------------------- | -------------------------------- | ----------------------------------- |
| Single character                | `"a"`                            | Answer is always 1                  |
| Entire string identical         | `"aaaaa"`                        | Answer is 5                         |
| All characters different        | `"abcde"`                        | Answer is 1                         |
| Update to same character        | `"aaaa"`, update index 2 to `a`  | Answer remains 4                    |
| Merge across boundary           | `"aabb"`                         | Correctly combine suffix and prefix |
| Update breaks longest group     | `"aaaaab"` → index 2 becomes `b` | Recompute affected ancestors        |
| Multiple updates at same index  | Update index 1 repeatedly        | Always use latest character         |
| Longest group at right boundary | `"abcccc"`                       | Answer is 4                         |
| Longest group at left boundary  | `"ccccab"`                       | Answer is 4                         |

**Important implementation detail:** Always compare boundary characters before combining suffix and prefix.

Also, never assume that the longest repeating substring must be located at the root's left or right child. It can be entirely inside any subtree or cross the boundary between two children.

## **7. Alternative: Iterative Segment Tree**

An interviewer might ask whether we can implement this without recursive build and update operations.

Yes.

We can use an iterative segment tree with leaves beginning at index `n`.

The same `merge()` operation applies.

The important difference is that after updating one leaf, we repeatedly move toward the root:

```java
class Solution {

    private record Node(
        int length,
        int prefix,
        int suffix,
        int best,
        char leftChar,
        char rightChar
    ) {}

    private Node[] tree;
    private int n;

    public int[] longestRepeating(
            String s,
            String queryCharacters,
            int[] queryIndices) {

        n = s.length();

        // Iterative segment tree.
        tree = new Node[2 * n];

        char[] chars = s.toCharArray();

        // Initialize leaves.
        for (int i = 0; i < n; i++) {

            char c = chars[i];

            tree[n + i] = new Node(
                1, 1, 1, 1, c, c
            );
        }

        // Build internal nodes from bottom to top.
        for (int i = n - 1; i >= 1; i--) {

            tree[i] = merge(
                tree[i * 2],
                tree[i * 2 + 1]
            );
        }

        int k = queryIndices.length;
        int[] answer = new int[k];

        for (int q = 0; q < k; q++) {

            int index = queryIndices[q];
            char c = queryCharacters.charAt(q);

            // Update the leaf.
            int pos = n + index;

            tree[pos] = new Node(
                1, 1, 1, 1, c, c
            );

            // Recompute all ancestors.
            for (pos /= 2; pos >= 1; pos /= 2) {

                tree[pos] = merge(
                    tree[pos * 2],
                    tree[pos * 2 + 1]
                );
            }

            // Root stores the global maximum.
            answer[q] = tree[1].best();
        }

        return answer;
    }

    private Node merge(Node left, Node right) {

        int length = left.length() + right.length();

        boolean matches =
            left.rightChar() == right.leftChar();

        int prefix = left.prefix();

        if (matches && left.prefix() == left.length()) {
            prefix += right.prefix();
        }

        int suffix = right.suffix();

        if (matches && right.suffix() == right.length()) {
            suffix += left.suffix();
        }

        int best = Math.max(left.best(), right.best());

        if (matches) {
            best = Math.max(
                best,
                left.suffix() + right.prefix()
            );
        }

        return new Node(
            length,
            prefix,
            suffix,
            best,
            left.leftChar(),
            right.rightChar()
        );
    }
}
```

**Complexity:**

- Build: \\(O(n)\\).
- Update: \\(O(\log n)\\).
- Answer retrieval: \\(O(1)\\).
- Total: \\(O(n+k\log n)\\).
- Space: \\(O(n+k)\\), including the answer array.

Note: This compact iterative implementation uses the standard `2*n` layout. For non-power-of-two sizes, its internal node layout does not always represent contiguous intervals in the intuitive recursive order. Because our merge operation is not commutative, an iterative implementation needs an order-preserving layout or a power-of-two padded tree. The recursive implementation above avoids this complication and is the safer interview solution.

# **8. Interviewer follow-up questions and answers**

### **Q1. Why can't we store only&#x20;**`best`**&#x20;in each segment tree node?**

Because we need to know whether repeating substrings can be combined across the boundary.

For example:

```
Left:  aaabb
Right: bbccc
```

The longest substring crossing the boundary depends on:

```
left.suffix + right.prefix
```

Without prefix and suffix information, we cannot calculate the combined answer.

### **Q2. Why do we need&#x20;**`leftChar`**&#x20;and&#x20;**`rightChar`**?**

They determine whether the suffix of the left interval and prefix of the right interval contain the same character.

We can merge them only when:

```
left.rightChar() == right.leftChar()
```

### **Q3. Why is the prefix condition&#x20;**`left.prefix() == left.length()`**?**

Suppose:

```
Left  = "aaabb"
Right = "bbccc"
```

The left prefix is `"aaa"`.

We cannot extend that prefix into the right interval because the left interval is not entirely made of `a`.

Only when the entire left interval consists of the same character can its prefix extend into the right interval.

### **Q4. Why is the answer available at the root?**

The root represents the complete interval:

\\[ [0,n-1] \\]

Its `best` property stores the longest repeating substring anywhere in the entire string.

Therefore:

```
answer[q] = tree[1].best();
```

No separate range query is necessary.

### **Q5. Can we use a Fenwick Tree (BIT)?**

A standard Fenwick Tree is designed around associative operations such as sum.

Here, we need to maintain a richer summary involving:

- Prefix.
- Suffix.
- Maximum repeating substring.
- Boundary characters.

A segment tree naturally supports this custom merge operation.

A Fenwick Tree is not a straightforward replacement.

### **Q6. Is the merge operation associative?**

Yes.

Our node represents a summary of a contiguous string.

Merging two nodes produces exactly the summary of their concatenated strings.

For three adjacent segments \\(A,B,C\\):

\\[ merge(merge(A,B),C) = merge(A,merge(B,C)) \\]

Both sides summarize the same concatenated string \\(ABC\\).

This associativity is what makes segment trees possible.

### **Q7. Can we optimize updates when the character does not change?**

Yes.

Before updating:

```
if (chars[index] == newChar) {
    answer[q] = tree[1].best();
    continue;
}
```

This avoids unnecessary tree modifications.

It does not improve worst-case complexity, but it can improve practical performance when many queries repeat the existing character.

### **Q8. What if the problem asks for the longest repeating substring only within a given range&#x20;**`[l, r]`**?**

We can extend the segment tree with a range query.

The query returns a `Node` summary for the requested interval.

We merge partial results in their original left-to-right order.

The answer is:

```
rangeQuery(l, r).best()
```

Each range query takes \\(O(\log n)\\).

### **Q9. Why not use a TreeMap to maintain repeating intervals?**

We could maintain maximal intervals of identical characters.

However, an update can split one interval and merge neighboring intervals. Maintaining the global maximum would also require another ordered structure.

This approach is possible but considerably more complicated.

The segment tree provides a cleaner and more predictable \\(O(\log n)\\) update.

## **9. Final interview takeaway**

The most important lesson from this problem is not simply how to implement a segment tree.

It is how to **design the information stored inside a segment tree node**.

Whenever a problem asks you to maintain a property over a range under point updates, ask yourself:

1. What information about a segment is sufficient to describe its answer?
2. Can I combine the information from two adjacent segments?
3. Can I calculate the combined answer in constant time?

For this problem, the answer is:

```
Node:
    length
    prefix
    suffix
    best
    leftChar
    rightChar
```

And the most important merge formula is:

\\[ \boxed{ best = \max(left.best,\ right.best,\ left.suffix+right.prefix) } \\]

The cross-boundary term is considered only when the boundary characters match.

**Remember this pattern:** Segment Tree + custom associative merge is extremely powerful for dynamic string and array problems.
