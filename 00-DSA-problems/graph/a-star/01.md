# **A\* Search – Shortest Path in a Binary Grid**

## **0. Simplify the problem statement**

We are given an `m × n` grid:

- `0` means we can walk through the cell.
- `1` means the cell is blocked.
- Start at `(0, 0)`.
- Reach `(m - 1, n - 1)`.
- We can move in four directions: up, down, left, right.
- Every move costs `1`.

Return:

- The minimum number of moves required to reach the destination.
- `-1` if no valid path exists.

**Important:** We must use A\* with the Manhattan distance heuristic.

For example:

```
grid = [
    [0, 0, 1, 0],
    [1, 0, 1, 0],
    [0, 0, 0, 0],
    [1, 1, 1, 0]
]
```

One shortest path is:

```
S  *  #  .
#  *  #  .
.  *  *  *
#  #  #  G
```

The shortest path costs `6`.

## **1. Clarifying questions to ask the interviewer**

| Question                                         | Why clarify?                                      |
| ------------------------------------------------ | ------------------------------------------------- |
| Are movements restricted to four directions?     | Determines the neighbors of each cell.            |
| Is the cost of every move exactly 1?             | Determines whether BFS or A\* is appropriate.     |
| Are start and destination guaranteed to be open? | Avoids additional validation logic.               |
| Should we return the path or only its cost?      | Determines whether parent pointers are necessary. |
| Can the grid contain up to 1000 × 1000 cells?    | Determines memory and performance requirements.   |

We assume:

- Four-directional movement.
- Every move costs `1`.
- Start and destination are open.
- Only the minimum cost is required.

## **2. Core idea – A\* Search**

### **Mental model**

Think of A\* as an intelligent version of Dijkstra's algorithm.

Dijkstra explores nodes based on the cost already spent.

A\* considers two things:

1. How much have we already spent?
2. How far do we estimate the destination is?

A\* uses:

\\[ f(x) = g(x) + h(x) \\]

Where:

- `g(x)` = actual cost from the start to the current cell.
- `h(x)` = estimated cost from the current cell to the destination.
- `f(x)` = estimated total cost of the complete path.

We always explore the cell having the smallest `f(x)`.

### **Manhattan distance heuristic**

Since movement is restricted to four directions, Manhattan distance is ideal.

For current cell `(r, c)` and destination `(m-1, n-1)`:

\\[ h(r,c) = |r-(m-1)| + |c-(n-1)| \\]

Why does this work?

Suppose we are at `(2, 3)` and the destination is `(5, 7)`.

We need:

- `3` downward moves.
- `4` rightward moves.

Therefore:

\\[ h = 3 + 4 = 7 \\]

Even without considering walls, we need at least 7 moves.

Walls can increase the actual distance, but they cannot make it smaller.

**This is why Manhattan distance is admissible:** it never overestimates the actual shortest remaining distance.

It is also consistent, which allows us to use A\* efficiently.

## **3. Edge cases**

| Case                       | Expected behavior                                                    |
| -------------------------- | -------------------------------------------------------------------- |
| `1 × 1` grid               | Return `0`.                                                          |
| Single row                 | Move horizontally if no walls.                                       |
| Single column              | Move vertically if no walls.                                         |
| Destination unreachable    | Return `-1`.                                                         |
| Obstacles force a detour   | A\* must find the longer valid route.                                |
| Multiple shortest paths    | Return the same minimum cost.                                        |
| Large grid (`1000 × 1000`) | Must avoid unnecessary object allocation and excessive memory usage. |

# **4. Solutions – Brute force to optimal**

## **Approach 1: DFS – Explore all possible paths**

The simplest approach is DFS.

We recursively explore every possible path until we reach the destination.

We maintain the minimum path cost encountered.

**Why is it inefficient?**

The same cell can be visited through many different paths.

The number of possible paths can grow exponentially.

```java
class Solution {

    private int minCost = Integer.MAX_VALUE;

    public int shortestPath(int[][] grid) {

        int m = grid.length;
        int n = grid[0].length;

        boolean[][] visited = new boolean[m][n];

        dfs(grid, 0, 0, 0, visited);

        return minCost == Integer.MAX_VALUE ? -1 : minCost;
    }

    private void dfs(
            int[][] grid,
            int r,
            int c,
            int cost,
            boolean[][] visited
    ) {

        /*
         * WHY: We cannot improve an already discovered answer
         * if the current path has reached or exceeded its cost.
         *
         * This is a basic branch-and-bound optimization.
         */
        if (cost >= minCost) {
            return;
        }

        int m = grid.length;
        int n = grid[0].length;

        /*
         * WHY: Reaching the destination means we have found
         * a complete valid path.
         */
        if (r == m - 1 && c == n - 1) {
            minCost = cost;
            return;
        }

        visited[r][c] = true;

        int[][] directions = {
                {0, 1},
                {0, -1},
                {1, 0},
                {-1, 0}
        };

        for (int[] dir : directions) {

            int nr = r + dir[0];
            int nc = c + dir[1];

            /*
             * WHY: A neighbor must be:
             * 1. Inside the grid.
             * 2. An open cell.
             * 3. Not already visited in this current path.
             */
            if (nr >= 0 && nr < m &&
                nc >= 0 && nc < n &&
                grid[nr][nc] == 0 &&
                !visited[nr][nc]) {

                dfs(
                        grid,
                        nr,
                        nc,
                        cost + 1,
                        visited
                );
            }
        }

        /*
         * WHY: Backtracking allows this cell to participate
         * in other possible paths.
         */
        visited[r][c] = false;
    }
}
```

**Complexity:**

- Time: Exponential in the number of cells in the worst case.
- Space: `O(m × n)` for visited and recursion stack.

Not suitable for a `1000 × 1000` grid.

## **Approach 2: BFS – Shortest path in an unweighted grid**

Before understanding A\*, understand BFS.

Since every move costs exactly `1`, BFS naturally finds the shortest path.

BFS explores cells level by level.

```
Level 0: Start
Level 1: All cells 1 step away
Level 2: All cells 2 steps away
Level 3: All cells 3 steps away
```

The first time we reach the destination, we have found the shortest path.

```java
import java.util.*;

class Solution {

    private static final int[][] DIRS = {
            {0, 1},
            {0, -1},
            {1, 0},
            {-1, 0}
    };

    public int shortestPath(int[][] grid) {

        int m = grid.length;
        int n = grid[0].length;

        /*
         * WHY: BFS uses a queue to process cells in increasing
         * order of distance from the start.
         */
        Queue<int[]> queue = new ArrayDeque<>();

        /*
         * WHY: visited prevents processing the same cell repeatedly.
         */
        boolean[][] visited = new boolean[m][n];

        queue.offer(new int[]{0, 0, 0});
        visited[0][0] = true;

        while (!queue.isEmpty()) {

            int[] current = queue.poll();

            int r = current[0];
            int c = current[1];
            int distance = current[2];

            /*
             * WHY: BFS processes cells in non-decreasing distance.
             * Therefore, the first time we reach the destination,
             * its distance is guaranteed to be optimal.
             */
            if (r == m - 1 && c == n - 1) {
                return distance;
            }

            for (int[] dir : DIRS) {

                int nr = r + dir[0];
                int nc = c + dir[1];

                if (nr < 0 || nr >= m ||
                    nc < 0 || nc >= n) {
                    continue;
                }

                if (grid[nr][nc] == 1 || visited[nr][nc]) {
                    continue;
                }

                visited[nr][nc] = true;

                queue.offer(new int[]{
                        nr,
                        nc,
                        distance + 1
                });
            }
        }

        return -1;
    }
}
```

**Complexity:**

Let `V = m × n` and `E` be the number of grid edges.

- Time: `O(V + E) = O(m × n)`.
- Space: `O(m × n)`.

For this particular problem, BFS is already asymptotically optimal.

However, the interviewer explicitly asks us to use A\*.

## **Approach 3: A\* Search – Optimal requested solution**

### **Important data structure**

We need a `PriorityQueue`.

Each entry represents a cell and stores:

- `row`
- `col`
- `g`: actual distance from start.
- `f`: `g + h`.

We can use a Java record to represent a search state.

### **Java 24 implementation**

```java
import java.util.*;

class Solution {

    /*
     * A search state represents one candidate cell.
     *
     * row, col = Current cell coordinates.
     * g        = Actual cost from start to this cell.
     * f        = g + h, estimated total path cost.
     *
     * Records are useful because search states are immutable
     * and we want a concise data carrier.
     */
    private record State(
            int row,
            int col,
            int g,
            int f
    ) {}

    /*
     * Four possible movement directions:
     * Right, Left, Down, Up.
     */
    private static final int[][] DIRS = {
            {0, 1},
            {0, -1},
            {1, 0},
            {-1, 0}
    };

    public int shortestPath(int[][] grid) {

        int m = grid.length;
        int n = grid[0].length;

        /*
         * WHY: We need the best known actual distance from
         * the start to every cell.
         *
         * Initially, every cell is considered unreachable.
         */
        int[][] dist = new int[m][n];

        for (int[] row : dist) {
            Arrays.fill(row, Integer.MAX_VALUE);
        }

        /*
         * WHY: A* must always expand the state with the
         * smallest estimated total cost f = g + h.
         *
         * Java PriorityQueue is a min-heap when we use
         * Comparator.comparingInt.
         *
         * The comparison is O(log V) per insertion/removal.
         */
        PriorityQueue<State> pq = new PriorityQueue<>(
                Comparator.comparingInt(State::f)
        );

        /*
         * WHY: Starting cell has actual cost 0.
         *
         * Manhattan distance provides the initial heuristic.
         */
        dist[0][0] = 0;

        pq.offer(new State(
                0,
                0,
                0,
                heuristic(0, 0, m, n)
        ));

        while (!pq.isEmpty()) {

            /*
             * WHY: Expand the state having the smallest f value.
             */
            State current = pq.poll();

            int r = current.row();
            int c = current.col();
            int g = current.g();

            /*
             * WHY: PriorityQueue does not support decrease-key.
             *
             * Therefore, when we discover a better path to a cell,
             * we insert a new state instead of updating the old one.
             *
             * This can leave outdated states in the queue.
             *
             * We skip them here.
             */
            if (g != dist[r][c]) {
                continue;
            }

            /*
             * WHY: Manhattan distance is admissible and consistent.
             * With these properties, when the destination is removed
             * from the priority queue with its current best g value,
             * that g value is the shortest possible path cost.
             *
             * Therefore, we can return immediately.
             */
            if (r == m - 1 && c == n - 1) {
                return g;
            }

            /*
             * Explore all four neighboring cells.
             */
            for (int[] dir : DIRS) {

                int nr = r + dir[0];
                int nc = c + dir[1];

                /*
                 * WHY: Ignore coordinates outside the grid.
                 */
                if (nr < 0 || nr >= m ||
                    nc < 0 || nc >= n) {
                    continue;
                }

                /*
                 * WHY: Walls cannot be traversed.
                 */
                if (grid[nr][nc] == 1) {
                    continue;
                }

                /*
                 * WHY: Every movement costs exactly 1.
                 *
                 * So the candidate distance is current g + 1.
                 */
                int newG = g + 1;

                /*
                 * WHY: Only update a cell if we found a strictly
                 * better path to it.
                 *
                 * This avoids unnecessary queue insertions.
                 */
                if (newG < dist[nr][nc]) {

                    dist[nr][nc] = newG;

                    /*
                     * Calculate:
                     *
                     * h = Manhattan distance to destination.
                     * f = g + h.
                     */
                    int h = heuristic(nr, nc, m, n);

                    int f = newG + h;

                    /*
                     * Insert the improved state.
                     */
                    pq.offer(new State(
                            nr,
                            nc,
                            newG,
                            f
                    ));
                }
            }
        }

        /*
         * WHY: If the queue becomes empty, every reachable cell
         * has been explored and the destination was never reached.
         */
        return -1;
    }

    /*
     * Manhattan distance:
     *
     * h(r, c) = |r - goalRow| + |c - goalCol|
     *
     * WHY is this admissible?
     *
     * We can only move horizontally or vertically.
     *
     * Therefore, we must make at least:
     * - |r - goalRow| vertical moves.
     * - |c - goalCol| horizontal moves.
     *
     * Obstacles can increase the required distance,
     * but cannot decrease it.
     *
     * Hence, h never overestimates the actual shortest distance.
     *
     * WHY is it consistent?
     *
     * For every neighboring cell u and v:
     *
     * h(u) <= cost(u, v) + h(v)
     *
     * Since one move changes Manhattan distance by at most 1,
     * this condition always holds.
     */
    private int heuristic(
            int r,
            int c,
            int m,
            int n
    ) {

        return Math.abs(r - (m - 1))
                + Math.abs(c - (n - 1));
    }
}
```

### **Complexity analysis**

Let:

- `V = m × n` be the number of cells.
- `E` be the number of possible grid edges.
- Each cell has at most four neighbors, so `E = O(V)`.

**Time complexity:**

- Initializing the distance matrix: `O(V)`.
- Each successful relaxation inserts a state into the priority queue.
- Each state expansion examines at most four neighbors.
- Priority queue insertion and removal cost `O(log V)` per operation.

Under this implementation, each directed edge can cause at most one successful relaxation per expansion of its source, and each cell's outgoing edges are processed when its current best state is expanded. With consistent Manhattan heuristic and stale-state skipping, each cell is expanded at most once at its best distance.

Therefore:

\\[ \boxed{O(V \log V)} \\]

Equivalently:

\\[ \boxed{O(mn \log(mn))} \\]

**Space complexity:**

- Distance matrix: `O(m × n)`.
- Priority queue: `O(m × n)` under consistent heuristic and stale-state skipping.
- Directions: `O(1)`.

Therefore:

\\[ \boxed{O(mn)} \\]

This meets the required complexity.

# **6. Interviewer follow-up questions**

### **Q1. Why use A\* instead of Dijkstra?**

Dijkstra prioritizes only actual distance:

\\[ f(n)=g(n) \\]

A\* prioritizes actual distance plus estimated remaining distance:

\\[ f(n)=g(n)+h(n) \\]

A\* uses goal-directed information to guide exploration.

It often explores fewer cells in practice, although its worst-case complexity remains `O(V log V)`.

### **Q2. Why is Manhattan distance appropriate?**

Because movement is restricted to four directions.

Each movement changes either the row or column by exactly one.

Manhattan distance gives a lower bound on the number of remaining moves.

### **Q3. What if diagonal movement is allowed?**

Manhattan distance is no longer the appropriate heuristic when diagonal movement costs 1.

For unrestricted diagonal movement with equal diagonal and straight costs, use Chebyshev distance:

\\[ h = \max(|r-r_g|, |c-c_g|) \\]

If diagonal movement costs \\(\sqrt{2}\\) and straight movement costs `1`, use the octile distance:

\\[ h = \max(dx,dy)+(\sqrt{2}-1)\min(dx,dy) \\]

### **Q4. What if the heuristic is always zero?**

Then:

\\[ f(n)=g(n) \\]

A\* becomes Dijkstra's algorithm.

### **Q5. What happens if the heuristic overestimates?**

A\* may return a non-optimal path because it might prioritize a path that only appears promising due to an inaccurate heuristic.

To guarantee optimality, use an admissible heuristic.

### **Q6. Why do we need the&#x20;**`dist`**&#x20;matrix?**

It tracks the best known actual cost to each cell.

Without it, we might repeatedly insert and process worse paths to the same cell.

### **Q7. Why do we skip stale priority queue entries?**

Java's `PriorityQueue` does not support decrease-key.

When a better distance is discovered, we insert a new entry.

The old entry remains in the queue.

This check:

```
if (g != dist[r][c]) {
    continue;
}
```

ensures that outdated entries are ignored.

### **Q8. Can A\* guarantee fewer visited cells than BFS?**

No.

A\* is often faster in practice because the heuristic guides exploration toward the destination.

However, depending on the grid structure, it can explore as many cells as BFS or even incur additional priority-queue overhead.

### **Q9. Can we optimize memory further?**

Yes.

Instead of storing `State` objects, we can encode coordinates into a single integer:

```
int id = row * n + col;
```

We can also use primitive arrays for distances and a custom primitive heap to reduce object allocation.

This can be useful for a million-cell grid.

## **7. Final interview comparison**

| Approach | Time            | Space   | Optimal?                       |
| -------- | --------------- | ------- | ------------------------------ |
| DFS      | Exponential     | `O(mn)` | Yes, if exhaustive             |
| BFS      | `O(mn)`         | `O(mn)` | Yes                            |
| Dijkstra | `O(mn log(mn))` | `O(mn)` | Yes                            |
| A\*      | `O(mn log(mn))` | `O(mn)` | Yes, with admissible heuristic |

**Senior interviewer takeaway:**

For this exact problem, BFS is theoretically more efficient because all edges have equal weight.

However, when the interviewer explicitly requests A\*, demonstrate that you understand:

1. `g(n)` – actual cost so far.
2. `h(n)` – estimated remaining cost.
3. `f(n) = g(n) + h(n)` – priority for exploration.
4. Manhattan distance – admissible and consistent heuristic.
5. Stale-entry handling – necessary because Java's priority queue has no decrease-key operation.

The key distinction: *BFS explores uniformly in all directions; A uses the destination to guide its search.*\*
