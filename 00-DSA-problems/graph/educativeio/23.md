This is a very good example of **0-1 BFS**. The important part is not just knowing the template, but understanding **why changing the grid problem into a weighted graph gives edge weights of exactly `0` or `1`**.

---

# 1. First understand the problem

Consider:

```text
grid =
[
    [1, 1, 3],
    [3, 2, 3],
    [1, 1, 4]
]
```

The meaning is:

```text
1 → →
2 → ←
3 → ↓
4 → ↑
```

So:

```text
(0,0) --→ (0,1) --→ (0,2)
                         |
                         ↓
                       (1,2)
                         |
                         ↓
                       (2,2)
```

If every move follows the sign, the cost is `0`.

But suppose a cell points in the wrong direction.

For example:

```text
grid[0][0] = 1
```

means:

```text
(0,0) → (0,1)
```

Moving right costs:

```text
0
```

because we follow the existing sign.

But moving down:

```text
(0,0)
   |
   ↓
(1,0)
```

would require changing the sign from:

```text
→
```

to:

```text
↓
```

so that move costs:

```text
1
```

Therefore every possible movement has one of two costs:

```text
follow existing sign → 0
change sign           → 1
```

And **that is exactly the situation where 0-1 BFS is useful.**

---

# 2. Convert the grid into a graph

Think of every cell as a graph node.

For example:

```text
(0,0) ---- (0,1)
  |           |
  |           |
(1,0) ---- (1,1)
```

From every cell, we can potentially move to its four neighboring cells.

For example, from:

```text
(r,c)
```

we can try:

```text
       up
        ↑
left ← (r,c) → right
        ↓
       down
```

The edge cost depends on the sign in the **current cell**.

Suppose:

```text
grid[r][c] = 1
```

Then:

```text
right → cost 0
left  → cost 1
down  → cost 1
up    → cost 1
```

If:

```text
grid[r][c] = 3
```

then:

```text
down  → cost 0
right → cost 1
left  → cost 1
up    → cost 1
```

So the graph contains edges with:

```text
weight ∈ {0, 1}
```

---

# 3. Why not normal BFS?

Normal BFS assumes every edge has the same cost:

```text
A --1--> B --1--> C
```

So:

```text
number of edges = total cost
```

But here:

```text
A --0--> B --1--> C
```

has total cost:

```text
0 + 1 = 1
```

while:

```text
A --1--> D --1--> C
```

has:

```text
1 + 1 = 2
```

Both paths contain two edges, but their costs are different.

Therefore normal BFS is not sufficient.

---

# 4. Why not Dijkstra?

Dijkstra **would work**.

We have non-negative edge weights:

```text
0 or 1
```

So we could use:

```text
PriorityQueue
```

and run Dijkstra.

But because the only possible weights are `0` and `1`, we can exploit that special structure.

That's where **0-1 BFS** comes in.

---

# 5. The key idea of 0-1 BFS

Suppose we are currently processing:

```text
A
```

and we have:

```text
A --0--> B
A --1--> C
```

If we reach:

```text
A
```

with cost:

```text
5
```

then:

```text
B = 5
C = 6
```

Clearly we want to process `B` first.

So:

```text
cost 0 → front of deque
cost 1 → back of deque
```

That's the entire trick:

```text
             cost 0
current ─────────────→ next
             ↑
          front

             cost 1
current ─────────────→ next
             ↑
           back
```

The deque acts like a specialized priority queue.

# 6. Your code step by step

Let's look at the important pieces.

## Directions

You have:

private static final int[][] DIRS = {
        {0, 1},   // 1 → Right
        {0, -1},  // 2 → Left
        {1, 0},   // 3 → Down

This is a nice mapping because the direction number directly corresponds to the index:

```text

d = 1 → left  → direction value 2

d = 3 → up    → direction value 4
```

Therefore:

```java
grid[r][c] == d + 1
```

means:

> Does the current cell's sign point toward the neighbor we're considering?

# 7. `dist` stores the real thing we're optimizing

```java
int[][] dist = new int[m][n];
```

Meaning:

```text
dist[r][c] =
minimum number of sign changes required to reach (r,c)
```

Initially:

```text
∞
∞
∞
```

because we haven't reached anything.

Then:

```java
dist[0][0] = 0;
```

because we're already at the starting cell.

# 8. Why use a `Deque`?

```java
Deque<int[]> deque = new ArrayDeque<>();
```

Unlike normal BFS:

```java
queue.offer(...)
queue.poll()
```

we need both ends:

```java
offerFirst()
offerLast()

pollFirst()
```

Because:

```text
0-cost edge → front
1-cost edge → back
```

# 9. The most important line

This:

```java
int cost = (grid[r][c] == d + 1) ? 0 : 1;
```

is basically the entire problem.

Suppose:

```text
grid[r][c] = 3
```

and we're trying direction:

```text
d = 2
```

Since:

```text
d + 1 = 3
```

we get:

```text
cost = 0
```

We're following the existing sign.

But if:

```text
d = 0
```

then:

```text
d + 1 = 1
```

and:

```text
grid[r][c] != 1
```

so:

```text
cost = 1
```

We need to modify the sign.

---

# 10. Relaxation

This is standard shortest-path relaxation:

```java
if (dist[r][c] + cost < dist[nr][nc]) {
    dist[nr][nc] = dist[r][c] + cost;
}
```

Suppose:

```text
dist[r][c] = 3
```

and:

```text
cost = 1
```

Then:

```text
newCost = 4
```

If we previously knew:

```text
dist[nr][nc] = 7
```

then:

```text
4 < 7
```

so we found a better path.

Update:

```text
dist[nr][nc] = 4
```

---

# 11. Why `offerFirst` for 0 and `offerLast` for 1?

This:

```java
if (cost == 0) {
    deque.offerFirst(new int[]{nr, nc});
} else {
    deque.offerLast(new int[]{nr, nc});
}
```

is what makes this **0-1 BFS**.

Imagine:

```text
deque:

[ A, B, C ]
```

We discover:

```text
D with cost 0
```

Put it at the front:

```text
[ D, A, B, C ]
```

But if we discover:

```text
E with cost 1
```

put it at the back:

```text
[ D, A, B, C, E ]
```

So zero-cost paths are explored before paths that require an additional modification.

# 12. A concrete example

Consider:

```text
grid =
[
    [1, 1, 3],
    [3, 2, 2],
    [1, 1, 4]
]
```

We start:

```text
(0,0)
```

Its sign is:

```text
1 → right
```

So:

```text
(0,0) → (0,1)
```

cost:

```text
0
```

Therefore:

```text
dist[0][1] = 0
```

and `(0,1)` goes to the front.

Now:

```text
(0,1)
```

also points right:

```text
(0,1) → (0,2)
```

cost:

```text
0
```

Again, front.

Eventually we may encounter a cell whose sign doesn't point toward the direction needed to continue.

We pay:

```text
+1
```

and put that state at the back.

The algorithm therefore naturally searches for:

```text
path with 0 changes
       ↓
path with 1 change
       ↓
path with 2 changes
       ↓
...
```

while still being more efficient than explicitly trying every possible path.

---

# 13. Why changing a cell only once is naturally handled

The statement says a sign can be modified only once.

At first this might sound like we need to track:

```text
which cells have already been modified
```

But we don't.

Why?

Because we're not constructing multiple modifications to the **same cell** during one path.

When we move:

```text
(r,c) → (nr,nc)
```

the cost is simply:

```text
0 = use existing direction
1 = change this cell's direction
```

Once we leave `(r,c)`, that decision is already accounted for.

For example:

```text
A → B
```

If we choose a direction from `A` that costs `1`, we've paid for changing `A`.

There's no reason to later pay again for changing `A` because the path has already moved beyond it.

So the state does **not** need:

```text
modifiedCells
```

The shortest-path formulation handles this naturally.

---

# 14. Why we can consider all four directions

A common question is:

> "If the sign says right, why are we allowed to move down?"

Because we're allowed to **modify the sign**.

Suppose:

```text
grid[r][c] = 1
```

means:

```text
→
```

If we want to go:

```text
↓
```

we conceptually change:

```text
→
```

into:

```text
↓
```

and pay:

```text
1
```

Therefore every valid neighboring cell is a possible graph edge.

# 15. A cleaner version of your code

I'd write it like this for interview/learning purposes:

```java
import java.util.*;

/**
 * Minimum Cost to Make at Least One Valid Path
 *
 * ------------------------------------------------------------
 * Core idea: 0-1 BFS
 * ------------------------------------------------------------
 *
 * Each grid cell is a graph node.
 *
 * From every cell we can move to its valid neighboring cells.
 *
 * Moving in the direction already specified by the sign:
 *
 *     cost = 0
 *
 * Moving in any other direction means changing the sign:
 *
 *     cost = 1
 *
 * Therefore every graph edge has weight 0 or 1.
 *
 * For graphs whose edge weights are only 0 and 1,
 * 0-1 BFS is more specialized than Dijkstra.
 *
 * ------------------------------------------------------------
 *
 * dist[row][column] =
 *     minimum number of sign changes required to reach
 *     this cell from (0, 0).
 *
 * Deque rule:
 *
 *     edge cost 0 -> add to FRONT
 *     edge cost 1 -> add to BACK
 */
public class MinimumCostGridPath {

    /*
     * Direction index + 1 corresponds to the value
     * stored in the grid.
     *
     * index 0 -> grid value 1 -> right
     * index 1 -> grid value 2 -> left
     * index 2 -> grid value 3 -> down
     * index 3 -> grid value 4 -> up
     */
    private static final int[][] DIRECTIONS = {
        {0, 1},    // 1: right
        {0, -1},   // 2: left
        {1, 0},    // 3: down
        {-1, 0}    // 4: up
    };

    public int minCost(int[][] grid) {

        int rows = grid.length;
        int columns = grid[0].length;

        /*
         * dist[row][column] stores the minimum number
         * of sign changes needed to reach this cell.
         */
        int[][] minimumCost = new int[rows][columns];

        for (int[] row : minimumCost) {
            Arrays.fill(row, Integer.MAX_VALUE);
        }

        /*
         * 0-1 BFS uses a deque instead of a normal queue.
         */
        Deque<int[]> deque = new ArrayDeque<>();

        /*
         * Starting cell requires zero modifications.
         */
        minimumCost[0][0] = 0;

        deque.offerFirst(new int[]{0, 0});

        while (!deque.isEmpty()) {

            int[] current = deque.pollFirst();

            int currentRow = current[0];
            int currentColumn = current[1];

            int currentCost =
                    minimumCost[currentRow][currentColumn];

            /*
             * Try all four possible neighboring cells.
             */
            for (int direction = 0;
                 direction < 4;
                 direction++) {

                int nextRow =
                        currentRow + DIRECTIONS[direction][0];

                int nextColumn =
                        currentColumn + DIRECTIONS[direction][1];

                /*
                 * Ignore moves outside the grid.
                 */
                if (nextRow < 0 ||
                    nextRow >= rows ||
                    nextColumn < 0 ||
                    nextColumn >= columns) {

                    continue;
                }

                /*
                 * direction + 1 is the actual grid sign.
                 *
                 * If it matches the sign already present
                 * in the current cell:
                 *
                 *     no modification needed -> cost 0
                 *
                 * Otherwise:
                 *
                 *     modify the sign -> cost 1
                 */
                int modificationCost =
                        (grid[currentRow][currentColumn]
                                == direction + 1)
                                ? 0
                                : 1;

                int newCost =
                        currentCost + modificationCost;

                /*
                 * Standard shortest-path relaxation.
                 */
                if (newCost < minimumCost[nextRow][nextColumn]) {

                    minimumCost[nextRow][nextColumn] = newCost;

                    /*
                     * A zero-cost move should be processed
                     * as soon as possible.
                     */
                    if (modificationCost == 0) {

                        deque.offerFirst(
                                new int[]{nextRow, nextColumn});

                    } else {

                        /*
                         * A cost-1 move is lower priority,
                         * so put it at the back.
                         */
                        deque.offerLast(
                                new int[]{nextRow, nextColumn});
                    }
                }
            }
        }

        /*
         * Bottom-right cell contains the minimum number
         * of sign modifications required.
         */
        return minimumCost[rows - 1][columns - 1];
    }
}
```

# 16. Why does 0-1 BFS actually give the shortest cost?

This is the most important theoretical part.

Suppose the deque currently contains nodes whose distances look roughly like:

```text
front
 ↓

[ cost 3 ] [ cost 3 ] [ cost 3 ] [ cost 4 ] [ cost 4 ]

                                                ↑
                                               back
```

When we process a node with distance `3`:

### Following its sign

```text
3 + 0 = 3
```

The new node goes to the **front**.

So it gets processed before nodes with cost `4`.

### Changing its sign

```text
3 + 1 = 4
```

The new node goes to the **back**.

So it waits behind the current cost-3 work.

This maintains the important ordering:

```text
smaller distance
      ↓
processed earlier
```

That is exactly the property Dijkstra needs from its priority queue.

0-1 BFS achieves it using a deque because the only possible edge increments are:

```text
+0
+1
```

---

# 17. 0-1 BFS vs Dijkstra

The problem can actually be solved with Dijkstra too.

### Dijkstra

```text
PriorityQueue
```

Each node is ordered by:

```text
minimum known distance
```

Complexity:

```text
O((V + E) log V)
```

---

### 0-1 BFS

Uses:

```text
Deque
```

with:

```text
0 → front
1 → back
```

Complexity:

```text
O(V + E)
```

For this grid:

```text
V = m × n
```

Each cell has at most 4 outgoing edges:

```text
E ≈ 4mn
```

Therefore:

```text
Time:  O(mn)
Space: O(mn)
```

With:

```text
m,n <= 50
```

this is easily manageable.

# 18. The mental model to remember

When you see a problem like:

> "You can move normally for free, but changing something costs 1."

Immediately think:

```text
Can I model this as graph edges with weights 0 and 1?
```

If yes:

```text
             weights
               ↓
            { 0, 1 }
               ↓
           0-1 BFS
```

Examples:

```text
Follow existing direction → 0
Change direction          → 1
```

So this problem becomes:

```text
Grid
 ↓
Graph
 ↓
Each cell = node
 ↓
Each neighboring move = edge
 ↓
Correct sign = weight 0
Wrong sign = weight 1
 ↓
Shortest path
 ↓
0-1 BFS
```

And the key distinction from ordinary BFS is:

> **BFS minimizes number of edges. 0-1 BFS minimizes the sum of edge weights when every weight is 0 or 1.**
