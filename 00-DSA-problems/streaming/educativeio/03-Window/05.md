# **1825. Finding MK Average — Hard**

**Topics:** Design, Data Stream, Ordered Set, Sliding Window, TreeMap, Fenwick Tree

## **0. Simplify the problem statement**

We need to design a data structure that continuously receives integers and calculates a special average called **MKAverage**.

We are given:

- `m`: Consider only the most recent `m` elements.
- `k`: Remove the smallest `k` and largest `k` elements among those `m` elements.

The remaining number of elements is:

\\[ m-2k \\]

The MKAverage is:

\\[ MKAverage = \left\lfloor \frac{\text{sum of remaining elements}}{m-2k} \right\rfloor \\]

If fewer than `m` elements have arrived, return `-1`.

### **Example**

Suppose:

```
m = 5
k = 1

Stream = [3, 1, 10, 5, 5]
```

The latest five elements are:

```
[3, 1, 10, 5, 5]
```

Sort them:

```
[1, 3, 5, 5, 10]
```

Remove the smallest and largest:

```
[3, 5, 5]
```

Calculate:

```
(3 + 5 + 5) / 3 = 4
```

Answer:

```
4
```

The important challenge is that we need to perform this calculation efficiently after every insertion.

Re-sorting the latest `m` elements every time would be expensive.

## **1. Clarifying questions to ask the interviewer**

**Q1. Do we always consider exactly the most recent&#x20;**`m`**&#x20;elements?**

Why ask?

Because this determines whether we need a sliding window. When a new element arrives and the window is full, the oldest element must be removed.

**Q2. Can duplicate elements exist?**

Why ask?

Yes, duplicates are allowed. Our data structure must maintain frequencies rather than assume all elements are unique.

**Q3. Are elements bounded by a maximum value?**

Why ask?

The constraint says:

```
1 <= num <= 100000
```

This is extremely useful. We can use a Fenwick Tree (Binary Indexed Tree) over the value domain.

**Q4. Can calculateMKAverage() be called before we receive&#x20;**`m`**&#x20;elements?**

Yes. It must return `-1`.

**Q5. Can we use long for the sum?**

We should.

Maximum possible sum:

\\[ 100000 \times 100000 = 10^{10} \\]

This exceeds Java's `int` range.

# **2. Core intuition — Three partitions**

There are multiple ways to solve this problem.

The most intuitive optimal approach is to maintain three partitions of the latest `m` elements.

Imagine dividing the sorted window into three groups:

```
       Smallest k       Middle m-2k       Largest k

      ┌──────────┐    ┌──────────────┐    ┌──────────┐
      │  LOW     │    │    MID       │    │   HIGH   │
      │          │    │              │    │          │
      └──────────┘    └──────────────┘    └──────────┘
```

We maintain:

| Partition | Number of elements | Purpose                          |
| --------- | ------------------ | -------------------------------- |
| LOW       | k                  | Smallest elements                |
| MID       | m - 2k             | Elements contributing to average |
| HIGH      | k                  | Largest elements                 |

We also maintain:

```
long middleSum;
```

This is the sum of all elements in MID.

Therefore:

\\[ MKAverage = \left\lfloor \frac{middleSum}{m-2k} \right\rfloor \\]

We never need to calculate the sum again!

We only update `middleSum` when elements move between partitions.

### **What data structure should we use?**

Java's `TreeMap` is a good choice.

It maintains sorted keys and supports:

- `firstKey()` — smallest element.
- `lastKey()` — largest element.
- `pollFirstEntry()` — remove smallest element.
- `pollLastEntry()` — remove largest element.

However, we need duplicates.

So we maintain a multiset using:

```
TreeMap<Integer, Integer>
```

Where:

```
key   = number
value = frequency
```

For example:

```
{2=2, 5=3, 8=1}
```

Represents:

```
[2, 2, 5, 5, 5, 8]
```

# **3. Solution 1 — Brute Force**

### **Idea**

Maintain the last `m` elements using a queue.

Whenever `calculateMKAverage()` is called:

1. Check whether we have at least `m` elements.
2. Copy the latest `m` elements.
3. Sort them.
4. Remove the smallest `k` and largest `k`.
5. Calculate the average.

### **Java 24 implementation**

```java
import java.util.*;

class MKAverageBruteForce {

    private final int m;
    private final int k;

    // Stores the latest m elements.
    private final Deque<Integer> window = new ArrayDeque<>();

    public MKAverageBruteForce(int m, int k) {
        this.m = m;
        this.k = k;
    }

    public void addElement(int num) {

        // Add the newest element.
        window.offerLast(num);

        // Maintain a sliding window of size at most m.
        if (window.size() > m) {
            window.pollFirst();
        }
    }

    public int calculateMKAverage() {

        // We cannot calculate MKAverage until we have m elements.
        if (window.size() < m) {
            return -1;
        }

        // Copy the current window into an array.
        int[] arr = window.stream()
                .mapToInt(Integer::intValue)
                .toArray();

        // Sort all m elements.
        Arrays.sort(arr);

        long sum = 0;

        // Ignore the first k and last k elements.
        for (int i = k; i < m - k; i++) {
            sum += arr[i];
        }

        // Integer division automatically rounds down
        // because all values are positive.
        return (int) (sum / (m - 2 * k));
    }

    /*
     * TIME COMPLEXITY:
     *
     * addElement():
     * O(1)
     *
     * calculateMKAverage():
     * O(m log m) for sorting.
     *
     * SPACE COMPLEXITY:
     *
     * O(m) for storing the sliding window.
     *
     * This solution is simple but inefficient when calculateMKAverage()
     * is called frequently.
     */
}
```

### **Why is this not optimal?**

Suppose:

```
m = 100000
Number of operations = 100000
```

If every operation calculates the average, we repeatedly sort 100,000 elements.

That is too expensive.

We need to avoid sorting from scratch.

# **4. Solution 2 — Three TreeMap Multisets (Optimal interview approach)**

This solution maintains the three partitions directly.

### **Mental model**

We want to maintain this invariant:

```
LOW <= MID <= HIGH
```

More precisely:

```
Every element in LOW <= every element in MID
Every element in MID <= every element in HIGH
```

And:

```
LOW.size()  = k
MID.size()  = m - 2*k
HIGH.size() = k
```

We maintain three sums:

```
long lowSum;
long middleSum;
long highSum;
```

Only `middleSum` is needed for the answer, but maintaining all three helps make updates easier to reason about.

### **Important helper operations**

We need four operations:

1. Add an element to a multiset.
2. Remove an element from a multiset.
3. Move the smallest element from one partition to another.
4. Move the largest element from one partition to another.

### **Java 24 implementation**

```java
import java.util.*;

class MKAverage {

    private final int m;
    private final int k;

    // The three partitions are multisets.
    //
    // LOW:
    // Contains the smallest k elements.
    //
    // MID:
    // Contains the middle m - 2*k elements.
    //
    // HIGH:
    // Contains the largest k elements.

    private final TreeMap<Integer, Integer> low = new TreeMap<>();
    private final TreeMap<Integer, Integer> mid = new TreeMap<>();
    private final TreeMap<Integer, Integer> high = new TreeMap<>();

    // Actual number of elements in each partition.
    // TreeMap.size() only returns the number of distinct keys,
    // not the total number of occurrences.
    private int lowSize;
    private int midSize;
    private int highSize;

    // Maintain partition sums incrementally.
    private long lowSum;
    private long midSum;
    private long highSum;

    // Stores the latest m elements in insertion order.
    private final Deque<Integer> window = new ArrayDeque<>();

    public MKAverage(int m, int k) {
        this.m = m;
        this.k = k;
    }

    public void addElement(int num) {

        // Step 1:
        // Add the new element to the window.
        window.offerLast(num);

        // Step 2:
        // If the window exceeds m, remove its oldest element.
        if (window.size() > m) {

            int oldest = window.pollFirst();

            removeElement(oldest);
        }

        // Step 3:
        // Insert the new element into one of the partitions.
        addToPartitions(num);

        // Step 4:
        // Rebalance the partitions so their sizes are correct
        // and all elements maintain sorted partition order.
        rebalance();
    }

    public int calculateMKAverage() {

        // Not enough elements to form a complete window.
        if (window.size() < m) {
            return -1;
        }

        // MID always contains exactly m - 2*k elements.
        // Its sum is maintained incrementally.
        return (int) (midSum / (m - 2 * k));
    }

    // ---------------------------------------------------------
    // BASIC MULTISET OPERATIONS
    // ---------------------------------------------------------

    private void add(
            TreeMap<Integer, Integer> set,
            int num
    ) {

        // Increase frequency instead of creating duplicate keys.
        set.merge(num, 1, Integer::sum);
    }

    private void remove(
            TreeMap<Integer, Integer> set,
            int num
    ) {

        int count = set.get(num);

        if (count == 1) {

            // Last occurrence: remove the key completely.
            set.remove(num);

        } else {

            // Multiple occurrences: decrease frequency.
            set.put(num, count - 1);
        }
    }

    // ---------------------------------------------------------
    // INSERTION INTO PARTITIONS
    // ---------------------------------------------------------

    private void addToPartitions(int num) {

        // Initially, place the element in MID.
        //
        // rebalance() will move elements to LOW or HIGH
        // if required.
        add(mid, num);

        midSize++;
        midSum += num;
    }

    // ---------------------------------------------------------
    // REMOVAL FROM PARTITIONS
    // ---------------------------------------------------------

    private void removeElement(int num) {

        // Find which partition contains this occurrence.
        //
        // Because partitions may contain equal values,
        // checking the frequency is sufficient.

        if (low.containsKey(num)) {

            remove(low, num);

            lowSize--;
            lowSum -= num;

        } else if (mid.containsKey(num)) {

            remove(mid, num);

            midSize--;
            midSum -= num;

        } else {

            // The element must be in HIGH.
            remove(high, num);

            highSize--;
            highSum -= num;
        }
    }

    // ---------------------------------------------------------
    // MOVE SMALLEST ELEMENT BETWEEN PARTITIONS
    // ---------------------------------------------------------

    private void moveSmallest(
            TreeMap<Integer, Integer> from,
            TreeMap<Integer, Integer> to
    ) {

        int num = from.firstKey();

        // Remove one occurrence from the source.
        remove(from, num);

        // Insert one occurrence into the destination.
        add(to, num);
    }

    // ---------------------------------------------------------
    // MOVE LARGEST ELEMENT BETWEEN PARTITIONS
    // ---------------------------------------------------------

    private void moveLargest(
            TreeMap<Integer, Integer> from,
            TreeMap<Integer, Integer> to
    ) {

        int num = from.lastKey();

        remove(from, num);

        add(to, num);
    }

    // ---------------------------------------------------------
    // REBALANCING
    // ---------------------------------------------------------

    private void rebalance() {

        /*
         * IMPORTANT:
         *
         * We first move elements based on partition sizes.
         *
         * The following implementation uses explicit helper
         * methods for size and sum maintenance.
         */

        // This implementation's rebalance logic is shown
        // completely below through dedicated transfer methods.
        rebalanceSizes();

        // Ensure partition ordering.
        rebalanceOrder();
    }

    private void rebalanceSizes() {

        int requiredLow = k;
        int requiredMid = m - 2 * k;
        int requiredHigh = k;

        // Move excess elements out of LOW.
        while (lowSize > requiredLow) {
            transferLargestLowToMid();
        }

        // Move excess elements out of HIGH.
        while (highSize > requiredHigh) {
            transferSmallestHighToMid();
        }

        // Fill LOW using the smallest elements from MID.
        while (lowSize < requiredLow && midSize > 0) {
            transferSmallestMidToLow();
        }

        // Fill HIGH using the largest elements from MID.
        while (highSize < requiredHigh && midSize > 0) {
            transferLargestMidToHigh();
        }

        // If MID has excess elements, move them to the
        // appropriate partition based on ordering.
        while (midSize > requiredMid) {

            if (lowSize < requiredLow) {
                transferSmallestMidToLow();
            } else {
                transferLargestMidToHigh();
            }
        }

        // If MID is too small, borrow from LOW or HIGH.
        while (midSize < requiredMid) {

            if (lowSize > requiredLow) {
                transferLargestLowToMid();
            } else if (highSize > requiredHigh) {
                transferSmallestHighToMid();
            } else {
                break;
            }
        }
    }

    // ---------------------------------------------------------
    // TRANSFERS WITH SIZE AND SUM MAINTENANCE
    // ---------------------------------------------------------

    private void transferLargestLowToMid() {

        int num = low.lastKey();

        remove(low, num);
        lowSize--;
        lowSum -= num;

        add(mid, num);
        midSize++;
        midSum += num;
    }

    private void transferSmallestHighToMid() {

        int num = high.firstKey();

        remove(high, num);
        highSize--;
        highSum -= num;

        add(mid, num);
        midSize++;
        midSum += num;
    }

    private void transferSmallestMidToLow() {

        int num = mid.firstKey();

        remove(mid, num);
        midSize--;
        midSum -= num;

        add(low, num);
        lowSize++;
        lowSum += num;
    }

    private void transferLargestMidToHigh() {

        int num = mid.lastKey();

        remove(mid, num);
        midSize--;
        midSum -= num;

        add(high, num);
        highSize++;
        highSum += num;
    }

    // ---------------------------------------------------------
    // PARTITION ORDERING
    // ---------------------------------------------------------

    private void rebalanceOrder() {

        /*
         * Enforce:
         *
         * max(LOW) <= min(MID)
         * max(MID) <= min(HIGH)
         *
         * If the boundaries are incorrect, exchange elements.
         */

        while (!low.isEmpty()
                && !mid.isEmpty()
                && low.lastKey() > mid.firstKey()) {

            int a = low.lastKey();
            int b = mid.firstKey();

            remove(low, a);
            remove(mid, b);

            add(low, b);
            add(mid, a);

            lowSum += (long) b - a;
            midSum += (long) a - b;
        }

        while (!mid.isEmpty()
                && !high.isEmpty()
                && mid.lastKey() > high.firstKey()) {

            int a = mid.lastKey();
            int b = high.firstKey();

            remove(mid, a);
            remove(high, b);

            add(mid, b);
            add(high, a);

            midSum += (long) b - a;
            highSum += (long) a - b;
        }
    }

    /*
     * TIME COMPLEXITY:
     *
     * TreeMap insertion/removal:
     * O(log m)
     *
     * Finding firstKey()/lastKey():
     * O(log m) in TreeMap.
     *
     * Each insertion or deletion can cause a bounded number
     * of partition transfers because the window changes
     * by only one element.
     *
     * Therefore:
     *
     * addElement(): O(log m)
     * calculateMKAverage(): O(1)
     *
     * SPACE COMPLEXITY:
     *
     * Three TreeMaps together contain at most m elements.
     * Queue contains at most m elements.
     *
     * Overall: O(m).
     *
     * NOTE:
     * For production-quality code, the cleanest implementation
     * is to centralize all partition transfers and perform
     * size normalization and ordering normalization together.
     * An alternative, simpler and more robust implementation
     * follows using a Fenwick Tree.
     */
}
```

**Important interviewer note:** The three-partition approach requires careful coordination between size balancing and ordering. For an implementation that is easier to prove correct and less error-prone, I would prefer the following Fenwick Tree solution given the constraints.

# **5. Solution 3 — Fenwick Tree (Recommended optimal solution)**

This is the solution I would recommend in a senior-level interview.

The constraints provide a crucial observation:

```
1 <= num <= 100000
```

The values belong to a small, fixed domain.

We can maintain:

1. A Fenwick Tree for frequencies.
2. A Fenwick Tree for sums.
3. A queue for the sliding window.

### **Core intuition**

Instead of storing sorted elements, maintain their frequencies.

For example:

```
Window = [3, 1, 10, 5, 5]
```

Frequency representation:

```
Value:      1  3  5  10
Frequency:  1  1  2   1
```

A Fenwick Tree supports:

- Add an element's frequency.
- Remove an element's frequency.
- Find the number of elements in a value range.
- Find the sum of elements in a value range.
- Find the value at a particular sorted rank.

The last operation is particularly important.

We need:

```
Sum of smallest k elements
Sum of smallest m-k elements
```

Why?

Let:

\\[ P(x) = \text{sum of the smallest x elements} \\]

Then:

\\[ \text{MiddleSum} = P(m-k)-P(k) \\]

This works because:

- `P(k)` removes the smallest `k`.
- `P(m-k)` includes the smallest `m-k`.
- Subtracting gives the elements at sorted positions `k` through `m-k-1`.

Therefore:

\\[ MKAverage = \left\lfloor \frac{P(m-k)-P(k)}{m-2k} \right\rfloor \\]

We only need to implement `P(x)` efficiently.

### **Fenwick Tree mental model**

A Fenwick Tree supports prefix sums.

We maintain two trees:

```
countBIT[value] = frequency of value
sumBIT[value]   = value * frequency of value
```

To calculate the sum of the smallest `x` elements:

1. Find the value at sorted position `x`.
2. Calculate the sum of all values strictly smaller than that value.
3. Add the required number of occurrences of the boundary value.

Example:

```
Sorted window = [1, 3, 5, 5, 10]

P(3) = 1 + 3 + 5 = 9
P(1) = 1

MiddleSum = P(4) - P(1)
          = (1 + 3 + 5 + 5) - 1
          = 12

MKAverage = 12 / 3 = 4
```

### **Java 24 implementation**

```java
import java.util.*;

class MKAverage {

    private static final int MAX_VALUE = 100_000;

    private final int m;
    private final int k;

    // Stores the latest m elements in arrival order.
    private final Deque<Integer> window = new ArrayDeque<>();

    // Frequency Fenwick Tree.
    //
    // countBIT[i] represents the accumulated frequency
    // for the corresponding Fenwick Tree range.
    private final FenwickTree countBIT;

    // Sum Fenwick Tree.
    //
    // Each inserted value contributes its value to the tree.
    // Thus, prefixSum(x) gives the sum of all elements
    // whose values are <= x.
    private final FenwickTree sumBIT;

    public MKAverage(int m, int k) {

        this.m = m;
        this.k = k;

        this.countBIT = new FenwickTree(MAX_VALUE);
        this.sumBIT = new FenwickTree(MAX_VALUE);
    }

    public void addElement(int num) {

        // If the window is already full, remove the oldest element.
        if (window.size() == m) {

            int oldest = window.pollFirst();

            // Remove its frequency and its contribution to the sum.
            countBIT.add(oldest, -1);
            sumBIT.add(oldest, -oldest);
        }

        // Add the new element to the sliding window.
        window.offerLast(num);

        // Update the frequency tree.
        countBIT.add(num, 1);

        // Update the sum tree.
        sumBIT.add(num, num);
    }

    public int calculateMKAverage() {

        // MKAverage is undefined until we have exactly m elements.
        if (window.size() < m) {
            return -1;
        }

        // Sum of the smallest m-k elements.
        long sumFirstMMinusK = prefixSumOfSmallest(m - k);

        // Sum of the smallest k elements.
        long sumFirstK = prefixSumOfSmallest(k);

        // Remove the smallest k and largest k elements.
        long middleSum = sumFirstMMinusK - sumFirstK;

        // Integer division rounds down because all values are positive.
        return (int) (middleSum / (m - 2 * k));
    }

    // ---------------------------------------------------------
    // SUM OF SMALLEST X ELEMENTS
    // ---------------------------------------------------------

    private long prefixSumOfSmallest(int x) {

        /*
         * We need the sum of the first x elements in sorted order.
         *
         * Example:
         *
         * Sorted elements = [1, 3, 5, 5, 10]
         *
         * prefixSumOfSmallest(3) = 1 + 3 + 5 = 9
         *
         * First, identify the value at sorted position x.
         */

        int value = countBIT.findByOrder(x);

        /*
         * Calculate the number of elements strictly smaller
         * than the boundary value.
         */
        long countSmaller = countBIT.query(value - 1);

        /*
         * Calculate the sum of all elements strictly smaller
         * than the boundary value.
         */
        long sumSmaller = sumBIT.query(value - 1);

        /*
         * Remaining elements must be taken from occurrences
         * of the boundary value.
         *
         * Example:
         *
         * Sorted = [1, 3, 5, 5, 10]
         *
         * x = 4
         *
         * Boundary value = 5
         *
         * countSmaller = 2
         * sumSmaller = 4
         *
         * We need 4 - 2 = 2 occurrences of 5.
         *
         * Result = 4 + 2*5 = 14.
         */

        long remainingCount = x - countSmaller;

        return sumSmaller + remainingCount * value;
    }

    // ---------------------------------------------------------
    // FENWICK TREE IMPLEMENTATION
    // ---------------------------------------------------------

    private static class FenwickTree {

        private final int n;
        private final long[] tree;

        FenwickTree(int n) {

            this.n = n;
            this.tree = new long[n + 1];
        }

        // Add delta to the frequency/sum associated with index.
        void add(int index, long delta) {

            while (index <= n) {

                tree[index] += delta;

                // Move to the next responsible Fenwick node.
                index += index & -index;
            }
        }

        // Return the prefix sum from index 1 through index.
        long query(int index) {

            long result = 0;

            while (index > 0) {

                result += tree[index];

                // Move to the parent Fenwick node.
                index -= index & -index;
            }

            return result;
        }

        // -----------------------------------------------------
        // FIND THE VALUE AT A GIVEN SORTED POSITION
        // -----------------------------------------------------

        int findByOrder(long order) {

            /*
             * Find the smallest index whose prefix frequency
             * is >= order.
             *
             * This is Fenwick Tree binary lifting.
             *
             * Example:
             *
             * Frequencies:
             *
             * Value:      1  3  5  10
             * Frequency:  1  1  2   1
             *
             * order = 3
             *
             * The third element in sorted order is 5.
             *
             * We find that value in O(log MAX_VALUE).
             */

            int index = 0;

            // Largest power of two <= n.
            int bitMask = Integer.highestOneBit(n);

            while (bitMask != 0) {

                int next = index + bitMask;

                if (next <= n && tree[next] < order) {

                    // Skip this entire Fenwick block.
                    index = next;

                    order -= tree[next];
                }

                bitMask >>= 1;
            }

            // index is the number of values before the answer.
            // Therefore index + 1 is the required value.
            return index + 1;
        }
    }

    /*
     * =========================================================
     * COMPLEXITY ANALYSIS
     * =========================================================
     *
     * Let:
     *
     * N = maximum possible value = 100000
     * m = sliding window size
     *
     * addElement():
     *
     * 1. Remove oldest element if window is full:
     *    O(log N) for countBIT update.
     *    O(log N) for sumBIT update.
     *
     * 2. Insert new element:
     *    O(log N) for countBIT update.
     *    O(log N) for sumBIT update.
     *
     * Overall:
     * O(log N)
     *
     * calculateMKAverage():
     *
     * 1. Find boundary value for m-k:
     *    O(log N)
     *
     * 2. Find boundary value for k:
     *    O(log N)
     *
     * 3. Calculate prefix sums:
     *    O(log N)
     *
     * Overall:
     * O(log N)
     *
     * SPACE COMPLEXITY:
     *
     * countBIT:
     * O(N)
     *
     * sumBIT:
     * O(N)
     *
     * Sliding window:
     * O(m)
     *
     * Overall:
     * O(N + m)
     *
     * Since N is fixed at 100000, this is highly efficient.
     */
}
```

# **6. Compare all approaches**

| Approach                 | addElement | calculateMKAverage | Space    |
| ------------------------ | ---------- | ------------------ | -------- |
| Brute force + sorting    | O(1)       | O(m log m)         | O(m)     |
| Three TreeMap partitions | O(log m)   | O(1)               | O(m)     |
| Two Fenwick Trees        | O(log N)   | O(log N)           | O(N + m) |

Where `N = 100000`, the maximum possible value.

**My recommendation:**

- For learning the problem: Understand the three-partition approach.
- For implementing this particular LeetCode problem: Use two Fenwick Trees.
- For an interview: Explain both and emphasize why the bounded value domain makes Fenwick Trees attractive.

# **7. Edge cases to watch out for**

| Edge case                               | Expected behavior                              |
| --------------------------------------- | ---------------------------------------------- |
| Fewer than `m` elements                 | Return `-1`                                    |
| All elements equal                      | Return that element                            |
| All elements distinct                   | Remove exactly the smallest/largest `k`        |
| Duplicate minimum values                | Remove only `k` occurrences                    |
| Duplicate maximum values                | Remove only `k` occurrences                    |
| New element removes oldest element      | Update both Fenwick Trees with negative deltas |
| `k = 1`                                 | Remove one element from each extreme           |
| Large values                            | Use `long` for sums                            |
| Repeated calculations without insertion | Return the same answer                         |
| Window contains exactly `m` elements    | Calculate normally                             |

### **Particularly important: duplicates**

Consider:

```
m = 5
```

# **8. Interviewer follow-up questions**

### **Q1. Why do we need two Fenwick Trees?**

One tree maintains frequencies, and the other maintains sums.

The frequency tree helps us identify the element at a particular sorted position.

The sum tree helps us calculate the sum of elements up to a particular value.

Both are necessary to efficiently calculate the sum of the smallest `x` elements.

### **Q2. Why can't we use a normal prefix sum array?**

Because the stream changes dynamically.

When an element arrives or leaves, the frequencies and sums change.

Rebuilding a prefix sum array after every operation would be expensive.

Fenwick Trees support point updates and prefix queries in logarithmic time.

### **Q3. Why do we use&#x20;**`long`**?**

Maximum possible sum:

\\[ m \times 100000 \\]

Given:

\\[ m = 100000 \\]

Therefore:

\\[ 10^{10} \\]

This exceeds `Integer.MAX_VALUE`.

### **Q4. Can we solve this using two heaps?**

Two heaps can maintain lower and upper portions of a sliding window, but arbitrary deletion of the oldest element is difficult with Java's standard `PriorityQueue`.

We would need lazy deletion or an indexed heap.

Additionally, we need the sum of the middle elements, so maintaining three balanced partitions is more natural.

### **Q5. Can we use a Segment Tree instead?**

Absolutely.

A Segment Tree can maintain:

- Frequency of each value.
- Sum of each value.

We can find the element at a particular sorted rank using frequency information.

The complexity is:

```
addElement:          O(log N)
calculateMKAverage:  O(log N)
Space:               O(N)
```

### **Q6. Why is Fenwick Tree binary lifting better than binary searching for the kth element?**

We could binary-search over the value domain and query prefix frequencies at each step.

That would take:

\\[ O(\log^2 N) \\]

Fenwick Tree binary lifting finds the kth element directly in:

\\[ O(\log N) \\]

### **Q7. What happens if the values are not bounded?**

The fixed-size Fenwick Tree approach becomes less attractive.

Alternatives include:

- Coordinate compression, if all values are known in advance.
- Three balanced ordered multisets.
- An augmented order-statistics tree.

### **Q8. Why is the final division safe using integer arithmetic?**

All input values are positive, so `middleSum` is non-negative.

Java integer division truncates toward zero, which is equivalent to floor for non-negative numbers.

Therefore:

```
middleSum / (m - 2 * k)
```

produces the required rounded-down average.

# **9. Final interview takeaway**

The most important insight in this problem is recognizing that we need two different capabilities:

1. **Order statistics:** Find the smallest or kth smallest elements.
2. **Range aggregation:** Calculate the sum of selected elements.

The Fenwick Tree solution combines these capabilities efficiently.

Remember this formula:

\\[ \boxed{ MKAverage = \frac{P(m-k)-P(k)}{m-2k} } \\]

Where `P(x)` represents the sum of the smallest `x` elements.

Once you understand this formula, the entire problem becomes a dynamic order-statistics and prefix-sum problem rather than a repeated sorting problem.
