# **1032. Stream of Characters — Hard**

**Primary pattern: Trie + Reverse Traversal**

The optimal solution uses a **Trie built from reversed words** and checks the incoming stream backwards.

This is a classic example where reversing the direction of a Trie makes a streaming problem efficient.

## **0. Understand the problem**

You are given a dictionary of words and a continuous stream of characters.

You need to implement:

```
StreamChecker(String[] words)
boolean query(char letter)
```

Every time `query(letter)` is called:

1. Add the new character to the stream.
2. Check whether **any suffix of the entire stream** matches one of the dictionary words.
3. Return `true` if a match exists; otherwise return `false`.

### **Example**

```
words = ["cd", "f", "kl"]

Stream: a → b → c → d → e → f → g → h → i → j → k → l
```

| Query | Stream so far | Matching suffix | Result |
| ----- | ------------- | --------------- | ------ |
| a     | a             | None            | false  |
| b     | ab            | None            | false  |
| c     | abc           | None            | false  |
| d     | abcd          | cd              | true   |
| e     | abcde         | None            | false  |
| f     | abcdef        | f               | true   |
| g     | abcdefg       | None            | false  |
| h     | abcdefgh      | None            | false  |
| i     | abcdefghi     | None            | false  |
| j     | abcdefghij    | None            | false  |
| k     | abcdefghijk   | None            | false  |
| l     | abcdefghijkl  | kl              | true   |

**Important:** We are checking suffixes, not arbitrary substrings or prefixes.

For example:

```
Stream = "axyz"
words  = ["xyz"]
```

The answer is `true` because `"xyz"` is a suffix.

| Is the stream potentially unlimited?                            | Helps decide whether storing the entire stream is acceptable.    |
| How many query calls are expected?                              | Determines whether we should optimize repeated suffix checking.  |

Given the constraints, we know:

- Maximum word length = 200.
- Maximum number of words = 2000.
- Maximum query calls = 40,000.
- Characters are lowercase English letters.

The maximum word length is particularly important: we never need to inspect more than 200 characters per query.

# **2. Core intuition — Reverse Trie**

Let's first understand why a normal Trie is not ideal.

Suppose:

```
words = ["abc", "xyz"]
stream = "axyz"
```

A normal Trie stores:

```
root
 ├── a
 │    └── b
 │         └── c
 │
 └── x
      └── y
           └── z
```

But we receive characters from left to right.

When `z` arrives, we need to determine whether `"xyz"` is a suffix.

A normal Trie starts matching from the first character of a word, but our newest character is the last character of the word.

**Solution: Reverse every word before inserting it into the Trie.**

### **Step 1: Reverse the dictionary words**

Original:

```
["abc", "xyz"]
```

Reversed:

```
["cba", "zyx"]
```

### **Step 2: Build a Trie**

```
             root
             /  \
            c    z
            |    |
            b    y
            |    |
            a    x*
```

`*` represents the end of a dictionary word.

### **Step 3: Traverse the stream backwards**

Suppose the stream is:

```
a → x → y → z
```

When `z` arrives:

```
Stream = "axyz"
```

We traverse backwards:

```
z → y → x
```

Our reversed Trie contains:

```
z → y → x*
```

We reach a terminal node, so return `true`.

### **The mental model**

Instead of asking:

> Does any suffix of the stream match a dictionary word?

We ask:

> Starting from the newest character, can I walk backwards through the Trie and reach the end of any reversed dictionary word?

That's the entire optimization.

# **3. All possible approaches**

We will discuss three approaches:

1. Brute force: Store stream and check every dictionary word.
2. Trie with forward words: Check suffixes using a normal Trie.
3. Optimal: Reverse Trie + backward stream traversal.

## **Approach 1: Brute force**

### **Intuition**

For every query:

1. Append the character to the stream.
2. Iterate over every dictionary word.
3. Check whether the current stream ends with that word.
4. Return `true` if any word matches.

### **Java 24 implementation**

```java
import java.util.*;

class StreamChecker {

    private final String[] words;
    private final StringBuilder stream;

    public StreamChecker(String[] words) {

        this.words = words;

        /*
         * Maintain the complete stream.
         *
         * Every query appends one character.
         */
        this.stream = new StringBuilder();
    }

    public boolean query(char letter) {

        /*
         * Step 1:
         * Append the incoming character.
         */
        stream.append(letter);

        /*
         * Step 2:
         * Check every dictionary word.
         */
        for (String word : words) {

            int wordLength = word.length();

            /*
             * If the stream is shorter than the word,
             * this word cannot possibly be a suffix.
             */
            if (stream.length() < wordLength) {
                continue;
            }

            /*
             * Compare the last wordLength characters
             * of the stream with the current word.
             */
            int start = stream.length() - wordLength;

            boolean matches = true;

            for (int i = 0; i < wordLength; i++) {

                if (stream.charAt(start + i) != word.charAt(i)) {

                    matches = false;
                    break;
                }
            }

            /*
             * At least one dictionary word is a suffix.
             */
            if (matches) {
                return true;
            }
        }

        return false;
    }
}
```

### **Complexity analysis**

Let:

- `N` = number of dictionary words.
- `L` = maximum word length.
- `Q` = number of queries.
- `S` = total stream length.

**Time complexity:**

For each query, we potentially examine every word and compare up to `L` characters.

\\[ O(N \times L) \\]

For all queries:

\\[ O(Q \times N \times L) \\]

With the given constraints:

\\[ 40,000 \times 2,000 \times 200 \\]

This is potentially very expensive.

**Space complexity:**

\\[ O(S + N \times L) \\]

- `O(S)` for storing the stream.
- `O(N × L)` for storing dictionary words.

**Verdict:** Simple, but inefficient.

## **Approach 2: Normal Trie + Checking Every Possible Suffix**

### **Intuition**

Instead of comparing strings directly, we can store all original words in a Trie.

For every query:

1. Append the incoming character.
2. Start at every possible suffix position.
3. Traverse the Trie forward.
4. Return `true` if any traversal reaches a terminal node.

For example:

```
Stream = "axyz"

Possible suffixes:
"a"
"z"
"yz"
"xyz"
"axyz"
```

We check these against the Trie.

### **Java 24 implementation**

```java
import java.util.*;

class StreamChecker {

    /*
     * Trie node.
     *
     * Each node represents one character.
     */
    private static class TrieNode {

        TrieNode[] children = new TrieNode[26];

        boolean isEnd;
    }

    private final TrieNode root;

    private final StringBuilder stream;

    private final int maxWordLength;

    public StreamChecker(String[] words) {

        root = new TrieNode();

        stream = new StringBuilder();

        int maxLength = 0;

        /*
         * Insert original words into the Trie.
         */
        for (String word : words) {

            maxLength = Math.max(maxLength, word.length());

            TrieNode node = root;

            for (char ch : word.toCharArray()) {

                int index = ch - 'a';

                if (node.children[index] == null) {
                    node.children[index] = new TrieNode();
                }

                node = node.children[index];
            }

            node.isEnd = true;
        }

        maxWordLength = maxLength;
    }

    public boolean query(char letter) {

        stream.append(letter);

        /*
         * Only suffixes of length <= maxWordLength
         * can possibly match.
         */
        int start = Math.max(
                0,
                stream.length() - maxWordLength
        );

        /*
         * Try every possible suffix.
         */
        for (int i = start; i < stream.length(); i++) {

            TrieNode node = root;

            for (int j = i; j < stream.length(); j++) {

                int index = stream.charAt(j) - 'a';

                node = node.children[index];

                /*
                 * No matching Trie path.
                 */
                if (node == null) {
                    break;
                }

                /*
                 * A complete dictionary word was found.
                 */
                if (node.isEnd) {
                    return true;
                }
            }
        }

        return false;
    }
}
```

### **Complexity analysis**

Let:

- `N` = number of words.
- `L` = maximum word length.
- `Q` = number of queries.

**Construction time:**

Every word is inserted character by character.

\\[ O(N \times L) \\]

**Query time:**

We try at most `L` possible starting positions.

Each traversal can take up to `L` characters.

\\[ O(L^2) \\]

For all queries:

\\[ O(Q \times L^2) \\]

**Space complexity:**

\\[ O(N \times L + Q) \\]

The Trie requires `O(N × L)` space in the worst case, and the stream requires `O(Q)` space.

**Verdict:** Better than brute force, but we are repeatedly checking many suffixes.

We can avoid this repeated work using a reversed Trie.

# **4. Approach 3: Optimal — Reverse Trie + Backward Traversal**

This is the approach I would recommend in an interview.

### **Step 1: Build a Trie using reversed words**

For:

```
words = ["abc", "xyz", "cd"]
```

Insert:

```
"cba"
"zyx"
"dc"
```

### **Step 2: Store incoming characters**

We can use a `StringBuilder` to maintain the stream.

### **Step 3: Traverse backwards**

Whenever a new character arrives:

- Start at the newest character.
- Move backwards through the stream.
- Follow corresponding Trie children.
- If a terminal node is found, return `true`.
- If a Trie path does not exist, return `false`.
- Stop after checking the maximum word length.

### **Why is this optimal?**

Consider:

```
words = ["abcd", "xyz", "pq"]
```

Reversed Trie paths:

```
d → c → b → a*
z → y → x*
q → p*
```

Suppose the stream is:

```
m → a → b → c → d
```

When `d` arrives, we only need:

```
d → c → b → a
```

We don't need to examine all possible suffix starting positions.

We perform one traversal of at most `L` characters.

## **Java 24 implementation**

```java
import java.util.*;

class StreamChecker {

    /*
     * Each TrieNode represents one character.
     *
     * children[i] represents the next character:
     *
     * 0  -> a
     * 1  -> b
     * ...
     * 25 -> z
     *
     * isEnd indicates whether the current Trie path
     * represents a complete reversed dictionary word.
     */
    private static class TrieNode {

        TrieNode[] children = new TrieNode[26];

        boolean isEnd;
    }

    /*
     * Root of the reversed Trie.
     */
    private final TrieNode root;

    /*
     * Stores all characters received so far.
     *
     * We traverse this StringBuilder backwards
     * whenever a new character arrives.
     */
    private final StringBuilder stream;

    /*
     * No dictionary word is longer than this value.
     *
     * Therefore, examining more than this many
     * stream characters is unnecessary.
     */
    private final int maxWordLength;

    public StreamChecker(String[] words) {

        root = new TrieNode();

        stream = new StringBuilder();

        int maxLength = 0;

        /*
         * STEP 1: Build the reversed Trie.
         *
         * Example:
         *
         * Original word: "abc"
         *
         * Insert:
         *
         * c -> b -> a
         *
         * This is important because queries arrive
         * from left to right, but suffix matching
         * needs to begin at the newest character.
         */
        for (String word : words) {

            maxLength = Math.max(maxLength, word.length());

            TrieNode node = root;

            /*
             * Traverse each word from right to left.
             */
            for (int i = word.length() - 1; i >= 0; i--) {

                int index = word.charAt(i) - 'a';

                /*
                 * Create the Trie node if it doesn't exist.
                 */
                if (node.children[index] == null) {

                    node.children[index] = new TrieNode();
                }

                node = node.children[index];
            }

            /*
             * Mark the last node as terminal.
             *
             * Reaching this node means that the characters
             * traversed backwards form a complete word.
             */
            node.isEnd = true;
        }

        maxWordLength = maxLength;
    }

    public boolean query(char letter) {

        /*
         * STEP 2: Append the newly received character.
         *
         * Example:
         *
         * Previous stream: "abc"
         * New character:   'd'
         *
         * Updated stream:  "abcd"
         */
        stream.append(letter);

        /*
         * STEP 3: Start from the Trie root.
         */
        TrieNode node = root;

        /*
         * STEP 4: Traverse the stream backwards.
         *
         * We inspect at most maxWordLength characters.
         *
         * Example:
         *
         * Stream: "axyz"
         *
         * Traversal:
         *
         * z -> y -> x -> a
         */
        int checked = 0;

        for (int i = stream.length() - 1;
             i >= 0 && checked < maxWordLength;
             i--) {

            /*
             * Convert the current stream character
             * into its Trie array index.
             */
            int index = stream.charAt(i) - 'a';

            /*
             * Follow the corresponding Trie edge.
             */
            node = node.children[index];

            /*
             * If this edge does not exist,
             * no dictionary word can match this suffix.
             *
             * Stop immediately.
             */
            if (node == null) {
                return false;
            }

            checked++;

            /*
             * If we reach a terminal node,
             * the characters examined so far form
             * a complete dictionary word.
             *
             * Therefore, a suffix match exists.
             */
            if (node.isEnd) {
                return true;
            }
        }

        /*
         * No complete dictionary word was found.
         */
        return false;
    }
}
```

# **5. Dry run of the optimal solution**

Consider:

```
String[] words = {"cd", "f", "kl"};
```

### **Trie construction**

Reverse the words:

```
cd → dc
f  → f
kl → lk
```

Trie:

```
              root
             / | \
            d  f  l
            |     |
            c*    k*
```

### **Query sequence**

```
a, b, c, d, e, f, g, h, i, j, k, l
```

| Query | Backward traversal | Explanation           | Result |
| ----- | ------------------ | --------------------- | ------ |
| a     | a                  | No Trie edge          | false  |
| b     | b                  | No Trie edge          | false  |
| c     | c                  | No Trie edge          | false  |
| d     | d → c              | Terminal node reached | true   |
| e     | e                  | No Trie edge          | false  |
| f     | f                  | Terminal node reached | true   |
| g     | g                  | No Trie edge          | false  |
| h     | h                  | No Trie edge          | false  |
| i     | i                  | No Trie edge          | false  |
| j     | j                  | No Trie edge          | false  |
| k     | k                  | No Trie edge          | false  |
| l     | l → k              | Terminal node reached | true   |

Notice that when `d` arrives:

```
Stream = "abcd"
```

We don't check the entire stream.

We only traverse:

```
d → c
```

Since we reach a terminal node, we immediately return `true`.

# **6. Edge cases to watch out for**

| Edge case                              | Example                    | Expected          |
| -------------------------------------- | -------------------------- | ----------------- |
| Single-character word                  | `["a"]`, query `'a'`       | true              |
| Word matches after several queries     | `["abc"]`, stream `xabc`   | true              |
| No matching suffix                     | `["abc"]`, stream `xyz`    | false             |
| Multiple matching words                | `["a", "ba"]`, stream `ba` | true              |
| One word is a suffix of another        | `["ab", "b"]`, stream `ab` | true              |
| Stream longer than maximum word length | `["abc"]`, stream `xyzabc` | true              |
| Duplicate words                        | `["abc", "abc"]`           | true when matched |
| Trie path breaks midway                | `["abcd"]`, stream `abx`   | false             |

### **Important edge case: One word is a suffix of another**

Consider:

```
words = ["a", "ba"];
stream = "ba";
```

Reversed words:

```
a
ab
```

Trie:

```
root
  |
  a*
  |
  b*
```

When `b` arrives:

```
b
```

The traversal is:

```
b → a
```

At the first step, the node for `a` is terminal.

Therefore, the algorithm returns `true` immediately.

This is correct because `"a"` is also a suffix of `"ba"`.

**Interview takeaway:** Always check `isEnd` at every step, not just after completing the maximum-length traversal.

# **7. Complexity comparison**

Let:

- `N` = number of dictionary words.
- `L` = maximum word length.
- `Q` = number of queries.
- `T` = total number of characters across all dictionary words.

| Approach     | Construction | Each query | Total query cost | Auxiliary space |
| ------------ | ------------ | ---------- | ---------------- | --------------- |
| Brute force  | O(1)         | O(N × L)   | O(Q × N × L)     | O(Q)            |
| Normal Trie  | O(T)         | O(L²)      | O(Q × L²)        | O(T + Q)        |
| Reverse Trie | O(T)         | O(L)       | O(Q × L)         | O(T + Q)        |

For the reverse Trie:

**Construction time:**

\\[ O(T) \\]

Each dictionary character is inserted exactly once, excluding shared Trie prefixes that already exist.

**Query time:**

\\[ O(L) \\]

We traverse at most the maximum dictionary word length.

**Total query time:**

\\[ O(Q \times L) \\]

**Space complexity:**

\\[ O(T + Q) \\]

- `O(T)` for the Trie in the worst case.
- `O(Q)` for storing the stream.

Since the alphabet contains only 26 lowercase English letters, each Trie node has a fixed-size array of 26 references.

If we count the actual allocated child-reference slots, Trie space is `O(26 × T)`, which simplifies to `O(T)` for a fixed alphabet.

**Can we reduce stream space?**

Yes. We only need the most recent `L` characters. Instead of storing the entire stream, we could use a circular buffer of size `L`.

That would reduce stream storage from `O(Q)` to `O(L)`.

# **8. Interviewer follow-up questions**

### **Q1. Why do we reverse the words instead of reversing the stream?**

Because the stream is naturally received from left to right.

We want to start matching from the newest character and move backwards.

Reversing dictionary words allows us to use a Trie in exactly that direction without modifying the stream.

### **Q2. Why do we stop when a Trie child is null?**

Suppose:

```
words = ["abcd"]
stream = "xyz"
```

Reversed Trie:

```
d → c → b → a
```

When the newest character is `z`, there is no `z` child.

Since every candidate suffix must start with the newest character, no suffix can match.

Therefore, further traversal is unnecessary.

### **Q3. Why do we need&#x20;**`maxWordLength`**?**

No dictionary word is longer than `maxWordLength`.

Therefore, a suffix longer than that cannot match any dictionary word.

We can safely limit every query to at most `L` characters.

### **Q4. Why use&#x20;**`boolean isEnd`**?**

A Trie node can represent both:

- A complete dictionary word.
- A prefix of a longer dictionary word.

For example:

```
words = ["a", "ab"]
```

The node representing `"a"` must be terminal even though it has a child representing `"ab"`.

Without `isEnd`, we cannot distinguish these cases.

### **Q5. Can we avoid storing the entire stream?**

Yes.

We only need the last `maxWordLength` characters.

We can maintain a circular buffer:

```
private final char[] buffer;
private int writeIndex;
private int size;
```

Every query overwrites the oldest character once the buffer becomes full.

This reduces stream storage to:

\\[ O(L) \\]

The Trie traversal still takes `O(L)` time per query.

### **Q6. Can we use a HashMap instead of an array?**

Yes.

Instead of:

```
TrieNode[] children = new TrieNode[26];
```

We can use:

```
Map<Character, TrieNode> children = new HashMap<>();
```

**Trade-off:**

| Array                             | HashMap                            |
| --------------------------------- | ---------------------------------- |
| O(1) child lookup                 | O(1) average child lookup          |
| Fixed 26 references per node      | Stores only existing children      |
| Lower lookup overhead             | Higher lookup overhead             |
| Best for fixed lowercase alphabet | Useful for flexible character sets |

For this problem, an array is a natural choice.

### **Q7. Is this an Aho-Corasick problem?**

It is related to multi-pattern string matching.

Aho-Corasick builds a Trie with failure links to efficiently search for multiple patterns in a text.

However, this problem has an important simplification:

- We only need to identify whether a dictionary word matches a suffix ending at the newest character.
- The maximum pattern length is only 200.
- A reversed Trie lets us perform that check directly in `O(L)` per query.

Aho-Corasick is another possible approach, but it is unnecessary here.

### **Q8. Why not use a Set of all dictionary words?**

A Set provides efficient lookup for a complete string, but we would still need to construct and test all possible suffix strings.

That would introduce additional string creation and comparison overhead.

The Trie allows us to search incrementally without constructing suffix strings.

# **9. Final interview summary**

Remember this pattern:

**Problem:** Match whether any dictionary word is a suffix of an incoming character stream.

**Observation:** A suffix match must end at the newest character.

**Transformation:** Reverse every dictionary word.

**Data structure:** Trie.

**Query:** Start at the newest stream character and traverse backwards.

**Complexities:**

- Construction: `O(T)`
- Query: `O(L)`
- Total queries: `O(Q × L)`
- Space: `O(T + Q)`

The most important insight to remember for interviews:

> Whenever you need to match a suffix of a continuously growing string against multiple dictionary words, consider reversing the dictionary words and using a Trie to search backwards from the newest character.

This is the key pattern behind LeetCode 1032.
