# **792. Number of Matching Subsequences**

**Difficulty:** Medium\
**Pattern:** String + HashMap + Greedy / Two Pointers / Binary Search / Bucketing

## **0. Simplify the problem statement**

You are given:

- A string `s`.
- An array of strings `words`.

You need to count how many strings in `words` can be formed by deleting zero or more characters from `s` without changing the order of the remaining characters.

In other words, each word must appear as a subsequence of `s`.

**Example:**

```
s = "abcde"

words = ["a", "bb", "acd", "ace"]

Output = 3
```

Let's check:

| Word  | Matching? | Reason            |
| ----- | --------- | ----------------- |
| "a"   | Yes       | a exists          |
| "bb"  | No        | Only one b exists |
| "acd" | Yes       | a → c → d         |
| "ace" | Yes       | a → c → e         |

Answer = 3.

## **1. Clarifying questions to ask the interviewer**

Before implementing, clarify:

1. **Can words contain duplicate strings?**

   Why: If duplicates exist, should each occurrence count separately? Usually, yes. For example, `["abc", "abc"]` contributes 2.
2. **Are all characters lowercase English letters?**

   Why: This allows us to use a fixed-size array of 26 characters instead of a HashMap.
3. **Can we modify the input?**

   Why: Some approaches use sorting or preprocessing. Knowing whether modification is allowed helps select an implementation.
4. **What are the constraints?**

   Why: With `s.length <= 50,000` and `words.length <= 5,000`, checking every word independently using two pointers is feasible, but we can do better in certain scenarios.

## **2. Core intuition**

There are multiple ways to solve this problem.

The important observation is:

**We don't need to construct subsequences. We only need to verify whether each word's characters appear in&#x20;**`s`**&#x20;in the correct order.**

Consider:

```
s = "abcde"
word = "ace"
```

We scan `s` and match:

```
a b c d e
↑   ↑   ↑
a   c   e
```

Every character of the word must be matched in order.

This naturally suggests two pointers.

However, checking every word independently repeatedly scans `s`.

Can we avoid that repeated work?

Yes. We can preprocess the positions of characters in `s`, or process all words simultaneously using buckets.

We'll explore all approaches.

# **3. Approach 1: Brute Force — Generate subsequences**

### **Mental model**

Generate every possible subsequence of `s` and check whether it exists in `words`.

For a string of length `n`, there are \\(2^n\\) possible subsequences.

This is extremely inefficient.

```java
import java.util.*;

class Solution {

    public int numMatchingSubseq(String s, String[] words) {

        /*
         * Store all words in a set for O(1) average lookup.
         *
         * Note: This implementation counts distinct words,
         * not duplicate occurrences. We would need a frequency
         * map to correctly handle duplicate words.
         */

        Set<String> wordSet = new HashSet<>(Arrays.asList(words));

        Set<String> subsequences = new HashSet<>();

        generate(s, 0, new StringBuilder(), subsequences);

        int answer = 0;

        for (String word : words) {
            if (subsequences.contains(word)) {
                answer++;
            }
        }

        return answer;
    }

    private void generate(
            String s,
            int index,
            StringBuilder current,
            Set<String> subsequences) {

        /*
         * Every completed selection represents a subsequence.
         */
        if (index == s.length()) {
            subsequences.add(current.toString());
            return;
        }

        /*
         * Choice 1: Do not include the current character.
         */
        generate(s, index + 1, current, subsequences);

        /*
         * Choice 2: Include the current character.
         */
        current.append(s.charAt(index));

        generate(s, index + 1, current, subsequences);

        /*
         * Backtrack.
         */
        current.deleteCharAt(current.length() - 1);
    }
}

/*
 * Time Complexity:
 * O(2^n * n + W * L)
 *
 * n = s.length()
 * W = words.length
 * L = maximum word length
 *
 * There are 2^n possible subsequences.
 * Creating and storing them can take O(n) per subsequence.
 *
 * Space Complexity:
 * O(n * 2^n)
 *
 * Stores potentially 2^n subsequences, each requiring O(n) space.
 *
 * This approach is impractical for the given constraints.
 */
```

# **4. Approach 2: Two Pointers — Check Every Word Independently**

This is the simplest practical solution.

### **Core intuition**

Use two pointers:

- `i` traverses the main string `s`.
- `j` traverses the current word.

Whenever characters match, move both pointers.

Otherwise, move only `i`.

If `j` reaches the end of the word, the entire word was matched.

### **Example**

```
s    = "abcde"
word = "ace"

         i
s    =   a b c d e
         ↑

word =   a c e
         ↑ j
```

We match `a`, then `c`, then `e`.

Both pointers finish successfully.

### **Java 24 implementation**

```java
class Solution {

    public int numMatchingSubseq(String s, String[] words) {

        int answer = 0;

        /*
         * Check each word independently.
         */
        for (String word : words) {

            int i = 0;
            int j = 0;

            /*
             * Traverse s until:
             *
             * 1. We match every character of word.
             * 2. We reach the end of s.
             */
            while (i < s.length() && j < word.length()) {

                /*
                 * If characters match, advance both pointers.
                 */
                if (s.charAt(i) == word.charAt(j)) {
                    j++;
                }

                /*
                 * Always advance the pointer in s.
                 */
                i++;
            }

            /*
             * If j reaches word.length(),
             * every character was matched in order.
             */
            if (j == word.length()) {
                answer++;
            }
        }

        return answer;
    }
}

/*
 * Time Complexity:
 * O(N + W * N) in the worst case, where:
 *
 * N = s.length()
 * W = words.length
 *
 * More precisely, O(sum of min(N, L_i) over all words).
 *
 * Each word can independently scan the entire string s.
 *
 * Space Complexity:
 * O(1)
 *
 * Only two pointers and an answer variable are maintained.
 *
 * Advantages:
 * - Very simple.
 * - Easy to implement and explain.
 *
 * Disadvantage:
 * - Repeatedly scans s for every word.
 */
```

**Interview observation:** This solution is already efficient enough for the given constraints in many practical situations.

But we can eliminate repeated scans.

# **5. Approach 3: Binary Search + Character Position Indexing**

This is an important optimization.

### **Core intuition**

Instead of repeatedly scanning `s`, preprocess the positions of every character.

For example:

```
s = "abcde"
```

Character positions:

```
a -> [0]
b -> [1]
c -> [2]
d -> [3]
e -> [4]
```

Consider:

```
word = "ace"
```

We need to find:

1. The first occurrence of `a`.
2. The first occurrence of `c` after `a`.
3. The first occurrence of `e` after `c`.

We can use binary search to find the next valid position.

### **Why binary search?**

Suppose:

```
s = "abacabad"
```

Positions of `a`:

```
a -> [0, 2, 4, 6]
```

If our current position is `3`, we need the first occurrence of `a` greater than or equal to `3`.

Binary search finds position `4`.

This avoids scanning the original string.

### **Java 24 implementation**

```java
import java.util.*;

class Solution {

    public int numMatchingSubseq(String s, String[] words) {

        /*
         * positions[c] stores all indices where character c
         * appears in s.
         *
         * Since input contains lowercase English letters,
         * we only need 26 lists.
         */
        List<Integer>[] positions = new ArrayList[26];

        for (int i = 0; i < 26; i++) {
            positions[i] = new ArrayList<>();
        }

        /*
         * Preprocessing:
         * Store every character's positions in sorted order.
         *
         * They are automatically sorted because we traverse s
         * from left to right.
         */
        for (int i = 0; i < s.length(); i++) {

            int character = s.charAt(i) - 'a';

            positions[character].add(i);
        }

        int answer = 0;

        /*
         * Check every word using the preprocessed positions.
         */
        for (String word : words) {

            /*
             * nextPosition represents the earliest index
             * where the next character can be matched.
             */
            int nextPosition = 0;

            boolean matched = true;

            for (char ch : word.toCharArray()) {

                List<Integer> indexes = positions[ch - 'a'];

                /*
                 * Find the first occurrence >= nextPosition.
                 *
                 * lowerBound returns the insertion position
                 * of nextPosition in the sorted list.
                 */
                int index = lowerBound(indexes, nextPosition);

                /*
                 * No occurrence exists at or after nextPosition.
                 */
                if (index == indexes.size()) {
                    matched = false;
                    break;
                }

                /*
                 * Move beyond the matched character.
                 */
                nextPosition = indexes.get(index) + 1;
            }

            if (matched) {
                answer++;
            }
        }

        return answer;
    }

    /*
     * Returns the first index i such that list[i] >= target.
     *
     * This is the standard lower-bound binary search.
     */
    private int lowerBound(List<Integer> list, int target) {

        int left = 0;
        int right = list.size();

        while (left < right) {

            int mid = left + (right - left) / 2;

            if (list.get(mid) < target) {
                left = mid + 1;
            } else {
                right = mid;
            }
        }

        return left;
    }
}

/*
 * Let:
 *
 * N = s.length()
 * W = words.length
 * L = maximum word length
 *
 * Preprocessing:
 * O(N)
 *
 * For each character in each word:
 * Binary search takes O(log N).
 *
 * Total:
 * O(N + W * L * log N)
 *
 * Space Complexity:
 * O(N)
 *
 * Every index of s is stored exactly once.
 *
 * Advantages:
 * - Avoids repeatedly scanning s.
 * - Particularly useful when s is large and many words
 *   need to be checked.
 *
 * Disadvantage:
 * - Binary search is performed for every character.
 */
```

# **6. Approach 4: Optimal — Bucketing / Waiting Lists**

This is the approach I would recommend in an interview.

It is particularly elegant because we process the main string only once.

### **Core intuition**

Imagine every word is waiting for its next required character.

For example:

```
s = "abcde"

words = ["a", "bb", "acd", "ace"]
```

Initially:

```
Waiting for 'a':
    "a"
    "acd"
    "ace"

Waiting for 'b':
    "bb"
```

When we encounter `a` in `s`:

- `"a"` is complete.
- `"acd"` now waits for `c`.
- `"ace"` now waits for `c`.

When we encounter `b`:

\- `"bb"` still needs another `b`.

When we encounter `c`:

- `"acd"` now waits for `d`.
- `"ace"` now waits for `e`.

And so on.

**The key idea: Group words according to the next character they are waiting for.**

Instead of checking every word independently, we advance all relevant words whenever we encounter a character in `s`.

### **Visual representation**

Initially:

```
Buckets:

'a' -> ["a", "acd", "ace"]
'b' -> ["bb"]
```

After processing `a`:

```
'a' -> []
'b' -> ["bb"]
'c' -> ["acd", "ace"]

Completed = 1
```

After processing `b`:

```
'b' -> ["b"]       // Remaining character of "bb"
'c' -> ["acd", "ace"]
```

After processing `c`:

```
'd' -> ["acd"]
'e' -> ["ace"]
```

After processing `d`:

```
Completed = 2
```

After processing `e`:

```
Completed = 3
```

Answer = 3.

### **Java 24 implementation (Optimal)**

```java
import java.util.*;

class Solution {

    /*
     * Each waiting word is represented by:
     *
     * word  = the original word
     * index = the index of the next character we need to match
     *
     * A record is useful here because it provides an immutable,
     * concise data carrier.
     */
    private record WaitingWord(String word, int index) {}

    public int numMatchingSubseq(String s, String[] words) {

        /*
         * 26 buckets, one for each lowercase English character.
         *
         * buckets[c] contains all words currently waiting
         * for character c.
         */
        Queue<WaitingWord>[] buckets = new ArrayDeque[26];

        for (int i = 0; i < 26; i++) {
            buckets[i] = new ArrayDeque<>();
        }

        /*
         * Initially, every word waits for its first character.
         *
         * Example:
         * "abc" goes into bucket 'a'.
         * "dog" goes into bucket 'd'.
         */
        for (String word : words) {

            int character = word.charAt(0) - 'a';

            buckets[character].offer(
                    new WaitingWord(word, 0)
            );
        }

        int answer = 0;

        /*
         * Traverse s exactly once.
         */
        for (char ch : s.toCharArray()) {

            int bucketIndex = ch - 'a';

            /*
             * Process only words waiting for the current character.
             *
             * Important:
             * Capture the initial bucket size.
             *
             * Why?
             * Some words may move back into the same bucket.
             * We must NOT process those words again using
             * the same occurrence of ch.
             */
            int size = buckets[bucketIndex].size();

            for (int i = 0; i < size; i++) {

                WaitingWord current =
                        buckets[bucketIndex].poll();

                String word = current.word();

                /*
                 * We have successfully matched the character
                 * that this word was waiting for.
                 */
                int nextIndex = current.index() + 1;

                /*
                 * If all characters are matched,
                 * this word is a subsequence.
                 */
                if (nextIndex == word.length()) {

                    answer++;

                } else {

                    /*
                     * Otherwise, move the word into the bucket
                     * corresponding to its next required character.
                     */
                    int nextCharacter =
                            word.charAt(nextIndex) - 'a';

                    buckets[nextCharacter].offer(
                            new WaitingWord(word, nextIndex)
                    );
                }
            }
        }

        return answer;
    }
}

/*
 * TIME COMPLEXITY:
 *
 * Let:
 * N = s.length()
 * W = words.length
 * L = maximum word length
 *
 * 1. Creating 26 buckets:
 *    O(26) = O(1)
 *
 * 2. Initializing the waiting words:
 *    O(W)
 *
 * 3. Traversing s:
 *    O(N)
 *
 * 4. Processing waiting words:
 *    Every character of every word is processed at most once.
 *    Therefore, total processing is O(W * L).
 *
 * Overall:
 * O(N + W * L)
 *
 * SPACE COMPLEXITY:
 *
 * O(W)
 *
 * Every word has exactly one active WaitingWord entry
 * in exactly one bucket at any point in time.
 *
 * Total number of waiting entries is at most W.
 *
 * The record objects and 26 queue references require O(W + 26).
 *
 * Therefore:
 * O(W)
 *
 * WHY IS THIS OPTIMAL?
 *
 * We must at least inspect the input words and the main string
 * in the general case.
 *
 * This solution processes the main string once and advances
 * each word only as its required characters appear.
 *
 * No repeated scanning of s.
 * No binary searches.
 *
 * This is the standard optimal solution for this problem.
 */
```

# **7. Important implementation detail: Why capture bucket size?**

This is probably the most important detail in the optimal solution.

Consider:

```
s = "aa"
word = "aa"
```

Initially:

```
'a' -> [(word="aa", index=0)]
```

We process the first `a`.

The word moves to the same bucket because its next required character is also `a`.

```
'a' -> [(word="aa", index=1)]
```

Now imagine we use:

```
while (!buckets[bucketIndex].isEmpty()) {
    // Process
}
```

The newly inserted entry would immediately be processed again using the same occurrence of `a`.

That would incorrectly match `"aa"` using only one `a`.

**Correct solution:**

```
int size = buckets[bucketIndex].size();

for (int i = 0; i < size; i++) {
    // Process only entries that existed before this character.
}
```

This ensures that one character from `s` can advance a word by at most one position.

# **8. Edge cases**

| Input                                                 | Expected | Explanation                      |
| ----------------------------------------------------- | -------- | -------------------------------- |
| `s = "abc", words = ["abc"]`                          | 1        | Exact match                      |
| `s = "abc", words = ["ac"]`                           | 1        | Characters appear in order       |
| `s = "abc", words = ["ca"]`                           | 0        | Incorrect order                  |
| `s = "abc", words = ["aa"]`                           | 0        | Insufficient occurrences         |
| `s = "aaaa", words = ["a","aa","aaa","aaaa","aaaaa"]` | 4        | Repeated characters              |
| `s = "abc", words = ["a","a","a"]`                    | 3        | Duplicate words count separately |
| `s = "abc", words = ["d"]`                            | 0        | Character doesn't exist          |

The bucketing solution handles all these cases.

# **9. Comparison of all approaches**

Let:

- `N` = length of `s`.
- `W` = number of words.
- `L` = maximum word length.

| Approach                  | Time Complexity           | Space Complexity     |
| ------------------------- | ------------------------- | -------------------- |
| Generate all subsequences | \\(O(N \cdot 2^N + WL)\\) | \\(O(N \cdot 2^N)\\) |
| Two pointers              | \\(O(WN)\\) worst case    | \\(O(1)\\)           |
| Binary search + indexing  | \\(O(N + WL\log N)\\)     | \\(O(N)\\)           |
| Bucketing / Waiting lists | \\(O(N + WL)\\)           | \\(O(W)\\)           |

**My interview recommendation:**

1. Start with two pointers to establish the basic subsequence-checking logic.
2. Explain that repeated scanning of `s` is unnecessary.
3. Introduce character-position indexing as an intermediate optimization.
4. Present bucketing as the optimal solution.

# **10. Interviewer follow-up questions**

### **Q1. Why can't we use a simple HashSet of characters?**

Because a HashSet only tells us whether a character exists, not whether characters appear in the correct order or whether enough occurrences exist.

Example:

```
s = "abc"
word = "ca"
```

Both characters exist, but `"ca"` is not a subsequence.

### **Q2. Why do we need 26 buckets?**

Because the input contains only lowercase English letters.

Each bucket represents words waiting for one particular character.

If the character set were larger, we could use a HashMap or another suitable indexing structure.

### **Q3. What happens when multiple words wait for the same character?**

All of them are processed when that character appears in `s`.

For example:

```
s = "abc"

words = ["ab", "ac", "ad"]
```

All three initially wait for `a`.

When `a` appears, all three advance to their respective next required characters.

### **Q4. Does the algorithm correctly handle duplicate words?**

Yes.

Each occurrence of a word is inserted independently into a bucket.

Therefore:

```
words = new String[]{"abc", "abc", "abc"};
```

If `s = "abc"`, the answer is 3.

### **Q5. Why is the bucketing solution better than binary search?**

Binary search performs a lookup for every character of every word.

Its complexity is:

\\[ O(N + WL\log N) \\]

Bucketing processes each character of each word only once:

\\[ O(N + WL) \\]

It also avoids maintaining separate character-position lists.

### **Q6. Can we optimize the memory further?**

We can use mutable objects with an integer pointer instead of creating a new record every time a word advances.

However, the asymptotic space complexity remains \\(O(W)\\).

The record-based implementation is generally cleaner and easier to reason about.

### **Q7. What if the words array contains millions of words?**

The algorithm still scales linearly with the total number of characters across all words.

If memory becomes a concern, we can process words in batches while preserving the same bucketing technique.

## **Final takeaway**

Remember this mental model:

**Two pointers:** Check one word at a time.

**Binary search:** Precompute where characters occur and jump to the next valid position.

**Bucketing:** Let every word wait for its next required character. When that character appears in `s`, advance the word.

The key interview insight is that we can process all words simultaneously rather than repeatedly scanning the main string.

For LeetCode 792, I would choose **Approach 4: Bucketing / Waiting Lists — O(N + W × L) time and O(W) space.**
