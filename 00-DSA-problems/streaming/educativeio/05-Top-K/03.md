# **642. Design Search Autocomplete System**

**Difficulty:** Hard\
**Topics:** Design, Trie, HashMap, Priority Queue, Sorting

## **0. Understand the problem in simple terms**

We need to design an autocomplete system similar to Google Search or a search bar.

The system receives:

- A list of previously searched sentences.
- The frequency of each sentence (how many times it has been searched).

When a user types characters one by one, we need to return the **top 3 most frequently searched sentences matching the current prefix**.

### **Example**

Suppose we have:

```
sentences = ["i love you", "island", "ironman", "i love leetcode"];

times = [5, 3, 2, 2];
```

The user starts typing:

| Input | Current prefix | Suggestions                                     |
| ----- | -------------- | ----------------------------------------------- |
| `i`   | `"i"`          | `"i love you"`, `"island"`, `"i love leetcode"` |
| ` `   | `"i "`         | `"i love you"`, `"i love leetcode"`             |
| `a`   | `"i a"`        | No suggestions                                  |

Important ranking rules:

1. Higher frequency comes first.
2. If frequencies are equal, lexicographically smaller sentences come first.
3. Return at most three suggestions.
4. When the user enters `#`, the current sentence becomes a completed search and its frequency increases by one.
5. After `#`, reset the current input and start a new search.

The system exposes one operation:

```
List<String> input(char c);
```

## **1. Clarifying questions to ask the interviewer**

| Question                                                       | Why clarify?                                                |
| -------------------------------------------------------------- | ----------------------------------------------------------- |
| Can sentences contain spaces?                                  | Determines how we handle prefixes containing spaces.        |
| Are sentences case-sensitive?                                  | Determines whether matching and ranking need normalization. |
| Can the same sentence appear multiple times initially?         | Determines whether we need to aggregate frequencies.        |
| Must we return exactly three suggestions?                      | The requirement is at most three, depending on matches.     |
| Can new sentences be introduced dynamically?                   | Determines whether our data structure must support updates. |
| Is `#` reserved as the sentence terminator?                    | Determines special-character handling.                      |
| What are the maximum sentence lengths and number of sentences? | Helps choose between Trie, HashMap, and other approaches.   |

For the standard LeetCode problem, assume:

- Input sentences contain lowercase English letters and spaces.
- `#` indicates the end of a sentence.
- At most three suggestions are returned.
- Frequency updates happen immediately after `#`.

## **2. Core intuition and mental model**

The key challenge is:

**For every prefix, efficiently find the three best matching sentences.**

There are two separate problems:

1. Find sentences that begin with the current prefix.
2. Rank those sentences by frequency and lexicographical order.

A Trie is a natural solution for the first problem.

### **Why Trie?**

Imagine the following sentences:

```
i love you
i love leetcode
island
ironman
```

Their prefixes share common paths.

```
                    root
                     |
                     i
                   / | \
                  ' ' s  r
                  /   |  |
                 l   land onman
                /
               o
              / \
             v   leetcode
             |
             e
             |
             you
```

Conceptually, every Trie node represents a prefix.

For example:

- Node `i` represents prefix `"i"`.
- Node `i -> space` represents prefix `"i "`.
- Node `i -> space -> l` represents prefix `"i l"`.

When the user types a character, we simply move to the corresponding child node.

We don't need to scan every sentence again.

### **How do we get the top 3?**

There are two useful Trie-based approaches:

**Approach A: Trie + HashMap + Sorting**

- Trie identifies the prefix.
- Each Trie node stores the sentences matching that prefix.
- Sort those sentences by frequency and lexicographical order.
- Return the first three.

**Approach B: Trie + HashMap + PriorityQueue**

- Trie identifies the prefix.
- Each Trie node stores matching sentences.
- Use a heap to retrieve the best three.

**Approach C: Optimized Trie**

- Every Trie node directly maintains its top three suggestions.
- Each input character takes constant time to traverse the Trie.
- No sorting or heap construction is necessary during queries.

Approach C is particularly attractive because the result size is fixed at three.

## **3. Edge cases to watch out for**

1. **No matching prefix:** Return an empty list.
2. **Fewer than three matches:** Return only the available sentences.
3. **Equal frequencies:** Use lexicographical (ASCII) ordering.
4. **Spaces:** Spaces are valid characters and must be stored in the Trie.
5. **New sentence:** A sentence not present initially must be inserted after `#`.
6. **Existing sentence:** Increment its frequency rather than creating a duplicate.
7. **Invalid prefix:** Once a prefix has no matching Trie path, subsequent characters cannot produce matches until `#`.
8. **Reset after&#x20;**`#`**:** Clear the input buffer and reset the Trie pointer.
9. **Duplicate initial sentences:** If the input contains duplicate sentences, aggregate their frequencies.
10. **Empty current input:** Never insert an empty sentence when `#` is received.

## **4. Solutions: Brute force to optimal**

### **Approach 1: Brute force — HashMap + Sorting**

**Mental model:** Maintain all sentences and their frequencies in a HashMap. Every time the user types a character, scan all sentences and find those matching the current prefix.

Algorithm:

1. Store sentence-frequency pairs in a HashMap.
2. Maintain a StringBuilder for the current input.
3. For each character:
   - If `#`, increment the completed sentence's frequency and reset.
   - Otherwise, append the character.
   - Scan all sentences.
   - Keep sentences starting with the current prefix.
   - Sort by frequency descending and lexicographical order ascending.
   - Return the first three.

```java
import java.util.*;

class AutocompleteSystem {

    private final Map<String, Integer> frequency = new HashMap<>();

    private final StringBuilder currentInput = new StringBuilder();

    private static final Comparator<String> RANKING =
            (a, b) -> {

                /*
                 * Higher frequency must appear first.
                 *
                 * We use Integer.compare instead of subtraction
                 * to avoid integer overflow.
                 */
                int frequencyComparison =
                        Integer.compare(frequency.get(b), frequency.get(a));

                if (frequencyComparison != 0) {
                    return frequencyComparison;
                }

                /*
                 * Equal frequencies:
                 * Lexicographically smaller sentence comes first.
                 */
                return a.compareTo(b);
            };

    public AutocompleteSystem(String[] sentences, int[] times) {

        /*
         * Initialization: O(N * L)
         *
         * N = number of initial sentences.
         * L = average sentence length.
         *
         * HashMap insertion is O(1) average per sentence.
         *
         * Aggregating duplicate sentences also handles
         * duplicate initial entries correctly.
         */
        for (int i = 0; i < sentences.length; i++) {

            frequency.merge(sentences[i], times[i], Integer::sum);
        }
    }

    public List<String> input(char c) {

        /*
         * Special character '#':
         * The current sentence has been completed.
         *
         * Update its frequency and reset the input buffer.
         */
        if (c == '#') {

            String completedSentence = currentInput.toString();

            frequency.merge(completedSentence, 1, Integer::sum);

            currentInput.setLength(0);

            return List.of();
        }

        /*
         * Append the newly typed character.
         */
        currentInput.append(c);

        String prefix = currentInput.toString();

        /*
         * Step 1: Scan all known sentences.
         *
         * Step 2: Keep only sentences matching the prefix.
         *
         * contains() is NOT sufficient here.
         * We specifically need startsWith().
         */
        List<String> candidates = new ArrayList<>();

        for (String sentence : frequency.keySet()) {

            if (sentence.startsWith(prefix)) {

                candidates.add(sentence);
            }
        }

        /*
         * Sort candidates using the ranking comparator.
         *
         * If K sentences match the prefix:
         *
         * Time: O(K log K)
         */
        candidates.sort(RANKING);

        /*
         * Return at most three suggestions.
         */
        return candidates.subList(
                0,
                Math.min(3, candidates.size())
        );
    }
}
```

**Complexity analysis:**

Let:

- `N` = number of distinct sentences.
- `L` = average sentence length.
- `K` = number of sentences matching the current prefix.

| Operation             | Complexity         |
| --------------------- | ------------------ |
| Initialization        | O(N × L)           |
| Character input       | O(N × L + K log K) |
| Completing a sentence | O(L) average       |
| Space                 | O(N × L)           |

The character-input complexity includes scanning every sentence and checking its prefix.

**Why is this not optimal?**

Even if the user types `"xyz"` and only one sentence matches, we still scan every sentence.

We are doing unnecessary work.

We need a data structure that directly locates sentences sharing a prefix.

That leads us to Trie.

### **Approach 2: Trie + HashMap + Sorting**

This is the natural improvement.

**Mental model:**

Instead of scanning every sentence, store all sentences passing through each Trie node.

For example:

```
Sentences:

i love you
i love leetcode
island
ironman
```

At the node representing prefix `"i"`, store:

```
{
    "i love you",
    "i love leetcode",
    "island",
    "ironman"
}
```

At the node representing prefix `"i "`, store:

```
{
    "i love you",
    "i love leetcode"
}
```

At the node representing prefix `"i l"`, store the same two sentences.

This gives us direct access to the matching candidates.

#### **Trie structure**

```
                         root
                           |
                           i
                     /     |      \
                  space    s       r
                    |      |       |
                    l    island  ironman
                    |
                    o
                    |
                    v
                    |
                    e
                  /   \
                 y     l
                 |     |
                you  eetcode
```

Each Trie node maintains a collection of sentences that have that prefix.

We also maintain a global HashMap containing the latest frequency of every sentence.

```java
import java.util.*;

class AutocompleteSystem {

    private static class TrieNode {

        /*
         * Every child represents the next character.
         *
         * HashMap supports lowercase letters and spaces.
         * Unlike a fixed-size array, it also allows the
         * implementation to be extended to a larger alphabet.
         */
        Map<Character, TrieNode> children = new HashMap<>();

        /*
         * All sentences that share the prefix represented
         * by this Trie node.
         */
        Set<String> sentences = new HashSet<>();
    }

    private final TrieNode root = new TrieNode();

    private final Map<String, Integer> frequency = new HashMap<>();

    private final StringBuilder currentInput = new StringBuilder();

    private TrieNode currentNode = root;

    public AutocompleteSystem(String[] sentences, int[] times) {

        /*
         * Initialization:
         *
         * Insert every initial sentence into the Trie.
         *
         * Time: O(N * L) average.
         */
        for (int i = 0; i < sentences.length; i++) {

            frequency.merge(sentences[i], times[i], Integer::sum);
        }

        /*
         * Insert each distinct sentence with its aggregated
         * frequency.
         */
        for (String sentence : frequency.keySet()) {

            insert(sentence);
        }
    }

    private void insert(String sentence) {

        TrieNode node = root;

        /*
         * Traverse every character in the sentence.
         */
        for (char c : sentence.toCharArray()) {

            /*
             * Create a Trie node if this character path
             * does not exist.
             */
            node = node.children.computeIfAbsent(
                    c,
                    ignored -> new TrieNode()
            );

            /*
             * IMPORTANT:
             *
             * Store the sentence at EVERY node along the path.
             *
             * This ensures that every prefix node knows
             * all sentences matching that prefix.
             */
            node.sentences.add(sentence);
        }
    }

    public List<String> input(char c) {

        /*
         * '#' means the current sentence is completed.
         */
        if (c == '#') {

            String sentence = currentInput.toString();

            /*
             * Increase the sentence frequency.
             */
            frequency.merge(sentence, 1, Integer::sum);

            /*
             * Insert the sentence into the Trie.
             *
             * HashSet automatically avoids duplicates.
             */
            insert(sentence);

            /*
             * Reset state for the next search.
             */
            currentInput.setLength(0);

            currentNode = root;

            return List.of();
        }

        /*
         * Record the character.
         */
        currentInput.append(c);

        /*
         * If a previous character already led to a missing
         * Trie path, no later character can restore a match.
         *
         * We still append characters to currentInput because
         * the complete sentence must be saved after '#'.
         */
        if (currentNode == null) {

            return List.of();
        }

        /*
         * Move to the next Trie node.
         *
         * This takes O(1) average time with HashMap.
         */
        currentNode = currentNode.children.get(c);

        /*
         * Missing path means no sentence matches the prefix.
         */
        if (currentNode == null) {

            return List.of();
        }

        /*
         * Retrieve only sentences matching the current prefix.
         */
        List<String> candidates =
                new ArrayList<>(currentNode.sentences);

        /*
         * Sort by:
         *
         * 1. Frequency descending.
         * 2. Lexicographical order ascending.
         */
        candidates.sort((a, b) -> {

            int comparison = Integer.compare(
                    frequency.get(b),
                    frequency.get(a)
            );

            if (comparison != 0) {
                return comparison;
            }

            return a.compareTo(b);
        });

        /*
         * Return only the top three suggestions.
         */
        return candidates.subList(
                0,
                Math.min(3, candidates.size())
        );
    }
}
```

#### **Complexity analysis**

Let:

- `N` = number of distinct sentences.
- `L` = average sentence length.
- `K` = number of sentences matching the current prefix.

| Operation              | Complexity           |
| ---------------------- | -------------------- |
| Build Trie             | O(N × L) average     |
| Move to next character | O(1) average         |
| Retrieve candidates    | O(K)                 |
| Sort candidates        | O(K log K)           |
| Complete sentence      | O(L) average         |
| Space                  | O(N × L²) worst case |

**Why is space O(N × L²) instead of O(N × L)?**

This is an important interview observation.

A sentence of length `L` is stored in every Trie node along its path.

Therefore, a sentence of length `L` can contribute approximately:

\\[ L \times L = L^2 \\]

characters across all the stored references, if we count the logical string contents rather than shared String object storage.

The actual Java implementation stores references to existing String objects, so physical string storage is not duplicated at every node.

The Trie still has O(N × L) node and sentence-reference storage in the worst case, assuming distinct sentences and bounded branching.

**Limitation:**

We have improved prefix lookup, but we still sort all `K` matching sentences after every keystroke.

Can we avoid sorting all candidates when we only need three?

Yes. We can use a PriorityQueue.

### **Approach 3: Trie + PriorityQueue (Top-K Heap)**

**Mental model:**

We don't need the complete sorted list.

We only need the best three sentences.

So instead of sorting all candidates, maintain a heap of size at most three.

The trick is to make the heap's root represent the worst candidate among the currently selected top three.

Ranking:

```
Better candidate:
    Higher frequency
    OR
    Same frequency + lexicographically smaller sentence

Worst candidate:
    Lower frequency
    OR
    Same frequency + lexicographically larger sentence
```

Algorithm:

1. Traverse the Trie to find the current prefix node.
2. Iterate through its matching sentences.
3. Add each sentence to a bounded heap.
4. If heap size exceeds three, remove its worst candidate.
5. Return the remaining three in the correct order.

```java
import java.util.*;

class AutocompleteSystem {

    private static class TrieNode {

        Map<Character, TrieNode> children = new HashMap<>();

        Set<String> sentences = new HashSet<>();
    }

    private record Candidate(String sentence, int frequency) {}

    private final TrieNode root = new TrieNode();

    private final Map<String, Integer> frequency = new HashMap<>();

    private final StringBuilder currentInput = new StringBuilder();

    private TrieNode currentNode = root;

    /*
     * Best-first comparator:
     * Higher frequency first, then lexicographically smaller.
     */
    private static final Comparator<Candidate> BEST_FIRST =
            Comparator.comparingInt(Candidate::frequency)
                    .reversed()
                    .thenComparing(Candidate::sentence);

    /*
     * Worst-first comparator:
     * Lower frequency first, then lexicographically larger.
     *
     * The heap root will be the worst among the selected
     * three candidates.
     */
    private static final Comparator<Candidate> WORST_FIRST =
            Comparator.comparingInt(Candidate::frequency)
                    .thenComparing(
                            Candidate::sentence,
                            Comparator.reverseOrder()
                    );

    public AutocompleteSystem(String[] sentences, int[] times) {

        for (int i = 0; i < sentences.length; i++) {

            frequency.merge(sentences[i], times[i], Integer::sum);
        }

        for (String sentence : frequency.keySet()) {

            insert(sentence);
        }
    }

    private void insert(String sentence) {

        TrieNode node = root;

        for (char c : sentence.toCharArray()) {

            node = node.children.computeIfAbsent(
                    c,
                    ignored -> new TrieNode()
            );

            node.sentences.add(sentence);
        }
    }

    public List<String> input(char c) {

        if (c == '#') {

            String sentence = currentInput.toString();

            frequency.merge(sentence, 1, Integer::sum);

            insert(sentence);

            currentInput.setLength(0);

            currentNode = root;

            return List.of();
        }

        currentInput.append(c);

        if (currentNode == null) {

            return List.of();
        }

        currentNode = currentNode.children.get(c);

        if (currentNode == null) {

            return List.of();
        }

        /*
         * Maintain only the best three candidates.
         *
         * The root contains the worst candidate among
         * the currently selected top three.
         */
        PriorityQueue<Candidate> heap =
                new PriorityQueue<>(WORST_FIRST);

        for (String sentence : currentNode.sentences) {

            Candidate candidate = new Candidate(
                    sentence,
                    frequency.get(sentence)
            );

            heap.offer(candidate);

            /*
             * If more than three candidates exist,
             * remove the worst one.
             */
            if (heap.size() > 3) {

                heap.poll();
            }
        }

        /*
         * Extract at most three candidates.
         */
        List<Candidate> result = new ArrayList<>(heap);

        /*
         * Heap iteration does not guarantee sorted order.
         *
         * Therefore, explicitly sort the final three.
         */
        result.sort(BEST_FIRST);

        return result.stream()
                .map(Candidate::sentence)
                .toList();
    }
}
```

#### **Complexity analysis**

For a prefix matching `K` sentences:

| Operation                   | Complexity                       |
| --------------------------- | -------------------------------- |
| Trie traversal              | O(1) average                     |
| Process matching candidates | O(K log 3)                       |
| Sort final three            | O(1)                             |
| Complete sentence           | O(L) average                     |
| Space                       | O(N × L) for Trie and references |

Since `log 3` is constant:

\\[ O(K\log 3)=O(K) \\]

This is better than sorting all `K` candidates.

However, we still need to inspect every sentence matching the current prefix.

We can do better.

### **Approach 4: Optimized Trie + TreeSet (Best interview solution)**

This is the approach I would recommend presenting as the optimal design.

**Core insight:**

We repeatedly perform the same operation:

> Given a prefix, return the three highest-ranked sentences.

Instead of calculating the top three every time, why not maintain the top-ranked sentences in an ordered data structure?

We can use a `TreeSet` at every Trie node.

A TreeSet keeps elements sorted automatically.

Each Trie node maintains:

```
TrieNode
    |
    |-- children
    |
    |-- top-ranked sentences (TreeSet)
```

For example:

```
Prefix = "i"

TreeSet:
    1. i love you       (5)
    2. i love leetcode  (2)
    3. island           (3)
```

The actual ordering is:

```
1. i love you       (5)
2. island           (3)
3. i love leetcode  (2)
```

When a new sentence is completed, we update the TreeSet at every node along its prefix path.

When a sentence's frequency increases, we must update its old ranking and insert its new ranking.

#### **Important design decision: Why not use a PriorityQueue?**

A PriorityQueue is good for retrieving the best element, but it does not efficiently support arbitrary removal or modification of an existing element.

A TreeSet supports:

- `add()` — O(log K)
- `remove()` — O(log K)
- `first()` — O(1)
- Ordered iteration — O(K) for K elements

This makes it particularly suitable for maintaining dynamically changing rankings.

#### **Java 24 implementation**

```java
import java.util.*;

class AutocompleteSystem {

    /*
     * Immutable ranking information.
     *
     * Why use a record?
     *
     * 1. Concise representation of ranking data.
     * 2. Immutable fields.
     * 3. Automatically generated equals() and hashCode().
     *
     * We must not modify a ranking entry while it is inside
     * a TreeSet because that would violate its ordering.
     */
    private record Entry(String sentence, int frequency) {}

    private static class TrieNode {

        /*
         * Each child represents the next character.
         *
         * Supports lowercase English letters and spaces.
         */
        Map<Character, TrieNode> children = new HashMap<>();

        /*
         * Maintains ALL sentences matching this prefix,
         * ordered according to their ranking.
         *
         * The first element is always the best sentence.
         *
         * We maintain all matching sentences rather than
         * only three because a frequency update can change
         * which sentences belong to the top three.
         */
        TreeSet<Entry> rankedSentences = new TreeSet<>(

                Comparator.comparingInt(Entry::frequency)
                        .reversed()

                        /*
                         * When frequencies are equal,
                         * lexicographically smaller sentence wins.
                         */
                        .thenComparing(Entry::sentence)
        );
    }

    private final TrieNode root = new TrieNode();

    /*
     * Global source of truth for sentence frequencies.
     */
    private final Map<String, Integer> frequency = new HashMap<>();

    /*
     * Characters entered by the user so far.
     */
    private final StringBuilder currentInput = new StringBuilder();

    /*
     * Pointer to the Trie node representing the current prefix.
     */
    private TrieNode currentNode = root;

    /*
     * Constructor
     *
     * Time Complexity:
     * O(N * L * log N)
     *
     * Every sentence is inserted along its L-character path.
     * Each TreeSet insertion costs O(log N).
     */
    public AutocompleteSystem(String[] sentences, int[] times) {

        for (int i = 0; i < sentences.length; i++) {

            /*
             * Aggregate duplicate initial sentences.
             */
            frequency.merge(sentences[i], times[i], Integer::sum);
        }

        /*
         * Build the Trie and ranking sets.
         */
        for (var entry : frequency.entrySet()) {

            insert(entry.getKey(), entry.getValue());
        }
    }

    /*
     * Insert a new sentence into the Trie.
     *
     * This method assumes that the sentence is not already
     * present in the Trie.
     *
     * The sentence is added to the TreeSet at every node
     * along its prefix path.
     */
    private void insert(String sentence, int count) {

        TrieNode node = root;

        /*
         * Create the Trie path character by character.
         */
        for (char c : sentence.toCharArray()) {

            node = node.children.computeIfAbsent(
                    c,
                    ignored -> new TrieNode()
            );

            /*
             * Insert the sentence with its current frequency.
             *
             * TreeSet automatically maintains the ranking.
             */
            node.rankedSentences.add(
                    new Entry(sentence, count)
            );
        }
    }

    /*
     * Update the frequency of an existing sentence.
     *
     * This is the most important part of this design.
     *
     * Suppose:
     *
     * "i love you" has frequency 5.
     *
     * After another search:
     *
     * "i love you" has frequency 6.
     *
     * We must:
     *
     * 1. Remove Entry("i love you", 5) from every node
     *    along its Trie path.
     *
     * 2. Insert Entry("i love you", 6) into every node
     *    along the same path.
     *
     * Why remove before adding?
     *
     * TreeSet uses its comparator to maintain ordering.
     * We cannot simply mutate the frequency of an existing
     * element because the TreeSet would not automatically
     * reposition that element.
     */
    private void updateSentence(String sentence, int oldCount, int newCount) {

        TrieNode node = root;

        /*
         * Phase 1: Remove the old ranking entry.
         *
         * The path already exists because this is an
         * existing sentence.
         *
         * Time: O(L * log N)
         */
        if (oldCount > 0) {

            Entry oldEntry = new Entry(sentence, oldCount);

            for (char c : sentence.toCharArray()) {

                node = node.children.get(c);

                node.rankedSentences.remove(oldEntry);
            }
        }

        /*
         * Phase 2: Update the global frequency.
         */
        frequency.put(sentence, newCount);

        /*
         * Phase 3: Insert the new ranking entry.
         *
         * For a new sentence, missing Trie nodes are created.
         *
         * For an existing sentence, the existing path is reused.
         *
         * Time: O(L * log N)
         */
        insert(sentence, newCount);
    }

    public List<String> input(char c) {

        /*
         * Case 1: User completes the sentence.
         */
        if (c == '#') {

            String completedSentence = currentInput.toString();

            /*
             * Retrieve the previous frequency.
             *
             * If this is a new sentence, oldCount = 0.
             */
            int oldCount = frequency.getOrDefault(
                    completedSentence,
                    0
            );

            /*
             * Every completed search increases frequency by one.
             */
            updateSentence(
                    completedSentence,
                    oldCount,
                    oldCount + 1
            );

            /*
             * Reset the input state.
             */
            currentInput.setLength(0);

            currentNode = root;

            return List.of();
        }

        /*
         * Case 2: Normal character input.
         */

        /*
         * Always append the character.
         *
         * Even if the Trie path is missing, we must preserve
         * the complete input for insertion after '#'.
         */
        currentInput.append(c);

        /*
         * If an earlier prefix had no Trie path,
         * subsequent characters cannot produce a match.
         */
        if (currentNode == null) {

            return List.of();
        }

        /*
         * Traverse exactly one Trie edge.
         *
         * No need to restart from the root.
         *
         * Time: O(1) average.
         */
        currentNode = currentNode.children.get(c);

        /*
         * Prefix does not exist.
         */
        if (currentNode == null) {

            return List.of();
        }

        /*
         * Case 3: Return top three suggestions.
         *
         * TreeSet already maintains the correct order.
         *
         * Therefore, no sorting or heap construction
         * is necessary during a query.
         */
        List<String> result = new ArrayList<>(3);

        int count = 0;

        for (Entry entry : currentNode.rankedSentences) {

            if (count == 3) {
                break;
            }

            result.add(entry.sentence());

            count++;
        }

        /*
         * Return at most three matching sentences.
         */
        return result;
    }
}
```

### **Why this approach is optimal**

Let's compare the work performed by all four approaches.

| Operation        | Brute force  | Trie + Sorting | Trie + Heap  | Trie + TreeSet     |
| ---------------- | ------------ | -------------- | ------------ | ------------------ |
| Find prefix      | O(N × L)     | O(1)           | O(1)         | O(1)               |
| Rank candidates  | O(K log K)   | O(K log K)     | O(K log 3)   | Already maintained |
| Return top 3     | O(1)         | O(3)           | O(3)         | O(3)               |
| Update frequency | O(1) average | O(L) average   | O(L) average | O(L log N)         |

Here, `K` is the number of sentences matching the prefix.

**The important trade-off:**

- Trie + Sorting: cheaper updates, expensive queries.
- Trie + Heap: cheaper ranking than sorting, but still scans every matching candidate.
- Trie + TreeSet: more expensive updates, but extremely efficient queries.

For an autocomplete system, queries happen on every keystroke, whereas frequency updates happen only when a sentence is completed.

Therefore, trading update performance for query performance is a sensible design decision.

### **Detailed complexity of the optimized solution**

Let:

- `N` = number of distinct sentences.
- `L` = maximum sentence length.
- `K` = number of sentences sharing a particular prefix.

**1. Constructor**

Each sentence traverses at most `L` Trie nodes.

Each node performs a TreeSet insertion costing O(log N).

\\[ O(N \times L \times \log N) \\]

**2. input(character)**

- StringBuilder append: amortized O(1).
- Trie traversal: O(1) average.
- Retrieving top three: O(3) = O(1).

Therefore:

\\[ \boxed{O(1)\text{ average per character}} \\]

**3. input('#')**

We remove the old entry and insert the new entry at every node along the sentence path.

Each operation costs O(log N).

\\[ \boxed{O(L \times \log N)} \\]

For a new sentence, insertion also creates its Trie path.

**4. Space complexity**

Each sentence is stored in every Trie node along its path.

There are at most O(N × L) sentence references across all TreeSets.

The Trie itself contains at most O(N × L) nodes.

Therefore:

\\[ \boxed{O(N \times L)\text{ space}} \\]

This counts stored references and Trie nodes, excluding the actual character storage of the sentence objects.

## **6. Interviewer follow-up questions and answers**

### **Q1. Why use a Trie instead of a HashMap?**

A HashMap can store sentence-frequency pairs, but it cannot efficiently retrieve all sentences sharing a prefix.

A Trie allows us to traverse the prefix character by character.

For example, for prefix `"apple"`:

- HashMap: potentially scan every sentence.
- Trie: traverse five edges and reach the exact prefix node.

### **Q2. Why store sentences at every Trie node?**

Because every node represents a prefix.

If we store sentences only at leaf nodes, we cannot directly retrieve all sentences matching an intermediate prefix.

For example, node `"app"` must know about:

```
apple
application
appreciate
```

### **Q3. Why not store only the top three sentences at each Trie node?**

That is an interesting optimization.

We could store only three sentences per node.

However, consider:

```
apple  -> 10
application -> 9
appreciate -> 8
apparel -> 7
```

Initially, the top three are:

```
apple
application
appreciate
```

Now suppose `apparel` is searched 20 times.

It should enter the top three.

If we maintain only three candidates without retaining any way to discover the fourth candidate, we cannot correctly update the ranking.

**Possible solution:**

Maintain a separate set of all matching candidates or an appropriately designed index.

Alternatively, maintain the top three at every node and update them by considering the changed sentence and the next-best candidate from a secondary structure.

### **Q4. Why can't we modify an Entry's frequency directly inside TreeSet?**

Because TreeSet relies on its comparator to maintain sorted ordering.

Suppose:

```
apple -> 10
banana -> 8
orange -> 5
```

If we modify `orange` to frequency 20 without removing and reinserting it, TreeSet does not automatically reposition it.

The internal tree can become inconsistent with the comparator.

Therefore:

```java
treeSet.remove(oldEntry);

treeSet.add(newEntry);
```

We use immutable records to prevent accidental mutation.

### **Q5. Why use&#x20;**`StringBuilder`**&#x20;instead of String concatenation?**

Repeated String concatenation:

```
currentInput = currentInput + c;
```

creates new String objects.

StringBuilder maintains a mutable character buffer.

Appending a character is amortized O(1).

### **Q6. What happens if the Trie path becomes null?**

Suppose the user types:

```
xyz
```

And no sentence starts with `"x"`.

After typing `x`, `currentNode` becomes null.

For subsequent characters, we should not attempt Trie traversal.

However, we must continue building the input string because the user might finish the sentence with `#`.

This is why we append before checking whether the Trie pointer is null.

### **Q7. Can we replace HashMap children with an array?**

Yes.

The problem permits:

- 26 lowercase English letters.
- One space character.

We can use an array of size 27.

Mapping:

```java
private int index(char c) {

    return c == ' '
            ? 26
            : c - 'a';
}
```

Then:

```java
TrieNode[] children = new TrieNode[27];
```

Advantages:

- O(1) worst-case child lookup.
- Less hashing overhead.
- Predictable memory layout.

Disadvantages:

- Every node allocates 27 references, even when most children are absent.
- Less flexible if the character set expands.

### **Q8. What if we need top 10 instead of top 3?**

The TreeSet implementation requires almost no changes.

Replace:

```java
if (count == 3) {
    break;
}
```

With:

```java
if (count == 10) {
    break;
}
```

The query complexity becomes O(10), which is still O(1) when K is fixed.

For a variable K, retrieving the first K entries takes O(K).

### **Q9. What if a sentence needs to be deleted?**

We need to:

1. Find the sentence's Trie path.
2. Remove its Entry from every TreeSet along the path.
3. Remove its frequency from the global HashMap.
4. Optionally prune Trie nodes that no longer contain any sentences.

The removal cost is:

\\[ O(L\log N) \\]

### **Q10. Is this implementation thread-safe?**

No.

Multiple threads modifying the TreeSets, HashMap, and current input buffer concurrently can cause race conditions.

For a production implementation, we would need synchronization or carefully designed concurrent data structures.

We would also need to separate user-session input state from the shared autocomplete index.

## **7. Final interview comparison**

| Approach             | Query complexity     | Update complexity | Recommendation         |
| -------------------- | -------------------- | ----------------- | ---------------------- |
| HashMap + Sorting    | O(N × L + K log K)   | O(1) average      | Brute force            |
| Trie + Sorting       | O(K log K)           | O(L) average      | Good                   |
| Trie + PriorityQueue | O(K)                 | O(L) average      | Better                 |
| Trie + TreeSet       | O(1) for fixed top 3 | O(L log N)        | Best query performance |

### **What I would say to the interviewer**

"I would initially consider a HashMap and sorting, but that requires scanning all sentences for every keystroke.

Since this is fundamentally a prefix-search problem, I would move to a Trie.

To optimize ranking, I would consider a bounded PriorityQueue, which avoids sorting all matching candidates but still scans them.

For the strongest query performance, I would maintain a TreeSet at every Trie node, ordered by frequency descending and lexicographical order ascending.

When a sentence is completed, I update its ranking along its Trie path by removing the old immutable entry and inserting the new one.

This gives us O(1) average query time per character for a fixed top three, at the cost of O(L log N) when a sentence is completed."

**My recommendation:** Understand and implement Approach 2 first. Then master Approach 4. The most important interview insight is understanding the trade-off between query performance and update performance.
