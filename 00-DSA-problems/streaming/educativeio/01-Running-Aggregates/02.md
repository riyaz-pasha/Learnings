# **1352. Product of the Last K Numbers**

**Difficulty:** Medium\
**Topics:** Array, Design, Prefix Sum, Math\
**Core concept:** Prefix Product + Zero Handling

## **0. Simplify the problem statement**

We need to design a data structure that supports two operations:

1. `add(num)`: Add a number to the end of a stream.
2. `getProduct(k)`: Return the product of the last `k` numbers.

For example:

```
add(3)  → [3]
add(0)  → [3, 0]
add(2)  → [3, 0, 2]
add(5)  → [3, 0, 2, 5]
add(4)  → [3, 0, 2, 5, 4]

getProduct(2) → 5 * 4 = 20
getProduct(3) → 2 * 5 * 4 = 40
getProduct(4) → 0 * 2 * 5 * 4 = 0
```

The challenge is to make both operations run in **O(1)** time.

A straightforward implementation of `getProduct(k)` would iterate over the last `k` elements, which takes O(k).

Can we avoid that iteration?

Yes, using prefix products.

## **1. Clarifying questions to ask the interviewer**

Before implementing, clarify:

**Q1. Can the stream contain zero?**

Why ask?

Zero is important because division by zero is undefined. It also means any product containing zero must be zero.

The constraints explicitly allow zero.

**Q2. Can the stream contain negative numbers?**

Why ask?

Negative numbers are supported by prefix products, but the constraints here guarantee `0 <= num <= 100`.

**Q3. Can the product overflow a 32-bit integer?**

Why ask?

Prefix products can become larger than the product of the last `k` elements.

Even if the requested answer fits in an `int`, intermediate prefix products might overflow.

The problem guarantees that the product of the stream at any point fits in a 32-bit integer. We can therefore use `int` for the prefix products.

**Q4. Can&#x20;**`getProduct(k)`**&#x20;request elements before the most recent zero?**

Why ask?

This determines how we handle zero boundaries.

The answer is yes, but any such range containing zero must return zero.

## **2. Core idea: Prefix Products**

Think about how we solve range-sum queries using prefix sums.

For an array:

```
nums = [2, 3, 4, 5]
```

Prefix sums:

```
prefixSum = [2, 5, 9, 14]
```

The sum of the last two elements is:

```
prefixSum[3] - prefixSum[1]
= 14 - 5
= 9
```

Can we do something similar with multiplication?

Yes!

Instead of prefix sums, maintain prefix products.

### **2.1 Prefix product formula**

Consider:

```
nums = [2, 3, 4, 5]
```

Maintain cumulative products:

```
prefixProduct = [1, 2, 6, 24, 120]
```

Notice that we include an initial `1`.

This makes the indexing and division formula convenient.

To calculate the product of the last `k` elements:

\\[ product = \frac{prefix[n]}{prefix[n-k]} \\]

For example, the last two elements:

```
nums = [2, 3, 4, 5]

prefix = [1, 2, 6, 24, 120]

getProduct(2):

prefix[4] / prefix[2]
= 120 / 6
= 20
```

Excellent!

We have reduced `getProduct(k)` from O(k) to O(1).

But there is one problem.

### **2.2 The zero problem**

Consider:

```
nums = [2, 3, 0, 4, 5]
```

If we calculate cumulative products:

```
prefix = [1, 2, 6, 0, 0, 0]
```

Now consider:

```
getProduct(2)
```

Expected:

```
4 * 5 = 20
```

But the prefix formula gives:

```
prefix[5] / prefix[3]
= 0 / 0
```

Division by zero is undefined.

We need a way to handle zeros.

### **2.3 The key observation: Reset prefix products after zero**

Whenever we encounter zero:

- Clear the previous prefix products.
- Start a new prefix product sequence with `1`.

Why?

Because any query that includes the zero must return zero.

We only need prefix products for numbers appearing after the most recent zero.

Consider:

```
add(2)
add(3)
add(0)
add(4)
add(5)
```

Our prefix products evolve as follows:

```
Initially:
[1]

add(2):
[1, 2]

add(3):
[1, 2, 6]

add(0):
[1]

add(4):
[1, 4]

add(5):
[1, 4, 20]
```

Now:

```
getProduct(2):

prefix[2] / prefix[0]
= 20 / 1
= 20
```

What about:

```
getProduct(3)
```

We have only two prefix-product elements after the last zero.

Therefore, the requested range contains a zero.

Return `0`.

This gives us the optimal solution.

## **4. All possible solutions**

### **Solution 1: Brute Force**

**Idea:** Maintain all numbers in an array/list. For every query, iterate backwards and multiply the last `k` numbers.

```java
import java.util.ArrayList;
import java.util.List;

class ProductOfNumbers {

    private final List<Integer> numbers;

    public ProductOfNumbers() {
        numbers = new ArrayList<>();
    }

    public void add(int num) {
        // Simply append the new number.
        // O(1) amortized time because ArrayList dynamically grows.
        numbers.add(num);
    }

    public int getProduct(int k) {

        int product = 1;

        // Traverse the last k elements.
        // We iterate backwards because we only need the suffix.
        for (int i = numbers.size() - 1;
             i >= numbers.size() - k;
             i--) {

            product *= numbers.get(i);
        }

        return product;
    }

    /*
     * Time Complexity:
     *
     * add():
     * O(1) amortized.
     *
     * getProduct(k):
     * O(k), because we explicitly multiply the last k numbers.
     *
     * Space Complexity:
     * O(n), where n is the total number of added elements.
     *
     * Drawback:
     * Repeated queries can repeatedly traverse the same elements.
     * We want O(1) query time.
     */
}
```

**Problem:** `getProduct(k)` takes O(k).

### **Solution 2: Prefix Products Without Zero Handling**

**Idea:** Store cumulative products and use division to calculate range products.

For every new number:

\\[ prefix[i] = prefix[i-1] \times num \\]

For every query:

\\[ answer = \frac{prefix[n]}{prefix[n-k]} \\]

```java
import java.util.ArrayList;
import java.util.List;

class ProductOfNumbers {

    private final List<Integer> prefix;

    public ProductOfNumbers() {
        prefix = new ArrayList<>();

        // Sentinel value makes the first prefix product convenient.
        prefix.add(1);
    }

    public void add(int num) {

        // Append cumulative product.
        int previous = prefix.get(prefix.size() - 1);

        prefix.add(previous * num);
    }

    public int getProduct(int k) {

        int n = prefix.size();

        // Product of the last k elements =
        // total prefix product / prefix product before the range.
        return prefix.get(n - 1) / prefix.get(n - 1 - k);
    }

    /*
     * Time Complexity:
     *
     * add(): O(1)
     * getProduct(k): O(1)
     *
     * Space Complexity:
     * O(n)
     *
     * Problem:
     *
     * Consider:
     * nums = [2, 3, 0, 4, 5]
     *
     * prefix = [1, 2, 6, 0, 0, 0]
     *
     * getProduct(2):
     * 0 / 0 -> ArithmeticException
     *
     * Therefore, this approach is incorrect when zeros exist.
     */
}
```

This solution establishes the prefix-product idea, but we need to handle zeros.

### **Solution 3: Optimal Solution — Prefix Products with Zero Reset**

This is the solution I would recommend in an interview.

```java
import java.util.ArrayList;
import java.util.List;

class ProductOfNumbers {

    private final List<Integer> prefix;

    public ProductOfNumbers() {

        prefix = new ArrayList<>();

        // Sentinel value.
        //
        // prefix[0] = 1 allows us to calculate products
        // without special handling for ranges starting at index 0.
        //
        // It also represents an empty product, which is mathematically 1.
        prefix.add(1);
    }

    public void add(int num) {

        // CASE 1: A zero is encountered.
        if (num == 0) {

            // Any product containing this zero must be zero.
            //
            // Previous prefix products are no longer useful
            // because no valid non-zero suffix can cross this zero.
            //
            // Resetting also ensures that future queries
            // never perform division by zero.
            prefix.clear();

            // Start a fresh prefix-product sequence.
            prefix.add(1);

            return;
        }

        // CASE 2: Non-zero number.
        //
        // The latest prefix product represents the product
        // of all numbers since the most recent zero.
        int previousProduct = prefix.get(prefix.size() - 1);

        // Append the new cumulative product.
        //
        // Example:
        // prefix = [1, 2, 6]
        // add(4)
        // prefix = [1, 2, 6, 24]
        prefix.add(previousProduct * num);
    }

    public int getProduct(int k) {

        int n = prefix.size();

        // If k >= n, the requested range contains at least
        // one zero.
        //
        // Why?
        //
        // prefix contains:
        // [1, products after the most recent zero]
        //
        // Therefore, n - 1 is the number of non-zero elements
        // after the most recent zero.
        //
        // If k is greater than that count, the requested
        // suffix must include a zero.
        if (k >= n) {
            return 0;
        }

        // Both prefix indices are guaranteed to be valid.
        //
        // prefix[n - 1]     = product of all elements after last zero.
        // prefix[n - 1 - k] = product before the last k elements.
        //
        // Dividing cancels the earlier elements.
        //
        // Example:
        // prefix = [1, 2, 6, 24, 120]
        // k = 2
        //
        // answer = 120 / 6 = 20
        return prefix.get(n - 1) / prefix.get(n - 1 - k);
    }

    /*
     * TIME COMPLEXITY:
     *
     * add(num):
     * O(1) amortized.
     *
     * - Reading the last prefix product takes O(1).
     * - Appending to ArrayList takes O(1) amortized.
     * - Resetting the prefix list after zero is O(1) here,
     *   because ArrayList.clear() clears its logical elements
     *   without individually traversing them.
     *
     * getProduct(k):
     * O(1).
     *
     * - Checking the prefix list size takes O(1).
     * - Two ArrayList.get() operations take O(1).
     * - Integer division takes O(1).
     *
     * SPACE COMPLEXITY:
     * O(m), where m is the number of non-zero elements
     * after the most recent zero.
     *
     * Worst case:
     * O(n), if no zero ever appears.
     *
     * IMPORTANT:
     * The problem guarantees that the product of the entire
     * stream fits in a signed 32-bit integer.
     * Therefore, int is sufficient for the stored products.
     */
}
```

This verifies that queries crossing a zero correctly return zero.

## **6. Why does the zero-reset technique work?**

This is an important interview discussion.

Suppose the stream is:

```
[2, 3, 0, 4, 5, 6]
```

The last zero divides the stream into two independent sections:

```
[2, 3, 0] | [4, 5, 6]
```

Any suffix query has only two possibilities:

**Case 1: The requested suffix is entirely after the last zero.**

Example:

```
getProduct(2) = 5 * 6 = 30
```

We can calculate it using prefix division.

**Case 2: The requested suffix crosses the last zero.**

Example:

```
getProduct(4) = 0 * 4 * 5 * 6 = 0
```

We immediately return zero.

Therefore, we never need to retain prefix products from before the last zero.

This is the central insight.

## **7. Interviewer follow-up questions**

### **Q1. Why do we initialize the prefix list with 1 instead of 0?**

Because 1 is the multiplicative identity:

\\[ a \times 1 = a \\]

It allows us to calculate prefix products without special cases.

For example:

```
nums = [2, 3, 4]

prefix = [1, 2, 6, 24]
```

For the entire array:

```
getProduct(3)
= prefix[3] / prefix[0]
= 24 / 1
= 24
```

If we initialized with zero, every prefix product would remain zero.

### **Q2. Why is the condition&#x20;**`k >= prefix.size()`**&#x20;and not&#x20;**`k > prefix.size()`**?**

Because the prefix list contains one extra element: the sentinel.

Example:

```
Stream: [2, 3, 4]

Prefix: [1, 2, 6, 24]

prefix.size() = 4
```

There are only three actual elements.

If:

```
k = 3
```

We need:

```
prefix[3] / prefix[0] = 24
```

But:

```
k = 4
```

The requested range cannot exist entirely after the last zero.

Therefore:

```
if (k >= prefix.size()) {
    return 0;
}
```

### **Q3. Why can't we simply maintain the product of all numbers?**

Because a query asks for the product of a suffix, not necessarily the entire stream.

For example:

```
[2, 3, 4, 5]

Total product = 120
```

To obtain the last two elements:

```
120 / (2 * 3) = 20
```

We need prefix products to efficiently cancel the earlier elements.

### **Q4. What if negative numbers are allowed?**

The same prefix-product approach works.

For example:

```
nums = [-2, 3, -4]

prefix = [1, -2, -6, 24]
```

Last two elements:

```
24 / -2 = -12
```

The result is correct.

Zero handling remains exactly the same.

However, we must ensure that intermediate prefix products do not overflow. If they can, we need a different representation or arithmetic strategy.

### **Q5. Can we use an array instead of ArrayList?**

Yes.

Since the problem specifies at most 40,000 operations, we can use a fixed-size integer array.

We only need:

- An array to store prefix products.
- An integer representing the current size.

This avoids dynamic array resizing.

### **Q6. Can we reduce the space complexity to O(1)?**

Not while retaining O(1) query time for arbitrary `k` with this prefix-product technique.

We need previously computed prefix products to answer suffix queries through division.

In the worst case, when no zero appears, we retain O(n) prefix products.

## **8. Complexity comparison**

| Approach                             | add(num)       | getProduct(k) | Space           |
| ------------------------------------ | -------------- | ------------- | --------------- |
| Brute force                          | O(1) amortized | O(k)          | O(n)            |
| Prefix product without zero handling | O(1) amortized | O(1)          | O(n)            |
| Prefix product with zero reset       | O(1) amortized | O(1)          | O(n) worst case |

The optimal solution satisfies the follow-up requirement.

## **9. What I would actually write in an interview**

If the interviewer asks you to implement the problem, I would start with this concise implementation:

```java
import java.util.ArrayList;
import java.util.List;

class ProductOfNumbers {

    private final List<Integer> prefix = new ArrayList<>();

    public ProductOfNumbers() {
        prefix.add(1);
    }

    public void add(int num) {

        if (num == 0) {
            prefix.clear();
            prefix.add(1);
            return;
        }

        int last = prefix.get(prefix.size() - 1);

        prefix.add(last * num);
    }

    public int getProduct(int k) {

        int n = prefix.size();

        if (k >= n) {
            return 0;
        }

        return prefix.get(n - 1) / prefix.get(n - 1 - k);
    }
}
```

**Interview takeaway:**

Remember this pattern:

- Range Sum → Prefix Sum + Subtraction.
- Range Product → Prefix Product + Division.
- Product with Zero → Reset prefix products at zero.

The broader lesson is that **a zero acts as a natural boundary for multiplication-based prefix queries**. By resetting at that boundary, we achieve O(1) time for both operations.
