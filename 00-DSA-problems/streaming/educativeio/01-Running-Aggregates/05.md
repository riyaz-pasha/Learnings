# **LeetCode 2656? Design an Array Statistics Tracker**

The key concept in this problem is **maintaining multiple statistics of a dynamically changing array efficiently**.

We want to avoid recalculating the entire array whenever an element is added, removed, or a statistic is requested.

Let's first understand the required operations and then derive solutions from brute force to optimal.

## **0. Understand the problem**

**Problem number: 3369 — Design an Array Statistics Tracker (Hard)**

We need to implement a class called `StatisticsTracker` that maintains a collection of integers and supports five operations.

| Operation                  | Description                               |
| -------------------------- | ----------------------------------------- |
| `StatisticsTracker()`      | Initialize an empty tracker               |
| `addNumber(number)`        | Add a number to the collection            |
| `removeFirstAddedNumber()` | Remove the oldest inserted number         |
| `getMean()`                | Return the floored average                |
| `getMedian()`              | Return the middle element in sorted order |
| `getMode()`                | Return the most frequent element          |

There are three important rules:

1. **Mean:** Return the average rounded down.
2. **Median:** If there are two middle elements, return the larger one.
3. **Mode:** If multiple numbers have the highest frequency, return the smallest number.

### **Example**

Suppose we perform:

```
addNumber(4)
addNumber(4)
addNumber(2)
addNumber(3)
```

The collection in insertion order is:

```
[4, 4, 2, 3]
```

Its sorted representation is:

```
[2, 3, 4, 4]
```

Now:

- Mean = (4 + 4 + 2 + 3) / 4 = 3.25 → `3`
- Median = larger middle element = `4`
- Mode = most frequent element = `4`

Therefore:

```
getMean()   -> 3
getMedian() -> 4
getMode()   -> 4
```

Now execute:

```
removeFirstAddedNumber()
```

The oldest number, `4`, is removed.

The collection becomes:

```
[4, 2, 3]
```

Sorted:

```
[2, 3, 4]
```

All elements have frequency 1, so the smallest number wins the mode tie.

```
getMedian() -> 3
getMode()   -> 2
```

### **What makes this problem hard?**

Each statistic requires a different kind of information:

| Statistic      | Information needed                  |
| -------------- | ----------------------------------- |
| Mean           | Sum and number of elements          |
| Median         | Elements maintained in sorted order |
| Mode           | Frequency of every distinct number  |
| Oldest removal | Insertion order                     |

The challenge is maintaining all four pieces of information consistently as elements are inserted and removed.

## **1. Clarifying questions to ask the interviewer**

Before implementing, clarify these points.

**Q1. Can the same number be inserted multiple times?**

Why ask?

Because duplicates affect both median and mode. We must maintain frequencies rather than treating the collection as a set.

Answer: Yes.

**Q2. Does removal always remove the earliest inserted element?**

Why ask?

This determines whether we need a FIFO queue.

Answer: Yes.

**Q3. What happens when there are two middle elements?**

Why ask?

There are two common median definitions: average of the middle two or selecting one of them.

Answer: Return the larger middle element.

**Q4. How should mode ties be resolved?**

Why ask?

Several values can have the same maximum frequency.

Answer: Return the smallest value.

**Q5. Can the collection become empty when a query is executed?**

Why ask?

This determines whether we need special handling for empty collections.

Answer: No. Removal and statistical queries are guaranteed to happen only when the collection is non-empty.

**Q6. What are the constraints?**

Why ask?

The constraints determine whether recalculating statistics from scratch is acceptable.

Important constraints:

- `1 <= number <= 10^9`
- At most `10^5` total operations.

This strongly suggests that we should target approximately `O(log n)` update operations.

Let's understand each responsibility.

### **A. Queue — maintain insertion order**

We need to remove the oldest inserted number.

Use:

```
Deque<Integer> queue = new ArrayDeque<>();
```

Insertion:

```
queue.offerLast(number);
```

Removal:

```
int oldest = queue.pollFirst();
```

Both operations take `O(1)` time.

### **B. Running sum — maintain the mean**

Instead of calculating the sum every time someone requests the mean, maintain it incrementally.

On insertion:

```
sum += number;
count++;
```

On removal:

```
sum -= oldest;
count--;
```

Query:

```
return (int) (sum / count);
```

Because all numbers are positive, integer division gives the required floor.

**Complexity:**

- Add: `O(1)`
- Remove: `O(1)`
- Mean: `O(1)`

### **C. Median — maintain two heaps**

This is the most important part.

We need the element at sorted index:

```
n / 2
```

Notice that this automatically selects the larger middle element when the collection size is even.

Use two heaps:

1. `lower`: Max heap containing the smaller half.
2. `upper`: Min heap containing the larger half.

The invariant is:

```
Every element in lower <= every element in upper

upper.size() == lower.size()
OR
upper.size() == lower.size() + 1
```

Why do we put the extra element in `upper`?

Because we want the larger middle element.

Consider:

```
Numbers: [1, 2, 3, 4]

lower (max heap): [2, 1]
upper (min heap): [3, 4]

Median = upper.peek() = 3
```

For an odd-sized collection:

```
Numbers: [1, 2, 3, 4, 5]

lower (max heap): [2, 1]
upper (min heap): [3, 4, 5]

Median = upper.peek() = 3
```

Therefore:

```
return upper.peek();
```

**But there is a complication.**

When we remove the oldest number, it might be located anywhere inside either heap.

Java's `PriorityQueue` does not support efficient arbitrary-element deletion.

We solve this using **Lazy Deletion**.

Instead of immediately deleting an element from a heap, we:

1. Mark the element as deleted in a frequency map.
2. Update the logical heap size.
3. Whenever a deleted element reaches the heap's top, physically remove it.

We maintain separate deletion maps for the two heaps because identical values can exist in both heaps.

This is important for correctness.

### **D. Mode — maintain frequencies**

Use a frequency map:

```
Map<Integer, Integer> frequency = new HashMap<>();
```

For example:

```
Numbers: [2, 3, 2, 4, 3, 2]

Frequency:
2 -> 3
3 -> 2
4 -> 1
```

The mode is `2`.

But how do we get the mode without scanning the entire frequency map every time?

Maintain an ordered set of pairs:

```
(frequency, number)
```

Ordered by:

1. Frequency descending.
2. Number ascending.

For example:

```
(3, 2)
(2, 3)
(1, 4)
```

The first element always represents the mode.

In Java, we can use:

```
TreeSet<ModeEntry>
```

Whenever a number's frequency changes:

1. Remove its old `(frequency, number)` entry.
2. Update its frequency.
3. Insert its new entry.

The first entry is always the correct mode.

**Complexity:**

- Frequency update: `O(log n)`
- Mode query: `O(1)` using `first()`.

## **3. Edge cases to watch out for**

| Edge case                        | Expected behavior                         |
| -------------------------------- | ----------------------------------------- |
| Only one element                 | Mean, median and mode return that element |
| Duplicate elements               | Frequencies must be maintained correctly  |
| All elements identical           | That element is the mode                  |
| Two elements                     | Median is the larger element              |
| Multiple modes                   | Return the smallest value                 |
| Remove the current median        | Rebalance the heaps                       |
| Remove the current mode          | Update its frequency and mode ordering    |
| Large values                     | Use `long` for the running sum            |
| Repeated insertions and removals | Lazy deletion must remain correct         |

One particularly important edge case is:

```
Numbers = [2, 2, 3, 3]
```

Both `2` and `3` have frequency 2.

The answer must be:

```
getMode() -> 2
```

Not `3`.

## **4. All approaches: Brute force to optimal**

### **Approach 1: Brute force — recalculate everything**

**Mental model:** Store all elements in a list. Whenever a statistic is requested, calculate it from scratch.

- Mean: Iterate over the list and calculate the sum.
- Median: Copy and sort the list, then access index `size / 2`.
- Mode: Build a frequency map and find the most frequent element, breaking ties by smallest value.
- Removal: Remove the first element.

```java

import java.util.*;

class StatisticsTrackerBruteForce {

    private final List<Integer> numbers = new ArrayList<>();

    public void addNumber(int number) {
        numbers.add(number);
    }

    public void removeFirstAddedNumber() {
        numbers.remove(0);
        // O(n): ArrayList shifts all remaining elements.
    }

    public int getMean() {
        long sum = 0;

        for (int number : numbers) {
            sum += number;
        }

        // O(n) time, O(1) auxiliary space.
        // Integer division gives the floor because numbers are positive.
        return (int) (sum / numbers.size());
    }

    public int getMedian() {
        List<Integer> sorted = new ArrayList<>(numbers);
        Collections.sort(sorted);

        // Index n / 2 selects the larger middle element for even n.
        // O(n log n) time and O(n) additional space.
        return sorted.get(sorted.size() / 2);
    }

    public int getMode() {
        Map<Integer, Integer> frequency = new HashMap<>();

        for (int number : numbers) {
            frequency.merge(number, 1, Integer::sum);
        }

        int mode = -1;
        int maxFrequency = 0;

        for (var entry : frequency.entrySet()) {
            int number = entry.getKey();
            int count = entry.getValue();

            if (count > maxFrequency ||
                (count == maxFrequency && number < mode)) {

                maxFrequency = count;
                mode = number;
            }
        }

        // O(n) time and O(d) additional space,
        // where d is the number of distinct values.
        return mode;
    }
}

```

**Complexity analysis**

Let `n` be the number of elements and `d` the number of distinct elements.

| Operation              | Time           |
| ---------------------- | -------------- |
| addNumber              | O(1) amortized |
| removeFirstAddedNumber | O(n)           |
| getMean                | O(n)           |
| getMedian              | O(n log n)     |
| getMode                | O(n)           |

Space: `O(n)`.

**Why is this insufficient?**

With up to `10^5` operations, repeatedly sorting or scanning the collection can become expensive.

We need to maintain statistics incrementally.

### **Approach 2: TreeMap + frequency map**

**Mental model:** Maintain a sorted representation of the collection instead of sorting whenever the median is requested.

Use:

```
TreeMap<Integer, Integer> sorted;
```

The key is the number, and the value is its frequency.

Example:

```
Numbers: [5, 2, 5, 3, 2, 5]

TreeMap:
2 -> 2
3 -> 1
5 -> 3
```

We can find the median by traversing the sorted entries and counting occurrences until reaching index `n / 2`.

The mode can similarly be found by scanning the frequencies.

```java

import java.util.*;

class StatisticsTrackerTreeMap {

    private final Deque<Integer> queue = new ArrayDeque<>();
    private final TreeMap<Integer, Integer> sorted = new TreeMap<>();

    private long sum = 0;
    private int size = 0;

    public void addNumber(int number) {
        queue.offerLast(number);

        sorted.merge(number, 1, Integer::sum);

        sum += number;
        size++;
    }

    public void removeFirstAddedNumber() {
        int number = queue.pollFirst();

        int frequency = sorted.get(number);

        if (frequency == 1) {
            sorted.remove(number);
        } else {
            sorted.put(number, frequency - 1);
        }

        sum -= number;
        size--;
    }

    public int getMean() {
        return (int) (sum / size);
        // O(1).
    }

    public int getMedian() {
        int target = size / 2;
        int index = 0;

        for (var entry : sorted.entrySet()) {
            index += entry.getValue();

            if (index > target) {
                return entry.getKey();
            }
        }

        throw new IllegalStateException();
    }

    public int getMode() {
        int mode = -1;
        int maxFrequency = 0;

        for (var entry : sorted.entrySet()) {
            int number = entry.getKey();
            int frequency = entry.getValue();

            if (frequency > maxFrequency) {
                maxFrequency = frequency;
                mode = number;
            }
            // Because TreeMap iterates in ascending order,
            // retaining the first maximum automatically
            // implements the smallest-number tie-breaking rule.
        }

        return mode;
    }
}

```

**Complexity analysis**

| Operation              | Time     |
| ---------------------- | -------- |
| addNumber              | O(log d) |
| removeFirstAddedNumber | O(log d) |
| getMean                | O(1)     |
| getMedian              | O(d)     |
| getMode                | O(d)     |

Space: `O(n + d)` including the queue and frequency map.

**Limitation:** Median and mode queries still require scanning distinct values.

This is better than brute force, but we can do better.

## **Approach 3: Optimal — Queue + Two Heaps + TreeSet**

This is the approach I would recommend in a senior-level interview.

We combine:

| Data structure           | Responsibility                |
| ------------------------ | ----------------------------- |
| `ArrayDeque`             | FIFO insertion/removal        |
| `long sum`               | Running sum                   |
| `PriorityQueue` max heap | Smaller half of numbers       |
| `PriorityQueue` min heap | Larger half of numbers        |
| `HashMap`                | Number frequencies            |
| `TreeSet`                | Efficient mode retrieval      |
| Two deletion maps        | Lazy deletion in median heaps |

### **3.1 Visualize the median heaps**

Suppose the current numbers are:

```
[8, 2, 5, 1, 9, 3]
```

Sorted:

```
[1, 2, 3, 5, 8, 9]
```

We maintain:

```
          lower                    upper

        Max Heap                 Min Heap

           3                        5
          / \                      / \
         1   2                    8   9
```

The median is:

```
upper.peek() // 5
```

Why?

Because the upper heap contains the larger half, and its minimum is the element at sorted index `n / 2`.

### **3.2 Heap balancing**

We maintain these invariants:

```
upperSize == lowerSize
OR
upperSize == lowerSize + 1
```

And:

```
lower.peek() <= upper.peek()
```

Here, `lowerSize` and `upperSize` represent logical sizes, excluding elements marked for deletion.

Whenever an insertion or removal happens, rebalance:

```java
while (upperSize > lowerSize + 1) {
    // Move upper's smallest element to lower.
}

while (upperSize < lowerSize) {
    // Move lower's largest element to upper.
}
```

### **3.3 Lazy deletion**

Consider:

```
lower = [1, 2, 3]
upper = [5, 8, 9]
```

We need to remove `1`.

The element `1` is not necessarily at the top of the max heap if another element is larger.

Instead of searching inside the heap, mark it:

```
delayedLower[1] = 1
```

Decrease the logical size of the lower heap.

Later, when `1` reaches the heap's top, physically remove it.

```java
private void pruneLower() {
    while (!lower.isEmpty()) {
        int number = lower.peek();

        if (!delayedLower.containsKey(number)) {
            break;
        }

        lower.poll();

        delayedLower.merge(number, -1, Integer::sum);

        if (delayedLower.get(number) == 0) {
            delayedLower.remove(number);
        }
    }
}
```

We use separate maps for the two heaps to avoid accidentally consuming a deletion marker belonging to the other heap when duplicates exist in both heaps.

### **3.4 Efficient mode retrieval**

Use this record:

```
record ModeEntry(int number, int frequency) {}
```

Define ordering:

```
Higher frequency first
Smaller number first when frequencies tie
```

For example:

```
(2, 3)
(3, 2)
(4, 2)
(5, 1)
```

The first entry gives the answer immediately.

Whenever a frequency changes, remove the old record and insert the updated record.

## **5. Optimal Java 24 implementation**

This is the complete implementation suitable for LeetCode.

```java

import java.util.*;

class StatisticsTracker {

    /*
     * ============================================================
     * 1. FIFO QUEUE
     * ============================================================
     *
     * Stores elements in insertion order.
     *
     * addNumber()              -> offerLast()
     * removeFirstAddedNumber() -> pollFirst()
     *
     * Both operations: O(1).
     */
    private final Deque<Integer> queue = new ArrayDeque<>();


    /*
     * ============================================================
     * 2. RUNNING SUM
     * ============================================================
     *
     * Maintaining the sum avoids traversing all elements
     * whenever getMean() is called.
     *
     * long is essential:
     *
     * Maximum possible value = 10^9
     * Maximum elements       = 10^5
     *
     * Maximum sum            = 10^14
     *
     * This exceeds Integer.MAX_VALUE.
     */
    private long sum = 0;
    private int count = 0;


    /*
     * ============================================================
     * 3. MEDIAN: TWO HEAPS
     * ============================================================
     *
     * lower = Max heap containing the smaller half.
     * upper = Min heap containing the larger half.
     *
     * We intentionally keep the extra element in upper.
     *
     * Invariants:
     *
     * 1. Every valid lower element <= every valid upper element.
     *
     * 2. upperSize == lowerSize
     *    OR
     *    upperSize == lowerSize + 1.
     *
     * Therefore:
     *
     * getMedian() = upper.peek()
     *
     * This also handles even-sized collections correctly:
     * we return the larger middle element.
     */

    private final PriorityQueue<Integer> lower =
        new PriorityQueue<>(Comparator.reverseOrder());

    private final PriorityQueue<Integer> upper =
        new PriorityQueue<>();


    /*
     * Logical sizes exclude elements marked for deletion.
     *
     * PriorityQueue.size() is not reliable for balancing
     * because stale elements can remain inside the heaps.
     */
    private int lowerSize = 0;
    private int upperSize = 0;


    /*
     * Separate lazy-deletion maps are necessary.
     *
     * A value can exist in BOTH heaps.
     *
     * Therefore, a deletion marker for one heap must never
     * accidentally remove a valid occurrence from the other.
     */
    private final Map<Integer, Integer> delayedLower =
        new HashMap<>();

    private final Map<Integer, Integer> delayedUpper =
        new HashMap<>();


    /*
     * ============================================================
     * 4. MODE: FREQUENCY MAP + ORDERED SET
     * ============================================================
     *
     * frequency:
     * number -> occurrence count
     *
     * modeOrder:
     * Entries ordered by:
     *
     * 1. Frequency descending.
     * 2. Number ascending.
     *
     * Consequently, modeOrder.first() is always the mode.
     */

    private final Map<Integer, Integer> frequency =
        new HashMap<>();


    /*
     * Java 24 supports records.
     *
     * A record gives us an immutable value object with
     * automatically generated equals() and hashCode().
     */
    private record ModeEntry(int number, int frequency) {}


    private final TreeSet<ModeEntry> modeOrder =
        new TreeSet<>(
            (a, b) -> {
                // Higher frequency must appear first.
                int byFrequency =
                    Integer.compare(b.frequency(), a.frequency());

                if (byFrequency != 0) {
                    return byFrequency;
                }

                // For equal frequencies, smaller number first.
                return Integer.compare(a.number(), b.number());
            }
        );


    /*
     * ============================================================
     * CONSTRUCTOR
     * ============================================================
     *
     * All structures are initially empty.
     *
     * Time: O(1).
     */
    public StatisticsTracker() {
    }


    /*
     * ============================================================
     * ADD NUMBER
     * ============================================================
     *
     * Responsibilities:
     *
     * 1. Add to FIFO queue.
     * 2. Update running sum and count.
     * 3. Insert into median heaps.
     * 4. Rebalance median heaps.
     * 5. Update frequency and mode ordering.
     *
     * Time: O(log n).
     */
    public void addNumber(int number) {

        // 1. Maintain insertion order.
        queue.offerLast(number);


        // 2. Maintain mean.
        sum += number;
        count++;


        // 3. Remove stale heap elements before inspecting tops.
        pruneLower();
        pruneUpper();


        /*
         * 4. Insert into the correct heap.
         *
         * If upper is empty, or number >= upper's minimum,
         * the number belongs in the upper half.
         *
         * Otherwise, it belongs in the lower half.
         */
        if (upper.isEmpty() || number >= upper.peek()) {

            upper.offer(number);
            upperSize++;

        } else {

            lower.offer(number);
            lowerSize++;
        }


        // 5. Restore heap-size invariants.
        rebalance();


        // 6. Update mode information.
        updateFrequency(number, 1);
    }


    /*
     * ============================================================
     * REMOVE FIRST ADDED NUMBER
     * ============================================================
     *
     * FIFO removal is guaranteed by the problem.
     *
     * We use lazy deletion for the median heaps.
     *
     * Time: O(log n) amortized.
     */
    public void removeFirstAddedNumber() {

        // 1. Get the oldest inserted number.
        int number = queue.pollFirst();


        // 2. Update mean.
        sum -= number;
        count--;


        // 3. Remove the number from the frequency structures.
        updateFrequency(number, -1);


        /*
         * 4. Clean stale elements before inspecting heap tops.
         */
        pruneLower();
        pruneUpper();


        /*
         * 5. Determine which logical heap contains the number.
         *
         * Every lower element <= every upper element.
         *
         * If number >= upper.peek(), we logically remove
         * one occurrence from upper.
         *
         * Otherwise, it belongs to lower.
         *
         * When equal values exist across both heaps, treating
         * the occurrence as belonging to upper is valid:
         * identical values are interchangeable in a multiset,
         * and upper contains a matching occurrence at its top.
         */

        if (number >= upper.peek()) {

            // Mark one occurrence in upper for lazy deletion.
            delayedUpper.merge(number, 1, Integer::sum);

            upperSize--;

        } else {

            // Mark one occurrence in lower for lazy deletion.
            delayedLower.merge(number, 1, Integer::sum);

            lowerSize--;
        }


        // 6. Physically remove stale heap tops if necessary.
        pruneLower();
        pruneUpper();


        // 7. Restore the median heap invariants.
        rebalance();
    }


    /*
     * ============================================================
     * MEAN
     * ============================================================
     *
     * Mean = sum / count.
     *
     * All numbers are positive, so Java integer division
     * produces the required floored mean.
     *
     * Time: O(1).
     * Extra space: O(1).
     */
    public int getMean() {
        return (int) (sum / count);
    }


    /*
     * ============================================================
     * MEDIAN
     * ============================================================
     *
     * upper contains the larger half.
     *
     * Its minimum is exactly the element at sorted index n / 2.
     *
     * Pruning is performed defensively before reading the top.
     *
     * Time: O(1) amortized.
     *
     * Note:
     * Each stale element is physically removed at most once.
     * Thus, the total cleanup work across operations is linear
     * in the number of heap insertions.
     */
    public int getMedian() {

        pruneUpper();

        return upper.peek();
    }


    /*
     * ============================================================
     * MODE
     * ============================================================
     *
     * modeOrder is sorted by:
     *
     * frequency descending,
     * number ascending.
     *
     * The first entry is therefore the correct mode.
     *
     * Time: O(1).
     */
    public int getMode() {
        return modeOrder.first().number();
    }


    /*
     * ============================================================
     * UPDATE FREQUENCY
     * ============================================================
     *
     * delta = +1 for insertion.
     * delta = -1 for removal.
     *
     * Important:
     * Remove the old TreeSet entry BEFORE modifying its frequency.
     *
     * TreeSet ordering depends on frequency.
     * Modifying a value without removing its old entry
     * would corrupt the ordering.
     *
     * Time: O(log d).
     */
    private void updateFrequency(int number, int delta) {

        int oldFrequency = frequency.getOrDefault(number, 0);


        // Remove the old frequency-number pair if it exists.
        if (oldFrequency > 0) {
            modeOrder.remove(
                new ModeEntry(number, oldFrequency)
            );
        }


        // Calculate updated frequency.
        int newFrequency = oldFrequency + delta;


        if (newFrequency == 0) {

            // Number no longer exists in the collection.
            frequency.remove(number);

        } else {

            // Save the updated frequency.
            frequency.put(number, newFrequency);

            // Insert its updated ordering information.
            modeOrder.add(
                new ModeEntry(number, newFrequency)
            );
        }
    }


    /*
     * ============================================================
     * PRUNE LOWER HEAP
     * ============================================================
     *
     * Remove elements that were logically deleted earlier.
     *
     * We only need to inspect the top.
     * Elements deeper inside the heap can remain until they
     * eventually reach the top.
     *
     * Each stale element is physically removed exactly once.
     */
    private void pruneLower() {

        while (!lower.isEmpty()) {

            int number = lower.peek();

            int pending = delayedLower.getOrDefault(number, 0);

            if (pending == 0) {
                break;
            }

            // Physically remove stale element.
            lower.poll();


            if (pending == 1) {
                delayedLower.remove(number);
            } else {
                delayedLower.put(number, pending - 1);
            }
        }
    }


    /*
     * ============================================================
     * PRUNE UPPER HEAP
     * ============================================================
     *
     * Same lazy-deletion process as lower.
     * Uses a separate deletion map.
     */
    private void pruneUpper() {

        while (!upper.isEmpty()) {

            int number = upper.peek();

            int pending = delayedUpper.getOrDefault(number, 0);

            if (pending == 0) {
                break;
            }

            upper.poll();


            if (pending == 1) {
                delayedUpper.remove(number);
            } else {
                delayedUpper.put(number, pending - 1);
            }
        }
    }


    /*
     * ============================================================
     * REBALANCE HEAPS
     * ============================================================
     *
     * Required invariant:
     *
     * upperSize == lowerSize
     * OR
     * upperSize == lowerSize + 1.
     *
     * We always maintain the extra element in upper.
     *
     * Each move takes O(log n).
     */
    private void rebalance() {

        pruneLower();
        pruneUpper();


        // Case 1: upper has too many elements.
        while (upperSize > lowerSize + 1) {

            int number = upper.poll();

            upperSize--;

            lower.offer(number);

            lowerSize++;


            pruneUpper();
        }


        // Case 2: lower has more elements.
        while (upperSize < lowerSize) {

            int number = lower.poll();

            lowerSize--;

            upper.offer(number);

            upperSize++;


            pruneLower();
        }


        // Remove any newly exposed stale elements.
        pruneLower();
        pruneUpper();
    }
}

```

### **5.1 Complexity analysis of the optimal solution**

Let:

- `n` = total active elements.
- `d` = number of distinct active elements.

| Operation              | Time complexity    | Reason                                       |
| ---------------------- | ------------------ | -------------------------------------------- |
| Constructor            | O(1)               | Initialize empty structures                  |
| addNumber              | O(log n)           | Heap insertion, balancing and TreeSet update |
| removeFirstAddedNumber | O(log n) amortized | Lazy deletion and balancing                  |
| getMean                | O(1)               | Running sum and count                        |
| getMedian              | O(1) amortized     | Read upper heap's top                        |
| getMode                | O(1)               | Read TreeSet's first element                 |

**Space complexity: O(n) amortized.**

We maintain:

- Queue: `O(n)`
- Median heaps: `O(n)` total inserted elements, including pending stale entries
- Frequency map: `O(d)`
- Mode TreeSet: `O(d)`
- Lazy deletion maps: `O(n)` worst case

One important nuance: lazy deletion means the physical heaps can contain stale elements. Their total size remains bounded by the number of insertions, not just the current active collection size.

## **7. Interviewer follow-up questions**

### **Q1. Why do we need two heaps instead of one heap?**

A single heap gives us access to either the smallest or largest element.

However, the median requires access to the middle element.

Two heaps divide the collection into two halves, allowing us to access the middle element through the top of the upper heap.

### **Q2. Why do we maintain logical heap sizes?**

Because lazy deletion doesn't immediately remove elements.

For example:

```
Physical heap size = 5
Stale elements     = 2
Logical heap size  = 3
```

If we use `PriorityQueue.size()` for balancing, our median can become incorrect.

Therefore, we maintain independent logical sizes.

### **Q3. Why do we need separate delayed deletion maps?**

Suppose:

```
lower = [2, 1]
upper = [2, 3]
```

The number `2` exists in both heaps.

If we maintain one shared deletion map, pruning one heap could consume the deletion marker intended for the other heap.

Separate maps prevent this problem.

### **Q4. Why use TreeSet instead of a PriorityQueue for mode?**

A priority queue supports efficient retrieval of the highest-priority element.

However, when a number's frequency changes, we need to invalidate its previous entry.

`TreeSet` allows us to remove the exact old `(number, frequency)` pair in `O(log d)` and insert the updated pair in `O(log d)`.

It also prevents duplicate entries for the same pair.

### **Q5. Can we implement mode using a frequency bucket?**

Yes.

We can maintain:

```
Map<Integer, Integer> frequency;
Map<Integer, TreeSet<Integer>> buckets;
```

Each bucket contains numbers having the same frequency.

However, finding the maximum nonempty frequency requires another structure or careful maintenance of the maximum frequency.

The `TreeSet<ModeEntry>` implementation is simpler to reason about.

### **Q6. Can we get O(1) median queries?**

Yes.

Our implementation already provides O(1) median retrieval using:

```
upper.peek();
```

The expensive work happens during insertions and removals.

### **Q7. What if we need to support removing any arbitrary number rather than only the oldest?**

The two-heap approach can still work if we maintain a mechanism to identify which logical heap contains the removed occurrence.

For this problem, FIFO removal makes the queue sufficient.

For arbitrary removals, we would need additional bookkeeping or an indexed ordered structure.

### **Q8. What if the interviewer changes the median definition to the average of the two middle elements?**

We would maintain the two heaps with equal sizes for even-sized collections.

Then:

```
double median = ((long) lower.peek() + upper.peek()) / 2.0;
```

For odd-sized collections, we return the top of the larger heap.

The current problem instead requires the larger middle element, so we intentionally keep the extra element in `upper`.

## **8. Final comparison: Which approach should you choose?**

| Approach            | Add      | Remove oldest      | Mean | Median         | Mode |
| ------------------- | -------- | ------------------ | ---- | -------------- | ---- |
| Brute force         | O(1)     | O(n)               | O(n) | O(n log n)     | O(n) |
| TreeMap             | O(log d) | O(log d)           | O(1) | O(d)           | O(d) |
| Two heaps + TreeSet | O(log n) | O(log n) amortized | O(1) | O(1) amortized | O(1) |

### **My recommendation for the interview**

I would explain and implement **Approach 3: Queue + Two Heaps + Frequency Map + TreeSet**.

The most important patterns to recognize are:

1. **Running aggregates:** Maintain sum and count instead of recalculating.
2. **Two heaps:** Maintain the median dynamically.
3. **Lazy deletion:** Handle arbitrary heap removals efficiently.
4. **Frequency indexing:** Maintain the mode without scanning all distinct numbers.
5. **Composite data structures:** Combine specialized structures to achieve efficient operations.

**The central interview takeaway:** Don't try to solve all statistics using one data structure. Maintain each statistic independently and synchronize them during insertion and removal.
