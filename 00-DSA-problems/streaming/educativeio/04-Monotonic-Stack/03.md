# **1438. Longest Continuous Subarray With Absolute Diff Less Than or Equal to Limit**

**Difficulty:** Medium\
**Pattern:** Sliding Window + Monotonic Deque\
**Related Problems:** Sliding Window Maximum (239), Minimum Window Substring, Shortest Subarray with Sum at Least K.

## **0. Simplifying the Problem Statement**

We are given:

- An integer array `nums`.
- An integer `limit`.

We need to find the **longest contiguous subarray** such that the absolute difference between every pair of elements is at most `limit`.

The important observation is:

For any subarray, the maximum absolute difference between any two elements is:

\\[ \text{maxElement} - \text{minElement} \\]

Therefore, instead of comparing every possible pair, we only need to check:

\\[ \boxed{\text{max(nums)}-\text{min(nums)} \leq limit} \\]

Our task becomes:

**Find the longest contiguous subarray whose maximum element minus minimum element is at most&#x20;**`limit`**.**

For example:

```
nums  = [10, 1, 2, 4, 7, 2]
limit = 5
```

The longest valid subarray is:

```
[2, 4, 7, 2]

max = 7
min = 2

max - min = 7 - 2 = 5
```

Answer = `4`.

## **1. Clarifying Questions to Ask the Interviewer**

| Question                                                | Why clarify?                                                                      |
| ------------------------------------------------------- | --------------------------------------------------------------------------------- |
| Is the subarray required to be contiguous?              | Distinguishes subarrays from subsequences. The statement says continuous, so yes. |
| Can the array contain duplicates?                       | Determines whether our data structures must support duplicate values.             |
| Can numbers be negative?                                | Helps determine whether arithmetic overflow is possible.                          |
| Can `limit` be zero?                                    | A zero limit means all elements in the window must be identical.                  |
| Do we need to return the length or the actual subarray? | The current requirement is only the length.                                       |
| What are the input constraints?                         | Determines whether an O(n²) or O(n log n) solution is feasible.                   |

**Important constraint:** `nums.length` can be up to \\(10^5\\), so we should aim for an O(n) or O(n log n) solution.

# **2. Core Idea and Intuition**

We will explore three approaches:

1. Brute Force – O(n³)
2. Sliding Window + TreeMap – O(n log n)
3. Sliding Window + Monotonic Deques – O(n)

The optimal solution uses two monotonic deques.

## **Approach 1: Brute Force**

### **Mental Model**

Generate every possible subarray.

For each subarray:

1. Find its minimum.
2. Find its maximum.
3. Check whether `max - min <= limit`.
4. Update the maximum valid length.

Example:

```
nums = [8, 2, 4, 7]
limit = 4
```

All possible subarrays:

```
[8]
[8, 2]
[8, 2, 4]
[8, 2, 4, 7]

[2]
[2, 4]
[2, 4, 7]

[4]
[4, 7]

[7]
```

The longest valid subarrays are:

```
[2, 4]
[4, 7]
```

Answer = 2.

### **Java 24 Implementation**

```java

class BruteForceSolution {

    public int longestSubarray(int[] nums, int limit) {

        int n = nums.length;
        int answer = 0;

        /*
         * WHY:
         * Generate every possible starting position.
         *
         * TIME: O(n)
         */
        for (int left = 0; left < n; left++) {

            /*
             * Track the minimum and maximum while
             * extending the subarray.
             */
            int min = nums[left];
            int max = nums[left];

            /*
             * Generate every possible ending position.
             *
             * TIME: O(n) per left position.
             */
            for (int right = left; right < n; right++) {

                min = Math.min(min, nums[right]);
                max = Math.max(max, nums[right]);

                /*
                 * A subarray is valid if its maximum
                 * and minimum differ by at most limit.
                 *
                 * We use long to make the subtraction
                 * safe even if integer constraints change.
                 */
                if ((long) max - min <= limit) {

                    answer = Math.max(
                        answer,
                        right - left + 1
                    );
                }
            }
        }

        return answer;
    }
}

```

**Complexity:**

- Time: O(n²), because there are O(n²) subarrays and we update min/max in O(1) per extension.
- Space: O(1), because we only maintain a few variables.

This is actually an optimized brute-force approach. A naive implementation that recalculates min/max for each subarray would take O(n³).

For \\(n = 10^5\\), O(n²) is too slow.

We need a better approach.

# **3. Approach 2: Sliding Window + TreeMap**

## **Core Intuition**

We already know that a window is valid when:

\\[ max-min \leq limit \\]

The question is:

**How can we efficiently maintain the minimum and maximum of a sliding window?**

A `TreeMap` is a sorted map implemented using a Red-Black Tree.

It maintains keys in sorted order.

We can store:

```
number -> frequency
```

For example:

```
Window = [2, 4, 7, 2]

TreeMap:

2 -> 2
4 -> 1
7 -> 1
```

Therefore:

```
map.firstKey(); // Minimum = 2
map.lastKey();  // Maximum = 7
```

Both operations take O(log n).

### **Sliding Window Strategy**

We maintain two pointers:

```
left
right
```

The `right` pointer expands the window.

The `left` pointer shrinks the window whenever the window becomes invalid.

### **Example Walkthrough**

```
nums  = [10, 1, 2, 4, 7, 2]
limit = 5
```

Initially:

```
left = 0
right = 0
```

| Right | Window    | Min | Max | Difference | Action |
| ----- | --------- | --- | --- | ---------- | ------ |
| 0     | [10]      | 10  | 10  | 0          | Valid  |
| 1     | [10,1]    | 1   | 10  | 9          | Shrink |
| 2     | [1,2]     | 1   | 2   | 1          | Valid  |
| 3     | [1,2,4]   | 1   | 4   | 3          | Valid  |
| 4     | [1,2,4,7] | 1   | 7   | 6          | Shrink |
| 5     | [2,4,7,2] | 2   | 7   | 5          | Valid  |

Maximum window size = 4.

### **Java 24 Implementation**

```java

import java.util.TreeMap;

class TreeMapSolution {

    public int longestSubarray(int[] nums, int limit) {

        /*
         * TreeMap stores:
         *
         * key   = number in the current window
         * value = frequency of that number
         *
         * WHY TreeMap?
         *
         * It maintains elements in sorted order.
         *
         * firstKey() -> Minimum element.
         * lastKey()  -> Maximum element.
         *
         * Both operations take O(log n) or better.
         */
        TreeMap<Integer, Integer> map = new TreeMap<>();

        int left = 0;
        int answer = 0;

        /*
         * Expand the sliding window using right.
         *
         * Each element enters the window exactly once.
         */
        for (int right = 0; right < nums.length; right++) {

            /*
             * Add the current element to the frequency map.
             *
             * merge() increments the frequency.
             */
            map.merge(nums[right], 1, Integer::sum);

            /*
             * Shrink the window until it becomes valid.
             *
             * Current window:
             * nums[left ... right]
             */
            while ((long) map.lastKey() - map.firstKey() > limit) {

                int outgoing = nums[left];

                /*
                 * Remove exactly one occurrence.
                 *
                 * If its frequency becomes zero,
                 * remove the key completely.
                 */
                map.compute(outgoing, (key, frequency) ->
                    frequency == 1 ? null : frequency - 1
                );

                left++;
            }

            /*
             * The current window is now valid.
             *
             * Window length = right - left + 1
             */
            answer = Math.max(
                answer,
                right - left + 1
            );
        }

        return answer;
    }
}

```

### **Complexity Analysis**

**Time Complexity: O(n log n)**

- We process every element once using the `right` pointer: O(n).
- Every element is removed at most once using the `left` pointer: O(n).
- Each TreeMap insertion, deletion and lookup takes O(log n).

Therefore:

\\[ O(n\log n) \\]

**Space Complexity: O(n)**

In the worst case, all elements in the window are distinct, so the TreeMap can contain up to n keys.

This solution is efficient and perfectly acceptable in an interview.

However, we can do better.

# **4. Optimal Approach: Sliding Window + Monotonic Deques**

**Target complexity: O(n) time and O(n) space.**

This is the most important approach to understand.

## **4.1 Why Two Deques?**

We need to efficiently retrieve:

1. Maximum element in the current window.
2. Minimum element in the current window.

A normal queue does not help because it does not maintain sorted order.

A priority queue can retrieve the minimum or maximum, but efficiently removing elements that leave the window requires additional bookkeeping.

Instead, we use two monotonic deques.

| Deque      | Purpose                     | Ordering   |
| ---------- | --------------------------- | ---------- |
| `maxDeque` | Maintains maximum candidate | Decreasing |
| `minDeque` | Maintains minimum candidate | Increasing |

**Important:** We store indices, not values.

Why?

Because we need to identify when an element moves outside the sliding window.

An index tells us exactly when an element becomes invalid.

## **4.2 Understanding the Maximum Deque**

The maximum deque maintains elements in decreasing order.

Example:

```
nums = [8, 2, 4, 7]
```

Process elements one by one.

**Step 1: Add 8**

```
maxDeque = [8]
```

**Step 2: Add 2**

2 is smaller than 8, so retain both.

```
maxDeque = [8, 2]
```

**Step 3: Add 4**

4 is greater than 2.

Remove 2 because 4 is newer and greater.

```
maxDeque = [8, 4]
```

**Step 4: Add 7**

7 is greater than 4.

Remove 4.

```
maxDeque = [8, 7]
```

The front always contains the maximum candidate.

```
maxDeque = [8, 7]
             ^
           Maximum
```

### **Why can we remove smaller elements from the back?**

Consider:

```
nums = [8, 2, 4]
```

When 4 arrives, why can we permanently remove 2?

Because:

- 4 is greater than 2.
- 4 is more recent than 2.
- Whenever both are inside a future window, 4 will always be the better maximum candidate.
- 2 will leave the window before 4 does.

Therefore, 2 can never become the maximum while 4 is still present.

This is the key insight behind the monotonic deque.

## **4.3 Understanding the Minimum Deque**

The minimum deque maintains elements in increasing order.

Using:

```
nums = [8, 2, 4, 7]
```

**Step 1: Add 8**

```
minDeque = [8]
```

**Step 2: Add 2**

2 is smaller than 8, so remove 8.

```
minDeque = [2]
```

**Step 3: Add 4**

4 is greater than 2.

```
minDeque = [2, 4]
```

**Step 4: Add 7**

7 is greater than 4.

```
minDeque = [2, 4, 7]
```

The front always contains the minimum candidate.

## **4.4 Complete Sliding Window Algorithm**

Now combine both deques.

For every element:

**Step 1: Expand the window**

Add the current index to both deques.

**Step 2: Maintain the maximum deque**

Remove elements from the back while their values are smaller than or equal to the current value.

**Step 3: Maintain the minimum deque**

Remove elements from the back while their values are greater than or equal to the current value.

**Step 4: Check the window**

Calculate:

\\[ max-min \\]

If:

\\[ max-min > limit \\]

The window is invalid.

**Step 5: Shrink the window**

Move `left` forward.

Remove indices from the front of either deque if they are outside the current window.

Repeat until the window becomes valid.

**Step 6: Update the answer**

\\[ answer = \max(answer,right-left+1) \\]

## **4.6 Optimal Java 24 Implementation**

This is the implementation I would recommend presenting in a coding interview.

```java

import java.util.ArrayDeque;
import java.util.Deque;

class Solution {

    public int longestSubarray(int[] nums, int limit) {

        /*
         * maxDeque:
         *
         * Stores indices in decreasing order of their values.
         * The front always represents the maximum element
         * in the current sliding window.
         *
         * minDeque:
         *
         * Stores indices in increasing order of their values.
         * The front always represents the minimum element
         * in the current sliding window.
         *
         * WHY STORE INDICES INSTEAD OF VALUES?
         *
         * We need to know whether an element has moved
         * outside the current sliding window.
         *
         * Its index allows us to check:
         *
         * index < left
         *
         * Deque operations at both ends take O(1).
         */
        Deque<Integer> maxDeque = new ArrayDeque<>();
        Deque<Integer> minDeque = new ArrayDeque<>();

        int left = 0;
        int answer = 0;

        /*
         * Expand the window one element at a time.
         *
         * right represents the newly included element.
         *
         * Every index enters each deque at most once.
         */
        for (int right = 0; right < nums.length; right++) {

            /*
             * -----------------------------------------
             * STEP 1: MAINTAIN MAXIMUM DEQUE
             * -----------------------------------------
             *
             * We want decreasing order of values.
             *
             * Remove all elements from the back whose
             * values are <= nums[right].
             *
             * WHY?
             *
             * The current element is greater than or equal
             * to those elements and is positioned later.
             *
             * Therefore, those older elements can never
             * become the maximum while the current element
             * remains inside the window.
             *
             * After removal, add the current index.
             */
            while (!maxDeque.isEmpty()
                    && nums[maxDeque.peekLast()] <= nums[right]) {

                maxDeque.pollLast();
            }

            maxDeque.offerLast(right);

            /*
             * -----------------------------------------
             * STEP 2: MAINTAIN MINIMUM DEQUE
             * -----------------------------------------
             *
             * We want increasing order of values.
             *
             * Remove all elements from the back whose
             * values are >= nums[right].
             *
             * WHY?
             *
             * The current element is smaller than or equal
             * to those elements and is positioned later.
             *
             * Therefore, those older elements can never
             * become the minimum while the current element
             * remains inside the window.
             */
            while (!minDeque.isEmpty()
                    && nums[minDeque.peekLast()] >= nums[right]) {

                minDeque.pollLast();
            }

            minDeque.offerLast(right);

            /*
             * -----------------------------------------
             * STEP 3: CHECK WINDOW VALIDITY
             * -----------------------------------------
             *
             * The front of maxDeque gives the maximum.
             * The front of minDeque gives the minimum.
             *
             * Valid window condition:
             *
             * maximum - minimum <= limit
             *
             * If the condition is violated, shrink
             * the window from the left.
             *
             * Use long for safe subtraction.
             */
            while ((long) nums[maxDeque.peekFirst()]
                    - nums[minDeque.peekFirst()] > limit) {

                /*
                 * -----------------------------------------
                 * STEP 4: REMOVE EXPIRED INDICES
                 * -----------------------------------------
                 *
                 * The current window is:
                 *
                 * nums[left ... right]
                 *
                 * We are about to move left forward.
                 *
                 * If left is at the front of maxDeque,
                 * it is no longer part of the window.
                 *
                 * Remove it.
                 */
                if (maxDeque.peekFirst() == left) {
                    maxDeque.pollFirst();
                }

                /*
                 * Apply the same logic to minimum deque.
                 */
                if (minDeque.peekFirst() == left) {
                    minDeque.pollFirst();
                }

                /*
                 * Shrink the window.
                 */
                left++;
            }

            /*
             * -----------------------------------------
             * STEP 5: UPDATE ANSWER
             * -----------------------------------------
             *
             * At this point, the current window is valid.
             *
             * Its length is:
             *
             * right - left + 1
             *
             * Keep the maximum length encountered.
             */
            answer = Math.max(
                answer,
                right - left + 1
            );
        }

        return answer;
    }
}

```

# **6. Edge Cases to Watch Out For**

| Input            | Limit | Expected | Reason                          |
| ---------------- | ----- | -------- | ------------------------------- |
| `[1]`            | 0     | 1        | Single element is always valid. |
| `[1,1,1,1]`      | 0     | 4        | All elements are identical.     |
| `[1,2,3,4]`      | 0     | 1        | No adjacent elements are equal. |
| `[1,5,6,7]`      | 1     | 3        | `[5,6,7]` is valid.             |
| `[8,2,4,7]`      | 4     | 2        | `[2,4]` or `[4,7]`.             |
| `[10,1,2,4,7,2]` | 5     | 4        | Standard example.               |

### **Important Implementation Pitfalls**

**1. Store indices, not values.**

We need indices to identify elements that have exited the window.

**2. Remove from the front only when the outgoing index matches.**

Do not blindly remove from both deques whenever `left` moves. An outgoing element might not be present in a deque because it was previously dominated.

**3. Use&#x20;**`while`**, not&#x20;**`if`**, when shrinking the window.**

A single left movement might not make the window valid.

**4. Handle duplicates correctly.**

Using `<=` and `>=` when removing from the back is safe. It discards older equal values because the newer equal value will remain in the window longer.

**5. Avoid integer overflow.**

Use:

```
(long) max - min
```

rather than relying on integer subtraction.

# **7. Comparing All Approaches**

| Approach                             | Time Complexity | Space Complexity | Verdict  |
| ------------------------------------ | --------------- | ---------------- | -------- |
| Brute force with incremental min/max | O(n²)           | O(1)             | Too slow |
| Sliding Window + TreeMap             | O(n log n)      | O(n)             | Good     |
| Sliding Window + Two Deques          | O(n)            | O(n)             | Optimal  |

### **Why Is the Deque Approach O(n)?**

This is an important interview question.

At first glance, we have nested `while` loops inside a `for` loop.

It might look like O(n²).

But it is actually O(n).

Why?

Consider `maxDeque`:

- Every index is inserted at most once.
- Every index is removed at most once.
- Removal can happen either from the front or the back.

The same reasoning applies to `minDeque`.

Therefore, across the entire algorithm:

- Maximum deque insertions: n.
- Maximum deque removals: n.
- Minimum deque insertions: n.
- Minimum deque removals: n.

Total operations are bounded by a constant multiple of n.

\\[ \boxed{O(n)} \\]

Space complexity:

Both deques can collectively store at most O(n) indices.

\\[ \boxed{O(n)} \\]

# **8. Interviewer Follow-Up Questions and Answers**

### **Q1. Why does checking maximum minus minimum guarantee that every pair satisfies the condition?**

For any two elements `a` and `b` in a window:

\\[ min \leq a,b \leq max \\]

Therefore:

\\[ |a-b| \leq max-min \\]

If `max - min <= limit`, every pair necessarily satisfies the condition.

### **Q2. Why do we use two deques instead of one?**

One deque maintains the maximum, while the other maintains the minimum.

Both are independently necessary to calculate:

\\[ max-min \\]

A single monotonic deque cannot simultaneously maintain both extrema in the required way.

### **Q3. Why not use a PriorityQueue?**

A `PriorityQueue` efficiently retrieves either the minimum or maximum, but removing arbitrary expired elements is not O(log n) through the standard API.

We would need lazy deletion and additional bookkeeping.

Two monotonic deques provide a simpler O(n) solution.

### **Q4. Why do we store indices instead of values?**

Suppose:

```
nums = [5, 5, 5]
```

If we only store values, we cannot determine which occurrence has left the window.

Indices distinguish individual occurrences and allow us to remove expired elements correctly.

### **Q5. Why do we remove smaller elements from the maximum deque?**

Suppose:

```
[8, 3, 6]
```

When 6 arrives, 3 is removed.

6 is greater and appears later. It will remain in every future window that still contains 3.

Therefore, 3 can never be the maximum of any future window containing 6.

### **Q6. Why do we shrink the window using&#x20;**`while`**&#x20;instead of&#x20;**`if`**?**

Because removing one element may not be sufficient.

For example:

```
nums = [10, 1, 2, 3]
limit = 1
```

The window may need multiple left-pointer movements before its maximum-minimum difference becomes valid.

### **Q7. Can we solve this using binary search on the answer?**

Yes, but it is not the most efficient approach.

We can binary-search the maximum window length and check whether a valid window of that length exists.

However, checking each candidate length requires maintaining window minimum and maximum, which can be done using deques.

The resulting complexity is:

\\[ O(n\log n) \\]

The direct sliding window solution is better at O(n).

### **Q8. Why is the sliding window technique valid here?**

The key property is that expanding a window cannot decrease its maximum or increase its minimum.

Once a window becomes invalid, extending it further to the right without removing elements cannot make it valid.

Therefore, moving `left` forward is the correct way to restore validity.

### **Q9. What happens when&#x20;**`limit = 0`**?**

The condition becomes:

\\[ max-min=0 \\]

Therefore, all elements inside the window must be identical.

The algorithm automatically finds the longest contiguous run of identical values.

### **Q10. Can we return the actual subarray instead of its length?**

Yes.

Whenever we find a longer valid window, store its boundaries:

```
bestLeft = left;
bestRight = right;
```

After processing the array, return:

```
Arrays.copyOfRange(nums, bestLeft, bestRight + 1);
```

The additional space for the returned subarray is O(answer).

# **9. Final Interview Takeaway**

Remember this mental model:

**Problem asks:** Longest subarray where the difference between every pair is at most `limit`.

**Transform the condition:**

\\[ \boxed{max-min \leq limit} \\]

**Use sliding window:**

- Expand using `right`.
- Shrink using `left` whenever invalid.

**Use two monotonic deques:**

- Decreasing deque → Maximum.
- Increasing deque → Minimum.

**Update answer:**

\\[ \boxed{answer=\max(answer,right-left+1)} \\]

**Final complexity:**

| Metric | Complexity |
| ------ | ---------- |
| Time   | **O(n)**   |
| Space  | **O(n)**   |

The difference is that here we maintain both the maximum and minimum of the sliding window rather than just the maximum.































Great question! The reason we use `if` instead of `while` is that **we remove elements from the front only when the front index is exactly equal to&#x20;**`left`**.**

Let's understand why.

## **1. What are we trying to remove?**

Our current sliding window is:

```
nums[left ... right]
```

When the window becomes invalid, we increment `left`.

The element at the old `left` index is leaving the window.

Therefore, we need to remove that index from the deques **if it exists at their front**.

```
if (maxDeque.peekFirst() == left) {
    maxDeque.pollFirst();
}

if (minDeque.peekFirst() == left) {
    minDeque.pollFirst();
}

left++;
```

## **2. Why is&#x20;**`if`**&#x20;sufficient?**

Remember how our monotonic deques work:

- Every index is inserted at the back.
- Elements can be removed from the back when they become dominated.
- Elements can be removed from the front when they leave the window.

Because indices are inserted in increasing order, the indices inside either deque are always maintained in increasing index order.

For example:

```
nums = [8, 2, 4, 7]

maxDeque = [0, 3]
             8  7

minDeque = [1, 2, 3]
             2  4  7
```

Suppose:

```
left = 1
```

We are removing index 1.

- `maxDeque.peekFirst()` is 0, so nothing to remove.
- `minDeque.peekFirst()` is 1, so remove it.

After removal:

```
maxDeque = [0, 3]
minDeque = [2, 3]
```

Notice that index 1 was not present in the maximum deque. It had already been removed from the back when a better maximum candidate arrived.

Therefore, we only need to check whether the outgoing index is at the front.

## **3. Why not use&#x20;**`while`**?**

Consider:

```
while (!maxDeque.isEmpty()
        && maxDeque.peekFirst() <= left) {

    maxDeque.pollFirst();
}
```

This is also safe in this particular algorithm.

However, it is unnecessary.

Why?

Because:

1. Indices are inserted in increasing order.
2. `left` increases one position at a time.
3. Every index smaller than `left` should already have been removed when it left the window.
4. Therefore, the only possible expired index at the front is exactly `left`.

So this:

```
if (maxDeque.peekFirst() == left)
```

is sufficient.

## **4. Important distinction**

| Condition             | Meaning                                                                  |
| --------------------- | ------------------------------------------------------------------------ |
| `peekFirst() == left` | Remove the element that is currently leaving the window.                 |
| `peekFirst() < left`  | Remove any previously expired elements.                                  |
| `peekFirst() <= left` | Remove the current outgoing element and any previously expired elements. |

The `<= left` version is more defensive, but it doesn't change the algorithm's complexity.

## **5. Interview takeaway**

I would recommend using the original implementation:

```
if (maxDeque.peekFirst() == left) {
    maxDeque.pollFirst();
}

if (minDeque.peekFirst() == left) {
    minDeque.pollFirst();
}

left++;
```

**Remember this principle:**

We use `if` because `left` advances exactly one position at a time, and each outgoing index needs to be checked only once.

We use `while` for the monotonic deque's back-removal operations because a newly inserted element might dominate multiple existing elements.

That's the key difference!
