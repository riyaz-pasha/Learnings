
# **239. Sliding Window Maximum**

**Difficulty:** Hard\
**Primary pattern:** Monotonic Decreasing Deque\
**Related patterns:** Sliding Window, Two Pointers, Monotonic Queue

## **0. Simplify the problem statement**

We are given:

- An integer array `nums`.
- A sliding window of size `k`.
- The window moves one position to the right at a time.

For every window, we need to return its maximum element.

**Example:**

```
nums = [1, 3, -1, -3, 5, 3, 6, 7]
k = 3
```

The windows are:

```
[1,  3, -1]  -3,  5,  3,  6,  7  -> 3
 1, [3, -1, -3]  5,  3,  6,  7  -> 3
 1,  3, [-1, -3, 5]  3,  6,  7  -> 5
 1,  3, -1, [-3, 5, 3]  6,  7  -> 5
 1,  3, -1, -3, [5, 3, 6]  7  -> 6
 1,  3, -1, -3,  5, [3, 6, 7] -> 7
```

Output:

```
[3, 3, 5, 5, 6, 7]
```

The challenge is to calculate every maximum efficiently.

A brute-force solution takes `O(n * k)`. We want an optimal `O(n)` solution.

## **1. Clarifying questions to ask the interviewer**

| Question                                              | Why clarify?                                           |
| ----------------------------------------------------- | ------------------------------------------------------ |
| Is `k` always between 1 and `nums.length`?            | Determines whether invalid window sizes need handling. |
| Can numbers be negative?                              | We must not initialize the maximum to zero.            |
| Are duplicate values possible?                        | Determines how we handle equal values in the deque.    |
| Do we need to return maximum values or their indices? | The implementation may differ.                         |
| Is an O(n) solution expected?                         | Helps establish the desired optimization.              |

For this problem, the constraints guarantee `1 <= k <= n`, and negative and duplicate values are possible.

## **2. Core intuition: Monotonic Decreasing Deque**

This is one of the most important monotonic deque problems.

### **First, understand the problem with a simple observation.**

Consider:

```
nums = [1, 3, -1, -3, 5]
k = 3
```

For the first window:

```
[1, 3, -1]
```

Maximum = `3`.

When the window moves:

```
[3, -1, -3]
```

Maximum is still `3`.

Notice something interesting:

**We don't need to remember every element in the window.**

Why?

Suppose we have:

```
[3, -1, -3]
```

The value `3` is greater than both `-1` and `-3`.

As long as `3` remains inside the window, neither `-1` nor `-3` can ever become the maximum.

Therefore, we can discard elements that are smaller than a newer element.

This is the key optimization.

### **The monotonic decreasing property**

We maintain a deque containing indices of array elements.

The corresponding values must always be in decreasing order.

For example:

```
Deque indices:  [1, 2, 3]

Array values:   [3, -1, -3]
                 ↓   ↓   ↓

Deque values:   3 > -1 > -3
```

The front of the deque always contains the index of the maximum element.

### **Three operations**

**Operation 1: Remove expired indices from the front.**

When the window moves right, some indices fall outside the window.

The current window starts at:

```
int windowStart = i - k + 1;
```

An index is expired if:

```
deque.peekFirst() < windowStart
```

Remove it.

**Operation 2: Remove smaller elements from the back.**

Before inserting the current index, remove all indices whose corresponding values are smaller than or equal to the current value.

```
while (!deque.isEmpty()
        && nums[deque.peekLast()] <= nums[i]) {

    deque.pollLast();
}
```

Why?

Suppose:

```
Existing deque values: [3, 1, -1]
Current value:          5
```

After inserting `5`, none of the previous values can ever become the maximum while `5` remains in the window.

Therefore:

```
Before: [3, 1, -1]
After:  [5]
```

**Operation 3: Insert the current index.**

```
deque.offerLast(i);
```

Now the deque maintains decreasing order.

The maximum is always:

```
nums[deque.peekFirst()]
```

### **Visual representation**

```
                 Sliding Window
                       |
                       v
              Remove expired indices
                       |
                       v
              Remove smaller elements
                 from deque's back
                       |
                       v
                Insert current index
                       |
                       v
              Deque front = Maximum
                       |
                       v
                Store the result
```

### **Example walkthrough**

Input:

```
nums = [1, 3, -1, -3, 5, 3, 6, 7]
k = 3
```

We maintain indices rather than values.

| i | nums[i] | Deque values after processing | Maximum |
| - | ------- | ----------------------------- | ------- |
| 0 | 1       | [1]                           | -       |
| 1 | 3       | [3]                           | -       |
| 2 | -1      | [3, -1]                       | 3       |
| 3 | -3      | [3, -1, -3]                   | 3       |
| 4 | 5       | [5]                           | 5       |
| 5 | 3       | [5, 3]                        | 5       |
| 6 | 6       | [6]                           | 6       |
| 7 | 7       | [7]                           | 7       |

Final answer:

```
[3, 3, 5, 5, 6, 7]
```

# **3. All possible solutions**

## **Approach 1: Brute Force**

**Idea:** For every window, iterate through all `k` elements and find the maximum.

```java
import java.util.Arrays;

class Solution {

    public int[] maxSlidingWindow(int[] nums, int k) {

        int n = nums.length;

        // Number of possible windows = n - k + 1.
        int[] result = new int[n - k + 1];

        // Visit every possible starting position.
        for (int start = 0; start <= n - k; start++) {

            // Integer.MIN_VALUE is important because
            // the array may contain only negative numbers.
            int max = Integer.MIN_VALUE;

            // Scan all elements belonging to this window.
            for (int j = start; j < start + k; j++) {

                max = Math.max(max, nums[j]);
            }

            result[start] = max;
        }

        return result;
    }
}

/*
TIME COMPLEXITY: O(n * k)

Why?
- There are n - k + 1 windows.
- For every window, we inspect k elements.
- Total operations = (n - k + 1) * k.
- Therefore, O(n * k).

SPACE COMPLEXITY: O(n - k + 1)

Why?
- We allocate an output array containing n - k + 1 elements.
- Auxiliary space excluding output = O(1).

Limitation:
- When n = 100,000 and k is large, repeatedly scanning
  overlapping windows becomes expensive.
*/
```

This solution is straightforward but inefficient.

## **Approach 2: Max Heap / Priority Queue**

**Idea:** Maintain a max heap containing elements of the current window.

Java's `PriorityQueue` is a min heap by default, so we use a reverse comparator.

We store both value and index.

Why store the index?

Because we need to identify whether an element has expired from the current window.

```java
import java.util.Comparator;
import java.util.PriorityQueue;

class Solution {

    // Stores the value and its original array index.
    private record Entry(int value, int index) {}

    public int[] maxSlidingWindow(int[] nums, int k) {

        int n = nums.length;

        int[] result = new int[n - k + 1];

        // Max heap: highest value appears at the top.
        PriorityQueue<Entry> maxHeap =
                new PriorityQueue<>(
                        Comparator.comparingInt(Entry::value)
                                .reversed()
                );

        for (int i = 0; i < n; i++) {

            // Insert the current element.
            maxHeap.offer(new Entry(nums[i], i));

            // Current window starts at i - k + 1.
            int windowStart = i - k + 1;

            // Remove expired elements from the heap.
            // Lazy deletion: expired elements are removed
            // only when they reach the heap's top.
            while (!maxHeap.isEmpty()
                    && maxHeap.peek().index() < windowStart) {

                maxHeap.poll();
            }

            // A complete window is available.
            if (i >= k - 1) {

                result[windowStart] = maxHeap.peek().value();
            }
        }

        return result;
    }
}

/*
TIME COMPLEXITY: O(n log n)

Why?
- We insert n elements into the priority queue.
- Each insertion costs O(log n).
- Each element can be removed at most once.
- Each removal costs O(log n).
- Total = O(n log n).

SPACE COMPLEXITY: O(n)

Why?
- In the worst case, expired elements may remain buried
  inside the heap.
- Therefore, the heap can contain up to n elements.
- Output array requires O(n - k + 1).

Advantages:
- Easier to understand if you already know heaps.
- Efficient compared with brute force.

Disadvantage:
- It does not achieve the optimal O(n) time complexity.
- A heap does not efficiently remove arbitrary expired
  elements without additional bookkeeping.
*/
```

**Important interviewer insight:** Lazy deletion is valid because an expired element cannot affect the answer unless it reaches the top. When it does, we remove it.

## **Approach 3: Monotonic Deque (Optimal)**

This is the expected optimal solution.

We use `ArrayDeque<Integer>` to store indices.

Why indices instead of values?

Because indices allow us to:

1. Identify expired elements.
2. Access the corresponding array values.
3. Maintain the window boundaries precisely.

```java
import java.util.ArrayDeque;
import java.util.Deque;

class Solution {

    public int[] maxSlidingWindow(int[] nums, int k) {

        int n = nums.length;

        // There are exactly n - k + 1 sliding windows.
        int[] result = new int[n - k + 1];

        // Stores array indices, NOT array values.
        //
        // Invariant:
        // nums[deque[0]] > nums[deque[1]] > ...
        //
        // Therefore, the front always represents the maximum.
        Deque<Integer> deque = new ArrayDeque<>();

        // Tracks the next position in the result array.
        int resultIndex = 0;

        // Process each element exactly once.
        for (int i = 0; i < n; i++) {

            /*
             * STEP 1: Remove expired indices.
             *
             * Current window:
             * [i - k + 1, i]
             *
             * Any index smaller than i - k + 1
             * is outside the current window.
             *
             * Since indices are inserted in increasing order,
             * expired indices can only be at the front.
             */
            int windowStart = i - k + 1;

            while (!deque.isEmpty()
                    && deque.peekFirst() < windowStart) {

                deque.pollFirst();
            }

            /*
             * STEP 2: Maintain decreasing order.
             *
             * Remove elements from the back while their
             * values are <= the current element.
             *
             * Why <= instead of < ?
             *
             * If two values are equal, the newer index is
             * preferable because it remains in the window
             * longer.
             *
             * Example:
             * Existing: [5 at index 0]
             * Current:  [5 at index 2]
             *
             * Index 0 expires earlier, so retain index 2.
             */
            while (!deque.isEmpty()
                    && nums[deque.peekLast()] <= nums[i]) {

                deque.pollLast();
            }

            /*
             * STEP 3: Insert current index.
             *
             * The deque now maintains decreasing values.
             */
            deque.offerLast(i);

            /*
             * STEP 4: Calculate maximum.
             *
             * A complete window exists when i >= k - 1.
             *
             * The front contains the index of the maximum.
             */
            if (i >= k - 1) {

                result[resultIndex++] = nums[deque.peekFirst()];
            }
        }

        return result;
    }
}

/*
TIME COMPLEXITY: O(n) -- OPTIMAL

Why?

The outer loop:
- Runs exactly n times.

Deque operations:
- Every index is inserted exactly once.
- Every index is removed at most once.
- An index can be removed either:
    1. From the front because it expired.
    2. From the back because a larger or equal value arrived.

Although we have while loops inside the for loop,
the total number of deque removals across the entire
algorithm cannot exceed n.

Therefore:
- Total insertions = n.
- Total removals <= n.
- Total deque operations = O(n).

Hence, overall time complexity = O(n).

SPACE COMPLEXITY: O(k) AUXILIARY SPACE

Why?
- The deque contains indices belonging to the current
  window or useful candidates from that window.
- It can contain at most k indices.
- Therefore, deque space = O(k).

Output space:
- The result array contains n - k + 1 elements.
- Output space = O(n - k + 1).

Total space including output = O(n).
Auxiliary space excluding output = O(k).

This is the optimal solution.
*/
```

## **4. Why does the monotonic deque work?**

This is the most important part to understand deeply.

Consider:

```
nums = [2, 1, 3]
k = 3
```

When we encounter `3`:

```
Existing candidates: [2, 1]
Current element:      3
```

Can `2` ever become the maximum in a future window while `3` is also present?

No.

Can `1` ever become the maximum in a future window while `3` is also present?

No.

Also, `3` appears later, so it will expire later than both elements.

Therefore, removing `2` and `1` is always safe.

This gives us the central property:

**An element can be discarded if a newer element is greater than or equal to it.**

The deque stores only elements that could potentially become the maximum in some future window.

These are called *candidates for maximum*.

### **Why do we need both ends of the deque?**

| End   | Responsibility                                    |
| ----- | ------------------------------------------------- |
| Front | Remove expired elements and retrieve maximum      |
| Back  | Remove dominated elements and insert new elements |

This is precisely why a monotonic deque is useful.

## **5. Edge cases to watch out for**

| Input                | k | Output      | What it tests                   |
| -------------------- | - | ----------- | ------------------------------- |
| `[1]`                | 1 | `[1]`       | Single element                  |
| `[1, 2, 3]`          | 1 | `[1, 2, 3]` | Window size 1                   |
| `[1, 2, 3]`          | 3 | `[3]`       | Window size equals array length |
| `[5, 5, 5, 5]`       | 2 | `[5, 5, 5]` | Duplicate elements              |
| `[9, 8, 7, 6]`       | 2 | `[9, 8, 7]` | Strictly decreasing             |
| `[1, 2, 3, 4]`       | 2 | `[2, 3, 4]` | Strictly increasing             |
| `[-5, -2, -8]`       | 2 | `[-2, -2]`  | Negative values                 |
| `[10, -10, 10, -10]` | 3 | `[10, 10]`  | Alternating values              |

**Common mistakes:**

1. Storing values instead of indices, making expiration difficult.
2. Forgetting to remove expired indices.
3. Removing smaller elements from the front instead of the back.
4. Using `i > k - 1` instead of `i >= k - 1`.
5. Initializing the maximum to `0`, which fails for negative arrays.
6. Using a normal queue instead of a deque.
7. Thinking that nested `while` loops make the algorithm O(n²). The aggregate number of removals is O(n).

## **6. Comparison of all approaches**

| Approach        | Time Complexity | Auxiliary Space | Optimal? |
| --------------- | --------------- | --------------- | -------- |
| Brute Force     | O(n × k)        | O(1)            | No       |
| Max Heap        | O(n log n)      | O(n)            | No       |
| Monotonic Deque | O(n)            | O(k)            | Yes      |

My recommendation in an interview:

1. Start with brute force to establish correctness.
2. Explain why overlapping windows cause redundant work.
3. Introduce a max heap as an intermediate optimization.
4. Recognize that we only need potential maximum candidates.
5. Derive the monotonic decreasing deque.

This demonstrates problem-solving ability rather than simply memorizing the deque template.

## **7. Interviewer follow-up questions**

### **Q1. Why do we store indices instead of values?**

Because we need to determine whether an element has expired from the sliding window.

For example:

```
nums = [5, 5, 5, 5]
k = 2
```

If we store only values, we cannot distinguish which occurrence has expired.

Indices solve this problem.

### **Q2. Why do we remove elements using&#x20;**`<=`**&#x20;instead of&#x20;**`<`**?**

Consider:

```
nums = [5, 5]
k = 2
```

When the second `5` arrives, the first `5` can be discarded.

The second occurrence:

- Has the same value.
- Appears later.
- Expires later.

Therefore, it dominates the first occurrence.

Using `<=` keeps the deque smaller.

Note: Using `<` is also correct, but equal elements will remain in the deque.

### **Q3. Why is the time complexity O(n), despite nested while loops?**

Amortized analysis.

Every index:

- Enters the deque exactly once.
- Leaves the deque at most once.

Therefore, across the entire algorithm, the total number of deque operations is O(n).

### **Q4. What if we need the sliding window minimum instead?**

Reverse the monotonic property.

For maximum:

```java
while (!deque.isEmpty()
        && nums[deque.peekLast()] <= nums[i]) {

    deque.pollLast();
}
```

For minimum:

```java
while (!deque.isEmpty()
        && nums[deque.peekLast()] >= nums[i]) {

    deque.pollLast();
}
```

The deque becomes monotonically increasing.

### **Q5. Can we solve this using a segment tree?**

Yes.

A segment tree supports:

- Point updates in O(log n).
- Range maximum queries in O(log n).

For this problem, each window is a range maximum query.

Total time:

```
O(n log n)
```

However, a segment tree is unnecessary when the array is static and the window moves sequentially. The monotonic deque is simpler and faster.

### **Q6. Can we solve it using a block-based approach?**

Yes. The left/right block decomposition technique also achieves O(n).

Divide the array into blocks of size `k`.

Calculate:

- `left[i]`: Maximum from the beginning of the current block through index `i`.
- `right[i]`: Maximum from index `i` through the end of the current block.

Then:

```java
maxWindow = Math.max(right[start], left[end]);
```

This is another O(n) solution, with O(n) auxiliary space.

### **Q7. What happens when k = 1?**

Every window contains exactly one element.

Therefore, the output is the original array.

The monotonic deque algorithm handles this automatically.

### **Q8. What happens when k = nums.length?**

There is only one window.

The answer is simply the maximum element in the entire array.

Again, the same algorithm handles it automatically.

## **8. What you should remember for interviews**

The most important pattern is:

```java
Deque<Integer> deque = new ArrayDeque<>();

for (int i = 0; i < nums.length; i++) {

    // 1. Remove expired indices from front.
    while (!deque.isEmpty()
            && deque.peekFirst() < i - k + 1) {

        deque.pollFirst();
    }

    // 2. Remove dominated elements from back.
    while (!deque.isEmpty()
            && nums[deque.peekLast()] <= nums[i]) {

        deque.pollLast();
    }

    // 3. Insert current index.
    deque.offerLast(i);

    // 4. Front represents maximum.
    if (i >= k - 1) {
        result[i - k + 1] = nums[deque.peekFirst()];
    }
}
```

**Remember this mental model:**

- Front = Maximum.
- Back = New element insertion.
- Remove from front = Expired.
- Remove from back = Dominated.
- Store indices = Know when elements expire.
- Each element enters and leaves at most once = O(n).

**Senior interviewer takeaway:** Sliding Window Maximum is a fundamental monotonic deque problem. Once you understand why a newer, larger element dominates older, smaller elements, the O(n) solution becomes natural rather than something you need to memorize.
