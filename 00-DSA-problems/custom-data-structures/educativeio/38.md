# LeetCode 353 — Design Snake Game

Problem: [Design Snake Game](https://leetcode.com/problems/design-snake-game/description/?utm_source=chatgpt.com)

Difficulty: Medium

The key interview insight is that a Snake Game is a simulation problem where we must efficiently track the snake's body, its movement, and collisions.

The most important data structures are:

- `Deque` — to add the new head and remove the tail efficiently.
- `HashSet` — to check whether a cell is occupied by the snake in \\(O(1)\\) average time.
- An index into the food array — to track the next food item.

## 0. Understand the problem in simple terms

Imagine a board with `width` columns and `height` rows. A snake starts at the top-left cell `(0, 0)`.

You receive a sequence of moves: `"U"`, `"D"`, `"L"`, and `"R"`.

Each time `move(direction)` is called:

1. The snake's head moves one cell in the given direction.
2. If the new head reaches the next food item, the snake grows by one cell and earns one point.
3. If the head goes outside the board, the game ends with `-1`.
4. If the head collides with the snake's body, the game ends with `-1`.
5. Otherwise, return the current score, which equals the number of food items eaten.

Food appears in the given order, and each food position is represented as `[row, column]`.

### Example

Suppose the board is `3 × 2` (width 3, height 2), and the food positions are `[[1, 2], [0, 1]]`.

The snake starts at `(0, 0)`.

## 1. Clarifying questions to ask the interviewer

These questions demonstrate that you understand the game rules and the state transitions.

| Question                                                         | Why clarify it?                                                                                                                            |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Does the snake always start at `(0,0)` with length one?          | Establishes the initial state.                                                                                                             |
| Does food appear in the specified order?                         | Lets us use a simple index instead of searching all food items.                                                                            |
| Can the snake move into the cell currently occupied by its tail? | This determines the correct self-collision logic.                                                                                          |
| Does eating food prevent the tail from moving?                   | Determines how the snake grows.                                                                                                            |
| Should every move after game over return `-1`?                   | The core requirement only defines the return value when a move ends the game; persistent game-over behavior is a useful API clarification. |
| Can food be placed on a cell occupied by the snake?              | The constraints guarantee that food will not appear on an occupied cell, simplifying initialization and updates.                           |

The most important question is the third one. Moving into the old tail cell is legal when the snake is not eating, because that tail cell becomes empty during the same move.

## 2. Core intuition: How should we think about this problem?

### Step 1: What changes during one move?

Suppose the snake occupies three cells:

```
Head -> A -> B -> C <- Tail
```

When the snake moves right, its new head is `N`.

If the snake does not eat food:

```
Before:  A -> B -> C
After:   N -> A -> B
```

The old tail `C` disappears, and the new head `N` is added. The snake's length stays the same.

If the snake eats food:

```
Before:  A -> B -> C
After:   N -> A -> B -> C
```

The tail remains in place, so the snake grows by one cell.

This tells us exactly what data structures we need.

### Step 2: Match the operations to data structures

| Operation                   | Data structure | Why?                                      |
| --------------------------- | -------------- | ----------------------------------------- |
| Add a new head              | `Deque`        | `addFirst()` takes \\(O(1)\\) time.       |
| Remove the tail             | `Deque`        | `removeLast()` takes \\(O(1)\\) time.     |
| Check if a cell is occupied | `HashSet`      | Average \\(O(1)\\) lookup.                |
| Find the next food          | Integer index  | Food appears in a predetermined sequence. |

The deque preserves the order of the snake's body, while the set answers whether a cell is occupied. We need both because a set does not preserve body order and a deque alone requires a linear search for collisions.

The collision check must account for the old tail. We'll implement that precisely in the optimal solution below.

## 3. Edge cases to watch out for

1. Moving into a wall: Return `-1` without updating the snake.
2. Moving into its own body: Return `-1`.
3. Moving into the old tail: Allow it only if the snake is not eating food.
4. Eating food: Increase the score and retain the tail.
5. No more food: Continue moving normally; the score stays unchanged.
6. A one-cell snake: Its tail and head occupy the same cell. The next head must still be checked correctly.
7. Repeated calls after game over: If the interviewer expects a persistent game-over state, subsequent calls should return `-1`.
8. Rows versus columns: Validate row against `height` and column against `width`.

## 4. Solution 1 — Brute force using a list

The simplest approach is to store the snake's body in an `ArrayList<Cell>`.

We can store the head at index `0` and the tail at the final index. Each move scans the body to detect collisions.

This approach is easy to understand but not efficient: checking collisions takes \\(O(L)\\) time, where \\(L\\) is the current snake length. Inserting at the front of an `ArrayList` also shifts existing elements.

```java
import java.util.ArrayList;
import java.util.List;

class SnakeGame {
    record Cell(int row, int col) {}

    private final int width;
    private final int height;
    private final int[][] food;

    // Index 0 is the head; the last index is the tail.
    private final List<Cell> snake = new ArrayList<>();

    private int foodIndex;
    private int score;
    private boolean gameOver;

    public SnakeGame(int width, int height, int[][] food) {
        this.width = width;
        this.height = height;
        this.food = food;

        // Initially the snake has exactly one segment at (0, 0).
        snake.add(new Cell(0, 0));
    }

    public int move(String direction) {
        // Optional API behavior: once dead, the snake stays dead.
        if (gameOver) {
            return -1;
        }

        Cell head = snake.get(0);

        // Convert the direction into a one-cell coordinate change.
        int dr = 0, dc = 0;
        switch (direction) {
            case "U" -> dr = -1;
            case "D" -> dr = 1;
            case "L" -> dc = -1;
            case "R" -> dc = 1;
            default -> throw new IllegalArgumentException("Invalid direction");
        }

        Cell next = new Cell(head.row() + dr, head.col() + dc);

        // Wall collision must be detected before changing the body.
        if (next.row() < 0 || next.row() >= height
                || next.col() < 0 || next.col() >= width) {
            gameOver = true;
            return -1;
        }

        // Determine whether the next cell contains the currently active food.
        boolean eating = foodIndex < food.length
                && food[foodIndex][0] == next.row()
                && food[foodIndex][1] == next.col();

        Cell tail = snake.get(snake.size() - 1);

        // If not eating, the old tail vacates its cell in this move.
        // Therefore, entering that particular cell is legal.
        for (int i = 0; i < snake.size(); i++) {
            Cell bodyCell = snake.get(i);

            if (bodyCell.equals(next)) {
                boolean isOldTail = bodyCell.equals(tail);

                if (!isOldTail || eating) {
                    gameOver = true;
                    return -1;
                }
            }
        }

        // Remove the tail only on a normal move.
        if (!eating) {
            snake.remove(snake.size() - 1);
        }

        // ArrayList insertion at index 0 shifts the existing elements.
        snake.add(0, next);

        if (eating) {
            foodIndex++;
            score++;
        }

        return score;
    }
}

/*
COMPLEXITY

Let L be the current snake length.

Time per move: O(L) average/worst-case for the body scan,
               plus O(L) for insertion at index 0.
               Overall: O(L).

Space: O(L) for the snake, excluding the supplied food array.
       Food storage is O(F), where F is the number of food items.

WHY THIS IS NOT OPTIMAL:
The algorithm repeatedly scans and shifts the body. Both operations
can be avoided with a deque and a hash set.
*/
```

## 5. Solution 2 — Optimal using `Deque` and `HashSet`

This is the recommended interview solution.

The key improvement is that we do not need to inspect every body segment to determine whether the new head is occupied. We maintain a set of occupied cells alongside the deque.

### The subtle collision rule

Suppose the snake is currently:

```
Head -> A -> B -> T <- Tail
```

The next head position is `T`.

- If the snake is not eating, `T` is about to become empty. The move is valid.
- If the snake is eating, the tail stays at `T`. The move is a collision.

We can handle this without modifying the snake prematurely:

1. Calculate the next head and check the walls.
2. Determine whether the move eats food.
3. Check whether the next head is occupied.
4. If it is occupied, allow it only when it is the current tail and the snake is not eating.
5. If not eating, remove the tail from both data structures.
6. Add the new head to both data structures.
7. Update the score and food index if food was eaten.

Notice that we check the old tail before removing it. This also means a failed move does not leave the internal state partially modified.

```java
import java.util.ArrayDeque;
import java.util.Deque;
import java.util.HashSet;
import java.util.Set;

class SnakeGame {
    // A record gives us immutable coordinates with value-based equals/hashCode.
    // Two Cell(1, 2) instances are equal, making them suitable HashSet keys.
    private record Cell(int row, int col) {}

    private final int width;
    private final int height;
    private final int[][] food;

    // Maintains body order: HEAD at the front, TAIL at the back.
    private final Deque<Cell> snake = new ArrayDeque<>();

    // Mirrors the cells in snake, allowing average O(1) collision checks.
    private final Set<Cell> occupied = new HashSet<>();

    // food[foodIndex] is the next food the snake must eat.
    private int foodIndex = 0;
    private int score = 0;
    private boolean gameOver = false;

    public SnakeGame(int width, int height, int[][] food) {
        this.width = width;
        this.height = height;
        this.food = food;

        Cell start = new Cell(0, 0);
        snake.addFirst(start);
        occupied.add(start);
    }

    public int move(String direction) {
        // After a fatal move, preserve the terminal state.
        if (gameOver) {
            return -1;
        }

        Cell head = snake.peekFirst();

        // A switch expression maps each command to its coordinate delta.
        // Rows increase downward; columns increase toward the right.
        int[] delta = switch (direction) {
            case "U" -> new int[]{-1, 0};
            case "D" -> new int[]{1, 0};
            case "L" -> new int[]{0, -1};
            case "R" -> new int[]{0, 1};
            default -> throw new IllegalArgumentException("Invalid direction");
        };

        Cell next = new Cell(
                head.row() + delta[0],
                head.col() + delta[1]
        );

        // 1. Check the walls before mutating either data structure.
        if (next.row() < 0 || next.row() >= height
                || next.col() < 0 || next.col() >= width) {
            gameOver = true;
            return -1;
        }

        // 2. Only the next uneaten food item matters.
        // The food index advances exactly once for each food eaten.
        boolean eating = foodIndex < food.length
                && food[foodIndex][0] == next.row()
                && food[foodIndex][1] == next.col();

        // 3. Find the current tail. It might be the next head position.
        Cell tail = snake.peekLast();

        // 4. A cell occupied by the body is normally a collision.
        // EXCEPTION: if we are NOT eating and next == tail, the tail
        // vacates that cell during this move, so entering it is legal.
        boolean hitsBody = occupied.contains(next)
                && (eating || !next.equals(tail));

        if (hitsBody) {
            gameOver = true;
            return -1;
        }

        // 5. On a normal move, the tail leaves before the new head is added.
        // Update BOTH structures, keeping them perfectly synchronized.
        // When eating, do not remove the tail: that is how growth occurs.
        if (!eating) {
            Cell removedTail = snake.removeLast();
            occupied.remove(removedTail);
        }

        // 6. Insert the new head at the front of the deque and into the set.
        snake.addFirst(next);
        occupied.add(next);

        // 7. Eating food increases length by one because the tail stayed put.
        // The next food becomes active only after this one is eaten.
        if (eating) {
            score++;
            foodIndex++;
        }

        return score;
    }
}

/*
WHY THIS SOLUTION IS CORRECT

Invariant 1: snake contains every body cell in head-to-tail order.

Invariant 2: occupied contains exactly the same cells as snake.

Invariant 3: score equals foodIndex, because every successfully eaten food
             item increases both by exactly one.

Initialization establishes all three invariants: the body and set both
contain only (0, 0), and both counters start at zero.

For a normal move, removing the tail and adding the new head preserves
the snake's length. For a food move, retaining the tail and adding the
new head increases the length by one. The score and food index then
advance together.

The collision test handles the only special case: the old tail is
considered available only if the snake is not eating. Consequently,
the algorithm rejects every wall collision and every genuine body
collision while permitting valid tail-vacating moves.

TIME COMPLEXITY

Let L be the current snake length and F the number of food items.

Constructor:
  O(1) auxiliary initialization, excluding the supplied food array.
  O(F) if counting the input food storage as part of the total
  space associated with the object.

Each move:
  O(1) average time.
  - Read the head and tail: O(1).
  - Calculate the next position: O(1).
  - Check the next food: O(1).
  - Check occupied.contains(next): O(1) average.
  - Remove the tail if needed: O(1) average for the set removal
    and O(1) for deque removal.
  - Add the new head: O(1) average for the set insertion
    and O(1) for deque insertion.

Thus, for M move calls, total expected time is O(M).

Worst-case hash-table operations can degrade under pathological hashing,
so O(1) is the expected/average bound, not a strict worst-case guarantee.

SPACE COMPLEXITY

  O(L + F) total storage including food.
  O(L) auxiliary space for the deque and occupied set.

The board is never allocated as a height-by-width matrix.
That is important because the dimensions can be large while the
snake occupies only a small number of cells.
*/
```

### Why the optimal approach is better

| Operation                            | Brute force | Optimal            |
| ------------------------------------ | ----------- | ------------------ |
| Determine whether a cell is occupied | \\(O(L)\\)  | \\(O(1)\\) average |
| Add a head                           | \\(O(L)\\)  | \\(O(1)\\)         |
| Remove a tail                        | \\(O(1)\\)  | \\(O(1)\\)         |
| Process one move overall             | \\(O(L)\\)  | \\(O(1)\\) average |
| Extra space for snake                | \\(O(L)\\)  | \\(O(L)\\)         |

Here \\(L\\) is the current snake length.

## 6. Interviewer follow-up questions and answers

Q1. Why use both a deque and a hash set?

The deque preserves the snake's order, which is necessary to identify the head and tail. The set provides fast membership checks for self-collision. Using only the deque would make collision checks linear in the snake length.

Q2. Why not allocate a `height × width` matrix?

A matrix can represent occupancy, but it requires \\(O(HW)\\) space. The snake and food can be tracked without allocating every board cell. The deque-plus-set solution uses \\(O(L+F)\\) space instead.

Q3. Can we use a `LinkedList` instead of `ArrayDeque`?

Yes. Java's `LinkedList` supports insertion and removal at both ends in constant time. `ArrayDeque` is generally preferable because it avoids per-node allocations and usually has better memory locality.

Q4. Why does the collision check depend on whether food is eaten?

Eating prevents the tail from moving. Therefore, the old tail remains occupied, and moving the head into it is illegal. On a normal move, the tail vacates its cell, making that cell a legal destination.

Q5. Can the score be calculated as `snake.size() - 1`?

Yes, provided the implementation always maintains the snake's length correctly. The initial length is one, and each food item increases the length by one. Keeping an explicit score is still straightforward and directly matches the required API.

Q6. What if the interviewer asks for strict worst-case constant-time collision checks?

A standard Java `HashSet` offers expected constant-time membership checks, not a universal strict worst-case guarantee. Given the problem constraints, the hash set is the natural choice. A deterministic alternative would need a different occupancy representation and a careful analysis of its update and lookup costs.

Q7. How would you test the tricky tail case?

Construct a snake that has grown and is about to move into its own tail cell without eating. That move should succeed. Then test the same destination when food is there; the move should fail because the tail must remain in place.

Q8. What design pattern does this problem use?

Primarily stateful object design and simulation. Each `move()` call updates persistent state. The design also illustrates choosing data structures based on the operations that must be efficient.

## Final interview takeaway

When you see a simulation where an ordered sequence grows at one end and shrinks at the other, think of a deque. When you also need fast membership checks, pair it with a hash set.

The most important reasoning in this problem is not the direction arithmetic. It is understanding the timing of the tail movement and making sure the deque and set always represent the same snake.
