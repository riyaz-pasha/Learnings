# 641. Design Circular Deque — Complete Java 24 Explanation

The key to solving this problem is to understand how a circular array can support insertion and deletion at both ends without shifting elements.

We'll build the intuition first, then derive the index calculations instead of memorizing them, and finally implement the solutions from a straightforward approach to the optimal circular-array approach.

## 0. Understand the problem in simple terms

A deque (double-ended queue) is a data structure that lets us add and remove elements from both ends.

- `insertFront(value)` — add an element at the beginning.
- `insertLast(value)` — add an element at the end.
- `deleteFront()` — remove the first element.
- `deleteLast()` — remove the last element.
- `getFront()` — read the first element.
- `getRear()` — read the last element.

Unlike an ordinary queue, which primarily adds at the rear and removes at the front, a deque supports both directions.

For this problem, the deque has a fixed capacity `k`. It must never hold more than `k` elements.

For example, with capacity `3`:

Deque containing three elements

10

20

30

Front → 10

30 ← Rear

The deque is full. Another insertion must return false.

One important observation: we do not need to move elements when inserting or deleting. We only need to update our indices and the number of elements.

## 1. Clarifying questions to ask the interviewer

Before implementing a data structure, clarify its contract.

1. Is the capacity fixed after construction? Yes, `k` is fixed. This means we can allocate one array and reuse it throughout the object's lifetime.
2. What should happen when inserting into a full deque? Return `false` and leave the deque unchanged.
3. What should happen when deleting from an empty deque? Return `false` and leave the deque unchanged.
4. What should `getFront()` and `getRear()` return when empty? Return `-1`, as specified.
5. Can stored values be negative? The constraints specify values from `0` to `1000`. Thus, `-1` is a safe empty-result sentinel.
6. Are all operations required to be efficient? The intended design supports all operations in \\(O(1)\\) time. Shifting elements after every insertion or deletion would make some operations \\(O(k)\\).

## 2. Core intuition: think in terms of positions, not movement

Imagine a circular array of capacity `5`:

```
Index:    0    1    2    3    4
       +----+----+----+----+----+
Array: |    |    |    |    |    |
       +----+----+----+----+----+
```

We will maintain three pieces of information:

- `elements`: the fixed-size array.
- `front`: the index of the first element.
- `size`: how many elements are currently stored.

Why use `front` and `size` instead of keeping a separate `rear` index?

Because the rear can always be calculated from the other two:

\\[ \text{rear}=(\text{front}+\text{size}-1)\bmod k \\]

This formula is a consequence of how array positions work, not something you need to memorize.

### 2.1 Derive the rear index

Suppose:

```
Capacity = 5
front = 1
size = 3
```

The three elements occupy these positions:

```
Index:    0    1    2    3    4
       +----+----+----+----+----+
Array: |    | 10 | 20 | 30 |    |
       +----+----+----+----+----+
                F         R
```

The front element is at index `1`.

There are three elements, so their positions are:

- First: index `1`
- Second: index `2`
- Third: index `3`

To get the last element's index, we start at `front` and advance by `size - 1` positions:

\\[ \text{rear}=\text{front}+(\text{size}-1) \\]

\\[ =1+(3-1)=3 \\]

Since the array is circular, we wrap around using modulo:

\\[ \boxed{\text{rear}=(\text{front}+\text{size}-1)\bmod k} \\]

Why subtract `1`? Because the front element already occupies the starting position. Three elements span only two steps from the first to the last.

### 2.2 What happens when the elements wrap around?

Suppose the array has capacity `5`, `front = 3`, and `size = 4`.

```
Index:    0    1    2    3    4
       +----+----+----+----+----+
Array: | 20 | 30 |    | 50 | 10 |
       +----+----+----+----+----+
             ↑         ↑    ↑
             2         3    4
```

The logical order is:

```
Front → 50 → 10 → 20 → 30 → Rear
```

The rear calculation is:

\\[ (3+4-1)\bmod 5=6\bmod 5=1 \\]

So the rear is at index `1`, even though the front is at index `3`.

That is the essential property of a circular array: physical array order and logical deque order do not have to match.

## 3. Derive every operation step by step

We will use this invariant throughout the implementation:

> `front` points to the first element, and `size` tells us how many consecutive logical positions belong to the deque, wrapping around the array when necessary.

For a capacity of `k`:

```
rearIndex = (front + size - 1) % k
```

The empty state has `size == 0`. In that state, `front` does not identify a valid element, so we must check emptiness before reading or deleting.

### 3.1 Insert at the rear

Suppose:

```
Capacity = 5
front = 1
size = 3

Index:    0    1    2    3    4
       +----+----+----+----+----+
Array: |    | 10 | 20 | 30 |    |
       +----+----+----+----+----+
```

The rear element is at index `3`. The next available logical position is index `4`.

We can calculate that directly:

\\[ \boxed{\text{insertIndex}=(\text{front}+\text{size})\bmod k} \\]

Here:

\\[ (1+3)\bmod 5=4 \\]

Insert `40` at index `4`, then increment `size`.

```
Index:    0    1    2    3    4
       +----+----+----+----+----+
Array: |    | 10 | 20 | 30 | 40 |
       +----+----+----+----+----+
```

Why is this different from the rear formula?

- To find the existing rear, use `front + size - 1`.
- To find the next insertion position, use `front + size`.

The first formula identifies the last occupied position. The second identifies the position immediately after all occupied positions.

Now consider wrapping:

```
Capacity = 5
front = 3
size = 2

Logical order: 10, 20
Physical positions: 3, 4
```

The next rear insertion index is:

\\[ (3+2)\bmod 5=0 \\]

Index `0` is the next position in the circular sequence.

### 3.2 Insert at the front

This operation is the reverse of inserting at the rear.

If the front is currently at index `2`, the new element needs index `1`.

```
Before:
Index:    0    1    2    3    4
       +----+----+----+----+----+
Array: |    |    | 20 | 30 |    |
       +----+----+----+----+----+
                  F
```

Move the `front` pointer one position backward, then write the new element there.

\\[ \boxed{\text{newFront}=(\text{front}-1+k)\bmod k} \\]

Why add `k` before applying modulo?

If `front = 0`, moving backward should take us to index `k - 1`. But `-1 % k` is negative in Java, so simply writing `(front - 1) % k` is unsafe.

Adding the capacity gives:

\\[ (0-1+5)\bmod 5=4 \\]

The pointer wraps correctly to the last array index.

For example, inserting `10` at the front of `[20, 30]` produces:

```
Logical deque: 10 → 20 → 30
```

No existing elements move.

### 3.3 Delete from the front

Deleting the front means discarding the element currently at `front` and advancing the pointer by one.

\\[ \boxed{\text{front}=(\text{front}+1)\bmod k} \\]

Example:

```
Before:
front = 3
Logical order: 10 → 20 → 30

After deleteFront():
front = 4
Logical order: 20 → 30
```

We also decrement `size`.

We do not need to clear the old array slot. It is no longer part of the logical deque because `front` and `size` define which positions are occupied. The next insertion can overwrite that slot.

### 3.4 Delete from the rear

We already derived the existing rear index:

\\[ \text{rear}=(\text{front}+\text{size}-1)\bmod k \\]

To delete the rear, we can simply decrement `size`. The `front` pointer remains unchanged.

For example:

```
Before:
front = 1
size = 3
Logical order: 10 → 20 → 30

rear = (1 + 3 - 1) % 5 = 3

After deleteLast():
front = 1
size = 2
Logical order: 10 → 20
```

Notice that the array itself doesn't change. The logical rear changes because `size` has decreased.

### 3.5 Get front, get rear, empty, and full

These operations now become straightforward.

| Operation    | Logic                                                          |
| ------------ | -------------------------------------------------------------- |
| `getFront()` | Return `elements[front]`, unless empty                         |
| `getRear()`  | Return `elements[(front + size - 1) % capacity]`, unless empty |
| `isEmpty()`  | `size == 0`                                                    |
| `isFull()`   | `size == capacity`                                             |

The same `size` variable tells us both whether the deque is empty and whether it is full.

The implementation has two central ideas:

1. The array stores the values; pointers describe the logical order.
2. Modulo arithmetic wraps an index back into the valid range.

## 5. Solution 1 — Simple array with shifting

The most straightforward approach is to maintain an array where the deque's elements always appear contiguously in logical order, starting at index `0`.

For example:

```
[10, 20, 30, _, _]
```

- Inserting at the rear writes at index `size`.
- Deleting from the rear decrements `size`.
- Inserting at the front shifts every existing element one position to the right.
- Deleting from the front shifts every remaining element one position to the left.

This is a useful starting point because it is easy to reason about. However, shifting is expensive.

```
class MyCircularDeque {

    private final int[] elements;
    private int size;

    public MyCircularDeque(int capacity) {
        elements = new int[capacity];
        size = 0;
    }

    public boolean insertFront(int value) {
        // A full deque cannot accept another element.
        if (isFull()) {
            return false;
        }

        // Shift all existing elements one position to the right,
        // starting from the last occupied index to avoid overwriting
        // values that we have not moved yet.
        for (int i = size; i > 0; i--) {
            elements[i] = elements[i - 1];
        }

        elements[0] = value;
        size++;
        return true;
    }

    public boolean insertLast(int value) {
        if (isFull()) {
            return false;
        }

        // Because the elements always start at index 0,
        // the next free position is exactly index size.
        elements[size] = value;
        size++;
        return true;
    }

    public boolean deleteFront() {
        if (isEmpty()) {
            return false;
        }

        // Removing index 0 requires shifting every other element
        // one position to the left to preserve the contiguous layout.
        for (int i = 0; i < size - 1; i++) {
            elements[i] = elements[i + 1];
        }

        size--;
        return true;
    }

    public boolean deleteLast() {
        if (isEmpty()) {
            return false;
        }

        // No shifting is needed when removing the last element.
        size--;
        return true;
    }

    public int getFront() {
        return isEmpty() ? -1 : elements[0];
    }

    public int getRear() {
        return isEmpty() ? -1 : elements[size - 1];
    }

    public boolean isEmpty() {
        return size == 0;
    }

    public boolean isFull() {
        return size == elements.length;
    }
}

/*
 * Complexity:
 *
 * Let k be the deque's capacity.
 *
 * Constructor:       O(k) time to initialize the array; O(k) space.
 * insertFront:       O(k) worst-case time because elements are shifted.
 * insertLast:        O(1) time.
 * deleteFront:       O(k) worst-case time because elements are shifted.
 * deleteLast:        O(1) time.
 * getFront/getRear:  O(1) time.
 * isEmpty/isFull:    O(1) time.
 *
 * The problem calls for a circular deque. This implementation is a
 * baseline, not the desired final solution: it wastes time maintaining
 * a contiguous layout that we do not actually need.
 */
```

The insight from this approach: the costly part is not inserting or deleting a value. It is maintaining the physical arrangement of the array. We can eliminate that cost by allowing the logical deque to wrap around the array.

## 6. Solution 2 — Doubly linked list

Another natural approach is a doubly linked list.

Each node stores:

- A value.
- A reference to the previous node.
- A reference to the next node.

The list maintains `head` and `tail`, allowing insertion and deletion at either end in constant time. We also maintain `size` so we can enforce the capacity.

```
class MyCircularDeque {

    private static final class Node {
        int value;
        Node previous;
        Node next;

        Node(int value) {
            this.value = value;
        }
    }

    private final int capacity;
    private int size;
    private Node head;
    private Node tail;

    public MyCircularDeque(int capacity) {
        this.capacity = capacity;
    }

    public boolean insertFront(int value) {
        if (isFull()) {
            return false;
        }

        Node node = new Node(value);

        if (isEmpty()) {
            // The first node is both the head and the tail.
            head = tail = node;
        } else {
            // Link the new node before the current head.
            node.next = head;
            head.previous = node;
            head = node;
        }

        size++;
        return true;
    }

    public boolean insertLast(int value) {
        if (isFull()) {
            return false;
        }

        Node node = new Node(value);

        if (isEmpty()) {
            head = tail = node;
        } else {
            // Link the new node after the current tail.
            node.previous = tail;
            tail.next = node;
            tail = node;
        }

        size++;
        return true;
    }

    public boolean deleteFront() {
        if (isEmpty()) {
            return false;
        }

        if (size == 1) {
            // Removing the only node makes the list empty.
            head = tail = null;
        } else {
            head = head.next;
            head.previous = null;
        }

        size--;
        return true;
    }

    public boolean deleteLast() {
        if (isEmpty()) {
            return false;
        }

        if (size == 1) {
            head = tail = null;
        } else {
            tail = tail.previous;
            tail.next = null;
        }

        size--;
        return true;
    }

    public int getFront() {
        return isEmpty() ? -1 : head.value;
    }

    public int getRear() {
        return isEmpty() ? -1 : tail.value;
    }

    public boolean isEmpty() {
        return size == 0;
    }

    public boolean isFull() {
        return size == capacity;
    }
}

/*
 * Complexity:
 *
 * Constructor:       O(1) time and O(1) auxiliary space.
 * Every operation:   O(1) time.
 * Storage:           O(k) worst-case space for up to k nodes.
 *
 * Why is this efficient?
 * We have direct references to both ends, so we never traverse the list.
 *
 * Why might it not be the preferred implementation here?
 * Each value needs a separate node with two references. Allocating nodes
 * adds memory and object-management overhead. The problem's fixed capacity
 * makes a preallocated circular array a natural alternative.
 *
 * The list is not circular in this implementation; the name of the
 * problem describes the deque's required behavior, not its implementation.
 */
```

This solution is fully valid for the API and offers \\(O(1)\\) operations. However, we can use the fixed capacity to store all elements in one array and avoid node allocations.

## 7. Solution 3 — Optimal circular array

This is the implementation I would recommend in an interview.

We will use exactly three fields:

```
private final int[] elements;
private int front;
private int size;
```

We do not need a `rear` field because it is derived whenever needed:

```
int rearIndex = (front + size - 1) % elements.length;
```

Here is the complete implementation with the reasoning included in the comments.

```
class MyCircularDeque {

    // Stores all deque values in a fixed-size circular array.
    private final int[] elements;

    // Index of the first logical element.
    // When the deque is empty, this index does not identify a valid value.
    private int front;

    // Number of elements currently stored, from 0 through capacity.
    private int size;

    public MyCircularDeque(int capacity) {
        elements = new int[capacity];
        front = 0;
        size = 0;
    }

    public boolean insertFront(int value) {
        // Never overwrite an existing element when the deque is full.
        if (isFull()) {
            return false;
        }

        /*
         * The new value must occupy the position immediately BEFORE front.
         *
         * Example with capacity = 5:
         *   front = 2  -> new front should be 1
         *   front = 0  -> new front should be 4 (wrap around)
         *
         * We add capacity before modulo because Java's % operator can
         * return a negative remainder for negative operands.
         *
         * This moves the pointer, not the existing elements.
         */
        front = (front - 1 + elements.length) % elements.length;

        // Write the new first element at the updated front position.
        elements[front] = value;

        // One additional logical position is now occupied.
        size++;
        return true;
    }

    public boolean insertLast(int value) {
        if (isFull()) {
            return false;
        }

        /*
         * Occupied positions begin at front and span size elements.
         *
         * Therefore, the next free logical position is front + size.
         * Modulo wraps that position back to index 0 when necessary.
         *
         * Example:
         *   capacity = 5, front = 3, size = 2
         *   occupied positions = 3, 4
         *   next position = (3 + 2) % 5 = 0
         */
        int insertionIndex =
                (front + size) % elements.length;

        elements[insertionIndex] = value;
        size++;
        return true;
    }

    public boolean deleteFront() {
        if (isEmpty()) {
            return false;
        }

        /*
         * The current front element is logically removed.
         *
         * Instead of clearing the array slot or shifting elements,
         * advance front to the next occupied position.
         *
         * Modulo handles the wrap-around from the last index to index 0.
         */
        front = (front + 1) % elements.length;

        // One fewer position belongs to the deque.
        size--;
        return true;
    }

    public boolean deleteLast() {
        if (isEmpty()) {
            return false;
        }

        /*
         * The rear index is (front + size - 1) % capacity.
         *
         * We do not need to calculate it or move any pointer explicitly.
         * Decreasing size excludes the old rear from the logical deque.
         *
         * front remains unchanged because the first element was not removed.
         */
        size--;
        return true;
    }

    public int getFront() {
        // front identifies the first element whenever size > 0.
        return isEmpty() ? -1 : elements[front];
    }

    public int getRear() {
        if (isEmpty()) {
            return -1;
        }

        /*
         * Derive the last occupied position:
         *
         * front + size - 1
         *   - front: index of the first element
         *   - size - 1: number of steps from the first to the last
         *   - modulo: wrap around the circular array if needed
         */
        int rearIndex =
                (front + size - 1) % elements.length;

        return elements[rearIndex];
    }

    public boolean isEmpty() {
        // No logical elements are stored.
        return size == 0;
    }

    public boolean isFull() {
        // Every array position belongs to the deque.
        return size == elements.length;
    }
}

/*
 * COMPLEXITY ANALYSIS
 *
 * Let k = elements.length, the fixed capacity.
 *
 * Constructor:
 *   Time:  O(k), because Java initializes the int array to zero.
 *   Space: O(k), for the preallocated array.
 *
 * Every public operation after construction:
 *   Time: O(1), because it performs a constant number of calculations,
 *         reads, writes, and/or comparisons.
 *
 * Auxiliary space per operation:
 *   O(1), because no additional structure grows with the input.
 *
 * Total storage:
 *   O(k), for the array and a constant number of integer fields.
 *
 * IMPORTANT:
 *   We intentionally do not clear deleted array positions. The logical
 *   contents are determined by front and size, not by whether an array
 *   cell contains an old value.
 *
 *   We must update size consistently after every successful insertion
 *   and deletion. Failed operations leave all state unchanged.
 */
```

## 8. Dry run using the problem's example

Input:

```
MyCircularDeque(3)
insertLast(1)
insertLast(2)
insertFront(3)
insertFront(4)
getRear()
isFull()
deleteLast()
insertFront(4)
getFront()
```

Let's track the array, `front`, and `size` after each operation.

| Operation        | Logical deque | `front` | `size` | Result  |
| ---------------- | ------------- | ------- | ------ | ------- |
| Constructor      | `[]`          | 0       | 0      | —       |
| `insertLast(1)`  | `[1]`         | 0       | 1      | `true`  |
| `insertLast(2)`  | `[1, 2]`      | 0       | 2      | `true`  |
| `insertFront(3)` | `[3, 1, 2]`   | 2       | 3      | `true`  |
| `insertFront(4)` | `[3, 1, 2]`   | 2       | 3      | `false` |
| `getRear()`      | `[3, 1, 2]`   | 2       | 3      | `2`     |
| `isFull()`       | `[3, 1, 2]`   | 2       | 3      | `true`  |
| `deleteLast()`   | `[3, 1]`      | 2       | 2      | `true`  |
| `insertFront(4)` | `[4, 3, 1]`   | 1       | 3      | `true`  |
| `getFront()`     | `[4, 3, 1]`   | 1       | 3      | `4`     |

Let's inspect the interesting transitions.

### After `insertLast(1)` and `insertLast(2)`

```
Capacity = 3

Index:    0    1    2
       +----+----+----+
Array: |  1 |  2 |    |
       +----+----+----+
         F    R
```

Here `front = 0` and `size = 2`.

### After `insertFront(3)`

Calculate the new front:

\\[ (0-1+3)\bmod 3=2 \\]

Write `3` at index `2`:

```
Index:    0    1    2
       +----+----+----+
Array: |  1 |  2 |  3 |
       +----+----+----+
         1    2    3
```

The logical deque is now:

```
Front → 3 → 1 → 2 → Rear
```

Although the array reads `[1, 2, 3]` from left to right, the deque begins at index `2` and wraps around. This is why we must distinguish physical order from logical order.

### After `deleteLast()`

The deque contains three elements, so the rear is:

\\[ (2+3-1)\bmod 3=1 \\]

That position contains `2`. Deleting the rear means decrementing `size` from `3` to `2`.

The logical positions are now index `2`, followed by index `0`:

```
Logical deque: 3 → 1
```

The old value at index `1` may still physically be present in the array. That is fine because it is no longer included in the logical deque.

### After `insertFront(4)`

Calculate:

\\[ (2-1+3)\bmod 3=1 \\]

Write `4` at index `1`, and increase `size` back to `3`.

```
Index:    0    1    2
       +----+----+----+
Array: |  1 |  4 |  3 |
       +----+----+----+

Logical deque: 4 → 3 → 1
```

The front is now index `1`, and the rear is:

\\[ (1+3-1)\bmod 3=0 \\]

Therefore, `getFront()` returns `4` and `getRear()` would return `1`.

The output matches the example:

```
[null, true, true, true, false, 2, true, true, true, 4]
```

## 9. Edge cases to consider

These are particularly useful to test in an interview.

| Case                                                 | Expected behavior               | Reason                                   |
| ---------------------------------------------------- | ------------------------------- | ---------------------------------------- |
| Insert into an empty deque                           | `true`                          | A slot is available                      |
| Delete from an empty deque                           | `false`                         | No element exists                        |
| Read either end when empty                           | `-1`                            | Required sentinel                        |
| Insert when full                                     | `false`                         | Capacity must not be exceeded            |
| Delete the only element                              | Deque becomes empty             | `size` becomes zero                      |
| Insert at the front when `front == 0`                | Wrap to `capacity - 1`          | Circular backward movement               |
| Insert at the rear when the next index is `capacity` | Wrap to index `0`               | Circular forward movement                |
| Refill after deletions                               | `true` when a slot is available | Deleted logical positions are reusable   |
| Capacity equals `1`                                  | All operations still work       | The sole slot is both the front and rear |

For capacity `1`, the following is worth checking explicitly:

```
MyCircularDeque deque = new MyCircularDeque(1);

assert deque.isEmpty();
assert deque.insertFront(7);
assert deque.isFull();
assert deque.getFront() == 7;
assert deque.getRear() == 7;
assert !deque.insertLast(8);
assert deque.deleteLast();
assert deque.isEmpty();
assert deque.getFront() == -1;
```

This test demonstrates why the design must handle the one-element state correctly: the front and rear refer to the same physical slot.

## 10. Which solution should you choose?

| Approach            | Front insertion | Rear insertion | Front deletion | Rear deletion | Storage          |
| ------------------- | --------------- | -------------- | -------------- | ------------- | ---------------- |
| Array with shifting | \\(O(k)\\)      | \\(O(1)\\)     | \\(O(k)\\)     | \\(O(1)\\)    | \\(O(k)\\)       |
| Doubly linked list  | \\(O(1)\\)      | \\(O(1)\\)     | \\(O(1)\\)     | \\(O(1)\\)    | \\(O(k)\\) nodes |
| Circular array      | \\(O(1)\\)      | \\(O(1)\\)     | \\(O(1)\\)     | \\(O(1)\\)    | \\(O(k)\\)       |

The circular array is the intended choice for this problem because capacity is known in advance and we can support every operation in constant time without allocating a node for each insertion.

## 11. Interviewer follow-up questions

Q1. Why not maintain both `front` and `rear` pointers?

You can, but it introduces another piece of state that must be updated correctly in every operation. Maintaining `front` and `size` is enough to derive the rear whenever needed. A separate rear index can also work if its invariants are carefully defined.

Q2. Why is the rear formula `front + size - 1`, but the insertion formula `front + size`?

`size - 1` is the number of steps from the first occupied position to the last occupied position. `size` is the number of steps from the first occupied position to the next free position.

For example, if `front = 2` and `size = 3`, the occupied positions are `2`, `3`, and `4`. The rear is `2 + 3 - 1 = 4`, while the next position is `2 + 3 = 5`, which wraps around when the capacity is `5`.

Q3. Why use `size` instead of checking whether `front == rear` to determine emptiness?

A single front/rear comparison can be ambiguous: both indices might be equal when there is one element or when the deque is empty, depending on the chosen representation. Tracking `size` explicitly makes empty and full states unambiguous.

Q4. Why don't we clear the array slot after deleting an element?

Because the logical contents are determined by `front` and `size`. A deleted slot becomes available for future insertion. Clearing it would be unnecessary work for an integer array.

Q5. What changes if we use a circular array with one unused slot?

Another common implementation reserves one slot to distinguish full from empty. In that design, a capacity of `k` elements generally requires an array of length `k + 1`, and the front and rear positions determine the state. Our implementation avoids that extra slot by tracking `size`.

Q6. Could this deque be made thread-safe?

Yes, but the current implementation is not thread-safe. Multiple concurrent operations could interleave updates to `front`, `size`, and the array. Synchronization or an appropriate concurrent design would be needed if the deque were shared across threads.

## Final mental model

Don't memorize eight separate methods. Remember three things:

1. `front` identifies the first element.
2. `size` identifies how many logical elements exist.
3. Modulo arithmetic wraps positions around the array.

From those three facts, the index formulas follow naturally:

```
// Move to the previous physical slot.
front = (front - 1 + capacity) % capacity;

// Next position after all current elements.
int nextRearInsertion = (front + size) % capacity;

// Existing last element.
int rear = (front + size - 1) % capacity;

// Move to the next physical slot.
front = (front + 1) % capacity;
```

The most important distinction is between the index of an existing element and the index where a new element should go. Once that is clear, circular deque implementation becomes a small set of predictable pointer and size updates rather than a collection of formulas to memorize.
