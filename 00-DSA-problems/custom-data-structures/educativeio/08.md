# Word Distance — Java 24 Interview Solution

## 0. Understand the problem in simple terms

You are given an array of strings. You need to design a class that can answer multiple queries asking for the minimum distance between two different words in that array.

The distance between two words is the difference between their indices:

\\[ \text{distance} = |i-j| \\]

For example:

```
String[] wordsDict = {
    "practice", "makes", "perfect", "coding", "makes"
};
```

Suppose we call:

```
shortest("coding", "practice"); // 3
shortest("makes", "coding");    // 1
shortest("makes", "practice");  // 1
```

Why?

Example array with zero-based indices

| Index | Word     |
| ----- | -------- |
| 0     | practice |
| 1     | makes    |
| 2     | perfect  |
| 3     | coding   |
| 4     | makes    |

- `coding` at index 3 and `practice` at index 0 have distance \\(3-0=3\\).
- `makes` at index 4 and `coding` at index 3 have distance \\(4-3=1\\).
- `makes` at index 1 and `practice` at index 0 have distance \\(1-0=1\\).

The key requirement is that the class should handle up to 1,000 calls to `shortest()`, so we should consider preprocessing the array in the constructor to make queries faster.

## 1. Clarifying questions to ask the interviewer

1. Can the same word appear multiple times? Yes, we should assume it can. Repeated occurrences are important because the shortest distance might involve a later occurrence rather than the first one.
2. Are `word1` and `word2` guaranteed to be different and present in the array? Yes, according to the constraints. This means we do not need special handling for missing words or identical query words.
3. Will the array change after construction? The problem implies the dictionary is fixed. This allows us to preprocess word positions once and reuse them across queries.
4. Should we optimize construction time or query time? With up to 1,000 queries, preprocessing is worthwhile. We can store every word's indices and answer each query efficiently.

## 2. Core intuition: remember where every word occurs

Imagine we build a map where each word points to all its positions in the array.

For the example:

```
practice -> [0]
makes    -> [1, 4]
perfect  -> [2]
coding   -> [3]
```

Now, if the interviewer asks for the shortest distance between `"makes"` and `"coding"`, we do not need to scan the original array from scratch. We look up their positions:

```
makes:  [1, 4]
coding: [3]
```

Compare the possibilities:

- \\(|1-3|=2\\)
- \\(|4-3|=1\\)

The minimum is `1`.

The main insight is that we can trade a little extra memory during construction for faster repeated queries.

There are two useful approaches:

- Approach 1: Store every word's positions in a hash map, then compare all pairs of positions for a query.
- Approach 2 (optimal): Store the positions in sorted order and use two pointers to find the closest pair in linear time relative to the number of occurrences of the two queried words.

## 3. Approach 1 — Brute force

The simplest solution scans the entire array for every query.

For each occurrence of `word1`, compare it with every occurrence of `word2`, and keep the minimum absolute difference.

```
public final class WordDistanceBruteForce {

    private final String[] words;

    public WordDistanceBruteForce(String[] wordsDict) {
        // Keep the original array for future queries.
        // Constructor time: O(n), because cloning copies n references.
        // Extra space: O(n), because we create a copy of the array.
        this.words = wordsDict.clone();
    }

    public int shortest(String word1, String word2) {
        int minDistance = Integer.MAX_VALUE;

        // Find every occurrence of word1.
        for (int i = 0; i < words.length; i++) {
            if (!words[i].equals(word1)) {
                continue;
            }

            // Compare it against every occurrence of word2.
            for (int j = 0; j < words.length; j++) {
                if (words[j].equals(word2)) {
                    minDistance = Math.min(
                        minDistance,
                        Math.abs(i - j)
                    );
                }
            }
        }

        // The constraints guarantee both words exist and differ,
        // so at least one valid pair will be found.
        return minDistance;
    }

    /*
     * Complexity:
     * Let n = wordsDict.length.
     *
     * Constructor:
     *   Time: O(n) to clone the array.
     *   Space: O(n) for the copied array.
     *
     * Each shortest() query:
     *   Time: O(n^2) in the worst case because we examine every
     *         pair of indices. String comparison is bounded by
     *         the maximum word length of 10, so it is O(1)
     *         under the given constraints.
     *   Auxiliary space: O(1).
     *
     * Why is this inefficient?
     * We repeatedly scan the same array for every query.
     * With 1,000 elements and 1,000 queries, this can perform
     * approximately 1,000,000,000 index-pair checks.
     */
}
```

When to use it: When the input is tiny or there are very few queries. It is easy to implement, but it ignores the opportunity to reuse work across queries.

## 4. Approach 2 — Hash map of positions, then compare every pair

Instead of scanning the original array on every query, preprocess it once.

Store each word's positions in a `Map<String, List<Integer>>`.

For example:

```
wordsDict = ["a", "b", "a", "c", "b"]

a -> [0, 2]
b -> [1, 4]
c -> [3]
```

A query for `"a"` and `"b"` compares these four pairs:

```
a positions: [0, 2]
b positions: [1, 4]

|0 - 1| = 1
|0 - 4| = 4
|2 - 1| = 1
|2 - 4| = 2

Answer = 1
```

```
import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

public final class WordDistancePairwise {

    private final Map<String, List<Integer>> positions = new HashMap<>();

    public WordDistancePairwise(String[] wordsDict) {
        // Build a word -> all occurrence indices mapping.
        // Each index is appended in ascending order because we
        // traverse the input array from left to right.
        for (int i = 0; i < wordsDict.length; i++) {
            positions.computeIfAbsent(
                wordsDict[i],
                ignored -> new ArrayList<>()
            ).add(i);
        }
    }

    public int shortest(String word1, String word2) {
        List<Integer> first = positions.get(word1);
        List<Integer> second = positions.get(word2);

        int minDistance = Integer.MAX_VALUE;

        // Examine every possible pair of occurrences.
        // This correctly handles duplicate words in the input.
        for (int i : first) {
            for (int j : second) {
                minDistance = Math.min(minDistance, Math.abs(i - j));
            }
        }

        return minDistance;
    }

    /*
     * Complexity:
     * Let n = total number of words,
     *     p = occurrences of word1,
     *     q = occurrences of word2.
     *
     * Constructor:
     *   Expected time: O(n), assuming expected O(1) hash-map
     *                  operations.
     *   Space: O(n) to store all occurrence indices, plus
     *          O(u) map entries for u distinct words.
     *          Since u <= n, total space is O(n).
     *
     * Each shortest() query:
     *   Expected lookup time: O(1) for each word.
     *   Distance calculation time: O(p * q).
     *   Auxiliary space: O(1), excluding the already stored map.
     *
     * Improvement over brute force:
     *   We avoid scanning positions belonging to unrelated words.
     *
     * Remaining inefficiency:
     *   We compare every occurrence of word1 with every occurrence
     *   of word2, even though most pairs cannot be the closest.
     */
}
```

This is a significant improvement when the queried words appear infrequently. However, if both words occur hundreds of times, the nested loops can still perform many unnecessary comparisons.

## 5. Approach 3 — Optimal solution using two pointers

This is the solution I would recommend in a technical interview.

### The key observation

The positions in each list are already sorted because we build them by scanning the original array from left to right.

For example:

```
word1 positions: [1, 8, 15]
word2 positions: [4, 10, 18]
```

We want the smallest distance between any position in the first list and any position in the second list.

Instead of comparing every possible pair, we use two pointers:

```
A = [1, 8, 15]
     ↑
     i

B = [4, 10, 18]
     ↑
     j
```

1. Compare positions `1` and `4`. Distance = `3`. Best answer so far: `3`.
2. Move the pointer at `1` forward, because it is the smaller position.

```
A = [1, 8, 15]
        ↑
        i

B = [4, 10, 18]
     ↑
     j
```

3. Compare `8` and `4`. Distance = `4`. Best answer stays `3`.
4. Move the pointer at `4` forward because it is smaller.

```
A = [1, 8, 15]
        ↑
        i

B = [4, 10, 18]
         ↑
         j
```

5. Compare `8` and `10`. Distance = `2`. Best answer becomes `2`.
6. Continue the same process until one list is exhausted.

The result is `2`.

### Why do we move the pointer at the smaller index?

Suppose the current positions are `a` and `b`, with `a < b`.

The current distance is `b - a`.

If we keep `b` fixed and move `a` to a later position, we might get closer to `b`. But moving `a` backward is impossible because the list is sorted and we have already examined earlier positions.

Therefore, advancing the pointer at the smaller index is the only move that can potentially improve the answer for the current pair.

The important guarantee is that once we move past the smaller position, no future position on the other list can make that discarded position part of a better pair.

### Complete Java 24 implementation

```
import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

public final class WordDistance {

    // Maps each word to every index where it appears.
    // Example: ["a", "b", "a"] -> a:[0, 2], b:[1]
    //
    // Keeping all positions handles duplicate words correctly.
    // The lists are naturally sorted because the constructor
    // processes the original array from left to right.
    private final Map<String, List<Integer>> positions;

    public WordDistance(String[] wordsDict) {
        // We preprocess once so that queries do not need to
        // repeatedly scan the entire input array.
        positions = new HashMap<>();

        for (int index = 0; index < wordsDict.length; index++) {
            String word = wordsDict[index];

            // Create a list on the first occurrence of a word.
            // Otherwise, reuse its existing list.
            positions.computeIfAbsent(
                word,
                ignored -> new ArrayList<>()
            ).add(index);
        }
    }

    public int shortest(String word1, String word2) {
        // Both words are guaranteed to exist and be different.
        // Therefore, both lists are non-null and contain indices.
        List<Integer> first = positions.get(word1);
        List<Integer> second = positions.get(word2);

        // i walks through the occurrence positions of word1.
        // j walks through the occurrence positions of word2.
        int i = 0;
        int j = 0;

        // Initially, no pair has been examined.
        int minDistance = Integer.MAX_VALUE;

        // Continue while both lists still have positions.
        while (i < first.size() && j < second.size()) {

            int index1 = first.get(i);
            int index2 = second.get(j);

            // Calculate the distance between the current pair.
            int distance = Math.abs(index1 - index2);

            // Record the best answer found so far.
            minDistance = Math.min(minDistance, distance);

            // Advance only the pointer at the smaller index.
            //
            // If index1 < index2:
            //   Moving j forward would only increase index2,
            //   so it cannot improve the distance to index1.
            //   Advance i to try a position closer to index2.
            //
            // If index2 < index1:
            //   Advance j to try a position closer to index1.
            //
            // If they were equal, either pointer could advance.
            // Equal indices cannot occur here because word1 and
            // word2 are different words at each array index.
            if (index1 < index2) {
                i++;
            } else {
                j++;
            }

            // Every iteration discards one position permanently.
            // Since positions are sorted, discarded positions
            // cannot produce a better pair in future iterations.
        }

        // Once either list is exhausted, there are no remaining
        // candidates that could beat the best distance found.
        return minDistance;
    }

    /*
     * ==================== COMPLEXITY ANALYSIS ====================
     *
     * Let:
     *   n = total number of words in wordsDict.
     *   p = number of occurrences of word1.
     *   q = number of occurrences of word2.
     *   u = number of distinct words.
     *
     * Constructor:
     *   Time: O(n) expected.
     *     - We visit each array element exactly once.
     *     - Each hash-map lookup/insertion is expected O(1).
     *     - Each index is appended once to a list.
     *
     *   Space: O(n + u) = O(n).
     *     - All n occurrence indices are stored.
     *     - The map maintains up to u word entries.
     *     - The lists collectively contain exactly n indices.
     *
     * Each shortest() query:
     *   Time: O(p + q) expected.
     *     - Hash-map lookups take expected O(1).
     *     - Each loop iteration advances i or j by one.
     *     - i advances at most p times; j advances at most q
     *       times. Hence there are at most p + q iterations.
     *     - Reading a List element by index is O(1).
     *
     *   Auxiliary space: O(1).
     *     - Only a fixed number of integer references/variables
     *       are used; the occurrence lists are already stored.
     *
     * Worst case for one query:
     *   p + q <= n, so query time is O(n).
     *
     * For Q queries:
     *   Total expected time = O(n + Q * n) in the worst case.
     *   More precisely, it is O(n + sum(p_k + q_k)) across queries.
     *
     * With n <= 1000 and Q <= 1000, this is easily efficient.
     */
}
```

## 6. Dry run of the optimal solution

Consider:

```
String[] wordsDict = {
    "practice", "makes", "perfect", "coding", "makes"
};

WordDistance wd = new WordDistance(wordsDict);
System.out.println(wd.shortest("makes", "coding")); // 1
```

After preprocessing:

```
makes  -> [1, 4]
coding -> [3]
```

| Iteration | `i` | `j` | `index1` | `index2` | Distance | Action      |
| --------- | --- | --- | -------- | -------- | -------- | ----------- |
| 1         | 0   | 0   | 1        | 3        | 2        | Advance `i` |
| 2         | 1   | 0   | 4        | 3        | 1        | Advance `j` |

Now `j == coding.size()`, so the loop terminates.

The minimum distance is `1`.

Notice that we performed only two comparisons instead of comparing every pair.

## 7. Edge cases to watch out for

| Case                                | Example                          | Expected behavior                                      |
| ----------------------------------- | -------------------------------- | ------------------------------------------------------ |
| Adjacent words                      | `["a", "b"]`                     | Distance `1`                                           |
| Multiple occurrences                | `["a", "x", "a", "b"]`           | Distance between `a` and `b` is `1`                    |
| Closest occurrence is not the first | `["a", "x", "x", "b", "a", "b"]` | Distance is `1`                                        |
| Words at opposite ends              | `["a", "x", "b"]`                | Distance `2`                                           |
| One occurrence per word             | `["a", "b", "c"]`                | Distance `1` for `a` and `b`                           |
| Large number of duplicates          | `["a", "b", "a", "b", "a"]`      | The closest pair is found without examining every pair |

The constraints guarantee that both queried words exist and are different. In production code, if those guarantees are removed, decide whether a missing word should throw an exception or return a sentinel such as `-1`.

## 8. Comparison of all approaches

| Approach                | Constructor time    | Query time            | Extra space |
| ----------------------- | ------------------- | --------------------- | ----------- |
| Brute force             | \\(O(n)\\)          | \\(O(n^2)\\)          | \\(O(n)\\)  |
| Hash map + all pairs    | \\(O(n)\\) expected | \\(O(pq)\\) expected  | \\(O(n)\\)  |
| Hash map + two pointers | \\(O(n)\\) expected | \\(O(p+q)\\) expected | \\(O(n)\\)  |

Here, \\(p\\) and \\(q\\) are the numbers of occurrences of the two queried words.

Interview recommendation: Start with brute force to establish correctness, introduce preprocessing to avoid repeated scans, and then optimize the query using two pointers. The third approach gives the best worst-case query complexity among these solutions while remaining easy to explain and implement.

## 9. Interviewer follow-up questions and answers

Q1. Why use a hash map instead of scanning the array on every query?

Because the constructor can perform the work once. A hash map provides expected \\(O(1)\\) lookup for each queried word, and we only process its occurrence positions afterward.

Q2. Why are two pointers better than nested loops?

Nested loops compare all \\(pq\\) pairs. The two-pointer technique uses the sorted order to eliminate candidates that cannot improve the answer, reducing the query time to \\(O(p+q)\\).

Q3. What if the same word can be queried twice?

The current problem explicitly guarantees `word1 != word2`. If that constraint were removed and the requested distance had to be between two distinct occurrences of the same word, we would need a separate implementation that finds the minimum gap between consecutive positions in that word's list.

Q4. Could we store only the first occurrence of each word?

No. For example, in `["a", "x", "x", "b", "a", "b"]`, keeping only the first occurrence of each word would miss the closest pair at indices 4 and 5. All occurrences are needed.

Q5. What if queries greatly outnumber the input size?

The two-pointer method is already a good choice. If a fixed set of words is queried extremely frequently, we could also cache results for previously queried word pairs. That trades additional memory for faster repeated queries.

Q6. What if the dictionary changes after construction?

The stored positions would become stale. We would need to support updates by adjusting the relevant position lists, or rebuild the index after changes. The current solution assumes the dictionary remains fixed.

Q7. Is the two-pointer approach guaranteed to find the global minimum?

Yes. The two position lists are sorted. At each step, we evaluate the current pair and advance the pointer at the smaller index. That smaller position cannot be part of a better pair with any future position on the other list, so eliminating it cannot discard the optimal answer.

Final takeaway: The most important interview concept here is not the hash map itself. It is recognizing that occurrence indices are sorted, and that this sorted structure enables the two-pointer technique to avoid unnecessary pair comparisons.
