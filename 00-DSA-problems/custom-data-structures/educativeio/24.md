# 642. Design Search Autocomplete System — Java 24

The key to solving this problem in an interview is to recognize that autocomplete is a prefix-search problem combined with ranking by popularity.

We need to design a system that remembers previously entered sentences, finds sentences matching the user's current prefix, and returns the three most popular matches. As the user types character by character, the prefix changes, and so do the suggestions.

The most important design decision is how to store sentences so that we can find prefix matches efficiently. We'll explore a brute-force solution first, then a Trie-based solution, and finally discuss how to maintain the top three suggestions efficiently.

## 0. Simplify the problem statement

Imagine a search box that suggests sentences as you type.

Given previously entered sentences and their usage frequencies:

```
Sentences:  ["i love you", "island", "i love leetcode", "ironman"]
Frequencies: [5,            3,        2,                 2]
```

When the user types `i`, the system suggests the three most popular sentences beginning with `i`.

When the user continues typing ` ` (a space), the prefix becomes `i `, so only sentences beginning with `i ` qualify.

When the user presses `#`, the system treats everything typed so far as a completed sentence and saves it, increasing its frequency.

### Required behavior

- `AutocompleteSystem(String[] sentences, int[] times)` initializes the system.
- `input(char c)` processes one character at a time and returns up to three suggestions.
- Suggestions must match the current prefix.
- Rank by frequency, highest first.
- Break frequency ties using lexicographical order, smallest first.
- `#` commits the current sentence, updates its frequency, clears the current input, and returns an empty list.

## 1. Clarifying questions to ask the interviewer

These questions help establish correctness and choose the right data structure.

1. Are spaces valid characters in sentences? Yes, spaces are part of the prefix and must be stored in the Trie.
2. What happens when the user types `#`? Commit the current sentence, increment its frequency, reset the input, and return an empty list.
3. What if a sentence has never appeared before? Insert it with frequency `1`.
4. How many suggestions should be returned? At most three; return fewer if fewer than three sentences match.
5. What determines ranking when frequencies tie? Lexicographical ordering of the complete sentences.
6. Can the same sentence appear multiple times in the initial input? The usual problem representation gives each initial sentence a frequency, but a robust implementation should correctly accumulate duplicate entries if they occur.
7. What are the constraints on sentence length and number of sentences? This helps decide whether scanning all sentences is acceptable or whether prefix indexing is needed.

## 2. The interview mental model

Think of the system as two separate responsibilities:

- Finding candidates: Which sentences start with the typed prefix?
- Ranking candidates: Which three candidates have the highest frequency, with alphabetical ordering as the tie-breaker?

A Trie handles the first responsibility. A frequency map and an ordering strategy handle the second.

```
                       root
                        |
                        i
                       / \
                      ' '  s
                     /      \
                    l        l
                   /          \
                  o            a
                 ...
```

Each path from the root represents a prefix. For example, the node reached by `i ` represents all sentences beginning with `i `.

There are three useful levels of solution:

1. Scan every sentence and sort the matches.
2. Use a Trie to find matches, then sort those matches.
3. Use a Trie with a `TreeSet` at each prefix node, keeping matching sentences ordered at all times.

The third approach makes each query very efficient while correctly handling frequency changes. Its trade-off is additional memory because sentences are indexed at multiple prefix nodes.

## 3. Solution 1 — Brute force: scan and sort

The simplest approach stores every sentence's frequency in a `HashMap`.

For each input character:

1. Append the character to the current prefix.
2. Scan every known sentence.
3. Keep sentences that start with the prefix.
4. Sort by frequency descending, then lexicographically ascending.
5. Return the first three.

```
import java.util.ArrayList;
import java.util.Comparator;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

class AutocompleteSystemBruteForce {

    // Stores each distinct sentence and its current frequency.
    private final Map<String, Integer> frequencyBySentence = new HashMap<>();

    // Represents the text typed since the last '#'.
    private final StringBuilder currentPrefix = new StringBuilder();

    // Centralize the ranking rule so every solution uses the same ordering.
    private static final Comparator<String> RANKING =
            Comparator.<String>comparingInt(
                    sentence -> 0 // Placeholder; actual frequency needs an instance comparator.
            );

    public AutocompleteSystemBruteForce(String[] sentences, int[] times) {
        // merge also handles duplicate initial sentences by accumulating frequencies.
        for (int i = 0; i < sentences.length; i++) {
            frequencyBySentence.merge(sentences[i], times[i], Integer::sum);
        }
    }

    public List<String> input(char c) {
        if (c == '#') {
            // '#' is a commit command, not part of the sentence.
            // A previously unseen sentence begins with frequency 1.
            frequencyBySentence.merge(currentPrefix.toString(), 1, Integer::sum);

            // Prepare for the next independent sentence.
            currentPrefix.setLength(0);
            return List.of();
        }

        currentPrefix.append(c);
        String prefix = currentPrefix.toString();

        // Collect every sentence matching the prefix.
        List<String> matches = new ArrayList<>();
        for (String sentence : frequencyBySentence.keySet()) {
            if (sentence.startsWith(prefix)) {
                matches.add(sentence);
            }
        }

        // The comparator reads the latest frequencies from the map.
        matches.sort((first, second) -> {
            int byFrequency = Integer.compare(
                    frequencyBySentence.get(second),
                    frequencyBySentence.get(first)
            );

            return byFrequency != 0
                    ? byFrequency
                    : first.compareTo(second);
        });

        // Only three results are required. Copy the result to avoid returning
        // a view backed by the temporary matches list.
        return List.copyOf(matches.subList(0, Math.min(3, matches.size())));
    }
}

/*
 * Complexity:
 *
 * Let N = number of distinct sentences, L = current prefix length,
 * and M = total characters in the matching sentences.
 *
 * Initialization:
 *   O(total initial input characters) expected, using HashMap operations.
 *
 * Each ordinary input character:
 *   O(L + N * L + K log K), where K is the number of matching sentences.
 *   - O(L) to materialize the current prefix.
 *   - O(N * L) to test startsWith against all stored sentences.
 *   - O(K log K) to sort the matches.
 *
 * Extra space per query:
 *   O(L + K) for the prefix string and matching list.
 *
 * Why this is not scalable:
 *   Almost every keystroke scans the entire sentence dictionary.
 *   It is easy to implement and useful as a correctness baseline,
 *   but repeated prefix queries do unnecessary work.
 */
```

## 4. Solution 2 — Trie for prefix lookup, sorting only matching sentences

The brute-force solution asks every sentence whether it matches the prefix. A Trie lets us navigate directly to the prefix node.

Once we reach that node, only sentences in its subtree can match. We collect those sentences, rank them, and return the top three.

```
Sentences: "i love you", "i love leetcode", "island"

root
 |
 i
 | \
 ' ' s
 |   |
 l   l
 |   |
 o   a
 |
 v
 |
 e

Typing "i " takes us directly to the node for prefix "i ".
We do not visit sentences beginning with unrelated prefixes.
```

```
import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

class AutocompleteSystemTrie {

    private static final class TrieNode {
        // Character edges are sparse: only characters that actually occur
        // beneath this prefix need entries.
        private final Map<Character, TrieNode> children = new HashMap<>();

        // Non-null only when a complete sentence ends at this node.
        private String sentence;
    }

    private final TrieNode root = new TrieNode();
    private final Map<String, Integer> frequencyBySentence = new HashMap<>();
    private final StringBuilder currentPrefix = new StringBuilder();

    public AutocompleteSystemTrie(String[] sentences, int[] times) {
        for (int i = 0; i < sentences.length; i++) {
            // Accumulate duplicate initial sentences rather than overwrite them.
            frequencyBySentence.merge(sentences[i], times[i], Integer::sum);
        }

        // Build the Trie once from the initial dictionary.
        for (String sentence : frequencyBySentence.keySet()) {
            insert(sentence);
        }
    }

    private void insert(String sentence) {
        TrieNode node = root;

        for (char c : sentence.toCharArray()) {
            // Create a node only when this character edge does not exist.
            node = node.children.computeIfAbsent(c, ignored -> new TrieNode());
        }

        // Mark this path as a complete sentence.
        node.sentence = sentence;
    }

    public List<String> input(char c) {
        if (c == '#') {
            String completedSentence = currentPrefix.toString();

            // Update the frequency, then ensure its path exists in the Trie.
            frequencyBySentence.merge(completedSentence, 1, Integer::sum);
            insert(completedSentence);

            currentPrefix.setLength(0);
            return List.of();
        }

        currentPrefix.append(c);

        // Navigate only as far as the current prefix.
        TrieNode prefixNode = findNode(currentPrefix);

        if (prefixNode == null) {
            // No sentence has this prefix. Future characters cannot restore
            // a match because extending a prefix only narrows its matches.
            return List.of();
        }

        List<String> matches = new ArrayList<>();
        collectSentences(prefixNode, matches);

        matches.sort((first, second) -> {
            int byFrequency = Integer.compare(
                    frequencyBySentence.get(second),
                    frequencyBySentence.get(first)
            );
            return byFrequency != 0 ? byFrequency : first.compareTo(second);
        });

        return List.copyOf(matches.subList(0, Math.min(3, matches.size())));
    }

    private TrieNode findNode(CharSequence prefix) {
        TrieNode node = root;

        for (int i = 0; i < prefix.length(); i++) {
            node = node.children.get(prefix.charAt(i));

            if (node == null) {
                return null;
            }
        }

        return node;
    }

    private void collectSentences(TrieNode node, List<String> matches) {
        if (node.sentence != null) {
            matches.add(node.sentence);
        }

        // Every terminal sentence below this node shares the current prefix.
        for (TrieNode child : node.children.values()) {
            collectSentences(child, matches);
        }
    }
}

/*
 * Complexity:
 *
 * Let L = current prefix length, K = number of matching sentences,
 * and S = total characters in the subtree of the prefix node.
 *
 * Initialization:
 *   O(T), where T is the total number of characters in all distinct sentences.
 *
 * Each ordinary input character:
 *   O(L + S + K log K).
 *   - O(L) to navigate from the root to the prefix node.
 *   - O(S) to traverse its subtree and collect terminal sentences.
 *   - O(K log K) to rank the matches.
 *
 * Commit:
 *   O(L) expected to update the frequency and insert the sentence path.
 *
 * Space:
 *   O(T + N + L) for Trie nodes, sentence frequencies, and current input.
 *
 * Why this is better:
 *   Prefix navigation avoids scanning unrelated sentences.
 *
 * Remaining bottleneck:
 *   A very common prefix may have a huge subtree, and we still collect
 *   and sort all of its matching sentences to return only three.
 */
```

## 5. Solution 3 — Trie + ordered candidate sets (efficient queries)

This is the approach I would discuss when the interviewer asks how to optimize repeated autocomplete queries.

### The key insight

At each Trie node, maintain a `TreeSet` containing every sentence that passes through that node, ordered by:

1. Frequency descending.
2. Sentence lexicographically ascending.

For example, the set at prefix `i ` contains all sentences beginning with `i ` in the exact order needed by the API.

Then the answer to a query is simply the first three entries in that set. No subtree traversal and no sorting are necessary.

### Why not cache only the top three sentences?

Because frequencies change. A sentence that was previously ranked fourth can become ranked first after enough commits. A node storing only its old top three would not necessarily know that the excluded sentence now belongs in the result.

Keeping all matching candidates in an ordered set avoids this correctness problem.

### A subtle implementation detail

The `TreeSet` comparator reads frequencies from a shared map. Never mutate a sentence's frequency while that sentence remains inside a `TreeSet` that uses the frequency to order it. Doing so can break the tree's ordering invariants.

The safe update sequence is:

1. Walk the sentence's Trie path and remove the sentence from every candidate set on that path.
2. Increment the sentence's frequency.
3. Walk the path again, inserting the sentence into each ordered set.

```
import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;
import java.util.TreeSet;

class AutocompleteSystem {

    private static final int SUGGESTION_LIMIT = 3;

    private static final class TrieNode {
        // Each edge represents one character of a sentence.
        private final Map<Character, TrieNode> children = new HashMap<>();

        // All sentences sharing the prefix represented by this node.
        // TreeSet keeps them ranked so that the best candidate is first.
        private final TreeSet<String> candidates = new TreeSet<>(
                (first, second) -> {
                    // This comparator is supplied by the enclosing instance
                    // in production code; see the comparator factory below.
                    return first.compareTo(second);
                }
        );

        // Indicates that a complete sentence ends at this node.
        private boolean isSentence;
    }

    private final Map<String, Integer> frequencyBySentence = new HashMap<>();
    private final TrieNode root;
    private final StringBuilder currentPrefix = new StringBuilder();

    public AutocompleteSystem(String[] sentences, int[] times) {
        // Create the root after the frequency map exists, so its comparator
        // can always consult the current frequencies.
        root = new TrieNodeWithRanking().node;

        for (int i = 0; i < sentences.length; i++) {
            frequencyBySentence.merge(sentences[i], times[i], Integer::sum);
        }

        // Insert each distinct sentence with its accumulated initial frequency.
        for (String sentence : frequencyBySentence.keySet()) {
            addSentenceToTrie(sentence);
        }
    }

    /*
     * A small factory demonstrates the dependency between candidate ordering
     * and the live frequency map.
     */
    private final class TrieNodeWithRanking {
        private final TrieNode node = new TrieNode();
    }

    public List<String> input(char c) {
        if (c == '#') {
            String completedSentence = currentPrefix.toString();

            // Existing sentences must be removed from every ordered set before
            // changing their frequency. New sentences have no old entries.
            boolean alreadyExists = frequencyBySentence.containsKey(completedSentence);

            if (alreadyExists) {
                removeSentenceFromTrie(completedSentence);
            }

            frequencyBySentence.merge(completedSentence, 1, Integer::sum);
            addSentenceToTrie(completedSentence);

            currentPrefix.setLength(0);
            return List.of();
        }

        currentPrefix.append(c);

        TrieNode node = findNode(currentPrefix);
        if (node == null) {
            return List.of();
        }

        // The TreeSet is already ranked; reading the first three elements
        // is enough to answer the query.
        List<String> suggestions = new ArrayList<>(SUGGESTION_LIMIT);
        for (String sentence : node.candidates) {
            suggestions.add(sentence);

            if (suggestions.size() == SUGGESTION_LIMIT) {
                break;
            }
        }

        return List.copyOf(suggestions);
    }

    private TrieNode findNode(CharSequence prefix) {
        TrieNode node = root;

        for (int i = 0; i < prefix.length(); i++) {
            node = node.children.get(prefix.charAt(i));

            if (node == null) {
                return null;
            }
        }

        return node;
    }

    private void addSentenceToTrie(String sentence) {
        TrieNode node = root;

        // The empty prefix at the root matches every sentence.
        node.candidates.add(sentence);

        for (char c : sentence.toCharArray()) {
            node = node.children.computeIfAbsent(c, ignored -> new TrieNode());
            node.candidates.add(sentence);
        }

        node.isSentence = true;
    }

    private void removeSentenceFromTrie(String sentence) {
        TrieNode node = root;
        node.candidates.remove(sentence);

        for (char c : sentence.toCharArray()) {
            node = node.children.get(c);

            // All nodes on an inserted sentence path are guaranteed to exist.
            node.candidates.remove(sentence);
        }
    }
}
```

The preceding sketch illustrates the data flow, but a clean implementation must give every node the correct frequency-aware comparator. Otherwise the sets are alphabetically ordered, not popularity ordered. Here is the complete, compile-ready implementation with that detail handled correctly:

```
import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;
import java.util.TreeSet;

class AutocompleteSystemOptimized {

    private static final int SUGGESTION_LIMIT = 3;

    private final Map<String, Integer> frequencyBySentence = new HashMap<>();
    private final StringBuilder currentPrefix = new StringBuilder();
    private final TrieNode root = new TrieNode();

    private final class TrieNode {
        private final Map<Character, TrieNode> children = new HashMap<>();

        // Every sentence sharing this node's prefix is indexed here.
        // The comparator uses the current frequency and lexical tie-breaker.
        private final TreeSet<String> candidates = new TreeSet<>((first, second) -> {
            int byFrequency = Integer.compare(
                    frequencyBySentence.get(second),
                    frequencyBySentence.get(first)
            );

            if (byFrequency != 0) {
                return byFrequency;
            }

            // Different sentences with equal frequencies must remain distinct.
            return first.compareTo(second);
        });

        private boolean isSentence;
    }

    public AutocompleteSystemOptimized(String[] sentences, int[] times) {
        for (int i = 0; i < sentences.length; i++) {
            frequencyBySentence.merge(sentences[i], times[i], Integer::sum);
        }

        // Populate all candidate sets only after the initial frequencies
        // have been aggregated, so every set is built with final initial ranks.
        for (String sentence : frequencyBySentence.keySet()) {
            addSentenceToTrie(sentence);
        }
    }

    public List<String> input(char c) {
        if (c == '#') {
            String completedSentence = currentPrefix.toString();

            if (frequencyBySentence.containsKey(completedSentence)) {
                // Critical ordering rule: remove before mutating comparator data.
                removeSentenceFromTrie(completedSentence);
            }

            frequencyBySentence.merge(completedSentence, 1, Integer::sum);
            addSentenceToTrie(completedSentence);

            currentPrefix.setLength(0);
            return List.of();
        }

        currentPrefix.append(c);

        TrieNode prefixNode = findNode(currentPrefix);
        if (prefixNode == null) {
            return List.of();
        }

        List<String> suggestions = new ArrayList<>(SUGGESTION_LIMIT);

        // TreeSet iteration follows ranking order, so we stop after three.
        for (String sentence : prefixNode.candidates) {
            suggestions.add(sentence);

            if (suggestions.size() == SUGGESTION_LIMIT) {
                break;
            }
        }

        return List.copyOf(suggestions);
    }

    private TrieNode findNode(CharSequence prefix) {
        TrieNode node = root;

        for (int i = 0; i < prefix.length(); i++) {
            node = node.children.get(prefix.charAt(i));

            if (node == null) {
                return null;
            }
        }

        return node;
    }

    private void addSentenceToTrie(String sentence) {
        TrieNode node = root;
        node.candidates.add(sentence);

        for (char c : sentence.toCharArray()) {
            node = node.children.computeIfAbsent(c, ignored -> new TrieNode());
            node.candidates.add(sentence);
        }

        node.isSentence = true;
    }

    private void removeSentenceFromTrie(String sentence) {
        TrieNode node = root;
        node.candidates.remove(sentence);

        for (char c : sentence.toCharArray()) {
            node = node.children.get(c);
            node.candidates.remove(sentence);
        }
    }
}

/*
 * Complexity:
 *
 * Let:
 *   N = number of distinct sentences,
 *   L = length of the current or committed sentence,
 *   Kp = number of sentences sharing a particular prefix p.
 *
 * Initialization:
 *   O(T log N) in a conservative bound, where T is the total number of
 *   sentence-character occurrences. Each sentence is inserted into the
 *   ordered sets for its prefixes, and each set operation is logarithmic
 *   in the number of candidates at that node.
 *
 * Ordinary input character:
 *   O(L + 3) expected, hence O(L).
 *   - O(L) to navigate from the root to the prefix node.
 *   - O(1) to retrieve at most three candidates once the node is found.
 *
 * Commit of a sentence of length L:
 *   O(L log N) as a conservative upper bound.
 *   - Remove the old sentence from each of its L + 1 prefix sets.
 *   - Increment its frequency.
 *   - Reinsert it into those same sets.
 *
 * Extra space:
 *   O(T + sum of Kp over all Trie prefix nodes).
 *   This can be O(N * L^2) in the worst case when many long sentences
 *   share long prefixes. The frequency map and Trie nodes themselves
 *   require O(T + N) space.
 *
 * Why it is faster:
 *   Each prefix node already knows its candidates in the required order.
 *   A query never traverses the entire matching subtree or sorts matches.
 *
 * Important correctness conditions:
 *   1. Remove a sentence from every affected TreeSet before changing its
 *      frequency, because the comparator depends on the frequency map.
 *   2. Reinsert it after the frequency update.
 *   3. Include the full sentence as a lexical tie-breaker; otherwise two
 *      equal-frequency sentences might compare as equal and one can vanish
 *      from the TreeSet.
 *   4. The root's candidate set is maintained too, even though normal input
 *      queries ask for non-empty prefixes.
 */
```

## 6. Edge cases to test

Use these as interview test cases. The expected behavior follows the problem's ranking and commit rules.

| Case                              | What to verify                                                                                  |
| --------------------------------- | ----------------------------------------------------------------------------------------------- |
| No matching prefix                | Return an empty list.                                                                           |
| Only one matching sentence        | Return one suggestion, not three padded results.                                                |
| Exactly three matches             | Return all three in ranking order.                                                              |
| More than three matches           | Return only the best three.                                                                     |
| Equal frequencies                 | Order tied sentences lexicographically.                                                         |
| Sentence contains spaces          | Treat spaces as ordinary prefix characters.                                                     |
| New sentence is committed         | Insert it with frequency `1`.                                                                   |
| Existing sentence is committed    | Increase its frequency and update all affected rankings.                                        |
| Previously unseen prefix          | Return an empty list without failing on subsequent characters.                                  |
| Empty sentence committed with `#` | Normally excluded by the problem's input assumptions; clarify if empty sentences are permitted. |
| Duplicate initial sentence        | Accumulate its frequencies rather than losing earlier counts.                                   |

One especially important test is a sentence that initially ranks fourth but becomes a top-three suggestion after repeated commits. It exposes implementations that cache only the original top three candidates.

## 7. Interviewer follow-up questions and answers

Q1. Why use a Trie instead of a `HashMap`?

A `HashMap` supports efficient exact-key lookup, but autocomplete asks for every sentence sharing a prefix. A Trie directly represents those prefixes, making it natural to find the relevant candidate group.

Q2. Why is sorting on every keystroke expensive?

The matching candidates can be numerous, even though the API returns at most three. Sorting \\(K\\) candidates costs \\(O(K \log K)\\), and repeated keystrokes repeat that work.

Q3. Why not store only three suggestions at each Trie node?

Because frequencies change. A sentence outside the cached top three can eventually enter the top three. Correctly maintaining only three requires additional machinery, such as tracking all candidates that might enter the ranking or recomputing affected rankings from a complete candidate collection.

Q4. Is the ordered-set solution always the best production design?

No. It trades memory and update cost for fast queries. If queries are frequent and commits are relatively rare, it can be a good fit. If memory is tight or updates are very frequent, a different design may be preferable.

Q5. Can we cache the top three and still support updates efficiently?

Yes, but the update logic must be correct. For example, each node can maintain all candidates in an ordered structure and derive its top three, or use a more sophisticated ranking index. Merely retaining the previous three entries is not sufficient.

Q6. What changes if the system must support millions of sentences?

Consider memory-efficient Trie representations, compressed radix trees, prefix indexes, bounded caches, and distributed search infrastructure. The correct choice depends on update frequency, query latency requirements, sentence lengths, and memory constraints.

Q7. What if the frequency changes while a sentence is in a `TreeSet`?

That is unsafe when the comparator depends on mutable frequency values. The sentence must be removed before changing its frequency and reinserted afterward. Otherwise the tree may no longer satisfy its ordering invariants.

## 8. Which solution should you present in an interview?

- Start with brute force. It establishes the ranking rules and provides a correctness baseline.
- Move to a Trie. This addresses the repeated prefix-search cost.
- Optimize with ordered candidate sets. This eliminates repeated subtree traversal and sorting at query time, at the cost of higher memory usage and more expensive updates.

The most important takeaway is not simply “use a Trie.” It is to recognize the two separate operations — prefix filtering and popularity ranking — and decide whether to perform ranking on demand or maintain it incrementally as data changes.
