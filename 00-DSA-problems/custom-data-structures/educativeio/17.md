# LeetCode 381 — Insert Delete GetRandom O(1) (Duplicates Allowed)

The key challenge in this problem is supporting duplicates while keeping insertion, removal, and random selection at average \\(O(1)\\) time.

The trick is to combine two data structures:

1. An `ArrayList<Integer>` that stores every occurrence of every value.
2. A `HashMap<Integer, Set<Integer>>` that stores the indices where each value appears in the list.

The most important idea to understand is how to remove an element from the middle of an array-backed list in \\(O(1)\\) time: replace it with the last element, update the indices, and remove the last element.

## 0. Understand the problem in simple terms

Imagine the collection contains:

```
[10, 20, 10, 30, 10]
```

There are five occurrences, not three distinct values.

- `insert(10)` adds another occurrence of `10`.
- `remove(10)` removes just one occurrence of `10`.
- `getRandom()` chooses a random index from `0` to `4` and returns the value at that index.

Therefore:

- Probability of returning `10` = \\(3/5\\).
- Probability of returning `20` = \\(1/5\\).
- Probability of returning `30` = \\(1/5\\).

Why use an array? Randomly selecting an index is \\(O(1)\\), and appending is amortized \\(O(1)\\).

Why use a hash map of index sets? A value may occur multiple times, so we need to locate one of its occurrences quickly when removing it.

Why not just use a `HashSet`? A set tracks distinct values, but it loses the number of occurrences and cannot provide the required duplicate-weighted random distribution.

## 1. Clarifying questions to ask the interviewer

| Question                                                                 | Why it matters                                                                                           |
| ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------- |
| Can the collection contain duplicate values?                             | Yes. We must track every occurrence independently.                                                       |
| Should `insert` return `true` only when the value was previously absent? | Yes. The return value depends on whether the value already exists, not whether insertion succeeds.       |
| Does `remove` remove one occurrence or every occurrence?                 | Only one occurrence must be removed.                                                                     |
| Must `getRandom()` select distinct values uniformly?                     | No. Every occurrence must be equally likely, so duplicate values have proportionally higher probability. |
| Can we assume `getRandom()` is called only on a nonempty collection?     | Yes, according to the constraints. We do not need to define empty-collection behavior for the judge.     |
| Is average \\(O(1)\\) acceptable?                                        | Yes. Hash-map operations are average \\(O(1)\\), and `ArrayList` appends are amortized \\(O(1)\\).       |

## 2. Core intuition: two data structures working together

We maintain these two structures:

```
List<Integer> values;

Map<Integer, Set<Integer>> valueToIndices;
```

### Data structure A: `values`

Stores every occurrence, including duplicates.

```
Index:   0   1   2   3   4
values: [10, 20, 10, 30, 10]
```

### Data structure B: `valueToIndices`

Maps each distinct value to all the indices at which it occurs.

```
10 -> {0, 2, 4}
20 -> {1}
30 -> {3}
```

The sets contain indices, not values. This distinction is essential because three occurrences of `10` need to be distinguishable.

### How insertion works

Suppose we insert `20` into:

```
values = [10, 20, 10]
```

The new element goes at index `3`.

```
values = [10, 20, 10, 20]

valueToIndices:
10 -> {0, 2}
20 -> {1, 3}
```

We return `false` because `20` already existed before the insertion.

The operation requires:

1. Checking whether the value already has an index set.
2. Appending the value to the array.
3. Adding the new index to its set.

All these operations take average \\(O(1)\\) time.

### How random selection works

If the array is:

```
values = [10, 20, 10, 30, 10]
```

We generate a uniformly random index from `0` through `4`.

```
random index -> value at that index
```

We do not randomly choose a key from the map. Doing so would give each distinct value equal probability, which would be incorrect.

### The difficult part: removing an element

Suppose we want to remove one occurrence of `20`.

```
values = [10, 20, 10, 30, 10]
```

The index set tells us that `20` is at index `1`.

A tempting approach is:

```
values.remove(1);
```

But this shifts all later elements one position to the left, requiring \\(O(n)\\) time.

Instead, we use a trick called swap with the last element.

The last element is `10` at index `4`. We move it into the position occupied by `20`, then remove the last array entry.

```
Before:

Index:   0   1   2   3   4
values: [10, 20, 10, 30, 10]
             ^
          remove 20

Step 1: Move the last element (10) into index 1.

Index:   0   1   2   3   4
values: [10, 10, 10, 30, 10]

Step 2: Remove the last entry.

Index:   0   1   2   3
values: [10, 10, 10, 30]
```

The array is now correct as a collection of values, but we must also update the index sets.

Initially:

```
10 -> {0, 2, 4}
20 -> {1}
30 -> {3}
```

After removing `20`, the moved `10` is now at index `1`, not index `4`.

The correct mapping becomes:

```
10 -> {0, 1, 2}
30 -> {3}
```

This requires three logical updates:

1. Remove index `1` from `20`'s index set.
2. Move the last value `10` to index `1` and update its index set from `4` to `1`.
3. Remove the final array entry.

Every set operation is average \\(O(1)\\), so removal is average \\(O(1)\\).

## 3. The removal algorithm, carefully reasoned

Let:

- `removeIndex` = an index of the value we want to remove.
- `lastIndex` = the final index in the array.
- `lastValue` = the value at `lastIndex`.
- `val` = the value we want to remove.

There are two cases.

### Case A: The element to remove is already the last element

```
values = [10, 20, 30]
                  ^
              remove 30
```

Here, `removeIndex == lastIndex`.

We simply remove the last array entry and delete its index from the corresponding set.

No swapping is necessary.

### Case B: The element to remove is not the last element

```
values = [10, 20, 30, 40]
             ^
          remove 20
```

We replace `20` with `40`:

```
values = [10, 40, 30, 40]
```

Then we remove the old final entry:

```
values = [10, 40, 30]
```

But the mapping for `40` must also change:

```
Before: 40 -> {3}
After:  40 -> {1}
```

Notice a subtlety: the value being moved might be the same as the value being removed.

For example:

```
values = [10, 20, 10]
```

If we remove the `10` at index `0`, the last `10` moves to index `0`.

The index set for `10` is initially `{0, 2}`. We must end with `{0}`.

This is why the order of updates matters.

Safe update order:

1. Pick an occurrence of `val` to remove.
2. Remove `removeIndex` from `val`'s index set.
3. If the removed position is not the last position:
   - Remove `lastIndex` from `lastValue`'s index set.
   - Write `lastValue` into `removeIndex`.
   - Add `removeIndex` to `lastValue`'s index set.
4. Remove the last element of the array.
5. If `val` has no remaining indices, remove its key from the map.

Why does this work when `val == lastValue`? The original `removeIndex` is removed first, then `lastIndex` is removed, and finally `removeIndex` is added back for the moved occurrence. The final set correctly contains the surviving occurrence at the new index.

## 4. Optimal Java 24 solution

```
import java.util.ArrayList;
import java.util.HashMap;
import java.util.HashSet;
import java.util.List;
import java.util.Map;
import java.util.Random;
import java.util.Set;

class RandomizedCollection {

    /*
     * CORE IDEA
     * ---------
     * values stores EVERY occurrence, including duplicates.
     *
     * Example:
     * values = [10, 20, 10]
     *
     * Each array position is one occurrence, so selecting a random
     * index gives each occurrence equal probability.
     *
     * ArrayList:
     * - get(index): O(1)
     * - add(value): amortized O(1)
     * - remove(lastIndex): O(1)
     *
     * Removing from the middle would cost O(n) because elements shift.
     * We avoid that by replacing the removed position with the last value.
     */
    private final List<Integer> values;

    /*
     * Maps each distinct value to ALL its positions in values.
     *
     * Example:
     * values = [10, 20, 10, 30, 10]
     *
     * valueToIndices = {
     *     10 -> {0, 2, 4},
     *     20 -> {1},
     *     30 -> {3}
     * }
     *
     * A HashSet is used because:
     * - We need to find an occurrence's index quickly.
     * - We need to add and remove indices quickly.
     * - We do not need the indices to be ordered.
     *
     * HashMap/HashSet operations are average O(1).
     */
    private final Map<Integer, Set<Integer>> valueToIndices;

    /*
     * A single Random object can be reused across calls.
     *
     * Random.nextInt(bound) returns a uniformly random index in
     * [0, bound), so every array occurrence has equal probability.
     */
    private final Random random;

    public RandomizedCollection() {
        values = new ArrayList<>();
        valueToIndices = new HashMap<>();
        random = new Random();

        /*
         * Constructor:
         * Time: O(1) expected, ignoring implementation-specific allocation.
         * Space: O(1) initially, excluding the empty structures' overhead.
         */
    }

    public boolean insert(int val) {

        /*
         * If the value has no set, it has never appeared in the collection.
         * This determines the return value BEFORE inserting the new occurrence.
         *
         * true  -> val was absent before this call.
         * false -> val was already present, but we still insert another copy.
         *
         * containsKey is average O(1).
         */
        boolean wasAbsent = !valueToIndices.containsKey(val);

        /*
         * The new occurrence will occupy the next available array index.
         *
         * IMPORTANT:
         * Store the index before appending so it refers to the correct position.
         */
        int newIndex = values.size();

        /*
         * Append the occurrence.
         * ArrayList.add is amortized O(1); occasional resizing can take O(n),
         * but the amortized cost over many insertions remains O(1) per insertion.
         */
        values.add(val);

        /*
         * Obtain the set for val, creating it if this is its first occurrence.
         *
         * Add the new index to the set. Since this is a new array position,
         * the index is not already present in val's set.
         *
         * Average time for map lookup/creation and set insertion: O(1).
         */
        valueToIndices
                .computeIfAbsent(val, ignored -> new HashSet<>())
                .add(newIndex);

        /*
         * Average time: O(1).
         * Extra space: O(1) per inserted occurrence, amortized, across
         * the array and index set.
         */
        return wasAbsent;
    }

    public boolean remove(int val) {

        /*
         * If val has no index set, no occurrence exists.
         * Nothing should change.
         *
         * Average lookup time: O(1).
         */
        Set<Integer> indices = valueToIndices.get(val);

        if (indices == null) {
            return false;
        }

        /*
         * Choose any occurrence of val.
         *
         * HashSet has no guaranteed ordering, but ordering does not matter:
         * the problem asks to remove ONE occurrence, not a particular one.
         *
         * Getting an iterator and its first element is O(1) on average.
         */
        int removeIndex = indices.iterator().next();

        /*
         * Identify the final array position and the value currently stored there.
         *
         * These values must be saved BEFORE modifying the array.
         */
        int lastIndex = values.size() - 1;
        int lastValue = values.get(lastIndex);

        /*
         * FIRST remove the index of the occurrence we are deleting.
         *
         * This ordering is important when val == lastValue.
         * We must remove the target occurrence's index before moving the last
         * occurrence, otherwise we can accidentally lose the surviving copy's
         * index or leave a stale index behind.
         */
        indices.remove(removeIndex);

        /*
         * If removeIndex == lastIndex, the target is already at the end.
         * No replacement is needed.
         *
         * Otherwise, move the last occurrence into the removed position.
         */
        if (removeIndex != lastIndex) {

            /*
             * The last occurrence of lastValue is about to leave lastIndex.
             * Remove that old index from lastValue's set.
             *
             * This also works if val == lastValue:
             * the target index was removed above, and this removes the
             * distinct lastIndex belonging to the moved occurrence.
             */
            Set<Integer> lastValueIndices = valueToIndices.get(lastValue);
            lastValueIndices.remove(lastIndex);

            /*
             * Overwrite the target position with the last value.
             *
             * ArrayList.set is O(1). No shifting occurs.
             */
            values.set(removeIndex, lastValue);

            /*
             * The moved occurrence now lives at removeIndex.
             * Update the mapping to reflect its new position.
             *
             * This is essential: every index stored in the map must point
             * to the current position of the corresponding value.
             */
            lastValueIndices.add(removeIndex);
        }

        /*
         * Remove the final array entry.
         *
         * We already moved its value if a move was necessary, so this
         * operation cannot disturb any other array position.
         *
         * ArrayList.remove(lastIndex) is O(1).
         */
        values.remove(lastIndex);

        /*
         * If val has no remaining occurrences, remove its map entry.
         * Otherwise, retain the set for future insertions and removals.
         *
         * This also handles the val == lastValue case correctly:
         * the surviving occurrence, if any, has already been reindexed.
         */
        if (indices.isEmpty()) {
            valueToIndices.remove(val);
        }

        /*
         * Average time: O(1).
         * We perform only a constant number of average-O(1) map/set operations
         * and O(1) array operations.
         */
        return true;
    }

    public int getRandom() {

        /*
         * The problem guarantees that values is nonempty for this call.
         *
         * Pick an index uniformly from [0, values.size()).
         * Do not pick a random map key: that would give distinct values
         * equal probabilities rather than weighting them by occurrence count.
         *
         * Time: O(1).
         * Extra space: O(1).
         */
        int randomIndex = random.nextInt(values.size());

        return values.get(randomIndex);
    }

    /*
     * COMPLEXITY SUMMARY
     * ------------------
     *
     * Let n = the total number of occurrences currently in the collection.
     * Let d = the number of distinct values.
     *
     * insert(val):
     *   Average O(1) time; ArrayList append is amortized O(1).
     *   O(1) additional space per occurrence, amortized.
     *
     * remove(val):
     *   Average O(1) time.
     *   Only one array position is overwritten and the final entry is removed.
     *
     * getRandom():
     *   O(1) time and O(1) extra space.
     *
     * Overall space:
     *   O(n + d) = O(n) for a nonempty collection, because the array stores
     *   n occurrences and the index sets collectively store n indices.
     *   The map has d keys.
     *
     * Hash-based operations have expected/average O(1) complexity,
     * not a worst-case guarantee for every possible hash-table operation.
     */
}
```

## 5. Dry run with detailed examples

Let's trace the example from the problem.

Operations:

```
insert(1)
insert(1)
insert(2)
getRandom()
remove(1)
getRandom()
```

### Step 1: `insert(1)`

Initially, both structures are empty.

```
values = []

valueToIndices = {}
```

Append `1` at index `0`.

```
values = [1]

valueToIndices:
1 -> {0}
```

Return `true`, because `1` was absent before insertion.

### Step 2: `insert(1)`

`1` already exists, but we must insert another occurrence.

Append it at index `1`.

```
values = [1, 1]

valueToIndices:
1 -> {0, 1}
```

Return `false`, because `1` already existed.

### Step 3: `insert(2)`

Append `2` at index `2`.

```
values = [1, 1, 2]

valueToIndices:
1 -> {0, 1}
2 -> {2}
```

Return `true`, because `2` was absent.

### Step 4: `getRandom()`

The possible random indices are:

```
Index:          0    1    2
values:        [1,   1,   2]
Probability:   1/3  1/3  1/3
```

Therefore:

- Probability of `1` = \\(2/3\\).
- Probability of `2` = \\(1/3\\).

The result is either `1` or `2`, with these probabilities.

### Step 5: `remove(1)`

Suppose the set iteration selects index `0`.

Before removal:

```
values = [1, 1, 2]

1 -> {0, 1}
2 -> {2}
```

The last value is `2` at index `2`.

Remove index `0` from the set for `1`:

```
1 -> {1}
```

Remove index `2` from the set for `2`, move `2` to index `0`, and add index `0` to its set:

```
values = [2, 1, 2]    // intermediate state

1 -> {1}
2 -> {0}
```

Finally, remove the last array element:

```
values = [2, 1]

1 -> {1}
2 -> {0}
```

Return `true`.

Notice that the remaining `1` is still present at index `1`. Only one occurrence was removed.

### Step 6: `getRandom()`

Now:

```
values = [2, 1]
```

Both indices are equally likely, so either value has probability \\(1/2\\).

## 6. All approaches: brute force to optimal

### Approach 1: A list only

The simplest solution is to store every occurrence in an `ArrayList`.

```
import java.util.ArrayList;
import java.util.List;
import java.util.Random;

class RandomizedCollectionListOnly {

    private final List<Integer> values = new ArrayList<>();
    private final Random random = new Random();

    public boolean insert(int val) {
        /*
         * contains() determines whether val already exists.
         * This costs O(n) because the list may need to be scanned.
         */
        boolean wasAbsent = !values.contains(val);

        /*
         * Appending is amortized O(1).
         * Duplicates are stored as separate occurrences.
         */
        values.add(val);

        return wasAbsent;
    }

    public boolean remove(int val) {
        /*
         * indexOf() finds one occurrence in O(n).
         * It returns -1 when val is absent.
         */
        int index = values.indexOf(val);

        if (index == -1) {
            return false;
        }

        /*
         * Removing from the middle shifts subsequent elements.
         * Worst-case time is O(n).
         */
        values.remove(index);

        return true;
    }

    public int getRandom() {
        /*
         * Choosing a random array index correctly weights duplicates.
         * Time: O(1).
         */
        return values.get(random.nextInt(values.size()));
    }

    /*
     * Time:
     *   insert:    O(n) due to contains(), plus amortized O(1) append.
     *   remove:    O(n) for indexOf() and potentially O(n) shifting.
     *   getRandom: O(1).
     *
     * Space: O(n).
     *
     * Why it is insufficient:
     * insert() and remove() are not average O(1).
     * It is a useful baseline because the random-selection requirement
     * is already solved by storing every occurrence in a list.
     */
}
```

This approach is easy to implement, but it fails the required average \\(O(1)\\) performance for insertion and removal.

### Approach 2: List plus a map of counts

We could store the values in a list and use a map to count occurrences:

```
values = [10, 20, 10, 30]
counts = {10: 2, 20: 1, 30: 1}
```

The count map makes checking whether a value exists average \\(O(1)\\), but it does not tell us where to remove an occurrence from the list.

For example, removing `20` still requires finding its position, which costs \\(O(n)\\). Removing from the middle may also require shifting elements.

The missing information is the set of indices for each value. Replacing the count map with an index set solves the locating problem, and swapping with the last element solves the shifting problem.

### Approach 3: List plus map of index sets — optimal

This is the solution implemented above.

| Operation     | Data structure technique                 | Average time         |
| ------------- | ---------------------------------------- | -------------------- |
| `insert(val)` | Append to list; add index to set         | \\(O(1)\\) amortized |
| `remove(val)` | Swap with last; update sets; delete last | \\(O(1)\\)           |
| `getRandom()` | Select a random list index               | \\(O(1)\\)           |

The total space complexity is \\(O(n)\\), where \\(n\\) is the number of occurrences.

## 7. Edge cases to watch out for

### Edge case 1: Inserting a duplicate

```
insert(5) -> true
insert(5) -> false
```

After both operations:

```
values = [5, 5]
5 -> {0, 1}
```

Do not reject duplicate insertion. The boolean return value only indicates whether the value was previously absent.

### Edge case 2: Removing a missing value

```
values = [5, 5, 8]
remove(7) -> false
```

Neither data structure should change.

Always check whether the map contains the value before attempting to retrieve an index.

### Edge case 3: Removing the last array element

```
values = [5, 8, 10]
remove(10)
```

The element to remove is already at the end. Just remove its index from the corresponding set and delete the final array element.

No swap is needed.

### Edge case 4: Removing a value whose last occurrence is being deleted

```
values = [5, 8]
remove(5)
```

After removal:

```
values = [8]
8 -> {0}
```

The map must no longer contain the key `5`. Otherwise, future operations may mistakenly treat `5` as present.

### Edge case 5: The removed value equals the last value

```
values = [5, 8, 5]
```

Suppose we remove the `5` at index `0`.

The last `5` moves from index `2` to index `0`.

```
values = [5, 8]
5 -> {0}
8 -> {1}
```

The order of index-set updates is critical here. Remove the target index first, then the old last index, and then add the replacement index.

### Edge case 6: Negative and extreme integer values

The constraints allow values from \\(-2^{31}\\) through \\(2^{31}-1\\).

The algorithm works without modification because Java's `HashMap<Integer, ...>` supports negative integers and both integer extremes.

### Edge case 7: Random selection with duplicates

```
values = [7, 7, 7, 9]
```

The probability of `7` must be \\(3/4\\), and the probability of `9` must be \\(1/4\\).

Never select a random distinct key from `valueToIndices`. Select a random array index instead.

The interviewer is looking for two connected insights:

1. Randomness requires occurrence-level storage. The array naturally gives duplicates the correct probability.
2. Constant-time removal requires eliminating shifting. Swapping with the last element makes this possible, but the index sets must stay synchronized.

A good way to explain the design aloud:

> “I'll store every occurrence in an array so I can select a random element by index in constant time. I'll maintain a hash map from each value to a set of all its indices, so I can locate one occurrence in average constant time. To remove an occurrence without shifting elements, I'll replace it with the last array element, update the index sets, and delete the last slot.”

## 9. Interviewer follow-up questions and answers

Q1. Why do we need a set of indices instead of a single index?

A value can occur multiple times. A single index would lose information about its other occurrences. The set represents all of them and allows us to remove any one occurrence efficiently.

Q2. Why use a `HashSet<Integer>` instead of a `List<Integer>` for the indices?

We need to remove a specific index quickly. A hash set supports average \\(O(1)\\) removal by index and does not require maintaining order. Removing an arbitrary index from an `ArrayList` of indices could require shifting elements.

Q3. Why does swapping with the last element preserve correctness?

The collection is a multiset, so the order of elements does not matter. Replacing one occurrence with the last occurrence and removing the final slot preserves exactly the same remaining values and multiplicities.

Q4. Why is the random distribution correct?

Every occurrence occupies exactly one array position, and every position has probability \\(1/n\\). If a value appears \\(k\\) times, its probability is \\(k/n\\).

Q5. What if the last element has the same value as the element being removed?

Remove the target index from the set first, remove the old last index from that value's set, then add the target index back for the moved occurrence. This preserves the correct set of surviving positions.

Q6. Is the complexity worst-case \\(O(1)\\)?

No. The usual guarantee is average or expected \\(O(1)\\) for hash-map and hash-set operations, and amortized \\(O(1)\\) for array appends. A hash table can have worse worst-case behavior under collisions, and an array append can occasionally trigger resizing.

Q7. Can we use a `TreeSet` for the indices?

A `TreeSet` provides \\(O(\log n)\\) insertion and deletion, which would not meet the required average \\(O(1)\\) complexity.

Q8. What is the total auxiliary space complexity?

The array stores \\(n\\) occurrences, and the index sets collectively store \\(n\\) indices. The map also has one entry per distinct value. Total space is \\(O(n)\\).

Q9. What if the interviewer requires thread safety?

The shown implementation is not thread-safe. Concurrent insertions and removals could temporarily leave the array and index sets inconsistent. A thread-safe version would need to synchronize the compound operations, for example with a single lock around each public method.

Q10. How would you make `getRandom()` work on an empty collection?

The original problem guarantees a nonempty collection for every `getRandom()` call. For a general-purpose API, we could throw `NoSuchElementException` when the array is empty.

| Method            | Average time         | Extra space per call |

| Constructor       | \\(O(1)\\)           | \\(O(1)\\) initially |

| `remove(val)`     | \\(O(1)\\)           | \\(O(1)\\)           |
| `getRandom()`     | \\(O(1)\\)           | \\(O(1)\\)           |
| Entire collection | —                    | \\(O(n)\\)           |
