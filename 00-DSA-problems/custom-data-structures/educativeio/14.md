# LeetCode 895 — Maximum Frequency Stack

The key to solving this problem is understanding that we are not building a normal stack. We are building a stack that prioritizes frequency first and recency second.

A normal stack removes the most recently pushed element. A maximum frequency stack removes the element that appears most often. If multiple elements have the same frequency, it removes the one whose most recent occurrence is closest to the top.

The optimal solution uses two hash maps and a variable called `maxFreq`. Once you understand why we group elements by their frequency, the solution becomes much easier to derive.

## 0. Simplify the problem statement

We need to implement two operations:

- `push(val)`: Add the number to the data structure.
- `pop()`: Remove and return the number with the highest current frequency. If several numbers have that frequency, return the one most recently pushed among them.

Consider these operations:

```
push(5)
push(7)
push(5)
push(7)
push(4)
push(5)
```

The stack, from bottom to top, is:

```
Bottom                         Top
  5    7    5    7    4    5
```

The frequencies are:

| Value | Frequency | Most recent occurrence |
| ----- | --------- | ---------------------- |
| 5     | 3         | Last position          |
| 7     | 2         | Fourth position        |
| 4     | 1         | Fifth position         |

The first `pop()` returns `5`, because its frequency is 3.

After removing it, the frequencies become:

| Value | Frequency |
| ----- | --------- |
| 5     | 2         |
| 7     | 2         |
| 4     | 1         |

Now `5` and `7` tie at frequency 2. The second `pop()` returns `7`, because its most recent remaining occurrence is newer than the most recent remaining occurrence of `5`.

This is the critical observation:

Frequency determines priority. Recency breaks ties.

We must maintain both pieces of information efficiently.

## 1. Clarifying questions to ask the interviewer

Even when the problem statement is clear, these are useful questions to demonstrate your problem-solving approach.

1. Can `pop()` be called on an empty stack?

   The constraints guarantee at least one element exists before every `pop()`. Therefore, we do not need to define empty-stack behavior for this implementation.
2. Can values be negative or repeated?

   The given constraints allow values from `0` to \\(10^9\\). Repeated values are expected, and frequency counts must account for every occurrence.
3. What is the expected time complexity?

   The ideal solution should support both `push()` and `pop()` in \\(O(1)\\) average time. Recomputing frequencies or scanning all elements for every `pop()` would be too slow for the intended design.
4. Does recency refer to the most recent occurrence that has not already been removed?

   Yes. When an occurrence is popped, it no longer contributes to the stack or to that value's current frequency.
5. Can we use auxiliary data structures?

   Assuming yes, we can use hash maps and lists to track the values at each frequency.

## 2. Core intuition: How do we think of the optimal solution?

### Step 1: Identify why a normal stack is insufficient

A normal stack remembers insertion order:

```
push(5), push(7), push(5), push(7), push(4), push(5)

Normal stack pop() -> 5
```

That happens to be correct for the first pop, but imagine the next one. A normal stack would return `4`, whereas the problem requires `7`.

Therefore, simply storing every value in one stack cannot solve the problem directly.

### Step 2: Ask what information `pop()` needs

To return the correct element, we need to know:

1. The highest frequency currently present.
2. Which value at that frequency was most recently pushed.

We could calculate all frequencies and scan the stack every time, but that would cost \\(O(n)\\) per `pop()`.

Instead, we can maintain the information as elements arrive.

### Step 3: The surprising idea — group elements by frequency

Imagine maintaining a separate stack for each frequency.

- `freq[x]` tells us the current frequency of value `x`.
- `group[f]` contains values that reached frequency `f`, ordered by when they reached that frequency.
- `maxFreq` tells us the highest frequency currently present.

When we push a value, its frequency increases by one. We put the value on the stack corresponding to its new frequency.

When we pop, we take the top element from the stack for `maxFreq`.

Why does this work? Because the top of that frequency stack is exactly the most recently pushed value among the values that most recently reached that frequency.

Let's walk through it carefully.

### Step 4: Build the data structure step by step

Suppose we perform the six pushes from the example.

We'll represent `group[f]` as a stack whose rightmost value is its top.

Initial state

```
freq = {}
group = {}
maxFreq = 0
```

Operation 1: `push(5)`

`5` has frequency 1.

```
group[1] = [5]
freq[5] = 1
maxFreq = 1
```

Operation 2: `push(7)`

`7` also has frequency 1. It reached frequency 1 after `5`, so it goes on top of `group[1]`.

```
group[1] = [5, 7]    <- top is 7
freq[5] = 1
freq[7] = 1
maxFreq = 1
```

Operation 3: `push(5)`

`5` goes from frequency 1 to frequency 2. Put it on `group[2]`.

```
group[1] = [5, 7]
group[2] = [5]

freq[5] = 2
freq[7] = 1
maxFreq = 2
```

Operation 4: `push(7)`

`7` goes from frequency 1 to frequency 2.

```
group[1] = [5, 7]
group[2] = [5, 7]    <- top is 7

freq[5] = 2
freq[7] = 2
maxFreq = 2
```

Notice that `group[2]` is not a list of all values currently having frequency 2 in arbitrary order. Its order tells us which value reached frequency 2 most recently. Since `7` was pushed most recently, `7` is at the top.

Operation 5: `push(4)`

`4` has frequency 1.

```
group[1] = [5, 7, 4]
group[2] = [5, 7]

freq[5] = 2
freq[7] = 2
freq[4] = 1
maxFreq = 2
```

Even though `4` is the newest overall, its frequency is only 1. We must not pop it while frequency 2 exists.

Operation 6: `push(5)`

`5` goes from frequency 2 to frequency 3.

```
group[1] = [5, 7, 4]
group[2] = [5, 7]
group[3] = [5]

freq[5] = 3
freq[7] = 2
freq[4] = 1
maxFreq = 3
```

Now let's pop.

### Step 5: Understand `pop()` and why `maxFreq` decreases

First `pop()`

`maxFreq = 3`, so pop from `group[3]`.

```
group[3] = [5] -> []
```

Return `5`. Its frequency decreases from 3 to 2.

There are no more elements in `group[3]`, so decrement `maxFreq` to 2.

Second `pop()`

`maxFreq = 2`, so pop from `group[2]`.

```
group[2] = [5, 7] -> [5]
```

Return `7`. Its frequency decreases from 2 to 1.

`group[2]` is not empty, so `maxFreq` remains 2.

Third `pop()`

Pop from `group[2]` again.

```
group[2] = [5] -> []
```

Return `5`. Its frequency decreases from 2 to 1.

Now `group[2]` is empty, so `maxFreq` becomes 1.

Fourth `pop()`

Pop from `group[1]`, whose current contents are:

```
group[1] = [5, 7, 4]
```

The top is `4`, so return `4`.

This produces the required output:

```
5, 7, 5, 4
```

The important thing to notice is that we never scan all values to find the most frequent one. `maxFreq` tells us exactly which stack to use, and that stack's top tells us exactly which value to remove.

### Step 6: Why does the frequency stack preserve the correct tie-breaking order?

Suppose `5` and `7` both have frequency 2.

```
group[2] = [5, 7]
                 ^
                 top
```

This means `7` most recently reached frequency 2.

When `7` is popped, its frequency becomes 1. Its next occurrence is not deleted from `group[2]` because it is already at the top and has just been removed from that stack. The remaining `5` is now the correct choice for frequency 2.

The frequency stacks store frequency transitions, not every occurrence of each value. Each `push(x)` creates exactly one entry in `group[f]`, where `f` is the new frequency of `x`.

This is why we don't need to sort values by frequency or keep timestamps in the optimal solution.

## 3. Data structure design

We need only three fields:

```
Map<Integer, Integer> frequency;
Map<Integer, Deque<Integer>> group;
int maxFreq;
```

Their responsibilities are different:

| Field       | Question it answers                                     |
| ----------- | ------------------------------------------------------- |
| `frequency` | How many times does this value currently occur?         |
| `group`     | Which value should be popped at a particular frequency? |
| `maxFreq`   | What is the highest frequency currently present?        |

The algorithm follows two simple rules:

- On `push(x)`, increment `frequency[x]`, push `x` onto `group[newFrequency]`, and update `maxFreq`.
- On `pop()`, pop from `group[maxFreq]`, decrement the value's frequency, and decrement `maxFreq` only if its group becomes empty.

## 4. All solutions — Java 24

### Solution 1: Brute force — one list and frequency counting

The simplest approach is to store all currently present elements in insertion order. For each `pop()`, count frequencies and scan the list from right to left to find the most frequent value, breaking ties in favor of the newest occurrence.

This is straightforward, but `pop()` costs \\(O(n)\\), where \\(n\\) is the number of elements currently in the structure.

```
import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

class FreqStackBruteForce {

    // Stores every currently present occurrence, from oldest to newest.
    private final List<Integer> elements = new ArrayList<>();

    public void push(int val) {
        // Appending preserves the insertion order needed for tie-breaking.
        elements.add(val);
    }

    public int pop() {
        Map<Integer, Integer> frequency = new HashMap<>();

        // First pass: count the frequency of every value currently present.
        for (int value : elements) {
            frequency.merge(value, 1, Integer::sum);
        }

        int bestValue = -1;
        int bestFrequency = 0;

        // Second pass: scan from newest to oldest.
        // Because we scan backward, the first value we encounter at a
        // particular frequency is the newest occurrence of that value.
        for (int i = elements.size() - 1; i >= 0; i--) {
            int value = elements.get(i);
            int currentFrequency = frequency.get(value);

            // Strictly greater is important:
            // if frequencies tie, keep the first value encountered while
            // scanning backward, since it is the most recent candidate.
            if (currentFrequency > bestFrequency) {
                bestFrequency = currentFrequency;
                bestValue = value;
            }
        }

        // Remove the newest occurrence of the chosen value.
        // The chosen value may not be at the end of the list, so removing
        // it also shifts subsequent elements and costs O(n).
        for (int i = elements.size() - 1; i >= 0; i--) {
            if (elements.get(i) == bestValue) {
                elements.remove(i);
                break;
            }
        }

        return bestValue;
    }

    /*
     * Time complexity:
     *   push: O(1) amortized for ArrayList append.
     *   pop:  O(n), where n is the number of current elements.
     *         Counting is O(n), scanning is O(n), and removal is O(n).
     *
     * Space complexity:
     *   O(n) for the element list and O(d) temporary space for the
     *   frequency map, where d is the number of distinct values.
     *   Overall auxiliary storage is O(n).
     *
     * This solution is useful as a baseline because its correctness is
     * easy to reason about, but repeated scans make it less efficient.
     */
}
```

### Solution 2: Optimal — frequency groups

This is the intended solution. Instead of rediscovering frequencies during each `pop()`, we maintain frequency information incrementally.

```
import java.util.ArrayDeque;
import java.util.Deque;
import java.util.HashMap;
import java.util.Map;

class FreqStack {

    // frequency.get(x) = the number of occurrences of x currently present.
    private final Map<Integer, Integer> frequency = new HashMap<>();

    // group.get(f) is a stack of values that have most recently reached
    // frequency f and have not yet been popped from that frequency group.
    //
    // The top of group[f] is the correct tie-break winner among values
    // available at frequency f.
    private final Map<Integer, Deque<Integer>> group = new HashMap<>();

    // Highest frequency currently present in the structure.
    // This lets pop() select the correct frequency group immediately.
    private int maxFreq = 0;

    public FreqStack() {
        // HashMap and maxFreq are already initialized to empty/zero states.
    }

    public void push(int val) {
        // Step 1: increase the value's current frequency.
        // A previously unseen value has frequency zero, so its new
        // frequency becomes one.
        int newFrequency = frequency.merge(val, 1, Integer::sum);

        // Step 2: record that val has just reached newFrequency.
        // Pushing onto this stack preserves recency among values at
        // this frequency. The most recent transition remains on top.
        group.computeIfAbsent(newFrequency, ignored -> new ArrayDeque<>())
             .push(val);

        // Step 3: update the highest frequency.
        // A push increases one value's frequency by exactly one, so the
        // maximum can increase by at most one.
        maxFreq = Math.max(maxFreq, newFrequency);
    }

    public int pop() {
        // Step 1: the most frequent value must be at the top of the
        // stack corresponding to maxFreq.
        Deque<Integer> candidates = group.get(maxFreq);
        int val = candidates.pop();

        // Step 2: remove this occurrence from the frequency count.
        // This occurrence had frequency maxFreq immediately before pop.
        int newFrequency = frequency.get(val) - 1;

        if (newFrequency == 0) {
            // The value no longer exists in the structure.
            frequency.remove(val);
        } else {
            // Other occurrences remain, now at the lower frequency.
            frequency.put(val, newFrequency);
        }

        // Step 3: reduce maxFreq only when its entire group becomes empty.
        //
        // Why is this safe?
        // If group[maxFreq] still has an entry, another value still
        // qualifies at maxFreq. Otherwise, no value can have that
        // frequency anymore, so the maximum must decrease by one.
        if (candidates.isEmpty()) {
            group.remove(maxFreq);
            maxFreq--;
        }

        return val;
    }

    /*
     * TIME COMPLEXITY:
     *
     * push: O(1) average.
     *   A constant number of HashMap operations and one stack push.
     *   HashMap operations are O(1) on average.
     *
     * pop: O(1) average.
     *   One stack pop, a constant number of HashMap operations, and
     *   at most one decrement of maxFreq.
     *
     * SPACE COMPLEXITY:
     *
     * O(n), where n is the total number of currently stored occurrences.
     * The frequency map uses O(d) space for d distinct values.
     * The frequency-group stacks collectively hold one entry per
     * currently stored occurrence, so their total size is O(n).
     *
     * This achieves the intended O(1) average time for both operations.
     */
}
```

## 5. Edge cases to watch out for

These cases are particularly useful in an interview because they test whether we understand the invariants rather than just memorizing the implementation.

### Case 1: Only one element

```
push(10)
pop() -> 10
```

`maxFreq` goes from 0 to 1 and then back to 0. Both maps become logically empty.

### Case 2: All values are distinct

```
push(1)
push(2)
push(3)

pop() -> 3
pop() -> 2
pop() -> 1
```

Every value has frequency 1. They share `group[1]`, so its stack naturally preserves the required LIFO behavior.

### Case 3: One value is repeatedly pushed

```
push(5)
push(5)
push(5)

pop() -> 5
pop() -> 5
pop() -> 5
```

`group[1]`, `group[2]`, and `group[3]` each receive an entry for `5`. Each pop removes the entry at the current maximum frequency.

### Case 4: Multiple values tie

```
push(5)
push(7)
push(5)
push(7)

pop() -> 7
```

Both values have frequency 2, but `7` reached frequency 2 later. It is on top of `group[2]`.

### Case 5: The maximum frequency decreases

```
push(5)
push(5)
push(5)

pop() -> 5   // maxFreq becomes 2
pop() -> 5   // maxFreq becomes 1
pop() -> 5   // maxFreq becomes 0
```

Common bug: Decreasing `maxFreq` after every pop.

That is incorrect because the maximum frequency may still be present after a pop. Decrement `maxFreq` only when `group[maxFreq]` becomes empty.

### Case 6: A value disappears completely

```
push(5)
pop() -> 5
```

Remove `5` from the frequency map when its frequency reaches zero. Otherwise, stale frequency entries could incorrectly suggest that the value is still present.

### Case 7: The same value reappears after disappearing

```
push(5)
pop() -> 5

push(5)
pop() -> 5
```

The value starts again at frequency 1. Since the old frequency groups were emptied as the value was popped, the data structure can handle this naturally.

## 6. Interview follow-up questions and answers

Q1. Why do we need both `frequency` and `group`?

`frequency` answers how often a value occurs. `group` answers which value should be removed at a given frequency. One map alone does not efficiently answer both questions while preserving recency.

Q2. Why is `maxFreq` necessary?

Without it, `pop()` would need to search for the highest nonempty frequency group. Tracking it during `push()` and `pop()` avoids that scan.

Q3. Why use `Deque<Integer>` instead of `Stack<Integer>`?

`ArrayDeque` provides efficient stack operations through `push()` and `pop()` and is generally preferred over the legacy `Stack` class.

Q4. Why does `pop()` not search for the most recent occurrence in the original stack?

Because the grouped stacks already encode the necessary order. The top of `group[maxFreq]` is the correct answer, so no global search is needed.

Q5. Is the time complexity strictly \\(O(1)\\)?

It is \\(O(1)\\) average time per operation under the usual hash-map complexity assumptions. A hash map operation can theoretically take longer in collision-heavy cases, so we generally state average-case \\(O(1)\\).

Q6. What is the invariant that makes this solution correct?

At every point:

- `frequency[x]` equals the current number of occurrences of `x`.
- Each push records a transition into the corresponding frequency group.
- The top of `group[f]` identifies the most recent eligible value at frequency `f`.
- `maxFreq` is the highest frequency that currently has any eligible values.

These invariants guarantee that every `pop()` returns the most frequent value and correctly breaks ties by recency.

## 7. How to derive this solution in an interview

Rather than memorizing the code, follow this reasoning sequence:

1. A normal stack solves recency but ignores frequency.
2. A frequency map tells us how often each value occurs, but finding the maximum still requires a scan.
3. A max-heap could find the maximum frequency, but maintaining recency and updating entries adds complexity.
4. Grouping values by frequency lets us combine both requirements: the highest frequency selects the group, and the stack order within that group resolves ties.
5. Tracking `maxFreq` removes the need to search for the highest frequency.

The final mental model is:

```
push(x):
    Increase x's frequency.
    Push x into the stack for its new frequency.
    Update maxFreq.

pop():
    Pop from the stack for maxFreq.
    Decrease the chosen value's frequency.
    If that stack is empty, decrease maxFreq.
    Return the chosen value.
```

The main interview takeaway: Whenever a problem asks for the most frequent item and uses recency to break ties, consider grouping items by frequency and maintaining a stack within each group. This converts a potentially expensive search into constant-time average operations.










Your implementation is very close to the optimal solution. The data structures and overall approach are correct, but there is one important bug in `pop()`: you calculate the popped value's new frequency using `this.maxFreq - 1` instead of using that specific value's current frequency.

Let's understand why this matters.

## 1. The bug in your code

Your code:

```
int val = candidates.pollFirst();
int newFreq = this.maxFreq - 1;
```

This assumes that the popped value's frequency is always equal to `maxFreq`.

That assumption is true at the moment it is popped from `freqToNums[maxFreq]` in this problem's frequency-group design, so `maxFreq - 1` does give the correct new frequency for that particular value. However, using the value's recorded frequency is clearer and more robust.

The bigger issue is your choice of deque operations: `addLast()` and `pollFirst()` are actually consistent with each other, so they are not a bug. They implement FIFO from the front, which means they remove the oldest value that reached a frequency, rather than the newest.

For this problem, that breaks tie-breaking.

## 2. Why `addLast()` and `pollFirst()` fail

Consider:

```
push(5)
push(7)
push(5)
push(7)
```

Both `5` and `7` have frequency 2. Since `7` reached frequency 2 most recently, `pop()` must return `7`.

Your `freqToNums[2]` deque becomes:

```
addLast(5) -> [5]
addLast(7) -> [5, 7]
```

But `pollFirst()` returns `5`, which is incorrect.

You should use either:

- `addLast()` with `pollLast()`, or
- `addFirst()` with `pollFirst()`.

Both combinations implement LIFO order within each frequency group.

## 3. Corrected Java solution

```
import java.util.*;

class FreqStack {

    private final Map<Integer, Integer> numToFreq;
    private final Map<Integer, Deque<Integer>> freqToNums;
    private int maxFreq;

    public FreqStack() {
        numToFreq = new HashMap<>();
        freqToNums = new HashMap<>();
        maxFreq = 0;
    }

    public void push(int val) {
        // Increase the value's current frequency.
        int newFreq = numToFreq.merge(val, 1, Integer::sum);

        // Record that this value has just reached newFreq.
        // addLast() makes the newest value the last element.
        freqToNums.computeIfAbsent(newFreq, k -> new ArrayDeque<>())
                  .addLast(val);

        // The maximum frequency can increase by at most one per push.
        maxFreq = Math.max(maxFreq, newFreq);
    }

    public int pop() {
        // The top frequency group contains the most frequent candidates.
        Deque<Integer> candidates = freqToNums.get(maxFreq);

        // Remove the most recently added candidate at this frequency.
        int val = candidates.pollLast();

        // Decrease this particular value's frequency.
        int newFreq = numToFreq.get(val) - 1;

        if (newFreq == 0) {
            // No occurrences of this value remain.
            numToFreq.remove(val);
        } else {
            numToFreq.put(val, newFreq);
        }

        // If this frequency group is empty, the maximum frequency drops.
        if (candidates.isEmpty()) {
            freqToNums.remove(maxFreq);
            maxFreq--;
        }

        return val;
    }
}
```

## 4. Complexity

- `push()` — \\(O(1)\\) average time.
- `pop()` — \\(O(1)\\) average time.
- Space — \\(O(n)\\), where \\(n\\) is the number of stored occurrences.

The essential fix is changing `pollFirst()` to `pollLast()` while keeping `addLast()`. Also, calculating `newFreq` from `numToFreq.get(val)` makes the frequency update more explicit and easier to reason about.
