# Max Stack — Java 24 Interview Solution

## 0. Simplify the problem statement

We need to design a stack that supports normal stack operations and maximum-element operations.

A regular stack follows LIFO (Last In, First Out). A Max Stack adds the ability to find and remove the maximum element, even when that element is not at the top.

For example:

```
push(5)
push(1)
push(5)

Stack (bottom → top): [5, 1, 5]

top()      → 5
peekMax()  → 5
popMax()   → 5    // Removes the topmost maximum
top()      → 1
pop()      → 1
peekMax()  → 5
```

The important distinction is that `pop()` removes the top element, while `popMax()` removes the topmost occurrence of the maximum element, wherever it appears in the stack.

## 1. Clarifying questions to ask the interviewer

1. Can duplicate values exist? Yes, the statement allows duplicates. We must remove the most recently added occurrence when multiple maximum values exist.
2. Can we assume removal and peek operations are called only on a non-empty stack? Yes. This means we do not need to define exception or sentinel behavior for empty-stack operations.
3. Are there any constraints on the number of operations? At most 100 calls are allowed. This makes a simple implementation with linear-time `popMax()` a reasonable choice, although we should also understand more efficient alternatives.
4. Do we need every operation to run in constant time? The statement does not require this. We should explain the time-space trade-offs and choose an implementation appropriate for the constraints.

## 2. Core idea and mental model

There are three useful approaches, from simplest to more efficient.

### Approach 1: Use an `ArrayList`

Treat the end of the list as the top of the stack.

- `push()` appends to the list.
- `pop()` removes the last element.
- `top()` reads the last element.
- `peekMax()` scans the entire list.
- `popMax()` scans for the maximum, remembering its last occurrence, and removes it.

This is the simplest approach and a good starting point in an interview.

### Approach 2: Use two stacks

Maintain:

- `stack`: all actual elements.
- `maxStack`: the maximum value at each corresponding position.

When pushing a value, push the larger of that value and the previous maximum onto `maxStack`. When popping, remove from both stacks.

This makes `peekMax()` constant time, but `popMax()` still needs to search through the stack. To preserve the order of the remaining elements, we temporarily remove elements above the maximum and then restore them.

### Approach 3: Doubly linked list + `TreeMap` — efficient general-purpose solution

Use two data structures together:

- A doubly linked list stores elements in stack order and allows removal of any known node in \\(O(1)\\) time.
- A `TreeMap` maps each integer value to a collection of nodes containing that value. Its keys remain sorted, so the maximum value is available through `lastKey()`.

For duplicate maximum values, keep their nodes in a deque in insertion order. The last node in that deque is the most recently pushed occurrence, which is exactly the node `popMax()` must remove.

## 3. Edge cases to watch out for

- Duplicate maximum values: `popMax()` must remove the topmost occurrence.
- Maximum is at the top: `popMax()` should behave like `pop()`.
- Maximum is at the bottom: remove it without changing the relative order of the other elements.
- All elements are equal: remove only the topmost occurrence of that value.
- Negative numbers: the maximum must be determined by numeric comparison, not assumptions about positive values.
- One element: all supported operations must work correctly.
- Removing the last occurrence of a value: delete that value's entry from the auxiliary map so stale entries cannot affect future maximum queries.

The given constraints guarantee non-empty-stack operations, so empty-stack error handling is outside the required behavior.

## 4. Solution 1 — Brute force using `ArrayList`

Complexity: simple implementation; linear maximum search.

```
import java.util.ArrayList;
import java.util.List;

public class MaxStackBruteForce {

    // Mental model:
    // The end of the ArrayList represents the top of the stack.
    // This avoids the overhead of manually implementing stack nodes.
    private final List<Integer> stack = new ArrayList<>();

    // Constructor: an empty list represents an empty stack.
    // Time: O(1). Space: O(1) initially, excluding backing-array allocation.
    public MaxStackBruteForce() {
    }

    // Push x onto the top of the stack.
    // Time: O(1) amortized; occasionally O(n) when the backing array grows.
    // Space: O(1) amortized per operation, excluding occasional resizing.
    public void push(int x) {
        stack.add(x);
    }

    // Remove and return the top element.
    // ArrayList removes its final element without shifting other elements.
    // Time: O(1). Auxiliary space: O(1).
    public int pop() {
        return stack.remove(stack.size() - 1);
    }

    // Return the top element without removing it.
    // The last valid index is size - 1.
    // Time: O(1). Auxiliary space: O(1).
    public int top() {
        return stack.get(stack.size() - 1);
    }

    // Find the maximum by scanning every element.
    // Integer.MIN_VALUE is a safe initial value because the stack is non-empty
    // and every int value is at least Integer.MIN_VALUE.
    // Time: O(n), where n is the number of elements.
    // Auxiliary space: O(1).
    public int peekMax() {
        int max = Integer.MIN_VALUE;

        for (int value : stack) {
            max = Math.max(max, value);
        }

        return max;
    }

    // Find the maximum's LAST occurrence, not its first occurrence.
    // Scanning from top to bottom makes the first match the topmost maximum.
    // Removing by index shifts the elements above it one position left.
    // Time: O(n) for searching and O(n) worst case for shifting.
    // Auxiliary space: O(1).
    public int popMax() {
        int max = peekMax();

        for (int i = stack.size() - 1; i >= 0; i--) {
            if (stack.get(i) == max) {
                stack.remove(i);
                return max;
            }
        }

        // Unreachable under the stated non-empty-stack constraints.
        throw new IllegalStateException("Stack unexpectedly empty");
    }
}
```

### Complexity summary

Let \\(n\\) be the number of elements in the stack.

| Operation | Time                 | Extra space          |
| --------- | -------------------- | -------------------- |
| `push`    | \\(O(1)\\) amortized | \\(O(1)\\) amortized |
| `pop`     | \\(O(1)\\)           | \\(O(1)\\)           |
| `top`     | \\(O(1)\\)           | \\(O(1)\\)           |
| `peekMax` | \\(O(n)\\)           | \\(O(1)\\)           |
| `popMax`  | \\(O(n)\\)           | \\(O(1)\\)           |

This is easy to implement and works well for the stated maximum of 100 operations.

## 5. Solution 2 — Two stacks

The key insight is that we can precompute the maximum at every depth. This eliminates the scan required by `peekMax()`.

For example, if the stack contains `[5, 1, 7, 3]`, the auxiliary maximum stack contains `[5, 5, 7, 7]`. Its top always holds the maximum of the entire stack.

For `popMax()`, temporarily move elements from the main stack to a buffer until the first maximum is found. Then restore the buffered elements in their original order.

```
import java.util.ArrayDeque;
import java.util.Deque;

public class MaxStackTwoStacks {

    // Main stack: holds the actual elements.
    private final Deque<Integer> stack = new ArrayDeque<>();

    // maxStack.getFirst() corresponds to stack.getFirst().
    // Each entry is the maximum value up to that depth.
    private final Deque<Integer> maxStack = new ArrayDeque<>();

    // Constructor: both stacks start empty.
    // Time: O(1). Initial auxiliary space: O(1).
    public MaxStackTwoStacks() {
    }

    // Push x and update the running maximum at this depth.
    // We store duplicate maxima too, so both stacks remain the same size.
    // Time: O(1). Auxiliary space: O(1) per pushed element.
    public void push(int x) {
        stack.push(x);

        int currentMax = maxStack.isEmpty()
                ? x
                : Math.max(x, maxStack.peek());

        maxStack.push(currentMax);
    }

    // Remove from both stacks to preserve their depth alignment.
    // Time: O(1). Auxiliary space: O(1).
    public int pop() {
        maxStack.pop();
        return stack.pop();
    }

    // Read the main stack's top without removing it.
    // Time: O(1). Auxiliary space: O(1).
    public int top() {
        return stack.peek();
    }

    // The top of maxStack is the maximum of all elements.
    // Time: O(1). Auxiliary space: O(1).
    public int peekMax() {
        return maxStack.peek();
    }

    // Remove the topmost occurrence of the maximum.
    // Since the main stack is top-first, the first maximum encountered
    // is the required occurrence.
    //
    // A temporary stack holds the elements above that maximum.
    // We pop normally so maxStack stays synchronized, then restore the
    // buffered elements through push(), rebuilding their running maxima.
    //
    // Time: O(n) worst case; each element above the maximum is moved twice.
    // Auxiliary space: O(n) worst case for the temporary stack.
    public int popMax() {
        int max = peekMax();
        Deque<Integer> buffer = new ArrayDeque<>();

        while (top() != max) {
            buffer.push(pop());
        }

        // Remove the topmost maximum.
        pop();

        // Restore the elements above it in their original order.
        while (!buffer.isEmpty()) {
            push(buffer.pop());
        }

        return max;
    }
}
```

### Complexity summary

| Operation | Time       | Extra space            |
| --------- | ---------- | ---------------------- |
| `push`    | \\(O(1)\\) | \\(O(1)\\) per element |
| `pop`     | \\(O(1)\\) | \\(O(1)\\)             |
| `top`     | \\(O(1)\\) | \\(O(1)\\)             |
| `peekMax` | \\(O(1)\\) | \\(O(1)\\)             |
| `popMax`  | \\(O(n)\\) | \\(O(n)\\) temporarily |

The two persistent stacks use \\(O(n)\\) space. The temporary buffer used by `popMax()` can require another \\(O(n)\\) space.

Interview trade-off: This is useful when `peekMax()` is frequent, but it is not the most efficient general solution when `popMax()` is also frequent.

## 6. Solution 3 — Doubly linked list + `TreeMap` (efficient `popMax`)

This approach avoids moving elements above the maximum.

The linked list stores elements from bottom to top. Each node has `prev` and `next` pointers, so we can unlink any node in \\(O(1)\\) time once we know its reference.

The `TreeMap` stores each value's nodes in insertion order:

```
Stack order (bottom → top):

HEAD ⇄ [5] ⇄ [1] ⇄ [5] ⇄ [3] ⇄ TAIL

TreeMap:
1 → [node(1)]
3 → [node(3)]
5 → [node(5, older), node(5, newer)]
```

If `popMax()` is called here, `TreeMap.lastKey()` returns `5`, and the last node in that value's deque is the newer `5`. We remove that node directly from the linked list.

```
import java.util.ArrayDeque;
import java.util.Deque;
import java.util.Map;
import java.util.TreeMap;

public class MaxStack {

    // Each node represents one occurrence of a value.
    // A node is a reference to a specific occurrence, not just its value.
    private static final class Node {
        final int value;
        Node prev;
        Node next;

        Node(int value) {
            this.value = value;
        }
    }

    // Doubly linked list sentinels simplify insertion and removal:
    //
    // head <-> bottom ... top <-> tail
    //
    // The actual elements lie between head and tail.
    private final Node head = new Node(0);
    private final Node tail = new Node(0);

    // Keys are sorted, so lastKey() identifies the maximum value.
    //
    // For each value, its deque stores nodes in insertion order.
    // The last node is the most recently pushed remaining occurrence.
    private final TreeMap<Integer, Deque<Node>> nodesByValue =
            new TreeMap<>();

    // Constructor: connect the two sentinels.
    // Time: O(1). Auxiliary space: O(1).
    public MaxStack() {
        head.next = tail;
        tail.prev = head;
    }

    // Insert a new node immediately before tail, which is the stack top.
    // Also append the node to its value's occurrence deque.
    //
    // TreeMap insertion takes O(log d), where d is the number of distinct
    // values; linked-list insertion and deque insertion take O(1).
    // Total time: O(log d). Auxiliary space: O(1) per new element,
    // with O(n) total space for all nodes and index entries.
    public void push(int x) {
        Node node = new Node(x);

        // Insert at the top of the stack.
        node.prev = tail.prev;
        node.next = tail;
        tail.prev.next = node;
        tail.prev = node;

        // Record this occurrence after all earlier occurrences of x.
        nodesByValue
                .computeIfAbsent(x, ignored -> new ArrayDeque<>())
                .addLast(node);
    }

    // Remove and return the current top.
    //
    // The top node is also the newest remaining occurrence of its value,
    // so it must be the last node in that value's deque.
    //
    // Linked-list unlinking and deque removal are O(1); TreeMap removal
    // of a key, when its final occurrence disappears, is O(log d).
    // Total time: O(log d) worst case.
    // Auxiliary space: O(1), excluding internal map rebalancing.
    public int pop() {
        Node node = tail.prev;
        removeNode(node);
        return node.value;
    }

    // Read the node immediately before tail.
    // Time: O(1). Auxiliary space: O(1).
    public int top() {
        return tail.prev.value;
    }

    // Return the greatest key in the sorted map.
    // TreeMap.lastKey() takes O(log d) in the general implementation.
    // Time: O(log d). Auxiliary space: O(1).
    public int peekMax() {
        return nodesByValue.lastKey();
    }

    // Remove the most recently pushed occurrence of the maximum value.
    //
    // 1. Find the greatest value through lastKey().
    // 2. Get the newest node for that value through peekLast().
    // 3. Remove that node from both data structures.
    //
    // Unlike the two-stack approach, no elements above the maximum
    // need to be moved or restored.
    //
    // Time: O(log d) worst case.
    // Auxiliary space: O(1) beyond the existing data structures.
    public int popMax() {
        Map.Entry<Integer, Deque<Node>> maxEntry =
                nodesByValue.lastEntry();

        int maxValue = maxEntry.getKey();
        Node node = maxEntry.getValue().peekLast();

        removeNode(node);

        return maxValue;
    }

    // Remove a known node from both the linked list and the TreeMap index.
    //
    // Because the node is already known, linked-list unlinking takes O(1).
    // The node must be the last occurrence of its value:
    // - pop() removes the global top, which is the newest occurrence
    //   of its value.
    // - popMax() explicitly selects the newest occurrence of the max.
    //
    // Thus pollLast() removes the correct node from the occurrence deque.
    // If no occurrence remains, remove the key from the TreeMap.
    //
    // Time: O(log d) worst case because removing a TreeMap key can rebalance
    // the tree. The list and deque operations themselves are O(1).
    // Auxiliary space: O(1).
    private void removeNode(Node node) {
        // Unlink the node from the stack's order.
        node.prev.next = node.next;
        node.next.prev = node.prev;

        // Remove this occurrence from its value's index.
        Deque<Node> occurrences = nodesByValue.get(node.value);
        occurrences.pollLast();

        // Do not retain keys for values that no longer exist in the stack.
        if (occurrences.isEmpty()) {
            nodesByValue.remove(node.value);
        }
    }
}
```

### Complexity summary

Let \\(n\\) be the total number of elements and \\(d\\) the number of distinct values, where \\(d \le n\\).

| Operation   | Time                       | Extra space per operation |
| ----------- | -------------------------- | ------------------------- |
| Constructor | \\(O(1)\\)                 | \\(O(1)\\)                |
| `push`      | \\(O(\log d)\\)            | \\(O(1)\\)                |
| `pop`       | \\(O(\log d)\\) worst case | \\(O(1)\\)                |
| `top`       | \\(O(1)\\)                 | \\(O(1)\\)                |
| `peekMax`   | \\(O(\log d)\\)            | \\(O(1)\\)                |
| `popMax`    | \\(O(\log d)\\) worst case | \\(O(1)\\)                |

Overall space is \\(O(n)\\), because every element has one linked-list node and one reference in its value's deque. The `TreeMap` also stores up to \\(d\\) distinct keys.

A subtle point: although `peekMax()` and `popMax()` are often described as \\(O(\log d)\\) here, `TreeMap.lastKey()` and `lastEntry()` are logarithmic in Java's general `TreeMap` complexity model. The key benefit is that we avoid the \\(O(n)\\) search and restoration work required by the two-stack solution.

## 7. Interviewer follow-up questions and answers

### Q1. Which implementation would you choose for this problem?

Answer: Given the constraint of at most 100 operations, I would start with the `ArrayList` implementation because it is easy to explain, implement, and verify. If the interviewer expects efficient `popMax()` for a larger workload, I would use the doubly linked list and `TreeMap` combination.

### Q2. Why is a doubly linked list better than an array for `popMax()`?

Answer: An array or `ArrayList` must shift elements after removing an element from the middle, which costs \\(O(n)\\). A doubly linked list can unlink a known node in \\(O(1)\\) time because it has direct references to both neighboring nodes.

The challenge is finding that node efficiently. The `TreeMap` and per-value deque provide that lookup.

### Q3. Why use a `TreeMap` instead of a `HashMap`?

Answer: A `HashMap` supports efficient lookup by a known value, but it does not maintain sorted keys. Finding the maximum would require scanning all distinct keys, taking \\(O(d)\\) time.

A `TreeMap` maintains keys in sorted order, allowing us to retrieve the maximum with `lastKey()` or `lastEntry()` in \\(O(\log d)\\) time.

### Q4. Why store a deque of nodes for each value instead of one node?

Answer: The stack can contain duplicate values, and each occurrence corresponds to a different position. We need the most recently added occurrence of the maximum, not just any node containing that value.

The deque preserves the order of occurrences, so `peekLast()` gives the correct node.

### Q5. Could we make every operation \\(O(1)\\)?

Answer: Yes, under the given bounded integer domain, we can replace the `TreeMap` with a fixed-size array of deques indexed by value. Since each value is between \\(-1000\\) and \\(1000\\), we can translate a value \\(x\\) to index \\(x + 1000\\).

Maintain a `currentMax` variable as well as the linked list and occurrence deques. Push and pop can update the maximum efficiently, while `popMax()` can remove the indexed node in \\(O(1)\\). If the maximum value disappears, finding the next maximum requires scanning the bounded value range, which is \\(O(2001)=O(1)\\) with respect to the number of stack elements.

This trades generality for constant-time operations under the fixed value constraints.

### Q6. What happens when `popMax()` removes the last occurrence of the maximum?

Answer: We remove that value's key from the `TreeMap`. The next call to `lastKey()` returns the next-largest value that remains. If the removed node was not the last occurrence of that value, the key stays in the map.

### Q7. What is the most important correctness invariant?

Answer: The linked list must preserve the exact stack order, and each value's deque must contain precisely the remaining nodes of that value in insertion order. Every removal must update both structures consistently. This guarantees that the maximum is correct and duplicate handling always removes the topmost occurrence.

## 8. Final recommendation

- Best for a quick interview implementation: `ArrayList` — simplest code, but `peekMax()` and `popMax()` are \\(O(n)\\).
- Best for constant-time maximum lookup: Two stacks — `peekMax()` is \\(O(1)\\), but `popMax()` is \\(O(n)\\).
- Best general-purpose design for efficient arbitrary maximum removal: Doubly linked list + `TreeMap` — `popMax()` takes \\(O(\log d)\\) worst-case time without moving unrelated elements.

For a senior-level interview, I would explain the `ArrayList` solution first, identify why `popMax()` is the bottleneck, and then derive the doubly linked list + `TreeMap` solution. That progression demonstrates both implementation clarity and data-structure trade-off reasoning.
