# LFU Cache — Java 24 Interview Solution

## 0. Simplify the problem statement

We need to design a cache that stores at most `capacity` key-value pairs. Every key has a usage frequency, which determines how likely it is to be evicted.

The cache supports two operations:

- `get(key)`: Return the value if the key exists; otherwise, return `-1`. A successful `get` increases the key's frequency.
- `put(key, value)`: Insert a new key or update an existing key. An existing key's frequency increases even if its value is unchanged.
- When the cache is full and a new key is inserted, evict the key with the lowest frequency. If multiple keys share that frequency, evict the least recently used among them.

Both operations must run in average \\(O(1)\\) time.

### Example

Assume the cache has capacity `2`.

| Operation       | Cache contents (key: value, frequency) |
| --------------- | -------------------------------------- |
| `put(1, 10)`    | `1:10, freq=1`                         |
| `put(2, 20)`    | `1:10, freq=1`; `2:20, freq=1`         |
| `get(1)` → `10` | `1:10, freq=2`; `2:20, freq=1`         |
| `put(3, 30)`    | Evict key `2`; insert `3:30, freq=1`   |
| `get(1)` → `10` | Key `1` remains at frequency `3`       |
| `get(2)` → `-1` | Key `2` was evicted                    |

Key `2` is evicted when inserting key `3` because its frequency is lower than key `1`'s frequency. Notice that the new key `3` starts at frequency `1`.

## 1. Clarifying questions to ask the interviewer

1. Does updating an existing key increase its frequency? Yes, according to this problem statement. This matters because `put` is also a usage event.
2. Does a newly inserted key start at frequency zero or one? It starts at `1`, because inserting it requires a `put` operation.
3. How do we break ties between keys with the same frequency? Evict the least recently used key within that frequency.
4. What should happen when capacity is zero? No entries can be stored. `get` always returns `-1`, and `put` does nothing.
5. Can we assume average \\(O(1)\\) hash-map operations? Yes. This assumption is necessary for the expected complexity of the standard solution.

## 2. Core intuition: frequency buckets plus LRU lists

The key challenge is finding the eviction candidate without scanning all cached entries.

A simple `HashMap<key, frequency>` is insufficient because finding the minimum frequency would require scanning the map. A priority queue is also insufficient for strict \\(O(1)\\) operations because updates and removals typically take \\(O(\log n)\\).

The optimal design combines three structures:

1. `keyToNode` — a hash map from each key to its cache node. This enables direct access to entries.
2. `frequencyToList` — a hash map from each frequency to a doubly linked list of nodes with that frequency. Each list is ordered by recency: most recently used at the front, least recently used at the back.
3. `minFrequency` — the minimum frequency currently present in the cache. This lets us immediately locate the bucket from which to evict.

### Mental model

Think of the cache as groups of people arranged by how many times they have been used.

- Each group represents one frequency.
- Within each group, people stand in recency order.
- When a key is accessed, move it from its current group to the next frequency group and place it at the front.
- When eviction is needed, find the lowest-frequency group and remove the person at its back.

```
keyToNode
   |
   +--> key 1 --> Node(value=10, frequency=2)
   +--> key 3 --> Node(value=30, frequency=1)

frequencyToList

Frequency 1:  MRU <--> [key 3] <--> LRU
Frequency 2:  MRU <--> [key 1] <--> LRU

minFrequency = 1
```

When we evict, we remove the tail node from the list at `minFrequency`. The hash maps provide direct access to both the node and its frequency list, and the doubly linked list allows removal and insertion in constant time.

## 3. All solutions: brute force to optimal

We can approach this problem in three stages.

- Approach 1 — Brute force: Store entries in a map and scan every entry to find the eviction candidate. Simple, but operations can take \\(O(n)\\).
- Approach 2 — Ordered frequency groups: Use ordered maps and per-frequency recency lists. Easier to reason about, but ordered-map operations generally cost \\(O(\log n)\\).
- Approach 3 — Optimal: Use hash maps, doubly linked lists, and `minFrequency`. Both `get` and `put` achieve average \\(O(1)\\) time.

Here, \\(n\\) is the number of entries currently stored in the cache.

### Approach 1: Brute force — scan for the eviction candidate

The simplest implementation stores each entry's value, frequency, and last-used timestamp. When eviction is required, scan every entry to find the lowest frequency and, among ties, the oldest timestamp.

```
import java.util.HashMap;
import java.util.Map;

class LFUCacheBruteForce {

    // Every cache entry carries enough information to determine eviction.
    private record Entry(int value, int frequency, long lastUsed) {}

    private final int capacity;
    private final Map<Integer, Entry> entries = new HashMap<>();
    private long clock;

    public LFUCacheBruteForce(int capacity) {
        // Zero capacity is valid: the cache simply never stores entries.
        this.capacity = capacity;
    }

    public int get(int key) {
        Entry entry = entries.get(key);

        // A missing key does not affect any frequency.
        if (entry == null) {
            return -1;
        }

        // A successful get increases frequency and refreshes recency.
        entries.put(key,
                new Entry(entry.value(), entry.frequency() + 1, ++clock));

        return entry.value();
    }

    public void put(int key, int value) {
        if (capacity == 0) {
            return;
        }

        Entry existing = entries.get(key);

        if (existing != null) {
            // Updating an existing key counts as usage, even when its
            // new value equals the old value.
            entries.put(key,
                    new Entry(value, existing.frequency() + 1, ++clock));
            return;
        }

        if (entries.size() == capacity) {
            int victimKey = -1;
            int lowestFrequency = Integer.MAX_VALUE;
            long oldestTimestamp = Long.MAX_VALUE;

            // BRUTE-FORCE BOTTLENECK:
            // We must inspect every entry to discover the minimum frequency.
            // Timestamp breaks ties by choosing the least recently used key.
            for (var entry : entries.entrySet()) {
                int keyToCheck = entry.getKey();
                Entry candidate = entry.getValue();

                if (candidate.frequency() < lowestFrequency
                        || (candidate.frequency() == lowestFrequency
                        && candidate.lastUsed() < oldestTimestamp)) {
                    victimKey = keyToCheck;
                    lowestFrequency = candidate.frequency();
                    oldestTimestamp = candidate.lastUsed();
                }
            }

            entries.remove(victimKey);
        }

        // Every new entry starts at frequency 1.
        entries.put(key, new Entry(value, 1, ++clock));
    }

    /*
     * TIME:
     * get: O(1) average, because it performs a constant number of hash-map
     * operations and creates one record.
     *
     * put without eviction: O(1) average.
     * put with eviction: O(n) because it scans all cached entries.
     *
     * SPACE: O(n) for the map and its entries.
     *
     * VERDICT: Correct and simple, but does not meet the requirement that
     * both operations run in average O(1) time.
     */
}
```

### Approach 2: Ordered frequency groups — \\(O(\log n)\\)

A natural improvement is to maintain frequency groups in a `TreeMap`. Each frequency maps to a recency-ordered collection of keys.

The smallest frequency is available through `firstKey()`, and the oldest key in that group can be evicted. However, inserting or removing frequency groups in a balanced tree costs \\(O(\log n)\\).

```
import java.util.*;

class LFUCacheOrdered {

    // The entry tracks its current frequency and value.
    private static final class Entry {
        int value;
        int frequency;

        Entry(int value, int frequency) {
            this.value = value;
            this.frequency = frequency;
        }
    }

    private final int capacity;
    private final Map<Integer, Entry> entries = new HashMap<>();

    // LinkedHashSet preserves insertion order:
    // oldest key first, newest key last.
    private final TreeMap<Integer, LinkedHashSet<Integer>> buckets =
            new TreeMap<>();

    LFUCacheOrdered(int capacity) {
        this.capacity = capacity;
    }

    public int get(int key) {
        Entry entry = entries.get(key);
        if (entry == null) {
            return -1;
        }

        touch(key, entry);
        return entry.value;
    }

    public void put(int key, int value) {
        if (capacity == 0) {
            return;
        }

        Entry existing = entries.get(key);

        if (existing != null) {
            existing.value = value;
            touch(key, existing);
            return;
        }

        if (entries.size() == capacity) {
            // The first tree key is the minimum frequency.
            var firstBucket = buckets.firstEntry();
            int victim = firstBucket.getValue().iterator().next();

            firstBucket.getValue().remove(victim);
            if (firstBucket.getValue().isEmpty()) {
                buckets.remove(firstBucket.getKey());
            }

            entries.remove(victim);
        }

        entries.put(key, new Entry(value, 1));
        buckets.computeIfAbsent(1, ignored -> new LinkedHashSet<>())
                .add(key);
    }

    private void touch(int key, Entry entry) {
        LinkedHashSet<Integer> oldBucket = buckets.get(entry.frequency);
        oldBucket.remove(key);

        if (oldBucket.isEmpty()) {
            buckets.remove(entry.frequency);
        }

        entry.frequency++;
        buckets.computeIfAbsent(entry.frequency,
                ignored -> new LinkedHashSet<>()).add(key);
    }

    /*
     * TIME:
     * get: O(log n) worst-case due to ordered frequency-bucket operations.
     * put: O(log n) worst-case due to TreeMap updates.
     * Hash-map operations are average O(1), but the TreeMap dominates.
     *
     * SPACE: O(n) across entries and frequency buckets.
     *
     * VERDICT: A useful intermediate design, but not optimal for this
     * interview requirement. LinkedHashSet provides recency ordering,
     * while TreeMap provides frequency ordering; both ordering requirements
     * can be satisfied in O(1) by a different combination of structures.
     */
}
```

### Approach 3: Optimal — HashMap + doubly linked lists

This is the solution I would expect in a senior Java interview.

The crucial observation is that we do not need to sort all frequencies. We only need to know the minimum frequency, and when a key moves from frequency \\(f\\) to \\(f+1\\), we can update that minimum incrementally.

```
import java.util.HashMap;
import java.util.Map;

public class LFUCache {

    /*
     * NODE:
     *
     * Each cached key has exactly one node. The node belongs to exactly
     * one frequency bucket, so its frequency and list membership must
     * always remain synchronized.
     *
     * prev/next permit O(1) unlinking when a key changes frequency
     * or is evicted. A singly linked list would not support arbitrary
     * O(1) removal without searching for the predecessor.
     */
    private static final class Node {
        final int key;
        int value;
        int frequency;
        Node prev;
        Node next;

        Node(int key, int value) {
            this.key = key;
            this.value = value;
            this.frequency = 1;
        }
    }

    /*
     * DOUBLY LINKED LIST:
     *
     * Each list contains only nodes having the same frequency.
     *
     * head.next is the MRU (most recently used) node.
     * tail.prev is the LRU (least recently used) node.
     *
     * Dummy head and tail sentinels eliminate special cases for
     * inserting/removing the first or last real node.
     *
     * addFirst: O(1)
     * remove:   O(1), provided the node belongs to this list
     * removeLast: O(1)
     */
    private static final class DoublyLinkedList {
        private final Node head = new Node(-1, -1);
        private final Node tail = new Node(-1, -1);
        private int size;

        DoublyLinkedList() {
            head.next = tail;
            tail.prev = head;
        }

        boolean isEmpty() {
            return size == 0;
        }

        void addFirst(Node node) {
            Node first = head.next;

            node.prev = head;
            node.next = first;
            head.next = node;
            first.prev = node;

            size++;
        }

        void remove(Node node) {
            // The node's neighbors are known; no search is needed.
            node.prev.next = node.next;
            node.next.prev = node.prev;

            // Detach the node so stale links cannot accidentally be reused.
            node.prev = null;
            node.next = null;

            size--;
        }

        Node removeLast() {
            if (isEmpty()) {
                return null;
            }

            Node lru = tail.prev;
            remove(lru);
            return lru;
        }
    }

    /*
     * keyToNode:
     *   Key -> exact cache node, for average O(1) lookup.
     *
     * frequencyToList:
     *   Frequency -> recency-ordered list for that frequency.
     *
     * minFrequency:
     *   The smallest frequency among all currently cached nodes.
     *
     * The crucial invariant is:
     * minFrequency always identifies a non-empty frequency bucket
     * whenever the cache is non-empty.
     */
    private final int capacity;
    private final Map<Integer, Node> keyToNode = new HashMap<>();
    private final Map<Integer, DoublyLinkedList> frequencyToList =
            new HashMap<>();

    private int minFrequency;

    public LFUCache(int capacity) {
        // The problem permits capacity zero.
        this.capacity = capacity;
    }

    public int get(int key) {
        Node node = keyToNode.get(key);

        if (node == null) {
            // Missing reads neither change frequency nor recency.
            return -1;
        }

        // A successful get counts as usage.
        increaseFrequency(node);

        return node.value;
    }

    public void put(int key, int value) {
        if (capacity == 0) {
            // Never attempt eviction from an empty zero-capacity cache.
            return;
        }

        Node existing = keyToNode.get(key);

        if (existing != null) {
            // Updating an existing key is a usage event too.
            existing.value = value;
            increaseFrequency(existing);
            return;
        }

        if (keyToNode.size() == capacity) {
            /*
             * EVICTION:
             *
             * minFrequency directly identifies the correct frequency.
             * Within that bucket, removeLast() chooses the LRU node.
             * Both operations take O(1) time.
             */
            DoublyLinkedList lruList =
                    frequencyToList.get(minFrequency);

            Node victim = lruList.removeLast();
            keyToNode.remove(victim.key);

            // Remove empty buckets to keep the map representative
            // of frequencies that actually exist.
            if (lruList.isEmpty()) {
                frequencyToList.remove(minFrequency);
            }
        }

        /*
         * INSERTION:
         *
         * Every newly inserted key starts at frequency 1.
         * It is the newest node in frequency bucket 1.
         *
         * Reset minFrequency to 1 because the new node guarantees
         * that frequency 1 is now the minimum existing frequency.
         */
        Node node = new Node(key, value);

        keyToNode.put(key, node);
        frequencyToList.computeIfAbsent(
                1, ignored -> new DoublyLinkedList()
        ).addFirst(node);

        minFrequency = 1;
    }

    private void increaseFrequency(Node node) {
        int oldFrequency = node.frequency;

        // First unlink the node from its current frequency bucket.
        DoublyLinkedList oldList = frequencyToList.get(oldFrequency);
        oldList.remove(node);

        /*
         * MINIMUM-FREQUENCY MAINTENANCE:
         *
         * If this node was the last node at minFrequency, that bucket
         * becomes empty after removal.
         *
         * Since this operation only moves a node from f to f+1,
         * no frequencies below f can suddenly become populated.
         * Therefore, when the old minimum bucket empties, the new
         * minimum is exactly oldFrequency + 1.
         *
         * This reasoning depends on oldFrequency being the current
         * minimum. If a non-minimum bucket empties, minFrequency
         * remains unchanged.
         */
        if (oldList.isEmpty()) {
            frequencyToList.remove(oldFrequency);

            if (minFrequency == oldFrequency) {
                minFrequency = oldFrequency + 1;
            }
        }

        // The usage counter increases exactly once.
        node.frequency++;

        /*
         * Add to the front of the new bucket because this access is
         * the most recent usage among all nodes at the new frequency.
         */
        frequencyToList.computeIfAbsent(
                node.frequency, ignored -> new DoublyLinkedList()
        ).addFirst(node);
    }

    /*
     * COMPLEXITY ANALYSIS:
     *
     * Let n = number of cached entries, with n <= capacity.
     *
     * get(key):
     *   - Hash-map lookup: average O(1).
     *   - Unlink from old list: O(1).
     *   - Update frequency and possibly minFrequency: O(1).
     *   - Insert into new list: O(1).
     *   Total: average O(1).
     *
     * put(key, value):
     *   - Existing key: update and increase frequency in average O(1).
     *   - New key without eviction: average O(1).
     *   - New key with eviction: locate minFrequency bucket and remove
     *     its LRU node in O(1), then insert in average O(1).
     *   Total: average O(1).
     *
     * SPACE:
     *   - keyToNode holds O(n) nodes/references.
     *   - frequencyToList holds at most O(n) non-empty buckets.
     *   - All frequency lists together hold O(n) real nodes and
     *     O(n) sentinel nodes.
     *   Total auxiliary space: O(n).
     *
     * This is average O(1), rather than worst-case O(1), because
     * HashMap operations have average constant-time complexity.
     */
}
```

## 4. Walkthrough of the optimal solution

Consider `LFUCache(2)`.

Initial state

```
keyToNode = {}
frequencyToList = {}
minFrequency = 0
```

Operation 1: `put(1, 10)`

Key `1` is new, so it starts at frequency `1`.

```
Frequency 1: MRU [1] LRU
minFrequency = 1
```

Operation 2: `put(2, 20)`

Key `2` also starts at frequency `1`. Because it is more recent, it goes to the front.

```
Frequency 1: MRU [2] <-> [1] LRU
minFrequency = 1
```

Operation 3: `get(1)`

The key's frequency increases from `1` to `2`. It moves to the frequency-2 bucket.

```
Frequency 1: MRU [2] LRU
Frequency 2: MRU [1] LRU
minFrequency = 1
```

Operation 4: `put(3, 30)`

The cache is full. `minFrequency = 1`, so we evict the LRU node from frequency `1`: key `2`.

Key `3` is then inserted with frequency `1`.

```
Frequency 1: MRU [3] LRU
Frequency 2: MRU [1] LRU
minFrequency = 1
```

Operation 5: `get(3)`

Key `3` moves to frequency `2` and becomes the most recently used key in that bucket.

```
Frequency 2: MRU [3] <-> [1] LRU
minFrequency = 2
```

The old frequency-1 bucket is empty, so the minimum frequency becomes `2`.

## 5. Edge cases to watch out for

| Edge case                            | Expected behavior                                                                              |
| ------------------------------------ | ---------------------------------------------------------------------------------------------- |
| Capacity is `0`                      | Ignore every `put`; `get` returns `-1`.                                                        |
| Key is missing                       | Return `-1`; do not change any frequency.                                                      |
| Only one entry exists                | Eviction removes that entry correctly.                                                         |
| Multiple keys have equal frequencies | Evict the LRU key in the minimum-frequency bucket.                                             |
| `put` updates an existing key        | Update its value and increment its frequency.                                                  |
| A frequency bucket becomes empty     | Remove the bucket and update `minFrequency` if necessary.                                      |
| A new key is inserted after eviction | Set its frequency to `1` and `minFrequency` to `1`.                                            |
| Values or keys are `0`               | Handle them normally; use node existence, not the value, to determine whether a key is cached. |

One particularly important bug to avoid is updating `minFrequency` unconditionally when any bucket becomes empty. Only update it when the emptied bucket was the current minimum.

## 6. Interviewer follow-up questions and answers

Q1. Why can't we use a single `HashMap` and a priority queue?

A priority queue generally requires \\(O(\log n)\\) to update a key's priority or remove an arbitrary entry. The requirement here is average \\(O(1)\\) for both operations. The frequency buckets and linked lists eliminate that overhead.

Q2. Why use a doubly linked list instead of `ArrayList`?

An `ArrayList` requires shifting elements when removing a node from the middle, which costs \\(O(n)\\). A doubly linked list can unlink a known node in \\(O(1)\\).

Q3. Why do we need both hash maps?

`keyToNode` locates the exact entry in average \\(O(1)\\). `frequencyToList` locates the group in which that entry belongs, also in average \\(O(1)\\). Either map alone would leave us searching for a node or frequency group.

Q4. Why is it safe to set `minFrequency = oldFrequency + 1` when the old minimum bucket becomes empty?

If the old bucket was the minimum, no cached key has a frequency below it. During the operation, the node moves from frequency \\(f\\) to \\(f+1\\). If the bucket at \\(f\\) becomes empty, the moved node guarantees that frequency \\(f+1\\) exists. Therefore, \\(f+1\\) is the new minimum.

Q5. Does `put` increment frequency if the value doesn't change?

Yes. The statement says the frequency increments whenever `Get` or `Put` is called on an existing key, so even an unchanged value counts as a usage event.

Q6. Can we make the solution thread-safe?

Yes, but synchronization would be needed across the maps, lists, and `minFrequency` because each operation changes multiple pieces of shared state. A synchronized method or a shared lock is the simplest starting point. More advanced designs would need careful locking and concurrency semantics.

Q7. Can frequency counters overflow?

With an unbounded operation stream, an `int` frequency can eventually overflow. A production implementation might use `long` counters or define a saturation/aging policy. For this problem's limits of at most 2,000 operations, `int` is sufficient.

Q8. What is the difference between LFU and LRU?

- LFU (Least Frequently Used): Evicts the key with the lowest access frequency, using recency to break ties.
- LRU (Least Recently Used): Evicts the key that has gone the longest without being accessed, regardless of its frequency.

Q9. What is the final complexity?

- `get`: average \\(O(1)\\) time.
- `put`: average \\(O(1)\\) time.
- Space: \\(O(\text{capacity})\\).

Interview takeaway: The core insight is to separate frequency ordering from recency ordering. Hash maps provide direct access, doubly linked lists provide constant-time movement and removal, and `minFrequency` avoids scanning for the eviction candidate.
