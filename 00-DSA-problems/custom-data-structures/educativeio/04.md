# Min Stack — Complete Java 24 Interview Solution

## 0. Understand the problem in simple words

We need to design a special stack called `MinStack` that supports three operations:

1. `push(value)` — add a value to the top of the stack.
2. `pop()` — remove and return the most recently added value.
3. `getMin()` — return the smallest value currently in the stack.

The important requirement is that all three operations must take \\(O(1)\\) time.

A normal stack already supports `push()` and `pop()` in \\(O(1)\\) time. The challenge is retrieving the minimum without scanning every element.

For example:

```
push(5)
push(3)
push(7)
getMin()  -> 3
pop()     -> 7
getMin()  -> 3
pop()     -> 3
getMin()  -> 5
```

Notice that when `3` is removed, the minimum changes back to `5`. We must remember the previous minimum so that we can restore it efficiently.

## 1. Clarifying questions to ask the interviewer

- Can the stack contain duplicate values? We should assume yes, because the same minimum may be pushed multiple times.
- Can values be negative? Yes, the constraints explicitly allow negative values.
- Can `pop()` or `getMin()` be called on an empty stack? No, the problem guarantees these methods are called only on a non-empty stack. Therefore, we do not need to define empty-stack behavior for this problem.
- Must every operation run in constant time? Yes. This rules out scanning the stack to find the minimum.

These questions clarify correctness requirements and help us choose a data structure that meets the complexity guarantee.

## 2. Core intuition: remember the minimum as the stack changes

There are two common ways to solve this problem:

- Maintain a second stack containing the minimum at each position.
- Store each value together with the minimum that existed when that value was pushed.

We'll first understand the simplest interview-friendly approach, then compare it with alternatives.

### Approach A: Two stacks

Use two stacks:

- `values` stores every value pushed onto the stack.
- `minValues` stores the minimum value at each corresponding position.

Whenever we push a value, calculate the new minimum:

\\[ \text{newMin}=\min(\text{value},\text{currentMin}) \\]

Whenever we pop a value, pop from both stacks. This restores the previous minimum automatically.

### Step-by-step example

Consider these operations:

```
push(5)
push(3)
push(7)
push(2)
pop()
getMin()
```

The stacks evolve as follows. The rightmost value is the top.

### After push(5)

5

minValues

5

The minimum is 5.

### After push(3)

values

5

3

minValues

The minimum changes to 3.

### After push(7)

values

3

minValues

7 is not smaller than 3, so the minimum remains 3.

### After push(2), then pop()

3

minValues

5

3

3

2 was the top value and is removed. The current minimum returns to 3.

The key insight is that the minimum at a particular stack position never needs to be recalculated. We stored it when that position was pushed.

## 3. Solution 1 — Brute force

The simplest idea is to maintain one normal stack and search through every element whenever `getMin()` is called.

Why it works: the smallest value must be among the values currently in the stack, so scanning all of them finds it.

Why it is not optimal: if there are \\(n\\) elements, finding the minimum takes \\(O(n)\\) time. This violates the problem's requirement.

```
import java.util.ArrayDeque;
import java.util.Deque;

class MinStackBruteForce {

    private final Deque<Integer> stack = new ArrayDeque<>();

    // Push: O(1) time.
    // Adding an element to the top of the stack does not require scanning.
    public void push(int value) {
        stack.push(value);
    }

    // Pop: O(1) time.
    // Removing the top element is a constant-time operation.
    // The problem guarantees that the stack is not empty.
    public int pop() {
        return stack.pop();
    }

    // getMin: O(n) time, where n is the current stack size.
    // We must inspect every element because we do not remember the minimum.
    // Space: O(1) auxiliary space because we only maintain a local variable.
    public int getMin() {
        int min = Integer.MAX_VALUE;

        for (int value : stack) {
            min = Math.min(min, value);
        }

        return min;
    }
}
```

## 4. Solution 2 — Optimal two-stack approach

This is a strong interview solution because the logic is simple and each operation is \\(O(1)\\).

```
import java.util.ArrayDeque;
import java.util.Deque;

class MinStack {

    // The main stack stores all values in insertion order.
    // The top of this stack is the most recently pushed value.
    private final Deque<Integer> values = new ArrayDeque<>();

    // minValues stores the minimum for each corresponding stack position.
    // Its top is always the minimum of the entire current stack.
    private final Deque<Integer> minValues = new ArrayDeque<>();

    // Constructor: O(1) time and O(1) initial space.
    // Both stacks begin empty.
    public MinStack() {
    }

    // Push: O(1) time.
    // Auxiliary space per push: O(1); total space across n elements: O(n).
    public void push(int value) {

        // Store the actual value.
        values.push(value);

        // If this is the first value, it is automatically the minimum.
        // Otherwise, compare it with the previous minimum.
        // Using <= correctly handles duplicate minimum values.
        if (minValues.isEmpty() || value <= minValues.peek()) {
            minValues.push(value);
        } else {
            // The new value is larger than the current minimum.
            // The minimum does not change.
            // We still need a corresponding entry for this stack position
            // so that popping both stacks stays synchronized.
            minValues.push(minValues.peek());
        }
    }

    // Pop: O(1) time.
    // The problem guarantees that the stack is not empty.
    public int pop() {

        // Remove the current minimum snapshot as well as the actual value.
        // The previous minimum becomes the new top of minValues.
        minValues.pop();

        return values.pop();
    }

    // getMin: O(1) time and O(1) auxiliary space.
    // No traversal or recalculation is needed.
    public int getMin() {
        return minValues.peek();
    }
}
```

### Why does popping work?

Suppose we push `5`, `3`, and `7`.

| Operation | `values` (bottom to top) | `minValues` (bottom to top) | Minimum |
| --------- | ------------------------ | --------------------------- | ------- |
| `push(5)` | `[5]`                    | `[5]`                       | 5       |
| `push(3)` | `[5, 3]`                 | `[5, 3]`                    | 3       |
| `push(7)` | `[5, 3, 7]`              | `[5, 3, 3]`                 | 3       |
| `pop()`   | `[5, 3]`                 | `[5, 3]`                    | 3       |
| `pop()`   | `[5]`                    | `[5]`                       | 5       |

Each minimum entry represents the minimum at that exact position. When we remove a position, we remove its minimum snapshot too.

### Complexity analysis

Let \\(n\\) be the number of elements currently in the stack.

| Operation     | Time       | Extra space per operation |
| ------------- | ---------- | ------------------------- |
| Constructor   | \\(O(1)\\) | \\(O(1)\\)                |
| `push()`      | \\(O(1)\\) | \\(O(1)\\)                |
| `pop()`       | \\(O(1)\\) | \\(O(1)\\)                |
| `getMin()`    | \\(O(1)\\) | \\(O(1)\\)                |
| Total storage | —          | \\(O(n)\\)                |

The two stacks each hold up to \\(n\\) entries, so total space is \\(O(n)+O(n)=O(n)\\).

## 5. Solution 3 — One stack using a Java record

We can avoid maintaining two separate stacks by storing both the pushed value and its minimum snapshot in a single stack entry.

This is a particularly clean option in modern Java because a `record` gives us a concise immutable data carrier.

```
import java.util.ArrayDeque;
import java.util.Deque;

class MinStackWithRecords {

    // Every entry remembers:
    // 1. The actual value pushed.
    // 2. The minimum of the stack at the time it was pushed.
    private record Entry(int value, int minSoFar) {}

    private final Deque<Entry> stack = new ArrayDeque<>();

    // Constructor: O(1) time and O(1) initial space.
    public MinStackWithRecords() {
    }

    // Push: O(1) time and O(1) additional space for the new entry.
    public void push(int value) {

        // If the stack is empty, the new value is the minimum.
        // Otherwise, compare the new value with the previous top's minimum.
        int minSoFar = stack.isEmpty()
                ? value
                : Math.min(value, stack.peek().minSoFar());

        // Save the value and its minimum together.
        // This preserves the previous minimum information even when
        // the new value is larger than the current minimum.
        stack.push(new Entry(value, minSoFar));
    }

    // Pop: O(1) time.
    // Removing one entry also removes its saved minimum snapshot.
    // The problem guarantees that the stack is non-empty.
    public int pop() {
        return stack.pop().value();
    }

    // getMin: O(1) time.
    // The top entry contains the minimum of the entire current stack.
    public int getMin() {
        return stack.peek().minSoFar();
    }
}
```

### Why this approach is elegant

For the operations `push(5)`, `push(3)`, and `push(7)`, the stack contains:

```
TOP
+----------------------+
| value = 7, minSoFar=3|
+----------------------+
| value = 3, minSoFar=3|
+----------------------+
| value = 5, minSoFar=5|
+----------------------+
BOTTOM
```

When `7` is popped, the entry containing `3` becomes the top. Its `minSoFar` field already contains `3`.

When `3` is popped, the entry containing `5` becomes the top, so the minimum automatically returns to `5`.

There is no need to explicitly restore the old minimum.

Complexities: all three operations take \\(O(1)\\) time. Total storage is \\(O(n)\\), with one record per stack element.

## 6. Solution 4 — One stack with encoded values

There is another approach that uses only one stack of `long` values and a separate variable for the current minimum.

It encodes special values when a new minimum is pushed, allowing the previous minimum to be recovered when that encoded entry is popped.

This is more space-efficient in terms of the number of stored stack entries, but the arithmetic is more difficult to explain and maintain. It is useful as an advanced interview follow-up.

```
import java.util.ArrayDeque;
import java.util.Deque;

class MinStackEncoded {

    private final Deque<Long> stack = new ArrayDeque<>();
    private long min;

    // Constructor: O(1) time and O(1) initial space.
    public MinStackEncoded() {
    }

    // Push: O(1) time and O(1) additional space.
    public void push(int value) {
        long x = value;

        if (stack.isEmpty()) {
            // The first value becomes the current minimum.
            min = x;
            stack.push(x);
        } else if (x >= min) {
            // Normal case: the value is not a new minimum.
            // Store it unchanged.
            stack.push(x);
        } else {
            // A new minimum is found.
            //
            // Encode the entry as 2*x - oldMin.
            // Because x < oldMin, the encoded value is less than x,
            // and therefore less than the new minimum.
            //
            // This lets pop() identify an encoded entry without
            // storing a separate flag.
            stack.push(2L * x - min);

            // Save the new minimum separately.
            min = x;
        }
    }

    // Pop: O(1) time.
    // The problem guarantees that the stack is non-empty.
    public int pop() {
        long top = stack.pop();

        if (top >= min) {
            // Normal entry: it does not encode an older minimum.
            return (int) top;
        }

        // An encoded entry means the popped value was the minimum.
        // Recover the actual value from the current minimum.
        long actualValue = min;

        // Reverse the encoding:
        // encoded = 2 * newMin - oldMin
        // Therefore oldMin = 2 * newMin - encoded.
        min = 2L * min - top;

        return (int) actualValue;
    }

    // getMin: O(1) time.
    // If the stack is non-empty, the separate variable holds its minimum.
    public int getMin() {
        return (int) min;
    }
}
```

Important: `long` is used for encoded values to avoid integer overflow during the arithmetic. With the given constraints, this encoding is safe in `long`.

The encoding approach assumes that callers obey the non-empty-stack guarantee. After the final element is popped, `min` is stale, but it is never read until another value is pushed, which initializes it again.

## 7. Edge cases to test

These cases are important in an interview because many incorrect implementations fail on duplicates or negative numbers.

| Test                | Operations                         | Expected result        |
| ------------------- | ---------------------------------- | ---------------------- |
| Single element      | `push(8)`, `getMin()`              | `8`                    |
| Increasing values   | `push(2)`, `push(4)`, `push(9)`    | Minimum is `2`         |
| Decreasing values   | `push(9)`, `push(4)`, `push(2)`    | Minimum is `2`         |
| Duplicate minimum   | `push(3)`, `push(3)`, `pop()`      | Minimum remains `3`    |
| Restore old minimum | `push(5)`, `push(2)`, `pop()`      | Minimum returns to `5` |
| Negative values     | `push(-2)`, `push(-8)`, `push(-3)` | Minimum is `-8`        |
| Mixed values        | `push(0)`, `push(-1)`, `push(1)`   | Minimum is `-1`        |

### Why duplicate minimums matter

Consider:

```
push(3)
push(3)
pop()
getMin() -> 3
```

If an implementation only tracks the minimum when it changes and fails to account for duplicate occurrences, it might incorrectly lose the minimum after a pop.

The two-stack solution avoids this by pushing a minimum snapshot for every value. The record-based solution stores the snapshot in every entry.

## 8. Interview follow-up questions and answers

Q1. Why can't we simply maintain one variable called `min`?

Because when the current minimum is popped, we need to know the previous minimum. A single variable does not preserve that history. The second stack or per-entry snapshot preserves it.

Q2. Why is `getMin()` \\(O(1)\\)?

The current minimum is always stored at the top of `minValues` or inside the top record. We retrieve it directly without traversing the stack.

Q3. What is the difference between the two-stack and record-based approaches?

Both have \\(O(1)\\) operation time and \\(O(n)\\) space. The two-stack approach separates values and minimums, while the record-based approach keeps both pieces of information together in each entry.

Q4. Which approach would you choose in a coding interview?

I would choose the two-stack solution when the goal is to demonstrate the core data-structure idea as clearly as possible. I would choose the record-based solution if the interviewer values encapsulating each value and its associated state into one entry.

Q5. Can we solve it with a priority queue?

A priority queue provides efficient access to the minimum, but it does not naturally support removing the most recently pushed value in \\(O(1)\\). It is therefore not a suitable direct replacement for a stack with these requirements.

Q6. What happens if we use `Integer.MAX_VALUE` as the initial minimum?

It can work for a scan-based implementation, but it is unnecessary when we can detect an empty stack explicitly. The two-stack and record-based implementations correctly handle every valid `int` value, including `Integer.MAX_VALUE` and `Integer.MIN_VALUE`.

Q7. What is the invariant that proves the two-stack solution is correct?

At every position, `minValues` stores the minimum of all values up to that position. Consequently, its top is always the minimum of the entire stack. Pushing extends this invariant, and popping removes the corresponding snapshot, preserving it.

## 9. Final recommendation

For this problem, remember this mental model:

> Every stack position must remember the minimum that would be visible if that position were the top.

That observation gives us constant-time minimum retrieval without scanning the stack.

- Brute force: easiest to understand, but `getMin()` takes \\(O(n)\\).
- Two stacks: easiest optimal solution to explain.
- One stack of records: clean, modern Java implementation with the same complexity.
- Encoded values: an advanced alternative that reduces the number of stack entries but requires careful arithmetic.

For an interview, I would implement the two-stack approach first, clearly explain its invariant, and then mention the record-based implementation as an equally efficient alternative.
