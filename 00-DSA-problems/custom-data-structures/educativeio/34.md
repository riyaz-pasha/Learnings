# 1206. Design Skiplist — Java 24

The key to understanding a Skiplist is this:

A Skiplist is a sorted linked list with extra express lanes. Instead of checking every element one by one, we use upper layers to skip over many elements, allowing us to search, insert, and delete in expected \\(O(\log n)\\) time.

The challenging part is not writing the code. It is understanding how the layers are built, how to navigate them, and how insertion and deletion keep all the layers consistent.

## 0. Simplify the problem statement

We need to implement a data structure that supports three operations:

- `search(target)`: Return `true` if the value exists; otherwise, return `false`.
- `add(num)`: Insert a value while maintaining sorted order.
- `erase(num)`: Remove one occurrence of the value. Return `false` if it doesn't exist.

Important requirements:

- Duplicate values are allowed.
- If a value occurs multiple times, removing any one occurrence is acceptable.
- We cannot use a built-in data structure to implement the Skiplist.
- There can be up to 50,000 operations.

A normal sorted linked list can implement these operations, but each operation takes \\(O(n)\\) time in the worst case. We want to make them faster by adding multiple levels of linked lists.

## 1. Clarifying questions to ask the interviewer

These questions help establish the exact requirements before choosing an implementation.

1. Can duplicate values exist? Yes. The problem explicitly allows duplicates, so our implementation must preserve them.
2. Which occurrence should `erase` remove? Any one occurrence is acceptable. We can remove the first matching occurrence encountered.
3. Must we guarantee \\(O(\log n)\\) for every operation? No. A standard Skiplist offers expected \\(O(\log n)\\) time, assuming randomized level selection; its worst case can still be \\(O(n)\\).
4. Can we use built-in ordered maps, trees, or lists? No. We should implement the linked nodes and their forward pointers ourselves.
5. Are values restricted to nonnegative integers? Yes, \\(0 \le num,target \le 20{,}000\\). We can use a special sentinel head node whose value is ignored during comparisons with actual values.

The most important clarification is the distinction between worst-case and expected time. Randomization makes the Skiplist efficient on average; it does not guarantee that every randomly generated structure is balanced.

## 2. The core intuition: think of express lanes

Imagine a sorted linked list containing:

`10 → 20 → 30 → 40 → 50 → 60 → 70 → 80 → 90`

Searching for `70` in this list requires walking through several nodes.

Now imagine we add express lanes:

Top level — long jumps

HEAD ───────────────→ 50 ───────────────→ 90

Middle level — medium jumps

HEAD ───→ 30 ───→ 50 ───→ 70 ───→ 90

Bottom level — every element

HEAD → 10 → 20 → 30 → 40 → 50 → 60 → 70 → 80 → 90

Each level is a sorted linked list, and every node in an upper level also appears in the levels beneath it.

The bottom level contains every value. Higher levels contain selected values that help us jump ahead.

### How does searching work?

Suppose we want to find `70`.

1. Start at the highest level.
2. Move right while the next value is smaller than `70`.
3. If the next value would be greater than or equal to `70`, move down one level.
4. Continue until we reach the bottom level.
5. Check the next node for an exact match.

For example, if we are at `50` on the top level, the next value is `90`. Since `90 > 70`, we move down to the middle level.

At the middle level, we can advance to `70`, and then confirm the value at the bottom level.

This is the central mental model:

Move right to make progress; move down when moving right would overshoot the target.

## 3. How do we decide which nodes get express lanes?

We cannot manually decide which nodes should appear at each level. That would be complicated to maintain after every insertion and deletion.

Instead, we use randomness.

Whenever we insert a new value:

- Every node is inserted at the bottom level.
- Flip a coin. If it succeeds, promote the node to the next level.
- Keep flipping and promoting until the coin fails or we reach the maximum level.

For example, inserting `40` might produce a node at levels 0, 1, and 2. Inserting `60` might produce a node only at level 0.

The probability of promotion is usually \\(1/2\\).

```
Level 2:  HEAD ───────────────→ 40
Level 1:  HEAD ───→ 20 ──────→ 40 ──────→ 70
Level 0:  HEAD → 10 → 20 → 30 → 40 → 50 → 60 → 70
```

Here, `40` has three forward-pointer slots, `20` has two, and `10` has one.

Why does this help?

- About half the nodes appear at level 1.
- About a quarter appear at level 2.
- About an eighth appear at level 3.

Higher levels become progressively sparser, making it increasingly likely that we can skip large portions of the list.

We do not need to rebuild the whole structure after insertion. We only update the pointers around the inserted node.

## 4. Build the solution from simpler to optimal

### Approach 1: A sorted singly linked list

This is the simplest correct implementation. It helps establish the behavior before introducing multiple levels.

```java
class Skiplist {
    /*
     * APPROACH 1: SORTED SINGLY LINKED LIST
     *
     * Each node contains a value and a pointer to the next node.
     * Values remain sorted in ascending order.
     *
     * Why start here?
     * We first solve the actual data-structure requirements:
     * search, insertion, deletion, and duplicate handling.
     * The Skiplist will optimize navigation, not change these
     * fundamental operations.
     */

    private static final class Node {
        int value;
        Node next;

        Node(int value, Node next) {
            this.value = value;
            this.next = next;
        }
    }

    private final Node head = new Node(-1, null);

    public boolean search(int target) {
        /*
         * Start at the first real node and walk until the value
         * is at least target.
         *
         * Because the list is sorted, once we reach a value greater
         * than target, target cannot appear later.
         *
         * Time: O(n) worst case; O(1) extra space.
         */
        Node current = head.next;

        while (current != null && current.value < target) {
            current = current.next;
        }

        return current != null && current.value == target;
    }

    public void add(int num) {
        /*
         * Find the node immediately BEFORE the insertion position.
         *
         * The condition uses < rather than <=. This allows a new
         * duplicate to be inserted before existing equal values.
         *
         * Pointer rewiring:
         *
         * Before: previous -> successor
         * After:  previous -> newNode -> successor
         *
         * Time: O(n) worst case; O(1) extra space.
         */
        Node previous = head;

        while (previous.next != null && previous.next.value < num) {
            previous = previous.next;
        }

        previous.next = new Node(num, previous.next);
    }

    public boolean erase(int num) {
        /*
         * Find the predecessor of the first occurrence of num.
         * If found, bypass that node.
         *
         * Before: previous -> target -> successor
         * After:  previous ------------> successor
         *
         * Because we stop at the first equal value, only one
         * occurrence is removed. Other duplicates remain intact.
         *
         * Time: O(n) worst case; O(1) extra space.
         */
        Node previous = head;

        while (previous.next != null && previous.next.value < num) {
            previous = previous.next;
        }

        if (previous.next == null || previous.next.value != num) {
            return false;
        }

        previous.next = previous.next.next;
        return true;
    }
}
```

This approach is correct, but it does not satisfy the intended performance of a Skiplist: all three operations can take \\(O(n)\\) time.

### Approach 2: Randomized Skiplist — optimal expected performance

We now replace each node's single `next` pointer with an array of forward pointers.

The most important design decision is:

`next[i]` points to the next node that participates in level `i`.

A node with three levels has `next[0]`, `next[1]`, and `next[2]`. A node with only one level has just `next[0]`.

We use a fixed maximum height of 32. This is more than enough for the given constraints, and each node allocates only as many pointers as its randomly selected height requires.

```java
import java.util.concurrent.ThreadLocalRandom;

class Skiplist {

    /*
     * APPROACH 2: RANDOMIZED SKIPLIST
     *
     * Core idea:
     * Maintain multiple sorted linked-list levels so that searching
     * can jump over many values instead of visiting them one by one.
     *
     * Level 0 contains every node.
     * Level 1 contains some of the level-0 nodes.
     * Level 2 contains some of the level-1 nodes.
     * And so on.
     *
     * Each higher-level node also belongs to every lower level.
     *
     * MAX_LEVEL = 32 is a fixed upper bound. With at most 50,000
     * operations, this is comfortably large for expected performance.
     *
     * Random promotion probability = 1/2.
     * Therefore, the expected number of forward pointers per node
     * is bounded by a constant.
     */

    private static final int MAX_LEVEL = 32;

    /*
     * Node represents one value in the Skiplist.
     *
     * next[i] is the forward pointer at level i.
     *
     * Examples:
     *   next.length == 1  -> node appears only at level 0.
     *   next.length == 2  -> node appears at levels 0 and 1.
     *   next.length == 3  -> node appears at levels 0, 1, and 2.
     *
     * A node's height is determined when it is inserted and does not
     * change during its lifetime.
     */
    private static final class Node {
        final int value;
        final Node[] next;

        Node(int value, int level) {
            this.value = value;
            this.next = new Node[level];
        }
    }

    /*
     * The head is a sentinel node, not a real stored value.
     *
     * It has pointers for every possible level, allowing us to start
     * a search at the highest level without special cases.
     *
     * Its value is never used to decide whether a real value exists.
     */
    private final Node head = new Node(-1, MAX_LEVEL);

    /*
     * Randomly choose the node's height.
     *
     * Every node gets at least level 0.
     * Each successful coin flip adds one more level.
     * Stop when the coin flip fails or MAX_LEVEL is reached.
     *
     * For promotion probability p = 1/2:
     *   P(height >= 1) = 1
     *   P(height >= 2) = 1/2
     *   P(height >= 3) = 1/4
     *   P(height >= 4) = 1/8
     *
     * This geometric distribution makes higher levels increasingly
     * sparse, creating useful express lanes.
     *
     * Time: O(MAX_LEVEL), which is O(1) for our fixed bound.
     * Extra space: O(1).
     */
    private int randomLevel() {
        int level = 1;

        while (level < MAX_LEVEL
                && ThreadLocalRandom.current().nextBoolean()) {
            level++;
        }

        return level;
    }

    public boolean search(int target) {
        /*
         * MENTAL MODEL:
         * Move RIGHT when the next value is smaller than target.
         * Move DOWN when moving right would overshoot target.
         *
         * Start at the head's highest level.
         *
         * At each level:
         *   1. Advance while the next value is < target.
         *   2. If we cannot advance, descend one level.
         *
         * Because every level is sorted, skipping a node at an upper
         * level cannot cause us to miss target: that node is also
         * represented at all lower levels.
         *
         * After descending to level 0, current is the last node
         * strictly smaller than target.
         * Therefore, current.next[0] is the first possible match.
         *
         * Example: search(45) in
         *
         * Level 2: HEAD ----------------> 50
         * Level 1: HEAD ------> 30 -----> 50
         * Level 0: HEAD -> 10 -> 30 -> 40 -> 50
         *
         * At level 2, 50 > 45, so descend.
         * At level 1, move to 30; 50 > 45, so descend.
         * At level 0, move to 40; 50 > 45, so stop.
         * The next node is 50, not 45, so return false.
         *
         * Expected time: O(log n).
         * Worst-case time: O(n), if the random levels are badly
         * distributed and the structure behaves almost like one list.
         * Extra space: O(1).
         */
        Node current = head;

        for (int level = MAX_LEVEL - 1; level >= 0; level--) {
            while (current.next[level] != null
                    && current.next[level].value < target) {
                current = current.next[level];
            }
        }

        current = current.next[0];

        return current != null && current.value == target;
    }

    public void add(int num) {
        /*
         * THE MOST IMPORTANT INSERTION IDEA:
         *
         * Before inserting, find the predecessor at EVERY level.
         *
         * update[i] stores the last node at level i whose value
         * is strictly smaller than num.
         *
         * Why do we need an update array?
         * A new node may participate in multiple levels. At each
         * of those levels, we need to know which existing pointer
         * must be redirected to the new node.
         *
         * STEP 1: Find all predecessors.
         *
         * Traverse from the highest level down to level 0.
         * At every level, move right while the next value < num.
         * Save the resulting node in update[level].
         *
         * Because we use < rather than <=, a duplicate is inserted
         * before existing equal values. This is valid because the
         * problem permits duplicates and does not require stable order.
         */
        Node[] update = new Node[MAX_LEVEL];
        Node current = head;

        for (int level = MAX_LEVEL - 1; level >= 0; level--) {
            while (current.next[level] != null
                    && current.next[level].value < num) {
                current = current.next[level];
            }

            update[level] = current;
        }

        /*
         * STEP 2: Randomly choose the new node's height.
         *
         * If its height is 3, it participates in levels 0, 1, and 2.
         * No pointers at levels 3 and above need to be changed.
         */
        int nodeLevel = randomLevel();
        Node newNode = new Node(num, nodeLevel);

        /*
         * STEP 3: Splice the new node into each level it participates in.
         *
         * At a particular level i, the old connection is:
         *
         *     update[i] ------------> successor
         *
         * We change it to:
         *
         *     update[i] -> newNode -> successor
         *
         * The order of the two assignments matters:
         * First preserve the old successor in newNode.next[i].
         * Then redirect update[i].next[i] to newNode.
         *
         * Every insertion always updates level 0, ensuring that
         * the value is stored even if its random height is 1.
         *
         * Expected time: O(log n).
         * Worst-case time: O(n), due to predecessor traversal.
         *
         * Extra temporary space: O(MAX_LEVEL), which is O(1) with
         * our fixed maximum level. The new node adds its own pointers.
         */
        for (int level = 0; level < nodeLevel; level++) {
            newNode.next[level] = update[level].next[level];
            update[level].next[level] = newNode;
        }
    }

    public boolean erase(int num) {
        /*
         * Deletion uses almost the same traversal as insertion.
         *
         * STEP 1: Find the predecessor at every level.
         *
         * update[i] is the node immediately before the position
         * where num would appear at level i.
         *
         * We stop before the first equal value, so duplicates are
         * handled by removing just one occurrence.
         */
        Node[] update = new Node[MAX_LEVEL];
        Node current = head;

        for (int level = MAX_LEVEL - 1; level >= 0; level--) {
            while (current.next[level] != null
                    && current.next[level].value < num) {
                current = current.next[level];
            }

            update[level] = current;
        }

        /*
         * STEP 2: Check the bottom level for the actual target.
         *
         * We must check equality, not merely whether a next node
         * exists. If the next value is greater, num is absent.
         *
         * No pointers have been changed yet, so an unsuccessful
         * deletion leaves the structure exactly as it was.
         */
        Node target = update[0].next[0];

        if (target == null || target.value != num) {
            return false;
        }

        /*
         * STEP 3: Unlink the target at every level where it appears.
         *
         * Before:
         *
         *     predecessor ------> target ------> successor
         *
         * After:
         *
         *     predecessor --------------------> successor
         *
         * IMPORTANT:
         * We cannot blindly access target.next[level] for all levels.
         * A short node might have only next[0] and not next[1].
         *
         * The condition update[level].next[level] == target is safe:
         * it can be true only at a level where target actually exists.
         * Java's short-circuit evaluation then guarantees that
         * target.next[level] is read only when that pointer exists.
         *
         * The target is removed from every level that points to it,
         * while other duplicate nodes remain untouched.
         *
         * Expected time: O(log n).
         * Worst-case time: O(n).
         * Extra temporary space: O(MAX_LEVEL), or O(1) for this
         * fixed maximum height.
         */
        for (int level = 0; level < MAX_LEVEL; level++) {
            if (update[level].next[level] == target) {
                update[level].next[level] = target.next[level];
            }
        }

        return true;
    }
}

/*
 * COMPLEXITY SUMMARY
 *
 * Let n be the number of stored elements.
 *
 * Sorted linked list:
 *   search: O(n) worst case
 *   add:    O(n) worst case
 *   erase:  O(n) worst case
 *   space:  O(n)
 *
 * Randomized Skiplist:
 *   search: O(log n) expected, O(n) worst case
 *   add:    O(log n) expected, O(n) worst case
 *   erase:  O(log n) expected, O(n) worst case
 *   space:  O(n) expected total space
 *
 * Why is expected space O(n)?
 * With promotion probability 1/2, the expected number of pointers
 * per node is bounded by a constant (approximately 2 when the height
 * is not capped). Therefore, n nodes need O(n) total pointers on
 * average. The fixed MAX_LEVEL also bounds every individual node's
 * pointer array.
 */
```

## 5. Edge cases to watch out for

```
/*
 * INTERVIEW EDGE CASES
 *
 * 1. Empty Skiplist
 *    search(5) -> false
 *    erase(5)  -> false
 *    add(5)    -> inserts the first real node.
 *
 * 2. Search for a missing value
 *    Values: [10, 20, 30]
 *    search(25) -> false.
 *    The final candidate is 30, which is not equal to 25.
 *
 * 3. Insert duplicates
 *    add(10), add(10), add(10)
 *    Level 0 contains three nodes with value 10.
 *    Upper levels may contain some or all of these nodes.
 *
 * 4. Delete one duplicate
 *    Values: [10, 10, 10]
 *    erase(10) -> true.
 *    Two occurrences must remain.
 *
 * 5. Delete a missing value
 *    Values: [10, 20, 30]
 *    erase(25) -> false.
 *    No pointers should change.
 *
 * 6. Minimum and maximum permitted values
 *    Values 0 and 20_000 are valid.
 *    The sentinel's value of -1 does not interfere because we
 *    start searching from head.next[level] rather than comparing
 *    the sentinel's value with the target.
 *
 * 7. Maximum node height
 *    randomLevel() must never return a value greater than MAX_LEVEL.
 *    The loop checks the bound before attempting another promotion.
 *
 * 8. Delete a tall node
 *    The node must be unlinked at every level where it appears.
 *    Updating only level 0 would leave stale upper-level pointers.
 *
 * 9. Delete the first real node
 *    The predecessor at each relevant level can be the head.
 *    The same pointer-update logic handles this case without
 *    requiring a special deletion branch.
 *
 * 10. Large operation count
 *     With up to 50,000 calls, a randomized Skiplist avoids the
 *     repeated full-list scans of the basic linked-list solution.
 */
```

## 6. How to think about this in an interview

The key is to derive the data structure from the performance requirement rather than memorize its implementation.

```
/*
 * INTERVIEW THOUGHT PROCESS
 *
 * Step 1: Recognize the bottleneck.
 *         A sorted linked list has O(n) search because we can only
 *         move forward one node at a time.
 *
 * Step 2: Ask what would make searching faster.
 *         We need a way to skip over groups of nodes.
 *
 * Step 3: Add express lanes.
 *         Maintain several sorted linked lists, with upper levels
 *         containing subsets of the nodes below them.
 *
 * Step 4: Ask how to choose the express-lane nodes.
 *         Randomly promote nodes with probability 1/2.
 *         This gives progressively sparser upper levels.
 *
 * Step 5: Derive search.
 *         Move right while the next value is smaller than the target.
 *         Otherwise, move down.
 *
 * Step 6: Derive insertion.
 *         Find the predecessor at every level, then splice the
 *         new node into every level it was randomly assigned.
 *
 * Step 7: Derive deletion.
 *         Find the same predecessors, verify the target exists,
 *         and bypass it at every level where it appears.
 *
 * Step 8: Verify duplicates and boundaries.
 *         Preserve duplicate nodes, delete one occurrence at a time,
 *         and check equality before reporting successful deletion.
 */
```

## 7. Interviewer follow-up questions and answers

```
/*
 * Q1. Why not use a balanced binary search tree?
 *
 * A. A balanced BST also provides O(log n) search, insertion, and
 *    deletion. A Skiplist is an alternative that uses linked lists
 *    and randomization rather than explicit tree rotations or
 *    rebalancing. The problem specifically asks us to implement one.
 *
 * Q2. Does a Skiplist guarantee O(log n) time?
 *
 * A. No. Its operations take expected O(log n) time, but the worst
 *    case is O(n). Randomization makes pathological structures
 *    unlikely, rather than impossible.
 *
 * Q3. Why use a promotion probability of 1/2?
 *
 * A. It creates a geometric distribution of node heights:
 *    approximately half the nodes at level 1, one-quarter at level 2,
 *    and one-eighth at level 3. Other promotion probabilities are
 *    possible, but 1/2 is a simple standard choice.
 *
 * Q4. Why does each node have an array of pointers?
 *
 * A. A node participates in multiple levels, and each level needs
 *    its own successor. An array represents these pointers directly.
 *
 * Q5. Why do we need the update array?
 *
 * A. A newly inserted node may occupy several levels. We must know
 *    the predecessor at each of those levels to update the correct
 *    pointers. Deletion needs the same information to unlink the node.
 *
 * Q6. Why does search compare using < rather than <=?
 *
 * A. We stop before the first value greater than or equal to target.
 *    Then we check whether that candidate equals target. This also
 *    makes insertion and deletion of duplicates straightforward.
 *
 * Q7. Can we store duplicate values in the upper levels?
 *
 * A. Yes. Every inserted occurrence is a distinct node and receives
 *    its own random height. Equal-valued nodes remain sorted.
 *
 * Q8. What happens if we always promote nodes to the highest level?
 *
 * A. The upper levels stop being sparse, and they provide little
 *    benefit over scanning a linked list. The random height
 *    distribution is essential to the expected performance.
 *
 * Q9. Could we make the Skiplist deterministic?
 *
 * A. Yes, with a different balancing strategy, but maintaining
 *    the right height distribution without randomization introduces
 *    additional complexity. The standard Skiplist uses random levels.
 *
 * Q10. Is the space complexity O(n log n)?
 *
 * A. That bound is possible for a structure where every node has
 *    O(log n) pointers. But in a randomized Skiplist, the expected
 *    node height is constant, so the expected total space is O(n).
 *    The worst-case number of pointers is O(n * MAX_LEVEL); because
 *    this implementation fixes MAX_LEVEL at 32, that is O(n).
 */
```

Final takeaway: A Skiplist is not a different sorting technique. It is a way to accelerate navigation through sorted linked lists. Remember the three operations as search = move right/down, add = record predecessors and splice, erase = record predecessors and bypass. Once those pointer rules are clear, the implementation becomes much easier to derive from scratch.
