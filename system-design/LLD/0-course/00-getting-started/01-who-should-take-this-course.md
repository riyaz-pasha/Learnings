# Who Should Take This Course?

## Intended audience

This course is for anyone who wants to get better at **algorithmic problem-solving**, not just at memorizing solutions.

Every lesson starts the same way: a short real-world scenario at a company (Netflix, Uber, a search engine...) describing a feature that needs to be built. You work through that feature to discover the underlying algorithmic pattern. Then you immediately re-apply that same pattern to solve classic, company-agnostic interview questions — so the pattern sticks, independent of the story that introduced it.

## Prerequisites

You should already be comfortable with the common data structures:

- Arrays and Linked Lists
- Hash Maps
- Stacks and Queues
- Heaps
- Graphs

You should also understand:

- Recursion
- Big-O notation

If any of these feel shaky, it's worth a quick refresher before diving in — the course assumes you know *what* these structures are and jumps straight to *when and why* to reach for them.

> **A note on the code style in this course:** proper object-oriented code marks class fields `private` and exposes them through getters/setters or a controlled interface. To keep the focus on the algorithm rather than boilerplate, the code in this course keeps fields `public` and skips that ceremony. Don't copy that habit into production code — do copy it here, where the goal is to read the *logic* as fast as possible.
