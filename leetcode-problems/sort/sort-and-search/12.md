This is a classic problem: **“Range Sum of Sorted Subarray Sums”** (LeetCode hard-ish pattern).
Brute force works due to constraints, but there are **3 levels of solutions**—let’s go from intuitive → optimized → interview killer 🔥

---

# 🧠 Key Idea

* Total subarrays = `n * (n + 1) / 2`
* Generate all subarray sums
* Sort them
* Return sum from `left → right`

---

# 🟢 Solution 1: Brute Force (Accepted, simplest)

## 💡 Idea

Generate all subarray sums using prefix accumulation.

---

### ✅ Java (Clean + Explained)

```java
import java.util.*;

public class RangeSumSubarray {

    static final int MOD = 1_000_000_007;

    public static int rangeSum(int[] nums, int left, int right) {
        int n = nums.length;

        // Total subarrays = n*(n+1)/2
        int total = n * (n + 1) / 2;
        int[] sums = new int[total];

        int index = 0;

        // Generate all subarray sums
        for (int i = 0; i < n; i++) {
            int runningSum = 0;

            for (int j = i; j < n; j++) {
                runningSum += nums[j]; // expand subarray
                sums[index++] = runningSum;
            }
        }

        // Sort all sums
        Arrays.sort(sums);

        long result = 0;

        // Sum from left to right (1-based index)
        for (int i = left - 1; i <= right - 1; i++) {
            result = (result + sums[i]) % MOD;
        }

        return (int) result;
    }
}
```

---

## ⏱ Complexity

* Generate sums → `O(n²)`
* Sort → `O(n² log n)`
* Total → **O(n² log n)**
* Space → `O(n²)`

✔ Works because `n ≤ 1000`

# 🟡 Solution 2: Min Heap (Better than sorting everything)

## 💡 Insight

Instead of generating ALL sums:

* Each subarray starting at `i` forms an increasing sequence:

  ```
  nums[i]
  nums[i] + nums[i+1]
  nums[i] + nums[i+1] + nums[i+2]
  ...
  ```
* Use **K-way merge (like merging sorted lists)**

---

## 🧠 Trick

Push `(sum, index)` into heap:

* Initially push all `nums[i]`
* Then expand gradually

---

### ✅ Java Code

```java
import java.util.*;

public class RangeSumHeap {

    static final int MOD = 1_000_000_007;

    static class Node {
        int sum;
        int index;

        Node(int sum, int index) {
            this.sum = sum;
            this.index = index;
        }
    }

    public static int rangeSum(int[] nums, int left, int right) {
        int n = nums.length;

        PriorityQueue<Node> pq = new PriorityQueue<>(Comparator.comparingInt(a -> a.sum));

        // Initialize heap
        for (int i = 0; i < n; i++) {
            pq.offer(new Node(nums[i], i));
        }

        long result = 0;

        for (int k = 1; k <= right; k++) {
            Node curr = pq.poll();

            if (k >= left) {
                result = (result + curr.sum) % MOD;
            }

            // Expand this subarray
            if (curr.index + 1 < n) {
                pq.offer(new Node(curr.sum + nums[curr.index + 1], curr.index + 1));
            }
        }

        return (int) result;
    }
}
```

---

## ⏱ Complexity

* Heap ops: `O(right log n)`
* Space: `O(n)`

✔ Much better when `right << n²`

# 🔴 Solution 3: Binary Search + Prefix Sum (INTERVIEW LEVEL 🔥)

## 💡 Core Insight

Instead of generating sums:

👉 We **binary search the k-th smallest subarray sum**

---

## 🧠 Observations

* Subarray sums are **monotonic increasing**
* We can count:

  > how many subarrays have sum ≤ X

---

## 🔑 Plan

1. Binary search for sum threshold `X`
2. Count subarrays ≤ X using sliding window
3. Compute prefix sum of those sums

---

## ⚠️ Hard part

We need:

* `count(X)` → number of subarrays ≤ X
* `sum(X)` → total sum of those subarrays

---

### 🚀 Code (Interview-Level Clean Version)

```java
import java.util.*;

public class RangeSumBinarySearch {

    static final int MOD = 1_000_000_007;

    public static int rangeSum(int[] nums, int left, int right) {
        long rightSum = prefixSumK(nums, right);
        long leftSum = prefixSumK(nums, left - 1);

        return (int) ((rightSum - leftSum + MOD) % MOD);
    }

    /**
     * Returns sum of first k smallest subarray sums
     */
    private static long prefixSumK(int[] nums, int k) {
        int n = nums.length;

        int low = 1, high = Arrays.stream(nums).sum();
        int answer = 0; // explicit answer variable (as per your preference)

        // Binary search for k-th smallest sum
        while (low <= high) {
            int mid = low + (high - low) / 2;

            if (countSubarrays(nums, mid) >= k) {
                answer = mid;
                high = mid - 1;
            } else {
                low = mid + 1;
            }
        }

        // Now compute sum of all subarrays <= answer
        return computeSum(nums, answer, k);
    }

    /**
     * Count subarrays with sum <= target
     */
    private static int countSubarrays(int[] nums, int target) {
        int n = nums.length;
        int count = 0;
        int left = 0, sum = 0;

        for (int right = 0; right < n; right++) {
            sum += nums[right];

            while (sum > target) {
                sum -= nums[left++];
            }

            count += (right - left + 1);
        }

        return count;
    }

    /**
     * Compute total sum of first k subarrays
     */
    private static long computeSum(int[] nums, int target, int k) {
        int n = nums.length;
        long totalSum = 0;

        int left = 0, sum = 0;
        long windowSum = 0;

        for (int right = 0; right < n; right++) {
            sum += nums[right];
            windowSum += (long) nums[right] * (right - left + 1);

            while (sum > target) {
                windowSum -= sum;
                sum -= nums[left++];
            }

            totalSum += windowSum;
        }

        return totalSum;
    }
}
```

---

## ⏱ Complexity

* Binary search → `O(log(sum))`
* Each check → `O(n)`
* Total → **O(n log(sum))**

🔥 This is the **optimal solution**

We maintain:

* `sum` → window sum
* `windowSum` → sum of ALL subarrays ending at `right`

#### right = 0 → [1]


Subarrays:

# 🔥 Key Intuition (Most Important)

## 💡 Why Binary Search Works?

Because:

```
If X increases → number of subarrays ≤ X increases
```

👉 This is **monotonic** → perfect for binary search

---

## 💡 Why Sliding Window Works?

Because:

* All numbers are **positive**
* So expanding window → sum increases
* Shrinking → sum decreases
